- **v8.22 的单调性在 50/30/10 以内继续成立**：T1（45/25/8）46.67 % > B1 39.58 %，
  差 +7.08 pp（p = 0.0701，单看这一跳并不显著）；
- **峰值在 40/20/5，不在 50/30/10**：T2 比 B1 高 **+19.17 pp**（p = 1.89e-05），
  比 T1 高 **+12.08 pp**（p = 0.005199，显著）；
- **越过 40/20/5 后显著回落**：T3 比 T2 低 **−10.00 pp**（单侧 p = 0.017567）。
  所以「越紧越好」的区间到此为止，转折点在 **40/20/5**。

### 7.2 方差不再是单调的

v8.22 的读法是「期望越高、方差越大」（25 pp）。本轮**不是**：T2 极差 31.25 pp
（最大），T1 20.00 pp，**T3 只有 6.25 pp**（比 B1 的 25 pp 小得多）。
读数：**T3 是本轮唯一「高期望 + 低方差」的配置**（48.75 %，三种子 47.5/52.5/46.25），
而 T2 是「最高期望 + 最大方差」（58.75 %，38.75–70.00）。
**T3 之所以稳，可能正是因为它有三档门里最「保守」的第三颗雷**（3 px，常留到死）——
这把期望拉低到 48.75 %，同时把种子间差异压到 6.25 pp。**这只是账面推断，
本轮没有做机制实验，不能作为结论。**

## 8. 判定与含义

**`S-rise`（T3，P1+P2 同时成立）+ `S-variance`（T2，P1 成立、P2 不成立）同时成立。**

按预注册 §2.1：

- **`S-rise`（T3 35/15/3）**：P1 成立（48.7500 %，p = 0.026731）且 P2 成立
  （极差 6.25 pp）⇒ 判「收紧仍有效」，且**这一档还是稳的**。预注册的下一步是
  降到 **30/10/2**（不在本轮范围）。
- **`S-variance`（T2 40/20/5）**：P1 成立（58.7500 %，p = 1.8946e-05）但 P2 不成立
  （极差 31.25 pp > 20 pp）⇒ 判「期望继续升、方差继续放大」，**不得推荐为默认**。
  这两种判定由**不同的臂**触发，因此两条同时记入 `stop_conditions_held`。
- **`S-turn` 未触发**：预注册把 `S-turn` 定义为「某臂 <39.5833 %」，本轮
  **没有一臂低于 39.5833 %**（最低是 T1 的 46.67 %），所以「50/30/10 是甜点」
  这个结论**不成立**。但预注册想找的**拐点确实出现了**，位置在 **40/20/5**：
  比它更紧的 35/15/3 显著回落 −10.00 pp。**表述上必须分开：S-turn（按冻结定义）
  没触发，而「甜点位置」这件事被本轮数据从 50/30/10 移动到了 40/20/5。**
- **`S-fork` 未触发**（D3 5/5）。

## 9. 不能声称什么（照预注册 §5）

- **不能声称「学会了资源分配」** —— 本轮只改手写阈值，雷是外部规则，不是策略头学出来的；

- **不能声称「通关」**；`bomb_emits` 与 `bombs_used` 不是同一个量，引用「用了几颗雷」
  只能引后者；
- **不能把 T3 的低方差当作「更安全」的机制结论** —— 它只是账面事实，机制未做实验。

## 11. 偏差与限制（必须一起读）

1. **9 路并行，不是 12 路。** 每个进程负责一个完整臂的**全部 4 个窗口**
   （`seed → window → episode`），因此每臂只需 3 个进程（按种子切）。若按
   「臂 × 窗口」切成 12 进程，同一臂的 4 个窗口会落在不同进程里，而生成器是
   **每进程一个、跨窗连续消费**的顺序流，切窗就会改变整条采样序列，也就破坏了
   与 B1（v8.22，同样按种子切 3 进程）和 R0（v8.19，同样）的可比性。
2. **B1 与 R0 都没有重跑。** B1 = v8.22.0 F2 的已发布格（95/240），
   R0 = v8.19.0 S1 的已发布格（58/240），本轮都从各自 240 条原始行重算
   （逐窗 24/26/18/27 与 16/11/11/20、逐种子 40/35/20 与 20/21/17 与
   v8.22/v8.19/v8.20 记录逐位相同），但**不是独立重复**。
3. **别的训练轮把机器占满了。** 开工前 27 台引擎（全部是 `v8m0_bombrl` 训练），
   按项目规则「> 6 先等 5 分钟」等了 **285 s**，复检反而涨到 **53 台**；按 v8.19 的
   先例（等过一轮仍超限，即在保留别人的前提下开工）继续，收尾时 **80 台**。
   全程**没有 `pkill -f`**、**没有触碰别轮进程**，本轮自己的引擎结束时为 **0**。
   这也是本轮单进程墙钟（351–381 s）比 v8.22（170–180 s）慢一倍的原因。
4. **运行器在评测批次之后改过两次，改动范围可核。** 第一次把判定聚合从
   「只看最高臂」改成「P1 与 P2 由同一臂满足即 `S-rise`」（T3 过 P1+P2，
   若按规定只看最高臂 T2 会误判成只有 `S-variance`）；第二次给 `mode_publish`
   补上全部 9 个 progress 文件与 `extra_numbers.json`（继承的 `arm` 变量泄漏只复制
   最后一个臂的 3 个）。两次都只在 `mode_summary` / `mode_publish` 内，`mode_eval`
   段逐字节相同（`rebuild3.sh` 断言），diff 三段全部落盘。
5. **冒烟的那一条活着**（T1/s0/w11，900/900 决策，1,800 帧，3 颗雷全部用掉）。
   冒烟的通过标准是审计与 gate（5 项 checks + 5 项 gate + cfg muted 全过），不是存活。
6. **预注册标题写 `35/15/5`，§1 表格与工单写 `35/15/3`。** 本轮按 §1 表格与工单执行
   **35/15/3**（T3）。若按 35/15/5，第三档门宽 2 px，预期会更常放出去，属于另一格。
7. **12 个（种子, 窗）格不是 12 个独立样本**：同一进程里的 80 条 episode 共用一条
   生成器流，同窗的 60 条共用一个引擎父进程。池化率带精确 CP95，但不构成 240 个
   i.i.d. 样本。**P2 的「极差」是按种子切（每种子 80 条）算的**，与 v8.22/v8.19 口径一致。
8. **`--tag` 唯一性**：9 个进程的 tag 是 `v8o0-{T1,T2,T3}-d900-s{0,1,2}`，
   私有 data 目录 `<work>/data/<tag>/w<window>`、引擎日志 `<work>/runs/<tag>`，
   因此不存在 v8.17.0 那种同秒共用 data 目录的故障模式。
