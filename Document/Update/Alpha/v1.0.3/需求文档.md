## 0. 给零上下文读者的三十秒版本

- 项目：用强化学习/模仿学习让 AI 玩东方 Project（当前是 TH08，目标 Lunatic 通关）。
- **终极目标是纯视觉**：用户框选一块游戏区域，模型只看这块画面就会玩，并能迁移到其它东方作品。
  读内存只是**训练期的特权教师**，部署端一行内存都不许读。
- 已经在真机上跑通的东西：只读状态、按键注入、菜单宏、回放采集、BC、教师策略、视觉分区录制、
  两阶段视觉训练、只用像素的真机评估。
- 现在卡在哪：**视觉学生的空间精度不够**（自机位置误差 71 px），而且实测证明
  "再多采数据也不会变好"，因为瓶颈在架构而不是数据量。
- 因此 v1.0.3 的第一优先级是**改架构并用已有的 7.2 万帧数据验证**，不是继续采集。

## 3. 本版需求（v1.0.3）

按优先级排列。**R1/R2 不占用游戏时间，是必须先做的前置。**

### R1 修正视觉架构（不采新数据）

用现有的 `datasets/pilot-ud0059`（72k 帧）迭代网络结构，直到 S1 达标。已知必须处理的三点：

1. **场地流不能池化到 2×2**：自机是小目标，池化到 4 个空间格等于把位置信息扔掉；
2. **自机坐标改用热图回归**：在保留空间分辨率的特征图上出 heatmap，再用加权期望取坐标，
   而不是从全局池化特征直接回归两个标量；
3. **HUD 两条流用独立小编码器**，不与场地共享权重（它们是文字，和弹幕的统计特性完全不同）。

> 允许改变量：编码器结构、池化方式、损失、学习率、epoch 数。
> 不允许改：观测契约（三个分区的定义）、动作空间、评估口径。

### R2 用同一份数据验证 R1 是否达标

- 固定验证集：manifest 里的 `val_index_sha256`（seed=7, val_fraction=0.1），**不得重新划分**；
- 达标线：**位置误差 < 10 px、danger 相关 > 0.8、0–15 px 桶后悔值 < 1.5 px**；
- 每次尝试约 10 分钟（8 epoch），要求把尝试记录成表（结构 → 指标），不要只留最后一次。

### R3 数据曲线（决定要不要采更多）

在架构达标后，用 1 份 / 4 份 / 10 份数据分别训练，画出「数据量 → 指标」曲线：

- 若指标仍随数据增长 → 才值得执行 R4；
- 若已平台化 → **不要**采全量，改为改架构/改标签。

### R4 全量采集（条件触发，默认不执行）

仅当 R3 证明数据仍是瓶颈时执行。约束：

- 30 Hz（`every=2`）、原生分辨率、三块分区；
- 全量规模：2,290,566 样本、**约 730 GB**、**约 21.3 小时**（回放实时播放，无快进手段）；
- 必须可中断续跑（`tools/collect_all.py` + `collection-registry.json` 已实现）；
- 采集期间机器被独占（失焦会让游戏掉到 14 fps）。

### R5 部署端"只看像素"的真机验证

`python -m touhou_rl.evaluate --vision-checkpoint <ckpt>`，要求：

- 报告里 `policy == "vision"`；
- 该局全程不调用 `state.py`（代码路径保证，不得为了省事偷偷读内存）；
- 存活帧数 > 随机基线 **2,418 帧**（同难度、同机体、同 `max_steps`）。

### R6 文档与过程

- 过程日志按仓库根 `readme.md` 的约定增量写 `Document/Dialogs/`（超过 100 KB 截断归档）；
- 本版需产出：`问题清单.md`、`设计文档.md`、`开发文档/`、`验收文档.md`、`验收报告.md`、`总结报告.md`；
- **每个结论都要给可复现命令与落盘 JSON**，不以自述为准。

## 4. 硬约束（违反即失败）

1. **只读游戏内存**：不 `WriteProcessMemory`、不注入 DLL、不改 `third_party/th08` 任何文件；
2. **部署端不读内存**：视觉策略分支只允许 `session.grab()`，不得调用 `state.py`；
3. **单实例、前台**：同一时刻只能有一个 `th08.exe`，失焦会掉到 14 fps；
4. **原生分辨率录制**：不得在采集时缩小画面；模型侧的分辨率是训练旋钮，可以改；
5. **三块分区定义不变**：`playfield (32,16,384,448)`、`hud_score (424,36,216,34)`、
   `hud_status (424,88,216,126)`；
6. **训练/推理共用同一预处理函数**：v1.0.2 出过一次"推理忘了归一化"的事故；
7. **不用训练指标冒充游戏表现**：验收结论只看真机存活帧数；
8. **数据/权重/截图不入库**：都在子模块 `build/` 下，已被 gitignore；
9. **不做有损压缩**：判定裕度是亚像素级（自机判定半宽 0.825 px）。

## 7. 已踩过的坑（不要重复）

| 坑 | 症状 | 正确做法 |
| --- | --- | --- |
| 末端池化到 2×2 | 位置误差 71 px 且加数据无效 | 保留空间分辨率 / 热图坐标 |
| 按 val loss 选策略模型 | loss 降而 top1、后悔值变差 | 按**后悔值**选 |
| `np.savez_compressed` 存 PNG | 每样本白烧 4.5 ms | PNG 已压缩，用 `np.savez` |
| 取帧用 `delta % every` | 迟采一帧就整轮跳过 | 按绝对目标帧号推进 |
| 速率分母含启动/菜单 | 速率被低估（16.6 vs 29.97） | 按播放时间或游戏帧跨度算 |
| 单线程 PNG 解码 | 6.3 ms/帧，一个 epoch 7 分钟 | 线程池解码 → 0.48 ms/帧 |
| KL 锚定到差先验 | BC 只有随机 55%，越训越死 | 锚到教师蒸馏版或衰减 kl |
| 两套预处理代码 | 推理漏归一化 | 只允许一个 `regions_to_batch` |
| Extra 回放硬写 stage 0 | 菜单宏超时 60 秒 | `--stage -1` 自动取回放第一面 |
| 检查器自己误报 | 好文件被判死 | 先看诊断字段再下结论 |

## 8. 未决问题与建议默认值

| 问题 | 建议默认 | 理由 |
| --- | --- | --- |
| 场地流用什么分辨率 | 224×192（原生 1/2） | 已能表达 10 px 子弹；再大 GPU 吃不消 |
| 三流是否共享权重 | 场地独立、HUD 各自小编码器 | HUD 是文字，统计特性与弹幕不同 |
| 帧堆叠 depth | 先 1，达标后试 3 | depth=3 使每 batch 解码量 ×3 |
| 是否先扩数据 | **先不扩**，用 1 份把架构调对 | 已实测：当前架构加 16 倍数据反而更差 |
| 坐标头形式 | heatmap + 加权期望 | 直接回归会被池化抹平 |
| 全量采集时机 | A-03 判定有收益后再做 | 730 GB / 21.3 小时，代价高 |
