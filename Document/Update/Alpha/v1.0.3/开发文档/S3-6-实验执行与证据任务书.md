## 4. 执行计划（按顺序，不可跳步）

### 4.1 第一步：快速筛选四个配方（批量约 45–50 分钟）

先确认当前代码可跑：`& $py -m pytest touhou_rl/tests -q` 全绿。

创建 `Stage3/recipes.json`，内容如下（**这就是要执行的配方，不得自行增删**）：

```json
{
  "dataset": "third_party/th08/build/rl/datasets/pilot-ud0059",
  "runs_root": "third_party/th08/build/rl/runs",
  "table": "Document/Update/Alpha/v1.0.3/Stage3/实验表.md",
  "recipes": [
    {"id": "R1-a", "arch": "v2", "note": "v2 baseline: 3-stream, stride8 heatmap, sigma1.5, loss 1:1:1",
     "args": {"stage": "both", "epochs_state": 8, "epochs_policy": 8, "batch_size": 96, "depth": 1,
              "train_fraction": 1.0, "max_train_batches": 160, "max_val_batches": 0}},
    {"id": "R1-b", "arch": "v2", "note": "A: depth3 frame stack",
     "args": {"stage": "state", "epochs_state": 8, "batch_size": 96, "depth": 3,
              "train_fraction": 1.0, "max_train_batches": 160, "max_val_batches": 0}},
    {"id": "R1-c", "arch": "v2", "note": "B: heatmap sigma 1.0 (sharper)",

              "train_fraction": 1.0, "max_train_batches": 160, "max_val_batches": 0}}
  ]

```

> `R1-c` 与 `R1-d` 需要 `vision_train` 暴露 `heatmap_sigma` / `w_heatmap` 两个参数。若 S3-3 未暴露，**停下报告 MainAgent**，不要改配方绕开。

预算依据（供你判断是否跑偏，超出 2 倍就停下来查原因）：`R1-a` 两个阶段各 8 epoch（约 19 分钟）；`R1-b/c/d` **只跑 state**（8 epoch，各约 9–10 分钟）。每个 epoch 的训练量 = 160 个训练 batch（约 48 s），验证始终全量 75 个 batch（约 22 s）。若某个配方耗时超过对应预算的 2 倍，先检查 `max_val_batches` 是否为 0、以及是否误跑成了 `both`。

执行：

```powershell

```

记录：四个配方的 `pos_px`、`perframe_median`、`regret_0_15`、耗时。**只有一处变量不同的两行才允许互相比较。**

### 4.2 第二步：胜出配方全量确认（约 60–80 分钟）

- 胜出配方 = 第一步中 `pos_px` 最小者（若差距 < 5%，取 `perframe_median` 更高者；并列时取配方 id 靠前者）；
- 把胜出配方写入新配方文件 `Stage3/recipes-confirm.json`，**配方 id 固定为 `R1-confirm`**：`stage=both`、`max_train_batches=0`、`max_val_batches=0`、`train_fraction=1.0`，其余与胜出配方一致；
- 跑一次。**目录名由工具分配（最低空位），不要假定它是 `v103-exp-05`**；跑完从 `sweep-report.json` 里按 id 取实际路径：

  ```powershell
  $report = Get-Content Document/Update/Alpha/v1.0.3/Stage3/sweep-report.json -Raw | ConvertFrom-Json
  $expConfirm = ($report.entries | Where-Object id -eq 'R1-confirm').out_dir
  ```

若第二步的 `pos_px` 显著差于第一步（> 25%），必须如实记录并说明「小样本筛选不可靠」，**不得**用第一步数字冒充最终结论。

### 4.3 第三步：R3 数据曲线（约 80 分钟）

```json
  {"id": "R3-025", "arch": "v2", "note": "R3 curve at 25% train frames",
   "args": {"stage": "both", "epochs_state": 8, "epochs_policy": 8, "batch_size": 96, "depth": 1,
```

`1.00` 直接复用第二步的 `R1-confirm` 产物（不要重跑）。跑完取实际路径：


要求三次的 `val_frames` 完全相同（都是 7,247），否则停下报告——说明验证集没有固定住。

### 4.4 第四步：真机视觉评估（A-04 的唯一合法证据）

前提：无其它 `th08.exe` 在运行；游戏窗口能被置前；机器独占（失焦会掉到 14 fps）。

```powershell
& $py -m touhou_rl.evaluate `
    --vision-checkpoint $expConfirm/policy.pt `
    --out third_party/th08/build/rl/eval/vision-v103 `
    --episodes 3 --max-steps 4000 --frameskip 2 --difficulty lunatic --device cuda
```

随后折叠成表（含随机基线）：

```powershell
& $py tools/rl/compare_evals.py `
    --run v103=third_party/th08/build/rl/eval/vision-v103/eval-report.json `
    --run random=third_party/th08/build/rl/eval/random/eval-report.json `
    --out third_party/th08/build/rl/eval/comparison-v103-vision.json
```

要求：`eval-report.json` 的 `policy == "vision"`、存在 `vision` 节点（`arch`、`region_sizes`、`depth`）；`comparison` 里 `hit_step_cap` 为 0。

**无法启动游戏时**：把阻塞原因（具体报错、时间、尝试次数）写进 `../问题清单.md` 的置顶区（作为新条目 Q4），并在完成报告里把 A-04 标为 `blocked`。**不得**用训练指标代替真机数字。
