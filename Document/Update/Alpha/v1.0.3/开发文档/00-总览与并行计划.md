## 1. 这一阶段要交付什么

把视觉学生从 v1（末端池化 2×2 + 全局回归坐标）换成 v2（场地流保留空间分辨率 + heatmap 取坐标 + HUD 独立编码器），并在**同一套修好的指标口径**下测出 A-01/A-02 是否达标、R3 数据曲线是否还有斜率。

本阶段**不**采新数据、**不**执行全量采集（R4 是条件动作，需 A-03 判定后再由用户批准）。

**文件所有权是硬约束**：一个文件在同一批次里只能有一个 SubAgent 写。若某 SubAgent 发现必须改别人拥有的文件，停下报告 MainAgent。

## 5. 通用交付要求（每个 SubStage 都适用）

1. **自测**：新功能必须有单元测试，覆盖正常路径 + 至少一个边界或异常；测试必须实际执行并把输出贴进完成报告。
2. **启动测试**：
   - 纯库层 SubStage（S3-1/S3-2）：以「新增单测通过 + 现有 59 条不退化」为启动测试证据；
   - 带 CLI 的 SubStage（S3-3/S3-5）：必须实际跑一次命令——真实数据集上用 `--max-train-batches 20` 之类的小配置，不得只跑合成数据就报完成；
   - 涉及游戏的（S3-6）：必须实际启动游戏并走完视觉策略核心路径。
3. **完成报告**：`Document/Update/Alpha/v1.0.3/Stage3/完成报告-S3X.md`，含：改动文件清单、测试命令与真实输出、启动测试命令与真实输出、偏离任务书之处（必须为零，否则先报告）、遗留问题。
4. **不确定就停**：任务书没写的接口、命名、枚举顺序，按最贴近设计文档的方案自决并写进完成报告；**涉及契约的歧义不得自决**，停下报告。
5. **禁止**：emoji；超出任务书范围的"顺手重构"；修改 `third_party/th08/` 下任何文件；改其它 SubStage 拥有的文件。
