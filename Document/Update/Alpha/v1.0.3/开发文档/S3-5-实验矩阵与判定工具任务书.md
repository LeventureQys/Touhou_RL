## 4. 实现契约

### 4.1 配方文件格式（JSON，由 S3-6 提供内容）

```json
{
  "dataset": "third_party/th08/build/rl/datasets/pilot-ud0059",
  "runs_root": "third_party/th08/build/rl/runs",
  "table": "Document/Update/Alpha/v1.0.3/Stage3/实验表.md",
  "recipes": [
    {
      "id": "R1-a",
      "arch": "v2",
      "note": "v2 baseline: 3 streams, stride8 heatmap, 8 epoch",
      "args": {"stage": "both", "epochs_state": 8, "epochs_policy": 8,
               "batch_size": 96, "depth": 1, "train_fraction": 1.0,
               "max_train_batches": 0, "max_val_batches": 0}
    }
  ]
}
```

- `args` 的键名与 `vision_train` CLI 一一对应，**下划线换连字符**（`train_fraction` → `--train-fraction`）；
- 允许的键集合固定为：`stage, epochs_state, epochs_policy, batch_size, lr, depth, train_fraction, max_train_batches, max_val_batches, seed, note, heatmap_sigma, w_heatmap, w_self, w_danger, pf_width, hud_width`；出现其它键 → `SystemExit(f"unknown recipe arg {key!r}")`；
- `max_val_batches` 若被设为非 0 值，工具必须**拒绝**并给出原因：`SystemExit("max_val_batches must be 0: validation must always be full")`（对应设计文档 §7.4）。

### 4.2 `tools/rl/v103_sweep.py`

```
python tools/rl/v103_sweep.py --recipes PATH [--only R1-a,R1-b] [--dry-run] [--out-json PATH]
```

行为：

1. 读配方文件并校验（未知键、`max_val_batches != 0`、`runs_root` 指向 `pilot-v1` → 全部拒绝）；
2. 对每个配方（按顺序）：
   - 分配目录 `runs_root/v103-exp-<NN>`，`<NN>` 取**最低空位**（该目录不存在，或其中没有 `vision-summary.json`）；**不要用配方在文件里的下标当序号** —— S3-6 会依次跑三份配方文件（筛选/确认/R3），下标方案会让第二份文件从 `01` 重新编号、撞上已冻结目录而被整体跳过；
   - 重入时**按配方 id 续跑**：`sweep-report.json` 里已有 `status: ok` 的 id 直接跳过；
   - **目录与配方的对应关系以 `sweep-report.json` 的 `out_dir` 为准**，不要假定 `v103-exp-05` 一定是某个特定配方；
   - 构造命令并打印完整命令（便于复制复核）；
   - `subprocess.run(cmd, check=False)`；非 0 退出 → 在 `out_json` 里记 `"status": "failed"` 与返回码，**继续跑下一个配方**（不中断整批）；
   - `--dry-run` 时只打印命令，不执行、不写表；
3. 每个配方结束后读该目录的 `vision-summary.json`，追加一行到 `table`（Markdown，表头只在文件不存在时写）：

```markdown
| 序号 | 配方 | arch | 训练帧数 | max_train_batches | 位置误差 px | perframe corr 中位数 | 0-15 桶后悔值 | 用时 s | summary 路径 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
```

   数值取自 `stages.state.best` 与 `stages.policy.best`；缺失字段写 `n/a`（不得让工具崩）；
4. `out_json`（默认 `Document/Update/Alpha/v1.0.3/Stage3/sweep-report.json`）**结构固定**为：

```json
{
  "generated": "2026-10-18T21:00:00",
  "dataset": "...", "runs_root": "...", "table": "...", "dry_run": false,
  "recipes": [ /* 本次调用传入的配方定义，原样保留 */ ],
  "entries": [
    {"id": "R1-a", "index": 1, "arch": "v2", "note": "...", "status": "ok",
     "returncode": 0, "seconds": 640.2, "out_dir": "third_party/th08/build/rl/runs/v103-exp-01",
     "summary": "…/v103-exp-01/vision-summary.json", "metrics": {...}, "command": "…"}
  ]
}
```

   **`entries` 是消费方唯一可用的路径来源**（S3-6 用 `entries[].out_dir` 解析目录）。报告必须**跨次调用合并**：同一配方 id 以最新一次为准，不得因本次只跑一个配方就把之前的记录清空（S3-6 会用三份配方文件分三次调用）；
5. 结论打印：每个配方一行 `id ok/failed pos_px/perframe_median/regret_0_15`。

**必须可重入**：中断后再跑同一份配方文件，已完成的目录被跳过，实验表不重复追加（按 `序号` 去重）。

### 4.3 `tools/rl/check_a01.py`

```
python tools/rl/check_a01.py \
  --summary runs/v103-exp-01/vision-summary.json \
  --summary runs/v103-exp-02/vision-summary.json \
  --primary runs/v103-exp-05/vision-summary.json \
  --r3 0.25=runs/v103-exp-07/vision-summary.json \
  --r3 0.50=runs/v103-exp-06/vision-summary.json \
  --r3 1.00=runs/v103-exp-05/vision-summary.json \
  --out acceptance-v103.json
```

判定规则（**写死，不得改动**）：

| 项 | 通过条件 | 取数位置 |
| --- | --- | --- |
| A-01 | **存在**某个 epoch 同时满足 `pos_px < 10.0` 且 `perframe_median > 0.8` | 该 run 的 `stages.state.history` 逐行扫描（不是只看 `best`） |
| A-02 | `regret_px_bucket_0_15 < 1.5` | 主实验的 `stages.policy.best.by_danger` 里 `bucket == "0-15"` |
| A-03 | 见下 | 三个 `--r3` 点的 `stages.state.best` / `stages.policy.best` |

**A-01 为什么是"存在某轮"而不是"best 那一轮"**：`state.pt` 按 `val_player_pos_px` 选模，联合达标的那一轮可能不是位置最优的一轮（例如第 3 轮 pos=9.5/perframe=0.85、第 5 轮 pos=8.0/perframe=0.70）。只看 `best` 会把唯一同时达标的轮次判掉，造成假失败。判定时：

1. 扫描 `stages.state.history`，**读取的键名是 `val_player_pos_px` 与 `val_danger_corr_perframe_median`**（history 行不存在 `pos_px` / `perframe_median` 这种短名；短名只出现在**输出** JSON 里）。收集所有 `val_player_pos_px < 10.0 且 val_danger_corr_perframe_median > 0.8` 的 epoch；
2. 有则 `a01.status = "pass"`，`a01.epoch` 取其中 **pos_px 最小**者的 epoch，输出时把 `val_player_pos_px` → `a01.pos_px`、`val_danger_corr_perframe_median` → `a01.perframe_median`；
3. 无则 `a01.status = "fail"`，`a01.best_pos_px` / `a01.best_perframe_median` 报告"最接近"的那一轮（先比 pos 达标数，再比 perframe），便于分析；
4. `primary` 节点的 `epoch`/`pos_px`/`perframe_median` 必须与 `a01.epoch` 一致（pass 时），并在 `primary` 里加 `"checkpoint": "state-pass.pt"`；fail 时 `primary` 指向 `best` 那一轮并标 `"checkpoint": "state.pt"`。

**主实验选取规则**（用于 A-01/A-02）：

1. 若传了 `--primary PATH`，直接用该 summary，不再推断（**S3-6 必须显式传**，见其任务书）；
2. 否则在输入 summary 里筛选：`arch == "v2"` 且 `train_fraction == 1.0` 且 `config.max_train_batches == 0`（排除筛选跑）。**不要用 `status` 字段**——summary 里没有 `status` 键，那是 `sweep-report.json` 的字段；无法解析或缺 `stages.state` 的 summary 直接跳过并打到 stderr。在这个集合里取 `stages.state.history` 中 `val_player_pos_px` 最小者；
3. 集合为空 → A-01/A-02 均判 `blocked`，`reason: "no full v2 run (train_fraction=1.0, max_train_batches=0)"`；
4. A-02 还需要该 summary 含 `stages.policy`；若它是 state-only 跑（缺 `stages.policy`），A-02 判 `blocked`，`reason: "primary run has no policy stage"` —— **不得**退而求其次去别的 run 里偷一个数字。

**A-03 规则**：

```
gain_pos    = pos(1.00) <= 0.85 * pos(0.50)
gain_regret = regret_0_15(1.00) <= 0.90 * regret_0_15(0.50)
status = "has_gain" if (gain_pos or gain_regret) else "plateau"
```

- 若三个点不全（缺 0.50 或 1.00）→ `status: "incomplete"`；
- 若 A-01 判 `fail` → `status: "blocked"`、`reason: "A-01 not met; R3 premise (architecture first) unmet"`（对应需求文档 R3「在架构达标后」）；
- `has_gain` 只是「值得补采 3 份做跨回放验证」，**不等于**授权 R4；输出里必须有字段 `"r4_authorized": false` 并附 `note`。

输出 JSON 结构：

```json
{
  "generated": "2026-10-18T20:00:00",
  "inputs": {"summaries": ["..."], "r3": {"0.25": "...", "0.50": "...", "1.00": "..."}},
  "primary": {"path": "...", "arch": "v2", "epoch": 3, "checkpoint": "state-pass.pt",
              "pos_px": 0.0, "perframe_median": 0.0, "regret_px_bucket_0_15": 0.0},
  "a01": {"status": "pass", "epoch": 3, "pos_px": 0.0, "perframe_median": 0.0,
          "best_pos_px": 0.0, "best_perframe_median": 0.0,
          "thresholds": {"pos_px": 10.0, "perframe_median": 0.8}},
  "a02": {"status": "pass", "regret_px_bucket_0_15": 0.0, "threshold": 1.5},
  "a03": {"status": "has_gain", "points": [{"fraction": 0.25, "train_frames": 16306,
                                            "pos_px": 0.0, "regret_px_bucket_0_15": 0.0}],
          "rule": "pos(1.00) <= 0.85*pos(0.50) or regret(1.00) <= 0.90*regret(0.50)"},
  "r4_authorized": false,
  "note": "A-03 has_gain only authorizes collecting 3 more replays for a cross-replay curve"
}
```

- 退出码：`a01.status == "pass"` 且 `a02.status == "pass"` → 0，否则 1（便于脚本串联）；
- 任何输入文件缺失或 JSON 缺关键字段 → 打到 stderr 并退出码 2，**不得**静默把缺失当 0。

### 4.4 容错约定

- summary 里 `stages.state.best` 缺失 → 视为该项 `blocked`，`reason` 说明缺哪个键；
- `danger_corr` 存在但 `perframe_median` 缺失 → **判 `blocked`**（不是 `fail`：这种情况是"无法判定"而非"判定为不达标"）。关键是两条红线：**绝不判 pass、绝不退回全局 `danger_corr`**（这是 Q2 裁决的核心，防止口径偷偷回退）。`acceptance-v103.json` 的 `a01.reason` 必须写明缺的是 `val_danger_corr_perframe_median`；
- summary 的 `schema` 不是 `vision-summary/2`、或 `arch` 不是 `v2`、或缺 `stages.state` → 打印 warning 到 stderr 后**跳过**该文件（不参与主实验推断）；若跳过后候选为空，则 A-01/A-02 判 `blocked`；
- `by_danger` 里找不到 `"0-15"` 桶 → A-02 `blocked`。
