## 4. 反向检查：有没有「设计里做了但需求没要求」的东西

| 设计内容 | 是否超出需求 | 判断 |
| --- | --- | --- |
| 三流独立编码器 + heatmap + danger 空间头 | 否 | R1 明文要求 |
| `state-pass.pt` | 是（机制层面） | 必要：否则 A-01 可能假失败且 A-04 无可部署权重。属实现正确性，不改变需求 |
| `--train-fraction` / 分层嵌套子采样 | 否 | Q3 裁决的落地方式 |
| `--max-train-batches` / `--max-val-batches` 分离 | 是（工程层面） | 必要：否则筛选跑的 val 被切小，指标不可比 |
| `env_factory` 注入 | 是（可测性） | 必要：否则「只看像素」无法自动化验证（需求 R5 要求代码路径保证） |
| depth 跟随 checkpoint | 是（缺陷修复） | 必要：否则 R5 的命令直接崩 |
| `vision_metrics` 独立模块 | 是（结构层面） | 必要：训练与判定工具必须共用同一口径，否则 A-01 会出现两套实现 |
