## 1. 背景与目标（无需任何对话历史）

视觉学生现在只有一个训练入口 `touhou_rl/vision_train.py`。它有四个必须修的问题（均已裁决），外加一个为架构迭代服务的新参数：

1. **验证集没有门禁**：`vision_train.py:226-230` 自己用 `default_rng(7).permutation(total)` 重算划分，不读 `manifest.json`。实测当前它与 manifest 恰好同集（7,247 帧），但两处独立实现随时会漂移，而需求要求「不得重新划分」。
2. **state 选模口径与验收口径不一致**：`vision_train.py:361` 按混合 `val_loss` 选 `state.pt`，而 loss 被 128 维 danger 项主导；A-01 判的是位置误差与 danger 两个指标。
3. **best epoch 的指标没落盘**：`vision_train.py:399-412` 只把最后一轮的 `by_danger` 写进 `final`，而 `policy.pt` 存的是 best-regret epoch，导致验收数字与权重对不上。
4. **弹量指标取错通道**：`vision_train.py:158` 用 `[:,13]`（恒为 1.0 的死通道），应为 `[:,14]`。
5. **train/val 批次限制耦合**：`vision_train.py:262-271` 的 `batches()` 同时限制 train 与 val，筛架构时 val 被切小，指标不可比。

**你的目标**：改造 `vision_train.py`，让它支持 v2 架构（含 heatmap 损失）、manifest 门禁、三档训练数据、正确的选模与落盘，并提供 S3-5/S3-6 要消费的 CLI 与 JSON schema。你**不**需要跑完整训练实验。

### 4.4 state 阶段（v2 的三项损失）

每个 batch：

```python
out = model.decode_state(batch)
truth_self = labels["self_feat"]          # [B,24] float32
truth_danger = labels["danger"]           # [B,16,8] uint8

loss_danger = smooth_l1(out["danger_log"].reshape(B,16,8), torch.as_tensor(_danger_target(truth_danger)))

if "heatmap_logits" in out:               # v2
    grid_h, grid_w = model.config.heatmap_hw      # 只在 v2 分支里取，v1 没有这个属性
    tgt = heatmap_target(truth_self[:,0], truth_self[:,1], grid_h, grid_w, sigma=cfg.heatmap_sigma)
    tgt = torch.as_tensor(tgt, device=device)                       # [B, H*W]
    logp = torch.log_softmax(out["heatmap_logits"].flatten(1), dim=-1)
    loss_heat = -(tgt * logp).sum(-1).mean()
    loss_self = smooth_l1(out["self_feat"][:, 2:24], torch.as_tensor(truth_self[:, 2:24]))
    loss = cfg.w_heatmap * loss_heat + cfg.w_self * loss_self + cfg.w_danger * loss_danger
else:                                     # v1（回归兼容路径；w_danger 默认 1.0 时与旧版一致）
    loss_self = smooth_l1(out["self_feat"], torch.as_tensor(truth_self))
    loss = loss_self + cfg.w_danger * loss_danger
```

- 权重默认 `w_heatmap = w_self = w_danger = 1.0`，加进 `VisionTrainConfig`。
- 梯度裁剪 `clip_grad_norm_(model.parameters(), 1.0)`、`AdamW(lr, weight_decay=1e-4)` 保持 v1 行为。
- 验证行必须同时收集 `pred_self`、`pred_danger`、`heatmap_logits`，调用 `vision_metrics.all_state_metrics(...)` 得到指标字典。

### 4.5 指标与 summary（跨 SubStage 契约 C3）

- **删除** `_state_metrics` / `_danger_metrics` / `_nearest_bullet` / `_policy_metrics` 的本地实现，改为调用 `vision_metrics`（policy 用 `policy_metrics`）。`_danger_target` / `_gather` / `teacher_values_for` 保留。
- 每个 epoch 的 val 行必须含（字段名精确）：
  state：`val_frames, val_self_mae, val_player_pos_px, val_player_pos_p95_px, val_ray_mae, val_bullet_count_mae, val_danger_mae_log, val_danger_corr, val_danger_corr_perframe_mean, val_danger_corr_perframe_median, val_danger_corr_perframe_valid, val_danger_iou, val_danger_cell_acc`（v2 再加 `val_heatmap_hit_rate`）。
  policy：`val_frames, val_top1, val_regret_px, val_regret_px_bucket_0_15, by_danger`。
  `val_frames` 必须是**本 epoch 验证实际用到的帧数**（正常情况下恒等于 `len(val_idx)`），这样「val 没被切小」可以被逐 epoch 核对。
- `by_danger` 每个 epoch 都要写（5 个桶，空桶也出现）。
- summary 顶层必须含 `"schema": "vision-summary/2"`、`"arch"`、`"note"`、`"train_fraction"`、`"manifest_verified"`、`"val_index_sha256"`、`"parameters"`、`"frame_shape"`、`"started"`、`"finished"`，以及 `stages` 下的 `history` / `best` / `final`（结构见 `../设计文档.md` §7.2）。
- summary 顶层还必须含 `"config"`，内容至少为：`{"stage","epochs_state","epochs_policy","batch_size","lr","depth","max_train_batches","max_val_batches","heatmap_sigma","w_heatmap","w_self","w_danger","pf_width","hud_width"}`。**`max_train_batches` 是必需的**：S3-5 用它把「筛选跑」与「全量确认跑」区分开，缺了会导致主实验选错。

### 4.6 选模与落盘（D2 + D4）

| checkpoint | 写盘条件 | 内容 |
| --- | --- | --- |
| `state.pt` | `val_player_pos_px` 创新低 | `extra={"stage":"state","epoch":E,"arch":arch,"train_fraction":f,"val_index_sha256":sha,**val_row}` |
| `state-bestdanger.pt` | `val_danger_corr_perframe_median` 创新高 | `extra={"stage":"state-danger","epoch":E,...}` |
| `state-pass.pt` | **首次**同时满足 `val_player_pos_px < 10.0` 且 `val_danger_corr_perframe_median > 0.8` | `extra={"stage":"state-pass","epoch":E,"a01":{"pos_px":…,"perframe_median":…}}`；只写第一次，不覆盖 |
| `policy.pt` | `val_regret_px` 创新低 | `extra={"stage":"policy","epoch":E,...}` |
| `best.pt` | 每次以上任一刷新 | 与最后执行阶段一致（兼容保留，不作验收依据） |

`state-pass.pt` 的理由（必须实现，不要省）：A-01 要求两个阈值同时满足，而 `state.pt` 只按位置选。若第 3 轮 pos=9.5 / perframe=0.85、第 5 轮 pos=8.0 / perframe=0.70，按位置选会丢掉唯一联合达标的权重，导致 A-01 假失败且 A-04 无可部署 checkpoint。阈值 `10.0` / `0.8` 必须写成模块级常量 `A01_POS_THRESHOLD = 10.0`、`A01_PERFRAME_THRESHOLD = 0.8`，供 S3-5 与验收引用同一数值。

- `summary["stages"]["state"]["best"]` = 被写入 `state.pt` 的那一行的**完整指标 + epoch**；`policy` 同理写 `best`（含 `by_danger`）。
- `summary["stages"]["policy"]["final"]` 保留最后一轮，但**验收不读它**。
- **拒绝覆盖**：`cfg.out` 解析为绝对路径后，若等于或位于 `third_party/th08/build/rl/runs/pilot-v1` 之内 → `SystemExit("refusing to overwrite the v1.0.2 evidence baseline runs/pilot-v1")`。
- 允许 `cfg.out` 已存在（继续写）；但若目录里已有 `vision-summary.json` 且 `--arch`/`--train-fraction` 不同，仍然继续并覆盖 summary（实验脚本会保证目录唯一）。

### 4.8 错误行为总表

| 情况 | 行为 |
| --- | --- |
