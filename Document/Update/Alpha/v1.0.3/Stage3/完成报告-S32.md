| 规则（任务书 §4.2） | 实现 |
| --- | --- |
| 1 `fraction` 越界抛 `ValueError(f"fraction must be in (0, 1], got {fraction}")` | 先判 `0.0 < fraction <= 1.0`，消息用原始入参 |

## 5. 自决项（任务书未规定或存在两种读法的实现细节）

1. **`policy_metrics` 最后一桶的边界**：v1 用 `danger < high`，当 `high = inf` 时「64 个槽全无效 -> 距离 inf」的帧不会落入任何桶（v1 因此会悄悄丢帧）。任务书 §5 测试 10 明确要求「bullets 全 invalid -> 只有 `120+` 桶有帧」，故实现为：最后一桶判据 `danger >= 120`（无上界），其余桶仍用 `[low, high)`。这是对 v1 的一处**有意**偏离，同时修掉了 v1 的丢帧问题；由单测 `test_policy_metrics_bucket_labels_and_empty_buckets` 锁定。
2. **`stratified_prefix` 的 RNG 用法**：按任务书 §4.2 规则 4「同一个 `default_rng(seed)` 依次 `permutation`」的字面实现——一个 rng 实例在 stage 循环外创建，按 stage 升序依次消费。设计文档 §6.2 的措辞也可读成「每个 stage 新建同 seed 的 rng」；两种读法的可观察契约（同 seed 可复现、分层、嵌套、`fraction=1.0` 集合相等）完全相同，只有具体抽中哪些索引不同。若 S3-3 需要另一种读法，只需在循环内建 rng（1 行）。
3. **`stage_of` 的整数化**：`meta` 是 `float32`，用 `np.rint(...).astype(np.int64)` 而非直接 `astype`，避免 `2.9999998` 之类截断成 1；对整数值完全相同。
4. **`stage_of` 的形状**：支持 list / 任意形状 `ndarray`，返回形状同入参（契约「形状同 indices」），`dtype` 恒为 `int64`。
5. **`player_pos_px` 上报位数**：聚合函数直接转发 `player_position_mae_px` 的 4 位结果，而 v1 的 `_state_metrics` 写 2 位。`§7.2` 未规定位数，4 位是 `player_position_mae_px` 的显式契约；对 70.97 的可比性无影响（前两位一致）。
6. **帧数不一致**：`danger_metrics` / `policy_metrics` 在 pred 与 truth 帧数不等时抛 `ValueError`（带两方帧数），而不是静默广播/截断——错位的指标比报错更贵。契约未规定该分支。
7. **`N == 0` 兜底**：`ray_mae` / `self_mae` / `heatmap_hit_rate` 也按「不得出现 NaN」的总要求返回 `0.0`（任务书只显式规定了 `player_position_mae_px` / `danger_metrics` / `bullet_count_mae`）。`_as_2d` 对 1 维输入按单帧处理、对空输入不抛异常。
8. **多出的 2 条补强测试**：任务书 §5 未给 `all_state_metrics` 单独测试、也未测 `N==0` 全路径的 NaN 约束，因此加了 `test_all_state_metrics_keys`（键集合与 §7.2 一一对应）与 `test_metrics_never_return_nan`。条数仍满足「>= 12 且全绿」。
