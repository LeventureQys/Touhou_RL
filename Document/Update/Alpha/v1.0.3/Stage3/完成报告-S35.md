## 4. `r4_authorized` 恒为 false 的证据

1. 源码只有一处赋值，是字面量 `False`（`check_a01.py:505`），a03 的任何状态都不参与该字段的计算：

   ```python
   495:    document = {
   ...
   502:        "a01": a01,
   503:        "a02": a02,
   504:        "a03": a03,
   505:        "r4_authorized": False,
   506:        "note": R4_NOTE,
   507:    }
   ```

   `Select-String -Path tools\rl\check_a01.py -Pattern 'r4_authorized'` 的**全部** 2 条命中：模块 docstring 说明（第 23 行）、`document` 里的 `False`（第 505 行）——没有任何读取/计算路径会把它写成 `true`。

2. 三条不同结论的实测输出都带 `"r4_authorized": false`：
   - `has_gain`（§7.2 合成主实验，退出码 0）：`"r4_authorized": false`；
   - `blocked`（§7.3 真实 pilot-v1，退出码 1）：`r4_authorized = False`；
   - 无 `--out` 时打印到 stdout 的 JSON（`test_r4_authorized_is_false_without_out_file` 断言含 `"r4_authorized": false`）。
3. `note` 固定为 `A-03 has_gain only authorizes collecting 3 more replays for a cross-replay curve`（对应设计文档 §6.3 的 Q3 裁决），`test_a03_has_gain_by_position` 断言 `"3 more replays" in doc["note"]`。

## 8. 自决区决策记录（任务书未规定，或需在两种读法中选一种）

| 编号 | 问题 | 决策 | 理由与风险 |
| --- | --- | --- | --- |
| D1 | 任务书 §4.4 写「`danger_corr` 存在但 `perframe_median` 缺失 → 必须 fail」，而 §5 第 4 条写 `→ blocked` | 判 `blocked`（`check_a01.py:172-178`） | 两处措辞冲突；§4.4 的「fail」按「不得判 pass」理解即与 `blocked` 相容，而 §5 第 4 条、任务书 §4.3 判定表与上级指示都明确要求 `blocked`。风险：若验收方按字面要求 `status == "fail"`，需要改一行状态字面量；判定行为（不判 pass、不读全局 `danger_corr`）不变 |
| D2 | 目录序号如何分配：任务书「从 01 开始，跳过已存在且含 summary 的目录」有两种读法（按配方下标 vs. 最低空位） | **最低空位 + 按配方 id 续跑**（`allocate_dir` + `prior_dirs`） | 按配方下标编号会让 S3-6 的第二个配方文件（确认跑）重新从 01 开始，撞上已冻结的 `v103-exp-01` 而被整体跳过，确认跑永远不会执行；S3-6 §4.2/§4.3 也写明「或下一个空闲序号」并期待 01-04 / 05 / 06-07 连续编号。重入时优先复用 `sweep-report.json` 里该 id 已记录的目录，保证「同一份配方文件重跑不换目录」。风险：`sweep-report.json` 被删除后重跑，会从最低空位重新分配（已完成目录仍因含 summary 被跳过，不会重训） |
| D3 | 实验表行已存在时是「跳过」还是「覆盖更新」 | **只跳过，不覆盖**（`write_table_row` 返回 `present`） | S3-6 禁止事项 5「不得在实验表里删行或改历史行的数字（只允许追加）」；覆盖会改历史数字。风险：若同一序号的结果后来变了（只在目录被手工删除时可能），表里的行会保持旧值 |
| D4 | `--dry-run` 是否写 `out_json` | **写**，条目 `status: "dry-run"`、`metrics: {}`、`returncode: null`，不建目录、不写表 | 任务书 §5 第 13 条要求「`out_json` 内容只有命令」，说明干跑要写报告；同时保证干跑不产生任何真实产物 |
| D5 | `out_json` 跨多次调用是覆盖还是累积 | **按配方 id 累积合并**；干跑条目**不覆盖**已有的真实条目 | S3-6 要跑三次 sweep（筛选 / 确认 / R3）且共用同一个默认报告路径，覆盖会丢掉前两批记录。风险：同一 id 重新真跑会替换旧条目（这是期望行为） |
| D6 | 配方校验的额外项（id 唯一、arch ∈ {v1,v2}、args 值类型、`--only` 未知 id） | 全部 `SystemExit` 拒绝，先校验后执行 | 任务书只列了未知键与 `max_val_batches`；补这几条是为了在执行 GPU 之前暴露配方笔误。风险：若 S3-6 之后要加新 arch（例如 `v3`），需同步 `ARCHES` |
| D7 | 是否需要 `--max-val-batches` 显式出现在命令里 | **总是输出 `--max-val-batches 0`**（即使配方没写） | 设计文档 §7.4「实验脚本必须显式设为 0」。这正是首版测试抓到的问题：漏写时命令里没有该参数，验证集大小就靠默认值，一旦默认改了就会悄悄变口径。风险：打印的命令比配方文件多一个参数（值恒为 0，不改变行为） |
| D8 | `status` 取值集合（任务书只提 `ok/failed`） | 额外引入 `skipped`（已冻结）、`dry-run`（干跑）、`no-summary`（返回码 0 但目录里没有 summary） | 三者都不能伪装成 `ok`：`no-summary` 若不单列，S3-6 会把一次没有产物的「成功」当成功。`no-summary` / `failed` 都会让整批返回码为 1 |
| D9 | `v103_sweep.py` 自身的退出码（任务书未规定） | 全部尝试成功 → 0；任一 `failed` / `no-summary` → 1；干跑 → 0 | 让 S3-6 能用 `$LASTEXITCODE` 判断整批是否干净，同时不中断整批执行（任务书要求继续跑下一个配方） |
| D10 | A-03 的判定顺序：A-01 未通过 与 R3 点缺失谁先 | A-01 `fail`/`blocked` → `blocked`（先判前提），再判缺 1.00/0.50 → `incomplete` | R3 的前提是「架构先达标」（需求文档 R3），前提未满足时算收益曲线没有意义。测试第 10 条（`incomplete`）在 A-01 pass 的前提下构造，两种顺序都能通过 |
| D11 | A-01 `fail` 时「最接近那一轮」的精确定义 | 排序键 `(达标阈值数 降序, perframe 降序, epoch 升序)` | 任务书只说「先比 pos 达标数，再比 perframe」；把「达标数」实现为「两个阈值中满足的个数」，平票时偏向 per-frame corr，再平票取早轮（保证确定性）。风险：若验收方期望平票时偏向位置，会看到不同的 `best_pos_px`；`best_*` 只用于分析，不参与判定 |
| D12 | 主实验推断时缺 `train_fraction` / `config.max_train_batches` 怎么办 | 视为「无法证明是全量跑」→ 跳过 + stderr | 设计文档 §7.2 要求这两个字段必在 schema/2 里；缺失说明是旧 schema 或残缺文件，不能拿来当主实验。风险：过度保守会漏选（会打 stderr，S3-6 显式传 `--primary` 时不受影响） |
| D13 | A-01 为 `blocked` 时 A-02 是否也 blocked | A-02 **独立判**（只要主实验存在且有 `stages.policy`） | A-02 只依赖 policy 阶段，与 per-frame 口径无关；强行一起 blocked 会掩盖一个本来已经能判的结论。任务书只要求「无主实验」时 A-01/A-02 都 blocked |
