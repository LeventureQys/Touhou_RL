### 2.2 网络结构（§4.2）

| 分支 | 实现位置 | 实测形状（默认配置） |
| --- | --- | --- |
| playfield 主干 4 卷积，总 stride 8 | `vmodels2.py:158-177`（`body`） | `(224,192) -> (112,96) -> (56,48) -> (28,24) -> (28,24)` |
| heatmap_head：`Conv2d(96->1,1)` + `squeeze(1)` | `vmodels2.py:177,181` | `[B,1,28,24] -> [B,28,24]` |
| danger_head：`AdaptiveAvgPool2d((16,8))` + `Conv2d(96->1,1)` + `flatten(1)` | `vmodels2.py:178-180,183` | `[B,1,16,8] -> [B,128]`（行主序） |
| global_pool：`AdaptiveAvgPool2d((2,2))` + `Linear(384->128)` + ReLU | `vmodels2.py:183-189` | `[B,128]` |
| hud_score：`width=16`，3 卷积 + `AdaptiveAvgPool2d((2,8))` + `Linear(768->64)` | `vmodels2.py:186-209`，实例化 `vmodels2.py:225` | `(34,216)->(17,108)->(9,54)->(5,27)->768->64` |
| hud_status：结构相同、权重独立，`AdaptiveAvgPool2d((8,4))` + `Linear(1536->64)` | 同上，实例化 `vmodels2.py:226` | `(126,216)->(63,108)->(32,54)->(16,27)->1536->64` |
| fusion `ReLU(Linear(256->256))` | `vmodels2.py:227-228` | `[B,256]` |
| `self_head`：`ReLU(Linear(256->256)) -> Linear(256->22)` | `vmodels2.py:229-237` | `[B,22]` |
| `candidate_embed`：`Embedding(18,64)`；`score_head`：`320->64->1` | `vmodels2.py:238-244` | `[B,18]` |

细节要求核对：

- 三分支是三个独立 `nn.Module` 实例（`self.playfield` / `self.hud_score` / `self.hud_status`），HUD 两路参数张量 `data_ptr` 集合不交（`test_hud_branches_are_independent` 断言）；
- 768/1536/384 全部由 `width*3*pool_cells` 与 `pf_width*3*4` 推导（`vmodels2.py:183-189, 202-204`），未硬编码；`test_hud_branches_are_independent` 另按 `hud_width*3*2*8` 与 `hud_width*3*8*4` 断言出入口宽度，`test_danger_head_regional_alignment` 断言 `AdaptiveAvgPool2d` 输出格数随 `danger_rows/danger_cols`；
- 未对 `AdaptiveAvgPool2d((16,8))` 做裁剪/插值「修正」。

1. **模块划分与命名**：`PlayfieldBranch`、`HudBranch`、`VisionScorerV2` 三个类，加 `PLAYFIELD_VEC=128` / `HUD_VEC=64` / `PLAYFIELD_STRIDE=8` / `PLAYFIELD_POOL` / `HUD_SCORE_POOL` / `HUD_STATUS_POOL` / `SELF_HEAD_DIM` 七个模块级常量。任务书只规定形状与参数量，未规定类名；`VisionScorerV2` 的**公共方法名**严格按 §4.4。
2. **`_as_batched` 放模块级私有函数**（`vmodels2.py:139-144`）而不是像 v1 那样挂在 encoder 上，因为 v2 的预处理由 `VisionScorerV2` 在分派到三个分支前统一做一次；行为与 v1 的同名静态方法逐句等价（4 维补 batch、`permute+reshape` 成 `depth*3` 通道）。
3. **`load_vision_checkpoint` 返回注解改为 `tuple[nn.Module, dict]`**：该函数现在按 `arch` 返回两种模型类，原注解 `tuple[VisionScorer, dict]` 会变成错的说法。纯注解改动，无运行时影响；未用前向引用（`"VisionScorerV2"`）以避免 `typing.get_type_hints()` 在未 import 该名字时抛 `NameError`。
4. **tuple 还原的位置**：写在 `vmodels.py` 的 v2 分派分支里（`vmodels.py:247-252`，三个 `*_hw` 字段），没有给 config 加 `from_dict` 之类的额外 API——任务书 §4.5 只要求「tuple 字段需 `tuple(...)` 还原」，未规定住哪；放在加载侧可保证 `VisionNetConfigV2(**config)` 仍是唯一构造入口。
5. **多出 2 条测试**（共 12 条，任务书要求 >= 8）：
   - `test_v2_error_behaviour`：§4.4 的错误消息是跨 SubStage 契约（S3-3 会依赖 `RuntimeError` 文本判断 `state_head`），任务书 §5 的 10 条没有覆盖它，故补一条锁住两条消息的精确格式；
   - `test_v1_param_count_unchanged`：本 SubStage 是唯一会改 `vmodels.py` 的 SubStage，用设计文档 §3.6 给出的 `707129` 作为 v1 参数量哨兵，防「顺手优化 v1」导致的静默回归。
6. **任务书 §5 第 10 条的取舍**（按要求写进报告）：随机初始化模型**无法**验证 danger 定位质量，因此该测试只断言「形状 + 有限性 + `AdaptiveAvgPool2d` 输出格数随配置」并不断言质量；定位质量留给 S3-6 的实验判定。另：该条的「所有参数 grad 非 None」在单条损失路径下**字面不可满足**——`state` 路径不经过 `candidate_embed`/`score_head`，`policy` 路径不经过 `self_head`/`heatmap_head`/`danger_head`。实现取三层覆盖：(a) 三条损失合成一次 backward 后断言 **41/41 全部参数**非 None（这是「所有参数」唯一有意义的口径）；(b) 只走 state 路径时，断言该路径上的 8 个参数前缀（含 `playfield.heatmap_head`、`playfield.danger_head`、`self_head`）全部非 None；(c) 只走 policy 路径时，断言该路径上的 7 个参数前缀（含 `candidate_embed`、`score_head`）全部非 None。上界比字面要求更严，不是放宽。
7. **`heatmap_target` 的数值精度**：内部全程 `float64` 计算再 `astype(np.float32)`，避免 float32 累加让「每行和为 1（atol=1e-5）」在极端分布上擦边。返回值 dtype 仍是 `float32`（契约）。
8. **`heatmap_target` 的长度检查**：`rx`/`ry` 长度不一致时抛 `ValueError`（任务书未规定该分支）；错位的目标比报错更贵。其余入参不做校验（`clip` 已吸收越界坐标）。
9. **`decode_position` 的 dtype**：`arange` 用 `heatmap_logits.dtype`，因此 fp16/bf16 输入也能跑；默认 fp32 下与契约公式逐位一致（`test_decode_position_recovers_peak` 在 1e-4 内）。
