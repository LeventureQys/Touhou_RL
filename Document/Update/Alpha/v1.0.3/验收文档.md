## 3. 验收项

### V-01 · 视觉架构 v2 的形状、参数与流独立性

- **目的**：确认 R1 的三条要求真的落到了模型结构上，而不是只写在文档里。
- **步骤**：
  1. `& $py -m pytest touhou_rl/tests/test_vmodels2.py -q`
  2. `& $py -c "from touhou_rl.vmodels2 import VisionScorerV2,VisionNetConfigV2; m=VisionScorerV2(VisionNetConfigV2()); print(m.num_parameters()); print(m.config.heatmap_hw)"`
  3. `grep -n "adaptive_avg_pool2d\|AdaptiveAvgPool2d" touhou_rl/vmodels2.py`
- **期望结果**：测试全绿；参数量在 `[450000, 650000]`；`heatmap_hw == (28, 24)`；`vmodels2.py` 中不存在把场地流特征池化到 `(2,2)` 之外的唯一空间出口——即 `heatmap_head` 与 `danger_head` 均直接接在 `(28,24)` 特征图上。
- **通过标准**：三条同时满足，且 `grep` 结果**恰好 4 处** `AdaptiveAvgPool2d`：`danger_head` 的 `(16,8)`、`global_pool` 的 `(2,2)`、`hud_score` 的 `(2,8)`、`hud_status` 的 `(8,4)`。后两处是 HUD 出口，HUD 不需要空间定位，池化不影响 R1-1；关键约束是**位置坐标只能来自 `heatmap_head`**（它直接接在 `(28,24)` 特征图上，无池化）。
- **失败标准**：参数量越界；`heatmap_hw != (28,24)`；位置只能从全局池化向量得到。
- **证据要求**：pytest 输出、参数量打印、grep 输出（含行号）。

### V-16 · 采集完整性（Q4 之后新增，任何采集任务都必须执行）

- **目的**：确认数据集里没有「画面冻结、标签前进」的坏样本。v1.0.3 的 `pilot-ud0059` 有 73% 这样的样本，
  使 A-01/A-02/A-04 的判定与 v1.0.2 的核心结论同时失效（见 `问题清单.md` Q4 与 `根因分析-数据冻结与解码错配.md`）。
- **步骤**：
  1. 读 `<dataset>/capture-report.json`：`frozen_frames`、`longest_identical_run`、`window_hidden_events`；
  2. 独立复核（不依赖检测器）：随机抽 3 个分片，逐帧算 `playfield` PNG 的 SHA-256，要求每个分片的唯一哈希数 == 帧数；
  3. 复核标签确实在前进：同一分片内 `meta.frame` 单调递增、`self_feat` 唯一值数 > 1。
- **期望结果**：`frozen_frames == 0`、`longest_identical_run <= 2`、`window_hidden_events == 0`；
  抽样分片的唯一哈希数等于帧数。
- **通过标准**：三条全部满足。
- **失败标准**：任一计数非零；任一抽样分片出现重复哈希；采样图为 CPU 边界情形（例如分片首帧不唯一）。
- **证据要求**：`capture-report.json` 全文 + 抽样分片的哈希统计输出。
- **备注**：本项在 v1.0.3 的原始数据集上是**失败**的，这正是 Q4 的发现方式。

## 5. 失败与阻塞处理

| 情形 | 处理 |
| --- | --- |
| 单测失败 | 回对应 SubStage 修，重试上限 3 次；3 次后暂停并重新拆分 |
| A-01 未达 < 10 px | 先检查是否 stride 8 已生效（V-01）；再按设计文档 §12 的退路下探 stride 4（需新增 SubStage 并报告用户）；不得直接判「架构方向错误」 |
| A-01 位置达标但 per-frame corr 未达 0.8 | 判 A-01 失败；报告中给出 per-frame corr 的分布（mean/median/p10），并说明是定位精度不足还是危度图分辨不足 |
| A-02 未达 1.5 px | 记录实测；不得用 top1 替代 regret |
| A-03 `incomplete` | 补跑缺失数据点；不得用插值或推断填数 |
| 真机无法启动 | 记录具体报错与尝试次数，写入 `问题清单.md` 置顶区（新条目），V-09 判 `阻塞` |
| GPU 不可用 | V-06/V-07/V-08 判 `阻塞`；V-01…V-05、V-11…V-15 仍须执行 |
| manifest 与磁盘不符（分片被删/改） | 判 `阻塞`，先查清是谁动了数据集，不得重跑 process 掩盖 |
| 发现契约不一致（文档互相矛盾） | 判 `阻塞`，要求 MainAgent 更新设计文档与任务书，不得自选一种解释 |
