# 预注册 v820-BOMBLETH-001：只在「真的要死」时放雷（lethal-only），并把预算推到 1,500 决策

冻结时刻：2026-11-22（Asia/Shanghai），**在任何 v8.2.0 结果之前**。
状态：**FROZEN**。

---

## 0. v8.0.0 / v8.1.0 给出的两个事实

1. **放雷把冻结策略从 13.44% 推到 100%（600 帧）**；机制是「段首一颗雷清屏 + 无敌」——A0 的 3,600 条逐条与 v4.5.0 相同，A1–A3 全部 3,600/3,600。
2. **预算拉长后出现真实的墙**（v8.1.0 收尾中，已见的数）：

| 预算 | 有雷（A3，80 px）活满 | 无雷（A0）活满 |
| --- | ---: | ---: |
| 600 决策（20 s） | **100.00%** | 13.4444%（v8.0.0） |
| 900 决策（30 s） | **99.35%** | 0/1,200（v5.4.0） |
| 1,200 决策（40 s） | **67.96%** | **0.17%**（本轮实测 2/1,200） |

- **每一档的用雷都是 3/3（耗尽）**——也就是说 80 px 规则**把雷浪费在不需要的时候**（v8.0.0 审计：A3 的 55,442 次按键只有 6,288 次被接受，其余 49,154 次是空按）。

**所以本轮的问题：如果只在「真的会死」的那一刻放，同样的 3 颗雷能撑多远？**

---

## 1. 设计（单因子：放雷触发条件）

| 臂 | 触发条件 |
| --- | --- |
| **L1** | **只在 lethal 接触时**放雷：最近子弹距离 ≤ **3 px**（玩家判定半径 2 px + 1 px 余量），且还有雷 |
| **L2** | 同上，阈值 **5 px** |
| **L3（对照，沿用 v8.0.0）** | 80 px（已知在 1,200 决策会耗尽） |

- 策略：v4.5.0 的 `S` 三个 checkpoint（冻结、stochastic）。
- 预算：**600 / 900 / 1,200 / 1,500 决策**（20 / 30 / 40 / 50 s）。
- 评测：4 dev 窗口 × 每格 300 条 × 3 种子；起点 frame 8663。
- **关键实现点**：v8.0.0 的记录里已经有 **lethal-only 最近距离**（`decisions_below_threshold_lethal` 与 `emit_nearest_lethal_px`），本轮必须用**同一口径**（只看 lethal 子弹），而不是全部子弹。

## 2. 判据

| # | 终点 | 判据 |
| --- | --- | --- |
| **P1（主）** | 1,200 决策下活满整段率 | **L1 或 L2 > L3（67.96%）**；单侧 Fisher（Holm 校正） |
| **P2** | 1,500 决策下活满整段率 | 三条臂各给率；与「无雷」的 0.17%（1,200）/（1,500 实测）比较 |
| **P3** | 同预算下的用雷分布 | 描述性：lethal-only 是否真的省雷（预期 1–2 颗而非 3 颗） |

### 2.1 停止条件

| # | 条件 | 动作 |
| --- | --- | --- |
| **S-fork** | 保真门失败 | 整轮作废 |
| **S-better** | L1/L2 在 1,200 决策 **> 90%** | 判「省着用能撑更远」；下一轮把预算推到 **2,400 / 3,600 决策**，找真正的墙 |
