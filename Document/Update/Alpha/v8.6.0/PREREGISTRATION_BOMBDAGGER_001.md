# 预注册 v860-BOMBDAGGER-001：用「会放雷的行为策略」重采状态，让 bombs∈{2,1} 进入标签集

冻结时刻：2026-11-22（Asia/Shanghai），**在任何 v8.6.0 标签或训练之前**。
状态：**FROZEN**。

---

## 0. 这一轮被一条实测事实逼出来的

**主代理实测（训练端，2026-11-22 10:59）**：v8.3.0 的 5,166 个标签状态里，`bombs_remaining` 的分布是

```
{3.0: 5166}
```

——**全部是 3 颗**。也就是说：**标定集里从来没有出现过「已经用掉一颗/两颗雷」的状态**。

这解释了两件事：
1. **v8.5.0 的规则蒸馏不可能学到「省雷」**：R5 与 R0 的差别只在第 2、3 颗雷的阈值（60/40 px），而那些状态在标签集里**根本不存在**；在 bombs=3 的状态上，R5 与 R0 给出**完全相同**的规则目标（80 px，而起手最近弹距只有 21 px ⇒ 恒为「放」）。
2. **v8.3.0 的纯标签策略也只能学到「开局就放」**：标签里 bomb=1 从未更差（safe 99.83% vs 54.58%，逐对「更短」0 例）。

⇒ **要学「何时省」，必须先让标签集覆盖「雷已经用掉」的状态。** 这就是本轮唯一的改动。

## 1. 设计（单因子：标定时的行为策略）

| 项 | v8.3.0 / v8.5.0 | **v8.6.0** |
| --- | --- | --- |
| 行为策略（决定状态从哪来） | v4.5.0 `S`（**永不放雷**）⇒ bombs 恒 3 | **v4.5.0 `S` + R5 放雷规则**（80/60/40 px）⇒ **bombs ∈ {3,2,1}** |
| 状态数 | 5,166 | **目标 ≈5,000**（尽量覆盖三种 bombs 值） |
| 每状态标签 | 36 路（18 候选 × bomb），H=120 | **完全不变** |
| 训练 | `Policy(106,64,36)`，BCE，Adam 1e-3、200 epoch、3 种子 | **完全不变**（**不再加规则辅助损失**，v8.5.0 已证明它无效） |
| 评测 | 300/600/900 决策 | **不变** |
| 对照 | v8.3.0（99.94/19.44/0.61）、R5 规则（100/77.05/19.38） | 同 |

> **为什么不再加规则辅助损失**：v8.5.0 在 bombs 恒 3 的数据上加规则损失，等价于重复「放」这个标签（无新信息），且 20 s 反而从 19.44% 掉到 ~8%。本轮只改**状态分布**，不加任何辅助损失——保持单因子。
