# Alpha v8.29.0｜在新弹幕起点上复验放雷策略

**2026-11-23 · 研究端规划版 · 历史基线提交 `8eeb0b4`。** 本版要决定一个具体问题：移动策略完全相同时，v8.26 的自适应放雷 G1 和 v8.23 的固定阈值 T2，哪一个值得带进更长的对局？本版已经给出实验设计；训练机上的起点存量、可运行性和新成绩均待回执。WP05 保持暂停。

训练端首轮只需接收 [V829-INFO-01 只读工单](TRAINING_HOST_REQUEST.md)。后续评测采用 [V829-PAIR-01 配对协议草案](PREREGISTRATION_PAIR_001.md)，在训练端清单和预算齐备后单独派发。

## 为什么先做复验

| 真实引擎历史记录 | 20 秒 | 30 秒 | 40 秒 |
| --- | ---: | ---: | ---: |
| G1，按剩余决策和雷数调节阈值 | 239/240 | 146/240 | 34/240 |
| v8.26 预注册的两种固定规则中，该档较高者 | 237/240 | 117/240 | 30/240 |
| T2，固定 40/20/5 px，v8.23 | 本轮历史来源只测 30 秒 | 141/240 | 待测 |

30 秒的 G1 与 T2 只差 5 局，四窗差值依次为 −2、+5、−5、+7 局，各窗每臂 60 局。研究端从发布计数复算，G1 对预注册固定规则 35/15/3 的单侧 Fisher p 为 0.00508，对 T2 为 0.35484。后者是跨版本、事后、按池化计数的描述性核对。原始采样按进程跨局连续使用随机流，四窗又都参与过开发；这批历史数据无法给出新起点的胜率。[G1 的对照和逐窗计数](../v8.26.0/evidence/URGENCY/extra_numbers.md) · [T2 逐窗结果及采样协议](../v8.23.0/evidence/RULETIGHT/RUN.md)

v8.28 学习放雷头的 150/1,800 个满段中，138 个集中在两格。该轮移动头取 argmax，G1 从 softmax 采样。两者的 30 秒成绩包含移动读出差异。G1 在原有 30、40 秒窗也从第 0 步发出首雷，因此新实验看库存真正扣除的时刻、最后一颗用尽后还能活多久，以及换起点后两臂的存活差。[v8.28 行为记录](../v8.28.0/evidence/FEATURES/RUN.md) · [G1 首雷记录](../v8.26.0/evidence/URGENCY/extra_numbers.md)

排期以回执为起点。优先安排一次只读盘点和一次旧窗冒烟；等训练端给出单局耗时、启动/恢复开销和可用并发后，再分配成批引擎时间。目标试点每档 48 对，两档共 192 个单臂回合，上限 403,200 个受控游戏帧，另计前缀、冒烟和有记录的技术重试。每批只回传汇总表、少量边界样本和清单 SHA，逐局记录留在训练端。

## 试点之后的研究路线

1. **若值得复验 G1**，用全新祖先检验冻结策略与 T2 在 30 秒的差异。先按开发批的不一致率和可供祖先数量计算独立配对规模，再冻结确认清单。若 40 秒的绝对存活率仍低，按弹幕阶段定位用完雷后最先失守的区段。
2. **若 T2 占优或两臂各有胜负**，保留简单固定规则作参照。先从已有开发轨迹判断差异集中在哪类状态，例如带雷死亡或过早耗尽，然后只立一个可检验的假设。一个后续候选是每 30 个决策选一次阈值、逐步按同一距离规则执行；训练和选参只用开发资料，冻结移动头、采样方式和评测预算后再与规则比较。
3. **若目标转向第一面通关**，可并行设计整面计分。G1 当前直接读取已知微段的剩余步数。整面实验须先定义部署时可得的预算输入，登记掉命补雷、拾取及库存超出 1–3 的行为。用自然开局、标准资源记录到达 Boss、实际过面、死亡耗尽、超时和技术中止。特权状态策略的整面结果用于诊断；G410-2 另需纯像素边界、100 个 S1N 确认局达到 50% 且 Wilson 下界至少 35%，并完成至少 20 局 Windows 零售复验，点估计达到 harness 的 70%。[第一面正式验收](../v4.1.0/README.md)
