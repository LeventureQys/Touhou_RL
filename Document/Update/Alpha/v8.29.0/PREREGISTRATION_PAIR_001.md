# V829-PAIR-01｜G1 与 T2 的新起点配对评测

**2026-11-23，研究端预注册草案，待训练端登记。** 主要问题为 TH08 第一面 Normal 的新开发微段上，同一冻结移动头搭配 G1 或 T2，哪种规则更常无死亡活满 900 个决策？1,200 决策为次要终点。训练端收到单独评测工单后实施。首轮只读工单见 [V829-INFO-01](TRAINING_HOST_REQUEST.md)。

## 1. 两臂仅更换放雷规则

| 冻结项 | 约定 |
| --- | --- |
| G1 | 令 B 为当前雷数、R 为本档预算减去已执行决策数。B 为 3、2、1 时基础阈值分别为 35、15、3 px，乘以 `sqrt(R / (max(B, 1) × 200))` 后裁到 [5,120] px |
| T2 | B 为 3、2、1 时分别使用 40、20、5 px；两个时长都用同一组常数 |
| 触发与动作 | 沿用同一 `nearest_all_px` 实现，B>0 且距离存在并严格小于阈值时发出请求；射击、focus、两帧移动保持、仅决策首帧带 bomb 位等设置相同。逐个核实新起点以 3 颗雷进入，登记段内库存越界和补给语义，超出已冻结实现覆盖范围时单列 |
| 候选移动 | 逐一使用旧 `bombdag.pt` 三个训练种子，分别按 SHA 绑定。18 个候选各取成对 logits 的最大值，温度 1.0 做 softmax，每个决策用 `torch.multinomial` 抽一次。两臂固定同版本特征、游戏数据、引擎和动作映射 |
| 随机数 | 对每个（祖先、预算、checkpoint、重复号）预分配唯一 RNG 种子，写入配对表。每臂开始时新建同状态生成器，不跨回合消费；记录 PyTorch 版本、设备、初始 RNG 摘要和消耗次数。同流容许状态分叉后选出不同动作 |

历史 G1/T2 在进程内跨窗、跨局沿用一个随机流。本版逐对重置，以免前一局的长度改变下一局的抽样。旧窗冒烟应在相同输入和指定初态 RNG 下比对动作与阈值；新协议单独编号。30 秒与 40 秒分别从同一接管状态开跑，G1 自首步起便使用各自预算。[G1 实现](../../../../tools/rl/v8r0_urgency.py) · [T2 实现](../../../../tools/rl/v8o0_ruletight.py)

## 2. 清单、抽样与工作量

- 目标为 **8 个新开发祖先，每个独立对局根只选一窗**。优先覆盖道中、Boss 两类阶段，各 4 个。以既有来源登记、前缀和脚本阶段判定资格，只纳入按既有脚本可容纳 2,400 帧、有可校验接管状态的起点；保留纳入/排除原因。一个根的多个分叉、相邻切片和派生录像归一簇。谱系待定的数量单报。拿不到两个阶段时，先登记可测阶段及范围，再决定缩小为探索批或补来源。
- 抽样前固定阶段判据、来源清单及其 SHA。先各选只具备单一阶段资格的祖先，每阶段最多 4 个；再从同时具备两种资格的祖先中依次补齐道中、Boss 的缺额，每选一根即从两表移除。每个候选集合都按预先公布的随机种子排序，每祖先按同一原则选一窗。记录种子、排序算法、每层供给量和所选前缀摘要；不足 4+4 时列为范围缩减。历史训练窗 13–16、开发窗 11/12/17/18 及其派生根排除在新样本外；另外核对其他训练和选参来源。保留区间 60000–60199、61000–61499 及已登记适应/确认家族继续原用途，正式封存内容保持封存。[既有切分规则](../../../../configs/v430/splits.json) · [祖先与阶段定义](../v4.4.0/EXPERIMENT_PROTOCOL.md)
- 每祖先、每预算评 3 个 checkpoint × 2 个配对 RNG。**每档 48 对、96 个单臂回合**。两档共 96 对、192 回合。两臂执行顺序按清单平衡交错。重复、种子和预算都保留嵌套关系。若墙钟不足，优先保全所有独立祖先的 30 秒主比较，40 秒另列待执行；任何缩减都在看新结果前记入冻结版本。
- 分两步登记。研究端根据 INFO 回执先锁定抽样设计、两臂和计分办法，经用户转交实施工单。训练端完成适配和旧窗冒烟后、在任何新开发窗产生策略结果前，冻结最终运行表。表内记录实际 run ID、主机与时间、引擎/数据/权重/适配器/计分器 SHA、祖先和前缀表、接管帧、最后历史锚点、接管哈希、每对 RNG、臂顺序、预算、资源限额和协议摘要。冻结后更改身份、源数据或统计口径须换清单版本并记录已看过的结果。

## 3. 训练端实施切片

1. 在曝光旧窗先走一次历史 D3 五项保真门。确认每个新起点均可按自己的参考前缀恢复，记录最后已执行帧、第一受控帧、核验锚点数和差异数，用两次独立恢复比对接管状态哈希、资源和阶段。旧窗帧号 8663 只用于历史桥接。
2. 建一个 v8.29 专用配对入口和清单读取器。继续复用已审计的策略、计分与引擎调用；v8.26 入口只接受四个旧窗、使用旧 PARK 前缀及历史路径。先核对上游恢复入口和 split guard 支持新开发用途，再以清单显式绑定合法起点、接管帧和输出目录。保留既有 runner 的限制与历史证据。旧窗用同一输入逐步比较规则阈值、移动采样、送出的 mask 和实收库存变化，记录首个差异帧。
3. 冒烟从一个旧窗、一个 checkpoint、一条配对流开始。验收两次恢复哈希、每决策抽样次数、两帧 mask、计时边界、静音、库存变化以及故障退出处理。检查已有正常满段、末帧死亡、提前转场及技术中断的计分样例，注明真实轨迹与离线边界测试各自来源。用实测启动、恢复和逐局时间估算整批墙钟。冒烟单独存档。
4. 正式启动试点前绑定新运行目录与各工作进程唯一 tag。每个 pair 保留起点与随机流、动作数、实际帧数、终态与发生帧、首死、请求/实际扣雷事件。新产物及必要 SHA 按资产册登记，旧运行目录和暂停快照保留原状。向研究端仅回传逐祖先小表、命令与退出码、运行清单和产物摘要。

## 4. 计分与验收

满段要求完整执行预算对应的 1,800 或 2,400 帧、帧序正确、截至末帧无死亡。末帧死亡记 0。预算前发生可核实的合法转场或过面，单列事件且本微段满段指标记 0；同时报两臂次数，以供整面指标解释。无法恢复、帧丢失、引擎报错或终态不明记技术无效。一次技术故障只按原 pair、起点、随机流和配置重跑双方一次，保留两次记录。合法输赢直接入账。回执列计划、有效、重试、待判配对数。待判对保留在原位置，报全部偏向 G1/T2 的差值上下界；未收齐主批时只报阶段性数字。

两份旧实现都按当前库存查阈值表；B=0 或 B>3 时不请求放雷。段内合法拾取导致 B>3 时保留该动作语义，单列事件并继续计分。记录库存变化前后的实际帧、决策号和游戏事件，分开计算发出请求、实际扣数与资源补充。审计器若无法区分补给和异常、导致配对有效性无法核实，保留该对并纳入待判上下界。

对每个祖先分别列两臂同满、仅 G1 满、仅 T2 满、同未满四格。祖先的差值为（仅 G1 满 − 仅 T2 满）/ 该祖先有效配对数；主要效应 Δ30 是完整清单上 8 个祖先差值的等权平均。分别报两臂绝对满段率、Δ30、正/平/负祖先数、删去任一祖先后的差值范围和三份 checkpoint 的结果。40 秒同法报告 Δ40，另按存活/死亡分别报每颗实际扣库存的步数、耗尽后存活帧数和带雷死亡数。历史记录只有发出指令时刻时标注可推断区间；幸存局的耗尽后时间在段尾截断。报告候选动作种类数以核对采样，独立样本量按祖先数报。

| 完整开发批的结果 | 预先约定的研发决策 |
| --- | --- |
| Δ30 ≥ +5 个百分点，且至少 5/8 个祖先为正 | 提名 G1 进入另一批独立祖先的 30 秒复验。仅在 40 秒批完整、Δ40 ≥ +5 个百分点且至少 5/8 个祖先为正时，同时建议复验 40 秒；单列次要终点 |
| Δ30 ≤ −5 个百分点，且至少 5/8 个祖先为负 | 保留 T2 作 30 秒默认参照，复查 G1 在哪些阶段消耗过早或带雷死亡 |
| 其余完整结果 | 两者差异未定，T2 保留为简单对照。先看逐祖先、逐阶段和库存事件，再决定增加新祖先或另立一个机制实验 |
| 祖先不足、身份不符、关键计分缺证或主配对不完整 | 如实报可用分母及界限，补来源、恢复或计分证据；继续独立的历史诊断 |

5 个百分点和 5/8 是本版建议的预算取舍门槛。只有 8 个独立祖先，试点用于选择后续实验，研究端不依据回合池化 p 值宣称泛化或等效。独立复验另编号，提前冻结一个主比较及新的祖先；用试点估计不一致率，计算达到目标效应所需祖先数和功效，事先登记配对检验及区间。达不到规模时只报告可支持的效应范围。
