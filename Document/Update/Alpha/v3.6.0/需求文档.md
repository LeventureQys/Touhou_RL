# v3.6.0 需求文档：策略增强型分层 RL

- 日期：2026-10-24
- 前置：v3.5.0（S0 状态/P 契约通过；S1 区域探针未通过，S2–S5 未启动）、v3.4.0（纯局部价值学习门未通过）
- 性质：**训练需求文档**。本版本允许开始新的 RL/教师联合训练，但必须按阶段门禁推进，不得跳过特权侧战术验证直接训练视觉策略。
- 第一终点：TH08 1.00d、Lunatic、固定机体/固定 frameskip 下，特权策略完成 **Stage 1 clear（M3）**；未满足 M3 不报告“通关”。
- 最终产品目标仍是视觉学生；本版本只把可解释的策略能力加入特权 RL 与教师流程。

---

## 1. 为什么新开 v3.6.0

当前系统已经具备较好的短视避弹教师和较干净的特权状态采集，但策略学习仍存在结构性缺口：

1. 局部 pilot 主要优化未来约 20 帧的最小 clearance，不知道当前动作会怎样改变未来几秒的弹幕；
2. PPO/BC 曾出现常数动作、低换向率、贴墙/贴角等退化；v3.3 模型 20 局平均 1353 帧，低于随机 2788 帧；
3. v3.5 S1 的区域定义未通过：区域死亡 AUC 0.8094，低于局部 clearance AUC 0.9246，不能把现有“区域内/区域外”二值标签直接接入控制；
4. 当前学生动作空间通常为 18 个移动/聚焦动作，没有明确的 bomb 决策；教师实际使用了 bomb；
5. 真实玩家的关键能力不是单纯躲弹，而是：**诱导弹幕、保留退路、主动清怪、维持输出、条件性收集 P、在 Boss 阶段管理资源**。

因此本版本不再把“纯 PPO 直接学会完整游戏”作为主假设，而采用：

```text
特权状态
  → 战术教师/短视搜索
  → 多时间尺度策略学习
  → 学生状态 DAgger
  → 视觉策略蒸馏
  → 高风险搜索或规则 fallback
```

**重要原则：策略标签必须描述“为什么这样做”和“未来收益”，不能只记录一个 20 帧固定方向。**

## 2. 玩法策略定义

### 2.1 诱导与换边（Lure / Reposition）

针对自机狙、延迟锁定或朝当前位置发射的弹幕：

- 在安全窗口内先维持一个可预测位置，使弹幕集中落向旧位置；
- 在弹幕生成/锁定后向预留侧快速换边；
- 换边后优先进入宽走廊，不为短期 clearance 反复左右摆动；
- 若两侧都被封死，进入 emergency mode，允许使用 bomb。

教师必须输出：

- 当前是否为可诱导攻击；
- 诱导站位方向/目标区域；
- 预计锁定或发射窗口；
- 换边方向；
- 换边后安全走廊宽度与预计暴露时间；
- 诱导失败条件和中止动作。

不得把“是否向左/向右”当作诱导标签；至少要保留 `intent=lure`、`lure_phase`、`target_side`、`abort_reason`。

### 2.2 出口与未来安全（Preserve Escape）

玩家应避免为了眼前几像素的空隙钻入边角。策略应最大化：

```text
未来安全面积
+ 可达安全区域连通长度
+ 换向后的出口宽度
- 未来区域暴露时间
- 到出口的路径风险
- 贴墙/贴角风险
```

必须使用多尺度时间视界：

- 1–4 帧：当前碰撞规避；
- 20–60 帧：离开大范围危险区、选出口；
- 120–600 帧：清怪、P、Boss 输出和 bomb 资源。

区域信息不能只用单一连通分量或单一二值变量表达。至少记录：危险密度、多尺度占据、扩张/流向、可达出口、最短暴露路径、贴墙风险。

### 2.3 主动清怪（Clear Enemy）

普通敌人是未来弹幕的生成源。策略应在安全约束下选择高未来威胁目标，而不是只追求当前 clearance：

```text
enemy_value(e) =
    未来 60/240 帧发弹量减少
  + 击杀后的安全区域改善
  + P/火力收益
  - 到达路线风险
  - 放弃当前出口的代价
  - bomb/生命风险
```

要求：

- 记录敌人位置、生命、类型、活动状态和目标 ID；
- 记录选择目标、开始攻击、生命下降、击杀及后续弹幕变化；
- 大范围危险形成时，立即中断清怪并切换 LeaveRegion；
- 不得以 score 增加代替敌人击杀证据；
- 只有在未来 60/240 帧收益显著时，才允许牺牲少量当前 clearance。

### 2.4 输出与火力窗口（Damage Window）

持续射击是默认行为，但输出不能压过生存：

- 安全时保持 Boss/高威胁敌人的有效瞄准；
- 需要精确穿缝时使用 focus；
- 需要快速横移或换边时解除 focus；
- 不在危险区域内为了追 Boss 横向瞄准而牺牲逃生路线；
- 对 Boss 区分非符、符卡、无敌/对话/阶段转换，分别学习输出窗口。

策略必须显式输出 `damage_intent`、`target_id`、`aim_confidence` 和 `damage_abort_reason`，防止“永远对准 Boss”成为隐藏奖励。

### 2.5 条件性收集 P（Collect Power）

已验证的基础契约：power 上限 128，自动收集线为场地 `y=128`，有效条件包含聚焦；但尚未证明任何 P 都值得冒险。因此本版本只允许条件性收集：

```text
power < 128
+ 存在有效 P
+ 自机存活且不在出生/死亡状态
+ 到 y < 128 的路线风险低
+ 预计 DPS/未来清怪收益 > 路线、生命、bomb 风险
```

收集期间：

- 按住 focus，移动到收集线；
- 等待有效 P 进入自动收集状态；
- 收集路线风险升高或危险区域扩张时立即中止；
- power=128 时不为 P 点冒险；
- 必须记录 P 出现、目标、收集、power 增量和中止原因。

### 2.6 Bomb 与生命资源

本版本必须在训练协议中明确 bomb 的归属，不能让教师使用 bomb 而学生仍声称具备同等能力。

推荐动作空间：

```text
9 个移动方向 × 2 个 focus 状态 × 2 个 bomb 状态 = 36 个动作
```

若工程上暂时保留 18 动作，则 bomb 必须由独立、可审计的风险 fallback 执行，报告中单独列出 fallback 调用率；不得把 fallback 的收益计入纯学生策略能力。

bomb 使用目标：

- 不是追求 score；
- 不是看到任何近弹就使用；
- 是在未来无可达安全路线、区域封死、或 Boss 资源交换明显划算时保命。

必须记录 `bomb_available`、`bomb_trigger_reason`、使用前候选路线数、使用后生存结果。

## 3. 总体模型与控制结构

### 3.1 分层策略

```text
Observation / privileged state
        ↓
Temporal encoder（至少保留最近 20–60 帧历史）
        ↓
Tactical policy/value
  ├─ LeaveRegion
  ├─ Lure/Reposition
  ├─ ClearEnemy
  ├─ CollectPower
  ├─ BossDamage
  ├─ LocalDodge
  └─ Emergency/Bomb
        ↓
Intent constraints
        ↓
Local pilot / MPC / beam search
        ↓
执行 1–4 帧后重新规划
```

高层意图优先级：

1. Emergency/Bomb；
2. LeaveRegion；
3. Lure/Reposition；
4. ClearEnemy / CollectPower / BossDamage；
5. LocalDodge。

该优先级允许价值比较，但安全硬约束不可被火力或资源收益突破。

### 3.2 输出头

模型至少包括以下独立头，不能将所有目标压成单一未经解释的 reward：

- `Q_intent(s, intent)`：高层意图价值；
- `Q_action(s, a)`：36 动作或 18 动作候选价值；
- `V_survival_60/240`：固定视界生存概率；
- `future_danger`：未来危险占据/密度/流向；
- `exit_value`：出口方向、到达时间、最大暴露量；
- `enemy_clear_value`：目标敌人未来弹幕减少；
- `collect_value`：P 的火力收益减路线风险；
- `damage_value`：Boss/敌人未来伤害收益；
- `resource_value`：bomb、life、power 的机会成本；
- `intent_abort`：何时中止当前战术。

### 3.3 首步与输入完整性

环境 reset 后第一步必须提供完整的 bullet/entity snapshot；不允许首步把弹池当空集合。若数据不可用，样本必须标记 `incomplete` 并从正式训练/评估分母中按预先定义的规则处理。

## 4. 训练阶段与需求

### T0：数据与事件契约

在训练前完成：

1. 修订 v3.5 S1 区域表示：多尺度危险密度/并集区域/扩张方向/出口；
2. 对自机狙、固定弹幕墙、散射/大范围攻击分别建立可识别场景标签；
3. 纳入激光或明确记录为未知盲区；
4. 验证真实 `stage_clear`、Boss 击破、阶段转换和 game-over 事件；
5. 修复 reset 首步完整快照；
6. 固定 train/validation/test 按整局切分，禁止同局泄漏。

T0 门禁：

| 指标 | 要求 |
|---|---:|
| 稳态样本 complete 率 | ≥99% |
| 关键字段 schema error | 0；未知字段写 `unknown` |
| 首步完整 snapshot | 100% |
| 真机可区分 stage-clear / game-over | 至少各 1 个真实样本 |
| 按整局切分 | 100% |

T0 未通过，不训练新策略。

### T1：单战术监督/离线价值门

先不做随机初始化 PPO。使用特权轨迹构造固定视界标签：

- `survival_60/240`；
- 未来危险区域、出口时间和暴露量；
- 诱导后换边收益；
- 敌人击杀后的 60/240 帧发弹减少；
- P 收集后的 power/DPS 增益；
- Boss damage 与资源消耗；
- bomb 是否为当时最小损失动作。

每一项都要和以下时间代理基线比较：active bullet count、stage_frames、power、Boss HP、当前 clearance。

T1 建议门：

| 指标 | 要求 |
|---|---:|
| 未来 60 帧危险排序 AUC | ≥0.80，且高于 clearance 条件基线 |
| 出口方向 top-3 | ≥70% |
| 诱导/换边意图 balanced accuracy | ≥0.70 |
| EnemyValue 排序 Spearman | ≥0.50，且高于当前 bullet-count 基线 |
| CollectValue 排序 AUC | ≥0.60 |
| 固定视界战术价值排序 | ≥0.60，且高于 stage_frames 基线 |
| Bomb 触发/不触发校准 | Brier ≤0.20 或报告可靠性曲线 |

任一标签无法稳定定义，先修标签，不进入 PPO。

### T2：分场景战术教师

每个场景先单独验证，再整合：

1. **Lure 场景**：诱导后换边成功率、换边后出口宽度；
2. **Region 场景**：提前离开危险区域，不以贴墙伪通过；
3. **Clear 场景**：高威胁敌人击杀及后续发弹减少；
4. **Collect 场景**：安全窗口收 P 与高风险 P 放弃；
5. **Boss 场景**：输出/闪避/符卡阶段切换；
6. **Emergency 场景**：无路可走时合理使用 bomb。

每个场景至少采用同初始状态、同弹幕条件的 paired comparison：局部 pilot vs 战术教师。必须同时记录生存、出口、敌人生命、P、Boss HP、bomb 与终止事件。

T2 不以单一 `frames_mean` 判定。任何场景收益不成立，都只关闭该战术，不得用其他场景收益掩盖。

### T3：多任务 RL / 受限 PPO

只有 T1、T2 通过后，才允许在线 RL 微调。

推荐训练顺序：

1. 行为克隆/价值回归预热战术头；
2. 先训练 LocalDodge + LeaveRegion；
3. 加入 Lure/Reposition；
4. 加入 ClearEnemy；
5. 加入 CollectPower 与 BossDamage；
6. 最后加入 bomb/resource；
7. 每次只改变一个因素，保留消融实验。

奖励必须保留向量而非只保留标量：

```text
survival
short_horizon_safety
future_escape
lure_success
enemy_clear
power_value
damage_progress
resource_preservation
stage_clear
terminal_death
```

要求：

- 生存与死亡不再只靠极小逐帧奖励；
- 采用固定视界 n-step/回溯死亡信用，覆盖至少 240–600 帧；
- 对安全硬约束使用 action mask 或 constrained value，不允许策略通过贴角、少移动、永不换向获得高分；
- 监控熵、换向率、动作占比、贴墙率、bomb 使用率和各意图占比；
- 出现常数动作、换向率低于教师 25%、贴墙率增加超过 5 个百分点时立即停线。

### T4：学生状态 DAgger 与视觉策略

特权战术教师在学生访问的状态上重新标注：

- intent；
- 全动作 value；
- 出口方向；
- enemy target/value；
- collect value；
- damage/resource value；
- 中止原因。

每轮：

```text
学生运行 20 局
→ 收集学生诱导状态
→ 特权战术教师重新标注
→ 保留历史并集
→ 训练学生
→ 20 局评估
```

至少进行 3 轮；不得只用人类轨迹或只保留最近一轮。视觉学生只有在“策略 + 搜索 fallback”稳定通过后，才进行纯策略评估。

## 5 评估协议与完成定义

### 5.1 固定协议

所有正式比较固定：

- TH08 1.00d；
- Lunatic；
- 固定机体和路线；
- 固定 frameskip；
- 同一启动/菜单流程；
- n=20 探针，随后 n=30 确认；
- 随机种子、版本、checkpoint、运行目录和终止原因全部落盘。

基线至少包括：still、random、冻结策略、旧 pilot、战术教师、纯 RL、RL+fallback。

### 5.2 战术指标

必须逐局报告：

- `stage_clear`、`boss_clear`、`game_over`、`left_game`；
- survival frames、Stage/Boss 进度；
- 诱导次数、换边成功率、换边后安全走廊；
- 大区域暴露时间、提前撤离比例；
- 敌人击杀数、目标敌人 life 下降、未来弹幕密度变化；
- power、P 收集率、高风险 P 误冲率；
- Boss damage、phase/spell 进度；
- bomb 使用数、触发原因、剩余资源；
- 意图切换率、换向率、贴墙率、动作熵；
- fallback 调用率和 fallback 贡献的结果。

### 5.3 分阶段通过标准

**战术教师门：**

- 各已启用战术的 paired comparison 达到其单独预注册门；
- 不增加超过 10% 的死亡率；
- 不得通过贴墙、少移动或频繁 bomb 伪通过；
- 至少有真实 Boss 击破和 Stage clear 事件证据。

**特权 RL 门：**

- n=20 达到 Stage 1 clear 概率 ≥旧 pilot；
- survival frames 不低于旧 pilot 的 90%；
- 意图分类 balanced accuracy ≥0.75；
- 出口方向 top-3 ≥70%；
- fallback 调用率单独报告，且不得超过 30%；
- 纯策略与带 fallback 的结果分别报告。

**视觉学生门：**

- 学生状态下 teacher-value MAE 逐轮下降；
- intent balanced accuracy ≥0.75；
- region-exit top-3 ≥70%；
- 在明确 clear 契约下，混合策略达到 M3；
- 纯视觉策略只有在混合策略稳定后才可验收。

## 6 明确不做与停止线

本版本明确不做：

- 不再直接运行“随机初始化 PPO + 只有存活帧奖励”；
- 不把 `frames_mean` 当作通关；
- 不把 score、活得久或像教师当作 Stage clear；
- 不在 S1 区域表示未修复前直接启动 LeaveRegion 真机控制；
- 不把固定方向保持 H 帧标签当作动态教师决策；
- 不将 bomb fallback 的收益冒充纯学生能力；
- 不在同一实验中同时修改动作空间、奖励、时间视界和模型结构；
- 不用同一局数据同时训练和验证。

以下任一情况触发停止并开新子版本：

1. T0 关键字段或真实 clear 事件无法验证；
2. T1 的战术标签无法超过时间代理基线；
3. T2 paired comparison 没有闭环收益；
4. RL 出现常数动作、贴墙、熵坍缩或 bomb 滥用；
5. 视觉学生在学生诱导状态上误差不下降；
6. 评估只能证明生存里程，不能证明阶段推进。

## 8 版本成功标准

v3.6.0 的成功不是“训练时间更长”或“模型分数更高”，而是完成下面这个可复核闭环：

```text
识别攻击意图与未来危险
→ 诱导并换边，保留可达出口
→ 必要时提前离开整片危险区
→ 在安全窗口主动清除高威胁敌人
→ power 未满且收益为正时收集 P
→ 在安全窗口持续输出
→ 无路可走时合理使用 bomb
→ 击破 Boss 并记录 Stage 1 clear
```
