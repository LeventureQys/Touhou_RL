## 0 结论

**T0 的全部门禁项到此已闭合。** 首步快照这条的核查过程中发现并修掉了一个一直存在的读取缺陷：

> 每个快照都多出**一颗幽灵弹**：位置恰好 (0,0)、速度恰好 (0,0)、half = 0.5（`np.maximum` 的下限），而 `state` 既不是 `BULLET_UNUSED` 也不是 `BULLET_DESPAWNING`，所以 `active_mask()` 把它当成活的。

它不是"首步读成空集合"，而是**反方向**的缺陷：首步（以及每一步）都多报一颗不存在的弹。已修。

判读：

1. **首步弹池是"真的空"**，不是"读失败被当成空"：`schema_status.bullets == "ok"`，且 sidecar 的 `offsets` 正常推进（0 → 0），`activeBulletCount` 计数为 0 与空池一致。第 1 面开局第 2–4 帧本来就没有弹幕。
2. 记录值 `count=1` 与真实值 `0` 的差恰好等于幽灵条目数（1），21 局全部成立。这本身就是幽灵存在的独立证据。
3. 首步之后的一致性检查（决策 1 的弹能否线性存活到决策 2）在剔除幽灵后分母为 0，故记为 `None` 而不是 `1.0`——**修复前那个 1.0 是幽灵自己匹配自己，属于假通过。**

## 2 幽灵是怎么被发现的

T0 的判据问的是"首步会不会把弹池当空集合"。用三条检查去测：schema 组有没有 `error`、记录计数与 sidecar 是否一致、首步的弹能否线性存活到第二步。

结果 21 局**全部**显示 `count=1`、`counter=0`、`survivors@1.0`。三件事同时成立很可疑：开局第 4 帧不该有弹；计数 0 与池内 1 颗矛盾；而"存活率 100%"过于整齐。

打出那颗弹的坐标就清楚了：`(0.0, 0.0) v=(0.00, 0.00) h=0.5`，而且**第 1 帧到第 6 帧一模一样**——不移动、不消失、永远在那里。场地原点是 `(32, 16)`，所以绝对坐标 (0,0) 不可能是真弹。

## 3 修复

`BulletField.active_mask()` 增加一条判据：位置与速度**同时**为零的条目不算活跃。

```python
live   = (state != UNUSED) & (state != DESPAWNING) & (disabled == 0)
zeroed = |x| < 1e-3 and |y| < 1e-3 and |vx| < 1e-3 and |vy| < 1e-3
return live & ~zeroed
```

四个边界情况都有单测（`touhou_rl/tests/test_bullet_field.py`，4 项）：真实弹在场地左上角 `(32.5, 16.5)` 必须保留；位置为零但速度非零必须保留；`UNUSED`/`DESPAWNING`/`disabled` 必须过滤；幽灵必须过滤。

**只影响今后的采集。** D1/D2/D3 的 trace 里仍然有幽灵，因为 sidecar 已经写死了——但逐列论证它对这些特征不可见：

| 特征/标签 | 幽灵的影响 | 原因 |
|---|---|---|
| `clearance` / `min_clearance_60` | 无 | 幽灵距自机约 400 px，早已被上限 60 截断 |
| 危险图 / `danger_60` / 区域面积 | 无 | `_cell_index` 把 `(0,0)` 判为网格外（`ix<0`）直接丢弃 |
| `n_bullets` / `BASE_n_bullets` | +1 常数 | 常数平移在标准化后被中心化，岭回归截距吸收 |
| `bullet_delta_60/240` | 无 | 差分抵消常数 |
| `attributed_spawns_60` | 无 | 幽灵的槽位每帧都在，永远不是"新弹" |
| LURE 瞄准统计 | 无 | 速度为 0 → `cosang=0` → 既不算 aimed 也不算 approaching |
| 教师动作 | 无 | `_prepare` 的 `near_radius=240` 会把 400 px 外的它过滤掉 |

所以**不需要重抽特征、不需要重跑任何消融**；已提交的 D1/D2/D3 数字不变。
