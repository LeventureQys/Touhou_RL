# v3.6.0 执行计划：七策略消融（T0 → T1）

- 日期：2026-10-25
- 依据：[需求文档](<./需求文档.md>) §2（玩法策略定义）、§3（分层策略）、§4（T0/T1 门禁）、§6（停止线）
- 性质：**预注册执行计划**。本文件写定后，门禁阈值、标签视界、特征块、交叉验证协议与判定规则**不得根据结果修改**；要改就新开版本。
- 本轮**不**训练像素策略，**不**启动 PPO，**不**做真机控制。本轮只回答一个问题：**七条策略各自提供的状态信息，是否在离线可测的未来量上超过"局部 clearance + 时间代理"基线。**

---

## 1 为什么先做消融

v3.5.0 的教训不是"数据不够"，而是**一个看起来合理的策略概念（大范围危险区域）在有对照的情况下没有增量**：

| v3.5.0 S1 结果 | 数值 |
|---|---:|
| 区域特征 AUC（预测 60 帧内死亡） | 0.8094 |
| 局部 clearance AUC | 0.9246 |
| 增量 | **−0.115**（p=0.002，稳定地更差） |

也就是说，"玩家在一个大区域里"这件事，没有比"离最近子弹多远"多提供任何信息。如果当时直接上 LeaveRegion 真机控制，就会把一个**零增量**的战术接进控制环，再把 `frames_mean` 的波动解释成它的功劳。

v3.6.0 §2 一口气定义了六条战术（Lure、PreserveEscape、ClearEnemy、DamageWindow、CollectPower、Bomb）。按 §6 停止线第 3 条（"T2 paired comparison 没有闭环收益"）与 §4 T1（"任一标签无法稳定定义，先修标签，不进入 PPO"），**必须先逐条证明每条战术的观测信息有增量，再谈控制**。

所以本轮把"策略"拆成可证伪的最小单位：

```text
一条策略 = 一个特征块（只有它能看见的观测）
          + 一个未来标签（这条策略声称能改善的量）
          + 一个基线（不含该块时能拿到的信息）
```

消融 = 同一标签、同一模型、同一交叉验证下，**加块前 / 加块后**的差。

## 2 消融单位与两级方向

### 2.1 特征块（8 块）

| 块 | 对应策略（需求文档） | 只包含该策略才能看见的观测 |
|---|---|---|
| `BASE` | **LocalDodge**（对照基线） | active bullet count、stage_frames、power、Boss HP、当前 clearance、18 动作短视 horizon clearance 聚合 |
| `REGION` | §2.2 Preserve Escape / LeaveRegion | 多尺度危险密度、玩家连通分量、并集/密度区域、扩张方向、最近出口环距/方向、路径暴露、贴墙距离 |
| `LURE` | §2.1 Lure / Reposition | 自机狙识别（速度方向对准自机且接近）、瞄准点偏移、左右横向余量、走廊宽度、交叉速度 |
| `ENEMY` | §2.3 ClearEnemy | 敌人数/距离/生命/类型聚合、按距离加权的预测发弹压力、列对齐威胁 |
| `POWER` | §2.5 CollectPower | power 缺口、P 道具数/距离/是否在自动收集线上方、到 y=128 距离、近期 power 速率 |
| `BOSS` | §2.4 Damage Window | Boss 存在/横向偏差/生命/符卡号、对准且安全的动作存在性、输出窗口判据 |
| `EMERGENCY` | §2.6 Bomb 与资源 | 可选撤离路线数、全部路线碰撞判据、剩余 bomb/life、死亡前兆 |
| `HISTORY` | §3.1 Temporal encoder | 最近 4 个决策的 clearance/bullet/py/power 及其差分 |

`BASE` 是需求文档 §4 T1 点名的"时间代理基线"（active bullet count、stage_frames、power、Boss HP、当前 clearance）的超集，**只多了短视 horizon clearance 聚合**（因为 LocalDodge 本身也是要消融的策略，不能把它从基线里偷偷去掉）。

### 2.2 两个消融方向

| 方向 | 记号 | 问的问题 |
|---|---|---|
| Add-one-in | `BASE + X` vs `BASE` | 只有这条策略时，它能带来多少增量？ |
| Leave-one-out | `ALL` vs `ALL − X` | 在全部信息都有时，去掉这条策略损失多少？ |

两个方向都必须报。只有 add-one-in 通过、leave-one-out 恰好为 0 的情况**不算通过**（说明该块与别块共线，是冗余不是能力），单独记为 `redundant`。

## 3 数据

### 3.1 本轮数据（D1）

| 项 | 值 |
|---|---|
| 来源 | `Document/Update/Alpha/v3.5.0/probe/s0-teacher`（v3.5.0 S0 采集） |
| 局数 | 9（train 6 / validation 3，按整局切分，见 `trace35.stable_split`） |
| 决策数 | 21,156（steady 20,639；complete 20,638，**99.995%**） |
| 死亡事件 | 18（ep01=2, ep02=3, ep03=3, ep04=1, ep05=2, ep06=2, ep07=1, ep08=1, ep09=3） |
| bomb 使用 | 15 |
| 每决策快照 | 全弹池 position/velocity/half + 玩家 + 敌人 + 道具 + Boss + shot 参数 + 帧事件位 |
| 策略 | `AvoidPilot`（局部 beam search 教师，不是人类） |

**已知局限（写进结论，不用来辩护）**：D1 只有 18 次死亡，死亡标签稀疏；且数据由同一个局部 pilot 产生，**人类才会用的 Lure/CollectPower/BossDamage 行为在 D1 里近乎不存在**。因此本轮 T1 的结论只对"该块能否**预测**该未来量"有效，**不**声称"该策略能被学会"。人类回放数据（D2）留到下一批。

### 3.2 数据切分

主协议：**留一局交叉验证（LOEO, leave-one-episode-out）**，9 折。理由：v3.5.0 的 6/3 固定划分只有 3 个验证局，任何单次 AUC 的抖动都会淹没 ±0.02 的增量门；LOEO 让每个决策都在"没见过它所在局"的模型下被预测一次，且不改变整局切分原则（同局绝不同时出现在训练和预测里）。

辅助协议：`stable_split` 的 6/3 固定划分，仅用于与 v3.5.0 数字对齐，**不参与判定**。

## 4 标签定义（全部来自真实未来，不用外推）

设决策 i、frameskip=2（1 决策 = 2 帧），短视界 `S = 30` 决策（60 帧）、中视界 `M = 120` 决策（240 帧）。

| 标签 | 定义 | 服务策略 | 类型 |
|---|---|---|---|
| `death_60` / `death_240` | (i, i+S] / (i, i+M] 内出现 `death` 事件 | LocalDodge、REGION、LURE、EMERGENCY | 二值 |
| `min_clearance_60` / `_240` | (i, i+S] / (i, i+M] 内**实测** clearance 的最小值（用未来快照里的真实弹位与真实自机位重算） | LocalDodge、LURE | 连续 |
| `danger_60` | 决策 i+S 时全场地危险格占比（8 px 尺度） | REGION | 连续 |
| `in_region_60` | 决策 i+S 时玩家连通分量 ≥ 80 格 | REGION | 二值 |
| `bullet_delta_60` / `_240` | `n_bullets[i+S] − n_bullets[i]`（负 = 弹幕减少） | ClearEnemy、LocalDodge | 连续 |
| `power_delta_60` / `_240` | `power[i+S] − power[i]` | CollectPower | 连续 |
| `p_collected_60` | (i, i+S] 内出现 `frame_events.item_collected` | CollectPower | 二值 |
| `boss_life_delta_60` / `_240` | 有 Boss 时 `boss_life[i] − boss_life[i+S]` | BossDamage | 连续（无 Boss 为未知，剔除） |
| `bomb_needed_60` | `death_60` 且 `bombs[i] > 0` | EMERGENCY | 二值 |
| `bomb_used_60` | (i, i+S] 内 `bombs_used` 上升 | EMERGENCY | 二值 |

> `escape_dir_20`（净位移方向桶）本轮**不建单元格**，延到 T2：它在离线唯一能有的真值只有"记录到的玩家实际往哪走了"，那是行为标签而不是出口质量标签；按需求文档 §4 T1 的"出口方向 top-3"，出口方向必须由教师在 T2 显式输出（契约 §2.2 `region_exit_direction`）。不伪造。

**标签纪律**

1. 所有标签只用 `i` 之后的数据；特征只用 `i` 当时的快照。跨局不借用。
2. 视界不足的尾部决策从该标签的分母剔除（不补零、不前向填充）。
3. 实测 clearance 的算法与 `region_probe.min_clearance` 一致（自机 0.825 px、弹丸 half、0.5 pad、上限 60、下限 −10），保证与 v3.5.0 S1 的 0.9246 可比。
4. **敌人发弹量不可归因于单个敌人**：当前 trace 没有 bullet→enemy 的归属字段。因此 ClearEnemy 的"击杀后未来发弹减少"只能用**全局** `bullet_delta` 作代理，逐敌人排序另立标签（`enemy_life_delta_60`），并在报告里明确标注这一处是 `unknown`，不冒充发弹量。

## 5 模型与评估协议（先固定，后看结果）

| 项 | 固定值 |
|---|---|
| 模型 | 线性岭回归（λ=1.0）。连续标签直接回归；二值标签按 0/1 线性概率回归（AUC 只依赖排序，对校准不敏感），Brier 用同一线性概率截断到 [0,1] 计算 |
| 标准化 | 只用训练折的均值/标准差；NaN 用训练折中位数填补（本轮特征块按构造无 NaN） |
| 交叉验证 | LOEO，9 折，每决策恰好被预测一次 |
| 二值指标 | AUC（平均秩处理并列，与 v3.5.0 S1 用同一实现）；另报 Brier |
| 连续指标 | Spearman ρ |
| 增量 | Δ = 指标(`+X`) − 指标(`BASE`)，同一批决策、同一折 |
| 显著性 | 块内置换检验：把 `X` 的各列在**局内**独立打乱（破坏与标签的对齐、保留边缘分布与局归属），重跑同一流程 200 次；p = 置换 Δ ≥ 观测 Δ 的比例 |
| 随机种子 | 主结果 `seed=3600`；置换 `seed=3601` |

**为什么统一用岭回归**：本轮问的是"信息在不在"，不是"能不能拟合"。线性模型在 21k 样本 / <130 特征下不会过拟合到增量为假，且 200 次置换检验可负担。二值标签的线性概率不是校准器，但 AUC/Brier 的比较对象都是同一模型族的"有块/无块"，偏差同向抵消。非线性与校准留到 T3。

## 6 预注册门禁

### 6.1 逐策略门（每条策略各判各的，互不掩盖）

| 策略 | 主标签 | 绝对门（需求文档 §4 T1） | 增量门（本计划新增） |
|---|---|---|---|
| LocalDodge | `death_60`；`min_clearance_60` | AUC ≥ 0.80；ρ ≥ 0.30 | —（它是对照） |
| REGION（LeaveRegion） | `in_region_60`；`death_60` | `in_region_60` AUC ≥ 0.80 | `death_60` ΔAUC ≥ **+0.02** 且 p<0.05 |
| LURE | `min_clearance_60`；`death_60` | `min_clearance_60` ρ ≥ 0.30 | ρ ≥ **+0.05** 或 `death_60` ΔAUC ≥ **+0.02**，p<0.05 |
| ENEMY（ClearEnemy） | `bullet_delta_60`；由 `bullet_count` 基线改进 | ρ ≥ 0.50 | Δρ ≥ **+0.05** 且 p<0.05 |
| POWER（CollectPower） | `p_collected_60`；`power_delta_60` | AUC ≥ 0.60 | ΔAUC ≥ **+0.02** 或 Δρ ≥ +0.05，p<0.05 |
| BOSS（DamageWindow） | `boss_life_delta_60` | ρ ≥ 0.30 | Δρ ≥ **+0.05** 且 p<0.05 |
| EMERGENCY（Bomb） | `bomb_needed_60`；`bomb_used_60` | 校准 Brier ≤ 0.20 | ΔAUC ≥ **+0.02** 且 p<0.05 |
| HISTORY | `death_60` | ΔAUC ≥ **+0.02** | 相对 `BASE+REGION+LURE+ENEMY+POWER+BOSS+EMERGENCY` |

判定三值：

- `pass`：绝对门与增量门同时满足；
- `redundant`：add-one-in 增量门过，但 leave-one-out 增量 < 0.01；
- `fail`：增量门不过或方向为负。**fail 不等于"策略没用"**，只等于"当前观测/标签不足以证明它在离线可测量上有增量"。

### 6.2 全局门（决定能否进入 T2 真机 paired comparison）

| 编号 | 判据 | 阈值 |
|---|---|---:|
| G-1 | 至少 3 条策略判 `pass` | ≥3 |
| G-2 | 通过块的点估计不为负且 p<0.05 | 全部 |
| G-3 | `ALL` 相对 `BASE` 的 `death_60` ΔAUC | ≥ +0.05 |
| G-4 | 无任何块的置换 p 与主结果符号相反 | 0 例 |

G-1..G-4 全过才进 T2；否则按 §9 处理。

## 9 停止线与失败处理

| 失败位置 | 处理 |
|---|---|
| 任一策略的标签在 21k 决策上阳性 < 100 | 标签记为 `underpowered`，不判 fail，改用 d=2 的连续标签，并在报告里写明功效不足 |
| REGION 仍然对 `death_60` 为负 | 不启动 LeaveRegion（延续 v3.5.0 S2 停止线），区域表示改到 v3.6.1 的方法迭代 |
| 全部策略都 fail | 不改阈值；结论写"当前观测无增量"，下一批转 D2 人类回放数据 |
| 某块增量巨大（ΔAUC > 0.15） | 先查泄漏（是否用了未来量），再复核；宁可判 `fail_leak` 不判 pass |
| 置换检验 p 与符号矛盾 | 记 `unstable`，不进 T2 |

## 10 本计划不接受的伪通过

- 用 `frames_mean`、score、活得久当作策略有效；
- 把"像教师"（与 pilot 动作一致率）当作策略价值；
- add-one-in 通过但 leave-one-out 为负却报告为 pass；
- 用同局数据同时训练和预测；
- 把 `bullet_delta` 的全局代理说成"敌人发弹量"；
- 把 fallback/bomb 的收益算进纯策略能力；
- 只在 `validation` 3 局上调参后报告 LOEO 数字；
- 看到负增量后改视界（S/M）、改阈值、改特征块。
