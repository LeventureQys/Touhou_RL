# v3.6.0 策略标签契约（T0 交付物 2/3）

- 日期：2026-10-25
- 依据：[需求文档](<../需求文档.md>) §2.1–§2.6、§3.3、§4 T0
- 作用：把六条战术的"必须记录字段"翻译成**当前 trace 能读到的字段**与**读不到、必须写 `unknown` 的字段**。本文件是 T1 特征块与标签表的唯一依据，代码见 `touhou_rl/ablate36.py`。

---

## 0 一句话结论

当前 `v350-trace/1` 能支撑 **观测侧 6/6 条战术的部分字段**，但**意图侧字段一律为 `unknown`**：trace 记录的是"游戏发生了什么"，不是"教师想要什么"。所以 T1 只能验证**信息增量**（这条战术能看见的量是否可预测），不能验证**意图正确性**（教师是否真的这么想）。意图标签要在 T2 由教师显式输出并落盘，本轮不伪造。

## 2 逐战术契约

### 2.1 Lure / Reposition（§2.1）

| 需求字段 | 来源 | 状态 |
|---|---|---|
| `intent=lure` | 教师输出 | `unknown` |
| `lure_phase` | 教师输出 | `unknown` |
| `target_side` | 教师输出 | `unknown` |
| `abort_reason` | 教师输出 | `unknown` |
| **可诱导攻击是否存在** | 由弹速方向与自机连线夹角计算（|cos| ≥ 0.985 且接近） | ✅ 可观测，记为 `aimed_count` |
| **预计锁定/发射窗口** | 由上述子弹的 TTC 分布估计 | ✅ 部分可观测（`aimed_ttc_min/mean`） |
| **换边后安全走廊宽度** | 由 `t=20/40` 危险图的玩家行自由连通宽度 | ✅ 可观测 |
| **预计暴露时间** | 沿"玩家→出口"直线采样危险密度积分 | ✅ 可观测（近似） |
| **诱导失败条件** | 教师输出 | `unknown` |

纪律：**不把"是否向左/向右"当诱导标签**。本轮 LURE 块只放"瞄准几何量"，不放任何方向动作。

### 2.2 出口与未来安全 / LeaveRegion（§2.2）

| 需求字段 | 来源 | 状态 |
|---|---|---|
| 危险密度 | 每格子弹中心计数（8 px / 16 px 两尺度） | ✅ |
| 多尺度占据 | 同上，`t = 0/10/20/40/60` | ✅ |
| 扩张 / 流向 | 玩家连通分量质心在 t=20→40 的位移 | ✅ |
| 可达出口 | 最近自由格（Chebyshev 环搜索）及其连通分量面积 | ✅ |
| 最短暴露路径 | 玩家→出口直线的密度积分 | ✅ 近似（不做法向 D 算法） |
| 贴墙风险 | 到 `MOVE_AREA` 四边的最小距离 | ✅ |
| 并集/密度区域 | 密度 ≥ 2 的连通分量（**v3.5.0 S1 缺的就是这个**） | ✅ 本轮新增 |

v3.5.0 S1 只取"玩家所在的单一连通分量"，本契约要求同时记录**并集/密度区域**，这是 T0 §4.1 的修订项。

### 2.3 ClearEnemy（§2.3）

| 需求字段 | 来源 | 状态 |
|---|---|---|
| 敌人位置 / 生命 / 类型 / 活动 / ID | `enemies[]` | ✅ |
| 选择目标 / 开始攻击 / 生命下降 / 击杀 | 目标选择是教师输出 `unknown`；生命下降与消失可从未来快照观测 | 🟡 部分 |
| **击杀后 60/240 帧发弹减少** | 需要 bullet→enemy 归属 | ❌ `unknown`；只能用全局 `bullet_delta` 代理 |
| `enemy_value` 各分量 | 预测发弹量不可得 | 🟡 只能用距离/生命/列对齐的启发式 |

纪律：**不得以 score 增加代替敌人击杀证据**。本轮 ENEMY 块的标签用 `bullet_delta`（全局）与 `enemy_life_delta`（逐敌人），二者都显式标注为代理。

### 2.4 Damage Window（§2.4）

| 需求字段 | 来源 | 状态 |
|---|---|---|
| `damage_intent` / `target_id` / `aim_confidence` / `damage_abort_reason` | 教师输出 | `unknown` |

### 2.6 Bomb 与资源（§2.6）

| 需求字段 | 来源 | 状态 |
|---|---|---|
| `bomb_available` | `resources.bombs > 0` | ✅ |
| `bomb_trigger_reason` | 教师输出 | `unknown` |

## 3 标签纪律（与执行计划 §4 同源）

1. 特征只用决策 i 当时的快照；标签只用 i 之后的数据。
2. 视界不足的尾部样本从该标签分母剔除。
3. `unknown` 字段不填 0、不插值、不参与特征。
4. 每份报告必须列出 `unknown` 字段清单与受影响的结论。

## 5 已发现的读取缺陷（D2 采集时确认）

### 5.1 `current_spell`：字段宽度读错 + 菜单标志污染

`GameManager::currentSpellCardNumber` 是 0x3DBB0 上的 **i16**（`C_ASSERT(offsetof(GameManager, currentSpellCardNumber) == 0x3DBB0)`，`third_party/th08/src/GameManager.hpp:416`）。`state.py` 原先按 4 字节 `<i` 读取，把紧邻的 `isInGameMenu`（0x3DBB2）与 `showRetryMenu`（0x3DBB3）一并读了进来。

| 语料 | 实测分布 | 含义 |
|---|---|---|
| D1（教师，21,156 决策） | `0` × 21,150；`16,777,216`（0x01000000）× 6 | 后 6 个是 **retry 菜单**，被 `trace35.events_between` 记成 `spell` 事件 |
| D2（人类，30,000 决策） | `65535` × 30,000 | i16 的 −1（"无符卡"）按 u32 读成 65535 |

后果与处置：

1. **v3.5.0 S0 的 3 个 "spell" 事件是假事件**（恰好落在 3 个 game_over 局，即 retry 菜单出现的时刻）。它不影响 S0-3 判定（该门看 stage_clear/game_over/left_game），但事件契约的 `spell` 类型此前是错的。
2. **符卡相位在正常游玩中读不到**：D2 全程 −1，而 57.3% 的决策有 Boss 在场。因此 §2.4 的"非符/符卡/无敌/阶段转换"记为 `unknown`，**不用常数列冒充**。
3. `state.py` 已改为按 i16 读取并抽出 `_read_current_spell()`（单测：`test_current_spell_is_read_as_i16_not_contaminated_by_menu_flags`）。修复只对后续采集生效；D1/D2 的 trace 保留旧编码，`BOSS_spell` 在两次消融中都是死列，所以已提交数值不受影响。

## 6 与需求文档 T0 门禁的对照

| T0 判据 | 阈值 | 本轮状态 |
|---|---|---|
| 稳态样本 complete 率 | ≥99% | **D1 ✅ 99.995%**；**D2 ❌ 98.59%**（唯一原因是 `frame_mismatch` 425 条，`schema_*_error` = 0；`--strict-frames` 敏感性显示结论不变，见 D2 报告 §5.4） |
| 关键字段 schema error | 0 | ✅ 两个语料均无 `schema_*_error` |
| 首步完整 snapshot | 100% | 🟡 待复核（`decision=1` 的 `bullets.count` 是否可信） |
| 真机可区分 stage-clear / game-over | 各 1 例 | ✅ **两格都有真实样本**：game_over 3 局（D1）、stage_clear 2 局（`data/probe/d2-stageclear`，`stage_advanced + clear_sequence + clear_screen` 三重证据） |
| 按整局切分 | 100% | ✅ `trace35.stable_split` |

结论：T0 的门禁项已全部有实测答案——complete 率在 99% 口径下回放语料不达标（97.2–98.6%，唯一原因 `frame_mismatch`，已用严格时序敏感性证明对结论无影响），其余四项通过。**首步完整 snapshot 仍待复核**（`decision=1` 的 `bullets.count` 是否可信），这是 T0 唯一的开放项。
