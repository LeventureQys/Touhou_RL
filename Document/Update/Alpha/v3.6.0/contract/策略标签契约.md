# v3.6.0 策略标签契约（T0 交付物 2/3）

- 日期：2026-10-25
- 依据：[需求文档](<../需求文档.md>) §2.1–§2.6、§3.3、§4 T0
- 作用：把六条战术的"必须记录字段"翻译成**当前 trace 能读到的字段**与**读不到、必须写 `unknown` 的字段**。本文件是 T1 特征块与标签表的唯一依据，代码见 `touhou_rl/ablate36.py`。

---

## 0 一句话结论

当前 `v350-trace/1` 能支撑 **观测侧 6/6 条战术的部分字段**，但**意图侧字段一律为 `unknown`**：trace 记录的是"游戏发生了什么"，不是"教师想要什么"。所以 T1 只能验证**信息增量**（这条战术能看见的量是否可预测），不能验证**意图正确性**（教师是否真的这么想）。意图标签要在 T2 由教师显式输出并落盘，本轮不伪造。

## 2 逐战术契约

### 2.1 Lure / Reposition（§2.1）

| 需求字段 | 来源 | 状态 |
|---|---|---|
| `intent=lure` | 教师输出 | `unknown` |
| `lure_phase` | 教师输出 | `unknown` |
| `target_side` | 教师输出 | `unknown` |
| `abort_reason` | 教师输出 | `unknown` |
| **可诱导攻击是否存在** | 由弹速方向与自机连线夹角计算（|cos| ≥ 0.985 且接近） | ✅ 可观测，记为 `aimed_count` |
| **预计锁定/发射窗口** | 由上述子弹的 TTC 分布估计 | ✅ 部分可观测（`aimed_ttc_min/mean`） |
| **换边后安全走廊宽度** | 由 `t=20/40` 危险图的玩家行自由连通宽度 | ✅ 可观测 |
| **预计暴露时间** | 沿"玩家→出口"直线采样危险密度积分 | ✅ 可观测（近似） |
| **诱导失败条件** | 教师输出 | `unknown` |

纪律：**不把"是否向左/向右"当诱导标签**。本轮 LURE 块只放"瞄准几何量"，不放任何方向动作。

### 2.2 出口与未来安全 / LeaveRegion（§2.2）

| 需求字段 | 来源 | 状态 |
|---|---|---|
| 危险密度 | 每格子弹中心计数（8 px / 16 px 两尺度） | ✅ |
| 多尺度占据 | 同上，`t = 0/10/20/40/60` | ✅ |
| 扩张 / 流向 | 玩家连通分量质心在 t=20→40 的位移 | ✅ |
| 可达出口 | 最近自由格（Chebyshev 环搜索）及其连通分量面积 | ✅ |
| 最短暴露路径 | 玩家→出口直线的密度积分 | ✅ 近似（不做法向 D 算法） |
| 贴墙风险 | 到 `MOVE_AREA` 四边的最小距离 | ✅ |
| 并集/密度区域 | 密度 ≥ 2 的连通分量（**v3.5.0 S1 缺的就是这个**） | ✅ 本轮新增 |

v3.5.0 S1 只取"玩家所在的单一连通分量"，本契约要求同时记录**并集/密度区域**，这是 T0 §4.1 的修订项。

### 2.3 ClearEnemy（§2.3）

| 需求字段 | 来源 | 状态 |
|---|---|---|
| 敌人位置 / 生命 / 类型 / 活动 / ID | `enemies[]` | ✅ |
| 选择目标 / 开始攻击 / 生命下降 / 击杀 | 目标选择是教师输出 `unknown`；生命下降与消失可从未来快照观测 | 🟡 部分 |
| **击杀后 60/240 帧发弹减少** | 需要 bullet→enemy 归属 | ❌ `unknown`；只能用全局 `bullet_delta` 代理 |
| `enemy_value` 各分量 | 预测发弹量不可得 | 🟡 只能用距离/生命/列对齐的启发式 |

纪律：**不得以 score 增加代替敌人击杀证据**。本轮 ENEMY 块的标签用 `bullet_delta`（全局）与 `enemy_life_delta`（逐敌人），二者都显式标注为代理。

### 2.4 Damage Window（§2.4）

| 需求字段 | 来源 | 状态 |
|---|---|---|
| `damage_intent` / `target_id` / `aim_confidence` / `damage_abort_reason` | 教师输出 | `unknown` |
| Boss 位置 / 生命 / 符卡 | `bosses[]`、`clock.current_spell` | ✅ |
| 非符/符卡/无敌/对话/阶段转换区分 | `current_spell` + `flags`（STAGE_CLEAR_SEQUENCE / dialogue） | 🟡 部分 |
| 输出窗口（安全时才对得准） | 由 18 动作 horizon 中"横向贴近 Boss 且 clearance>阈值"的动作存在性 | ✅ 可观测 |

纪律：**不把"永远对准 Boss"当隐藏奖励**；BOSS 块里的对准量必须与安全量联合给出（`align_safe` = 既对准又安全的动作是否存在）。

### 2.5 CollectPower（§2.5）

| 需求字段 | 来源 | 状态 |
|---|---|---|
| power 上限 / 未满判据 | `POWER_MAX=128`、`resources.power` | ✅ |
| 自动收集线真实 y | `shot.point_item_value_line`（实测 128.0） | ✅ |
| 有效 P 存在 | `items[].type ∈ {0,2,4}` 且 `onscreen` | ✅ |
| 到收集线路线风险 | 向上动作的 horizon clearance（近似，不是路径规划） | 🟡 近似 |
| P 出现 / 目标 / 收集 / power 增量 / 中止原因 | 出现与收集可从 `items`/`frame_events`/`power` 观测；目标与中止原因是教师输出 | 🟡 部分 |

v3.5.0 已验证的基础契约（power≤128、收集线 y=128、聚焦条件、自动收集速度 10 px/帧）在本版沿用，不重复验证。

### 2.6 Bomb 与资源（§2.6）

| 需求字段 | 来源 | 状态 |
|---|---|---|
| `bomb_available` | `resources.bombs > 0` | ✅ |
| `bomb_trigger_reason` | 教师输出 | `unknown` |
| 使用前候选路线数 | 18 动作中 horizon clearance > 0 的动作数 | ✅ 可观测 |
| 使用后生存结果 | 未来 `death_60` | ✅ |
| bomb 归属（纯学生 vs fallback） | 本版为教师内部行为，必须在报告里单列 | ✅ 可审计 |

纪律：**18 动作空间里没有独立 bomb 决策位**（动作维度是 `[move, shoot, focus, bomb]`，但教师只在"所有路线都碰撞"时才置位）。因此本版 bomb 一律记为 **fallback**，其收益**不得**计入纯策略能力。§2.6 建议的 36 动作空间（9×2×2）冻结在本版之外。

## 3 标签纪律（与执行计划 §4 同源）

1. 特征只用决策 i 当时的快照；标签只用 i 之后的数据。
2. 视界不足的尾部样本从该标签分母剔除。
3. `unknown` 字段不填 0、不插值、不参与特征。
4. 每份报告必须列出 `unknown` 字段清单与受影响的结论。
