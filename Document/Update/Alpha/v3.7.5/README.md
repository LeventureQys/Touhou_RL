# v3.7.5 清理版本：Alpha 未完成目标收口计划

- 版本：v3.7.5
- 日期：2026-11-05
- 状态：计划版，尚未执行，不代表任何能力门通过
- 上一版本：v3.7.4 同帧证明
- 计划来源：v3.7.3 升级执行计划

## 0. 版本目的

本版本不是继续增加网络结构，也不是重新包装历史实验结果，而是把 Alpha 阶段所有未完成目标集中登记、重新排序、逐项清理。

清理版本的目标是：

1. 清除“已实现代码”和“已验证能力”之间的混淆；
2. 清除没有真实标签、没有清晰门禁、没有独立测试的训练路径；
3. 清除未实现的 CLI、契约、清单和证据接口；
4. 清除旧实验中不等曝光、常量可解、特权泄漏和同步未知造成的结论污染；
5. 在没有游戏的机器上完成所有可离线完成的工作，并把游戏依赖项明确留为 blocked 或 not_run；
6. 形成一个可以继续执行、也可以在失败时停止的单一计划。

本版本不声称已经会玩，不替换默认模型，不修改 canonical 游戏镜像，不把合成训练、工程冒烟或旧报告当成真机能力。

## 1. 清理版本的出口范围

Alpha 的最小可交付范围暂定为：

> 在 F2 类“对象可以从真实画面观察到”的战术上，形成可审计的 exact 帧采集、合法标签、分组数据、关系型目标训练、因果闭环和真机实验接口。

以下目标从本版本出口中移出，作为后续版本：

- F1/F3 等无法从真实会话产生合法标签的战术；
- 六类战术全部支持；
- 未经过独立确认的死亡率改善；
- 跨东方作品迁移；
- 自动框选、跨分辨率和跨画风输入层。

如果后续要扩大范围，必须新建预注册和新版本，不能在本版本中隐式扩大。

## 3. 全部未完成目标

### C0：计划、范围和证据状态清理

- 把历史结论分为 passed、failed、void、not_run、blocked。
- 把 v3.7.0 真机结果标为协议不完整，不能作因果结论。
- 把 R11–R16 等含常量可解场景的聚合结论标为作废。
- 把 v3.7.4 的同帧结论限定为 build_fence 变体和对应环境指纹。
- 为每个任务绑定文件、命令、输出路径和验收条件。

### C1：exact 采集正式接入

- capture_dataset.py 增加 frame-proof exact。
- exact 模式启动前检查变体 exe、map、地址表、SHA 和环境。
- 使用 FenceFrameSampler(accept_current=True)，避免逐样张写盘时浪费 hold。
- 每个样本保存 PNG、ticket、逻辑帧、游戏状态、13 项检查、读取耗时、镜像身份和地址表哈希。
- 任一样本失败、hold 过期或校验不一致时停止并写失败报告。
- 旧路径继续输出 alignment_unknown，不能静默升级为 exact。

### C2：exact 清单和数据门

- manifest.json 增加 frameProof、exactValidFrames、checkNames、构建哈希和环境指纹。
- process 和 inspect 对 exact 数据执行 fail-closed 审计。
- 检查 PNG、JSONL、分片和 manifest 的数量、顺序、SHA 和 proof 一致性。
- 预注册 3000 帧试采集；discarded=0、13 项检查全过后才允许进入事件数据阶段。
- 试采集前不解冻像素几何标签。

### C3：标签源、课程和教师清理

- Alpha 默认只支持 F2 类目标；如扩展 F5，必须单独预注册。
- F1/F3 只有在真实画面能独立产生对象标签后才能重新纳入。
- 教师不得读取部署输入中不存在的世界参数来生成成功标签。
- unknown、budget_exhausted、no_solution 不自动变成失败标签。
- 每个支持族至少建立训练、验证、测试完整事件，按模板分组，禁止逐帧随机拆分。
- 每个成功标签包含目标、截止时间、路线见证、实际动作、有效性和置信度。

### C4：契约、CLI 和工程缺口清理

计划中的接口必须和仓库实际代码一致：

- 新增 tactical_contracts.py。
- 新增 tactical_evaluate.py。
- 补齐 tools/rl/tactical.py 的 scenarios、teacher-eval、train、closed-loop、live-pair、settle。
- 为每个命令提供 --help、参数校验、退出码和 smoke 测试。
- 将 v3.7.3 计划中的 configs、manifests、reports、evidence 变成真实产物目录。
- 工程冒烟输出必须明确标注 not_gameplay_training，不能被训练门接受。

### C5：关系型目标和 P4 训练清理

- 将“屏幕左/右分类”替换为 gap_center - player_x 关系型目标。
- 训练分布必须同时覆盖两个朝向、不同自机位置和左右边界。
- 先冻结 v3-st 视觉骨干，只训练新头。
- 先对 8 个可靠事件做过拟合诊断，要求可靠动作正例一致率至少 95%。
- 比较 B0、B1、N0、N1 四个实验臂，使用相同数据、预算、分组和 3 个 seed。
- 只按留出事件指标选模型，不按训练 loss 单独选。
- 骨干解冻、空间特征或更复杂时序结构只能作为单因素后续实验。
- 训练失败时状态为 overfit 或 not_learned，不得进入接管。

### C6：P5 因果闭环和失败状态清理

- 合成环境必须响应实际动作，不使用固定未来轨迹冒充反事实。
- runner 保持 propose(pixels) 和 commit(actual_action, actual_hold, effective_frame) 两阶段语义。
- 未发送、超时、fallback 和人工接管不能写入已执行动作。
- 死亡、重生、reset 和帧回退清空 hidden、目标和动作历史。
- 高层意图和低层控制分别记录，危险或目标失效可中断。
- 最多两轮失败状态补采；重复同类返身失败时停止堆数据，检查目标和结构。
- 旧合成结果只作为诊断，不恢复为能力结论。

### C7：P6 真机公平实验清理

该阶段依赖游戏，当前机器没有游戏，因此本版本只能完成代码、协议和假时钟测试。

有游戏后必须满足：

- 以 gameplay_frame 而不是决策次数结束；
- baseline 和 subject 使用共同的截图、输入后端、frameskip、资源协议；
- AB/BA 随机顺序；
- 记录 start/end frame、实际曝光、发送帧、生效帧、hold、延迟和 stale/reject；
- 先影子运行，再进行短窗口共同管线配对；
- 死亡前保留至少 120 帧，并区分观测、预测、路线、执行、输入延迟、资源和未知原因；
- P95 端到端候选延迟低于一个 2 帧周期 33.3 ms；
- 真机数据不足时保持 not_run，不以合成结果替代。

### C8：P7 独立确认、发布和回滚清理

- 在独立测试前冻结模型 SHA、配置、阈值、关卡窗口、主指标、样本量和排除规则。
- 使用功效分析确定样本量，不得看到结果后追加到显著。
- 主指标为固定逻辑帧窗口死亡数，同时报告首死、生存到窗口末、bomb 和各战术族。
- 发布门：死亡相对下降目标至少 20%，配对差 95% 区间上界小于 0，资源指标无明显退化。
- 交付 checkpoint、SHA、配置、数据 manifest、训练日志、原始 trace、重算工具、失败清单和回滚说明。
- 未通过时只发布研究 flag，不替换默认模型。

### C9：跨作品输入层

- 自动框选尚未实现。
- 分辨率、缩放、DPI、画风变化的归一化尚未验证。
- 该目标不阻塞 F2/TH08 Alpha 清理，放到后续版本。

- 使用测试集选择网络、阈值或标签规则。

## 5. 无游戏机器的执行边界

当前机器没有游戏时，可以完成：

- 文档、配置、预注册和状态清理；
- exact schema、manifest、CLI、fake sampler 和负例测试；
- F2 合成课程、教师审计和关系型目标；
- 冻结骨干的工程训练、过拟合诊断和合成闭环；
- P6 所需的假时钟、延迟、回退、commit 和 trace 测试。

当前机器不能完成：

- 真实 exact 帧采集；
- 真实 F2 标签数据；
- 真实像素能力训练；
- 真机公平配对；
- 独立真机确认和发布。

所有不能执行的项目必须写成 blocked: game_required 或 not_run，不能用工程 smoke、旧数据或合成图像替代。
