# v3.7.5 验收标准

## 1. 状态规则

本版本所有验收项初始为 not_started。不能因为文件存在、单测通过或命令能启动就判为能力通过。

- passed：有实际命令、退出码、输出路径和可复核证据；
- failed：执行过但指标未达；
- not_run：没有执行；
- blocked：外部前置条件缺失，当前无法执行；
- void：历史结果因协议、标签或数据质量问题作废。

## 2. 清理门

| 门 | 内容 | 通过条件 | 无游戏时 |
|---|---|---|---|
| G0 | 范围和状态清理 | 所有历史结果和未完成项有唯一状态；F2 范围冻结 | 可执行 |
| G1 | exact 代码接入 | capture、proof、manifest、inspect、负例和回归测试通过 | 可执行 |
| G2 | exact 试采集 | 3000 帧、0 丢弃、13 项检查全过、环境指纹完整 | blocked: game_required |
| G3 | F2 标签数据 | 标签可观测、输入因果、资产隔离、分组无泄漏 | 只能做合成和结构审计 |
| G4 | P4 训练 | 8 事件过拟合、四臂比较、3 seeds、留出有方向性收益 | 可做合成诊断；真实像素为 not_run |
| G5 | P5 闭环 | 环境响应实际动作，commit/reset/unknown 语义正确，闭环门通过 | 可执行合成闭环 |
| G6 | P6 真机 | 等逻辑帧曝光、AB/BA、共同管线、时序和死亡归因完整 | blocked: game_required |
| G7 | P7 发布 | 独立确认、功效、死亡门、资源门、全量回归通过 | blocked: game_required |
| G8 | 跨作品 | 自动框选、归一化和跨作品验证 | 本版本不执行 |

## 3. 关键硬门

以下任一条件失败，不能进入下一阶段：

1. exact 数据的任一帧没有 ticket、hold 状态和完整校验；
2. canonical 镜像被用于 exact 声明；
3. F1/F3 的特权标签混入 F2 正式训练集；
4. unknown 或 budget 被当作负标签；
5. train/validation/test 存在模板、像素或 episode 泄漏；
6. 训练集拟合但留出无效；
7. proposal 未实际执行却写入动作历史；
8. 真机两臂实际逻辑帧曝光不一致；
9. 看过独立测试结果后修改阈值、样本量或排除规则；
10. 没有游戏时伪造真实采集、真机效果或发布证据。

## 4. 必须保存的证据

每个通过或失败的门都必须保存：

- 完整命令；
- 退出码；
- 代码、配置和数据 SHA；
- 环境版本；
- JSON 机器报告；
- pytest 或 smoke 日志；
- 原始 trace 或失败样本；
- 结论适用范围；
- 下一任务或停止原因。

## 5. 版本出口

v3.7.5 只有在 G0、G1、G3、G4、G5 通过后，才能称为“离线清理完成”。

G2、G6、G7 在没有游戏时只能保持 blocked 或 not_run，不能通过文档补齐。

即使 G0–G7 全部完成，也只有 G7 通过后才允许声明指定协议下的真机改善；跨作品迁移仍属于 G8 后续目标。
