# v3.7.5 清理执行计划

## 使用方式

本文件是执行顺序和文件级修改计划。每个工作包必须同时产出代码、测试、命令记录和状态报告。状态只允许：

- passed：满足本文件验收条件并有证据；
- failed：执行过但未满足条件；
- not_run：没有执行；
- blocked：外部条件缺失，当前无法执行；
- void：历史结论因协议或数据问题作废。

没有证据的任务不得写成 passed。

## U01：实现 exact 采集适配层

目标：让正式采集路径能产生 exact 数据，同时保留旧路径。

修改文件：

- touhou_rl/capture_dataset.py
- touhou_rl/frame_proof.py
- touhou_rl/pipeline/manifest.py
- touhou_rl/pipeline/cli.py
- tools/rl/frame_fence_capture.py

实现：

1. 增加 frame_proof 参数，默认 alignment_unknown；
2. exact 模式强制使用 fence 模板和 TH08_ADDRESS_FILE；
3. 启动前校验 exe、map、地址表、text SHA、地址表 SHA；
4. 使用 FenceFrameSampler(accept_current=True)；
5. 把每帧 proof、PNG、状态、动作和耗时写入统一 schema；
6. hold 失败、校验失败、环境不匹配时 fail-closed；
7. 老数据不添加伪造 exact 字段，只标记 unknown。

验收：

- fake sampler 可以测试成功、失败即停、hold 超时和混合 proof；
- canonical 模板请求 exact 在启动游戏前失败；
- manifest 篡改 PNG、JSONL 或地址表后 inspect 失败；
- 默认旧采集路径回归通过。

当前无游戏状态：代码和假对象测试可做；真机试采集为 blocked: game_required。

- 结果不足时标为探索性，不进入 P7。

## U07：冻结、独立确认和发布

目标：只有能力门通过才允许发布。

- 样本量和排除规则；

确认：

- 使用独立测试集；
- 以固定逻辑帧窗口死亡数为主指标；
- 计算功效和配对区间；
- 报告失败、unknown、技术剔除和资源使用。

发布门：

- 死亡相对下降目标 ≥20%；
- 配对差 95% 区间上界 <0；
- bomb、局部生存和支持族指标不明显退化；
- 全量回归通过。

不通过则交付负结果和研究 flag，不替换默认模型。

## 串行停止规则

- C2 exact 数据门未通过：停止正式训练；
- C3 合法标签不足：缩小支持范围，不补造标签；
- C4 工程契约失败：停止训练和真机；
- C5 留出失败：先修目标或数据，不扩大网络；
- C6 闭环失败：停止 P6；
- C7 真机协议不完整：停止 P7；
- C8 发布门失败：保留默认模型，交付负结果。
