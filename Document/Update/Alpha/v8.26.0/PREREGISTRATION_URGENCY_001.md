# 预注册 v8260-URGENCY-001：**紧迫度自适应阈值**（用「每颗雷还能换多少决策」调阈值）

冻结时刻：2026-11-22（Asia/Shanghai），**在任何 v8.26.0 评测之前**。
状态：**FROZEN**。

---

## 0. 为什么

本线已确立一个**矛盾**（§34.4 / §35.3）：

| 预算 | 最优阈值 | 现象 |
| --- | --- | --- |
| 20 s | **60/40/20（松）** | 雷够用，收紧反而掉 6.25 pp |
| 30 s | 35/15/3（紧） | 收紧 +24.6 pp |
| 40 s | 35/15/3（紧） | 收紧 +10.4 pp |

⇒ **`S-switch`：一套固定阈值无法覆盖三档**（v8.25 已证，P1 不成立）。

**但「固定阈值」本身可能是问题**：真正该依赖的不是「预算」，而是**「每颗雷还能换多少决策」**（紧迫度）：

```
urgency = 剩余决策数 / max(剩余雷数, 1)      # 每颗雷覆盖多少决策
```

- **urgency 大**（雷少、路长）⇒ **紧**（别浪费）；
- **urgency 小**（雷多、路短）⇒ **松**（该用就用）。

开局：20 s 时 urgency=200；40 s 时 urgency=400 ⇒ **同一套公式会自动在长段更紧**。

---

## 1. 设计（单因子：紧迫度响应强度 α）

阈值按紧迫度缩放：

```
scale = (urgency / 200) ** α            # 200 = 20 s 开局的基准
thr[size] = base[size] * scale          # base = 35/15/3
          clipped to [5, 120] px        # 见下方 §1.1 的下限理由
```

### 1.1 下限为何是 5 px（而不是 1 px）

v8.23 已实测：**第三档 3 px 太紧**——`49/240 局带着 1 颗雷死掉`（§35.8）。
而本公式在**末段**（剩 100 决策、1 颗雷）会给 `scale = 0.5^α < 1`，把阈值压到
`35/15/3 × 0.5 = 17.5/7.5/1.5` ⇒ **第三档 1.5 px 几乎永不触发**，等于把最后一颗雷作废。

⇒ **必须给下限 5 px**（与 v8.23 的 40/20/5 中已验证可用的 5 px 一致）。
**这是公式的唯一硬编码保护**，在 §1 之上追加，不算新因子。

| 臂 | α | 行为 |
| --- | --- | --- |
| **G0**（对照） | — | 固定 35/15/3（v8.25 已测：92.50 / 48.75 / 12.50） |
| **G1** | **0.50** | 温和响应（urgency 400 时阈值 ×1.41） |
| **G2** | **1.00** | 线性响应（urgency 400 时阈值 ×2.0） |
| **G3** | **1.50** | 强响应（urgency 400 时阈值 ×2.83） |

**另一组对照**：固定 60/40/20（v8.20 已测：98.75 / 24.17 / 2.08）。

每臂 **3 种子 × 4 窗 × 20 = 240 条 × 3 档（600/900/1200）**。

**关键**：urgency 用**真实剩余决策数**（`budget_decisions - decisions_executed`），不用剩余帧数。

## 2. 判据

| # | 终点 | 判据 |
| --- | --- | --- |
| **P1（主）** | **三档同时** | 每档都 **≥ max(固定阈值的两臂在该档的结果)**：20 s ≥98.75%、30 s ≥48.75%、40 s ≥12.50% |
| **P2** | 三档是否都超过 G0 | 30 s **>48.75%** 或 40 s **>12.50%**（至少一档严格更好，Fisher p<0.05） |
| **P3** | 用雷 | 报三档的**存活局均值**（§35.12 的口径） |
| **P4** | distinct | 每格必须报 |

### 2.1 停止条件

| # | 条件 | 动作 |
| --- | --- | --- |
| **S-adaptive** | P1 与 P2 都成立 | 判「**紧迫度自适应统一了三档**」⇒ 本线的最终部署配置 |
| **S-partial** | P2 成立但 P1 不成立 | 报「自适应在某档更好、某档更差」，给出**分档最优表** |
| **S-null** | P2 不成立 | 判「紧迫度响应无效」⇒ 保留 `S-switch`（两套固定阈值） |
| **S-fork** | 保真门失败 | 整轮作废 |
