## 机制：α 越大，长段越崩（本轮最强、可复核的因果链）

1. **开局阈值随 α 指数抬高**。40 s 开局 `urgency = R/B = 1200/3 = 400` ⇒ `scale = 2**α` ⇒ `thr[3]` =
   **49.50 px（G1）/ 70.00 px（G2）/ 98.99 px（G3）**，而 PARK 后第一帧最近弹距约 **24.96 px**
   （smoke 决策 0 实测 `nearest_all_px = 24.9619`）。三臂在 40 s 的 `first_bomb_decision` 均值都是 **0.00**，即开局立刻放雷。
2. **公式自带正反馈**：放掉一颗后 `B` 减 1、`R` 几乎不变 ⇒ `urgency = R/B` 变大 ⇒ `scale = (urgency/200)**α` 变大 ⇒ 阈值更松 ⇒ 下一颗更容易放。α 越大，反馈越猛：`B=1` 时 `urgency ≈ 1200` ⇒ `scale = 6**α` = 2.45 / 6.00 / 14.70 ⇒ `thr[3] = 85.8 / 120（封顶）/ 120（封顶）`。
3. **实测后果**（40 s，三档同一生成器流）：

   | α | 开局 thr[3] | 放雷时阈值均值 | 放雷时最近距离均值 | 最后一颗雷的中位决策 | 用尽 3 颗雷的局 | 存活 |
   |---|---|---|---|---|---|---|
   | 0.50 | 49.50 | 25.18 px | **16.91 px** | 600.5 / 1200 | 239/240 | **34/240 = 14.17%** |
   | 1.00 | 70.00 | 40.53 px | 21.23 px | 534.0 / 1200 | 240/240 | 9/240 = 3.75% |
   | 1.50 | 98.99 | 68.58 px | **25.58 px** | 500.5 / 1200 | 240/240 | 5/240 = 2.08% |

   即：α 越大 ⇒ 雷在**更远**的距离被丢掉（16.9 → 21.2 → 25.6 px）、且**更早**丢完（中位 601 → 534 → 501），
   剩下的决策段完全无雷。两个因素的相对贡献本轮**不做分解**（没有消融臂，公式里的 α 同时控制两者）。

## 不能声称什么（预注册 §5 + 本轮实测边界）

1. **不能声称"紧迫度自适应更好"**。只在 30 s 得到统计证明（+12.08 pp, p=0.0051）；20 s 是 +0.83 pp（p=0.3117，**非劣**）、40 s 是 +1.67 pp（p=0.3437，不显著）。正确表述：**α=0.50 在三档都"不劣于"该档最优固定阈值，并在 30 s 显著更好。**
2. **不能把 α=0.50 之外的设置当成可选**。G2/G3 的 40 s 分别 3.75% / 2.08%，是灾难性崩塌，不是"稍差"。
3. **不能声称"学会了资源分配"**：这仍是手写公式 `thr = base * (R/max(B,1)/200)**α`，只是公式依赖剩余量（预注册 §5 原话）。
4. **窗重叠**：训练/评测同批 dev 窗（11/12/17/18），不能声称跨窗泛化。
5. **v8.27 的 scale 上限未做**：本轮只有 `[5, 120]` 的硬裁剪，**没有**给 `scale` 本身设上限/阻尼；α>1 的正反馈正是靠 120 px 封顶才没更糟。"把 scale 封顶/加阻尼"是下一轮的事，本轮未做、也不能从本轮数据推断其效果。
6. **12 个 (seed, window) 单元格不独立**：pooled 率带精确 Clopper-Pearson 区间，不能把 240 条当 240 个独立样本去做更细的检验。
7. **不许引用任何 argmax 读数**（§32.5）：本轮 `candidate_sampled` 每局都 ≥2 个不同候选，`all_pass` 见 `summary.json` 的 `invalid_rows = 0`。

## 判定（预注册 §2 / §2.1）

### 主判定：预注册字面读法 = `S-adaptive`（且只对 α=0.50 成立）

| 判据 | 结果 |
|---|---|
| **P1** 三档**同时** ≥ 各自最优固定阈值 | **成立（仅 G1）**：20 s 239/240 = 99.5833% ≥ 98.75%；30 s 146/240 = 60.8333% ≥ 48.75%；40 s 34/240 = 14.1667% ≥ 12.50% |

| **P3** 用雷（**存活局单独报**，§35.12） | 已报：见"Bomb usage, survivors reported apart"与表 A |
| **P4** `distinct` 每格 | 已报四处：arm×tier、逐窗口、逐种子、逐单元格（window×seed） |

⇒ `stop_condition = S-adaptive`，`S-adaptive.held = true`；唯一通过臂 **G1（α=0.50）**。

### 敏感性：更严读法（三档**都**要显著更好）= `S-partial`

## 机制：α 越大，长段越崩（本轮最强、可复核的因果链）

1. **开局阈值随 α 指数抬高**。40 s 开局 `urgency = R/B = 1200/3 = 400` ⇒ `scale = 2**α` ⇒ `thr[3]` =
   **49.50 px（G1）/ 70.00 px（G2）/ 98.99 px（G3）**，而 PARK 后第一帧最近弹距约 **24.96 px**
   （smoke 决策 0 实测 `nearest_all_px = 24.9619`）。三臂在 40 s 的 `first_bomb_decision` 均值都是 **0.00**，即开局立刻放雷。
2. **公式自带正反馈**：放掉一颗后 `B` 减 1、`R` 几乎不变 ⇒ `urgency = R/B` 变大 ⇒ `scale = (urgency/200)**α` 变大 ⇒ 阈值更松 ⇒ 下一颗更容易放。α 越大，反馈越猛：`B=1` 时 `urgency ≈ 1200` ⇒ `scale = 6**α` = 2.45 / 6.00 / 14.70 ⇒ `thr[3] = 85.8 / 120（封顶）/ 120（封顶）`。
3. **实测后果**（40 s，三档同一生成器流）：

   | α | 开局 thr[3] | 放雷时阈值均值 | 放雷时最近距离均值 | 最后一颗雷的中位决策 | 用尽 3 颗雷的局 | 存活 |
   |---|---|---|---|---|---|---|
   | 0.50 | 49.50 | 25.18 px | **16.91 px** | 600.5 / 1200 | 239/240 | **34/240 = 14.17%** |
   | 1.00 | 70.00 | 40.53 px | 21.23 px | 534.0 / 1200 | 240/240 | 9/240 = 3.75% |
   | 1.50 | 98.99 | 68.58 px | **25.58 px** | 500.5 / 1200 | 240/240 | 5/240 = 2.08% |

   即：α 越大 ⇒ 雷在**更远**的距离被丢掉（16.9 → 21.2 → 25.6 px）、且**更早**丢完（中位 601 → 534 → 501），
   剩下的决策段完全无雷。两个因素的相对贡献本轮**不做分解**（没有消融臂，公式里的 α 同时控制两者）。

## 不能声称什么（预注册 §5 + 本轮实测边界）

1. **不能声称"紧迫度自适应更好"**。只在 30 s 得到统计证明（+12.08 pp, p=0.0051）；20 s 是 +0.83 pp（p=0.3117，**非劣**）、40 s 是 +1.67 pp（p=0.3437，不显著）。正确表述：**α=0.50 在三档都"不劣于"该档最优固定阈值，并在 30 s 显著更好。**
2. **不能把 α=0.50 之外的设置当成可选**。G2/G3 的 40 s 分别 3.75% / 2.08%，是灾难性崩塌，不是"稍差"。
3. **不能声称"学会了资源分配"**：这仍是手写公式 `thr = base * (R/max(B,1)/200)**α`，只是公式依赖剩余量（预注册 §5 原话）。
4. **窗重叠**：训练/评测同批 dev 窗（11/12/17/18），不能声称跨窗泛化。
5. **v8.27 的 scale 上限未做**：本轮只有 `[5, 120]` 的硬裁剪，**没有**给 `scale` 本身设上限/阻尼；α>1 的正反馈正是靠 120 px 封顶才没更糟。"把 scale 封顶/加阻尼"是下一轮的事，本轮未做、也不能从本轮数据推断其效果。
6. **12 个 (seed, window) 单元格不独立**：pooled 率带精确 Clopper-Pearson 区间，不能把 240 条当 240 个独立样本去做更细的检验。
7. **不许引用任何 argmax 读数**（§32.5）：本轮 `candidate_sampled` 每局都 ≥2 个不同候选，`all_pass` 见 `summary.json` 的 `invalid_rows = 0`。
