# 预注册 v800-BOMB-001：协议 v2 的第一步——把「放雷」纳入动作空间（先用脚本规则测它值多少）

冻结时刻：2026-11-22（Asia/Shanghai），**在任何 v8.0.0 结果之前**。
状态：**FROZEN**。**本轮的授权依据**：用户在 2026-11-22 明确选择「协议 v2：授权改冻结协议（动作集/观测/决策帧）」。

## 0. 为什么先测「放雷」

现有 18 个候选的构造是 `cand = focus * 9 + move`（`touhou_rl/v400/gym/actions.py:5-22`）：
**9 个方向（含 idle）× 2 个 focus 状态**，而**射击恒开、放雷恒关**（同文件 L58-75 的注释明说「bombing off」）。

- 方向粒度**没有扩的余地**：TH08 的输入是 8 向数字键（`touhou_rl/spec.py` 的 `MOVES`），不存在更细的方向编码。
- **唯一被排除、且真的能救命的东西就是雷**：放雷清弹 + 无敌帧，正是「在密集弹幕里多撑几秒」的手段；而人类的通关打法里雷是核心资源。
- 观测里**已经有雷数**（`tools/rl/v431_arm_a.py:99` 把 `bombs_remaining/8` 放进 106 维特征）——所以「看见自己有几颗雷」这件事早就成立了，只是**从来没有允许它用**。

**所以协议 v2 的第一刀不是「换更大的动作集」，而是「把已经存在但被禁用的那个动作打开」。**
本轮先用**脚本规则**（不是学习）测量「放雷值多少帧」，再决定要不要为它重采标签、重训一个 36 动作的策略。

## 1. 设计（单因子：放雷规则）

| 臂 | 放雷规则 |
| --- | --- |
| **A0（对照）** | 从不放雷（= 现行协议的行为） |
| **A1** | 当**最近子弹距离 < 40 px** 且 `bombs_remaining > 0` 时，该决策放雷 |
| **A2** | 同上，阈值 **60 px** |
| **A3** | 同上，阈值 **80 px** |

- 策略：v4.5.0 的 `S` 三个 checkpoint（冻结，stochastic，与 v4.5.0 同采样规则）。
- 评测：4 个 dev 窗口（11,12,17,18）、起点 frame **8663**、**300 决策 / 600 帧**预算、每 (种子,窗口) **300 条**。
- 放雷实现：在该决策的首帧把 `BTN_BOMB` 与候选动作同时发出（`cand_to_mask(cand, bomb=1)` 已支持），随后 2 帧仍按候选动作走。
- 「最近子弹距离」= 从 `HAZARDS` 的子弹列表里取与玩家位置的最小欧氏距离（像素；玩家命中判定半径按引擎的 2 px 处理，阈值取 40/60/80 是为了覆盖「即将贴身」的三个尺度）。

## 2. 判据

| # | 终点 | 判据 |
| --- | --- | --- |
| **P1（主）** | 活满 600 帧的条数 | 某个放雷臂 **> A0**；单侧 Fisher（三个阈值各对 A0，**Holm 校正**） |
| **P2** | 存活帧数均值 | 某个放雷臂 **> A0**；置换 20,000 次（种子 0） |
| **P3（描述）** | 雷的消耗量、放雷后的存活增量、`bombs_remaining` 掉到 0 的比例 | 只报 |

### 2.1 停止条件

| # | 条件 | 动作 |
| --- | --- | --- |
| **S-fork** | 保真门失败 | 整轮作废 |
| **S-nohelp** | P1 与 P2 都不成立 | 判「放雷不是缺失的能力」；**协议 v2 转下一刀**（观测/决策帧已在 v6/v7 试过，故转为「让策略自己学放雷的时机」或「把段长缩到 120 帧做诊断」） |
| **S-ok** | P1 或 P2 成立 | 判「放雷有增益」；下一轮**为 36 动作（18 × bomb∈{0,1}）重采标签并训练**，再与 18 动作策略同协议对比 |
| **S-harm** | 某个放雷臂显著**更差**（反向 Fisher p<0.05） | 报告写清（可能是「雷放在了不需要的时候、把资源耗尽」）；下一轮改成「只在无路可走时放」的规则 |
