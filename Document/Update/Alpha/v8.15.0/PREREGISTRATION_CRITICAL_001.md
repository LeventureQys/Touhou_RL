# 预注册 v8150-CRITICAL-001：只在**「18 个候选全部在 H 内死亡」**的状态上采样（让标签第一次能表达雷的价值）

冻结时刻：2026-11-22（Asia/Shanghai），**在任何 v8.15.0 采集之前**。
状态：**FROZEN**。

---

## 0. v8.11 的发现把问题改写了

v8.11 的 10,008 个状态给出了一个**比 P0 失败更重要的事实**：

| 指标 | 值 |
| --- | ---: |
| 36 路全 safe 的状态 | **65.67%** |
| 36 个动作平均 `alive_frames` | **118.56 / 120** |
| `max(alive_frames) == 120` | **10,008 / 10,008 个状态都成立** |
| **best bomb=1 − best bomb=0** | **更好 0 / 更差 0 / 相等 10,008** |

⇒ **在被采样的状态上，总有一个「不放雷」的候选能活满 120 帧** ⇒ 反事实标签**从未表达雷的价值**。
这不是采样密度问题（v8.11 已把正例率提高 4 倍）、不是权重问题（v8.5）、也不是状态里有没有雷的余量（v8.6）——是**标签在该状态上根本没有可表达的差异**。

---

## 1. 设计（单因子：采样「哪一类状态」）

| 项 | v8.6 / v8.11 | **v8.15.0** |
| --- | --- | --- |
| 采样对象 | 轨迹上的均匀/触发点附近的状态 | **只采「critical states」**：先对候选状态跑一遍 36 路短标签（H=120），**保留 `max(alive_frames) < 120` 的状态**（即 18 个候选全部在 H 内死亡） |
| 每状态标签 | 36 路（18 候选 × bomb），H=120 | **完全不变** |
| 目标数量 | — | **≥1,200 个 critical 状态**（每段 bombs∈{3,2,1} 各 ≥200） |
| 行为策略 | `S` + R5 | **不变** |
| 训练 | BCE 36 路 | **两臂**：**A** `BCE36 + 0.5×BCE_bomb(R5 规则)`；**B** 仅 `BCE36` |
| 评测 | 300/600/900 | **不变** |

> **为什么这会不一样**：在 critical 状态上，`max over bomb=0` < 120，而 `bomb=1` 可能把它拉到 120 ⇒ 标签第一次出现「放雷更好」的差异，bomb 头才有信号。

---

## 2. 判据

| # | 终点 | 判据 |
| --- | --- | --- |
| **P0（前置）** | 标签是否终于有差异 | 在采到的 critical 状态上，**`best bomb=1 > best bomb=0` 的状态占比 ≥ 20%**；且三段各 ≥200 状态 |
| **P1（主）** | 臂 B（**纯标签**）的 600 决策活满率 | **> 19.44%**（v8.3.0）；单侧 Fisher + CP95 |
| **P2** | 臂 A（规则监督）的 600 决策活满率 | 与 B 并排 |
| **P3** | 用雷分布 | **出现「只用 1–2 颗」的 episode** |
| **P4** | 900 决策 | 与 v8.3（0.61%）、v8.6（2.94%）、R5（17.61%）并排 |

### 2.1 停止条件

| # | 条件 | 动作 |
| --- | --- | --- |
| **S-nodiff** | P0 不成立（<20% 有差异） | 判「H=120 内雷的价值不可表达」；**转在线 RL（v8.8 预注册已就绪）** |
| **S-ok** | P1 与 P3 都成立 | 判「critical-state 采样可行」；下一轮扩到 5,000 状态并做 H 扫描 |
| **S-partial** | P1 成立但 P3 不成立 | 判「学得更久但不省」；转在线 RL |
| **S-fail** | P1 不成立 | 判「critical 状态太少/分布偏」；下一轮改「按死亡前 N 帧采样」 |
| **S-fork** | 保真门失败 | 整轮作废 |

## 3. 成本

| 项 | 估算 |
| --- | --- |
| 预扫（对 ~10,000 个候选状态跑 36 路短标签，判断 critical） | 复用 v8.11 已有的 10,008 状态标签（**零成本**，直接用 `alive_frames` 判定） |

| 训练 A/B 各 3 种子 | ≈ 10 min |
| 评测 A 三档 + B 三档 | ≈ 90–120 min |
| **合计** | **≈ 1.5–2 h**（可能零采集） |
