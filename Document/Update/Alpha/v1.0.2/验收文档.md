## 3. 验收项

> 每项格式：目的 / 步骤（可照抄）/ 期望结果 / 通过标准 / 失败标准 / 证据要求。
> 统一前缀：`$py="C:\Users\a5935\AppData\Local\Programs\Python\Python312\python.exe"`。

### A-01 包结构与版本
- **目的**：v1.0.1 承诺的代码存在且可导入。
- **步骤**：`Get-ChildItem touhou_rl -Filter *.py | Select-Object Name`；`& $py -c "import touhou_rl;print(touhou_rl.__version__)"`。
- **期望**：存在 `spec/winapi/memory/state/config_file/session/menu/obs/reward/env/dataset/capture_dataset/models/bc/ppo/evaluate/play.py`；版本 `1.0.2`。
- **通过标准**：文件齐全且导入无异常。
- **失败标准**：任一文件缺失或导入报错。
- **证据**：命令输出 + `touhou_rl/` 文件清单。

### A-02 单元测试
- **目的**：无游戏依赖的逻辑正确。
- **步骤**：`& $py -m pytest touhou_rl/tests -q`。
- **期望**：`30 passed`（≥28），退出码 0。
- **通过标准**：全绿且退出码 0。
- **失败标准**：任一失败/跳过关键用例（`state`/`obs`/`reward`/`dataset`/`models` 不得 skip）。
- **证据**：pytest 末尾输出。

### A-03 只读与单实例约束
- **目的**：不写内存、不注入、遵守单实例。
- **步骤**：`Select-String -Path touhou_rl/*.py -Pattern "WriteProcessMemory|CreateRemoteThread|VirtualProtectEx"`；启动两个实例观察第二个的报错。
- **期望**：无任何写内存 API；第二实例抛 `RuntimeError` 且消息含 `another th08.exe` 或启动对话框文本。
- **通过标准**：两条都满足。
- **失败标准**：出现写内存/注入调用，或第二实例静默卡死无报错。
- **证据**：grep 输出 + 异常文本。

### A-04 状态与子弹解码（真机）
- **目的**：契约 §2 的字段在真机上正确。
- **步骤**：`& $py -c "..."` 启动会话，进 Stage 1，打印 `read_state()` 与 `read_bullets().active_mask().sum()`。
- **期望**：`supervisor_state=2`、`stage=0`、`lives=2.0`、`bombs=3.0`、玩家坐标在 `(8..376, 16..432)` 内；子弹数与计数器同量级。
- **通过标准**：全部字段合理且子弹坐标落在场地范围内。
- **失败标准**：出现指针值（如 `0x3bd04b8` 型 flags）、坐标越界或子弹恒 0。
- **证据**：`build/rl/probe-v102/probe-v102.json` 的 `in_game`，或本次新跑的 JSON。

### A-05 回放采集（启动测试 L-1）
- **目的**：人类 Lunatic 录像可变成数据集，且专家动作正确。
- **步骤**：`& $py -m touhou_rl.capture_dataset --replay third_party/th08/tests/fixtures/replays/th08-1.00d/accepted/th8_ud2ce5.rpy --out third_party/th08/build/rl/datasets/verify --tag verify --max-minutes 3`。
- **期望**：`frames ≥ 9000`、`nonzero_action_frames/frames > 0.9`、`stages_seen` 含 0、`ended_reason` 为 `max_seconds reached`。
- **通过标准**：以上全部满足，且 `dataset-summary.json` 的帧数等于分片之和。
- **失败标准**：`nonzero_action_frames == 0`（说明用了错误的输入地址）、或一帧未落盘。
- **证据**：`capture-report.json` + `dataset-summary.json` + 分片清单。

### A-06 BC 训练（GPU）
- **目的**：模型能从数据集学到人类动作。
- **步骤**：`& $py -m touhou_rl.bc --dataset <数据集> --out third_party/th08/build/rl/runs/bc --epochs 5 --batch-size 512`。
- **期望**：`bc-summary.json` 存在；`best.pt`/`last.pt` 存在；`parameters < 2e6`；方向头验证准确率 > 0.20（1/9≈0.111 基线的两倍内不设人为门槛，只要求「明显高于基线」）。
- **通过标准**：训练正常结束、检查点可加载、准确率数字与日志一致。
- **失败标准**：NaN 损失、不可加载的检查点、准确率等于随机。
- **证据**：`bc-summary.json` 每 epoch 行 + 训练终端输出。

### A-07 检查点自洽
- **目的**：检查点契约（§8）。
- **步骤**：`& $py -c "from touhou_rl.models import load_checkpoint; m,e=load_checkpoint('...best.pt'); print(m.num_parameters(), e)"`。
- **期望**：加载成功，`extra` 含 `epoch`/`val_loss`。
- **通过标准**：无异常且字段齐备。
- **失败标准**：`ValueError`（维度不符）或字段缺失。
- **证据**：命令输出。

### A-08 实时评估（启动测试 L-2）
- **目的**：模型真的能在游戏里动起来，并给出可比较的数字。
- **步骤**：`& $py -m touhou_rl.evaluate --checkpoint ...best.pt --out third_party/th08/build/rl/eval --episodes 2 --difficulty lunatic --frameskip 2 --max-steps 600`。
- **期望**：`eval-report.json` 含 2 局，`frames_reported > 0`、`wall_seconds > 0`、`stages_reached ≥ 0`、每局截图存在；模型动作导致玩家明显移动（截图或 `last_state`）。
- **通过标准**：两局都完成且字段齐备。
- **失败标准**：抛异常、帧数为 0（游戏没动）、或没有截图。
- **证据**：`eval-report.json` + `episode-*.png`。

### A-09 随机基线对照
- **目的**：证明模型不是「随便按」。
- **步骤**：同 A-08，但用 `--random-baseline`（或在脚本里用未训练检查点）跑 2 局。
- **期望**：报告给出两者的存活帧数对比。
- **通过标准**：对比数字写入验收报告（无论模型好坏）。
- **失败标准**：缺少对照实验。
- **证据**：两份 `eval-report.json` 的 `summary`。

### A-10 play 脚本（无需菜单）
- **目的**：需求「模型不需要选菜单」。
- **步骤**：`& $py -m touhou_rl.play --checkpoint ...best.pt --minutes 3 --team 0 --out third_party/th08/build/rl/play`。
- **期望**：终端逐局 JSON；`play-report.json` 存在；全过程无人工按键。
- **通过标准**：脚本自行完成启动、选难度、选机体、开打、死亡重开。
- **失败标准**：需要人工介入菜单，或中途崩溃。
- **证据**：`play-report.json` + 终端输出 + 截图。

### A-11 PPO 冒烟
- **目的**：在线微调闭环可运行且 KL 锚定生效。
- **步骤**：`& $py -m touhou_rl.ppo --out third_party/th08/build/rl/runs/ppo-smoke --total-steps 64 --rollout-steps 32 --max-steps 40 --bc-checkpoint ...best.pt --kl-coef 0.5`。
- **期望**：`ppo-summary.json` 含 ≥1 个 iteration；`last.pt` 存在；日志里 `value_loss` 有限。
- **通过标准**：退出码 0 且产物齐备。
- **失败标准**：NaN/崩溃/无检查点。
- **证据**：`ppo-summary.json` + 终端输出。

### A-12 一键验证
- **目的**：门禁可复现。
- **步骤**：`powershell -NoProfile -ExecutionPolicy Bypass -File tools/rl/Verify-RL.ps1 -SkipGame`；再跑一次不带 `-SkipGame`（若时间允许）。
- **期望**：`verify-report.json` 每步 `ok=true`，退出码 0。
- **通过标准**：全部 ok。
- **失败标准**：任一步 `ok=false`。
- **证据**：`verify-report.json`。

### A-15 Lunatic 通关判定（如实结论）

- **期望**：验收报告明确写「达成 / 未达成」，未达成时给出：最好的一局到达的关卡、存活帧数、死亡次数、与需求差距。

## 4. 失败与阻塞处理

| 现象 | 处理 |
| --- | --- |
| 游戏启动卡在 `log` 对话框 | 记为阻塞，证据存对话框文本；按 `问题清单.md` F-04 的互斥体原因解释 |
| 失焦导致帧率 14 | 验收前确保窗口前台，或用采集器的前台守卫；在报告里注明 |
| GPU 不可用 | A-06/A-11 允许 `--device cpu`，但要在报告里标注降级 |
| 数据采集不完整（< 3 万帧） | A-05 判失败；A-06 允许用已有更大数据集继续，但需说明 |
