# 视觉改造报告 · 第一批

- 所属阶段：Stage 6（架构改造：特权 RL → 视觉优先）
- 承接：`框架评估-鲁棒性与性能.md`（结论：旧框架是"特权教师工厂"，不是视觉系统）
- 契约：`视觉框架-契约v2.md`
- 一句话结论：**视觉通道从 0 行代码变成可跑通的三层（帧契约 / 数据 / 模型 + 训练 + 部署），
  并在真机上只用像素跑完一局；但"看得准"和"会玩"都还没到可用线，且这是用 2.7 分钟数据换来的
  第一版基线，不是结果。**

## 1. 改了什么（结构层面）

改造前，整条链路没有一处消费像素：抓帧只用于截图，观测是纯数值向量，
`obs.py` 文档里承诺的 `profile.state_source` 开关在代码中并不存在。

改造后，视觉成为一等公民，特权数据降级为**标签**：

```
【训练期 · 特权侧】                          【部署期 · 视觉侧】
 th08.exe 只读内存                            框选区域（PlayfieldBox）
   → self_feat / bullets / danger        ┌──▶  vision.encode_frame
   → pilot 教师 18 路价值                 │      （裁剪 + 面积平均缩放 + 3 帧堆叠）
        │                                │            │
        └─────── 标签 ───────────────────┘      VisionScorer（CNN）
                                                    │
                                            argmax over 18 candidates
                                                    │
                                               SendInput 按键
```

新增模块（均带单测）：

| 文件 | 职责 | 关键约束 |
| --- | --- | --- |
| `touhou_rl/vision.py` | 帧契约：`PlayfieldBox` → 裁剪 → 面积平均缩放 → 帧堆叠 → 归一化 | 部署端唯一允许的输入路径；面积平均保证子弹不被点采样漏掉 |
| `touhou_rl/vision_data.py` | 视觉分片格式（帧 + 特权标签 + 专家动作 + 可选教师价值） | 分片边界 = 回合边界，历史回看不跨片 |
| `touhou_rl/vmodels.py` | 共享 CNN 主干 + 状态解码头 + 候选价值头 | 候选集与特权教师完全一致（18 个） |
| `touhou_rl/vision_train.py` | 两阶段训练：表征 → 策略 | 指标换算成游戏单位（px / 颗）；策略按**后悔值**选模型 |
| `touhou_rl/vision_capture.py` | 回放自走 + 抓帧 + 落盘 | 30 Hz（每 2 逻辑帧），与决策频率一致 |
| `evaluate.py --vision-checkpoint` | 视觉策略真机评估 | 该分支不调用 `state.py`，只 `session.grab()` |

单测：新增 10 条（共 49 条），覆盖框选裁剪、子弹可见性、帧序、分片往返、
历史不跨片、模型输出形状、检查点往返。

## 2. 首批实测（4,524 帧，Lunatic Stage 1，2.7 分钟）

采集：`vision_capture`，28 帧/s，9 分片 136 MB，单帧 128×112×3。

### 2.1 表征阶段（画面 → 特权观测）

| 指标 | 值 | 怎么读 |
| --- | --- | --- |
| 危险图相关系数 | **0.82** | 训练 12 epoch 内从 0.37 升到 0.82，**确实在"看见"子弹** |
| 危险格子命中率 | 0.90 | 0.2 阈值下"有弹/无弹"判断 |
| 子弹数误差 | 39 颗 | 相对满场数百颗，量级可接受 |
| 射线最小间距误差 | 0.23 | 归一化尺度（1.0 = 320 px） |
| **自机位置误差** | **48 px** | 384×448 场地内约 12%，**不可用** |

位置误差大的原因很明确：主干末端用了 `AdaptiveAvgPool2d(4,4)`，空间精度被抹平，
而位置回归恰恰需要精细定位。修法是把它换成**热图回归**（预测 32×28 的球员位置热图再取期望），
这是下一批的第一项。

### 2.2 策略阶段（画面 → 教师 18 路价值）

| 指标 | 视觉学生 | 特权学生（对照） |
| --- | --- | --- |
| 教师 argmax 一致率 | 0.13 | 0.59 |
| **后悔值（px 空隙）** | **3.98** | 2.34 |
| 参数量 | 843,001 | 455,831 |
| 训练数据 | 4,524 帧 | 46,034 帧 |

同时发现一个必须修的**训练侧缺陷**：按验证 loss 选模型时，loss 持续下降但 top1 与后悔值
从第 4 epoch 起持续变差——也就是"越训越自信地选错"。已改为按**后悔值**选模型
（`best_val_regret_px`），本表用的是改后结果。

### 2.3 部署（只用像素）

```
python -m touhou_rl.evaluate --vision-checkpoint .../vision-policy/best.pt \
    --episodes 1 --max-steps 700 --frameskip 2 --difficulty lunatic --vision-depth 3
```

| 项 | 值 |
| --- | --- |
| 报告里的 `policy` 字段 | `vision` |
| 存活帧数 | **1,239** |
| 死亡 | 3 |
| 决策速率 | 28.4 决策/s（含每步抓帧 0.7 ms + CNN 推理） |
| 输入 | **只有 128×112×3×3 帧张量** |

也就是说：**部署链路已经做到"只看画面"**，且推理开销没有拖慢决策速率
（特权模型约 29–30 决策/s，视觉模型 28.4，差距在抓帧与 CNN 前向）。

1,239 帧低于随机策略的 2,418 帧——这与后悔值 3.98 px 一致：它会动，但不会躲。
这是**数据量与精度**的问题，不是通路问题。

## 3. 为什么这一版不值得当成"结果"

必须写清楚，避免下一轮在错误的前提上推进：

1. **数据只有 2.7 分钟**（4,524 帧），而视觉表征通常需要 10^5 帧量级才稳定。
   作为对照：特权学生用了 46,034 帧才学到"安全区 93% 命中"。
2. **自机位置 48 px 误差**意味着它连"我在哪"都不确定，躲避无从谈起。
3. **没有 DAgger**：视觉数据全部来自人类轨迹，学生自己走到的状态（也就是它会死的状态）
   没有任何标签——这正是 v1.0.2 特权侧踩过的同一个坑。
4. **标签本身缺项**：激光与敌人在 `state.py` 里能读，却没进观测，视觉学生自然也学不到；
   而激光是中后期的头号死因。

## 4. 下一批的优先级（按性价比）

| 优先级 | 动作 | 为什么 | 预算 |
| --- | --- | --- | --- |
| 1 | 自机位置改**热图回归** | 48 px → 目标 < 10 px；一行结构改动，收益最大 | 半天 |
| 2 | **批量采集到 10 万帧**（约 1 小时回放 = 4 个 Lunatic 面） | 表征与策略都缺数据；采集是纯离线、可无人值守 | 1 小时机时 |
| 3 | **视觉 DAgger**：教师带扰动行动，录"学生也会走到"的状态 | 直接补上 §3 第 3 条 | 2 小时机时 |
| 4 | 激光/敌人进特权标签 → 重训教师 → 重标视觉标签 | 提高学生上限；属于标签工程 | 1–2 天 |
| 5 | 跨作品输入层（自动框选 + 分辨率自适应） | 基模前提，与 1–4 解耦 | 1–2 天 |
