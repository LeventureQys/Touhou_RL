# 开发文档总览与并行计划 · v1.0.2

- 所属阶段：Stage 3（开发）
- 唯一真源：`../框架接口契约.md`（下称「契约」）。任务书与契约冲突时以契约为准，并立即报告 MainAgent。
- 目标读者：**没有任何对话历史的 SubAgent**。每份任务书自带背景、前置、契约引用、验收标准、禁止事项。

---

## 1. Stage 3 目标

把 `问题清单.md` 的自决结论（D-01 ~ D-10）落成可运行、可测试、可复现的代码：

1. 运行时可读 TH08 状态与子弹池、可抓帧、可注入按键（只读、单实例）；
2. 能把人类 Lunatic 录像变成 (观测, 动作) 数据集；
3. 能训练 BC 策略、能评估、能一条命令让模型自己开打；
4. 有 PPO 在线微调闭环（KL 锚定 BC）；
5. 单元测试 + 启动测试 + 一键验证。

## 3. 并行批次

- **批次 1（可同时开 3 个 SubAgent）**：S3-1、S3-2、S3-4。三者只通过契约 §2/§3/§4 交互，不需要读彼此代码。
- **批次 2（依赖批次 1）**：S3-3（需要 `obs.encode`）、S3-5（需要 `env` 与 `models`）。
- **批次 3**：S3-6（全部模块到位后补测）。

> 实际执行记录：本版由 MainAgent 串行实现全部 SubStage（模块之间强耦合于内存偏移的实测结果，反复交给 SubAgent 会重复踩坑）。任务书仍按「零上下文可执行」标准写，用于复现与后续版本。

## 4. 跨 SubStage 契约（禁止自行改动）

| 契约项 | 冻结值 | 出处 |
| --- | --- | --- |
| 观测键与形状 | `self_feat[24]`、`bullets[64,6]`、`danger[16,8]` | 契约 §3 |
| 动作空间 | `MultiDiscrete([9,2,2,2])`，扁平 `move*8+shoot*4+focus*2+bomb` | 契约 §4 |
| 奖励分量顺序 | `survive, progress, score, graze, resource, event` | 契约 §5 |
| 数据集键 | `self_feat/bullets/danger/action/meta` | 契约 §7 |
| 检查点字段 | `state_dict/config/obs/extra` | 契约 §8 |
| 专家动作来源 | `g_GuiMessageInputCurrent`（`0x0161C674`），**不是** `g_CurFrameInput` | 契约 §2.1、问题清单 F-12 |

## 5. 全局禁止事项

1. 不得写游戏内存、不得注入 DLL、不得修改 `third_party/th08` 任何文件；
2. 不得用 `pyautogui`/`mss`/`keyboard` 等会改变 DPI 或全局输入状态的库；
3. 不得在日志/代码/提交信息里使用 emoji；
4. 不得把「编译通过」当作「完成」：每个 SubStage 必须给出可执行的测试命令与输出；
5. 不得为了通过测试而放宽契约（例如把观测维度改小、把终止条件改成永远 False）。
