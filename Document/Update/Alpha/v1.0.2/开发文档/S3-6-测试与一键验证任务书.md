# S3-6 测试与一键验证任务书

- 所属 Stage：Stage 3（开发）
- 依赖前置：S3-1 ~ S3-5 的模块已落地
- 并行状态：与 S3-1 ~ S3-5 同步推进（每完成一个模块就补对应用例）
- 所属阶段：开发

---

## 1. 背景与目标（零上下文）

系统规则：新功能必须有**单元测试 + 启动测试**，且实际执行通过；「编译通过」不算完成。
本任务交测试集与一键验证脚本，并给出可粘贴进报告的运行证据。

## 2. 交付物

```
touhou_rl/tests/test_core.py        # 单元测试（无游戏依赖）
tools/rl/Verify-RL.ps1              # 一键验证（单测 + 启动测试 + 仓库卫生）
```

## 3. 单元测试覆盖矩阵（最低要求）

| 模块 | 正常路径 | 边界/异常 |
| --- | --- | --- |
| `spec` | 动作双射 72、按钮位映射往返 | 越界动作抛 `ValueError` |
| `config_file` | 默认/保存/加载、位置与位标志 | 字段越界时的取值 |
| `state` | 子弹掩码过滤、`is_playing/is_run_over` | 无子弹、全无效子弹 |
| `obs` | 形状/归一化/最近排序/射线单调/危险图计数 | `bullet_field=None` 时全零且射线=1 |
| `reward` | 生存/分数/擦弹/资源/事件 | 权重非法抛错、分量裁剪、未 reset 返回 0 |
| `dataset` | 分片写入/读取/旁车/summary | 小分片、跨分片 batch |
| `models` | 前向形状、`act` 与 `evaluate_actions` 一致 | 全掩码不产生 NaN、检查点往返 |
| `bc` | 划分不重叠且覆盖 | 数据集过小抛错 |
| `env` | `EnvConfig.validate` | `frameskip=0`/未知 `reset_mode`/越界练习面 |
| `menu` | `install_replay` 覆盖旧文件 | — |
| `memory`/`winapi` | 只读自身内存、进程枚举 | 未知 PID 返回 0、未映射地址抛 `OSError` |

## 4. 启动测试（真实游戏，必须实际执行）

| 编号 | 路径 | 判定 |
| --- | --- | --- |
| L-1 | 回放采集 10 分钟 | `frames ≥ 30000`、`nonzero_action_frames/frames > 0.9` |
| L-2 | `env.reset()` + 200 步随机策略 | 无异常、帧数单调、`info` 字段齐备 |
| L-3 | `evaluate` 1 局 | `frames_reported > 0`、截图存在 |
| L-4 | `play` 1 局（≤3 分钟） | 正常收尾并写报告 |

## 5. 一键验证脚本要求

`tools/rl/Verify-RL.ps1`：

1. 解析可选的 `-SkipGame`（只跑单测 + 静态导入检查）；
2. 用仓库内的 Python 路径运行 `pytest touhou_rl/tests -q`；
3. `python -c "import touhou_rl.env, touhou_rl.models, touhou_rl.capture_dataset"` 静态导入；
4. 若未跳过游戏：跑 L-1（短版 3 分钟）+ L-2；
5. 检查 `git -C third_party/th08 status --short` 为空（不得污染子模块）；
6. 写 `third_party/th08/build/rl/verify-report.json`：每步 `ok/duration/关键输出`，全通过退出码 0。

## 6. 可观察的验收标准

1. `pytest` 全绿，用例数 ≥ 28；
2. `Verify-RL.ps1` 退出码 0，报告 8 步全 `ok=true`；
3. `git -C third_party/th08 status --short` 为空；
4. 报告里的每条命令都能被零上下文读者照抄执行。

## 7. 禁止事项

- 禁止把失败的用例改成 `skip` 或删掉断言；
- 禁止用「手动点一下游戏」代替可执行命令；
- 禁止在测试里依赖桌面焦点（除启动测试，且要自我夺回前台）；
- 禁止让验证脚本修改 `third_party/th08` 的受版本管理文件。
