## 1. 背景与目标（零上下文）

TH08 是一个 32 位 Windows 直连 3D 游戏，**每 Windows 会话只允许一个实例**（命名互斥体
`Touhou 08 App`）。本任务实现「运行时数据层」：把游戏窗口、进程内存、键盘、配置文件这四件事
封在一个稳定的 Python 层里，供上层观测/环境/采集使用。

硬约束（实测，见 `问题清单.md`）：

- 只能**读**内存：写入会触发反篡改校验并崩溃；
- 必须用 **PID + 窗口类 `BASE`** 找窗口（标题是乱码）；
- 采样进程必须先 `SetProcessDpiAwareness(2)`，否则客户区读成 512x384；
- 启动游戏要带 `__COMPAT_LAYER=HIGHDPIAWARE`，否则抓到的是插值放大图；
- 键盘只能通过 `SendInput`（扫描码）+ 前台生效；`dontUseDirectInput` + `PostMessage` 无效。

## 4. 输入 / 输出

**输入**：运行目录路径（含 `th08.exe`/`th08.dat`/`thbgm.dat`/`th08.cfg`）。

**输出**：

- `prepare_run_dir(run_dir, template_dir, windowed=True, default_difficulty=3, use_postmessage_input=False)` → 装配好的运行目录（大文件硬链接，cfg 写入 `windowed=1`、`default_difficulty=3`、`musicMode=OFF`、`disableVsync`）；
- `GameSession(SessionOptions(run_dir)).start()` → 进程已启动、已到标题、窗口已稳定、`reader`/`keyboard`/`capture` 就绪；
- `session.reader.read_state()` / `.read_bullets()` / `.read_input_mask()`；
- `session.close()` → 退出码（超时则强杀并记录）。

## 5. 可观察的验收标准

1. 在真实游戏上：`read_state()` 返回 `supervisor_state=1`、`title_screen_current=0`、`title_screen_state=1`；
2. `read_bullets()` 在 Stage 1 有子弹时 `active_mask().sum()` 与 `active_bullets` 同量级（允许 1–2 的瞬时差）；
3. `read_state(with_bullets=False)` 平均 < 0.1 ms，`read_bullets()` < 2 ms（10 次均值）；
4. 窗口客户区恰好 640x480；
5. 关闭后 `list_process_ids("th08.exe")` 为空；
6. 第二实例启动时抛 `RuntimeError`，消息含 `another th08.exe` 或启动对话框文本。

## 6. 禁止事项

- 禁止 `WriteProcessMemory` / `CreateRemoteThread` / `VirtualProtectEx` / 修改 `third_party/th08`；
- 禁止按窗口标题匹配；
- 禁止在不是前台的窗口上期待 `SendInput` 生效（要么 `force_foreground`，要么明确返回失败）；
- 禁止把读取失败吞成 0（必须抛 `OSError`）。

## 7. 出错行为

| 情况 | 期望 |
| --- | --- |
| 模块基址解析失败 | `GameStateReader.__init__` 抛 `RuntimeError("module base for th08.exe was not resolved")` |
| `ReadProcessMemory` 短读 | `OSError("ReadProcessMemory 0x... +N failed (read k/N, err=E)")` |
| 启动超时且存在 `#32770` | `RuntimeError("th08 start-up dialog: ...")` |
| 3 次启动都失败 | `RuntimeError("could not boot th08 after 3 attempts: ...")` |
| 无窗口 | `TimeoutError("no stable game window for pid N: ...")` |
