## 1. 背景与目标

### 1.1 需求（原文要点）

`v1.0.2/需求文档.md` 要求：

1. 基于 v1.0.1 的完成情况，**组织一次完整的强化学习训练**；
2. 本机可用 **RTX 4070 SUPER**（实测 `torch.cuda.is_available()==True`，F-02）；
3. 需要在不同路线中**做取舍**；
4. 最终目标：**TH08 的 Lunatic 难度，使用任意组通关**；
5. 模型不需要会选菜单，**只需要会玩**，所以「进入游戏的脚本」也要交付。

### 1.2 本版目标（可验收）

| 目标 | 交付物 | 验收编号（见验收文档） |
| --- | --- | --- |
| 补齐 v1.0.1 承诺的运行时代码 | `touhou_rl/` 包（只读状态、抓帧、注入、观测、奖励、环境） | A-01 ~ A-04 |
| 把「人类 Lunatic 录像」变成训练数据 | `touhou_rl.capture_dataset` + 数据集分片 + 采集报告 | A-05 |
| 训练出会玩的模型 | BC 训练器 + 检查点 + 训练日志 | A-06 ~ A-07 |
| 在真实游戏里证明「会玩」 | 实时评估（存活帧数/触达关卡/死亡次数）+ 截图 | A-08 ~ A-09 |
| 能直接开打的脚本（无需选菜单） | `python -m touhou_rl.play` | A-10 |

| 工程门禁 | 单元测试 + 启动测试 + 一键验证 | A-12 ~ A-14 |

### 1.3 本版**不做**什么（防范围膨胀）

- 不做像素/视觉 CNN 策略（观测契约保留 `Dict` 扩展位，v1.0.3 再加视觉通道）；
- 不做并行多实例（需要 32 位 `dinput8.dll` 代理 DLL，列入路线图）；
- 不做 HUD OCR、不做录像回放之外的复位捷径；
- 不修改 `third_party/th08` 的任何源码/二进制，不写游戏内存（D-08）；
- 不承诺「本版一定 1CC Lunatic」——本版承诺的是**完整可复现的训练组织 + 真实证据链**，1CC 是否达成按实测写进验收报告。

## 3. 路线取舍结论（详见 `训练方案与路线取舍.md`）

一句话：**从零 RL 在本机不可行，回放模仿 + KL 锚定 PPO 是唯一在单实例上能给出真实证据的路线。**

| 路线 | 数据需求 | 本机现实 | 结论 |
| --- | --- | --- | --- |
| 从零像素 RL | 1e8 帧量级 | 60 帧/s、单实例 → ≥19 天独占 | 否决 |
| 从零特权状态 RL | 1e7–1e8 帧 | 同上，仍 ≥数天 | 否决为主线 |
| 回放模仿（BC） | 24 份 Lunatic 录像（已入库） | 一份约 32 分钟采集（F-14），训练在 GPU 上分钟级 | **主线** |
| BC + PPO（KL 锚定） | 在线 10^5–10^6 决策 | 约 1–10 小时/10 万决策 | **微调线** |
| 并行实例（代理 DLL） | 提高吞吐 | 需要注入 DLL（D-03 推迟） | 下一版 |
| 让游戏跑得比 60 帧快 | 无 | 游戏主循环按墙钟节流到 60 逻辑帧/s（`main.cpp:307-376`），关 vsync 无用；提速只能 hook 时钟（需注入） | 否决 |

## 4. 总体架构

```
                 ┌──────────────────────────── 数据侧（离线，GPU） ───────────────────────────┐
  .rpy 录像 ──►  │ touhou_rl.capture_dataset: 回放播放 + 只读采样                            │
  (108 份)       │   state.read_bullets() ─► obs.encode() ─► dataset.ShardWriter(.npz)      │
                 └───────────────────────────────────┬─────────────────────────────────────────┘
                                                     │  (self_feat[24], bullets[64,6], danger[16,8], action[4])
                 ┌───────────────────────────────────▼─────────────────────────────────────────┐
                 │ touhou_rl.bc: DanmakuPolicy（集合编码器 + 四头策略 + value/reward 头）       │
                 │   → runs/bc/best.pt                                                          │
                 └───────────────────────────────────┬─────────────────────────────────────────┘
                                                     │
                 ┌───────────────────────────────────▼─────────────────────────────────────────┐
                 │ touhou_rl.ppo: 真实游戏环境 + PPO + 对 BC 的 KL 锚定（防遗忘）               │
                 │   → runs/ppo/last.pt                                                         │
                 └───────────────────────────────────┬─────────────────────────────────────────┘
                                                     │
  ┌──────────────────── 运行侧（真实游戏，60 Hz） ───▼─────────────────────────────────────────┐
  │ touhou_rl.env.Th08Env（Gymnasium）                                                         │
  │   reset(): menu.ensure_title → enter_game(difficulty=LUNATIC, team=0)                       │
  │   step(a): input.set_keys → 等 frameskip 帧 → state.read_state+read_bullets → reward        │
  └───────────┬──────────────────────────────┬──────────────────────────────┬─────────────────┘
              │ ReadProcessMemory(只读)      │ SendInput(前台)              │ GdiCapture(证据)
        ┌─────▼─────┐                  ┌─────▼─────┐                  ┌─────▼─────┐
        │ th08.exe  │                  │  键盘     │                  │ 截图/证据 │
        └───────────┘                  └───────────┘                  └───────────┘
```

分层原则（与 v1.0.1 一致）：

1. **游戏适配层可替换**：`winapi`/`memory`/`state` 之外的所有模块都不认识 TH08 的地址；
2. **观测是契约**：`obs.py` 输出固定形状，训练/推理/数据集三处共用同一编码器；
3. **训练侧只见 Gymnasium + 张量**：算法不需要知道「子弹池 6.58 MB」这类细节；
4. **只读**：`memory.ProcessMemory` 只打开 `PROCESS_VM_READ|PROCESS_QUERY_INFORMATION`。

## 5. 观测/动作/奖励设计（契约见 `框架接口契约.md`）

| 条目 | 设计 | 依据 |
| --- | --- | --- |
| 观测 | `self_feat[24]` + `bullets[64,6]` + `danger[16,8]` | F-08 读成本；PIFE 的对象级编码思想；D-02 |
| 动作 | `MultiDiscrete([9,2,2,2])` = 方向/射击/低速/炸弹（爆炸沿触发） | 东方操作是「8 向 + 3 键」；扁平等价 72 双射有单测 |
| 控制频率 | `frameskip=2`（≈20–30 决策/s） | F-09 的实测上限 |
| 奖励 | 6 分量向量 + 加权标量（生存/进度/分数/擦弹/资源/事件） | v1.0.1 设计；保留多目标接口 |
| 网络 | 逐子弹 MLP + 掩码池化 + 自机 MLP + 危险图 MLP → 共享 trunk → 四头 + value + 6 维 reward 头 | 排列不变、样本效率高、CPU 推理 <1 ms |
| 标签 | 回放逐帧的 `g_GuiMessageInputCurrent` | F-12（关键：不是 `g_CurFrameInput`） |

| Stage | 内容 | SubStage | 依赖前置 | 并行状态 |
| --- | --- | --- | --- | --- |
| S1 提问 | 事实基线与取舍 | — | 无 | 已完成（`问题清单.md`） |
| S2 设计 | 设计/契约/任务书/验收文档 | — | S1 | 本文件 + `框架接口契约.md` + `验收文档.md` |

| S3-3 | 数据采集 | `touhou_rl/{dataset,capture_dataset}.py` | S3-1、S3-2 | 需等 S3-2 的 `obs.encode` |
| S3-4 | 模型与 BC | `touhou_rl/{models,bc}.py` | 契约 §3/§4 | **可并行**（只需契约，无需游戏） |

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| BC 协变量偏移（离开人类轨迹就崩） | 真实存活帧数远低于验证集准确率暗示 | PPO + KL 锚定；评估只看真实游戏；报告中同时给「像人程度」与「存活帧数」 |
| 单实例吞吐低（~30 决策/s） | PPO 一小时仅 10 万决策 | 主要算力放在离线 BC；PPO 只做小步微调 |
| 前台依赖（失焦 14 帧/秒） | 采集/训练变慢甚至行为异常 | 采集器 2 s 前台守卫；`env._focus_guard` 每 15 步校验 |
| 命名互斥体（单实例） | 双开卡死 | 会话层启动前等待旧进程退出，3 次重试，检测 `log` 对话框并报出文本 |
| 标题屏结构体偏移易错 | 菜单状态判断错误 | 偏移全部实测（F-10），并用 `screen 0→4→5` 轨迹回归 |
| 1CC 未达成 | 需求最终目标未满足 | 验收报告如实判定；总结报告给出下一版预算与改进项 |
