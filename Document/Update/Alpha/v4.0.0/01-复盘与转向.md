# 01 复盘与转向：为什么 v4.0.0 要换路

- 读者：执行 v4.0.0 的 Agent，以及项目负责人。
- 用途：说明 v4.0.0 **为什么**这样设计。执行时以 [04-阶段计划](<04-阶段计划.md>) 与各阶段规格为准；本文只回答"为什么不沿用 v3.9.0 的计划"。
- 所有数字都给了出处。若你质疑某条，先打开出处。

## 1. v3.9.0 做了什么，哪些成立

v3.9.0 只完成了 Stage A（E0 合同冻结 + E1 环境正确性与经济性），经四轮独立验收后通过（[stage-a-acceptance-r4](<../v3.9.0/reports/stage-a-acceptance-r4.md>)）。下面这些事实继续成立，v4.0.0 直接沿用：

| 事实 | 数值 | 出处 |
|---|---|---|
| 栅栏环境正确性六项 | 步进语义、终止三分、重开一致、30 分钟稳定全部通过 | [stage-a-closeout §3.1](<../v3.9.0/reports/stage-a-closeout.md>) |
| 动作延迟 | 掩码 +1 帧、位移 +1 帧（不是旧假设的 1+1=2） | 同上 §3.2 |
| 吞吐 | 21.19 决策/s；单次重开约 11.8 s | 同上 §3.4 |
| **时间花在哪** | **采集侧 92.7%**，推理 7.3%，更新 0.00%（两次 30 分钟 run 结果一致） | 同上 §3.4 |
| 练习关初值 | lives=8、bombs=3、power=0 | 同上 §3.2 |
| 旧演示数据 | 可用于初始化，不可作为评估 | 同上 §5 |

最关键的是 **92.7%**：瓶颈在训练场，不在算法。

**没有做的事**：Stage A 共 30 行账本（12 行 `failed`），用掉 142,826 个决策和 9,401 s 墙钟，**全部用于测量环境本身，没有一次学习实验**。v3.9.0 目录下的 markdown 约 59 万字节，v390 相关代码约 9.1 千行。

## 2. 三条必须撤回的结论

这三条结论已经写进 v3.9.0 的后续计划和跨作品协议，并且在压缩后续路线。它们都不成立。**v4.0.0 的任何文档与代码不得再以它们为前提。**

### 2.1 "TH08 第 0 面不可复现，路线 B 出局"（[问题清单-Stage-B Q-B01](<../v3.9.0/问题清单-Stage-B.md>)）

- 探针 `.tmp_qb01_determinism.py` 两次都从菜单冷启动，**没有固定 RNG 种子**。
- TH08 的 `g_Rng` 是 16 位种子。回放路径在进关时用 `g_Rng.SetSeed(stageData->rngSeed)` 固定它（[ReplayManager.cpp:601](<../../../../third_party/th08/src/ReplayManager.cpp>)）。
- 子模块的 Linux x86_64 / i386 构建**逐位复现了 108/108 份回放、12,311,460 次计算、25 个字段（含浮点位）**（[REPLAY_RESULTS.md](<../../../../third_party/th08/docs/REPLAY_RESULTS.md>)）。

**正确表述**：不固定种子时，两次冷启动的结果不同；**固定种子并给定输入序列后，引擎完全确定**。子模块已经验证过这一点。

### 2.2 "纯像素奖励不可行"（[r1](<../v3.9.0/reports/r1-pixel-reward.md>)、[l1](<../v3.9.0/reports/l1-pixel-learnability.md>)、`l1b-hires-learnability.json`、[跨作品协议 §9](<../v3.9.0/跨作品评测协议.md>)）

这个实验有四个缺陷，每一个都足以让它失效：

1. 输入用 `spec.PLAYFIELD`（x=32, y=16, 384×448）裁剪，**右侧 HUD 被切掉了**。残机、bomb、分数正好显示在 HUD 上，所以从这个输入预测 `lives` 本来就做不到。
2. 数据只有 1 局，l1b 的 10 个块里有 8 个块标签是常数。
3. l1b block 0 的 `active_bullets` MAE 是 **10,029 颗**，而真实范围只有 0–108，说明计算本身已经出错。
4. 模型是 32×28 亮度图上的线性岭回归，比合理的检测器弱几个数量级。

**正确表述**：实验无效，不构成负结果。像素奖励问题**还没有被正确测试过**。v4.0.0 的 P2 会正式测试它。

### 2.3 "50 万决策下，完整一面与确认成绩不能兼得"（[问题清单 Q-01](<../v3.9.0/问题清单.md>)）

这是"21 决策/s、每局重启 12 s"这个训练场的算术，不是任务本身的算术。换掉训练场后，这个约束就不存在了。

## 3. 为什么"做了很多训练仍然没有效果"

### 3.1 样本量差了 3–4 个数量级

| 实验 | 样本量 | 结果 |
|---|---|---|
| v3.8.0 BC 热身（**迄今唯一成立的控制能力**） | 3,282 个人类标签 | 每 1,500 决策（≈50 s 游戏时间）死 2.95 次，随机策略是 4.40 次 |
| v3.8.0 PPO 从零训练 | ≤ 1 万决策 | 与随机无差异（p=0.65） |
| v3.8.0 PPO 从热身接管 | 同一量级 | 中性，或者破坏先验 |
| v3.9.0 计划的 E3 四臂 × 3 seed | 总共 20 万决策，每臂每 seed 约 1.7 万 | 未执行 |

像素输入的端到端深度 RL，常见样本量级是 10⁷–10⁸ 帧（Nature DQN 每个 Atari 游戏训练 5,000 万帧）。本项目最大的一次 RL 实验约 2 万帧。**在这个量级上，RL 失败的结果不带信息量。**

出处：[v3.8.0 W6 总结](<../v3.8.0/W6总结.md>)。

### 3.2 训练场选错了

训练场是实时的 Windows 窗口：每帧跨进程握手，用 GDI 抓图，每局要重启进程。92.7% 的时间都花在搬运帧上。底座不换，吞吐的天花板就不会变。

### 3.3 从来没有一个会玩的教师

历史上的教师有两类：

- **近似动力学**：圆形碰撞近似、线性外推。v3.7.0 拿它上真机，结果比基线还差（1.333 vs 1.033 死/局）。
- **少量人类标签**：3,282 个。

"离线指标好、闭环崩溃"反复出现：v1.0.4 离线后悔值 1.27 px，闭环只活 1,627.7 帧（门槛 4,000）；v3.7.3 离线 0.92，闭环 14–29%。这是**协变量偏移**的典型表现：学生一旦犯错，就会进入教师数据里从没出现过的状态，然后越错越多。

标准解法是 DAgger：让学生自己玩，在学生实际到达的状态上请教师标注。**DAgger 需要一个能在任意状态上被查询的教师，因此需要快照。** 而快照被禁掉了。

### 3.4 自我设限把唯一的通路堵住了

下面这几条，单独看每一条都有理由，但合在一起，正好排除了唯一可行的路线：

- 不做 savestate（[v3.9.0 需求 §10](<../v3.9.0/需求文档.md>)）
- 不做无头运行
- 裁剪时去掉 HUD
- 预算按"决策数"计算

### 3.5 治理开销挤占了实验

严谨本身没有错，错在用的地方：用 30 项验收和四轮复核，去确认一个注定太慢的环境。

## 4. 转向：v4.0.0 改了什么

| 维度 | v3.x | v4.0.0 |
|---|---|---|
| 训练场 | 实时 Windows 窗口 + 栅栏握手 + GDI 抓图 + 进程重启 | 真实引擎源码的研究构建：不限帧、按种子直接进关、进程内取帧、`fork` 快照、多实例 |
| 样本量级 | 10³–10⁴ | 10⁷–10⁸ 帧 |
| 教师 | 近似动力学，或少量人类标签 | 用真实引擎做前瞻搜索（精确未来） |
| 学生训练 | 离线 BC | BC → DAgger → 专家迭代 → 像素回报 RL |
| 人类录像 | 主要训练数据 | 中途起点来源、评估参照、可选热身 |
| 框选 | 只取 playfield | 完整客户区，含 HUD |
| 回报 | 内存读数 | 训练期两路并行（内存真值 / 像素检测），像素路径必须达标 |
| 数据存储 | 存帧（每帧约 445 KB PNG） | 存回放（种子 + 输入序列）；像素只作为可删除的缓存 |
| 预算口径 | 决策数 | GPU 时 + 墙钟 + 磁盘 |
| 文档 | 需求、设计、验收三件套，多轮验收 | 每阶段一份规格 + 每个实验一张卡片 + 门报告 |

**部署约束保持不变**：最终模型只接收画面和按键，不读内存，不注入，不写进程内存。
