# 20 基准与评测：TH08-Bench

- 读者：执行 Agent。
- 用途：定义 v4.0.0 里"变强了没有"的**唯一**衡量方式。所有门判据都引用本文的套件和统计口径。
- 实现位置：`touhou_rl/v400/bench/`；入口 `tools/rl/v400_bench.py`。实现时间：P0-WP7（框架）、P1-WP1（第一次正式使用）。

---

## 1. 原则

1. **统计单位是独立 episode**，由 `(套件, 种子)` 唯一确定。训练场是确定的，所以确定性策略在同一个种子上的结果完全可以复现。
2. **开发种子与确认种子严格分开。**
   - 开发种子：日常调参与诊断使用。
   - 确认种子：只在门评估时使用，且每个 checkpoint 只评一次。
3. **学生在零特权模式下评测。** 策略只能拿到像素（以及它自己的动作历史）。死亡、分数等成绩由独立的裁判代码读取引擎状态得到，裁判的输出不回传给策略。
4. **每个 checkpoint 评测时，同时跑参照点**（或者引用同一版本训练场下已有的参照成绩）。

---

## 2. 种子

TH08 的 RNG 种子是 16 位的，共 65,536 个取值。划分如下：

| 用途 | 种子范围 | 规则 |
|---|---|---|
| 训练 | 任意 | 训练可以使用任何种子，但凡是用于训练过的种子，都要记录在训练配置里 |
| 开发评测 | 0–49,999 中，固定取 `dev = [1000, 1001, …, 1099]`（100 个） | 日常使用 |
| 确认评测 | `confirm = [60000, 60001, …, 60199]`（200 个） | 只在门评估时使用。**训练绝不能用这个区间内的种子**，训练入口必须做断言检查 |

---

## 3. 套件

| 套件 | 内容 | 起点 | 结束条件 | 主指标 |
|---|---|---|---|---|
| `S1N` | Stage 1 Normal | 训练场 `reset(stage=1, difficulty=normal, team=0, start=standard)` | 过关 / game over / 帧数达到上限 | 过关率；每局死亡数 |
| `PSN` | 逐面 Normal（1、2、3、4A、4B、5、6A、6B） | 每一面都从练习式起点开始，残机足够多，确保不会 game over | 这一面结束或达到帧数上限 | 每面死亡数（会累计死亡，但不会因死亡提前结束） |
| `RUNN` | 一周目 Normal | 从 Stage 1 开始，标准资源，不允许续关 | 打到 Final 结束 / game over | 打到第几面；不续关通关率；分数 |
| `S1L`、`PSL` | 与 `S1N`、`PSN` 相同，难度换成 Lunatic | 同上 | 同上 | 同上 |
| `HO-*` | P5 的留出设置（其他机体、留出关卡），具体在 P5 定义 | — | — | — |
| `REAL-S1N` | 真实 Windows 游戏上的 Stage 1 Normal | 通过 v380 的无栅栏实时路径 | 同 `S1N` | 过关率、死亡数，与 harness 中 `S1N` 的成绩对比 |

**细节**

- "标准资源"和"练习式起点"的具体值，由 P0-WP3 从引擎源码中确认后写进 `touhou_rl/v400/bench/suites.py`，并在本文的修订记录里注明。
- 每面的帧数上限 = 该面人类参考长度 × 1.5。人类参考长度由 P0-WP6 从回放语料中测量。
- 动作接口与决策周期以 checkpoint 自带的配置为准，评测器不得替它修改。

**样本量**

| 场景 | 每套件局数 |
|---|---|
| 日常开发 | `dev` 种子取 20 个 |
| 门评估 | `confirm` 种子取 100 个（`REAL-S1N` 取 20 局，因为实时运行很慢） |

## 4. 参照点

| 参照 | 说明 | 何时可用 |
|---|---|---|
| `random` | 18 个"方向 × 聚焦"动作均匀随机，开火常开，决策周期 2 帧 | P0 |
| `still` | 不移动，开火常开 | P0 |
| `teacher-v*` | P1 / P4 的搜索教师（特权，只作为上限参照） | P1 起 |
| `student-v*` | P3 / P4 的像素学生 | P3 起 |
| `human` | 回放语料中人类专家的逐面死亡数与分数。种子和我们的不同，所以只作为参照线，不做配对比较 | P0-WP6 |
| `warmstart-v2` | v3.8.0 的 BC checkpoint。需要一个观测适配器，**可选**；做不了就在卡片里写明原因 | P3（可选） |

## 5. 统计

- **过关率**：点估计 + bootstrap 95% 区间（重采样 10,000 次，以 episode 为单位）。
- **死亡数、分数**：均值 + bootstrap 95% 区间。
- **两个 checkpoint 比较**：
  - 用同一组种子，按种子配对计算差值，报告配对 bootstrap 区间和配对置换检验的 p 值。两个都要报。
  - "显著提升"的定义是：**区间下界 > 0**，且点估计 ≥ 门规格里写的最小幅度。
- 实现放在 `touhou_rl/v400/bench/stats.py`，可以复用 `touhou_rl/v390` 中已有的统计工具。

## 6. 记录格式

结果文件 `Document/Update/Alpha/v4.0.0/bench/results.jsonl` 只追加，每局一行：

```json
{"ckpt":"sha256:…","agent":"student-v1","suite":"S1N","seed":60017,
 "harness_commit":"…","privilege":"deploy_pixel","frames":17020,
 "stages":[{"stage":1,"deaths":0,"bombs":1,"cleared":true,"frames":17020}],
 "deaths":0,"bombs_used":1,"lives_end":3,"score":12345670,"cleared":true,
 "end":"stage_clear","wall_s":9.8}
```

`tools/rl/v400_bench.py --summarize` 根据它生成 `bench/scoreboard.md`。表格的行是 agent，列是套件，单元格写"主指标点估计 [区间]"。

## 7. 零特权的强制方式

- 策略对象只接收 `PixelObs`，它只包含 `pixels` 和 `prev_actions` 两个字段。在类型层面就不提供任何其他字段。
- 写一个单元测试：遍历 bench 路径中传给策略的对象，断言其中不包含任何特权字段。
- 裁判模块（`bench/judge.py`）在一个独立的函数里读取引擎状态，它的结果只写入日志。
