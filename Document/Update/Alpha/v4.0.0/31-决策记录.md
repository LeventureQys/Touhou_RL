3. **2026-11-07 P0-WP1 回放基线的参考轨迹来源（待负责人确认，默认取方案 B）。**
   - `10-P0` WP1 的首选方案是"直接用 `config/replay-fixtures.json` 里每个用例的 `retailTrace.sha256` 指纹比对"。实测**这条路走不通**：`src/modern/linux/replay_trace.cpp` 的 `Initialize()` 在 `TH08_REPLAY_TRACE_REFERENCE` 缺失时直接返回、记录器完全不启用；即使给了文件，也是每写一行就 `fread` 参考行并 `memcmp`，不一致立刻 `Finish("Replay diverged")`。空参考文件只会产出 1 行。记录器无法自举。
   - 官方 suite 的做法是为每个用例用 `scripts/capture-replay.py` + Wine32 + ptrace 观测器跑零售版生成参考轨迹（108 例，每例都是一次完整播放），本机没有现成参考套件，成本高。
   - 三个可选方案：
     - **A（官方正路）**：装 Wine32 + xdotool，逐例生成零售参考，再跑 `test-portable-replay-suite.py`。最忠实，但 108 例耗时长，需要分多轮完成。
     - **B（默认，先做）**：先只对少量用例（如 `easy-0-b`、`normal-3-b`）执行 A，把方法跑通并形成可复现的实验卡片；完整 108 例留到 G0 门报告之前补完。
     - **C（退路，需改代码）**：按 `10-P0` 的"退路"用原样构建做差分参考，这需要给记录器加一个"无参考时纯录行"的开关，属于对研究构建的改动，且削弱了"与零售逐位一致"的证明力。
   - 建议：先做 B，若耗时可控再扩到 A。C 只在 A/B 都不可行时采用，并要在门报告里明确说明证明力的下降。
