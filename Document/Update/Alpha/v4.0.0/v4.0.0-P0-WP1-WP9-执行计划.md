### 19.1 G0.1：判据修正后首份真实零售位一致

manifest 的 `retailTrace.sha256` **不是** `rows.jsonl` 的文件哈希，而是官方
`third_party/th08/scripts/compare-replay-traces.py:12-19` 的 `trace_sha256()`：
**紧凑排序 schema JSON + 每行 25 个 `<I` 小端 uint32**（注释：`independent of JSON spacing`）。
用该官方函数（importlib 载入，不重写算法）对 `.tmp_v400_trace_full_1/rows.jsonl` 复算：

| 项 | 值 |
|---|---|
| 行数 / 字节 | **99,113** / 18,043,248 B（= manifest `calculationFrames`） |
| 官方规范哈希 | `81f535e3e01743255fe1edbe71740f0b27050702ce4d28848ce934d38be1643c` |
| manifest `retailTrace.sha256` | 同上 → **精确相等** |
| `rows.jsonl` 文件 SHA-256 | `ed07eeb7…19b0c4`（与 manifest **本不应相等**） |

生产方式：**Windows 原生 Debug API**（`DebugActiveProcess` + DR0–DR3 硬件断点 + `ReadProcessMemory`）
驱动**零售原件** `th08.exe`（840,704 B，SHA `330fbdbf…d924`）自然播完 `th8_ud2cd2.rpy`；
`deleteReplay` 断点命中 1 次（1192.265 s）→ `ended=true` / `naturalReplayExit=true` / `errors=[]`。
交叉校验：`stageFrames` 6/6 = `inputRecords − tail`（`2,2,2,2,2,6`），`endScores` 6/6 精确相等
（`2447070 / 10352151 / 23602972 / 42644410 / 59772037 / 90941860`），stage 序列 `[0,1,2,4,5,6]` 一致。
反例（判据非恒真）：前 99,112 行 → `ae13b8e0…6908`；旧 17,843 行 → `b9866512…7d67`。

**判定：G0.1 = 真实零售位一致 1/108。** 「0/108」与「文件 SHA 不等」为历史表述。

**限制**：零售件单实例/单窗口/SendInput 焦点、**不可并行**；单份 ≈1200 s（≈106 行/s）；
12,311,460 帧串行预计 **≈32–36 h**；剩余 107 份由串行批跑推进（EXP-P0-072，**卡片与结果尚未落盘**），
故本计划**不据此推断任何比例**；批量结果未出前**不得写 108/108**。
