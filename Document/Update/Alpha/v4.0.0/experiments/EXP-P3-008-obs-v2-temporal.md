## 0. 结论先说

1. **obs-v2 契约与数据都成立**：只加不改（obs-v1 逐字节未动）、27 片 / 76,912 决策、
   v1 平面 sha256 27/27 重算匹配、history 重建逐字节相等。摘要 `95110743…`。
2. **预注册判据 FAIL**：M2 **1,343.8** 帧、M3 **746.0** 帧，都远低于 2,116；
   macroR 腿两条都过（0.2986 / 0.2661），但主判据是 AND。
3. **"时序输入"方向是反的**：两条 obs-v2 臂的**离线**指标大幅领先（top-1 +8.4 / +6.2 pp，
   macroR +0.11 / +0.08），**闭环**却更差或持平——首死帧没有推后，M3 直接退化成单一动作。
4. **原因可定位**：8 决策动作历史在离线时是**教师行为通道**（把历史清零，M2 top-1
   0.6785→0.4975、M3 0.6561→0.3541；把历史打乱更差）。部署时历史是学生自己的动作，
   通道变成自激反馈——M3 的 373 个决策全部输出 `cand=3`，5 个种子全部 746 帧。
5. **本卡最大的副产物是尺子的问题**：同一个 checkpoint 重跑 5 局**逐帧完全一致**
   （2,243/2,999/2,299/3,355/2,976；F 臂 1,816.0 也逐局复现），但**同一配置、同一初始化与
   数据顺序、仅训练时长不同（+73 % step）、离线 val top-1 只差 0.0004 的两个 checkpoint
   （M1 与 M1b）闭环差 1,330 帧（5/5 同向）**。这条方差比本项目过去追逐的 300–550 帧
   "杠杆"更大。
6. **下一步**：先修尺子（同 checkpoint 重跑零分布 + ≥10 局/臂），再把历史改成部署一致
   （self-history / dropout），最后用**已经存在的** `player_x/player_y`（STATE f10/f11）
   做 obs-v3 诊断臂，回答"位置信息是不是缺的那块"。

## 1. 假设与**预注册**判据

**假设 H（本卡要杀的那一个）**：P3 学生到不了 G3 不是标签不够细，而是**输入里没有"我刚被逼到角落"这类时序状态**——
obs-v1 只有 `play64` 4 帧堆叠（= 8 逻辑帧）+ 当前 HUD，**没有动作历史、没有速度、没有自机位置**，
一个 204k 的前馈 MLP 无法从 8 帧里区分"我正在往角落走"和"我刚从角落出来"。

**预注册（跑之前写死，不按结果改）**：

| 项 | 冻结值 |
|---|---|
| 主判据 | **M2 或 M3** 的 S1N 5 局均值 **≥ 1,816.0 + 300 = 2,116 帧**，**且** 离线 `test` macro recall **≥ 0.20** |
| 副判据 | 是否 **≥ 教师 30 % = 4,070 帧** |
| 尺 | `--obs-window consecutive`、seeds **1000–1004**、`--stage 0`、`--max-frames 19887`、`--stop-on-death`、1 引擎 |
| 三臂同条件 | 同语料（D0 53,512 + DAgger R1 23,400 = 76,912）、同 split（`seed 0`，整片 70/15/15）、同 `τ = 2.0`、同 690 s 优化预算 |
| "方向正确"的事前定义（主判据不过时使用） | ① 首死帧（`--stop-on-death` 下 `frames` 即首死帧）**均值推后**；② 动作分布**更分散**（动作 0 占比下降、focus 类覆盖上升）；③ 离线 top-1 / macroR 提高 |
| 否证条件 | 三臂差异 < se，或 M2/M3 均不优于 M1 → **"输入信息不足"假设不成立**（至少"动作历史"这一项不是瓶颈），不得改判据 |

**为什么阈值是 1,816 + 300**：EXP-P3-004/005 里唯一反复有效的杠杆是数据量（+417~552 帧），
`verify_k` / `margin_cap` / 几何分辨率 / 动作集扩展全部无效或有害；300 帧是"接近数据量级杠杆"的下界，
低于它就不能说时序输入改了什么。

## 7. 判据判定与"方向是否正确"

### 7.1 预注册判据：**FAIL**

- 帧数腿：M2 1,343.8 ✗、M3 746.0 ✗（离 2,116 差 772 / 1,370 帧）
- macroR 腿：M2 0.2986 ✓、M3 0.2661 ✓（都 ≥0.20）
- 主判据是 **AND** → **FAIL**；教师 30 %（4,070）两条都没过（33.0 % / 18.3 %）。
- **必须同时写明的边界**：**M1 自己（2,774.4）就越过了 2,116**。这条绝对门在"重训基线"
  出现后已失去判别力；真正的问题是"相对基线有没有变强"，而 M1b 又把基线的读数区间拉到了
  1,444–2,774（§7.3）。

### 7.2 机制：obs-v2 的离线增益是**教师行为通道**，不是"被逼到角落"的知觉

对 val（12,294 决策）做 history 通道消融（推理期改写输入，**不重训**）：

| 臂 | stored（真实历史） | zeros（全零） | shuffled（打乱到别的决策） |
|---|---|---|---|
| M2 top-1 | **0.6785** | 0.4975（−0.181） | 0.4166（−0.262） |
| M2 macroR | 0.2904 | 0.1234 | 0.0973 |
| M3 top-1 | 0.6561 | 0.3541（−0.302） | 0.2969（−0.359） |
| M3 macroR | 0.2655 | 0.0865 | 0.0628 |

- 训练集里的历史行是**教师/环境实际执行的动作**（D0 = `chosen_plan.first_action`，
  DAgger = `dagger.executed_cand`）。它离线极强，因为它泄漏"教师正在做什么"；
  打乱后比清零更差，说明模型学的是"跟随历史的动作"，而不是从历史推断运动。
- **部署时历史是学生自己的动作**，通道立刻从"读教师"变成"读自己"：M3 因此自激成常量动作。
- 部署一致性探针（`deploy_parity`，真实分片 16–24 决策）：
  - M2：**live == batched 24/24**，且 live 历史行与训练存储行 24/24 相同 → eval 路径无误；
  - M3：live ≠ batched（仅 2/16 相同），live 历史行只有 1/16 与训练行相同 → 分歧来自
    **模型自己产生的历史**，不是采样/缓存 bug（缓存逐步前向 == 整窗前向有单测）。

### 7.3 方向是否正确：**否**（三条事先定义的判据逐条落空）

1. **首死帧没有推后，反而提前**：M1 2,774 → M2 1,344（−51.6 %）→ M3 746（−73.1 %）；
   对预算对齐的 M1b（1,444）M2 也只是持平（−100.4，1/5 同向）。
2. **动作分布没有更分散**：M2 的动作 0 占比 0.516 > M1 0.469 / M1b 0.460；focus 类覆盖
   2 vs 1（唯一为正的一项，且幅度很小）；M3 直接退化到单动作。
3. **离线↔闭环再次反向**：M2 的离线 macroR 比 M1 高 0.112，闭环却低 100–1,431 帧。
   这与 EXP-P3-005 §7.3 的"macroR 与 top-1 反向"是同一类现象，只是这次方向更糟。

### 7.4 副产品（比主结果更重要）：**S1N 的 checkpoint 级方差 > 本项目所有"杠杆"**

- **尺子本身是确定性的**：同一个 M1 checkpoint 重跑 5 局 → `2,243 / 2,999 / 2,299 / 3,355 / 2,976`，
  与第一次**逐帧完全一致**（`eval/m1_repeat`）；F 臂 checkpoint 复现 `1,816.0` 也逐局一致
  （`eval/f_arm`）。所以 1,330 帧的差不是评测噪声。
- **同一配置的两个 checkpoint 就能差 1,330 帧**：M1 与 M1b 共用 init / 数据顺序 / split / τ
  （M1b = M1 多训 73 % 的 step），val top-1 0.5946 vs 0.5950（Δ0.0004；test 0.5810 vs 0.5863，
  Δ0.0053），闭环 2,774.4 vs 1,444.2（**5/5 同向**）。也就是说"在哪个 step 停下"这一个自由度
  就足以搬动 1,330 帧。
- 推论：过去以 5 局均值比较的 ±300~550 帧效应（数据量、`geo_restore`）**落在同一个
  checkpoint 级方差带内**；EXP-P3-004 的 t=24.9 需要一个"同 checkpoint 重跑"的零分布
  才能解释。任何新臂的读数据此必须在**≥10 局**或**多 checkpoint 平均**上取。

## 8. 下一步最小改动（按证据强度排序）

| 优先级 | 改动 | 为什么是这一条 | 成本 |
|---|---|---|---|
| **P0** | **先修尺子**：把 S1N 每臂局数从 5 提到 ≥10，并用"同 checkpoint 重跑"的零分布校准判据；或一臂取 2–3 个 checkpoint 的均值 | §7.4：同配置两次训练差 1,330 帧，±300 帧判据目前无法分辨任何东西 | 纯评测时间，无代码风险 |

**关于 P2 的边界（必须写明）**：`px/py` 来自引擎 STATE，是**特权输入**；用它的臂
`privilege` 会从 `deploy_pixel` 变成 `deploy_state`，只能当**诊断**，不能当可部署策略。
若它显著抬升闭环，结论是"位置信息是瓶颈"，下一步是**在 P2 里做位置估计**（自机定位），
不是把特权状态直接接进部署策略。

## 10. 已知限制

1. **obs-v2 只加了动作历史**。它能让学生知道"我刚才在往哪走"，但**不能**知道自机在场上的
   绝对位置；若"被逼到角落"的本质是位置无知，本卡的臂**看不全**那个假设（见 §8 P2）。
2. **没有 lives/bombs 数值**：危险摘要留空（部署侧只有像素、仓库无 HUD OCR）。
3. **n = 5 局不足以支撑 ±300 帧判据**：§7.4 实测同配置两次训练差 1,330 帧。本卡的判据因此
   只能给出"没有正效应"的结论，不能给出精确的效应量。
4. **三臂的 `labels seen` 不同**（M1 5.34 M / M1b 9.23 M / M2 8.66 M / M3 7.41 M）：
   预算是墙钟 690 s，机器上同时有零售 trace 批跑与 WSL 引擎任务，吞吐在 3.6k–13.3k labels/s
   之间波动。因此额外训了 **M1b**（预算对齐的 obs-v1）作为公平对照；M2 vs M1b 仍无可区分。
5. **M1 不是 F 臂 checkpoint**：F 臂（1,816.0）是另一份数据（27 片含 v2i 标签、420 s）的结果，
   本卡只把它当参照行；M1 是 D0+R1 上的重训基线。
6. **GRU 的 8 决策窗口**在换面/分片边界丢弃首 7 个决策（28/12,294 val 决策 = 0.23 %），
   已在逐臂 `unscored_windows` 中报告。
7. **history 消融是推理期干预（OOD）**：zeros/shuffled 的绝对值不是"纯像素模型"的能力，
   而是"这个模型有多依赖该通道"的下界；结论只用它的**差值**。
