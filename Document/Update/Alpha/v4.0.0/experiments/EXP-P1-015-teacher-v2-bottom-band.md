## 2. 诊断：贴底是怎么发生的（EXP-P1-015 §1）

证据分三层：**(A)** EXP-P1-012 的 6 面真实日志（全段 21k–28k 帧）；**(B)** 本轮新跑的 2 局 v1 策略仪表化诊断（Stage4A / Stage6A 各 1,500 决策，真实引擎，`--mode full`）；**(C)** 由 (B) 的 tape 现算的"向上空间 vs 子弹闭合时间"。

### 2.1 (A) 选中计划末端 `y` 与首动作方向（v1 全段）

| 面 | 决策数 | 末端 `y` 均值 | `y>400` | `y>420` | 首动作 up/down/idle/horiz | 停止时 `py` |
|---|---|---|---|---|---|---|
| Stage3 (stage2) | 5,327 | 394.1 | **52.6%** | 34.3% | 1402 / 1030 / 1702 / 1193 | 429.2 |
| Stage4A (stage3) | 7,154 | 406.1 | **66.9%** | **46.0%** | 1839 / 1491 / 2262 / 1562 | 432.0 |
| Stage4B (stage4) | 3,227 | 390.5 | **45.8%** | 31.3% | 651 / 506 / 1488 / 582 | 432.0 |
| Stage5 (stage5) | 2,293 | 400.4 | **61.3%** | 35.1% | 376 / 315 / 1303 / 299 | 428.0 |
| Stage6A (stage6) | 3,371 | 383.7 | **36.1%** | 22.3% | 479 / 378 / 2122 / 392 | 416.4 |
| Stage6B (stage7) | 1,913 | 377.0 | **63.7%** | 39.5% | 400 / 238 / 947 / 328 | 84.5（死亡瞬间在反弹） |

要点：

1. **`idle` 是最大项**（Stage4A 31.6%、Stage6A 63.0% 的决策首动作是"不动"）：计划末期贴底时，最省事的选择就是不动，而**评分里没有任何一项因为贴底而变差**。
2. **margin 项解释不了贴底**：按末端 `y` 分桶的平均 margin（Stage4A）是 350–400 → 15.47、400–420 → 14.58、420–432 → **14.46**；中位数全部是 16（`MARGIN_CAP` 饱和）。也就是说贴底并不"更安全"，而 `min(margin,16)` 在 16 处饱和后**几乎不区分任何计划**，剩下的排序几乎只由 `align`（4.0）+ `high`（−3，仅 `y<200`）决定。
3. **贴底时有存活计划可用却没选**：Stage4A 的 4,803 个贴底决策（`py>400`）里，有 **609** 次"已验证的存活计划末端 `y≤400`"存在，但最终选中的是末端 `y>400` 的那个（4,391 次选中存活贴底计划）。这说明**只要给底部一个惩罚，选择就会变**。

### 2.3 (C) "可用闪避空间 vs 子弹下落时间"——为什么贴底会死

以实测速度（normal 轴向 4.0 px/帧、聚焦 2.0 px/帧）换算"爬出自己头顶那段余量需要几帧"，与 `frames_to_close` 比较：

| 面 | 有闭合剂量的贴底决策 | 爬出所需帧数（中位） | 闭合时间（中位） | **来不及（normal）** | **来不及（聚焦）** |
|---|---|---|---|---|---|
| Stage4A | 391 | 37.1 | 54.0 | **78（20.0%）** | **206（52.7%）** |
| Stage6A | 499 | 27.2 | 64.4 | **81（16.2%）** | **97（19.4%）** |

**结论（诊断成立）**：v1 的评分里"越靠下越不亏"，于是策略长期停在 `y>400`（1/4–2/5 的决策离底边 ≤2 px，向下无路）；一旦有墙压下来，最坏十分位只剩 **5.8–8.1 帧**，而爬出头顶余量要 **27–37 帧**，即 **16–20% 的贴底决策在战术上已经无法用上移脱身（聚焦时 19–53%）**。这不是"有空间不走"，而是"空间换不来时间"。→ 需要给末端 `y` 加底部安全带惩罚，并且把"向上是否还有路"作为可选加分项。

### 2.4 与 EXP-P1-016 死亡分析对齐（订正一条旧结论）

P1-WP4 的死亡分析（EXP-P1-016，原局 JSONL + env 重放，271 检查点 0 不匹配）给出的死因分布是：`bullet_wall` **6/6**、`bomb_exhausted` **6/6**、`bottom_pin` **5/6**、`boss_pattern` 5/6、`laser` **1/6**（Stage6A，死亡帧 51 条激光、gap 0.0）。

**订正**：EXP-P1-012 §6.4 的"死亡位置 `py≈416–432`（贴底）"只对 **5/6** 成立——**Stage6B 死在 `py=84.5`（Boss 距 102 px），是主动压向 Boss 本体被 body 打死，不是贴底**（本文 §2.1 表里 Stage6B"停止时 py"=84.5 也是同一事实）。因此：

- 底部带只对 5/6 的死因有效，**不能把 v2 只押在底部**；第 1 轮实测正好验证了这一点（§6.1：Stage4B/6A 被赶去顶角后死亡）。

公式（`h = 1 if y<200`，`e = 1 if 近边界`，`b(u) = max(u,0)`）：

```text
bottom = 1.5·b(y−400)/32 + 2.0·b(y−420)/12          (v2a)
       = 2.5·b(y−400)/32 + 3.5·b(y−420)/12          (v2b)
escape = 1.0 · clip(room_up, 0, 32)/32  仅当 y>400（v2b；向下无路时才计）
score(活) = 100 + min(margin,16) + 4·align + 2·items − e − 3·h − bottom + escape
```

**强度依据**（不是拍的）：`y=432` 时 v2a 扣 **3.5**、v2b 扣 **6.0**，而实测"贴底 vs 中段"的 margin 差异只有 **0.3–1.0 分**（§2.1 第 2 条），因此这个量级足以让"末端 400–432"让位给"末端 ≤400"，同时**远小于** `align` 的 4 分满权重（不会把横向对齐整条推翻）。`escape` 项只在底部带内生效，避免让"向上余量"变成第二个全局主导项。

## 13. 局限与声明

1. **`partial=true` 的含义**：三轮覆盖的面集不同——第 1 轮 v2a 是**唯一单档 8 面齐全**的一轮（5/8 = 0.625）；第 2 轮 v2c 只跑了 3/8 面就被主动停止（3/3 变差，见 §7）；第 3 轮 v2d 只重跑了第 1 轮仍死的 5 面（5/5 全部跑完、5 面全死），Stage 1/2/4A 未在 v2d 下重测。**因此没有"v2d 的 8 面均值"，本卡也不拼这个数。**
2. **没达标**：0.625 > 0.5。本卡没有把"存活帧数变长"包装成"死亡变少"——`--stop-on-death` 下每面就是 0/1，只有"活到过面或帧上限"才算 0。
3. **dead 判定仍只认引擎**：所有死亡都来自 `STATE.f6` 增量，`stage_clear` 只认 `STATE.f1` 变化；没有用"残机/血量/存活时间"推断任何一次死亡或过面。
4. **没改的东西**：引擎、协议、依赖、第三方、build 全部未动（engine SHA `f172399f…` 与 EXP-P1-012 相同，每次 run 都自校验）；`tools/rl/v400_g1_eval.py` 未改（8 面驱动写在 `.tmp_v400_v2/psn_v2.py`，只复用它的公开函数）。
5. **并发**：6 teacher × (主 shadow + PARK/SPAWN 子) —— 运行时 `pgrep -xc th08-modern` 实测 **13–16**，不是 2×6=12；启动前的 `TH08_BEFORE` 分别为 2 / 0 / 0（第 1 轮那 2 个是诊断批的收尾进程）。零售 trace 批跑（Windows 侧 `th08` + python）全程未动。
6. **同 seed 单局**：每面只跑 1 局（seed 1），所以"每面死亡"是 0/1 的伯努利样本，8 面均值 0.625 的置信区间很宽（按 Wilson，5/8 的 95% 区间约 [0.31, 0.86]）；**不能**据此声称 v2a 的真实均值一定低于 v1，只能说同 seed 下少死 1 次、且 6 个靶点的存活帧数一致变长。
7. **性能断言的负载敏感性**：`test_raster_search_is_faster_than_the_exact_search_on_a_dense_tape` 在并发 teacher 运行时偶发失败（§11），空闲重跑通过；不把它算成本轮回归。
8. **`v2b` 未跑整轮**：它的逃脱空间项有单测（§11）但没有 8 面数据，卡里明确标注"未重测"，不作为结论依据。
