# v4.0.0：把真实引擎变成训练场

> 用像素学会玩东方，这件事卡了很多个版本。v4.0.0 的判断是：卡住的不是算法，而是训练场。本文是 v4.0.0 的导入文章，讲清楚为什么转向、怎么做，以及这套文档该怎么读。

- 日期：2026-11-07
- 状态：**路线已定，等待执行。** 训练场走 WSL2 路线（[决策 D-04](<31-决策记录.md>)，已确认）。WSL 已经装好，开工前负责人还要做两件事：重启电脑，安装 Ubuntu 24.04 发行版。
- 关系：本版本**取代** v3.9.0 Stage B–F 的计划。v3.9.0 Stage A 测出的环境事实继续有效。

## 一、我们要做成什么

项目的最终目标从没变过：**只看框选画面，就能玩东方；换一部作品、给一个框，它能自己学会、自己变强。**

部署时，模型只接收画面和按键，不读内存、不注入、不依赖游戏版本。训练时，内存和引擎可以随意用，但它们只能当"老师"和"裁判"，不能当学生的眼睛。

v4.0.0 把这个目标拆成四层，逐层兑现：

1. **会玩**：只看像素，就能通关 TH08 的一面。
2. **会自我改进**：只靠画面算出的回报继续训练，并且越练越强。
3. **会适应**：在没见过的关卡、机体、难度上，用有限的交互学得比从零更快。
4. **会迁移**：在另一部东方作品上做到第 3 层。

## 二、为什么之前一直做不出来

结论只有一句：**每一次失败，都发生在样本少到不可能成功的量级上。**

- 迄今唯一成立的控制能力，是用 3,282 个人类标签训练出的 BC。它每 50 秒游戏仍然要死 2.95 次，随机策略是 4.40 次。
- 最大的一次 RL 实验只用了约 2 万帧。而像素端到端 RL 的常见量级是千万到亿帧。
- 训练场是实时 Windows 窗口：每秒 21 个决策，每局重启进程要 12 秒，**92.7% 的时间花在搬运画面上**（v3.9.0 实测）。
- 从来没有一个"会玩"的老师。学生只能学人类的少量录像，一离开录像覆盖的状态就崩。

另外，v3.9.0 有三条结论需要撤回，因为它们在压缩后续路线：

- "引擎不可复现"：实际上是探针没有固定随机种子。
- "纯像素奖励不可行"：实验把显示残机的 HUD 切掉了，数值也已经出错。
- "预算不够做完整一面"：这只是慢环境下的算术。

详见 [01-复盘与转向](<01-复盘与转向.md>)。

## 三、转机：仓库里已经有一台"游戏机"

`third_party/th08` 不是模拟器，它就是游戏本身：一份完整的源码重建。它的 Linux 构建**逐位复现了 108 份人类回放、1,231 万次逻辑计算，25 个状态字段连浮点位都一致**；它还自带不限帧运行、回放追踪记录器和无光栅化运行的能力。

这意味着可以做到实时窗口做不到的四件事：

| 能力 | 怎么做 | 带来什么 |
|---|---|---|
| **快** | 去掉 60 帧限制、多进程并行、进程内直接取帧 | 吞吐目标是现在的 50 倍以上 |
| **确定** | 固定随机种子加输入序列，一局就完全确定 | 数据可以存成几 KB 的回放，像素需要时再重新渲染 |
| **可快照** | Linux 上用 `fork()` 写时复制 | 可以在任意状态"如果这样走会怎样"，向前推演 |
| **可重入** | 回放可以快进到任意一帧 | 可以从人类打到的任何位置开始练 |

## 四、路线：先造一个会玩的老师，再让学生自己练

```text
P0 训练场 ──► P1 搜索教师 ──┐
          └─► P2 像素感知与回报 ─┴─► P3 像素学生（DAgger） ──► P4 自我改进 ──► P5 留出适应 ──► P6 第二作
```

1. **P0 训练场**：在引擎研究构建里实现不限帧、按种子直接进关、进程内取帧、`fork` 快照和多实例。
2. **P1 搜索教师**：每一步都用快照在真实引擎里试走 18 个方向、看未来一秒会发生什么，然后选最安全、最有利的那个。它看到的就是真实的未来，所以几乎不会被打中。目标是通关 Normal 1–6 面。这将是项目里**第一个真正会玩 TH08 的东西**（特权版）。
3. **P2 像素感知与回报**：用引擎自动产生的海量标签，教模型从画面里看出子弹、自机、危险区域，以及从 HUD 读出残机、bomb、分数，并识别死亡和过面。这一步把"不读内存也能算回报"变成实测事实。
4. **P3 像素学生**：只看像素的学生先模仿老师，然后**自己玩**；在它自己走到的每一个状态上请老师纠正（DAgger）。这正好治"离线好、闭环崩"这个老毛病。
5. **P4 自我改进**，分两条循环：
   - **专家迭代**：学生反过来指导老师搜索，让老师看得更远，变强的老师再教学生，如此反复。这一步不需要任何人类录像。
   - **像素回报 RL**：不准用引擎、不准用老师，只靠画面算出的回报自己练。这就是将来在新作品上"自己微调自己"的那套方法。
6. **P5 留出适应**：在 TH08 内部模拟"换一作"，用没见过的机体、关卡、难度和换了画风的画面来测试。
7. **P6 第二作**：前提是负责人提供 TH07 或 TH06 的合法数据。

### 关于"录像有限，能不能让它自己练"

能，而且这就是主线，但要用对方式。

从零开始乱按、只靠"死了扣分"去摸索，效率最低：弹幕游戏里随机乱按几十秒就会死光，根本见不到后面的内容。

正确的"自己练"是**专家迭代**：用真实引擎做前瞻搜索当老师，老师的动作比学生好，就蒸馏给学生；学生变强了，又帮老师更快、更远地搜索。这个循环完全不需要人类录像。

人类录像退到三个辅助位置：

- 提供"从关卡中途开始"的起点；
- 作为人类水平的参照线；
- 可选的少量热身。

详见 [02-思想与目标 §3 原则 3](<02-思想与目标.md>)。

## 五、怎么衡量"真的变强了"

只有一种衡量方式：**TH08-Bench**。它在固定的、训练从未用过的随机种子上，统计独立 episode 的过关率、死亡数和分数，并给出置信区间。学生评测时只能看到像素，成绩由独立的裁判读取。

准确率、loss 都只能当诊断用，不能拿来证明能力。见 [20-基准与评测](<20-基准与评测.md>)。

## 八、不变的底线

- 部署模型只接收画面和按键。
- 不改 canonical 构建、原始镜像、默认模型；不往外部游戏进程写内存。
- 所有引擎改动都放在研究编译开关后面，默认关闭，并且必须通过回放逐位验证。
- 负结论在落笔之前，必须先通过有效性自检。
- 门不过，就不往下走。
