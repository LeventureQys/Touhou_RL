# 14 P4 自我改进：专家迭代 + 像素回报 RL

- 依赖：G3。
- 时间盒：15 个工作日。循环 A 和循环 B 可以并行推进。
- 产出：`teacher-v2`、`student-v2`（循环 A）；像素回报 RL 的四臂结果（循环 B），通过 G4。

---

## 1. 为什么有两条循环

负责人提出的问题是："能不能让它自己玩、自己训练自己？"答案是两条循环，**它们回答的是两个不同的问题**：

| | 循环 A：专家迭代 | 循环 B：像素回报 RL |
|---|---|---|
| 回答的问题 | 在 TH08 上，能不能**不靠人类**持续变强，并超过手写的教师？ | 在**没有引擎、没有教师**的条件下，只靠画面算出的回报，能不能自我改进？ |
| 可以用的东西 | 引擎、快照、特权状态 | 只有像素、按键、像素回报。训练场只用来加速 |
| 迁移到新作品时 | 用不上（新作品没有引擎） | **这就是在新作品上"自己微调自己"的那套算法** |
| 主门 | G4-A | G4-B |

## 2. 循环 A：专家迭代

### 2.1 思路

P1 的教师是手写评分加上固定地平线，它有两个已知的弱点：

- 地平线约 60 帧，更远的陷阱看不到；
- 评分是手写的启发式规则，不懂怎样更快打掉 Boss、什么时候该放 bomb、怎么经营资源。

专家迭代的做法是**用学到的东西补上这两点**：

```text
teacher-v(k+1) = 搜索( 先验 = student-v(k) 的策略,  叶子估值 = V-v(k) )
student-v(k+1) = DAgger( 教师 = teacher-v(k+1) )
V-v(k+1)       = 在 teacher-v(k+1) 的轨迹上拟合"从此刻开始的真实回报"
```

### 2.2 教师 v2 的改动

1. **先验剪枝**：只展开学生策略概率前 k 的动作（默认 k=6），另外**始终**加上"安全兜底"候选，也就是 P1 评分中余量最大的那个动作。
2. **叶子估值**：分支在地平线 H 处的得分 = 存活项 + `V(s_H)`。这里的 V 是一个**特权**价值网络：输入是引擎状态的结构化特征（子弹、敌人、资源），训练目标是从该状态起、按当前教师继续玩所得的折扣回报。
3. **任务回报**（替代手写启发式）：
   - `r = Δscore / 1e5 − 1.0·死亡 − 0.3·用 bomb + 2.0·过面`
   - 这些权重是初始值，要写进配置。修改权重需要另开一张实验卡片。
4. **更长的有效地平线**：搜索本身的深度不变，靠叶子估值把视野延伸出去。

### 2.3 工作包（循环 A）

| WP | 内容 | 验收 |
|---|---|---|
| A1 | 特权价值网络 V：数据来自 P1/P3 期间教师轨迹的结构化状态；目标是折扣回报 | 在留出种子上，V 预测的解释方差 ≥ 0.5 |
| A2 | `teacher-v2` = P1 的搜索 + 先验剪枝 + 叶子估值 | `PSN` 和 `RUNN` 开发集上，按种子与 `teacher-v1` 配对比较 |
| A3 | 用 `teacher-v2` 跑 DAgger，从 `student-v1` 出发，得到 `student-v2` | `S1N`、`PSN`、`RUNN` 开发集 |
| A4 | 可选：迭代 k=2,3，直到改进 < 5% | 每一轮一张实验卡片 |

### 2.4 门 G4-A

| 判据 | 阈值 |
|---|---|
| `teacher-v2` 相对 `teacher-v1` | `RUNN` 确认种子 100 局：平均打到的面数或分数，配对区间下界 > 0 |
| `student-v2` 相对 `student-v1` | `PSN` 确认种子：8 面总死亡数配对下降，区间下界 > 0 |
| 人类录像的使用 | 循环 A 中**完全不使用**人类录像（起点也不用），以证明"不靠人类也能变强" |

## 3. 循环 B：像素回报 RL

### 3.1 规则（模拟"在新作品上自己练"）

- 智能体只能拿到像素、自身动作历史和**像素回报**。像素回报由 P2 的检测器计算，检测器冻结，不随 RL 更新。
- **不使用**快照、教师、引擎状态，也不能从回放中途起步。只能从标准起点开始，game over 后重开，和真实游戏一样。
- 训练场只提供加速。
- critic 也只看像素。为了比较，另外设一个"特权 critic"变体臂，但它不能作为 G4-B 的依据。

### 3.2 回报

```text
r_t = 1.0 · clip(Δscore_pix / 1e5, 0, 1)
    − 1.0 · death_pix
    − 0.3 · bomb_pix
    + 2.0 · stage_clear_pix
```

- `*_pix` 全部来自 P2 的像素检测器。
- 同时记录用内存真值算出的回报 `r_priv`，但**只写日志**，不参与训练（B2 臂例外）。
- 每 10 万步统计一次 `r_pix` 与 `r_priv` 的一致率，写进日志。

### 3.3 算法

- PPO（GAE λ=0.95，γ=0.995/决策），向量化环境 64–128 个。
- 吸取 v3.8 的三条教训：
  1. **行为概率**在采集时保存 `logp_old`，不要重算后替换（v3.9.0 P-1）。如果使用循环网络，burn-in 部分不进入策略损失。
  2. **熵奖励会破坏先验**（v3.8.0 W6：entropy 1.01→1.87，死亡数回到随机水平）。做法是：熵系数设为 0 或很小；加一项"对初始策略的 KL 惩罚"（默认 β=0.05），并且随训练衰减。
  3. **先预热 critic**：前 N 次更新（默认 20）只训练价值头，不更新策略。
- 进入价值目标的 V 是哪一个，必须写进 `train_config.json` 的 `advantage_source` 字段（v3.9.0 P-2）。

### 3.4 四臂（主实验）

**目标设置**：选一个学生还不擅长、但还没有到完全不会的设置作为主战场。默认是 `S1L`（Stage 1 Lunatic）。如果 `student-v1` 在 `S1L` 上的过关率已经 ≥ 80% 或者 ≤ 2%，就改用 `PSL` 中过关率最接近 30% 的那一面。这个选择必须在 RL 开跑**之前**写进实验卡片并冻结。

| 臂 | 起点 | 回报 | 说明 |
|---|---|---|---|
| B0 | `student-v1`（或 v2） | 不训练 | 基线 |
| B1 | 同 B0 | 像素回报 | **主臂** |
| B2 | 同 B0 | 内存真值回报 | 像素回报的上限参照 |
| B3 | 随机初始化 | 像素回报 | 从零开始，不用教师。回答"没有教师能学到哪一步" |

- 每臂 3 个训练种子；每次 run 的预算为 5,000 万帧（具体按 P0 的吞吐换算成墙钟，写进卡片）。
- 每 10% 预算评测一次，用 `dev` 种子 20 局，画学习曲线。

### 3.5 门 G4-B

| 判据 | 阈值 |
|---|---|
| B1 − B0（目标设置，确认种子 100 局，3 个训练种子合并） | 过关率差的区间下界 > 0，且点估计 ≥ +15 个百分点（预注册） |
| B1 相对 B2 | B1 的提升 ≥ B2 提升的 70%，即像素回报不比内存回报差太多 |
| B3 | 只报告，不设门。这一臂的结果直接决定 P6 的预期 |
| 回报一致率 | 训练全程 `r_pix` 与 `r_priv` 的符号一致率 ≥ 99% |

### 3.6 不过怎么办

- B2 有提升而 B1 没有：问题在像素回报。回到 P2，看哪一类事件的检测出了偏差。
- B1 和 B2 都没有提升：问题在 RL 本身，包括超参数、KL 约束、critic 预热。允许一次预定修订（只能改 §3.3 中列出的超参数），重跑一次。仍然不过，就交付负结果，并写清已经排除了哪些原因。
- 学生在目标设置上反而变差：检查 KL 惩罚系数，以及 critic 的解释方差。
