# 13 P3 像素学生：BC → DAgger

- 依赖：G1（搜索教师能通关）、G2（像素感知达标，且已决定观测分辨率）。
- 时间盒：12 个工作日。
- 产出：`student-v1` checkpoint（只看像素），通过 G3。
- 接口引用：训练场与教师服务的 API 见 [03-系统架构 §4–§5](<03-系统架构.md>)。

---

## 1. 为什么这样做

v1.0.4 和 v3.7.3 都出现过"离线指标好、闭环崩溃"，根因是**协变量偏移**：学生只在教师走过的状态上学过，一旦自己犯错进入陌生状态，就不知道该怎么办，错误会越积越多。

DAgger 的做法是：让学生自己玩，在**学生实际到达的状态**上请教师标注，然后再训练。这样训练分布会逐步收敛到学生自己的分布上。

DAgger 需要能在任意状态上查询教师。P0 的影子进程加上 `fork` 快照，正好提供了这个能力（[03 §5](<03-系统架构.md>)）。

## 2. 学生规格

### 2.1 观测（只有像素）

- 输入：最近 4 帧的游戏客户区画面。
  - 分辨率由 G2 决定（P2-WP5 的结论）。默认候选是整帧 320×240 RGB，也就是半分辨率，此时 playfield 为 192×224，HUD 也在画面里。
  - 如果 P2 测出半分辨率看不清判定附近的子弹，就改成双输入：playfield 用原分辨率 384×448，HUD 用半分辨率。
- 外加最近 8 个决策的自身动作（one-hot）。
- **不允许**任何其他输入。

### 2.2 动作

- 决策周期：2 帧，与 v3.9.0 的合同一致，也与真机部署通路一致。P3-WP6 会做 1 帧的消融。
- 动作是因子化的：
  - `move_focus`：18 类，即 9 个方向 × 聚焦与否，与教师的 18 个候选一一对应；
  - `bomb`：2 类；
  - `shoot`：固定开火（D-08 的主线设置）。
- 动作到按键位掩码的映射复用 `touhou_rl/spec.py` 的定义（见 [03 §3](<03-系统架构.md>)）。

### 2.3 网络（起点，可以按实验结果调整）

- 编码器：IMPALA-ResNet 风格。3 个 stage，通道 32/64/64，每个 stage 是 conv + maxpool + 2 个残差块。4 帧在通道维拼接（12 通道）。
- 可选：编码器后接 GRU(256)。P3-WP6 消融。
- 输出头：
  - 策略头：`move_focus` 18 维 logits，`bomb` 2 维 logits；
  - 价值头：预测教师回合内的"剩余存活/回报"，只作辅助；
  - 感知辅助头，目标来自 P2 的标签：自机位置（热图）、1/4 分辨率的弹幕占用图、未来 8 帧的危险图、残机数和 bomb 数。
- 参数量目标为 2–6 M。v3.8 的 actor 只有约 0.25 M 参数（checkpoint 0.99 MB），小模型是需要排除的变量之一。

### 2.4 损失

```text
L = KL(π_teacher || π_student)                     # 18 类软标签
  + λ_bomb · BCE(bomb_teacher, bomb_student)
  + λ_aux  · Σ 感知辅助损失
  + λ_v    · Huber(V, 教师回报)
默认 λ_bomb=1, λ_aux=0.5, λ_v=0.25
```

软标签：`π_teacher(a) ∝ exp(score(a)/τ)`，其中 `score` 是教师对 18 个候选的评分（[11-P1 §3](<11-P1-搜索教师.md>)）。`τ` 的取值要保证"会死的动作"概率小于 1e-3，并写进配置。

## 4. DAgger 循环细节

```text
for i in 0..K-1:
    β_i = [1.0, 0.5, 0.25, 0, 0, …][i]        # 执行教师动作的概率
    并行 N_env 个环境（默认 16），每个环境配一个影子进程
    每个决策：
        学生前向，得到 a_s
        影子进程查询教师，得到 (score[18], bomb_t)
        以概率 β_i 执行教师动作，否则执行 a_s
        记录 (像素缓存键, 教师标签, 感知标签)
    每轮采集 M 个决策（默认 50 万）
    聚合：保留最近 R 轮的数据（默认 R=6）+ D0 的 20% 抽样
    从上一轮权重开始继续训练 E 个 epoch（默认 2）
    在开发集上评测 S1N（20 局）和 PSN（每面 10 局）
停止条件：连续两轮 S1N 开发集死亡数的改进 < 5%，或达到时间盒
```

**起点课程**：每轮的起点按比例混合——关首 50%、人类回放中途状态 30%、学生自己上一轮死亡点前 5 秒的状态 20%（从回放快进得到）。最后这一类专门练学生自己的弱点。

**成本估算**（需要 P0 的实测吞吐来校准）：教师查询每个决策约需 3,000 推演帧。如果推演速度是 5,000 帧/s/核、16 核，那么每秒约能标注 25 个决策，每轮 50 万决策约需 5.5 小时，这太慢了。三条对策：

- 每个决策只做一层搜索，并且只在"学生动作与教师首选不同、或者危险余量很小"的状态上做完整搜索；
- 用 P1 的"快速教师"模式，见 [11 §3.4](<11-P1-搜索教师.md>)；
- 降低每轮的 M。

WP3 开始前，先用一张实验卡片测出实际的标注速率，再据此确定 M 和 K。

## 5. 门 G3

| 判据 | 阈值 |
|---|---|
| `S1N` 确认种子 100 局的过关率 | 点估计 ≥ 50%，且 95% 区间下界 ≥ 35% |
| `PSN` 每面死亡数 | 只报告，不设门，但必须全部 8 面都有数据 |
| `REAL-S1N` 真实 Windows 游戏 20 局 | 过关率点估计 ≥ harness 中 `S1N` 过关率的 70% |
| 零特权 | bench 的零特权单元测试通过；评测日志中 `privilege=deploy_pixel` |

**不过怎么办**

- harness 内过关率 < 50%：按顺序排查。
  1. 学生在教师状态上的动作一致率是否 ≥ 90%？如果不是，说明是学习或容量问题。
  2. 死在哪里？用死亡点聚类分析。
  3. 在死亡点附近，感知辅助头的输出是否正确？如果不正确，说明是感知问题，回到 P2 提高分辨率。
- `REAL` 远低于 harness：回到 G0.4，检查像素一致性、帧时序和动作延迟。真机上动作延迟是 1 帧，训练场里也必须用同样的延迟来模拟（[10 §4](<10-P0-训练场.md>)）。
- 止损：BC 加 3 轮 DAgger 之后，`S1N` 开发集死亡数相对 BC 的改进如果 < 30%，就停下来写分析，并问负责人。
