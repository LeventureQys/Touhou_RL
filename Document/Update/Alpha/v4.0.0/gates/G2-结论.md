### 3.1 第 13 行 `stage_clear`：样本量不足 + 2 个漏检

| 项 | 值 |

| n（事件） | **250**（EXP-P2-008 131 + 本轮 34 + 30 + 55；四轮并集，软链语料）；n=250 时零失败下界封顶 **98.49%** |

| 门的 3 折 CV（每折重选）| **248/250 = 99.20% / LB 97.13%**；精确 100.00% / LB 98.47%；fold 选中 3.0/0.0/5 |
| 冻结判据的漏检 | `th8_ud2cce-s1`（窗口第 3 帧误触发，`Δvgrad` 16.06）、`th8_ud2ce5-s2`（第 8 帧，Δ 2.16）；150 帧不应期把第 60 帧真边沿压掉 |
| 全语料里出现「边沿前候选」的事件数 | **2 / 250**（`diag_predict.py`），漏检率 ≈0.8% |
| 放宽匹配窗到 `[edge−8, edge+10]`（只报告）| 冻结判据仍 **248/250**、严格点仍 **248/250** —— **放宽窗口无效** |
| 网格点 4.0/5.0/8（只报告，非公布判据）| 250/250（LB 98.49%，仍因 n 不足而 <99%） |

**为什么补样本不是万能药**：`th8_ud2ce5-s2` 的面板在窗口第 6–8 帧就已点亮（早于引擎边沿约 50 帧），
`th8_ud2cce-s1` 是「开-关-开」三段式；两者都不是「n 不够」造成的。
本轮已把整段逐帧 `vgrad` 流落盘（`events/*/stream.npz`）。

**真连续流评估（55 个带流事件，回读起点 → edge+120，中位 783 帧）—— 本轮最重要的发现**

| 匹配口径 | 命中 | 召回 | 首个告警相对 edge |
|---|---|---|---|
| 门冻结窗 `[edge, edge+10]` | **15 / 55** | **27.27% / LB 17.28%** | 中位 **−112 帧**（范围 −172…+1） |
| 允许早检的窗 `[edge−150, edge+10]`（只报告） | **55 / 55** | **100.00%** | 同上 |

**像素侧过面板比引擎 `stageClear` 电平位早约 112 帧出现**，冻结判据在真连续流上每次都在过渡起点
正确触发；但门的匹配窗锚在引擎位，于是把 40/55 次**提前命中**记成漏检，同时 150 帧不应期又压掉了
`edge` 处的二次触发。切片评估（起点 = edge−60）恰好裁掉了这段提前量，所以切片 99.20% 与连续流
27.27% 相差 72 个百分点 —— **差别在匹配窗锚点，不在检测器能力**。

⇒ 第 13 行既不能靠补样本过门，也不能靠「换成连续流评估」过门（连续流在冻结窗下更差）。
要真正达标只有两条路，且**都需要负责人签字改判据**：①把事件锚点改成像素过渡起点
（或把匹配窗左拓到 `[edge−150, edge+10]`）；②让引擎把 `stageClear` 电平位与像素面板同时置起（T7 范畴）。

**death 是本行的决定性缺口**：修好 5/6 通道加载 bug、把负样本从「25,291 respawn + 57 普通帧」
改成「21,673 + 32,651」重训后，val 召回从 25.2% 抬到 **40.8%**、精确从 19.0% 抬到 33.0%，
但仍然差两个数量级；在线 1,325 个真实死亡事件上召回 19.47%、精确 4.58%。
**要在这一行达标还差什么**（供下一轮决策）：
1. **数据**：负样本不能只从「同 stage 3 的 respawn 带」取，需要覆盖全 8 面、全难度、多种自机与弹幕密度的
   普通帧（本轮语料只有 stage 3 d3）；正样本要有 +4 / +29 两条消解路径的均衡覆盖（本轮 bombEmpty 子集
   只有 139/1325）；
2. **模型**：96×112 全局 CNN 在 89k 参数下分辨不出「机体被弹幕遮挡」与「机体消失」；需要显式机体
   定位 + 局部高分辨率窗（obs-v3 的 D 方案），或模板跟踪 + 遮挡模型；
3. **判据**：死亡的正样本带宽（`posAfter=4`、7 帧窗）与 +29 帧消解路径不匹配，需要按路径分别定窗；
4. **规模**：这一行的 99% LB 需要 ≥386 个**可观测**死亡样本下零失败 —— 以本轮 19% 的召回率，
   需要模型侧先做到 ~99%，样本量才有意义。
