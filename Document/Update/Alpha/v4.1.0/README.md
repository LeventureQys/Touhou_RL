# v4.1.0 路线分析与持续执行规划

日期：2026-11-12，Asia/Shanghai。接手对象：项目主代理与执行代理。

**当前状态：规划已编写，实施未开始。** 本次只新增规划文件，没有启动训练、采集、构建或真机控制。后续代理收到用户明确的“执行本规划”指令后，才进入下述实施流程。

本规划保留真实引擎、搜索教师、像素学生、DAgger 和像素回报强化学习的主线。顺序改为：先确认评测、时间与标签是否正确，再证明学生能学会第一面，随后证明像素回报可靠和自我改进有效，最后覆盖完整一周目、留出适应与第二作。每个阶段都规定继续条件与替代路径，避免把工程完成、离线准确率或阶段通过当作项目完成。

本文件是 v4.1.0 的唯一实施规格和交接入口。运行状态以后记录在本文件第 15 节约定的状态文件中；实验结果进入各自实验卡片与证据目录，不向本文件反复追加历史状态。v4.0.0 原始规格、报告、模型、数据与二进制继续保存。

## 1 最终目标与完成边界

最终目标沿用 [v4.0.0 目标定义](../v4.0.0/02-思想与目标.md)：智能体只接收框选画面与自身动作历史，完成东方作品；换一作后，用有限交互自己学习和微调。外部游戏进程不接受注入、patch 或内存写入。

“完成作品”在本规划中采用一个可检验的起步范围：Normal、预注册机体与路线、自然开局、标准资源、不续关，完成选定路线的有效结局。它不包含所有机体、所有难度或所有结局，扩展能力另行报告。

| 层级 | 要证明的能力 | 对应门 | 不能替代它的结果 |
|---|---|---|---|
| L0 | 实验、环境、数据与裁判可信 | G410-0、G410-1 | 标题画面、单测、旧报告中的 PASS |
| L1a | 像素学生能过 TH08 第一面，并能真实部署 | G410-2 | 首死时间变长、离线 top-1 提高 |
| L2 | 只靠像素回报继续训练，独立游戏成绩提高 | G410-3、G410-4 | 使用引擎回报、引擎终止信号或教师纠正 |
| L1b | 同一像素策略能完整一周目，不续关 | G410-5 | 八个练习关分别过关、换面后补资源 |
| L3 | 在未见设置上，有限交互适应优于从零 | G410-6 | 只报告预训练零样本成绩 |
| L4 | 第二作严格像素适应，并完成作品 | G410-7 | TH08 换色、第二作人工 HUD 标注后的适配 |

**G410-0 至 G410-5 全部通过，可以宣布 TH08 阶段目标达成；G410-0 至 G410-7 全部通过，才能宣布本规划对应的项目目标达成。** 全部主线工作仍按依赖持续推进，不因版本阶段交付而自动停止。第二作资源缺失时，明确记录 L4 未验证，不能写“只缺资源，方法已经成立”。

本文件中的新增阈值是后续实验的事前规格，不回写为 v4.0.0 已通过。未来实施时先冻结协议和配置；如用户另行修改范围，以用户最新指令为准。

## 2 对当前路线的分析

### 2.1 应当保留的资产

1. **真实引擎与确定性回放。** 它们大幅缩小了自写弹幕世界的动力学误差，支持可再生数据与可复查的实验。但有限回放一致不证明所有状态、像素、输入延迟都一致。
2. **进程内重开与统一研究构建。** [T7 证据](../v4.0.0/evidence/EXP-P0-078/replay12-summary.json)记录了 12 份差分回放一致；旧二进制按 SHA 保留，复核后复用。已有能力不再另造一套。
3. **教师提供起步能力。** [G1 报告](../v4.0.0/gates/G1-报告.md)记录第一面 20/20 开发局过关，是有价值的探索证据。
4. **BC 后接 DAgger。** 在学生实际访问的状态上获得纠正，直接针对离线模仿的分布偏移；它有研究依据，但不承诺任意教师和观测下都能成功。
5. **训练期特权与部署期像素分离。** 保留特权标签和独立裁判，继续产出可迁移的视觉表征、策略、像素回报与适应算法。

### 2.3 待检验假设

优先级按低成本、高信息量排列，不把以下项目预写为根因：

1. 学生塌缩首先来自评测、归一化、设备、帧窗口、动作历史或动作节拍错误。
2. 教师分数中的验证折扣、并列动作与特权反射，产生了不好学习的动作目标。
3. 训练的大部分梯度来自容易的“不动”状态，关键躲避状态监督不足。
4. 当前观测或时序记忆不足以恢复动作需要的信息；全局池化只是可疑因素之一。
5. 多面任务混合、样本有效覆盖、训练更新量和模型容量之间存在负面交互。
6. BC 的真实瓶颈是学生状态覆盖，必须通过有效 DAgger 才能解除。
7. 像素回报误差、终局泄漏或 PPO 实现细节导致先验破坏。

无论哪项成立，都只允许在对应证据范围内作结论。“样本越多越差”“2.6M 参数太大”“GAP 必然无法定位”“再训十倍一定成功”均不得作为默认事实。

## 4 统一评测协议

### 4.1 游戏结果与终止语义

| 套件 | 运行定义 | 主要指标 |
|---|---|---|
| DIAG-FIRST-DEATH | 到首次死亡、过面或 cap，用于排错 | 首死时间、动作轨迹；不作为过关门 |
| S1N | stage_index=0、Normal、固定机体、标准资源，允许消耗正常残机 | 过关率、每局死亡、bomb、失败原因 |
| PSN | 八面分别练习起点，运行到过面或冻结 cap，持续累计死亡 | 各面过关率和死亡均值；同时报告跨面汇总 |
| RUNN | 自然第一面开局，同一局连续推进，固定路线，标准资源，无续关 | 有效结局率、到达进度、死亡、bomb、分数 |
| REAL-S1N、REAL-RUNN | Windows 零售原件、真实 60 Hz、像素控制 | 与相同模型的 harness 结果比较 |
| HO、SECOND | 留出适应与第二作，预算和运行口径事前冻结 | AULC、固定预算成绩、实际交互小时、人工成本 |

PSN 若练习资源耗尽而提前 game over，应记为失败并暴露资源设计问题；不得将提前停止的死亡数当作完整面的死亡均值。练习状态与标准状态必须逐字段实测并登记。RUNN 不得在换面时 RESET、换模型、补残机或清除 rank。

cap 优先使用已核验人类参考长度的 1.5 倍。缺参考时先补参考，或在开发集冻结统一保守 cap 并报告 censored 比例；不得看确认结果后扩 cap。超时、崩溃、缺记录不能从过关率分母消失。

Final 的“结束”由路线、结局和最终状态共同确认；单看 stage_index 增大不足以证明整作通关。

### 4.2 时间和动作契约

默认继承每决策 2 个逻辑帧、18 个移动与聚焦动作、独立 bomb 二分类，开火规则及必要释放脉冲必须完整记录。任何变动建立新 action/obs/protocol 版本。

每条数据记录逻辑帧 t、最后可见渲染帧、决策边界、动作生效帧、实际输入掩码、保持时长，以及动作历史的单位。“一个 CLI 决策”与“一个学生决策”分列，不把 4 帧采集块视为 2 帧部署标签。

帧堆叠默认四个连续游戏帧，不混用跨决策抽样帧。训练、harness 和 Windows 通过同一观测适配器；动作历史只含已实际执行的过去动作。新增 bomb 历史、时间间隔或记忆状态时创建 obs-v410-* 版本，不能悄悄改旧格式。

### 4.3 种子与确认集

训练默认使用 1–49,999，排除 1000–1099 和所有已登记评测种子。旧确认范围 60000–60199 永久禁止训练。训练谱系包含教师数据、感知预训练、回报检测器、模型选择和适应数据，不能只查最终策略的 seed 字段。

新确认范围是预分配建议。WP00 必须先检查历史暴露登记；任何已使用值在首次正式运行前整体换到未暴露区间，写入配置并冻结。

| 用途 | 初始分配 | 使用规则 |
|---|---|---|
| 开发诊断 | 1000–1019 | 排错、开发曲线 |
| 候选模型选择 | 1020–1039 | 冻结选模规则；不把多轮筛选当确认 |
| 保留开发检查 | 1040–1099 | 预注册消融和回归 |
| 第一面正式确认 | 61000–61099 | 每个最终候选只使用一次 |
| 一周目正式确认 | 61100–61199 | 100 局 |
| 留出适应正式确认 | 61200–61299 | 另冻结任务、训练和评测交互 |
| 教师正式确认 | 61300–61399 | S1N 与 PSN 分表，不能池化伪增样本 |
| RL 正式确认 | 61400–61499 | 冻结策略与训练种子后使用 |

配置公开种子不等于可用于调参。正式确认 CLI 默认拒绝运行，只有实验预注册、依赖门、候选 SHA 与曝光登记全部齐全才放行。确认失败后继续改进使用开发集；下一候选必须登记新的确认批次，不能反复在同一批种子上选赢家。

Windows 若不能可靠设置 RNG，记录为真实独立会话，随机化策略运行顺序；不能伪称与 harness 同种子配对。第二作按真实可控能力预注册种子或会话抽样方式。

### 4.4 统计与选模

1. 二元过关率报告成功数/总数和 Wilson 95% 区间；避免 0/5 得到 [0,0] 的退化百分位 bootstrap。
2. 方法比较至少 3 个独立训练种子，每个 checkpoint 至少 20 个开发 episode；明确训练种子、环境种子与派生轨迹的层级。正式候选 100 个确认 episode。
3. 同种子比较使用配对差与区间；跨训练种子用层级 bootstrap，先采训练运行，再采配对 episode。保留逐训练种子结果，不能把 300 局当作 300 个独立训练实验。
4. 确定性环境同一种子重复结果只用于复现，不增加独立样本量。多个中途起点若来自同一原轨迹，切分与统计都按共同祖先分组。
5. 不要求“两臂区间不重叠”才承认差异；直接估计事前定义的配对差区间。旧的 1,309 帧分辨极限只适用于当时协议，不能变成所有新实验的固定常量。
6. BC/DAgger 的 checkpoint 选择按开发过关率优先，其次冻结 cap 下的截断存活/进度指标，最后死亡与资源；按预注册顺序作字典序比较。严格像素更新的正式 run 使用预注册预算末 checkpoint，或只由像素反馈决定的冻结选择规则，不能按裁判成绩挑最好中间模型。感知、top-1、macro recall、KL 与熵只作诊断。
7. 候选评测次数设上限，预算阶梯的中途结果只作继续/止损判断；最终显著性来自事前冻结的确认分析。多任务比较指定一个主指标，其余探索性结果明确标注。
8. 运行缺失与错误独立列出。技术有效性门失败时不能作能力结论，也不能通过删失败局美化通过率。

## 6 工作包实施规格

### WP00 接管与证据恢复

**目标：** 确定当前机器实际拥有的资源，并让另一台机器或另一名代理能重算结论。

**允许修改：** v4.1.0 文档与证据、configs/v410/、touhou_rl/v410/evidence.py、tools/rl/v410.py 的 preflight/check/status 入口、tests/test_v410_evidence.py。不扫描整仓、不打开 sealed 资产、不安装系统软件。

执行顺序：

1. 记录主仓库与相关工作树的 commit、diff 摘要、未提交工作、Python、torch、CUDA、WSL 发行版和可用磁盘。先列明确目录，绕开 .pytest_cache。
2. 分别定位 Windows 检出、WSL 代码、研究引擎、零售原件、V400_DATA 与现有大产物。路径不能从旧文档直接假定；同一仓库的两份检出分别登记。
3. 核验 rl_v3 与零售件 SHA。恢复 D0、D1、m1、v3 三版、训练 metrics、split、逐局评测和日志。没有找到则逐对象写 missing，不创造占位 checkpoint 或补写成功日志。
4. 从现存账本、run 记录与文件系统计算已花资源及剩余预算；未知消耗与已知消耗分开，不能把未知当零。恢复不了时先估算下界，并采用保守试验额度。
5. 核对历史确认集曝光和数据谱系。已污染的模型只作诊断，不参与干净适应或最终确认。
6. 保存一份新证据索引，逐条给出 claim、范围、原始对象、文件 SHA、代码与协议身份。旧 G1 标为“不满足新确认协议”；旧 G0、G2 状态照实保留，不改历史报告。
7. 实现轻量状态与证据检查器。每个实验的命令、退出码、原始统计与产物身份都可由它校验。

**验收：** 每个必需资产都有 verified/missing/invalid 三选一结果；最少一条已有结论能由其原始记录重新汇总。恢复失败时不伪称资产门通过，但可在新目录重建依赖较少的最小实验。

**替代路径：** 原数据缺失先核对 Windows 与 WSL 两个已知根，再核对清单和版本记录；仍缺时，用已核验合法资源重新采 Stage 1 小切片，不为恢复一份旧大实验阻塞全部新工作。只有需用户提供资源、授权或重启时才请求协助。

### WP01 协议和运行一致性

**目标：** 同一输入、时间和模型在采集、训练、harness 与 Windows 中有一致含义。

**允许修改：** touhou_rl/v410/protocol.py、bench/、adapters/、tools/rl/v410.py、configs/v410/protocol.json、tests/test_v410_protocol.py 与 test_v410_runtime.py。默认不改引擎。

必做检查：

- 同一帧数据通过数据加载器与在线适配器，uint8 平面逐字节相同；归一化后张量最大误差不超过 1e-6。
- 同 checkpoint 同设备，离线和在线前向 logits 在 CPU 误差不超过 1e-5、GPU 不超过 1e-4；记录库版本和非确定算子。argmax 在非并列样本一致，近似并列按预定容差另报。
- CPU、GPU 均执行一次真实 batch=1 与 batch>1 检查；输入、权重、RNN 状态都在正确设备。新接口不再以“只用 CPU”长期掩盖设备错误。
- 明确 2 帧策略槽与旧 4 帧采集块；以逐帧掩码、位置、HASH 与渲染索引证明动作提交和标签时刻。若使用教师宏动作，记录整个未来计划，训练标签只对应当前可执行动作。
- 动作历史从实际输入重建；教师纠正后写实际执行动作；中途接管与 RNN burn-in 不能无理由清空，换面清空规则必须与部署一致。
- STATE/共享内存新鲜度、初始化帧、death/bomb/过面帧、暂停与菜单状态分列。不能把菜单静止帧计作存活。
- 随机、静止、固定横移/摆动等非学习基线在同一协议下运行；旧 m1 和 v3 可加载时在新尺上重测，旧数字不直接搬入新表。
- 验证标准资源、路线与训练用练习资源；实现整局、首死诊断和逐面练习三种明确终止类型。
- 添加信息边界测试：伪造不同裁判状态但保持像素和自身历史相同，策略输出与严格训练反馈应保持相同；测试覆盖奖励、done、reset 和样本选择。

**验收：** 真实引擎完成至少 3 个训练种子 × 3 次重开 × 1,000 帧的一致性切片；一次至少 30 分钟的小规模运行无未解释 stale/错帧；所有新增协议测试通过。性能记录真实端到端决策/s及帧/s，不以动作重复增大刷吞吐。

**G410-0：** WP00 的必需资产、WP01 的一致性与评测分母全部满足。旧 G0.1 的 108 份零售验证继续完成并报告，不能用新小切片替代“108/108”；它可在后台收尾，不必阻塞不依赖其未覆盖范围的开发诊断。正式产品结论必须说明并关闭目标范围内的保真缺口。

### WP02 教师质量与标签可学习性

**目标：** 分清教师会玩、标签正确、学生能从像素学到这三件事。

**允许修改：** touhou_rl/v410/teacher_audit.py、labels/、configs/v410/teacher*.json、相关新测试和证据。旧教师及 obs-v3 保持原样。

1. 用同一构建、同一动作节拍分别评测 fast 与 v2h；先跑 Stage 1 的 20 个开发种子，再决定实际采集教师。快速教师须至少 18/20 过面，且不能通过“首死就停”或更宽 cap 获利。达不到时用完整教师，按真实吞吐重估预算。
2. 对所有 verified 计划核对 first_action、duration、died、frames_advanced、验证视界、trajectory_matches 与掩码。任何验证没跑满视界、发生不一致或缺 died 字段的计划都不能标成存活。
3. 新标签使用 query_status 与 survival_status；未知、已验证死亡、已验证存活分开。同一首动作的不同后续计划不能直接合并为“该动作必然安全”；它们只证明“存在这条后续计划在该视界内存活”。
4. 诊断集从至少 10 个独立训练轨迹取 1,000 个状态，覆盖低余量、并列动作、bomb、教师失败与面过渡。对其中 200 个状态补足全部 18 个首动作的匹配验证或记录不可行原因；不能用稀疏验证集合评价全部动作的真实安全率。
5. 保存 raw geometry scores、验证后 scores、折扣量、chosen_plan 与 tie-break；测熵、top1-top2、类别分布。延续 EXP-P3-004 发现，先排除“只是学到哪个动作被挑去验证”的伪目标。
6. 将教师默认 death-bomb 与禁用隐藏 PLAYER_HIT 触发的预防式 bomb 教师作开发对照。报告多少次生存依赖隐藏事件、学生可见先兆持续多久。保留教师性能更强的事实，同时检查是否适合视觉蒸馏。
7. 可使用“特权状态学生”作为诊断上限：相同标签和训练预算，输入真状态。如果它也学不好，优先查目标、采样与优化；如果它学好而像素学生失败，再查可观察性与表示。此模型绝不进入部署或迁移成绩。
8. 视界只是有限前瞻，搜索只是候选计划近似最优。瞄准弹会使旧 tape 依赖自机轨迹，几何近似必须由真实分支复核；不得称教师拥有“所有动作的精确最优答案”。

**G410-1 的教师腿：** Stage 1 最终教师在 100 个新确认种子上过关率至少 90%，无执行与验证不一致；报告 Wilson 区间。逐面扩展时 PSN 每面各 100 个确认种子，完整面死亡跨面均值不超过 0.5，且逐面结果必须全部列出。第一面数据生产只依赖第一面教师通过，不能因后面教师失败停止第一面学生开发；多面数据各自要求教师质量与失败分布可审计。

**止损与替代：** 教师因隐藏 death-bomb 强而视觉不可学，先改用更早的预防式资源策略；标签并列则使用等价计划集合和真实代价，不强迫学任意 top-1；动作/验证不一致则回 WP01，不继续大采集。教师后面仍弱时，利用人类起点补覆盖、单面修教师，并在学生成熟后考虑专家迭代。

### WP03 数据覆盖与标签生产

**目标：** 每个被训练和被验收的样本都有明确时间、真实观测、正确监督与独立谱系。

**允许修改：** touhou_rl/v410/data/、labels/、tools/rl/v410.py 的数据入口、数据配置、新测试与新数据目录。禁止覆盖 D0/D1、删除重复分片或更改旧 manifest。

先产出 D410-S1，再按需扩展 D410-MULTI。不要在学习链路尚未通过小规模验证前，先盲目补齐旧八面 200 万帧。

| 数据集 | 首轮要求 | 用途 |
|---|---|---|
| D410-DIAG | 至少 10 条独立轨迹、1,000 个分层状态、200 个完整候选验证状态 | 对齐、标签、可学习性诊断 |
| D410-S1 | 至少 50,000 个唯一决策点、20 个独立起始种子；每 2 帧可部署决策都有标签 | 第一面 BC 与感知预训练 |
| D410-MULTI | 总计至少 2,000,000 个真实提交游戏帧、八面各至少 150,000 帧 | 多面课程；以实际值核算 |
| D410-RECOVERY | 学生访问与死亡前状态，按祖先轨迹去重 | DAgger 与困难状态补充 |

Stage 1 总数据按原始轨迹组切为 train/val/test=70/15/15，训练种子固定；同时保证各类高危状态可评估。将同一完整轨迹裁成十片，不能算十个独立 episode。同 seed、不同面可作为不同任务轨迹，但同一 run 的派生片和重复输入序列不能跨切分。

每条样本至少记录：

- source_run_id、trajectory_parent、engine_sha、protocol_sha、obs_sha、teacher_config_sha。
- 绝对逻辑帧、像素帧、决策槽、实际输入、保持长度、过去动作、起点类型与接管 burn-in。
- 学生可见像素；辅助自机热图、致死物占用、未来 4/8/16 帧危险。未来危险的条件动作与生成方法必须登记，不能把依赖未来动作的图当作无条件事实。
- 原始计划、验证状态与结果、候选覆盖、bomb 决策及原因、各类目标的 available 标记。
- 完整轨迹掩码、事件、资源、终止类型、数据切分谱系；特权字段只给标签与裁判。

生成辅助标签后，抽至少 100 个分层真实样本做叠图，另外测批量几何与引擎事件一致性。标签准确性可与高分辨率像素感知能力分开验证，不能用“图上有亮点”替代致死物真值。

中途起点在 D410-MULTI 目标为关首 50%、真实轨迹中后段 30%、学生失败前状态 20%，按实际决策点计数，并记录与完整自然轨迹的覆盖关系。尚无学生轨迹时该 20% 记未满足，先用于 BC 的数据可明确命名为 bootstrap 子集；最终覆盖门不能默默降级。重放前缀不计新增数据量。

**G410-1 的数据腿：** 数据能够加载、SHA 全部匹配、HASH 对齐 100%、决策时间一致、祖先切分无泄漏、重复不计有效覆盖、阶段所需辅助标签可用；实际总量与起点分布达到对应数据集要求。Stage 1 与多面腿分别结算，不以 Stage 1 通过冒充多面完成。

**特别规则：** verified_mask=False 不等于死亡，True 也不自动等于存活；没有验证过的候选不能作为安全分类负例。辅助目标缺失时允许工程冒烟，但训练配置若要求 aux>0，正式训练入口应拒绝缺目标数据，不能静默置零。

### WP04 学习链路诊断与受控 BC

**目标：** 在固定的第一面任务上辨别“学不进、看不清、选错模型、离线到闭环偏移”。

**允许修改：** touhou_rl/v410/student/、diagnostics/、configs/v410/bc*.json、相关测试与实验。先复用现有空间模型，默认不造 Transformer、世界模型或新的大训练框架。

先做四项短诊断：

1. **小集合拟合。** 固定 128–512 个具有清楚教师偏好的样本，关闭增强，确认损失下降、梯度非零、目标与动作索引一致；清楚偏好样本训练集动作一致率达到 95%。不能拟合时先查代码和标签，不采更多数据。并列动作以集合一致率评价。
2. **输入敏感性。** 同一状态换图、遮挡自机附近、平移弹幕、打乱动作历史；观察 logits 与关键动作变化，并与相同历史但不同危险方向的成对样本比较。该诊断不单独证明控制能力。
3. **相同轨迹离线与在线回放。** 同一帧、同一历史应给出相同输出；找第一处动作差异及其原因，保存失败前 180 帧。
4. **标签信号审计。** 先比较 raw、折扣后、教师 chosen 与真实验证集合；诊断 KL 的熵和梯度是否主要来自任意验证折扣。不能看到塌缩就直接调温度。

随后只在 D410-S1 上做第一组受控实验：

| 臂 | 模型 | 感知辅助 |
|---|---|---|
| B0 | 约 0.4M–0.8M 参数，保留空间 | 关闭 |
| B1 | 同 B0 | 开启，权重 0.5 |
| B2 | 现有约 2.6M 空间模型的兼容适配 | 关闭 |
| B3 | 同 B2 | 开启，权重 0.5 |

每臂 3 个训练种子，同数据、同切分、同动作节拍、同有效样本曝光量。首轮统一 20 个有效 epoch，batch=128、AdamW lr=3e-4、weight_decay=1e-4、梯度裁剪 5。这些是事前起点，不能据此断言最佳超参。记录真实 samples_seen、更新步、样本/s、有效 epoch、训练/验证损失、梯度、类分布、实际 aux 权重及真实 GPU 占用。价值头若没有真实目标，默认关闭，另设受控诊断臂。

主要动作目标先采用通过 WP02 的配方；KL、教师 chosen 的 CE、集合目标作为后续独立对照，不能同时与分辨率、数据规模和模型容量一起变更。bomb 使用训练集统计的有限类别权重并记录，不能把“没有 bomb 也很高的准确率”当技能。

安全监督如采用集合损失，使用负 log 的已验证存活计划对应动作概率之和，且必须报告候选验证覆盖和集合大小。它只鼓励已知安全续行，不能假装学到了完整安全集合；对同首动作下存在不同未来计划的情况保留条件信息。

每臂按第 4 节规则选 checkpoint 并跑独立开发局。危险状态按原始几何余量和真实死亡距离分层；重点报告学生动作是否被实际验证、存活、未知，以及多解率。宏观指标包括过关、首死、到达 Boss、资源和动作持续形态。

**继续与止损：**

- 已能拟合且过关明显改善：选容量最小且开发成绩合格者进入 WP05。
- 输入弱、特权诊断学生好：依次试同模型下 96×112 与 192×224、灰度与 RGB；只改一项，先在危险状态切片验证。
- 位置或速度别名明显：增加局部高分辨率窗或 GRU。局部窗中心必须来自像素定位器；定位差时保留全局高分辨率方案。GRU 按完整序列训练、burn-in，不能拿独立帧假装训练记忆。
- 动作历史成为复制捷径：做历史关闭、dropout 与真实学生历史对照；引入变化时升级观测版本。
- 同数据同更新量下较大模型更好，允许继续大模型；较小模型更好才采用小模型。参数/样本数量比不构成结论。
- 20 epoch 后未收敛但曲线健康，允许预注册 40/80 epoch 阶梯；记录边际收益。禁止只按墙钟把预算翻十倍。

一次最多一组四臂或两个针对性替代实验。两组仍无可信信号时，完成因果诊断后换路线分支，不能无界网格搜索。

### WP05 在学生分布上做 DAgger

**目标：** 让学生在自己的错误与恢复状态上学习，形成 G410-2 候选。

**允许修改：** touhou_rl/v410/dagger/、学生训练适配、对应配置和测试。教师变更另开任务，不在同一 DAgger 比较里悄悄换老师。

每轮按以下顺序执行：

1. 测每秒真实标注决策数，区分环境、教师推演、像素、加载、训练和重开成本。首轮 50,000 决策用于证明流水线，之后默认每轮 250,000；8 小时内可完成且有收益时可升到 500,000。
2. 教师执行概率 beta 按轮次 1.0、0.5、0.25、0、0。每个状态都以实际执行历史构造学生输入。beta=1 的教师访问分布不能称作学生自主闭环。
3. 起点默认关首 50%、教师中后段 30%、上一轮学生失败前 5 秒 20%；重建状态与像素历史，核验 HASH。严格评测始终自然开局。
4. 聚合采样默认当前轮 50%、最近历史轮 30%、固定 BC 数据 20%；记录真实采样权重。危险状态可上调至普通状态的 5 倍以内，报告覆盖变化，不能把所有非 idle 状态一律当危险。
5. 保存学生提议、教师提议、实际执行、是否干预、资源与事件。教师用来纠正动作，不能把自己的状态或内部余量作为学生输入。
6. 每轮固定一个训练种子画开发曲线；第 3 轮与最终轮各做 3 个独立训练种子的确认性开发比较。最终至少两轮 beta=0，并有至少 50,000 个 beta=0 学生访问决策点。
7. 使用开发检查点选择策略；未过 G410-2 前不消耗正式确认集。选择最终候选后冻结所有身份再评一次。

**G410-2：** S1N 新确认集 100 局，过关点估计至少 50%，Wilson 95% 下界至少 35%；策略边界测试通过，日志为 deploy_pixel。Windows 腿由 WP07 完成：至少 20 局，点估计不低于 harness 的 70%，同时报告各自区间，不声称 20 局足以证明总体比例相等。

**止损：** 三轮后若仍零过关且截断存活相对受控 BC 的改善不足 30%，结束当前配方并复核失败状态；该条件只决定停止这个配方，不代表结束整个项目。优先执行 WP04 的表示/标签替代分支，并继续 WP06。若教师在学生恢复状态也无安全续行，应改恢复课程或教师，而非重复蒸馏无解状态。

### WP06 连续像素回报与终局

**目标：** 智能体在连续画面里可靠判断死亡、资源、过面、game over 与重开，不依赖裁判信号。

**允许修改：** touhou_rl/v410/reward/、session/、标签生成与回报评测配置、新测试。裁判真值只进入离线监督和审计。

1. 以原始完整客户区或框选区域保留 HUD，不以策略低分辨率输入限制回报检测器。先做可解释的 HUD 模板/数字/图标读数与时间状态机，再根据失败样本引入学习检测器。
2. 数据覆盖所有目标 Normal 关卡、资源增减、死亡与 death-bomb 两条消解路径、无 bomb 死亡、遮挡、慢速、Boss 转场、暂停、菜单及长时间无事件段。其他难度与机体作为明确的外部分布测试。
3. 训练、验证、确认按完整原轨迹及其祖先隔离。回放同一事件十次只增加复现检查，不能当十个独立事件。
4. 显式建立 alive、hit_pending、respawn、stage_transition、game_over、menu、unknown 的状态机或等价时序模型。未知读数不自动补成零，不能由引擎纠正。
5. 定义两种过面时间：像素可见过渡起点与引擎正式过面；分别记录，学习事件检测按事前冻结的可见语义计分，另报告相对正式边沿的提前量。不得通过改引擎语义让旧指标通过。
6. 默认新事件门按完整连续流计分：每种事件 recall 和 precision 的 Wilson 95% 下界均至少 99%，正事件与预测事件各至少 400；同时按原轨迹聚类给区间。事件若高度聚类，以聚类区间为主要判据，400 只是最低计数。
7. 新死亡延迟门：相对首次可见证据的识别延迟 P95 不超过 10 帧；相对引擎死亡的延迟 P95 不超过 30 帧、最大不超过 60 帧。全部真实死亡都计入端到端事件召回，包括末命死亡；不可见样本单列分析，不能从总分母删除。
8. 新延迟门与旧 G2 的“引擎边沿后 10 帧”不同，名称明确为 G410-3，旧 G2 仍照原协议结算。新的可见锚点须在开发阶段由独立标注冻结，并在未用确认流检验。
9. 资源读数准确率至少 99.5%，并按轨迹/片段报告，不能以十万相邻静止帧抬置信度。score 的增量测试包含真实变化，负向未出现时写不可测，不冒充三分类全对。
10. 每个目标分布至少做 10 小时等效游戏时间的无事件/长生存连续测试，事件误报不超过 1 次/游戏小时。分别报告背景段误报、unknown 占比、资源不一致和整局累计回报误差。
11. 做至少 100 次由像素终局驱动的菜单与重开闭环，至少 99 次自动成功；失败录屏与超时齐全。纯像素训练只能用此终止/重开路径或事前固定截断。

**G410-3：** 上述事件、资源、延迟、长流误报、像素终局与重开全部满足；运行时禁止读取真值回报与真值 done。冻结检测器和状态机版本，在独立连续流确认后才允许 WP09 的严格像素臂。

**替代路径：** HUD 读数可靠则优先用资源变化与时序融合；机体消失难辨则加像素定位与局部窗；全局 CNN 失败不等于像素事件不可识别。确实不可观察的事件要提供成对画面证据和可观察的延后结果，重审任务定义；不能靠宽松匹配窗或增加重复事件数过门。

### WP07 Windows 真实部署复验

**目标：** 证明模型在无栅栏、真实 60 Hz 的零售游戏里仍然有效。

**允许修改：** touhou_rl/v410/deploy/、session/、对应 CLI、Windows 配置和新测试。不注入、不写游戏进程内存，不替换默认模型。

尽早做一次随机/冻结模型的采集和发键冒烟；正式成绩依赖 G410-2 的 harness 子门通过与学生候选冻结，WP07 的真实结果再补齐 G410-2，避免循环依赖。画面用 GDI 或已获授权的现有抓图后端，GPU 推理，SendInput 发键；记录每次抓图、推理、排队、发键、生效的时间戳与实际帧间隔。仅用已有工具，不新增需要管理员权限的后端。

部署适配使用与训练相同的归一化和空间裁剪。fps 文本、平台叠层与调试信息不得成为策略捷径；以已有配对差与真实延迟确定增强强度，不使用任意重噪声。训练延迟增强只使用实测分布，保持动作生效语义。

在目标决策周期为 2 帧时，端到端控制预算为约 33.3 ms：报告 batch=1 的 P50/P95/P99、错过预算比例、实际动作保持长度和重复截图比例。默认 P95 不超过 33.3 ms、错过预算比例不超过 1%；未达时先查 CPU/GPU、读回、队列和推理，不通过减慢决策周期掩盖问题。

窗口不在前台或发键权限失败时应停止该会话并记录，不能声称按键成功。失败会话保留分母与原因；仅在事前定义的环境故障规则下作无效批次处理，不根据胜负选择重跑。

**验收：** WP05 第一面候选至少 20 个真实独立会话；点估计保留 harness 的至少 70%。WP08 完成后，同一要求用于 REAL-RUNN。报告模型身份、零售件身份、会话条件、截图与按键日志；裁判内存只写日志。

### WP08 多面课程与完整一周目

**目标：** 将一个会第一面的像素学生扩展为同一模型自然连续通关的策略。

**允许修改：** touhou_rl/v410/curriculum/、训练与评测适配、预注册多面配置、新测试与产物。默认不改游戏逻辑。

1. 第一面通过后，按单面教师与学生失败分布扩展课程。先补当前学生最早失败的下一面和 Boss，再逐步加入后面；每次保留至少 20% 已掌握任务样本，监控遗忘。
2. 多面共享模型为产品主线。分面模型可定位冲突，最终不得使用引擎 stage_id 选择专家。若采用像素识别阶段或混合专家，选择器也必须只看像素，包含误判成本。
3. D410-MULTI 的实际覆盖与困难状态比例通过后再扩大训练。教师失败前的全部动作不能一律丢弃；使用真实验证质量、动作裕量与结局信息分层，避免只保留容易成功轨迹。
4. 针对 boss 超时、瞄准位置、道中清敌、资源收集、bomb 时机和换面状态分别做失败分类。生存教师若不打 Boss，增加由引擎提供的训练标签/搜索目标可以，但产品策略输入不增加特权字段。
5. 练习起点只用于训练；必须增加自然连续轨迹，以覆盖残机、bomb、power、rank、路线条件和跨面记忆。不能把练习资源条件下的逐面成功等同连续一周目。
6. 先在开发集连续运行，冻结机体、路线、结局定义、时间上限与检测器。关卡之间不 RESET，不切换 checkpoint，不注入资源。菜单与路线选择也纳入像素控制或事前固定、通用的输入协议。
7. 某些后面教师不足时允许专家迭代：学生建议动作/价值用于搜索，真实引擎验证改善；新教师、新学生各做独立对照。搜索增强只能计为 TH08 训练手段，不计作零特权自我改进。

**G410-5：** 同一像素 checkpoint 在 100 个新 RUNN 确认 episode 上有效结局率点估计至少 50%，Wilson 95% 下界至少 35%；无续关、无跨面补资源；20 个 REAL-RUNN 会话点估计保留至少 70%。各面的到达率、死亡和资源同时报告，不能只报最好的一面或最成功的视频。

若达到第一面门但完整一周目失败，明确写“L1a 已成立、L1b 未成立”，继续执行最早失败处的课程与恢复任务。

### WP09 严格像素回报自我改进

**目标：** 在不向优化器提供任何新特权反馈的条件下，继续训练并提高真实游戏结果。

**允许修改：** touhou_rl/v410/rl/、reward/、对应实验配置与测试。优先复用 PPO 数值实现和 checkpoint 初始化，不盲目迁移到另一个算法库。

**先做算法与数据检查：**

- 用同一冻结 BC checkpoint 初始化 actor，核对首次更新前输出与 BC 一致。
- 解释 advantage、return、value、reward 的单位与尺度，验证动作 log_prob、双头联合概率、entropy、mask 和截断 bootstrap。
- 真实终止不 bootstrap，固定时间截断可按协议 bootstrap；RNN 状态按真实序列重建。不得将首次死亡误设为标准整局终止。
- critic 预热时冻结 actor，先验证目标可拟合；再用低学习率 actor 与冻结 BC 的 KL 约束起步。默认 actor lr=1e-4、critic lr=3e-4，clip=0.2、梯度裁剪 0.5；折扣时间单位明确写为 2 帧决策，不能从不同节拍直接搬数值。
- BC 回放辅助与 KL 系数先冻结，记录梯度贡献。发现策略立即塌缩先核对 PPO ratio、归一化、critic、reward 与 done，而非增加总帧数。
- 训练进度使用真实引擎游戏帧、策略决策、梯度步和墙钟四个口径。readback 重放帧、菜单帧、影子推演帧不算有效交互。

**主对照：**

| 臂 | 初始化 | actor 与 critic 输入 | 回报与训练终局 | 结论范围 |
|---|---|---|---|---|
| R0 | 冻结 BC/DAgger 候选 | 像素与自身历史 | 不更新，只评测 | 固定参照 |
| R1 | 同 R0 | 全部为像素与自身历史 | 像素事件、像素终局、像素重开 | 严格自我改进主臂 |
| R2 | 同 R0 | 与 R1 完全相同 | 引擎真值回报与相应终局 | 反馈通道诊断上限 |
| R3 | 随机初始化 | 同 R1 | 同 R1 | 从零参照，预算允许时执行 |

R1 与 R2 同优化器和更新预算，只比较反馈通道；因为终局也不同，结论明确为“像素反馈整体对照”，不能只归因于奖励数值。需要隔离奖励时另开固定截断、固定数据诊断。

特权 critic 可作额外诊断，但它不能进入 R1，也不与 R2 的主比较混合。它的作用是区分价值估计问题与像素 actor 可控性，不能替代严格像素臂。

R1 的环境不得把裁判 death、stage、game_over、真实残机、teacher margin、未来危险或快照起点回传给采样器、优化器与重开控制。对同一像素流伪造裁判状态，R1 的奖励、done、重开与梯度 batch 选择必须不变。优化过程也不能根据裁判反馈动态调整训练课程。

正式 R1 在预注册的预算末输出候选；期间裁判结果可封存供事后审计，但不能用于早停、扩大预算、超参修订、回滚或中间 checkpoint 挑选。GPU OOM、NaN、管道失效等工程故障可按冻结规则暂停恢复。诊断 run 若查看了裁判来选择修订，明确标为开发实验；正式自我改进必须用冻结后的学习程序与独立新批次验证。阶段性资源扩展只能依据事前规则和像素健康指标。

奖励先从过面/结局、死亡、资源和有限进度信号构成。开跑前用真实轨迹分解各项量级，保证拖延、原地刷时间、菜单静止、无限 bomb、反复触发面板都不能获得高于真实过关的目标回报。生存常数与 bomb 惩罚只在开发轨迹校准；稀疏奖励可保留，但不把“奖励越密越好”当原则。

每臂至少 3 个训练种子；阶梯为每 run 1M、5M、20M 有效游戏帧，全部臂采用相同帧预算与评测节奏。进入下一档前核算剩余预算和健康指标。没有信号时允许一次预注册的学习率、KL 与 critic 预热修订；仍无信号则转问题诊断，不自动跑满 50M。

目标任务在正式 RL 前冻结：选择已经有控制能力、又未饱和的开发任务，基础过关率建议位于 20%–80%。若 S1N 已接近满分，改用预注册的后续关卡或更难设置，不能事后挑最有提升的任务。

**G410-4：** 100 个新确认 episode、至少 3 个训练种子，R1 相对 R0 的过关率提高至少 15 个百分点，层级配对差 95% 下界大于零；R2 有正提升时，R1 提升至少达到 R2 的 70%。R2 无正提升时第二条不作除零或负比值，先报告算法诊断，R1 仍须满足自身硬门。报告所有种子及资源。

奖励一致性不能只看符号，因为大量零回报会掩盖错误。必须另报事件级漏/误报、非零回报时刻、延迟、整局累计误差和 reward hacking 轨迹。

### WP10 干净留出适应

**目标：** 证明预训练改善有限交互的学习效率。

**允许修改：** touhou_rl/v410/adapt/、渲染适配的独立研究开关、留出配置、新测试与训练产物。不触碰 sealed 资产。

机体、关卡、难度、视觉风格是四个候选家族。至少两个家族用于正式门。进入前由数据谱系核查确定哪些真正干净：曾用于策略、感知或回报检测预训练、教师训练数据、候选挑选、超参选择的目标样本，都必须登记。

全八面预训练的学生不能用于“新关卡留出”结论；重训一个只见允许关卡的完整系统，包括对应感知与回报模型。目标回报模型若接受过目标游戏/任务标注，就属于有监督协助，单独开臂。

| 臂 | 做法 |
|---|---|
| Z | 冻结预训练模型，零样本评测 |
| A | 从预训练模型开始，仅用目标像素反馈适应 |
| S | 随机初始化，同样的目标交互与训练资源 |
| A-ad | 只更新适配器或末层，作为受限适应对照 |

默认预算档 1M、5M、20M 有效目标游戏帧，至少 3 个训练种子；有条件先以 1M 档验证经济性。适应期间不使用教师、引擎状态、目标人工逐弹标签或引擎 done。每 10% 预算按冻结协议评测，评测交互单独记账，不能藏在训练预算外无限试。

AULC 按实际累计交互帧积分，并同时换算实时游戏小时；比较 A 与 S 的配对差，报告负迁移。视觉随机化只改渲染，需验证游戏逻辑轨迹不变；TH08 视觉变化只能支持该留出家族，不能替代第二作。

各预算档使用固定时点 checkpoint；裁判评测只用于事后曲线和门结算。评测轨迹、奖励真值与任务种子不得进入适应训练数据、早停和超参选择。若人工看到结果后改了适应算法，该批次转为开发，正式留出结论需换未暴露任务/批次；所有此类试验成本继续计入账本。

**G410-6：** 至少两个事前冻结的干净留出家族中，A 的 AULC 相对 S 的层级差 95% 下界大于零；固定预算最终成绩不能靠曲线早期偶然收益掩盖明显退化。最后一项具体非劣容差在开发适应前冻结，默认过关率不低于 S 超过 5 个百分点，并报告差的区间。目标家族用 Holm 校正控制预注册多重比较。

无法证明目标系统未受污染时，先重训干净模型，不补写“零样本/留出”标签。三种子区间过宽时结论为证据不足；是否增加种子由剩余预算与预注册功效分析决定。

### WP11 第二作与严格迁移

**目标：** 在一部新的东方作品上，仅给框选画面和通用按键接口，完成适应与标准资源通关。

**允许修改：** touhou_rl/v410/transfer/、通用像素区域/菜单适配、第二作协议、新测试和新证据。合法资源、目标作品、系统安装等外部前提由用户确认；不自行下载版权游戏数据。

提前只读核查 TH06/TH07 的合法资源与加速能力，不把公开重建的存在当作当前机器可用事实。无加速环境时走真实 Windows；1M 帧约 4.63 小时纯游戏时间，5M 约 23.15 小时，20M 约 92.59 小时，另外计算菜单、重开、推理和评测开销。预算不足时报告具体成本，不假装能完成既定规模。

框选必须包含玩法区域和必要 HUD。TH08 固定 playfield/HUD 坐标是训练脚手架，严格模式不得要求用户再标注第二作 HUD、自机或弹幕。采用框内归一化全图与可由像素学习的区域定位；若继续使用多流裁剪，裁剪来源也要可迁移并实测。

两种模式分开：

- **STRICT。** 用户只提供合法游戏、外层框选与通用按键映射。目标策略、回报、终局、重开均由像素产生；不提供第二作人工 HUD、逐弹标注、内存标签、教师或快照。记录所有人工介入。
- **ASSISTED。** 允许有限人工 HUD/事件标注或模板配置，记录分钟数、标注数和操作。可以提供实用成果，但不能通过严格迁移门。

第二作引擎若可用，只用于加速、输入和隔离裁判；不能向 STRICT 学习系统反馈内部事件。若第一阶段严格检测器不能得到可靠目标回报，先在像素时序、可观察资源与通用视觉表征上改进；ASSISTED 同时保留独立结果，不能将其隐去成本后归入 STRICT。

预注册 Z/A/S/A-ad、目标资源、路线、完整结局、训练与评测预算；先做真实小时经济性 spike，再按 WP10 的同预算方式评适应。第二作没有可控种子时以预注册独立会话抽样，不能套用 TH08 种子并伪称独立随机世界。

**G410-7：** STRICT 模式满足目标连续回报/终局门，至少一个新作品上适应 AULC 优于从零且差的 95% 下界大于零；同一最终像素模型在事前冻结的 Normal 一周目 100 个独立确认局上结局率至少 50%、Wilson 下界至少 35%。若使用加速环境，还需至少 20 个真实零售会话保留其 70% 点估计。人工介入只有外层框选和预注册通用设置，不包含目标标注。

若严格迁移失败，具体报告失败在定位、回报、探索、重开、控制还是预算，保留负结果。资源未到位时 WP11 为外部阻塞，继续其他未完成工作；所有其他工作完成后再向用户提出最小资源请求。

## 8 实验与证据规范

每个实验只维护一张卡片和一个不可覆盖的 run 目录。卡片约一页，超出的原始数字保存在机器文件中，不复制成多个相互冲突的快照。

~~~text
Document/Update/Alpha/v4.1.0/
  README.md
  state.json                         后续实施代理创建
  journal.jsonl                      追加状态变更
  budget.jsonl                       追加资源账目
  experiments/EXP-410-WPxx-nnn.md
  gates/G410-n.md
  evidence/<run_id>/
    manifest.json
    protocol.json
    commands.jsonl
    episode-results.jsonl
    metrics.json
    verdict.json

V410_DATA/
  datasets/<dataset_id>/
  runs/<run_id>/
  checkpoints/<sha256>/
  traces/<run_id>/
~~~

字段约定：

- commands.jsonl：原始 argv、cwd、允许公开的环境设置、开始/结束 UTC 与本地时区、真实退出码、stdout/stderr 路径和 SHA、超时/中断标记。不得记录密钥。
- episode-results.jsonl：run_id、训练种子、环境种子/会话、套件、起点、资源、所有身份哈希、privilege、frames、deaths、bombs、score、clear、ending、end_reason、exit、invalid_reason。
- metrics.json：由原始行生成的分子、分母、置信区间、缺失和失败数、数据切分与实际样本曝光；不只保留百分数。
- manifest.json：每件产物的用途、路径、大小、SHA、是否必需、是否存在、原始/派生、可再生方法、来源和保留策略。路径本身不代表内容可用。
- verdict.json：每条门的 expected、observed、evidence_refs、status 与原因，由检查器计算；缺字段、缺原始输入、不匹配或含未知依赖时不能返回通过。

小型核心证据保存到版本目录：逐局记录、关键训练曲线、配置、哈希、失败摘要和可重算统计。大像素与权重保存在明确的持久目录，写恢复说明。不要把唯一证据留在按 .gitignore 可随时清理的 .tmp_*。

checkpoint 除模型权重外还保存 optimizer、scheduler、RNG、训练步、数据游标/采样配置、观测/动作/奖励版本与数据身份。恢复一次后，用短片段证明没有重置训练进度或跨 split；不能只加载权重就声称无缝恢复原 run。

预注册必须包含：假设、主指标、样本量与训练种子、候选次数、阈值、预算、停止条件、随机化、统计方法和允许的替代分支。先冻结 SHA，再开始有结果的运行。实验无效、有效负结果和有效正结果分别记录。

## 10 失败后的决策表

| 现象 | 先核对什么 | 自动允许的下一步 | 不允许的结论或动作 |
|---|---|---|---|
| 多个种子完全相同地早死 | 实际动作 trace、观测变化、输入历史、按键与节拍 | 重放首个偏离状态；小集合拟合；修对应链路 | 直接认定模型容量过大或样本太多 |
| top-1 高而闭环差 | 多数类基线、并列动作、验证折扣、安全样本与选模 | 改受控目标；按开发游戏成绩选择 | 用更高准确率宣布会玩 |
| 教师能过关而学生不行 | 隐藏 PLAYER_HIT、teacher plan 条件、可见先兆 | 预防式教师、观测/记忆对照、DAgger | 强制蒸馏每个隐藏反射动作 |
| 验证掩码看似安全却仍死亡 | died 字段、验证视界、未查询候选、后续计划 | 四类语义审计；真实分支复核 | 把 verified=True 当作存活 |
| 更大数据效果更差 | 相同曝光、阶段比例、独立轨迹、优化进度 | 同数据对照容量；同模型对照数据 | 删掉所有最终死亡轨迹 |
| 96×112 感知弱 | 标签可见性、聚合、像素定位与误差尾部 | 半分辨率/RGB/局部窗的单项实验 | 根据 F1<0.90 直接断言视觉控制不可能 |
| 三轮 DAgger 无改善 | beta=0 的真实数据、教师恢复质量、数据混合 | 换标签/观测分支，必要时修教师 | 只重复采相同种子或宣布总目标结束 |
| 回报离线好、在线差 | 锚点、阈值冻结、长流、负样本、状态机 | 修连续事件语义、补真实分布 | 裁掉提前检测段，扩大窗口后称旧门通过 |
| PPO 很快破坏 BC | log_prob、done、reward 尺度、critic、KL | 预热 critic、低 actor lr、一次预注册修订 | 直接跑满大预算等待“自己恢复” |
| harness 好、Windows 差 | 延迟、发键、抓旧图、fps 捷径、归一化 | 实测延迟增强、设备/采集修复 | 更换零售件或改动作周期隐藏问题 |
| 逐面都行、一周目不行 | 资源、rank、换面记忆、路线与自然状态分布 | 增加自然连续课程和资源策略 | 换面补资源或拼接独立练习成绩 |
| 留出适应没收益 | 谱系污染、反馈质量、目标预算与初始化 | 干净重训、适配器与负迁移对照 | 事后挑家族，只报获益项 |
| 第二作 HUD 失败 | 框选是否完整、布局泛化、像素终局 | STRICT 改进；ASSISTED 独立记账 | 把人工 HUD 配置隐藏成只给一个框 |
| 某个资源/权限缺失 | 精确路径、权限、已尝试命令与退出码 | 缩小真实切片、换验证路径、推进其他 WP | 用合成数据替代真实门或反复无界重试 |

出现新问题时也按相同原则：先保留复现，再分清代码、协议、数据、模型、环境与科学假设。一个具体配方失败不等于整条路线被否定；同样，换一个算法名也不能自动解除旧问题。

## 11 预算与经济性

预算必须在 WP00 由实际剩余资源确定。旧 D-05 的 400 GPU 小时、300 GB 新增磁盘不能自动变成“再获得一份新预算”。v4.1.0 首轮规划资源上限建议为 **min(160 GPU 小时，历史已授权剩余额度)**；新增磁盘建议不超过 **min(150 GB，历史已授权剩余新增容量)**。这些是计划额度，不是本次开始消耗的授权。

GPU 同时记录实际活动时间与分配占用墙钟，避免等待环境的 GPU 空闲被隐藏。CPU 采集小时、真实交互小时、墙钟、磁盘峰值、持久证据大小分别记账。

| 方向 | 首轮 GPU 小时分配建议 | 进入更大规模前应回答的问题 |
|---|---:|---|
| 协议、证据、标签与学习短诊断 | 8 | 能否可信地测量、拟合和复现 |
| 第一面受控 BC | 12 | 哪个因素提供闭环收益 |
| DAgger 与恢复课程 | 24 | 学生分布覆盖是否改善 |
| 连续像素回报 | 16 | 连续流中的事件和终局是否可靠 |
| 多面与一周目 | 32 | 是否跨面遗忘，资源与课程是否有效 |
| 像素 RL | 40 | 1M/5M 档是否出现有效信号 |
| 留出与第二作初步适应 | 16 | 严格适应和实际小时成本是否可接受 |
| 诊断预留 | 12 | 是否仍有可验证的替代路径 |
| 合计 | 160 | 超出不自动扩额 |

这不是完成所有研究目标的工期保证。第二作实时通路、多训练种子和长确认运行可能超过首轮额度；若触及预算，保存已完成证据、具体剩余工作和继续所需最小资源，不能以“计划跑完”代替能力完成。

每次扩大 run 前估算：

~~~text
交互墙钟 = 所有训练臂有效游戏帧 / 实测总采样帧率
教师标注墙钟 = 决策数 / 实测标注决策率
更新墙钟 = 优化步数 / 实测更新步率
总预算还应加：验证、启动/重开、重放前缀、确认评测与失败裕量
像素磁盘 = 实测每决策字节 × 有效决策数
~~~

同一机器共享资源不能把每个进程的 FPS 相加后忽略并发争用；以整批墙钟验证预测。D1 约 27 GB 的历史数字只作估算起点，不代表新辅助标签、原始 RGB 或序列模型占用相同。

并发默认最多 3 个执行代理，最多 1 个重 GPU 训练；引擎先 2–4 实例 spike，再依据全机负载扩到不超过 16。主环境、影子、验证 fork 和残留进程都计入实际资源；不能每个代理各自使用 16 个。至少留出 4 个逻辑核，设置 NUMBA_NUM_THREADS=1、OMP_NUM_THREADS=1，软件渲染线程按实测配置。

WSL 热数据优先放 ext4，不能盲目复用 /mnt/d 大数据加载布局。训练器避免每个 batch 重新拼接全量标签；通过实际 profile 决定缓存、mmap 与预取。只有性能阻碍当前能力实验时才优化，不重新追逐旧 2,000 FPS 阈值作为所有学习的前置条件；吞吐未达事实仍如实保留。

达到资源上限的 80% 时停止新增长实验，结算并向用户请求明确扩额或缩小范围；现有已授权短任务可安全收尾。没有回答不代表预算授权。证据和 checkpoint 不因预算紧张被自行删除。

## 12 持续推进规则

### 12.1 主代理职责与派发

遵守根 [AGENTS.md](../../../../AGENTS.md)。主代理规划、调度、审查范围、独立复算和处理阻塞；实际实现、测试、构建、采集和实验交给 Provider=DeepSeek、模型=DeepSeek v4.1 flash 的执行代理。不能在未说明的情况下换成其他模型。

本次属于纯规划，指定执行入口在当前会话不可用，因此只由主代理完成文档。后续执行环境若不提供指定 Provider，应记录能力限制；按根规则只做最小必要处置，或复用已配置的执行入口，不自行读取凭据、改 Provider 或安装外部平台。

建议分工：一名执行代理负责协议和证据，一名负责学习链路，一名负责像素回报。只在前提已满足时并行；同一个代码文件和同一个 GPU/引擎资源由唯一 owner 持有。主代理复核原始命令、真实退出码、统计分母、diff 和产物身份。

### 12.2 自动继续的状态机

收到用户“执行本规划”的任务后，按以下循环推进：

1. 读 state.json 和 journal 最后有效记录，对照当前仓库与资源；核对在运行进程，不能从旧状态直接重复启动。
2. 找出依赖满足的最小可验收切片。依赖按明确子门判断，例如 WP03.s1 可解锁第一面 BC，不要求 WP03.multi 也完成；WP05.harness 解锁 WP07，WP07.real 再补齐 G410-2。
3. 写预注册与资源预约；派发包含目标、文件白名单、禁止事项、验收命令和立即返回要求的短任务。
4. 执行后立即核查命令、退出码、文件、统计和范围。失败切片进入第 10 节决策表。
5. 更新状态、证据、资源与 next_actions。通过普通技术门后自动执行下一个已授权切片；不以“是否继续”代替推进。
6. 有效负结果停止当前配方，自动转到事前允许的替代分支，并继续其他独立 WP。没有新证据，不重复同命令期待不同结果。
7. 同一具体阻塞连续至少三轮、已尝试多个合理路径且无其他可推进依赖时，登记 blocked，说明最小解阻动作。不得无限调度同一失败任务。
8. 只有 G410-0 至 G410-7 全部真实通过才把 project_objective 标为 complete。预算不足记 budget_limited，外部资源缺失记 blocked；二者都不是能力完成。

v4.1.0 采用上述技术门自动推进规则；v4.0.0 D-09 的“每个门通过后都停下来问”不作为新版默认流程。需要新增外部授权、资源、产品范围或改变事前门阈值时，仍保留用户决策。该规则从用户明确派发执行本规划时生效，本次不据此启动工作。

### 12.3 监控与恢复

- 每个长任务在 60 秒内产生可读心跳：run_id、当前阶段、完成量、速度、最近有效日志、资源和预计下次检查。主代理对用户的进展更新重点说明新证据和下一动作，不重复无变化状态。
- 工具等待采用不超过 60 秒的有界检查；长训练本身可后台继续，不以持续占用一个阻塞调用作为监控。
- 每个进程记录 host、Linux/Windows PID、创建时间、命令身份和 owner；Windows wsl.exe PID 不当作 Linux 引擎 PID。只回收本任务确认拥有的失效进程，不杀用户其他会话。
- 子代理长时间无心跳先判断工具是否仍有进展；确实无响应时中断一次、等清理，缩小范围再派。不要反复 send_message/interrupt 把槽位卡住。
- 遇 ACTIVATION_LIMIT_REACHED 按根规则处理，优先复用已驻留代理；池满不修改 Provider。当前环境真实并发上限优先于文档建议。
- 保存 checkpoint、采样 cursor、run 配置与状态后再换切片。训练恢复身份不匹配时新建 fork run_id，不能覆盖原 run 或拼接不同配置曲线。
- 只有数据、checkpoint 和小证据都完成持久化后，才讨论缓存清理；删除和覆盖仍遵守用户授权。

### 12.4 需要用户参与的情形

只就确实需要用户动作的事项提问：合法游戏资源、系统安装/重启/提权、预算扩额、删除或覆盖、公开发布、默认模型替换，以及无法从目标推断的产品取舍。

## 16 方法依据与研究限制

- [DAgger 原论文](https://proceedings.mlr.press/v15/ross11a.html)支持通过迭代收集策略实际访问分布上的专家监督来处理模仿偏移；其保证有相应学习与归约假设，不能替代本项目的闭环实验。
- [Asymmetric Actor Critic](https://arxiv.org/abs/1710.06542)提供训练期全状态 critic、部署期图像 actor 的先例。本规划只把它用于特权诊断或 TH08 训练辅助，不把含特权 critic 的新任务更新称作严格像素适应。
- [Implementation Matters](https://arxiv.org/abs/2005.12729)显示 PPO/TRPO 的实现细节足以显著影响行为，因此在改变算法前检查初始化、归一化、价值学习与更新过程。
- [Statistical Precipice](https://arxiv.org/abs/2108.13264)强调有限训练运行的不确定性；本规划因此保留多训练种子、区间和层级，而非只比较单个最好 checkpoint。

以上论文只支持方法选择与实验设计，不证明东方像素通关、跨作品回报识别或自我适应必然成功。v4.1.0 的价值在于把这些假设变成可推进、可否证、可恢复的实验链，并把真正会留下来的像素能力逐项做出来。
