# WP05.11 — β=0.5 DAgger 数据与 20k 学生的 idle / 动作分布诊断（只读）

> **一句话**：20,000 步学生在 20 dev 局的 idle 占比 **60.87 %**，与它的训练标签先验 **61.72 %**（DAgger 66.16 % 与 S1 43.96 % 的 0.8/0.2 混合）（dev − 先验 = **-0.84 pp**）——学生并没有「把非 idle 学成 idle」，它复现的就是标签先验。而先验本身是**标签工件**：教师 18 路几何分在 **44.58 %** 的决策上完全打平，「取第一个最大值」永远先遇到候选 0（idle），于是 **67.38 %** 的 idle 标签来自完全打平行；同样的分数向量换成随机 tie-break，idle 只会是 **4.67 %**。全 52,500 个决策里，**idle 从未是唯一最优动作**。

> **边界**：这是 WP05.11 的**只读分布诊断**，**不是 G410-2**，不设门、不是过关率、不是 development score；没有训练、没有采数据、没有新 DAgger 轮、没有改任何 shard、没有动 confirm 种子。dev 只用 seeds 1000-1019。

**动作空间**：`cand = focus*9 + move`，move 0..8 = idle/N/NE/E/SE/S/SW/W/NW，`cand ≥ 9` 为按住 focus；射击恒开、无炸弹。**idle = cand 0（完全不按方向）**，`cand 9` 是 focus-idle（按住 focus 但不按方向），两者从不合并。

**标签语义（本次实测确认，不是假设）**：

- `chosen == chosen_plan.first_action == teacher_cand` 在 **52,500/52,500** 行成立：**BC 目标永远是教师动作**，β 只决定「执行谁」，不决定「标谁」。
- `executed_cand` = injected 时取 teacher（26,295 行），否则取 student（26,205 行），逐行验证一致。
- `raw_geo_score` 是**打完折**的数组：17 个未验证候选每个已扣 `unverified_discount = 5.0`，所以 `true[i] = raw[i] + 5.0·(i ≠ chosen)`。这是仓库自己文档化的约定（`v410/teacher_audit.py` 的 `top1_top2_gap_is_dominated_by_unverified_discount`、`v410/student/diagnostics.py` 的 note）。本诊断 §7 全部建立在把折扣加回去之上。

## 6. 诊断：三个候选原因逐条回答

### 6.1 是教师数据本身 idle 高，还是学生把非 idle 学成 idle？

**两者都有，但权重完全不同。**教师标签本身 **66.16 %** idle；采集学生 73.69 %（**+7.53 pp**）。拆开看：

- 学生 idle 的 **87.06 %**（33,679 行）是教师也说要 idle 的；
- 只有 **5,006** 行（全样本 9.54 %）是「教师让动、学生不动」，即 P(student idle \| teacher 非 idle) = **28.17 %**；
- 反向几乎不存在：P(student 非 idle \| teacher idle) = 3.03 %。

所以「学生把非 idle 学成 idle」只解释 5,006 行；**主因是教师标签本身就 66.16 % idle**。而教师为什么这么 idle，见 §7：44.58 % 的行上 18 路几何分完全打平，argmax 取第一个 → 候选 0。

### 6.2 哪些方向类教师里存在、学生几乎不输出？

**20k 学生（dev）没有任何一类是字面 0 recall**，唯一 0 输出的 `focus-idle`(9) 在教师里也是 0 行。真正接近 0 的是竖直/斜向类：

| 动作 | dev/先验 | dev 次数 | 教师标签数 |
|---|---|---|---|
| `focus-NW` | 0.14× | 5 | 82 |
| `NW` | 0.17× | 23 | 365 |
| `focus-S` | 0.20× | 4 | 56 |
| `focus-W` | 0.22× | 14 | 131 |
| `focus-N` | 0.30× | 6 | 40 |
| `S` | 0.32× | 53 | 473 |

采集学生（D1）这一侧则确实有 4 个类**逐行 0 recall**：`focus-N` 0/40、`focus-S` 0/56、`focus-W` 0/131、`focus-NW` 0/82，另有 `N` 3.90 %、`S` 1.90 %、`SE` 4.24 %、`NW` 4.38 % 几乎为 0。共同点是样本 ≤ 131 行且都要求 focus。

### 6.3 是否存在「贴边 / 固定方向」的短动作循环？

**有一个循环，但不是左右贴墙滑动，而是「idle 冻结」。**

- student 自转移 **90.43 %**，最长单一动作连跑 **1,334** decisions（= 2,668 帧，占一个 shard 的 38.11 %）；
- **31.89 %** 的 decisions 落在长度 ≥ 512 的 run 里，41.94 % 落在 ≥ 128 的 run 里；
- 这些长 run 里 **97.09 %** 是 idle（E 675、W 282 行）；
- 固定水平向连跑 ≥ 8 只覆盖 9.61 %，其中 ≥ 32 的只有 146 行；真周期循环覆盖 1.02 %（student）/ 1.79 %（executed）。

结论：**不是 ABAB 抖动、也不是沿墙左右滑，而是「停住不动」的吸引子。**而且停在原地时教师也同意 idle（run ≥ 512 桶里 teacher idle 98.41 %，完全打平 89.48 %）——数据因此不断确认这个冻结。

## 7. 根因：教师 18 路分数的 tie 结构

把 `unverified_discount = 5.0` 加回去，还原教师的真实分数向量后：

| 量 | 值 |
|---|---|
| 18 路分数**完全打平**（max−min < 1e-6）的行 | **23,404 = 44.58 %** |
| max−min < 0.01 / < 0.2 / < 1.0 | 44.81 % / 63.47 % / 88.83 % |
| top1 与次优**完全打平**的行 | **41,211 = 78.50 %** |
| 「取第一个最大值」重算能复现 `chosen` | **52,498 / 52,500 = 99.9962 %** |
| idle 标签总数 | 34,732 |
| 其中来自「完全打平」 | **23,404 = 67.38 %** |
| 其中 idle 是**唯一**最优 | **0** |
| 反例：idle 打平却不是 chosen | 1 行（6 位小数序列化舍入） |
| E 与 W 完全打平的行 / 其中 E 被选 / W 被选 | 24,205 / 6 / 0 |

**同样的 52,500 个分数向量，换 tie-break 规则的 idle 占比（离线重算，无引擎、无新数据、无训练）**

| tie-break 规则 | idle 占比 | 相对现状 |
|---|---|---|
| 现状：候选序号最小者胜（0 = idle） | **66.16 %** | — |
| 在最大值集合上均匀随机 | **4.67 %** | -61.49 pp |
| 最大值里取最小的非 idle | 0.00 % | -66.16 pp |
| 动作空间里删掉 idle | 0.00 % | -66.16 pp |

最大值集合大小分布（18 = 全打平）：1:11,289, 2:2,428, 3:1,352, 4:1,342, 5:771, 6:707, 7:238, 8:1,073, 9:4,110, 10:1,713, 11:82, 12:2,177, 13:83, 14:96, 15:1,266, 16:125, 17:244, 18:23,404

**这条是关键**：idle 从来不是「分数最高」，它只是「并列最高里序号最小」。现状 66.16 % 的 idle 与随机 tie-break 的 4.67 % 是同一批分数的两种读法——**标签分布由 tie-break 的写法决定，不由教师偏好决定**。反过来说，「把 tie-break 翻向移动」会得到 0.00 % idle，同样是工件；真正的修法是让分数有分辨力（更长 horizon / 危险度加权），而不是换一行 tie-break。

## 9. 建议（按性价比排序）

| 编号 | 优先级 | 动作 | 理由 | 代价 |
|---|---|---|---|---|
| R1 | P0 | 先在源头修标签分布，再花任何算力：给几何分去平局，或者有意识地选择 tie-break 规则（move-first、带种子随机、或 idle 最后才选），然后离线重算这 52,500 条标签。§7 的反事实表明同一批分数在三行不同规则下给出 66.16 % / 4.67 % / 0.00 % 三种 idle。 | 现在 66.16 % 的 idle 不是教师偏好，而是候选 0 赢下了每一次并列 | 只做离线重算，不需要引擎 |

## 10. 限制

- 五个 β=0.5 臂共用同一个采集 checkpoint，所以 shard 统计里的 student 是采集学生 D1，永远不会是 20k 臂
- labels.jsonl 只对 chosen 一个候选做了验证，所以「被并列的那个方向同样安全」无法用这份数据核对
- 位置通道是几何 rollout 的 end_xy（模型误差 ≤ 4 px，抽样行 trajectory_matches = false），不是引擎里的玩家坐标
- run/循环分析用的是 15 个 shard 的序列（52,500 决策）；dev 局只存直方图
- DAgger 状态先验（66.16 %）和 S1 状态先验（43.96 %）的对比把「状态分布」和「产生它的 rollout 策略」混在一起——这是描述性的，不是受控 A/B
