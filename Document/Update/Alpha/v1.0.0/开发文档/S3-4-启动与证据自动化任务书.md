# S3-4 启动与证据自动化任务书

- 所属 Stage：Stage 3（开发）
- SubStage：S3-4
- 依赖前置：S3-3 完成（`build/play` 已装配）且 S3-1/S3-2 的函数与产物可用
- 并行状态：**独占串行**。任意时刻只允许一个 `th08.exe` 进程；执行前若发现残留游戏进程，只报告，不擅杀
- 所属阶段：Stage 3 开发

---

## 1. 背景与目标

验收要求（Q-02=L2）：标题 → 难度选择 → 队伍选择 → Stage 1 实际游玩（移动/射击/暂停）→ 正常退出，并留下截图与日志证据。本 SubStage 把该路径做成脚本化、可重跑、可判定的运行器。

关键事实（不得再推断，按此实现）：

- 键盘走 DirectInput 且为 `DISCL_FOREGROUND|DISCL_NONEXCLUSIVE`（`src/Supervisor.cpp:937`），**必须先置前台**，注入前每次复查；
- 键位：Z=`0x5A` 确认/射击、X=`0x58`、Esc=`0x1B` 菜单、Enter=`0x0D`、Shift=`0x10`、Ctrl=`0x11`、方向键 `0x25/0x26/0x27/0x28`（`src/Global.cpp:733-756`）；
- 标题菜单 0=Start…8=Quit；未解锁项会被跳过（`src/TitleScreen.cpp:81-91`、`:388-404`）；标题空闲 1,500 帧会自动进 demo（`:434`），首个等待不得超过 2,500 ms；
- 标题菜单按 `X`/`Esc` 直接把光标移到 Quit（`:601-608`），Quit 确认后 60 帧退出（`:610-622`）；
- 游戏内 `Esc` 打开暂停菜单（`src/GameManager.cpp:431-448`）；
- 窗口为 640x480 客户区、标题 `東方永夜抄 ～ Imperishable Night. ver 1.00d`（B-06 实测）。

## 4. 函数契约

### 4.1 `Read-Th08KeyScript -Path <string>`

- 行为：`Get-Content -Raw | ConvertFrom-Json`；校验 `schema`、`name`、`steps`；逐条校验 action 与字段（设计文档 §6.4）。
- 输出：`[pscustomobject]@{Path; Name; Steps=[...]}`（步骤对象字段统一化为 `Action/Ms/Vk/HoldMs/ShotName`）
- 失败：`TH08-E12`（消息指出第几步、哪个字段）。

### 4.2 `Test-Th08LogAudit -LogPath <string>`

- 行为：文件不存在或长度 0 → 返回 `Pass=$false` 且 `Reason='missing-or-empty'`；否则按 CP932 解码（`[System.Text.Encoding]::GetEncoding(932)`），检查必需的 `DirectSound`、`KeyBoard` 标记与禁用标记 `Fatal`/`致命的`/`ERROR:`/`Error :`。
- 输出：`[pscustomobject]@{Pass; RequiredMissing; ForbiddenFound; Length; Reason}`；`Pass=$false` 时**不抛异常**（由 `Invoke-Th08Run` 抛 E09），便于单测。

### 4.3 `Invoke-Th08Run -Context <object> -ProfilePath <string> [-Tag <string>] [-WindowTimeoutSeconds 30] [-TotalTimeoutSeconds 60]`

必须实现的行为（顺序不可变）：

1. `Assert-Th08Runtime`；`Read-Th08KeyScript`；
2. 若存在其它 `th08.exe` 进程（`Get-Process th08`，PID 不等同本次）→ 直接 `TH08-E10` 报告，不杀；
3. `Start-Process -FilePath <PlayDir>\th08.exe -WorkingDirectory <PlayDir> -PassThru`，`runId = yyyyMMdd-HHmmss`（若已存在同名报告，追加 `-2`）；
4. 轮询 250 ms 等 `MainWindowHandle`（≤`WindowTimeoutSeconds`）；进程提前退出 → `TH08-E10`（消息含 `ExitCode`）；
5. `SetForegroundWindow` + `GetForegroundWindow()==hwnd` 校验，最多 3 轮（轮间 300 ms）；失败 → `TH08-E08`；
6. 逐步执行：`wait` 期间每 200 ms 检查进程存活；`key`/`hold` 前重做第 5 步校验（失败重试 3 次后 E08），注入用 `SendInput`（`KEYEVENTF_KEYUP` 组合按下/抬起，按住时长由 `holdMs`/`ms` 决定，`hold` 期间不得整段阻塞超过 30 s）；
7. 截图：`ClientRect` → `ClientToScreen` → `Graphics.CopyFromScreen` 存 PNG；计算 `distinctColors`（唯一 ARGB 计数，可降采样到 64x48 计算）与 `meanLuma`（0–255）；`distinctColors < 64` 或 `meanLuma < 2` → `TH08-E11`；
8. 退出：最后一步为 `close` → `PostMessage(WM_CLOSE)` 并等待 ≤10 s；profile 无 `close` → 等待进程自然退出（`l2-menuexit` 由游戏自身退出）≤`TotalTimeoutSeconds`；仍存活 → `Stop-Process -Force`（仅限本次 PID）并记 `forced=true`；
9. 判定：`ExitCode` 必须为 0（`WM_CLOSE` 与游戏自退都应为 0）；日志审计 `Pass=$true`；必需截图（见 §3 中标注的全部 `shot` 名称）存在并写入 `shots[]`；任一不满足 → E09/E10/E11；
10. 无论成败都写 `<runId>_report.json` 与 `<runId>_log.txt`（若日志存在），并清理：确认无残留 `th08.exe` 进程。
11. 全程 `TotalTimeoutSeconds` 守护：超时 → 强制关闭本次 PID → `TH08-E10`。

- 输出：run report 对象（schema 见设计文档 §6.4）。
- 失败：E08/E09/E10/E11/E12，异常消息必须含 `runId` 与报告路径。

## 5. 入口脚本行为

`Run.ps1`：解析 profile（`l2-gameplay`/`l2-menuexit`）→ 调 `Invoke-Th08Run` → 打印摘要（runId、窗口尺寸、首窗毫秒、步骤成功率、退出码、审计结论、截图清单、报告路径）→ 退出码：`0`/`5`（运行类失败）。

## 6. 可观察验收标准

| 编号 | 检查 | 通过标准 |
| --- | --- | --- |
| S3-4-a | 游玩运行通过 | `Run.ps1 -Profile l2-gameplay` → 退出码 `0`；报告 `exit.code=0`、`exit.forced=false`、`log.audit.pass=true` |
| S3-4-b | 截图齐全且非空 | 报告 `shots[]` 含 `01-title`…`08-pause` 全部名称；`06-stage1-play` 的 `distinctColors ≥ 200`、`meanLuma ≥ 8`（人工复核为 Stage 1 画面，含 HUD/子弹） |

| S3-4-d | 前台校验生效 | 人为把焦点切到其它窗口再执行 `Run.ps1`（或在报告中确认 `foregroundChecks` 次数 ≥ 步骤数），脚本必须报 E08 或成功抢回前台，不允许"按键打到别的窗口" |
| S3-4-e | 无残留进程 | 两次运行结束后 `Get-Process th08 -ErrorAction SilentlyContinue` 为空 |

## 7. 禁止事项

- 禁止注入按键到非游戏窗口；禁止使用 `AppActivate` 等按标题模糊匹配的前台手段（标题含日文，需以 hwnd 精确匹配）。
- 禁止修改 `play/` 内数据文件或 `th08.cfg` 语义（只允许按 S3-3 契约生成）。
- 禁止在报告中记录用户桌面其它窗口内容；截图只允许截取游戏客户区。
- 禁止为"让流程过"而延长单次运行超过 60 s 或跳过日志审计。
- 禁止修改上游源码来放宽输入/时序。

## 8. 自测要求

1. 校准过程留痕：把每次校准尝试的 profile 变化（等待/按键调整）与对应截图名写进完成报告；最终锁定值与 `profiles/*.json` 完全一致。
2. 两次 `l2-gameplay` + 一次 `l2-menuexit` 全部通过，报告路径记入完成报告。
3. 异常路径：①先用记事本等窗口抢占前台，验证 E08 逻辑（或验证能抢回前台）；②对 `shots` 空白判定做单元级验证（S3-5 的 T-1x 用例）。
4. 人工复核 `06-stage1-play.png` 是否为 Stage 1 实际游玩画面（含自机/敌机/子弹/HUD 至少两项），并在完成报告写明复核结论。
