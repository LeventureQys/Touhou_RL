# S3-6 证据归档与文档定稿任务书

- 所属 Stage：Stage 3（开发）
- SubStage：S3-6
- 依赖前置：S3-4、S3-5 完成（已有通过的 run report 与 verify report）
- 并行状态：串行（收尾步骤）
- 所属阶段：Stage 3 开发

---

## 1. 目标

把 S3-1..S3-5 的实际结果沉淀成可复用、可验收的材料：

1. `Stage3/完成报告.md`：每个 SubStage 的门禁证据（命令、输出尾部、耗时、失败与修复记录）；
2. `Document/Update/Alpha/v1.0.0/evidence/` 下 ≤4 张关键截图副本；
3. 校准后的"实测生效操作序列"与复现步骤（供零上下文 Agent 直接照做）；
4. 更新 `问题清单.md`（新增问题与关闭情况）与 `验收文档.md`（若实现与设计有偏差，先改设计/验收文档再定稿）。

## 2. 交付物

| 文件 | 内容 |
| --- | --- |
| `Document/Update/Alpha/v1.0.0/Stage3/完成报告.md` | 按 SubStage 分节：目标、做了什么、证据（命令 + 输出尾部 ≤10 行）、门禁自检表、偏差与处置、耗时 |
| `Document/Update/Alpha/v1.0.0/evidence/<runId>_01-title.png` 等 ≤4 张 | 从 `build/play/evidence/` 复制；文件名保留 runId |

| `Document/Update/Alpha/v1.0.0/设计文档.md` | 若实现偏离契约，同步修订并登记决策编号（DD-xx） |

## 3. 完成报告必须包含的内容

1. **环境**：前缀文件数/字节、目标哈希实测值、Python 版本、构建耗时（normal / bugfix）。
2. **构建**：两份 build report 的关键字段（大小、SHA-256、PE 字段），以及产物可运行的定性说明（normal 不可运行、bugfix 可运行，原因引 B-13）。
3. **装配**：运行目录清单摘要（文件数、总字节、cfg 字段实测字节）、正版目录未变证据（前后哈希）。
4. **运行**：两次运行（`l2-gameplay`、`l2-menuexit`）的 runId、窗口尺寸、首窗毫秒、退出码、日志审计结论、截图清单与人工复核结论。
5. **测试**：单测 `TOTAL/PASSED/FAILED`、`Verify.ps1` 8 步结果。
6. **仓库卫生**：根仓库与子模块 `git status --short` 输出（应为空或仅预期文件）。
7. **偏差记录**：与设计文档/任务书不一致之处 + 处置（改文档 or 改实现）。
8. **遗留与建议**：例如 DirectInput 注入稳定性、暂停菜单项未探索、v1.1 的状态导出切入点。

## 4. 可观察验收标准

| 编号 | 检查 | 通过标准 |
| --- | --- | --- |
| S3-6-a | 完成报告完整 | 上述 8 项内容均有实质证据，不含"应该/大概"表述 |
| S3-6-b | 证据可追溯 | `evidence/` 内每张图能在 `Stage3/完成报告.md` 里找到对应 runId 与用途 |
| S3-6-c | 文档一致性 | `设计文档.md`、任务书、`验收文档.md` 与实现一致（无未登记的偏差） |
| S3-6-d | 问题清单更新 | 追加 v3 记录；置顶区为空或已获用户裁决 |
| S3-6-e | 私有材料未入库 | `git status --short`（根仓库）不含 `*.dat`、`*.exe`、`prefix/`、`build/` 等私有物 |

## 5. 禁止事项

- 禁止把 `build/play` 下的原始大图（>2 MB/张）不筛选地复制进 `Document/`。
- 禁止在完成报告中粘贴超过 10 行的连续日志（保留尾部即可）。
- 禁止删除或改写 S3-1..S3-5 的原始报告（`build/reports/`、`build/play/evidence/`）来"美化"结果。
