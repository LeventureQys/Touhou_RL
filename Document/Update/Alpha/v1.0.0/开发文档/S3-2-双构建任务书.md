- 所属 Stage：Stage 3（开发）
- SubStage：S3-2

## 1. 背景与目标

本 SubStage 用本机已有的 VC7 工具链前缀，从子模块源码冷构建两个产物：

- `normal`：精确重建面（用于后续与目标二进制的对照证据，**不可运行**，因零售版本身份校验会失败）；
- `bugfix`：运行面（在 `Supervisor::CheckVersion` 等 3 处启用 `FIX_REALLY_BAD_BUGS`），其产物即 v1.0.0 的运行体。

目标：构建可复现、产物可体检、指纹可追溯，并沉淀为 `tools/th08/Build.ps1`。

## 4. 函数契约

### 4.1 `Resolve-Th08Python [-PythonExe <string>]`

- 解析顺序：
  1. 显式 `-PythonExe`：存在且 `--version` 输出匹配 `Python 3\.(1[1-9]|[2-9][0-9])` → 采用；
  2. PATH 中 `python`：**必须排除** `%LOCALAPPDATA%\Microsoft\WindowsApps\python.exe`（应用商店占位桩，执行会报错）；
  3. `%LOCALAPPDATA%\Programs\Python\Python3*\python.exe` 中版本最高者。
- 输出：`[pscustomobject]@{Path; Version}`
- 失败：全部不满足 → `TH08-E07`。

### 4.2 `Invoke-Th08Build -Context <object> -BuildType <normal|bugfix> [-Fresh] [-Jobs 1] [-TimeoutMinutes 30]`

- 行为：
  1. `Resolve-Th08Python`；
  2. 组装参数：`scripts\build.py --build-type <t>` +（`-Fresh` → `--fresh`）+ `-j <Jobs>`；`Start-Process -Wait -PassThru -NoNewWindow -RedirectStandardOutput/-Error`，`WorkingDirectory=$Context.Th08Root`，超时按 `TimeoutMinutes` 计；超时则结束该进程树并抛 `TH08-E04`；
  3. 非零退出 → `TH08-E04`（消息含退出码与输出尾部 20 行）；
  4. `Assert-Th08PeInfo -Path <Th08Root>\build\th08.exe`（E05）；
  5. 计算产物 SHA-256，写 `build/reports/build-<type>.json`（schema 见设计文档 §6.4）；
  6. 返回报告对象。
- 约束：**不得**并行调用自身；同一时刻只允许一个 `Invoke-Th08Build` 在跑（可用进程内互斥变量 `$script:Th08BuildRunning` 保护，重入抛 `TH08-E04`）。

## 5. 构建顺序（硬性，不可重排）

1. `Invoke-Th08Build -BuildType normal -Fresh` → 保留 `build/reports/build-normal.json`
2. `Invoke-Th08Build -BuildType bugfix -Fresh`（最后构建，其产物供 S3-3 装配）

理由：`docs/WINDOWS_I386_RUNTIME.md:118-151` 规定 same-`build/` 图必须顺序执行，bugfix 最后构建以避免产物混淆；`--fresh` 会清理 ninja 声明的产物与已知 VC7/linker 副产物。

## 6. 入口脚本行为

`Build.ps1`：

- `-BuildType both`：按 §5 顺序执行两步；`normal`/`bugfix`：只执行对应一步（但 bugfix 若未先做 normal，仍允许执行，脚本在输出中提示"未构建 normal，无法据此声明精确性"）。
- 打印每步：构建类型、耗时、产物大小、SHA-256、PE 字段（Machine/Subsystem/ImageBase）。
- 退出码：`0` 成功；`4` 构建失败（E04）；`3` 体检失败（E05）；`2` Python 不可用（E07）。

## 8. 禁止事项

- 禁止 `-j 2` 及以上；禁止同时跑两个 `build.py`。
- 禁止手工编辑 `build.ninja` 或 `src/`；禁止为让构建通过而修改上游源码、编译器参数、链接库顺序。
- 禁止用 `--reuse-build` 之类复用手段声称"冷构建通过"（本版只做本机构建成功证据，不做聚合精确性声明）。
- 禁止把 `build/` 内产物复制进 `Document/`。
- 若构建失败：只允许调整环境（前缀完整性、Python 版本、工作目录、路径长度），不允许改源码。

## 9. 自测要求

1. 先做单对象探针：`python scripts\build.py --object-name utils`（或直接 `--build-type normal -j 1` 到产物）验证前缀可用；把探针输出前 20 行记入报告。
2. 全量 `Build.ps1 -BuildType both -Fresh` → `exit 0`，两份报告存在。
3. 异常路径：把 `resources/th08.exe` 临时改名，再执行构建应快速失败且退出码 `3`（E02/E05 之中实际触发的那个要写清）；恢复文件。
4. 记录两次构建耗时到 `Stage3/完成报告.md` 的 S3-2 小节。
