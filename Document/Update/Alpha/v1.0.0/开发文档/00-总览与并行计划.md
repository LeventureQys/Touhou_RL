## 2. 并行与串行规则（硬性）

1. VC7 编译与链接（S3-2）是全局独占资源：任意时刻只能有一个 `cl.exe`/`link.exe`/`ninja` 批处理在跑，`-j 1`，不得派 SubAgent 执行。
2. 游戏进程（S3-4）同样独占：任意时刻只能有一个 `th08.exe` 在运行；执行前若发现残留进程，只报告不擅杀（除本脚本自己启动的 PID）。
3. SubAgent 只允许承担：只读检查、根仓库 `tools/th08` 与 `Document` 下的独立文档/测试文件编写；**不得**触碰 `third_party/th08` 内的构建、运行目录或 private 材料。
4. S3-3 的装配脚本编写可与 S3-2 的构建等待并行（不同文件），但 `Stage-Runtime.ps1` 的执行必须在 bugfix 构建完成后。

## 3. 出错与重试规则

| 情形 | 处理 |
| --- | --- |
| SubStage 内实现失败 | 修正后重试；同一 SubStage 最多重试 3 次 |
| 3 次仍失败 | 停止，不改方案继续硬碰；把失败证据写入 `Stage3/完成报告.md`，并把阻塞项升级到 `问题清单.md` 置顶区 |
| 构建（E04/E05）失败 | 保存完整 `ninja` 输出尾部到 `build/reports/`，先做单对象探针（`--object-name utils`）再复现全量 |
| 运行（E08/E09/E10/E11）失败 | 保留 `runId` 的截图与日志副本，按设计文档 §8 R-01/R-04 的缓解路线排查 |
| 需要偏离设计文档契约 | 先改设计文档（登记决策编号），再改代码；不允许"代码先行、文档滞后" |

## 4. 零上下文自检（Stage 2 → Stage 3 门禁）

一份任务书可由"没有任何对话历史的 Agent"独立执行，判断标准：

- [ ] 任务书列出**全部**要新建/修改的文件相对路径；
- [ ] 每个函数给出签名、输入、输出、失败错误码；
- [ ] 所有路径、尺寸、哈希、VK 码都以明文写在任务书或指向设计文档 §6.1 的表格（不要求读者猜）；
- [ ] 每条验收标准都是可观察、可执行的命令或文件检查；
- [ ] 写明禁止事项与依赖前置；
- [ ] 写明失败时该保留什么证据、该写到哪里；
- [ ] 不出现"如之前讨论""按上述思路"等依赖对话的表述。

S3-1..S3-6 六份任务书均已按此自检。
