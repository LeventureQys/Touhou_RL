- 所属阶段：Stage 3 开发

## 1. 背景与目标

VC7 重建版按零售逻辑从**当前工作目录**读取数据（`src/main.cpp:121` 读 `th08.cfg`；`src/Supervisor.cpp:589` 加载 `th08.dat`；`Supervisor.cpp:1387` 打开 `./thbgm.dat`），不支持 `--data-dir`（该参数只存在于现代移植层 `src/modern/**`）。

因此需要一个独立运行目录：正版数据 + 窗口化配置 + bugfix 产物，且**绝不写回正版目录**。

| 项 | 默认 | 说明 |
| --- | --- | --- |

## 4. 函数契约（`tools/th08/Th08Pipeline.psm1` 补齐）

### 4.1 `Write-Th08WindowedConfig -SourceCfg <string> -Destination <string>`

- 行为：`ReadAllBytes` → 断言长度 60 → `bytes[0x22]=1` → 断言 `bytes[0x14..0x17]` 的小端值等于 `0x00080001`（否则 `TH08-E06`，说明源 cfg 版本不符）→ `WriteAllBytes` → 计算 SHA-256。
- 输出：`[pscustomobject]@{Path; Length; Windowed; Version; Sha256}`，其中 `Version` 以 `"0x00080001"` 字符串返回。
- 幂等：重复执行产生相同字节与 SHA-256。

### 4.2 `Get-Th08RuntimeManifest -DataDir <string> -ExePath <string> [-CfgSource <string>] [-IncludeScoreDat]`

- 行为：按 §3 生成清单对象（尚未复制）：
  - `th08.dat`、`thbgm.dat` 必须存在且尺寸精确匹配常量，否则 `TH08-E03`；
  - `CfgSource` 缺省取 `<DataDir>\th08.cfg`，必须存在且 60 字节，否则 `TH08-E06`；
  - `score.dat`：仅当 `-IncludeScoreDat` 且存在时纳入；
  - `th08.exe`：取 `ExePath`，必须存在且通过 `Assert-Th08PeInfo`（E05）。
- 输出：`[pscustomobject]@{Files=[...]; Cfg; Exe; DataDir}`，`Files` 每项含 `Name,Size,Sha256,Source,Action`（`copy` / `write-cfg`）。

### 4.3 `Initialize-Th08Runtime -Context <object> -DataDir <string> [-CfgSource <string>] [-Refresh] [-UseHardLink] [-IncludeScoreDat]`

- 行为（严格按序）：
  1. `Get-Th08RuntimeManifest`；
  2. 建目录 `PlayDir`、`replay`、`backup`、`evidence`（`New-Item -ItemType Directory -Force`）；
  3. 对每个 `copy` 项：目标存在且大小+SHA-256 一致且未 `-Refresh` → 跳过；否则 `Copy-Item -LiteralPath`（`-UseHardLink` 时对 `th08.dat`/`thbgm.dat` 用 `New-Item -ItemType HardLink`，失败则回退复制并记录 `fallback=copy`）；
  4. 用 `Write-Th08WindowedConfig` 生成 `play\th08.cfg`；
  5. 复制 `th08.exe`（覆盖）；
  6. 写 `play/runtime-manifest.json`（schema 见设计文档 §6.4），`files[]` 记录实际 `action` 与最终 SHA-256。
- 输出：manifest 对象。
- 失败：E03/E05/E06；失败时不得留下 `runtime-manifest.json`。

### 4.4 `Assert-Th08Runtime -Context <object>`

- 行为：逐项校验 §3：文件存在、尺寸符合常量、`cfg` 长度 60 且 `byte[0x22]==1` 且 `byte[0x14..0x17]==0x00080001`、`th08.exe` 与 `build/reports/build-bugfix.json` 的 `artifact.sha256` 一致（若报告缺失则跳过该子项并在返回对象中标记 `exeHashChecked=$false`）。
- 输出：`[pscustomobject]@{Ok=$true; Checks=[...]; ExeHashChecked=<bool>}`
- 失败：`TH08-E06`（消息含首个失败项）。

## 5. 入口脚本行为

`Stage-Runtime.ps1`：

```powershell
param(
  [string]$DataDir = 'D:\Games\[th08] 东方永夜抄 (日文版)\[th08] 东方永夜抄 (日文版)',
  [switch]$Refresh,
  [switch]$UseHardLink,
  [switch]$IncludeScoreDat
)
```

- 校验 bugfix 产物存在（`build\th08.exe`），且 `build\reports\build-bugfix.json` 存在；否则提示先执行 `Build.ps1 -BuildType bugfix` 并 `exit 2`。
- 执行装配 + `Assert-Th08Runtime`，打印清单摘要（文件数、总字节、cfg 字段、exe 哈希）。
- 退出码：`0` 成功；`2` 前置缺失；`3` 校验失败。

## 6. 可观察验收标准

| 编号 | 检查 | 通过标准 |
| --- | --- | --- |
| S3-3-a | 目录齐备 | §3 列出的 6 个文件 + 3 个目录全部存在 |
| S3-3-b | 尺寸精确 | `th08.dat=46838025`、`thbgm.dat=449961024`、`th08.cfg=60`、`th08.exe` 与 `build/th08.exe` 同哈希 |
| S3-3-c | 窗口化配置 | `cfg[0x22]==1` 且 `cfg[0x14..0x17]==0x00080001`（用 PowerShell 读字节断言，输出实际字节） |
| S3-3-d | 幂等 | 连续执行两次（第二次不带 `-Refresh`）→ 均 `exit 0`，第二次全部命中跳过分支（报告里 `skipped` 计数 = 文件数） |
| S3-3-e | 不回写正版目录 | 装配前后对正版目录做 `Get-FileHash th08.dat/thbgm.dat`，哈希不变；且正版目录不出现 `evidence/` |
| S3-3-f | 清单可信 | `runtime-manifest.json` 中每个文件的 `sha256` 与 `Get-FileHash` 实测一致 |

## 7. 禁止事项

- 禁止以正版目录为工作目录运行游戏（会写 `log.txt`/`score.dat`/`th08.cfg`，污染正版存档）。
- 禁止修改正版目录内任何文件（包括改名、移动）。
- 禁止把 `score.dat` 之外的存档/全开档隐式带入；若需使用 `全开档`（正版目录下子目录），必须在 `runtime-manifest.json` 与完成报告中注明来源与原因。
- 禁止在 `play/` 内保留旧产物而不更新清单（必须先删清单再重建，保证清单与实物一致）。

## 8. 自测要求

1. 正向装配：`Stage-Runtime.ps1` → `exit 0`，打印摘要；手工 `Get-FileHash` 抽验 2 个文件与清单一致。
2. 幂等：再执行一次 → `exit 0` 且跳过全部复制（耗时显著低于首次）。
3. 边界：把 `-DataDir` 指向不存在路径 → `exit 2/3` 且报 `TH08-E03`。
4. 异常：临时修改 `play/th08.cfg` 的 `0x22` 为 0，执行 `Assert-Th08Runtime` 应报 `TH08-E06`；随后重新装配修复。
5. 记录首次装配耗时与总字节到 `Stage3/完成报告.md` 的 S3-3 小节。
