## 4. 验收项

### A-01 环境自举可复现

- **目的**：证明私有输入能从既有来源被脚本化落地并校验，而不是依赖"上一轮已存在"。
- **步骤**：
  1. 记录当前 `third_party/th08/resources/th08.exe` 的 `Get-FileHash`；
  2. 执行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools\th08\Prepare-Environment.ps1`；
  3. 检查 `third_party/th08/build/reports/env-report.json`；
  4. 再执行一次（不带 `-Force`），确认幂等；
  5. （可选、更严格）如需证伪"依赖上一轮残留"，再执行一次 `Prepare-Environment.ps1 -Force`，应同样 `exit 0` 且 `copied=true`。
- **期望结果**：两次均退出码 0；报告 `ok=true`；`target.sha256` = `330FBDBF58A710829D65277B4F312CFBB38D5448B3DF523E79350B879213D924`；`target.size=840704`；`prefix.checks` 四项全 `true`。
- **通过标准**：上述全部满足，且第二次执行 `prefix.files` 与第一次相同（未重复复制）。
- **失败标准**：非 0 退出；报告缺失或 `ok=false`；哈希/尺寸不符；第二次执行改变前缀文件数。
- **证据要求**：两次命令的退出码与输出尾部（≤6 行）；`env-report.json` 全文路径（`build/reports/env-report.json`）。

### A-02 normal 构建成功且产物身份正确

- **目的**：证明 VC7 精确重建面可编译链接，为后续精确性工作留下产物。
- **步骤**：`powershell -NoProfile -ExecutionPolicy Bypass -File tools\th08\Build.ps1 -BuildType normal -Fresh`；读 `build/reports/build-normal.json`。
- **期望结果**：退出码 0；`exitCode=0`；`artifact.size>0`；`artifact.pe.machine="0x14C"`、`subsystem=2`、`imageBase="0x00400000"`、`isPe32=true`；`artifact.codeSha256` 为 64 位十六进制。
- **通过标准**：以上全满足，且报告含 `artifact.sha256`（整文件）与 `durationSeconds`。整文件 `sha256` 因 PE 链接时间戳每次不同，**不作**复现性判据；复现性看 `codeSha256`。
- **失败标准**：非 0 退出；PE 字段不符；`codeSha256` 缺失或非法；报告缺失。
- **证据要求**：命令退出码、`build-normal.json` 关键字段、耗时。

### A-03 bugfix 构建成功且产物身份正确、与 normal 可区分

- **目的**：产出可运行体并证明两者确为不同构建。
- **步骤**：`Build.ps1 -BuildType bugfix -Fresh`；读 `build/reports/build-bugfix.json`，比较两者 SHA-256。
- **期望结果**：退出码 0；PE 字段同 A-02；`build-normal.json.artifact.sha256 ≠ build-bugfix.json.artifact.sha256` 且两者 `codeSha256` 不同（证明 `FIX_REALLY_BAD_BUGS` 生效）。
- **通过标准**：以上全满足。
- **失败标准**：非 0 退出；两者 `codeSha256` 相同（说明构建类型未生效）；PE 字段不符。
- **证据要求**：两份报告的关键字段与 `codeSha256` 对照。

### A-04 运行目录装配完整且未污染正版目录

- **目的**：证明运行环境自足、配置正确、正版目录只读。
- **步骤**：
  1. 记录正版目录 `th08.dat`、`thbgm.dat` 的 SHA-256；
  2. `Stage-Runtime.ps1 -Refresh`；
  3. 读 `build/play/runtime-manifest.json`；用 PowerShell 读 `th08.cfg` 字节；
  4. 再次记录正版目录两个 DAT 的 SHA-256。
- **期望结果**：退出码 0；`third_party/th08/build/play/` 内 6 项必需物（`th08.exe`、`th08.dat`、`thbgm.dat`、`th08.cfg`、`runtime-manifest.json`）与 `replay/`、`backup/`、`evidence/` 三个目录齐备；`th08.dat=46838025`、`thbgm.dat=449961024`、`th08.cfg=60`；`cfg[0x22]=1`、`cfg[0x14..0x17]=0x00080001`；`play/th08.exe` 哈希 = `third_party/th08/build/th08.exe`；正版目录两 DAT 哈希不变，且正版目录未出现 `evidence/`。
  - `score.dat` 默认**不**装配（游戏会自建并回写）；若用 `-IncludeScoreDat` 装配，其清单条目 `mutable=true`，不得用于事后一致性判定。
- **通过标准**：全部满足；清单内 `mutable=false` 的每个 `sha256` 与实测一致。
- **失败标准**：任一尺寸/字段不符；正版目录被写入；清单与实物不一致。
- **证据要求**：装配退出码、清单摘要、`th08.cfg` 实测字节（至少含 `0x14..0x17` 与 `0x22`）、正版目录前后哈希。

## 5. 失败与阻塞处理

| 情形 | 处理 |
| --- | --- |
| 单项失败（可复现） | 记录 `runId`/命令/截图/日志尾部，判定"失败"，回退至 Stage 3 对应 SubStage 修复；同一缺陷最多 3 次修复尝试 |
| 单项阻塞（环境缺失、无法启动、需要用户授权） | 判定"阻塞"，写入 `验收报告.md`，并升级到 `问题清单.md` 置顶区等用户裁决；不得以"应该没问题"结案 |
| 前置条件不满足（P-01..P-05） | 先修复前置；无法修复则整体判定"阻塞" |
| 文档不清导致无法执行 | 判定"阻塞（文档缺陷）"，要求补文档后重新验收，不得默认通过 |
