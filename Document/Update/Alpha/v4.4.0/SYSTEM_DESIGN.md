# 系统设计｜真实环境、策略和独立裁判

## 1. 系统边界与复用

一次正式运行由冻结清单驱动。读取器验证资产和身份，重放器建立起点，策略适配器只接收该臂允许的信息，动作编译器发键，引擎记录事实。最后由无模型依赖的进程从封存记录算分。相同的代码路径覆盖训练评测、固定动作、开环、随机和教师，减少旧驱动之间的语义差异。

| 组件 | 已有入口及适用范围 | v4.4.0 的设计决定 |
| --- | --- | --- |
| 历史引擎与状态向量 | [密集前缀驱动](../../../../tools/rl/v431_dense_driver.py)、[106 维状态策略](../../../../tools/rl/v431_arm_a.py)、[协议解析](../../../../touhou_rl/v400/gym/protocol.py) | 经运行机原始 v420 代码和配置绑定后包装；用实际权重校验固定输入到 logits 的一致性。保留历史训练与推理实现供比对 |
| 完整动作与观测 | [v430 契约](../../../../configs/v430/contracts.json)、[像素观测](../../../../touhou_rl/v430/observation.py)、[动作编译](../../../../touhou_rl/v430/actions.py) | 本版微段用 R15 的 18 动作；v430 的 72 个联合动作留给完整资源任务。显式转换和逐键验证，避免两个索引体系同号异义 |
| 终局与汇总 | [v430 独立裁判](../../../../touhou_rl/v430/evaluate.py)、[状态与退出码](../../../../touhou_rl/v430/contracts.py) | 复用摘要校验、原始记录入参和四状态协议；新增微段逐帧裁判与祖先配对统计。自然过关与 10 秒无死亡各用自己的任务 ID |
| 学习组件 | [BC 编排](../../../../touhou_rl/v430/learn.py)、[PPO 数值组件](../../../../touhou_rl/v430/ppo.py)、[序列处理](../../../../touhou_rl/v430/sequence.py) | 先验算接口、形状与真实输入契约。已有纯函数和合成批次测试可支持开发，真实 rollout 与像素接管另验 |
| 谱系与资产 | [切分登记](../../../../configs/v430/splits.json)、[本机同步规则](../../../../ASSET_SYNC.md) | 只读旧登记，建立本版独立运行映射和双向核验。重资产留本机，配置通过参数绑定路径 |

**权限按数据流控制。** `policy.decide(allowed_observation, policy_rng) → candidate_id`；actor 对象无 engine client、judge、终局标签或后续录像句柄。状态策略接 `STATE/HAZARDS`，像素策略接渲染像素与已执行动作，开环接已封存的查表器及时间索引。裁判看到引擎终态用于评分；它的输出只进入事件日志和已结束轨迹的训练奖励。H2 替换危险物由输入适配器完成，各臂时序一致。整个微段的能力标签保留 `privileged_state`、`open_loop`、`pixel_actor_privileged_reward` 等实际信息边界。研究机上的特权奖励不等于部署后的纯像素自我改进。

## 2. 时间、恢复与动作契约

1. RESET 后绑定任务、引擎 SHA、模板和 RNG，按录像实际逐帧 mask 推进。每到有参考哈希的帧即验证。记录预期检查数、实测检查数、最近一个参考锚点和第一个不符帧。检查数为零、漏锚点或静默分歧均使配对无效。用逐帧顺序及最终状态摘要验证两臂接管点。
2. 冻结 `start_frame=f` 为前缀最后已执行的游戏帧。决策 j（从 0 起）只用截至 `f+2j` 的观测，发相同 mask 给 `f+2j+1` 和 `f+2j+2`；首帧死亡立即结束。历史记录的 `target_frame` 与实际引擎帧分列。游戏每帧记录 requested、emitted 和（接口可读时）executed mask，无法验证发键/锁步时标明缺项并停止正式使用。
3. 记录接管时的 lives、deaths、stage/phase、窗口有效性和初始 hash。核验 18 个候选到 mask 的映射逐一可逆；#12 的历史 mask 为 0x85。记录 teacher 实际发出的动作；如无法做到相同的固定射击、禁 bomb、两帧保持，则该教师只能单列为不同任务参考。[动作枚举](../v4.3.1/evidence/R15/candidate_space.json)
4. A 的历史特征为 10 个玩家/资源/全局量（含决策索引）、12 颗近弹各 6 维、4 个敌人各 5 维、最近激光 4 维。记录字段顺序、归一化、距离排序和 padding。遇到缺失的必需字段单列无效；真实零与读数缺失必须能区分。修改危险物排序或新增特征时分配新模型身份，不能拿旧权重的分数作新特征结果。
5. 每张表只对应一种阶段、视界和实际动作语义；将不同阶段合并时沿用冻结混合权重。首次接管的阶段和 phase 标签只能用于抽样配对，除原协议允许的输入外不可额外喂给闭环演员。

## 3. 统一裁判与边界例子

定义 `alive_frames` 为接管后、首个致死帧之前且可核验的完整游戏帧数，最多 600。满段成功须在全部 600 帧上没有死亡或冲突终态。死亡优先于同帧达上限；无死亡的正常满段独立于记录数组长度。游戏合法失败与运行故障使用不同的 reason。以存活为任务时，正常提前过面属于另一种终态；若要研究提前清场，在新协议定义相应成功事件。

| 输入事实（相对接管时刻，从 1 起） | episode 分类 | Y / T |
| --- | --- | --- |
| 第 1 帧确认死亡 | 合法失败 death | 0 / 0 |
| 第 2 帧确认死亡 | 合法失败 death | 0 / 0.5 |
| 第 600 帧确认死亡 | 合法失败 death | 0 / 299.5 |
| 完整 600 帧，存活且身份一致 | 合法成功 horizon_alive | 1 / 300 |
| 合法终局 game_over、有明确致死帧 | 合法失败 game_over | 0 / 致死帧之前的完整帧数÷2 |
| 提前过面、退出且缺失死因、哈希错误、缺帧、超时、空日志或异常 | out_of_scope / invalid / incomplete，并保留具体原因 | Y、T 置空；可核验的已执行帧数另记 |

每帧记录 deaths 变化、终态枚举与引擎运行状态。death 与 stage_clear 同帧且顺序可证时按已见死亡处理，语义无法确定时标为冲突，保留原始回复。所有臂共享同一裁判，含随机/固定动作。旧 `return_decisions`、`survived` 以及 `first_death_offset=null` 只作旧字段映射，回填时必须有证据支持满段；对只有汇总的历史数据保留原版本定义。[旧 A 日志和训练实现](../../../../tools/rl/v431_arm_a.py) · [旧随机臂汇总](../../../../tools/rl/v431_n80.py)

## 4. 数据对象与证据身份

| 对象 | 必需字段 | 可检查的不变量 |
| --- | --- | --- |
| 运行清单 `manifest.json` | run_id、协议与代码版本、真实引擎/游戏数据/配置摘要、作用域、预算、分析器版本、候选权重 SHA、训练谱系、许可路径、时区 | 运行开始前封存；相对路径和路径根映射可在另一台获准主机解析；缺身份列出 missing |
| 起点清单 `windows.jsonl` | ancestor_id、parent/source、game_seed、task/phase、split、prefix_sha、start_frame、最后锚点、接管哈希、像素/历史身份 | 同祖先同分组；启动每臂前逐项相同；无历史接管哈希时保存两次真实重放的观测哈希及其来源 |
| 动作库 `donors.jsonl` | train 祖先、源模型、采样器版本、每步来源/供体/补齐原因、300 个动作引用、表摘要 | 动作在目标评测前生成，所有供体只来自训练；打乱目标传感器后开环仍输出完全相同序列 |
| 配对清单 `pairs.jsonl` | pair_id、ancestor/window、重复号、预定两臂、policy_rng、运行顺序、动作库 SHA | 主分析一祖先一对；每臂同起点；配对缺一臂不能入主表；固定动作的确定性重复只作工程冒烟 |
| 原始轨迹 `episodes/<pair>/<arm>/<attempt>/` | attempt_id、run_id、帧/决策/动作、状态与像素摘要、死亡/过面事实、真实帧数、错误、按段墙钟、stdout/stderr 与 exit_code | 帧索引单调且连续，最长 600 帧；原始字节有 SHA；每条终态定位到对应帧；无执行证据不算满段 |
| 模型与训练清单 | 权重、优化器、RNG、学习基线、更新步、已消费决策数、预处理和训练窗摘要、选模规则 | 中断复训能重建下一批次；只有权重时明确为 warm start。B/C 预训练和在线更新分别持有计数器 |
| 派生结果 `report.json` | 运行与分析版本、总尝试数、有效/无效/未跑、四格表、每窗数据、差与区间、资源实耗、结论适用范围 | 独立进程只读 raw + manifest 即可重建；训练脚本传入的均值不进裁判。故障与未定分别报告 |

对二进制和原始记录按原始字节计算 SHA-256；文本若使用换行归一化，须登记算法，比较双方采用相同口径。分配独立输出目录，在同一文件系统中先写临时记录、刷盘、完成校验，再原子发布。以 `(run, pair, arm, attempt)` 作唯一键，排程器以排他创建认领，重试占新 attempt；恢复只排尚缺的配对成员。统计者按冻结规则选首次有效尝试，重复成功记录不能增加 N。保留坏记录和故障时间，新 run 的配置不得覆盖旧 run。

建议本地保存逐帧真值/渲染及 checkpoint，只将允许同步的小型证据表、参数、身份摘要、命令与退出码放到 `Document/Update/Alpha/v4.4.0/evidence/<run_id>/`。`.tmp_v440_runs/<run_id>/` 是建议的重资产输出根。按资产同步规则登记每项新资产及清单校验；不得把本地数据包传给远端研究员。[资产规则](../../../../ASSET_SYNC.md)

## 5. 学习器和像素分支

**E2 的受控比较。** 令 H=300，任一决策内存活的半决策按实际完整帧数计；各新的受控配方使用一致的每步奖励 `r_t=该步存活帧数/2`，无奖励塑形、无未来状态输入。为分离计分改动，先在相同轨迹上复算原 v431 的“只给完整存活决策 +1”回报和新回报，历史数单列。以下三个配方共享新回报、相同网络/Adam、梯度裁剪 1.0 和冻结学习率。旧式估计量在新计分下有单独实验号。

| 配方 | 单条 episode 的损失 | 要区分的原因 |
| --- | --- | --- |
| L0 旧式估计量 | `−mean_t(logπ_t) × (R−b)/H` | episode 实际长度参与归一化 |
| L1 固定归一化 | `−sum_t(logπ_t) / H × (R−b)/H` | 对比 L0 只改轨迹长度权重 |
| L2 剩余回报 | `−sum_t[logπ_t × (G_t−b_t)] / H²`，`G_t=sum_{k≥t}r_k` | 动作只对其后收益归因，并按决策位置使用过去轨迹的基线 |

`R=sum r_t`，L0/L1 共享整局基线，建议 EMA 衰减 0.95；L2 的逐步基线同衰减、只随已观测到该步的历史训练轨迹更新。所有基线在当前更新后才吸收当前轨迹，梯度不穿过基线。L1/L2 同为固定尺度；L2 同时改变归因和基线，若它单独胜出，再以逐步回报+同一标量基线消融。用手算短轨迹验证梯度方向，记录梯度范数（裁剪前/后）、裁剪率、熵、策略 KL、return 和动作切换率。训练目标偏向活得久，最终门评估是否满段，两者都保留。奖励改动、采样器变化、学习率调参各另编 recipe。

每个 E2 运行固定更新次数与起点顺序；因不同策略存活时间不同，实际引擎交互量会变化。同时画按更新数和有效决策数对齐的曲线，另报等帧预算下的最后一次可用 checkpoint。续训保存优化器和随机状态；旧脚本仅加载 state_dict 再新建 Adam，不足以复现未中断训练。首次开发建议 Adam 学习率 0.003，绑定历史配方时以真实运行配置为准。

**E3 的像素输入。** 优先选择能从 RESET 开始满足逐决策同 mask 的真实录像；如需新录，只在获准的本机资产范围执行并登记。保持旧像素 arm 契约的 4 帧画面、HUD、8 个已执行动作；以资产机实际实现锁定帧距、裁剪、缩放和通道顺序。序列 burn-in 使用接管点以前的真实合法帧，GRU 初始状态固定，禁止读未来动作或用教师隐藏状态填充。为每帧保存哈希和时间戳，用独立逐帧路径重建栈并比对。把旧磁带相邻不同 mask 改写成相同值会改变起点，不能用于本版同起点配对。[像素臂冻结观测](../v4.3.1/PREREGISTRATION_SEG_001.md) · [历史阻塞范围](../v4.3.1/evidence/R74/pair_cand_scope.json)

B/C 首选小型共享 CNN + GRU + 18 路策略头，两臂同结构。建议两层卷积、64 维图像嵌入、64 维 GRU 作为首轮开发起点，训练段携带 burn-in 与 episode 边界重置；实际尺寸、步长和参数量在开发清单冻结。C 在仅训练祖先的真实像素和已对齐动作上做 BC；若仅有移动头标签，用 move 边缘概率的 CE（合并同 move 的两个 focus 候选），不伪造缺失 focus 标签。前缀近重复按祖先分组；归一化统计、词表和调参只用训练/开发。旧 down16 的权重若架构不兼容，重训共同架构并保存新 BC 权重。

B/C 首轮共享更新器、采样规则和窗口清单。建议每臂起步 12,000 个真实受控决策，每满 600 个新决策更新一次，共 20 次。每批固定行为权重，跨局积累，若第 600 步落在局中，以训练批边界截断剩余回报、末值设 0，下一批从预分配起点重开。明确给截断打标、报告所占比例和损失的剩余视界；训练中的批界只用于这一有限回报估计，评测仍完整运行 600 游戏帧。无效技术尝试不参加更新，额外执行的引擎帧和墙钟全部计费。按 3k、6k、9k、12k 决策存快照，同一开发规则比较固定终点与曲线；C 的 BC 数据量、迭代次数和墙钟单独报告。训练预算不足时先给同预算小样诊断，正式比较另冻结。E3 的 A 在同一新窗上重新运行，历史 A 在旧窗的数据只作背景。

## 6. 可选的 PARK 恢复加速

历史 PARK 在五个接管位置返回相同的拒绝状态。先量未加速流程的总墙钟和前缀占比；只有预计节省时间超过原型、验证、维护的总成本才申请第三方修改。独立构建目录和二进制身份由有权修改引擎者管理，已有二进制只读。[已有 PARK 探针](../v4.3.1/evidence/R33/park_frames.json)

比较冷重放和恢复：先一个真实开发窗口、两个不同固定动作，再两个阶段各至少一个窗口，加入随机但冻结的动作表。连续两次恢复分别核对引擎哈希、RNG 后续轨迹、真值、像素栈、动作历史、末次死亡帧和成功判定；检查兄弟进程间无状态串扰。记录同负载每小时有效配对、P50/P95 前缀延迟和峰值内存。出现任何未解释差异即退回冷重放；性能好但结果不同不能把新旧记录拼成同一批次。PARK 成功本身也不能补齐像素前缀历史。
