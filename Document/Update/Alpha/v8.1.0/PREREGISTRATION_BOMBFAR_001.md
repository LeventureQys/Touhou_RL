## 0. v8.0.0 已经测到什么（这是本轮的直接前提）

冻结的 `S` 策略 + 三条脚本放雷规则（最近子弹 < 40 / 60 / 80 px 且还有雷时，该决策首帧放雷）：

| 臂 | n | 活满 600 帧 | 率 | 每 episode 用雷数（1/2/3 颗） |
| --- | ---: | ---: | ---: | --- |
| A0（不放雷） | 3,600 | 484 | **13.4444%** | 0 / 0 / 0 |
| A1（40 px） | 3,357 | 3,357 | **100.0000%** | 2,216 / 1,095 / 46 |
| A2（60 px） | 3,420 | 3,420 | **100.0000%** | 1,551 / 1,690 / 179 |
| A3（80 px） | 3,446 | 3,446 | **100.0000%** | 1,165 / 1,960 / 321 |

- 冒烟审计（A3 × 4 条）：12 颗雷里用掉 **7 颗**，49 次放雷指令中 **42 次被忽略**（无敌帧内再按无效）⇒ 机制正确，雷是**有限资源**（每局 3 颗）。
- ⇒ **10 s 的「难度」几乎全部来自「禁止放雷」这一条协议约束**；把雷打开后，一个不做任何训练的启发式就让任务变成全过。

**于是本轮的问题变成：雷能把它撑多远？** 如果 1,200 / 1,800 / 2,400 帧仍是 100%，那「段长」这个维度在**有雷**的条件下要重新标定。

## 2. 判据

| # | 终点 | 判据 |
| --- | --- | --- |
| **P1（主）** | 各预算下的**活满整段**率 | 600 决策 **> 13.4444%**（v8.0.0 已成立，本轮作为复现检查）；900 与 1,200 决策各给出率，**并与不放雷基线（900：0/1,200；1,200：本轮实测）比较** |
| **P2** | **雷耗尽时的剩余预算比例** | 描述性：用雷数 3/3 的 episode 占多少、以及它们是否仍活满整段 |
| **P3** | 三档的存活帧均值/中位数 | 描述性；**跨预算的均值不可直接比**（删失上限不同） |

### 2.1 停止条件

| # | 条件 | 动作 |
| --- | --- | --- |
| **S-fork** | 保真门失败 | 整轮作废 |
| **S-100** | 1,200 决策仍 100% 活满 | 判「雷的储备足以覆盖 40 s」；下一轮把预算推到 **2,400 / 3,600 决策（40 / 60 s）**，直到出现非 100% 的那一档——那一档才是「有雷条件下的真实难度」 |
