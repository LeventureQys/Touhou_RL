## 1 起始状态（冻结）

### 1.1 为什么用 A1 状态而不是启发式片段

A1 pass 对 **200 个冻结状态 × 18 个首动作**在真实引擎里各跑 120 帧，记录每个动作的
`engine_death` / `engine_alive`（`arms_present 3600/3600`，`unknown 0`，`invalid 0`，
`prefix_hash_mismatches 0`）。于是"这个状态需要决策"是**实测**的，不是推断的：

| 量 | 值 |
| --- | --- |
| 状态数 | 200 |
| `0 < \|S\| < 18` 且 18 臂全部有效（proper） | **184（92%，Wilson 95% [0.874, 0.950]）** |
| proper 状态下 18 个动作里"会死"的比例 | 中位数 **0.500**，均值 0.514，min 0.056，max 0.944 |
| 18 个动作全死 / 全活的 proper 状态 | **0 / 0** |
| 独立祖先 | **50 个 seed（3042–3091）** |

也就是说：**在每一个被选中的状态上，一半左右的首动作会在 120 帧内导致死亡，另一半不会。**
恒按一个键无法完成——不需要再跑一个"恒定动作必败"的校准门。

**这套判定的可靠性（`R15`/`R16` 补验）**：

| 检验 | 结果 | 意义 |
| --- | --- | --- |
| 18 个候选是否 18 个不同动作 | **注入**：18 个互异 mask、0 碰撞、往返一致 | "18 臂"不是重复计数 |
| 同一臂重跑是否给同一判定 | **4/4 对一致（100%）** | 判定可重复（样本量小，只 4 对） |
| 选中状态里"学生自己那个动作会死"的比例 | **81/84 = 96.4%** | 这些确实是学生失败过的状态，不是"随便挑的帧" |
| 选中状态的有效臂数 | **1,512 / 1,512**（0 个 unknown） | 没有一个状态靠"未判定"混过去 |
| 选中状态的 `\|S\|` 范围 / 每状态致命臂均值 | **2–8** / **12.96 / 18** | 任务有难度：约 5 个动作可用 |

### 2.2 控制协议（冻结）

- 决策周期 2 帧；动作空间 18 个 `(focus, move)` 候选；`bomb` 固定 0。
- `shoot` 由 `cand_to_mask` 恒 OR；shoot pulse period = **48**（与 W01 S1/S2/S3 一致）。
- 墙钟上限 = 60 s/次（不含前缀重放）。
- **18 个候选确实是 18 个不同动作**（`R15` 实测）：`cand_to_mask` 在 0..17 上**注入**
  （18 个互异 mask，无碰撞，`mask_to_cand` 往返一致，`bomb` 恒 0）。
  `focus` 是 bit `0x04`（cand 0–8 = 不聚焦，9–17 = 聚焦），`shoot` 是 bit `0x01`（恒置位），
  方向位 `0x10/0x20/0x40/0x80`。所以"18 臂"是诚实的计数。

### 2.3 控制臂与 `C4` 校准门（rev D 重写）

> **rev C 的错误**（`R19` 实测推翻）：rev C 认为"从 `S` 采样在 `alive@120` 上恒 100%"，
> 因此把 `C-priv` 降为参照。这个推理**建立在错误前提上**——它以为 `alive@120` 只取决于
> 第一个动作。实际上 A1 的 `alive@120` 是"候选 2 帧 + **冻结学生**续跑"的结果，
> 一旦换成自己的策略驱动整段，`S` 就不再是存活集：cand 2 持有 35 帧就死，
> cand 7 持有 180 帧不死。**所以 `S` 既不是上界也不是下界。**

rev D 把控制与筛选重新分成三层，职责互不重叠：

| 层 | 名称 | 定义 | 用途 |
| --- | --- | --- | --- |
| **前置筛选** | `C4` 恒定动作校准门 | 对每个候选状态，把 **18 个候选分别"整段持有"** 各跑一次；若**存在任何一个**恒定动作跑满整段未死，该状态**剔除** | 保证"恒按一个键打不完"，即复核文档要求的战术可学性前提 |
| **平凡基线** | `C-const-best` | 上述 18 次里**存活最久**的那个恒定动作 | 学习必须在**同一个段长口径**上显著优于它 |
| **随机基线** | `C-fair` | 每次决策在 18 个候选上均匀抽样 | 主门槛：臂 A 必须显著优于它 |

**为什么 `C4` 必须每状态、每段长、策略驱动地重跑**：`R19` 里同一个状态在
"学生续跑 120 帧"口径下 cand 2 安全、在"策略驱动 180 帧"口径下 cand 2 第 35 帧就死。
口径一换结论就换，所以校准门不能借用别的口径的数。

**成本与覆盖面（必须如实写）**：18 个恒定动作 × 单次尝试 17 s ≈ **5.1 min / 状态**。
所以 `C4` 只能对**少数状态**跑，不能对 68 个训练状态全跑。这带来一个明确的限制：

> **只对被 `C4` 筛过的状态做结论。** 未被筛过的状态即使出现在池子里，
> 也不得被当作"需要决策的片段"来报告。筛选覆盖面必须与结果一起写出来。

`C4` 输出同时给出 `C-const-best`，所以这道门**不是纯开销**：它顺手产出平凡基线。

### 2.4 `S` 的正确用法（仅作诊断，不作判据）

开发种子 3082–3091 也在 A1 的测量范围内，所以每个状态的 `S` 已知。但按 §2.3，
`S` **不是**整段存活集，因此：

- 记录 `pick_hit = 1[ 第一个决策的动作 ∈ S ]` 作为**诊断**，报告它的提升曲线；
- **不得**用它当主判据，也**不得**把"`pick_hit` 高"写成"会玩"；
- `S` 与 `alive@120` 的一致性只在"A1 口径（学生续跑）"下成立，不在本驱动的口径下成立。

**注意**：开发状态的 `S` 已知，不等于"开发集泄漏"。泄漏与否取决于**策略是否在这些状态上更新过**，
本预注册规定开发状态**不进任何梯度步**。

而"该停还是该继续"的错判比训练曲线难看更危险。所以 `v431_seg001_gate.py` 只做纯函数运算——
Wilson 区间、aborted 排除、S1/S2/S4/S6/S7 触发、`C-fair`/`C-const-best` 双门槛——全部可在没有引擎的情况下自测。

> **`v431_seg001_gate.py` 需要按 rev D 更新**：它现在仍把 `C-priv` 当"永不设门"的特权参照，
> 而 rev D 已删除 `C-priv`、改为 `C-fair` + `C-const-best` 双门槛。
> 在跑正式实验之前必须先改它并重跑自测，否则判据与预注册不一致。

**复现风险（必须写进执行前提）**：`a1_expand.py` 位于 `.gitignore` 忽略的 `.tmp_v420_expand/`，
`configs/v420/a1-safe-set-full.json` 仍是 untracked。
**结果 JSON 被 `ASSET_SYNC` 钉住（`d6da8ea8…82ef`，实测逐字节一致），但产出它的代码没有被钉住。**
所以在动工之前，第一步应当是**把该驱动与配置转为受版本控制的正式路径并登记 SHA**
——否则"扩认证到 3 s"这一步没有可信的起点。

## 6 停止条件（冻结）

| # | 条件 | 动作 |
| --- | --- | --- |
| S1 | 恢复门哈希不匹配率 > 5% | **停**：恢复协议不可信，先修 |
| **S1b** | **`C4` 筛出的合格状态数 < 4（训练侧）或 < 4（开发侧）** | **停**：可用片段太少，先扩大 `C4` 扫描面或换状态来源，**不得**用过不了 `C4` 的状态凑数 |
| S2 | 臂 A 在 200 更新后，开发状态上的 `alive@180` 成功率 **≤ C-fair**，或 **≤ C-const-best**（Wilson 区间重叠也算未超过） | **停**：目标/奖励/探索/优化有问题，**不得**启动像素臂 |
| S3 | 臂 A 学到、臂 B 学不到 | 停：查可见信息/表示/记忆 |
| S4 | 臂 B 与 C 都 ≤ C-fair 与 C-const-best | 停：不扩到多片段/多 seed |
| S5 | 引擎墙钟超 §5 上限 | 停并报已花成本 |
| S6 | `alive@120` 与 `alive@180` 结论方向相反 | 停：段长在主导结果，先统一段长再判 |
| S7 | 臂 A 在**训练**状态上达到 100% 但开发状态仍 ≤ C-fair | 不是"停"，但**不得**据此宣布可学：这是记忆而非泛化，按 §4 的独立性边界报告 |

**三个基线都必须跑**：`C-fair`（18 路均匀）与 `C-const-best`（`C4` 里最强的恒定动作）都是门槛；
`C-priv` 已被 rev D 删除——`S` 不是整段存活集，用 `S` 采样既不是上界也不是下界（§2.3）。

任一条触发都**不得**被读成"整条路线失败"。
