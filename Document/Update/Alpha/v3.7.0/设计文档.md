## 2. 接口事实（摘要）

完整表格见[核查报告 §2](<reports/接口与基线核查.md>)。要点：

1. 子弹位置是屏幕坐标 px，速度是 px/帧，逐逻辑帧 `position += velocity`（`third_party/th08/src/BulletManager.cpp:865`）。
2. 自机速度由 shot 文件字段给出，按下方向当帧即满速，无加速过程（`Player.cpp:781-790, 849-854`）；正常游玩 `framerateMultiplier = 1.0`。
3. 自机中心被夹取到 `[topLeft, topLeft+size]`，实测 `x∈[8,376]`、`y∈[16,432]`，夹的是**中心**而不是内缩后的碰撞盒（`Player.cpp:856-871`）。
4. 命中判定是子弹 AABB 对自机 hurtbox AABB（`Player.cpp:298-307`），hurtbox 半宽 0.825 px、聚焦不缩小（`Player.cpp:1576-1577`）。而且**每颗弹每逻辑帧只判一次**（`BulletManager.cpp:865` 位移后 `:933` 判定）。所以“安全”的硬谓词是逐帧盒重叠；连续扫掠比游戏更严，只能当余量工具，不能当硬门槛。D1 影子实测二者差异约 34%。
5. 旧 pilot 用“圆 + 0.5 px pad”近似。盒对盒恰好接触时（45°），圆几何差 1.17 px，pad 只抵掉 0.5 px，所以旧 pilot 在此刻仍报 **+0.67 px** 余量；它还把候选位置再内缩 0.825 px，比真实夹取更保守。
6. 旧 pilot 的计划视界是 20 游戏帧，且在全场 ≥40 px 时从第 8 帧起提前结束（`pilot.py:359-361`）；因此“horizon=10 步”不等于“真的看了 20 帧”。
7. 旧 pilot 按当前距离截断到 320 颗、并按 `near_radius=240 + |v|·20` 过滤（`pilot.py:230-243`）。300 px 外的静止弹墙会被整体丢弃（fixture `far-static-wall`：输入 24 颗，使用 0 颗）。
8. 旧链路里“弹池数量 vs 引擎计数器”不是同帧一致性证明：12000 条既有决策中只有 26.8% 完全相等，差值可达 ±416（`trace35.py:252-255` 已注明计数器会被原地改写）。
9. 12000 条既有决策里 11999 条恰好推进 2 帧，1 条推进 7 帧（记为 `frame_mismatch`）；速度分量 12000/12000 落在四个合法类别上，包含对角与聚焦对角。
10. ECL 可以把 `framerateMultiplier` 改成 1/N，并**同时改写已在飞行中的子弹速度**（`EclExIns.cpp:776-784, 859-882`）。这类“子弹时间”帧不支持匀速预测，必须显式标记为不支持，而不是照常给高置信。

## 3. 冻结决策

| ID | 决策 | 理由 | 落地位置 |
|---|---|---|---|
| F-01 | 长度单位 px、时间单位游戏帧、60 fps 名义；墙钟只用于性能 | 需求 §3 要求所有时间用游戏帧 | `contracts.COORDINATE_CONTRACT` |
| F-02 | 坐标原点为屏幕左上，playfield 从 `(32,16)` 起，+x 右、+y 下 | 与 `spec.PLAYFIELD_*`、内存读取和 obs 编码一致 | 同上 |

| F-04 | 中心夹取 `[8,376]×[16,432]`，包端点 | 与游戏夹取一致；不额外内缩 | `geometry.MoveModel.clamp` |

## 4. 分时危险表示（R1 设计，未实现）

**表示**：`DangerForecast` 是一组时间节点上的占据栅格，而不是一张并集图。查询接口语义：

- `risk(x, y, t)`：给定位置与时间偏移返回风险，节点之间线性插值，超出 `valid_until` 返回 `unknown`。
- `swept_clearance(p0, p1, t0, t1)`：两状态间扫掠，按 §2.5 的 AABB 口径，用于“这一小段到底撞不撞”。
- `dropped_entities / drop_reasons`：为省算力而忽略的实体数量与保守理由，必须能解释“为什么可以忽略”。

**首轮候选**（开发集可调，见 `configs/dev-v1.json`）：

| 区间（帧） | 节点间隔 | 用途 |
|---|---|---|
| 0–30 | 2 帧 | 近期精细避弹与执行复核 |
| 30–90 | 6 帧 | 走廊可行性 |
| 90–180 | 15 帧 | 出口关闭趋势 |

时间节点是**查询**网格，不是碰撞检查步长：碰撞仍按逐帧扫掠（或经误差界验证的细分）计算，否则 SC-08 会重演。

**不确定性**：线性预测只对已知实体、`framerateMultiplier == 1`、且未发生 ECL 变速的时段有效。远期节点必须带 `uncertainty`，且 `calibrated=false` 的长时预测**不得**用于硬拒绝动作（与开发计划 §3.2 一致）。

## 5. 路线与出口（R1 设计，未实现）

1. 粗层在 8/12/16 px 候选栅格上生成按时间的自由区域与可达后继；粗层只提候选，不裁决碰撞。
2. 每个首动作至少保留两个不同空间方向的候选，避免单走廊占满 beam。
3. 候选被转换成真实 18 动作序列，再用 §2.5 的扫掠逐段精验；**无法跟踪的候选不得提交**。
4. 出口必须通过“后继保持窗口”（首轮 ≥60 帧）验证；视界外是 `unknown`，不是安全。
5. 比较顺序：碰撞与最低余量 → 后继可行性 → 时间裕量/出口宽度 → 稳定性与局部余量；不得用加权和抵消碰撞风险。
6. `certified_blocked` 只在“存在保守可验证的排除证据”时使用（例如乐观自由空间上界仍不可达）。粗栅格被挡**不算**证据，因为离散化会漏窄缝。

## 6. 控制器（R1 设计，未实现）

状态机：`LOCAL → PREPARE_EXIT → EVACUATE → HOLD / REPLAN`，另有 `UNKNOWN` 与 `EMERGENCY`。

- 触发撤离用 `closure_eta − exit_eta − uncertainty_margin − latency_margin`，不依赖“已经贴脸”。
- 意图持续但每周期复核；“有效”= 位置仍在走廊内、路线未过期、且没有显著更优的安全出口。
- 局部搜索只在宏观允许的首动作与可跟踪走廊内进行，提交前再做一次扫掠复验。
- 走廊内全部动作立即碰撞时允许 `EMERGENCY` 越界并同周期重规划；必须记录越界与原因。
- bomb 只有一个仲裁入口（沿用旧语义：无路且还有资源），不允许旧 `pilot.act` 与新控制器各触发一次。
- 缺输入时没有“普遍安全”的默认动作：按 `observed_frame_age` 复用旧动作或停止正式评估，退出时释放按键。

### 10.1 D1 修订（2026-10-25）

- **F-05 修订**：硬安全谓词改为逐帧 AABB；连续扫掠降级为保守余量工具（依据 `BulletManager.cpp:865→933`，影子实测多报 34%）。

### 10.2 D2 修订（2026-10-25）

- **试验台语义**：逐帧 AABB + 1 帧沉降 + 生成窗口；`synth.advance` 是唯一的物理实现（试验台与参考共用），路线返回前必须精确重放。
- **证明与搜索分离**：`no_solution_certified` 只来自可复核的充分条件（初始重叠、静态格点覆盖、18 首动作全死）；离散状态图耗尽记 `budget_exhausted` 并注明“不是证明”。
- **开口构造**：墙的开口从边界向外放置盒子得到精确宽度（此前按格点跳过会宽出 `step-2*half`）。
- **余量现实**：参考能在 0.0034 px 余量下走钢丝；D4/D5 的路线比较与 D7 的判定都必须单列余量，不能只看成功率。

### 10.3 D3 修订（2026-10-25）

- **预测不是安全判据**：`DangerField.clearance` 只用于排序/预警；硬判定走 `geometry.frame_min_clearance`（逐帧 AABB）。
- **时间轴**：31 节点；`t>horizon` 返回 `None`（unknown），不是“安全”。
- **裁剪充分条件**：危险体扫掠包围盒与移动区不相交才可丢弃；超上限记 `over_cap` 并声明覆盖不完整。
- **膨胀与窄缝**：E-05 的 4.65 px 缝在膨胀 ≥1.5 px 时被封死；`max_inflation_for_gap` 是硬上界。
- **预算实测**：构建 2.7 / 3.1 / 5.2 / 8.4 ms（25 / 88 / 400 / 1,024 实体）；4 ms 目标只在 ≤100 实体达标。

### 10.4 D4 修订（2026-10-25，部分完成）

- **首动作条件搜索**：18 条 beam 各自返回 `feasible/immediate_collision/unknown`；只有“18 首动作全在首个决策内死亡”才是 `no_solution_certified`。
- **覆盖不完整即未知**：`dropped_over_cap>0` 的场直接 `model_unknown`，不在残缺场上给安全结论。
- **出口偏好未实现**：排序仍用“计划末端余量”代理；SC-15/16 在当前生成器下不迫使位移，因此“拒绝入坑”未被证明（D4 记 partial）。
- **时延**：P50 28–224 ms，超控制预算；D4b 做首层共享展开与剪枝。
- **视界对照**：E-05 在 4 决策下失败、20+4 决策下存活，是 FR-03 长视界的直接经验支持。

### 10.5 D5 修订（2026-10-25）

- **意图裕量用当前格**：路线终点若是安全区永不关闭，用终点格会把意图永远锁在 LOCAL。
- **模式按回合固定**：控制器逐决策重解析 `auto` 会让 SC-16 从 180 掉到 133 帧（与 D4d 同因）。
- **唯一 bomb 入口**：只有控制器可置 bomb 位，带冷却；规划器不再参与。
- **UNKNOWN 与 EMERGENCY 分开**：观测不可用 vs 无路且贴脸，回退动作与理由分别记录。

### 10.6 D6 记录决策（2026-10-25）

- **弹池不内联**：JSON 只存 `hazards_ref`（数量 + sidecar 索引），否则 90 决策 trace 约 4 MB；回放按 sidecar 取回。
- **预测只存摘要**：覆盖网格可由 sidecar + 配置重算，避免每条记录附 31×672 浮点。
- **真值与预测分色分层**：PNG 里危险盒、计划路线、实际轨迹、自机分别颜色，防止“图好看”被当成预测正确。
- **归因三分类**：clean / no_route_at_decision / hit_while_route_feasible，死亡窗口默认 8 决策。

### 10.7 D8–D12 修订（2026-10-25）

- **探针的接口缝**：`FrameSource`（`read/advance/done`）让离线 `ReplaySource` 与真机 `AdapterSource` 共用同一段决策循环；离线跑过的路径不等于真机跑过。
- **不可读观测不产生决策**：契约校验失败或来源返回 `None` 时写 `unreadable`，这是 E-11 超字段上限时的真实行为。
- **教师普查只做标签**：18 动作 × 24 帧保持普查是特权信息，只在离线用于配对分类，不进控制器。
- **学生评估按场景划分**：按样本随机划分会把同场景相邻帧泄进测试集（第一版 0.667 就是噪声）。
- **合成光栅不是视觉前端**：`vision.render_state` 从特权状态画图，真机要处理裁剪/阈值/HUD，这块明确未做。
