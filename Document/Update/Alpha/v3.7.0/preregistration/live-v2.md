# v3.7.0 真机预注册 v2（确认集）

- 日期：2026-10-25
- 状态：**已锁定，运行中**（`live_pairs.py --pairs 30`）
- 与 v1 的关系：v1 规定 ≥30 对但未定具体配置；v2 只补一件事——**把探索阶段选出的配置写死**，避免看到结果后再改。
- 约束：v2 运行期间**不允许**再改视界/续接/评分模式；结果按此配置一次性报告。

## 1. 为什么需要 v2

真机首轮探索（`data/d8-live-{baseline,subject-bombs,subject-12-bombs}.json`）是**探索集**，不是确认集：

| 配置 | 局数 | 死亡均值 |
|---|---:|---:|
| baseline | 6 | 1.33 |
| 新方案 h12/2（原冻结） | 4 | 1.50 |
| 新方案 h8/1 | 6 | 2.17 |
| 新方案 h6/1 | 4 | 0.50 |

四个配置都是看到结果后才比较的，直接拿 h6 的 0.50 去宣布 B-01 通过属于事后择优。所以：

1. 探索集只用来**选配置**（h6/1 在 4 局上最好，同时能保持接近实时：31–33 s / 1800 帧）；
2. 确认集用 v2 锁定配置重跑 30 对，**只看这一次**的结果。

## 2. 锁定配置

| 项目 | 值 |
|---|---|
| 游戏 | TH08 1.00d，practice stage 0，Lunatic，team 0 |
| 输入 | SendInput（前台）；PostMessage 会在菜单导航失败 |
| frameskip | 2（每决策 2 帧，33.3 ms 预算） |
| 每局窗口 | 1800 帧（30 s @60 fps） |
| 臂 | baseline = `AvoidPilot(PilotConfig())`；subject = 逃逸控制器 h6/1 |
| 配对 | 每对先 baseline 后 subject，同一进程、同一会话 |
| 对数 | 30（v1 的下限；不足则在报告里标 underpowered） |
| 主指标 | 每局死亡数 |
| 判定 | B-01：相对下降 ≥20% 且配对差 95% 区间上界 <0 |
| 禁止 | 运行中改配置；用确认集调参；把某个臂的失败局剔除 |

## 3. 记录与判据

- 逐对记录两臂死亡数、耗时；subject 另记 P50/P95、超时决策数、`same_frame`、完整率、帧跨度；
- 配对差 = subject − baseline（负值表示新方案更好）；同时报告正/负差值计数；
- 95% 区间用配对差的 t 区间（n=30）；
- 若出现单局超 120 s、`same_frame=False`、完整率 <0.99 → 该对记为**技术失败**并从分母剔除，同时报告剔除对数（>3 对则该次运行作废）。
