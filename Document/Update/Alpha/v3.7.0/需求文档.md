# v3.7.0 需求文档：范围弹幕预判与安全通道撤离

- 创建日期：2026-10-25
- 状态：需求定义完成，尚未实现、训练或验收。
- 前置版本：v3.6.0 / v3.6.1；不修改历史结论、阈值或产物。
- 本轮授权范围：建立新版本目录并定义需求；不启动游戏、采集、训练，不改控制代码。
- 版本目标：从“近弹到面前才微操”提升为“预测整片弹幕的时空覆盖，在出口关闭前选择并执行可达安全路线”。
- 最终产品约束：部署只读取框选画面；内存特权状态只能用于训练教师、标注和独立评估。

## 1. 问题、证据与待验证假设

### 1.1 用户报告的失败现象

敌人射出明显有范围的弹幕，自机会主动进入其覆盖区，或等子弹接近才小幅闪避，最终被整片弹幕封住。需要解决的是提前选位和撤离，不只是提高贴身反应速度。

本现象是本版本的需求来源，不等于已完成死亡归因。开发前必须通过逐帧轨迹区分：可提前撤离但没有撤离、预测错误、执行错误、输入不完整、真正无解，以及资源决策失败。

### 1.2 已核实的项目事实

1. [现有 pilot](<../../../../touhou_rl/pilot.py#L26-L55>) 描述了短时束搜索；[默认配置](<../../../../touhou_rl/pilot.py#L90-L115>) 为 frameskip=2、10 个规划步，即 20 游戏帧，约 0.33 秒，并存在近邻范围和弹数上限。
2. [v3.6.0 需求](<../v3.6.0/需求文档.md#L58-L77>) 已提出未来安全和出口，但提出需求不代表完成实现或验证。
3. [历史总索引](<../v3.6.0/总索引.md#L11-L22>) 记录 LeaveRegion 未通过既有门禁；[同一索引](<../v3.6.0/总索引.md#L110-L116>) 明确这些实验没有训练策略网络、没有新 checkpoint，也没有将战术接入正式控制环。
4. v3.6.1 是逐战术真机比较，不能据此宣称范围弹幕规避已经完成。

### 1.3 本版本检验的假设

- H1：短视界与局部截断可能漏掉尚远但即将封路的弹幕。
- H2：保持时间维度的危险预测，比单张密度图或静态区域标签更适合选出口。
- H3：比较完整可达路线及其后续出口，比只比较当前 clearance 更能减少可避免的封死。
- H4：具有中断机制的持续撤离意图，能减少左右摇摆和撤离途中返身。

以上均为假设；不得在实验前写成已证明根因。

### 1.4 路线强化补充：把战略避险作为主控制，而非微操加分项

2026-10-25 用户补充判断：多数死亡来自钻入必死弹幕群，零散子弹已基本可以闪避。本版本据此调整研发优先级，不等待先证明“超过一半死亡属于该类”才开始原型；归因审计与原型设计并行，比例结论仍需数据支持。

**激进的是控制权与提前量，不是碰撞风险。** 默认保留现有局部避弹器作为执行基线，把主要新增容量、标签和开发精力放在全场时空选路上，而不是继续优先优化最近子弹的 clearance。

主控制关系必须是：

```text
全场未来危险与可行后继分析
    → 先排除高置信的封死路线/进入动作
    → 选择安全走廊、目标和撤离时机
    → 局部避弹器在可行走廊内处理零散子弹
    → 每周期复核；紧急碰撞规避可越出旧走廊，但必须触发重规划与记录
```

原则如下：

1. **避免进入优先于进入后补救。** 高置信预测表明会丧失退路、且另有已验证可行路线时，应在动作筛选阶段拒绝该进入动作，不仅给它扣少量奖励。不能将所有不确定区域直接硬屏蔽；若候选全被排除，进入显式未知/无路线处理。
2. **未来可行性优先于局部最宽间隙。** 两条路径都满足当前碰撞与最低余量约束时，允许选择眼前 clearance 较小、但出口更宽、时序更稳健的路线。安全碰撞约束不能被未来收益抵消。
3. **主动提前撤离，不等触发近弹阈值。** 当关闭出口所需时间接近自身到达时间加误差/延迟余量时，即使身边空旷也必须启动；不把“已经危险”当作启动前提。
4. **宏观粗、局部细的更长视界。** 开发候选从 90 帧扩展到 120/180 帧（2–3 秒），远期用粗粒度可达性与不确定性，近期保留精细碰撞检查；不对长时匀速预测作虚假保证。具体预算和视界由开发集冻结。
5. **优先宽而稳健的撤离走廊。** 多条路线都可行时，优先选择时间裕量与后续出口充足的方案；不为较短路程或输出位置主动钻入依赖极限微操的弹群。若只有可靠窄缝可行，仍允许穿缝。
6. **局部能力保留为回归门。** “零散弹基本可闪避”作为工作假设，不作为已完成验收；不优先重训该能力，但必须防止新增宏观控制损伤它。

## 2. 目标与范围

### 2.1 必须达到的行为

1. 当前没有近弹，但未来会被宽幅弹幕覆盖时，能够提前开始撤离。
2. 左右出口代价不同时，选择时间上来得及、路径上可通过的一侧。
3. 撤离过程中保持意图，不为短期 clearance、输出或 P 点折返危险区。
4. 不能绕过整片弹幕但存在可靠内部缝隙时，允许穿缝；不硬编码“遇到大弹幕一律绕外侧”。
5. 识别目前安全但随后会被第二波封死的终点。
6. 路线失效时立即重规划；无路线与“不确定/搜索没找到路线”必须分开。
7. 不依赖更多 bomb、额外生命或不攻击来制造伪提升。

### 2.2 本版本不做

- 不同时重做清怪、P 收集、Boss 输出和完整资源经济系统。
- 不承诺完整关卡通关，也不把本专项通过写成 Stage 1 clear。
- 不以扩大网络规模、增加死亡惩罚作为唯一方案。
- 不默认更改动作空间、机体速度、碰撞判定或旧版 baseline。
- 不把所有激光、追踪弹、未知生成逻辑自动当作已支持。

## 3. 术语与可测定义

- **范围弹幕**：多个危险实体在未来时空中形成连续或近连续的通行限制；不是单纯“弹数多”。场景家族由测试清单预先给定，不用算法自己的输出定义测试分母。
- **安全路线**：从当前状态出发，满足移动动力学，且整个移动过程在对应时刻没有碰撞的动作序列；不能只检查终点。
- **可达出口**：在危险到达前可通过安全路线抵达，并在规定保持窗口内仍存在后续安全动作的区域。
- **可避免封死**：独立参考求解器确认起始时存在路线，而受测策略随后进入参考求解器判定无路线的状态。参考求解器超时或未知不算无解。
- **撤离启动时刻**：受测轨迹首次沿参考安全路线族取得预先规定的有效进展，且持续至少预注册的最小窗口；仅抖动一帧不算撤离。
- **最迟安全启动时刻**：在指定“延续原动作/停留”的延迟协议下，参考求解器仍能找到撤离路线的最后时刻。必须记录延迟协议，不能混用。
- **撤离提前量**：最迟安全启动时刻减去实际启动时刻；正值代表在最后机会前启动，负值代表已晚。

所有时间使用游戏帧；墙钟时间只用于运行性能。评估不得让未来真值进入部署观测。

## 4. 功能需求

| ID | 必须满足的需求 | 验证方式 |
|---|---|---|
| FR-01 | 输入含自机位置、判定范围、聚焦状态、移动速度、帧号和历史有效性；危险实体支持位置、形状、运动信息及置信度。缺失必须显式标记，不得当成空弹池。 | 契约与缺失输入测试 |
| FR-02 | 产生保留时间轴的未来危险表示，支持查询某位置、某时刻的风险和有效性。不得把所有未来占据简单并成永久禁区。 | 时间交叉、先危险后安全测试 |
| FR-03 | 首轮开发候选包含 15/30/60/90 帧的近期预测与 120/180 游戏帧的宏观视界，采用粗细多尺度计算；这是候选配置，不是已冻结最优值。内部碰撞检查需更细，不能仅检查少量时间切片；远期不确定性必须显式表达。 | 连续穿越、远期封路与预算测试 |
| FR-04 | 按自机与子弹实际几何、预测误差和输入延迟定义安全余量；误差膨胀策略需可配置、可审计。不可用过大膨胀封死所有可行缝隙。 | 几何与窄缝测试 |
| FR-05 | 远处但在预测视界内可达或会封出口的子弹必须参与判断；任何裁剪需给出保守依据，并记录裁剪数量、范围及未知风险。 | 远处弹墙、超弹数上限测试 |
| FR-06 | 搜索完整时空路线，考虑速度、对角线、focus、边界、frameskip 和动作延迟，验证路径而非只验证终点。 | 动力学与扫掠碰撞测试 |
| FR-07 | 路线比较先满足碰撞与最低余量约束，再以未来可行后继、出口宽度及时间裕量为主，最后比较局部余量、贴墙程度和切换成本。高置信封死且存在已验证替代路线时，在动作筛选阶段阻止进入；局部执行不能仅因眼前 clearance 更大而离开有效走廊，紧急越界需触发重规划。输出/P 收益不能突破安全约束。 | 死胡同、局部诱惑与紧急越界测试 |
| FR-08 | 输出撤离目标/路线及短期有效期。高层意图可持续，底层每个控制周期重新检查安全；不得锁死长时间按键。 | 持续横移、突然封路测试 |
| FR-09 | 支持提前横移、等待弹幕通过、穿内部缝隙与紧急重规划；不要求必须识别弹幕语义类别后才行动。 | 多家族行为测试 |
| FR-10 | 将“证实无路线”“搜索预算耗尽”“模型未知”分开。回退与 bomb 使用独立记录，受既有资源协议约束。 | 无解、超时和未知测试 |
| FR-11 | 每步输出预测版本、候选路线数、选择/拒绝原因、最小 clearance、出口 ETA、剩余时间裕量、意图切换/中止、回退及耗时。 | trace schema 测试 |
| FR-12 | 生成离线可视化：当前弹幕、分时预测、选中路线、出口、实际轨迹、晚撤离时刻。真值与预测分层显示。 | 失败回放人工复核 |
| FR-13 | 训练时可使用特权教师；视觉部署只能由历史/当前画面推断，独立检测任何内存或未来真值泄漏。特权结果与视觉结果分开验收。 | 输入依赖审计 |

## 5. 推荐结构与训练边界

推荐验证顺序：时间化危险预测 → 可达路线/出口规划 → 可中断撤离意图 → 局部执行。可以采用 MPC、分层策略或等价实现；需求不锁死某个网络结构。

先证明特权输入下能提前撤离，再学习视觉表征或蒸馏，避免感知误差与规划错误混在一起。若需要网络，至少应能表达时间危险、目标/路线、路线有效性及中断条件；具体头数和损失在设计阶段确定。

奖励或监督可以覆盖未来风险、可行后继空间和有效撤离进展，但必须：

- 保留死亡/碰撞真实终点，不用辅助指标替代生存；
- 不单纯最大化离最近子弹的距离；
- 不以贴墙不动、不射击、频繁 bomb 获取奖励；
- 方向稳定性不得压过紧急改道；
- 对成功提前撤离、误入弹幕和假安全终点都采样；必要时采用学生状态 DAgger。

## 6. 数据与评估约束

1. 数据来源分别标记：合成可控环境、特权教师、人类回放、学生状态、真机策略轨迹。
2. 人类回放的后续弹幕不一定适用于反事实动作：自机狙、击杀和新发弹会因动作改变。不得把原回放未来坐标直接当作所有候选路线的真值。
3. 合成测试必须有独立参考求解器/解析解；不能由受测规划器给自己生成唯一正确标签。
4. 参考求解器应使用更充分预算及独立校验，并保留 unknown。合成有界场景可用穷举小实例交叉验证。
5. 按整局、弹幕模板及其参数种子族分组切分，近重复、同回放和同种子不得跨 train/test。划分、代码版本和配置需哈希归档。
6. 测试集不得用于选视界、网格大小、风险阈值、奖励权重或选择最优 checkpoint。
7. 首轮真机候选协议沿用 TH08 1.00d、Lunatic、team 0、frameskip=2；开跑前复核速度、首步完整性、帧对齐与真实事件。
8. 帧不对齐、缺输入、未知实体、出生/无敌、bomb 清弹等必须分别记录。排除规则提前冻结，按臂公开排除量；不得仅删除失败轨迹。

## 7. 阶段门与交付物

| 阶段 | 工作 | 出口条件 |
|---|---|---|
| R0 需求 | 本文、验收定义、过程日志 | 本次交付；不代表实现通过 |
| R1 设计与预注册 | 接口/schema、碰撞口径、参考求解器、场景实例、预算、统计方案与冻结配置 | 评审确认；正式实验前冻结 |
| R2 特权原型 | 未来危险、路线搜索、意图与可视化；单元/合成测试 | 通过验收文档的契约与专项门 |
| R3 特权真机 | 固定 baseline 与新方案交错配对；独立审计安全与资源 | 真机安全和效果门全部通过 |
| R4 学生训练 | 教师标签、视觉或策略训练、必要的 DAgger；消融 | 独立留出集达标且无输入泄漏 |

任一阶段失败，保留配置、trace、结论和原因；改动后建立新修订，不改写历史结果。R3 未通过不扩大为完整多战术 RL 联合训练。

## 8. 成功声明边界

- R2 通过：仅称“受控场景中证明提前撤离可行”。
- R3 通过：仅称“指定特权协议下改善范围弹幕规避”。
- R5 通过：才可称“指定视觉部署协议下该能力通过”。
- 超时、样本不足、参考标签未知或基线事件数过少，记为 inconclusive/underpowered，不算通过，也不强行算失败。
- 本版本的具体验收公式、场景矩阵与拟定阈值见[验收标准](<验收标准.md>)；它们必须在正式实验前冻结，不能看结果后改到通过。
