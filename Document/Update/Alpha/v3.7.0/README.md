## 本版本只解决什么

**让自机在整片弹幕封路之前，选择可达的安全路线并提前撤离，而不是子弹贴脸以后才小幅闪避。**

2026-10-25 路线强化：**宏观选路是主控制，局部避弹是执行层，不是给现有微操附加一个很弱的区域奖励。** 有已验证替代路线时，主动阻止高置信的入坑动作；允许牺牲部分眼前空隙换取更稳健的出口，但不突破最低碰撞余量。开发宏观视界扩展至 120/180 游戏帧候选；零散避弹保留为独立回归门。用户关于主要死因的观察作为优先工作假设，比例仍需审计。

- 预测必须保留时间轴，不能把未来弹幕简单叠成永久禁区。
- 安全目标必须走得到，路径和后续退路都要检查。
- 有绕外侧的机会就提前绕开；只有内部缝隙可行时允许穿缝。
- 撤离意图持续但可中断，局部控制每周期复核。
- 先证明特权原型有效，再训练/蒸馏视觉学生；最终部署仍只看画面。

## 与旧版本的关系

沿用旧版状态、输入与评估能力，不覆盖旧数据或结论。[v3.6.0 / v3.6.1 总索引](<../v3.6.0/总索引.md>) 中 LeaveRegion 的失败仍有效；本版本提出新的时间化表示和路线级验证，不能把历史未通过的战术直接接入控制环。

D0 的三条硬结论（详见[核查报告](<reports/接口与基线核查.md>)）：

1. 旧 trace 的 `complete=true` **不等于**弹池与状态同帧：12000 条决策中弹池数量与引擎计数器只有 26.8% 完全相等。
2. 旧 pilot 的 20 帧视界可退化为 8 帧，320 颗/240 px 截断会把 300 px 外的静止弹墙整体丢弃（fixture 输入 24 颗、使用 0 颗）。
3. 碰撞是盒对盒；旧 pilot 的圆近似在 45° 盒接触时仍报 +0.67 px 余量。

D1 的两条修正（详见[D1 报告](<reports/D1-适配层与影子扫掠.md>)）：

1. 游戏**逐帧**判定碰撞（每颗弹每帧一次），连续扫掠会多报约 34%；硬谓词必须是逐帧 AABB。
2. 按键后第 1 帧仍用旧速度（输入沉降 1 帧），旧 pilot 计划路径与实际执行路径不同；2,903 对快照中 96.62% 可由“旧速度 1 帧 + 新速度”精确重建。

D2 的三条交付与发现（详见[D2 报告](<reports/D2-合成试验台与参考求解器.md>)）：

1. 试验台是可判定的世界：逐帧 AABB、1 帧沉降、生成窗口；17 族 + 20 边界实例全部可执行且确定性可复现。
2. 参考求解器把 `no_solution_certified`（覆盖证明/初始重叠/18 首动作全死）、`budget_exhausted`、`model_unknown`、`feasible` 分开；E-06 的 0.65 px 缝只报预算耗尽，不宣称无路。
3. 离散碰撞可被“蹭”过去：第一版 E-06 存在最小余量 0.0034 px 的合法路线，地板因此加厚到 3 排；多数族的可行路线余量 <0.5 px，D4/D5 必须把余量当独立项。

D3 的三条实测与边界（详见[D3 报告](<reports/D3-分时危险表示.md>)）：

1. 预测保留时间轴：31 个节点（2–30/2、36–90/6、105–180/15）；同一位置 t=10 危险、t=40 空闲分别可查，不是并集。
2. 裁剪有充分条件：扫掠包围盒不进入移动区才丢；SC-09 的 300 px 外弹墙 88 颗保留 86 颗，SC-12 的 1,671 颗丢弃全部带 `irrelevant`/`over_cap` 理由。
3. 构建时延实测 2.7 ms（25 实体）→ 5.2 ms（400）→ 8.4 ms（1,024 上限）；工程目标 4 ms 只在 ≤100 实体达标，D4 若每决策构建会撞 33.3 ms 门。

D4 实测与未达标项（详见[D4 报告](<reports/D4-路线搜索.md>)）：

1. 视界是实的：E-05 用 4 决策规划在第 47 帧被压升地板追上；20+4 决策后存活到 60 帧。同一搜索、不同视界。
2. 失败语义正确：E-06（0.65 px 缝）两种视界都不假装通过；覆盖不完整的场直接 `model_unknown`；只有 18 首动作全死才 `no_solution_certified`。
3. 未达标：SC-15/16 当前不迫使位移（原地不动也能活），所以“拒绝入坑/出口偏好”没有被证明；规划 P50 28–224 ms 远超 33.3 ms。

D7 的结论（详见[D7 报告](<reports/D7-开发集验收.md>)）：

1. **“配置互补”是假象**（D7f）：SC-15 与 E-05 的“互补失败”根因是长视界下 18 条候选路线终点完全相同、排序并列，`sort` 保持 `ACTIONS` 原序而 `ACTIONS[0]` 是 **idle**。加“首动作朝目标方向的投影”作为第四排序键后，E-05 @12×2 从 31 → 60 帧，SC-15 @12×2 保持 180 帧。
2. **dev 12 种子八门全通过**：A-02 1.0（81/81）、A-04 相对死亡下降 **89.5%**（19→2，95 对），两例死亡是 E-06/E-11 这类**应当失败**的实例。
3. **formal v2 八门全通过**（137 实例，16 worker 137 s）：A-01/A-02(117/117)/A-03(分母 19)/A-04(92.3%)/A-05/A-06/A-07/A-08。第一份 formal（v1）因 A-03 分母仅 1、A-07 `not_computed` 被**声明作废并留档**（`data/d7-formal-eval-v1-void.json`）；作废理由是测量缺口，参数未变、未见结果后调参。
4. **配置冻结**为 12×2（`configs/formal-v2.json`，含 void_note 与 limitation）；20×4 仍在 SC-15 上 126 帧失败。
5. **过程负结果保留**：路线延续（D7d）与走廊管状承诺（D7e）都没修好 SC-15，真正原因是排序并列取到 idle；`corridor_by_time` 仍作为真实输出保留。
