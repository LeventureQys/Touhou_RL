## 1. 两条修正性事实

### 1.1 碰撞是“每帧一次”的盒检测

`BulletManager::OnUpdate` 先 `position += velocity`（`BulletManager.cpp:865`），随后对每颗弹调用一次 `Player::CheckBulletCollision`（`BulletManager.cpp:933`）。`CheckBulletCollision` 做的是子弹 AABB 与自机 hurtbox AABB 的重叠测试（`Player.cpp:298-307`）。

推论：

1. **逐帧盒重叠**是游戏的硬安全谓词；两帧之间的穿越（tunneling）游戏本身不检测。
2. 连续扫掠比游戏**更严**：会把子弹在帧间“跳过”自机的情况判成碰撞。影子数据显示这类多报占 34.3%（21/61、35/102）。
3. 因此 D0 的 F-05 需要修订：**硬判定用逐帧 AABB，连续扫掠作为保守余量工具**；否则规划器会封死游戏本来允许的窄缝（正好撞上 FR-04/SC-03 的反例）。

### 1.2 执行路径包含 1 帧输入沉降（已量化）

旧 trace 的相邻两次位置差有 34.1% 无法用“新速度 × 帧数”解释。真实规律是：

```text
第 1 帧：仍按上一次按键的速度
第 2…N 帧：按本次按键的速度
每帧都按 [8,376]×[16,432] 夹取
```

用该模型重建 2,903 对相邻快照：**96.62% 在 0.01 px 内完全吻合**（简单模型只有 65.86%），P95 残差 0.001 px，最大 8 px 的少数与死亡/重生相邻。排除死亡与无敌帧后，三个 teacher 局的重建吻合率为 **99.2% / 98.6% / 99.3%**。

这同时说明：**旧 pilot 的计划路径 ≠ 游戏执行的路径**。它假设新动作从第 1 帧生效，而游戏至少晚 1 帧。这是模型误差，不是随机噪声。

## 2. 适配层（`adapter.py`）

| 机制 | 行为 |
|---|---|
| 同帧证明 | 读 状态A → 读弹池 → 读状态B；仅当 `gameplay_frame(A) == gameplay_frame(B)` 才接受；最多 4 次，否则降级 |
| 读失败 | `hazards=None` + `missing_reasons="bullets: read failed"`，**不是**空池 |
| 帧倒退 | 与 `last_frame` 比较，倒退即 `UNREADABLE`，不当作“现在” |
| 持久不稳 | `hazards=None` + `"frame: state and pool never agreed on gameplay_frame"` |
| 空池 | `hazards=()`、`bullet_pool_count=0`、完整性 `complete` |
| 逐轴半宽 | 保留 `half_size` 的 (x,y)，不折叠成 max（折叠会把子弹变方块） |
| 无敌/濒死 | `player_state==3` 记 `invulnerable`；`==2` 仍允许读，但由上层跳过 |
| 子弹时间 | 读不到 `framerateMultiplier` 时记覆盖缺口 `framerateMultiplier: not observable`；≠1 时记 `bullet_time_active` |

`to_observation()` 产出的记录会立刻过一遍 `validate_document`，单位契约不一致就直接抛错，而不是写进 trace 再说。

## 3. 影子扫掠（`shadow.py`）

对每个决策，用**上一次快照**（旧 pilot 的输入）+ **执行路径模型** + 线性传播的弹池，计算：

- `frame_collisions`：逐帧盒重叠（游戏语义）；
- `swept_collisions`：连续扫掠（保守上界）；
- `reported_safe_but_frame_collision`：旧 pilot 自报 clearance > 0 却逐帧重叠；
- 死亡邻近：碰撞是否落在记录死亡前 3 个决策内。

### 3.1 teacher 臂（3 局，纯 pilot 控制）

| 指标 | 值 |
|---|---:|
| 检查决策 | 6,914 |
| 跳过：无敌 / 濒死 | 1,995 / 88 |
| 路径重建吻合 | 99.2% / 98.6% / 99.3% |
| 逐帧重叠 | 40 |
| 其中旧 pilot 自报安全 | 39 |
| 连续扫掠重叠 | 61 |
| 仅连续扫掠报警（游戏不会判） | 21（34.4%） |
| 落在死亡前 3 决策内 | **1**（该局共 5 次死亡） |
| 重叠深度中位数 / P95 / 最深 | −0.98 / −0.10 / −5.30 px（基于每局最多 12 条示例事件，共 33 条） |

### 3.2 T2 两臂（4 局，跳过 175 条被战术覆盖的决策）

| 指标 | 值 |
|---|---:|
| 检查决策 | 8,658 |
| 逐帧重叠 | 67 |
| 其中自报安全 | 63 |
| 仅连续扫掠 | 35（34.3%） |
| 落在死亡前 3 决策内 | 0 |

### 3.3 这些数字能说明什么、不能说明什么

**能说明**：

- 连续扫掠与游戏谓词的差异是稳定可测的（约 34%），所以二者不能混用。
- 旧 pilot 的“安全”与逐帧盒重叠存在系统性分歧（39/40、63/67），量级约 0.5%。分歧方向与 D0 的几何差异一致。
- 路径模型足够准（P95 0.001 px），影子不是被“位置算错”污染的。

**不能说明**（因此本轮不据此写死亡率或归因）：

1. sidecar 只存一个半宽（`max(half_x, half_y)`），影子把它当**方块**，对长条弹是明显高估；中位重叠深度 0.98 px 正好落在这种高估的量级里。
2. 只有 1/40 与死亡邻近。若这些重叠真是“本该死亡”，应该有更多死亡；因此它们更可能是**上界筛查**里的假阳性。
3. 死亡前一瞬新生成的子弹不在快照里，影子无法看到。
4. 旧 pilot 的计划与执行差 1 帧（§1.2），所以“自报安全却重叠”里有一部分是计划路径与执行路径不同，而不是几何错。

结论：影子是一个**上界筛查器**，可用于发现“旧模型明显看不到的几何”，不能当作死亡归因工具，也不能写进任何验收比例。

## 5. 余量上界（给 D3 的硬约束）

E-05/E-06 的窄缝换算成对膨胀系数的约束：

- 缺口 = hurtbox + 3 px（宽 4.65 px）→ 最大可用膨胀 `4.65/2 − 0.825 = 1.50 px`；膨胀 **≥1.5 px 就会封死这条缝**。
- 缺口 = hurtbox − 1 px（宽 0.65 px）→ 上限 0，本身不可行。

因此 `configs/dev-v1.json` 增记 `margin_upper_bound_px = 1.5`（几何上界，不是调参结果）。D3 的误差膨胀只能在这个上界内分配，超出就必须显式记录“该场景不可行”而不是声称规划器找到了路。
