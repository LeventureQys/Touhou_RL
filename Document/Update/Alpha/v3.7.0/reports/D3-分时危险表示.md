## 1. 表示与查询

| 能力 | 实现 | 测试 |
|---|---|---|
| 时间轴 | 31 个节点：2–30 每 2、36–90 每 6、105–180 每 15 | `test_time_nodes_cover_the_three_bands` |
| 不并集 | 同一位置 t=10 危险、t=40 空闲必须分别可查 | `test_time_axis_is_not_a_union` |
| 点查询 | `clearance(x,y,t)` 精确盒间隔（不含膨胀）；`inflation` 可显式覆盖 | `test_inflation_is_bounded_by_the_gap_geometry` |
| 逐帧查询 | `frame_clearance` = 游戏谓词，恒不带膨胀 | 与 `synth.frame_clearance` 50 次随机对照，误差 <1e-9 |
| 保守扫掠 | `swept_clearance` 逐段调用 `geometry.swept_box_clearance` | 帧间穿越：t=2/4 安全、扫掠为负 |
| 宏观占据 | 31 节点 × (24×28) 格，差数组栅格化 | `record_matches_the_contract` |
| 支持域 | `t>180` 或 `t<0` 返回 `None`，不是“安全” | `test_beyond_the_horizon_is_unknown_not_safe` |
| 不确定性 | `0.02 px/帧` 线性增长；>90 帧不计入 calibrated | `test_uncertainty_grows_and_calibration_is_declared` |

**预测不是安全判据。** 规划器只能用 `clearance`/`occupancy` 排序和预警；真正的“这一步撞不撞”必须走 `geometry.frame_min_clearance`（逐帧 AABB，D1 修订）。E-05 的 4.65 px 缝在膨胀 ≥1.5 px 时被封死，这就是“过大膨胀”会伤到 FR-04 的具体机制。

## 2. 裁剪与覆盖

| 规则 | 行为 |
|---|---|
| 无关裁剪 | 危险体的扫掠包围盒在视界内不进入移动矩形 → 丢弃，理由 `irrelevant`（充分条件：自机永远在矩形内） |
| 数量上限 | 超过 `max_entities` 后按“最早进入”保留，其余记 `over_cap` 并声明覆盖不完整 |
| 记录 | `dropped_entities` + `drop_reasons` 随记录输出；SC-12 的 1,671 个丢弃不会被静默吞掉 |

实测：SC-09（远处弹墙）88 颗中保留 86 颗，只丢掉 2 颗真正在移动区外的；SC-12（区域填充）2,695 颗中丢 204 颗无关 + 1,467 颗超上限、保留 1,024 颗。

## 3. 计时实测（单线程，无游戏）

| 场景 | 危险体 | 保留 | 构建 P50 / P95 | 查询 P50 |
|---|---:|---:|---:|---:|
| SC-01 扇 | 25 | 25 | 2.71 / 2.93 ms | 11.5 µs |
| SC-09 远墙 | 88 | 86 | 3.08 / 3.43 ms | 13.6 µs |
| 400 实体 | 400 | 400 | 5.17 / 5.87 ms | 24.3 µs |
| SC-12 填充（上限 1024） | 2,695 | 1,024 | 8.41 / 9.04 ms | 45.1 µs |

工程目标（开发计划 §7）是预测 4 ms。**结论：在 ≤100 实体时达标（2.7–3.4 ms），400 实体以上超标（5.2–9.0 ms）**。这是实测，不是估算。

第一版用“逐危险体 Python 切片”栅格化，400 实体时 9.9 ms；改成差数组 + 二维前缀和后 5.2 ms。剩余成本主要是 31 个节点各自的掩码与栅格分配。

## 4. 发现

| ID | 内容 | 处理 |
|---|---|---|
| D3-01 | 覆盖栅格化是主要成本；差数组把 400 实体从 9.9 ms 降到 5.2 ms | 已落地 |
| D3-02 | 裁剪必须用“扫掠包围盒 vs 移动区”的充分条件，不能按当前距离取最近 N（旧 pilot 的做法） | 已实现；SC-09 保留远处弹墙 |
| D3-03 | 预测构建在 400 实体时超 4 ms 目标 | 记入预算表；D4 若每决策构建会撞 33.3 ms 门，需降节点数/只在宏观节点存覆盖/或复用上一周期 |
| D3-04 | 远期节点不可 calibrated，但当前记录只有一个 `calibrated` 布尔值 | 查询层用 `calibrated(t)` 逐点判断；记录级布尔只表达“全窗口是否可信”（默认 False） |
| D3-05 | 危险体的 `spawn/despawn` 在真机快照里没有 | 适配器给 `valid_until`；真机轨迹会退化成“一直有效直到视界”，这是 D8 要审计的覆盖缺口 |
