# v3.7.0 具体开发计划：宏观选路主导、局部避弹执行

- 日期：2026-10-25
- 状态：开发计划已定义；下述代码、命令入口和实验产物均为**拟新增**，不是已实现。
- 依据：[需求文档](<需求文档.md>)、[验收标准](<验收标准.md>)。
- 本轮只编写计划，不启动游戏、训练或修改控制代码。
- 首个工程终点：特权原型在“周围暂时安全、出口即将关闭”场景中提前离开，并阻止局部最大 clearance 将自机引入死胡同。

## 1. 技术决策与不变项

### 1.1 主路线

不先训练一个更大的端到端 PPO。先实现一个可解释的时空规划教师，验证“拒绝入坑 + 提前撤离”确实改善生存，再生产标签和训练视觉学生。

```text
完整、同步的当前状态/历史
  → 全场分时危险预测（近期细、远期粗）
  → 多个走廊/出口候选与实际动作路线验证
  → 首动作条件下的后续可行性、置信度和未知原因
  → 拒绝高置信入坑动作，选择稳健安全路线
  → 可中断撤离意图 + 受路线约束的局部动作搜索
  → 本周期动作扫掠复验
  → 提交一次动作，读取新状态，重规划
```

“激进”指宏观控制优先与撤离更早，不是更低碰撞余量、更频繁 bomb 或无条件高速横移。

### 1.2 代码隔离策略

以拟新增包 `touhou_rl/escape/` 承载本版本。保留旧控制器作不可静默改变的 baseline，不把新逻辑混进旧战术判定。

已查阅的复用边界：

- [pilot](<../../../../touhou_rl/pilot.py#L221-L244>) 在准备输入时按距离截断弹数；宏观层不能直接依赖这个截断结果。
- [pilot 的搜索](<../../../../touhou_rl/pilot.py#L288-L361>) 在动作终点计算 clearance，且可在附近安全时提前结束；不能简单把 horizon 改到 180 就当成长视界规划。
- [候选评分接口](<../../../../touhou_rl/pilot.py#L370-L412>) 只给首动作分数，不返回可验证完整路线。因此不能先调用旧 act，再把结果强行朝航点偏转。
- [环境配置](<../../../../touhou_rl/env.py#L38-L73>) 已有 raw bullet、boss 和输入证据开关，可作为特权适配器的接入点。
- [trace 契约](<../../../../touhou_rl/trace35.py#L31-L80>) 有独立 schema 和 Snapshot。新版本写扩展 sidecar，不把旧 schema 静默换义。
- [既有 probe](<../../../../touhou_rl/probe35.py>) 的战术列表受固定配置约束。新建 probe37，不修改旧版战术名单和预注册参数。

局部搜索尽量复用已验证的移动常量、动作编码与评分语义，但首轮采用隔离的受约束执行器。若后续需要抽取公共纯函数，单独提交兼容性改动，用 golden fixtures 证明旧结果未变。

## 3. 先冻结的接口草案

实现前在 R1 定稿 schema；以下名称可以在设计评审中调整，含义不能静默变更。

### 3.1 输入 `EscapeObservation`

- `schema_version / episode_id / decision_id / frame_id / source`。
- 自机：`position_xy / hit_shape / focus / speed_model_id / alive / invulnerable`。
- 控制：`frameskip / observed_frame_age / action_latency_frames / previous_action`。
- 子弹：`position / velocity / collision_shape / track_id? / motion_model / confidence / valid_until`。
- `completeness / missing_reasons / unsupported_hazards / coordinate_contract`。
- 真机只包含当前与历史；未来真值仅存在离线评估独立对象中。

空弹池与读取失败是不同状态。无可靠 track_id 时标记 unknown，不把槽位复用误认成同一颗弹。首轮已知弹做匀速预测，利用历史残差估计可信时间；未知新发弹和交互式追踪弹不会因当前弹池完整就变成可预测。

### 3.2 输出 `DangerForecast`

- `time_nodes_frames / coverage / model_version / valid_until / uncertainty`。
- 位置—时间风险查询，以及两状态间扫掠碰撞查询。
- 为计算节省而忽略的实体数量与保守排除理由。
- 预测置信度分为校准/未校准，未校准长时预测不可用于确定性入坑否决。

### 3.3 输出 `RoutePlan`

- `route_id / action_sequence / position_time_knots / corridor_by_time`。
- `first_action_status[18]`：`feasible / certified_blocked / unknown / immediate_collision`；保留判断支持域、失败原因和验证证据。
- `min_clearance / exit_eta / closure_eta / slack / continuation_window`。
- `confidence / valid_until / alternatives / node_budget / elapsed_ms`。

重要限制：有限 beam 只找到某条安全路线，可证明“找到可行候选”；没有找到不能证明“该动作无路”。`certified_blocked` 仅在支持域内存在保守可验证的排除证据时使用。利用乐观自由空间上界仍不可达，可作无路证据；普通粗栅格被障碍堵住不够，因为离散化可能漏窄缝。

### 3.4 输出 `ControlDecision`

- 动作仍为现有 `[move, shoot, focus, bomb]`，移动/聚焦组合仍为 18 类。
- `intent / route_id / accepted_action / rejected_actions / reason`。
- `emergency_override / fallback / bomb_reason / deadline_miss / timing_breakdown`。
- 计划、控制器请求动作、实际提交动作及输入证据必须可对齐；拒绝入坑门以实际提交和后续轨迹为准。

## 4. 关键算法的首轮落地方式

### 4.1 预测：全场、分时、带不确定性

- 首轮不做弹幕语义分类器，直接处理物理危险与通行限制。
- 候选时间网格：0–30 帧每 2 帧，30–90 每 6 帧，90–180 每 15 帧；开发集同时比较 90/120/180 帧终点。时间节点不是碰撞检查步长。
- 宏观栅格先比较 8/12/16 px；近场保留实际实体几何，避免窄缝被粗图抹掉。所有数值是开发候选，须经预算和开发集冻结。
- 对线性段用相对运动解析最小距离/相交检测；非线性段采用有误差界的细分。仅检查端点不可接受。
- 实体按预测扫掠体与自机可达包络的交集裁剪，不按当前距离只取最近 N 颗。上限触发则显式降级，不报完整覆盖。

### 4.2 选路：先候选，后真实动作精验

1. 建立按时间排序的自由区域和可达后继，生成多个目标/出口，而非只取单一最大连通区。
2. 在每个首动作下保留不同空间方向的候选，避免同一走廊占满 beam。
3. 粗图提出路线，再转换为真实 18 动作序列并精验完整路径；无法跟踪的候选不能提交。
4. 出口须经过后继保持窗口验证，避免把视界末端当成永久安全；视界外风险写 unknown。
5. 安全层过滤后按“后继可行性 → 时间裕量/出口宽度 → 路线稳定性 → 局部余量与位置偏好”分层比较，不用一个未校准的加权和抵消碰撞风险。
6. 高置信入坑动作仅在存在已精验的替代路线时硬拒绝。弱证据只影响偏好并触发进一步搜索，不夸大为物理无解。

### 4.3 控制：意图持续，按键不锁死

状态机：`LOCAL → PREPARE_EXIT → EVACUATE → HOLD/REPLAN`；另有 `UNKNOWN` 和 `EMERGENCY`。

- 当 `closure_eta - exit_eta - uncertainty_margin - latency_margin` 接近冻结触发阈值时启动撤离，不依赖近弹距离。
- 每决策检查当前位置、剩余路线与路线年龄；仅在仍有效且无显著更优安全出口时延续意图。
- 局部搜索只在宏观允许的首动作与可跟踪走廊内优化；已选动作再次做扫掠复验。
- 若走廊内动作都会立即碰撞，允许紧急越界并同周期重规划；没有预算则执行经当前步验证的最低风险回退，记录其不提供长期保证。
- 首轮资源使用维持旧版约定，不新增“预测可能封路就自动 bomb”规则。bomb 保持唯一仲裁入口，避免旧 pilot.act 与新控制器各触发一次。
- 对缺失输入没有普遍安全的默认动作；按观测年龄给出受限复用或停止正式评估，并在退出时释放按键。

## 6. 实施顺序与最小可见里程碑

### M0：接口与试验台

D0 → D1 与 D2 并行。死亡归因可使用已有有效轨迹同步开展，不作为原型启动的先决条件。已有 trace 缺字段时先报告缺口，不能反复等待大规模补采。

### M1：第一个能说明路线正确的闭环原型

D3 → D4 → D5，D6 同步推进。首先只盯三个开发实例：

1. SC-15：眼前更宽的方向最终封死，主动选另一条有出口的路线。
2. SC-16：身边空旷仍提前解除 focus 横移（仅在真实动力学下需要时）。
3. SC-17：零散弹仍由局部能力正常处理。

产物必须是“同一实例 baseline 与新方案的实际轨迹 + 分时预测 + 决策理由”，不是只有危险热图。三个开发实例通过仅标记 smoke pass，不代表 A 门通过。

### M2：合成全矩阵通过

完成 D2 全家族、D7 正式测试。按 17 家族各至少30个种子，最低510个实例槽位；其中 SC-12 无解和 SC-17 回归分母独立，不能合并稀释。至少20个可解析/人工核验边界实例另计。SC-17 非劣检验可能需要更多样本，样本量由开发基线和预注册功效分析决定。

### M3：真机值得继续训练的证据

D8 开发影子/小样本排障 → D9 独立正式配对。影子结果只检验预测与运行可靠性，不是反事实生存提升。至少30对是下限，不保证统计功效；不得看到不显著后随意追加到显著。

### M4：视觉学生与部署

D10–D12 只在特权控制路线通过后展开。不强行要求一步端到端：先让视觉输出有置信的时空危险/自机状态，接已验证规划器；必要时再蒸馏高层选路以降低时延。不能训练视觉高层后仍在底层偷用内存子弹避弹。

**不承诺固定天数。** 每个里程碑用上述可验证产物结算；真实游戏采集和统计样本量是实际耗时的重要因素。开发阶段可并行，真机控制与资源占用必须串行。

## 7. 预算、降级与停止规则

端到端仍服从 P95≤33.3ms、截止时间错过率≤1%的既有拟定门。

首轮工程预算目标（不是实测值）：适配1ms、预测4ms、宏观搜索8ms、局部与扫掠5ms、同步提交与轻日志3ms，合计约21ms，余量留给抓帧/调度；视觉阶段需重新分配，不能继承特权耗时结论。

优化顺序：缓存静态几何 → 向量化危险查询 → 安全裁剪 → 缓存短期仍有效路线 → 降低宏观候选数/远期分辨率。**不得通过省略扫掠、静默截断危险或放慢游戏达标。**

只有旧路线重新验证后仍有效，才可跨周期复用。宏观层可低频完整更新，但近期安全每周期重算，预测风险突变立即强制更新。

| 失败现象 | 优先定位 | 停止/处理 |
|---|---|---|
| 全部候选都不可行 | 过度膨胀、粗网格漏缝、预算、真实无路 | 分清 unknown 与 certified；不直接 bomb 或宣称必死 |
| 提前撤离仍撞弹 | 预测、时序、扫掠、速度/输入执行不符 | 修输入/模型，不先加死亡惩罚 |
| 躲第一波撞第二波 | 后继窗口/新发弹不可知/视界终点假安全 | 支持域与误差审计，补场景或建模；不读未来作弊 |
| 为躲大弹幕损伤零散弹 | 走廊过硬、局部搜索缺失、紧急越界失效 | A-08 未过不得进入正式效果结论 |
| 合成过、真机不过 | 交互发弹/新生弹、几何、延迟、实体覆盖差异 | 保留R2结论，停止学生训练，修特权侧 |
| 真机仅更多bomb活下来 | 资源收益混杂 | B-03失败，不能称路线有效 |
| 特权过、视觉不过 | 自机定位/速度估计/未来危险漏检 | 保留分层报告，不回退偷用特权输入 |
