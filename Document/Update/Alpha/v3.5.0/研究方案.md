# v3.5.0 研究方案：因果战术规划、区域级避险与主动清怪

- 日期：2026-10-24
- 前置：[v3.4.0 研究方案](<../v3.4.0/研究方案.md>)、[v3.4.0 Stage 0 报告](<../v3.4.0/Stage0报告.md>)
- 版本性质：**新路线研究方案，不是执行授权**；具体执行以[执行计划](<./执行计划.md>)为准。
- 第一终点：M3，TH08 Lunatic Stage 1 clear；在 M3 通过前不进入全局通关优化。

---

## 1. 本版本为什么重新开路线

v3.4.0 已确认两个事实：

1. 现有搜索教师可以在部分局中存活到约 9,000 帧，并击破 Boss 的前一阶段；
2. 现有教师仍然会在大范围攻击中进行局部快速摆动，未主动清理普通敌人，也没有在 P 槽未满时主动收集 P。

因此问题不再是单纯的“看不见子弹”或“短期 clearance 不够”，而是：

> 当前策略只优化“当前动作未来 20 帧是否碰撞”，没有建模“当前动作会如何改变未来几秒的弹幕、敌人、power、生命与安全区域”。

v3.4.0 的“手写完整 Oracle → 再学习”的路线仍然过于粗粒度；v3.5.0 改为先实现可解释的**因果战术教师**，再决定是否需要 Oracle、价值学习或蒸馏。

---

## 2. 新的核心假设

### H1：大范围攻击必须做区域级规避

扇形只是例子，不把攻击模式硬编码成“扇形检测”。所有大范围攻击统一表示为时间变化的危险区域：

```text
R(t) = 未来 t 帧内被攻击覆盖的空间集合
```

R(t) 可以是：

- 扇形或锥形；
- 横向/纵向弹幕墙；
- 环形或收缩区域；
- 多个敌人攻击区域的并集；
- 具有明显扩张方向的散射攻击；
- 暂时无法识别形状但能由 bullet flow 估计出的高密度区域。

玩家不应在 R(t) 内寻找“局部最优小路”，而应：

1. 在区域形成早期识别其扩张方向；
2. 选择一个连通的外部安全区；
3. 尽早离开整个区域；
4. 离开后才恢复局部躲避和攻击。

### H2：清怪是未来安全性的控制动作

敌人不是静态障碍物，而是未来弹幕的生成源。应估计：

```text
enemy_clear_value =
    未来弹幕生成量
  + 敌人持续存活时间
  + 对安全区域的封锁程度
  + 击杀后的 P / power 收益
  - 到达路线风险
  - 放弃当前安全区的代价
```

主动清理高威胁敌人可能牺牲少量当前 clearance，但会降低未来 60–240 帧的弹幕密度，属于合理的长期投资。

### H3：P 点是条件性资源投资

P 槽未满时，P 点提高攻击力，进而缩短敌人和 Boss 的存活时间；但收集路线本身有风险。

```text
collect_value =
    未来 DPS 增益
  + 未来弹幕减少量
  - 收集路线风险
  - 当前安全区损失
  - 生命/bomb 资源风险
```

只有满足以下条件时才主动收集：

```text
power < power_max
+ 屏幕内存在可收集 P
+ 到达 25% 收集线的路线不穿越高风险区域
+ 预计 DPS 增益大于当前风险
```

power 已满时，不为 P 点冒险。

### H4：安全、清怪、收集必须使用多时间尺度

| 时间尺度 | 作用 | 示例 |
|---|---|---|
| 1–4 帧 | 电机控制 | 当前马上要撞弹时向哪边移动 |
| 20–60 帧 | 战术区域规划 | 离开整片攻击区、选择安全出口 |
| 120–600 帧 | 战略战场经济 | 清哪个敌人、收不收 P、保不保 bomb |

当前 pilot 主要在第一层工作，v3.5.0 的核心工作是补齐第二、三层。

## 3. 总体架构

```text
特权状态读取
  ├─ 自机、bullet pool、boss
  ├─ 普通敌人：位置/生命/类型/活动状态
  ├─ 道具：位置/类型/活动状态
  ├─ power / P 槽 / bombs / lives
  └─ stage / spell / dialogue / clear
          ↓
未来战场预测
  ├─ bullet flow / danger occupancy
  ├─ 大范围危险区域 R(t)
  ├─ 敌人未来弹幕生成量
  ├─ 收集路线与未来 DPS 增益
  └─ 可达安全区 / 逃离时间
          ↓
战术意图仲裁
  ├─ LeaveRegion：离开大范围危险区
  ├─ ClearEnemy：攻击高未来威胁敌人
  ├─ CollectPower：power 未满时安全收 P
  ├─ BossDamage：在攻击窗口输出
  └─ LocalDodge：在已选安全区内局部躲避
          ↓
局部动作规划
  ├─ 当前意图约束下的短视 beam/MPC
  ├─ 执行 1–4 帧
  └─ 重新规划
          ↓
因果教师轨迹
  ├─ 高层 intent
  ├─ 全动作 value / advantage
  ├─ 未来危险区域
  ├─ enemy-clear value
  └─ P-collection value
          ↓
DAgger → 价值/策略蒸馏 → 纯策略或受限 fallback
```

现有局部 pilot 不废弃，而是降级为 `LocalDodge` 执行器；它不能再作为最高层决策器。

## 4. 状态与数据契约

### 4.1 必须读取的状态

| 状态 | 用途 | 要求 |
|---|---|---|
| player position / hurtbox | 电机控制、路线风险 | 已有，逐决策 |
| bullet position / velocity / half | 危险区域预测 | 已有，保留全池 |
| boss position / life / spell | BossDamage、phase | v3.4.0 已增加 |
| normal enemy position | ClearEnemy、威胁源 | 新增 |
| normal enemy life | 击杀收益、敌人目标 | 新增 |
| enemy type / active state | 识别发弹敌人 | 新增；未知必须标记 unknown |
| item position / type / active | CollectPower | 新增 |
| power / bombs / lives | 资源价值 | 已有 power；验证 bombs/lives |
| stage / stage_frames | 长时进度 | 已有 |
| dialogue / stage-clear / game-over | 不把停帧误判为死亡 | v3.4.0 已开始增加 |

普通敌人读取可以低于 bullet 读取频率，例如 5–10 Hz；不能因为读取成本高就把 ClearEnemy 写成没有状态依据的规则。

### 4.2 Item 收集契约

必须记录：

```text
item_id / item_type / position / active / onscreen
spawn_frame / collected_frame / power_delta
```

重点验证：

1. P 槽上限值；
2. 25% 收集线的真实 y 坐标；
3. 是否需要持续按住 Shift；
4. 25% 线是否会收集屏幕内所有 P；
5. 收集动作对 item 状态和 power 的时间关系。

### 4.3 未知字段

任何读取不到或无法确认的字段必须写为 `unknown`，不能用 0 表示“不存在”。

## 5. Stage 0：因果可学习性离线门

Stage 0 不再只问“哪个动作未来 20 帧 clearance 高”，而要问“动作和意图是否能预测未来战场结果”。

### 5.1 标签

每个状态构造以下标签：

```text
survival_60 / survival_240
future_danger_area(t=20/40/60)
region_exit_time
region_exposure
enemy_clear_delta_60 / enemy_clear_delta_240
bullet_density_delta_60 / bullet_density_delta_240
power_delta_240
stage_progress_240
boss_damage_240
```

对每个敌人增加：

```text
future_bullet_count(enemy, H)
future_bullet_density_reduction_if_killed
estimated_power_drop
```

对 P 点增加：

```text
safe_collection_route
collection_cost
power_gain
future_dps_gain
```

### 5.2 模型

先不做 end-to-end RL，使用可解释的监督模型：

```text
ThreatNet(s)       → future danger occupancy / region risk
EnemyValueNet(s,e) → future bullet reduction if enemy e is cleared
CollectValueNet(s) → value of collecting P now
V_tactical(s)      → survival + future safety + stage progress
Q_intent(s,intent) → Leave / Clear / Collect / BossDamage / LocalDodge
```

允许共享状态编码器，但每个头必须保留独立指标，不能把所有目标压成一个未经解释的 reward。

### 5.3 防止时间代理

报告必须同时给出以下基线：

- active bullet count；
- stage_frames；
- power；
- boss HP；
- 当前危险区域面积。

任何 value 指标都要报告相对这些基线的增量，不能只报告裸 Spearman 或裸 AUC。

### 5.4 Stage 0 门

| 编号 | 判据 | 建议标准 |
|---|---|---:|
| S0-1 | 留出集未来 60 帧危险排序 AUC | ≥ 0.80 |
| S0-2 | 同状态安全区域/危险区域排序 AUC | ≥ 0.75 |
| S0-3 | region-exit 方向 top-1 与几何 oracle 一致率 | ≥ 60% |
| S0-4 | EnemyValue 对未来弹幕减少排序 Spearman | ≥ 0.50，且高于 bullet-count 基线 |
| S0-5 | CollectValue 对未来 power/DPS 增益排序 | ≥ 0.60 |
| S0-6 | 未来 240 帧 tactical value 排序 | ≥ 0.60，且高于 stage_frames 基线 |
| S0-7 | 按整局切分、防同局泄漏 | 必须通过 |

任一关键标签无法稳定定义，停止训练，先修状态或标签契约。

## 6. Stage 1：区域级威胁规划

### 6.1 不硬编码攻击形状

不先判断“这是扇形”，而是从 bullet flow 生成时间展开危险图：

```text
occupancy[x,y,t] = P(collision at position x,y and time t)
```

建议时间片：

```text
t = 0, 10, 20, 40, 60
```

从危险图中计算：

- 高密度连通区域；
- 区域扩张方向；
- 当前玩家是否在区域内；
- 最近外部安全区；
- 离开区域所需时间；
- 离开路线的最大暴露量。

### 6.2 LeaveRegion 评分

```text
leave_score(route) =
    future_safe_area
  + safe_region_connectivity
  + time_to_clear_threat_region
  - max_region_exposure
  - immediate_collision_risk
  - direction_switch_cost
```

如果当前在大区域内部：

```text
优先最小化离区时间
而不是最大化区域内部 clearance
```

### 6.3 Stage 1 验收

在相同弹幕/相同重放条件下，与旧 pilot 对照：

- 大范围区域内平均暴露时间下降 ≥ 40%；
- 死亡前 10 个决策进入区域的比例下降 ≥ 30%；
- 可检测区域中，提前至少 20 帧选择逃离方向的比例 ≥ 70%；
- 不允许以“少移动”或“贴墙”伪通过。

## 7. Stage 2：主动清怪与 P 资源策略

### 7.1 ClearEnemy

每个决策生成候选敌人目标：

```text
target_score(e) =
    predicted_bullet_generation(e)
  + predicted_bullet_reduction_if_killed(e)
  + predicted_power_gain(e)
  - attack_route_risk(e)
  - region_exit_cost(e)
```

规则：

1. 大范围攻击即将形成时，立即中断清怪并 LeaveRegion；
2. 没有高风险区域时，优先攻击未来弹幕生成量最高的敌人；
3. 可以接受短暂降低当前 clearance 换取敌人死亡，但必须由未来 60/240 帧收益支撑；
4. 不能只用 score 代替敌人击杀证据；必须记录 enemy life/death 或弹幕密度变化。

### 7.2 CollectPower

```text
if power < power_max:
    if safe_collection_route and collect_value > 0:
        move_to_collection_line()
        hold_focus()
        collect_all_P()
        return_to_safe_region()
else:
    ignore_P_unless_route_is_free()
```

收集期间如果危险区域预测超过阈值，立即中止收集，不为 P 点穿越区域。

### 7.3 Stage 2 验收

- power 未满且安全收集窗口存在时，P 收集率 ≥ 80%；
- 高风险 P 路线误冲率 ≤ 10%；
- 主动清怪模式未来 60/240 帧弹幕密度增长低于纯闪避模式；
- 清怪模式在相同弹幕下敌人 life 下降速度更快；
- 清怪增加的死亡率不超过预注册上限 10%；
- 不得用“score 增加”代替清怪证据。

## 8. Stage 3：因果战术教师

将 Layer 1–2 与现有局部 pilot 组合：

```text
high_level_intent = argmax(
    LeaveRegion,
    ClearEnemy,
    CollectPower,
    BossDamage,
    LocalDodge
)

low_level_action = constrained_local_pilot(
    intent,
    safe_region,
    target_enemy,
    collection_route
)
```

优先级不是固定状态机，而是安全约束下的价值比较：

```text
LeaveRegion 优先于其他所有意图
否则比较 ClearEnemy / CollectPower / BossDamage
最后才是 LocalDodge
```

教师输出：

```text
intent label
full action value vector
future danger map
region exit direction
enemy target / enemy value
collect target / power value
TTC / clearance / exposure
```

Stage 3 教师门：

- 20 局评估中，区域暴露门通过；
- 20 局中 power/敌人清除指标不低于旧教师；
- Stage 1 boss phase 1/phase 2 的 damage 与生存分布均有证据；
- 发生 stage clear 时必须能记录 clear 事件，不能用 frames 代替。

## 9. Stage 4：DAgger 与蒸馏

只有 Stage 3 教师达到 M3 前的战术门，才启动 DAgger。

### 9.1 DAgger 数据

每轮：

```text
学生运行 20 局
→ 记录学生诱导状态
→ 因果战术教师重新标注
→ 保留历史并集
→ 训练
→ 20 局评估
```

标签包括：

- 高层 intent；
- full action value；
- future danger map；
- region exit direction；
- enemy-clear value；
- collect value；
- power / boss damage value。

### 9.2 学生动作空间

v3.5.0 必须在执行前冻结以下选择之一：

1. 18 路学生：bomb 由受限 fallback 处理，纯策略不声称具备 bomb 能力；或
2. 36 路学生：加入 bomb，重新建立所有基线。

不能在蒸馏中途隐式改变动作空间。

### 9.3 蒸馏门

- 学生状态下 teacher-value MAE 逐轮下降；
- intent 分类 balanced accuracy ≥ 0.75；
- region-exit 方向 top-3 命中率 ≥ 70%；
- power/clear 相关 value 误差逐轮下降；
- 纯学生策略在明确 clear 契约下达到 M3；
- fallback 调用率必须单独报告并设上限。

## 10. 明确不做

v3.5.0 不做：

- 随机初始化 PPO 作为主路线；
- 只用 `frames_mean` 作为成功标准；
- 只做扇形模式硬编码；
- 只做 20 帧局部 clearance 调参；
- 没有敌人/道具契约就训练 Clear/Collect；
- 以 score、存活帧或“像教师”代替 Stage clear；
- 在没有 clear/ending 事件时声称通关。

---

## 11. 版本成功标准

v3.5.0 的阶段目标不是“先把像素策略训练出来”，而是完成以下因果闭环：

```text
识别大范围未来威胁
→ 提前离开整个危险区域
→ 选择高未来收益的敌人清理
→ 在 power 未满且安全时收 P
→ 提高 DPS、减少未来弹幕
→ 提高 Boss 阶段生存与击破概率
→ 可复核 Stage 1 clear
```

在这个闭环尚未被特权教师验证前，不进入大规模 DAgger 或视觉蒸馏。
