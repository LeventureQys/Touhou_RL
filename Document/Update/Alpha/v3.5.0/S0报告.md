## 3 字段契约

### 3.1 普通敌人

- `EnemyManager.enemies[]`：481 × 0x53D0，一次 9.8 MB 读；9 局 21,156 次，0 次读失败；
- 字段：position / life / maxLife / flags(active,boss) / itemDropType / bossSlot / **sub_id**（`EnemyEclContext::subId`，0x224）；
- `sub_id=null` 只表示“该敌人 ECL 上下文不可读”，不是类型 0；S0 数据里 0 条 schema error；
- 实测读成本：中位 **1.155 ms**、p95 2.44 ms（含 ≤36 个 live 敌人的 sub_id 读）。

### 3.2 道具

- `ItemManager.items[]`：2,097 × 0x2E4，一次 1.5 MB 读；21,156 次，0 次读失败；
- 字段：position / itemType / state / isInUse / isOnscreen / isMaxValue；
- 实测读成本：中位 **0.197 ms**、p95 0.38 ms；
- 道具消失 ≠ 被收集：可能是掉出屏幕；S0 的收集解释用 `frameEventFlags & 0x40`（ITEM_COLLECTED）辅助。

### 3.3 shot 参数与 P 点

`Player.primaryShtFile`（+0xE2A74）→ `pointItemValueLine`（+0x1C）：

- 9 局全部读到 `line=128.0`、`box=24.0`、`auto_speed=10.0`；
- P 契约的独立实验（受控臂 + replay 臂，26,400 决策）**H-P1…H-P6 全部通过**，详见 [P点契约实验报告](<./probe/p-contract/P点契约实验报告.md>)；
- 本 S0 报告中 `max_power` 只有 26（teacher 不主动收 P），**不能**用 S0 的 power 证明上限；上限证据在 P 报告。

### 3.4 事件

- `game_over`：`lives` 在死亡屏停在 **0.0**（不是负数），`player_state` 2→1，frame 冻结；分类器用 `lives<=0 + player_state∈{1,2} + frame stalled` 识别；
- `max_steps`：采集截断，**不是**游戏事件；截断后轮询到的死亡不再改变该局归类（ep04/06/07 已按此修正）；
- `stage_clear`/`game_clear`/`left_game`：分类器与单测已就位，但**真机 S0 没有触发**（见 §5）。

## 4 质量门逐条

### S0-1 时间戳单调

21,156 / 21,156。帧非递减（对话/死亡屏会停帧，但不会倒退），wall 单调，decision 连续。稳态决策的“精确推进 frameskip”属于 S0-4 的 complete，不在 S0-1 重复计。

### S0-2 字段可追溯

20,639 / 20,639。`schema_status` 的 enemy/item/power 全部 ∈ {ok, empty}，0 个 error。注意：单个敌人的 `sub_id=null` 不算 schema error（未知类型是允许的，见契约 §1）。

### S0-3 事件可区分

3 / 3 个游戏终止都是 `game_over`，每个都有 post-terminal 证据（lives 0.0、player_state 2→1、frame 停）。6 个 `max_steps` 不计入分母。**真机没有 clear/left-game 样本**，因此“clear vs game-over”在真机上没有被同时观测到；分类器优先级（game_clear > stage_clear > game_over > left_game）由 `test_trace35.py` 单测覆盖，S4 必须用真实 clear 再验一次。

### S0-4 complete 有效率

20,638 / 20,639 = **99.9952%**。唯一的稳态不完整记录是 `collect-ep06` decision 1286：`frame_pre=2572, frame_post=2575`，实际推进 3 帧而不是 2（调度/读阶段跨帧），标为 `frame_mismatch`。其余 5 个不完整记录都是终止决策，按契约不计入分母。这远高于 95%。

### S0-5 整局切分

`stable_split` 按 `sha256("v350-s0:"+episode)` 分 4 桶；9 局中 7 train / 2 validation，同一局不跨 split。manifest 与磁盘文件一一对应，无多/少文件。

### S0-M manifest

19 个文件（9 trace + 9 bullets npz + episodes.jsonl），SHA256、行数、episode 列表全部核对通过。

## 5 限制与未做的事

1. **没有真机 clear**。S0-3 的分母只有 game_over；`stage_clear`/`game_clear` 只有分类器单测。`left_game` 的受控尝试（用暂停菜单退出）在 60 步时 `menu.exit_run_to_title` 超时，产生 `probe_error`，已从正式数据移除并记录在此。S4 必须用真实的 `stage_clear` 事件再过一次 S0-3。
2. **S0 的 teacher 不是策略结果**。`frames_mean`、score、存活帧都不作为任何结论；S0 只证明“字段读得到、事件分得开、采集够干净”。
3. **S0 没有主动收 P**。P 契约由独立实验证明；S3 的 `CollectPower` 必须重新在 S3 场景中验证收益与风险。
4. **没有扫激光**。`read_lasers()` 存在但未进 trace；S1 的区域预测先用 bullet flow，不把激光当已知量。
5. **没有改** `entity_obs` / `options` / `chunk_safety` 的既有口径；没有训练任何策略；没有启动 DAgger。
