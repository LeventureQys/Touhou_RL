# 预注册 v8280-FEATURES-001：**换放雷头的表示**（加显式特征）——本线最后一个有希望的方向

冻结时刻：2026-11-22（Asia/Shanghai），**在任何 v8.28.0 训练之前**。
状态：**FROZEN**。

---

## 0. 为什么只剩这一条路

本线已用 **9 次实验**否定「学习放雷」的三种做法（§44.4/§44.9）：

| 途径 | 结果 | 被否证的解释 |
| --- | --- | --- |
| 反事实标签（5 次） | 用雷恒 3.00 | 标签能教放雷 |
| 终点回报（600 决策） | = 规则 | 学习能超越规则 |
| 终点回报（900 决策） | 4.08% | 拉长回合可行 |
| **密集奖励（2 次）** | **0.61 / 0.78%** | **§33.3 的「稀疏⇒噪声」** |

v8.27 的关键观察：**两臂都收敛到「首雷决策恒为 0」**（存活局 100% 用满 3 颗）。

⇒ **瓶颈在「表示」**：`BombHead(106→64→2)` 从 106 维状态直接输出 2 类 logits，
**没有「还剩几颗雷 / 还剩多少决策 / 距最近弹幕多远」这类显式输入**，
所以它学到的唯一稳健策略是「开局就放」。

**本轮问题**：**把这三个量显式加进输入，能否让它学到「什么时候放」？**

## 1. 设计（单因子：放雷头的输入维度）

| 项 | v8.24/v8.27（对照） | **v8.28.0** |
| --- | --- | --- |
| 输入 | 106 维观测 | **109 维 = 106 + 3 显式特征** |
| 结构 | `Linear(106,64)→Tanh→Linear(64,2)` | **`Linear(109,64)→Tanh→Linear(64,2)`** |
| 奖励 | `survived(900) + 0.5×alive/1800` | **不变**（用 v8.24 的稀疏奖励，保证与 4.08% 可比） |
| 训练 | 3 种子 × 300 回合 × 900 决策 | **不变** |
| 候选头 | argmax 冻结 | **不变** |

### 1.1 三个显式特征（都归一化到 [0,1]）

```
f1 = bombs_left / 3.0
f2 = max(budget - decisions_executed, 0) / budget
f3 = clip(nearest_all_px, 0, 200) / 200.0
```

### 1.2 判据

| # | 终点 | 判据 |
| --- | --- | --- |
| **P1（主）** | 30 s | **> 24.17%** 且单侧 Fisher p<0.05（vs 60/40/20 固定阈值） |
| **P2** | 30 s | > 4.08%（v8.24 的稀疏奖励同框架结果） |
| **P3** | 首雷决策 | **中位数 > 10**（不再「开局就放」）—— 这是本轮最关键的行为指标 |
| **P4** | 用雷（存活局） | 报均值 |
| **P5** | distinct | 每格必报（<10 作废） |

### 1.3 判定

| 条件 | 判定 |
| --- | --- |
| P1 且 P3 | **`S-features-work`**：表示是瓶颈 ⇒ 这条路线重新打开 |
| P2 成立但 P1 不成立 | **`S-features-partial`**：比稀疏/密集好，但仍不如规则 |
| **P1 与 P2 都不成立** | **`S-representation-hopeless`**：**连换表示也无效 ⇒ 「学习放雷」这条路在本框架内彻底关闭** |
| 保真门失败 | `S-fork` |
