**结论：`S-features-partial`。** 三个显式特征把 900 决策（30 s）活满率从 v8.24 的 **4.08%**
抬到 **8.33%（150/1,800）**——单侧 Fisher 对 4.08% **p = 2.47e-10**（P2 成立）——但

反方向 p = **1.11e-11**。**P3（首雷决策中位数 > 10）彻底失败：1,800/1,800 回合的首雷都在
decision 0**（中位数 0.0）。按预注册 §1.3 ⇒ **`S-features-partial`**。

## 2. 协议（预注册 §1）

| 项 | v8.24/v8.27（对照） | **v8.28.0** |
| --- | --- | --- |
| 放雷头输入 | 106 维 | **109 = 106 + [f1,f2,f3]** |
| 结构 | `Linear(106,64)→Tanh→Linear(64,2)` | **`Linear(109,64)→Tanh→Linear(64,2)`** |
| 奖励 | `survived(900)+0.5×alive/1800` | **不变**（v8.24 稀疏式，可比 4.08%） |
| BC 热启动 | 200 步 / 4 窗 × 1 回合 / 900 决策 | **不变，但用 109 维输入**（每种子 1 次） |

| 评测 | 900 档 × 3 种子 × 4 窗 × 150 = 1,800 | 不变 |
| 候选头 | argmax 冻结 | 不变 |

三个特征（每次决策计算，∈[0,1]）：`f1 = bombs_left/3`、`f2 = max(budget−decisions_executed,0)/budget`、
`f3 = clip(nearest_all_px,0,200)/200`。`nearest_all_px` 用 `v800_bomb.nearest_bullet_distances`
——**与 60/40/20 规则测距完全同源**。

## 6. **P3：`first_bomb_decision` 的中位数与分布（本轮最关键的行为指标）**

**1,800/1,800 回合的首雷都在 decision 0。中位数 0.0，均值 0.0，min 0，max 0，q1=q3=0。**

| 桶 | 0 | 1–5 | 6–10 | 11–20 | 21–50 | 51–100 | 101–300 | >300 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 回合数 | **1,800** | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 占比 | **100%** | 0 | 0 | 0 | 0 | 0 | 0 | 0 |

逐窗中位数都是 0.0（每窗 450/450 都在 0），逐种子同样 0.0。BC 克隆探针（argmax，4 窗）
也是 `[0, 0, 0, 0]`（种子的三次完全相同）。

⇒ **P3 不成立（中位数 0.0 ≤ 10）。显式特征没有把「开局就放」改掉。**

### 6.1 但第 3 颗雷被推迟了（机制诊断；v8.27 的 106 维臂本来就有）

| 首次在「还剩 k 颗」时放雷的 decision 中位数 | 106 维（v8.27）D1 | 106 维 D2 | **109 维（本轮）** |
| --- | ---: | ---: | --- |
| k = 3（第 1 颗） | **0** | **0** | **0** |
| k = 2（第 2 颗） | **1** | **1** | **1** |
| k = 1（第 3 颗） | 253 | 173.5 | **430.5 / 474 / 250**（s0/s1/s2） |

即：**前两颗仍然在 decision 0 与 1 放掉**，只有第 3 颗被留到 ~decision 250–474。
v8.27 的 106 维头**已经**有这个行为（173–253），所以「留一颗」**不是**显式特征带来的新能力，
本轮只是把这一颗推得更晚一点。**首雷、次雷的时机一个都没动。**

用雷：全体均值 **2.9794**（3 颗 1,763 回合、2 颗 37 回合、0/1 颗 0 回合），
`bombs_end==0`（打空）1,763 回合；`bomb_emits` 均值 **23.4**、`bomb_ignored` 均值 **20.4**
——**头几乎一直在输出 "bomb"**，引擎只在还有雷时兑现。这就是「用雷恒 3.00」的机械原因。

## 9. 判定（预注册 §1.3）

| 条件 | 判定 | 是否成立 |
| --- | --- | --- |
| P1 且 P3 | `S-features-work` | ❌（P1、P3 都不成立） |
| **P2 成立但 P1 不成立** | **`S-features-partial`** | ✅ **本轮** |
| P1、P2 都不成立 | `S-representation-hopeless` | ❌ |
| 保真门失败 | `S-fork` | ❌（D3 5/5，且门文件早于 summary） |

**`S-features-partial`。** 显式特征把 30 s 活满率从 4.08% 抬到 8.33%（p = 2.47e-10，**确实**比
106 维的稀疏/密集两族都好），但仍比手写规则低 **15.83 pp**（反向 p = 1.11e-11），
且 **P3 完全没动**：1,800/1,800 首雷都在 decision 0。

**机制层面的结论（比判定更重要）**：`f1/f2/f3` 是**可用**的（都在 [0,1]、与规则同源的
`nearest_all_px`、第 3 颗雷被推迟到 ~430），但**头的策略仍是「一直输出 bomb」**
（emits 23.4/回合、兑现只有 2.98），所以「何时放」的自由度被 2 动作头 + argmax 冻结候选头
压成了「前两颗必丢」。**表示不是唯一瓶颈——即便给了正确的量，2 动作 argmax 头也没有
把它变成时机。**

### 9.1 不能声称什么

- **不能**声称「放雷可学」或「表示是瓶颈」：P3 全灭，P1 不成立；
- **不能**把 4.08%→8.33% 归因于「学会了时机」：首雷/次雷的决策位置与 106 维臂逐位相同，
  138/150 的活满集中在两格，seed2 全灭；更保守的读法是「同一行为 + 不同的兑现轨迹」；
- 只测 900 档（30 s），**不能**推断 20 s / 40 s；
- 训练/评测同批 4 个 dev 窗，无跨窗泛化结论；
- 不能声称「资源分配」——候选头冻结，只有 2 类放雷动作。
