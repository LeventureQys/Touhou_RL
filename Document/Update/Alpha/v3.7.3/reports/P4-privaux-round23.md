# P4 训练期特权辅助任务（缺口侧别）→ 按组留出闭环（round23）

## 一句话

R22 把约束定位得很干净：**信息在表征里**（冻结 256 维 trunk features 在留出几何上线性可解码缺口侧别 **98.5%**），**但行为目标不逼它用**（预告窗口内 95–97% 的决策是 hold，方向由底座"屏幕向右"先验决定，加池化空间特征 94 维完全无效、镜像走对率 3/9 → 3/9）。本轮只加**一个特权辅助任务**：从 GRU 状态（residual 头已经在用的那个 conditioning 向量）用一个 `Linear(256,2)` 预测"安全缺口的屏幕中心在 192 左还是右"，标签取自 `s.gap` 与 `s.mirror`（经 `round21.telegraph_gap`，就是 R21 渲染器画带子用的同一段算术），**只在训练损失里出现**，权重固定 **0.5**（A 臂 0.0，其余逐位相同）。3 seeds × 200 updates、R21 的 14 个 telegraph 资产（SHA 绑定、不重渲染）、R19 冻结 split、R20/R21/R22 的超参与评估口径一律不变，在 R19 的 validation 14 事件上闭环。

**控制成立到逐位**：A 臂三个 checkpoint SHA 与 R22 的 A **完全相同**（`d52551bb…`/`fb9233f1…`/`49ff13d9…`），6 个 (arm,split) 的闭环**每一步**与 R22 存盘相同（`equivalence.all_equal = true`），F1 留出 2/2/2、合计 3/3/3 —— 与 R22 一格不差。

**结果比 R22 复杂，也比 R22 更进一步**：本次干预**真的改变了方向结构**（R22 的融合层没能做到），但改的方向不对。

- **主指标（预注册判据）**：F1 留出 A = **2/2/2**，X = **1/3/2**；逐 seed Δ = **−1 / +1 / 0**。按冻结的判定次序（"任一 seed 严格更大 = improved"）本轮判定为 **`improved`**；但同一批数据里 **一个 seed 掉了 1 格**，三 seed 合计 **A 3/3/3 → X 1/3/2**，而且 **F2 留出的唯一可行事件在三个 seed 上全部丢失**（`F2-399-m1`：A 三个 seed 都不碰撞，X 三个 seed 都在 52 帧碰撞）。这两条必须一起读，本轮**不**把它当成"变好了"。
- **方向机制**：base 组走对 **6/9 → 9/9**、停进缺口 **3 → 5**、平均停车误差 **13.33 → 8.00 px**；镜像组走对 **3/9 → 1/9**、停进缺口 **3 → 1**、平均误差 **45.33 → 60.44 px**。屏幕方向分布从 A 的 **12 右 / 3 左 / 3 hold** 变成 X 的 **17 右 / 1 左 / 0 hold**：**"屏幕向右"这个先验被加强了，而不是被翻转**。X 的镜像组在 3 个 seed 里有 2 个（s7、s27）是 **0 走对 / 0 hold / 3 走反**，与冻结 B0 的 3 格结构逐个相同（s17 是 1/0/2；合计 1/0/8）。
- **辅助头本身**：训练行上**学会了**（seen 0.984 / 0.977 / 0.867，在线最后 20 步 0.85 / 0.87 / 0.81，A 臂同一读数是 0.46）；**留出上只部分泛化**（0.636 / 0.682 / **0.500**，池化 0.606 对 A 的 0.467，chance = 0.5），第三个 seed 的混淆矩阵是"全投 left"（left 66/66、right 0/66）。按预注册的 `aux_learned` 规则（三 seed 的平衡准确率都要超 0.5），**本轮不能宣称"辅助任务在留出上学会了"**，只能说"2 个 seed 高于机会、1 个 seed 恰好等于机会"。
- **"学会但不用"的逐格证据**：X 臂辅助头在 18 个 (seed × 事件) 格子里有 **11 格读对**，其中策略**走反 7 格、走对 4 格、hold 0 格**（A 臂是 9 格读对 → 走对 5 / 走反 2 / hold 2）。镜像组最刺眼：**辅助头 8/9 格读对该侧的缺口，而策略仍然 8/9 格背离缺口**。其中 `005-m1` 与 `010-m1` 共 6 格是"辅助头读 left（正确）、所需运动也是屏幕向左、策略仍然屏幕向右并撞死"——这是本轮最干净的"表征知道了、行为没用"。
- **反直觉的一条**：辅助任务让它自己的 514 参数头在留出上从 0.467 升到 0.606，却让**同一个标签从 GRU 状态里线性可解码的程度从 0.826 降到 0.619**（8 个 λ 的平均；24 个 (seed, λ) 对里 22 个 A 严格高于 X），也就是说它没有把侧别信息"加进去"，而是把已有的信息**转进了只有这个头能读的非线性编码**。

本轮不宣称战术理解，不产生可部署产物，不开启正式门，不运行游戏，不调参。

## 干预：辅助任务是什么、不是什么

### 1) 唯一改动

| 元素 | 值 |
|---|---|
| 标签来源 | `round21.telegraph_gap(s)`，即 `s.gap` 在 `s.mirror` 下的屏幕区间；取中心与 **192**（384 px playfield 的屏幕中心）比较，`>192 → right(1)`，否则 `left(0)` |
| 监督位置 | **只在预告窗口内**：逻辑帧 `2*i ∈ [wall_frame-45, wall_frame)` 的行（`round21.telegraph_window`，就是渲染器真正画带子的区间） |
| 监督范围 | 只有 **F1** 事件有缺口（F2/F3 `internal_gap = False`）→ train 侧 **6 个 F1 事件 / 128 行（3 左 + 3 右）**，其余 8 个事件贡献**恰好为 0** 的辅助项 |
| 辅助头 | `Linear(256, 2, bias=True)` = **514** 个参数，读 **GRU 状态**（`heads['option']` 的输入），**放在 `heads` 之外** |
| 损失 | `L = L_control + w · CE(aux_logits, side)`，`w = 0.0`（A）/ `0.5`（X） |
| 梯度路径 | 只到辅助头与**共享的 GRU**；`residual`/`option`/`target`/`urgency`/`termination`/`slack` 在状态**下游**，拿不到任何辅助梯度（单测逐个断言 `grad is None`） |
| 策略头 | **完全没有改**：`PrivAuxPolicy.forward_features is TacticalPolicy.forward_features`（函数对象同一性，不是文本相等） |
| 参数 | 两臂的参数集合、形状与初值**完全相同**：**429 200**（策略头）+ **514**（辅助头）= **429 714** 活跃；总参数 **2 002 668**（冻结骨干 1 507 162 + 头 494 992 + 辅助 514）。两臂只差 `w` |
| 梯度裁剪 | 只裁 **429 200 个策略头参数**，两臂同一个张量集合（辅助头在裁剪之外）——理由与后果见 §"为什么"第 6 条 |
| 推理 | 闭环网络是**未修改的 `TacticalPolicy`**，从 `payload['heads']` 构造；`payload['heads']` 的键只含 9 个策略头模块，**没有任何辅助张量**，`hasattr(model,'aux') == False` |

### 2) 与 R22 的关键结构差别：这次**不需要**绕过 detach

R22 的融合层在 `forward_features` 的**上游**，而父类第一行是
`features, base_logits = features.detach(), base_logits.detach()`，所以 R22 必须用子类去掉那一行。
本轮辅助头在 GRU 的**下游**：`features` 是冻结骨干的输出，**没有任何可训练祖先**，
所以父类的 `detach()` 对辅助头完全无害，**父类函数体逐字使用，本轮一行都没有覆写**。

GRU 状态是 `heads['option']` 的**输入**，因此用一个 forward pre-hook 捕获它。这不是"看起来是"：
单测用捕获到的张量把**五个**消费它的头（`option`/`target`/`urgency`/`termination`/`slack`）
全部重算一遍，与 `forward_features` 自己的输出**逐位相等**。因此"这个张量就是策略用的状态"是被测出来的。

### 3) 标签是"位置事实"，不是"运动指令"（预注册前就冻结，也是最重要的限制）

设玩家的屏幕 x 为 `x`、缺口屏幕中心为 `c`。标签是 `c > 192`，而**需要的运动**是 `c > x`。
两者只有在"玩家与控制中心同侧"时一致。六个 F1 留出事件：

| 事件 | 起点 x | 缺口屏幕区间 | 中心 c | 标签（c 对 192） | 需要的运动（c 对 x） | 一致？ |
|---|---:|---|---:|---|---|---|
| `F1-005-m0` | 216 | [248, 264] | 256 | right | right | **是** |
| `F1-005-m1` | 168 | [120, 136] | 128 | left | left | **是** |
| `F1-007-m0` | 128 | [152, 172] | 162 | left | **right** | **否** |
| `F1-007-m1` | 256 | [212, 232] | 222 | right | **left** | **否** |
| `F1-010-m0` | 216 | [256, 268] | 262 | right | right | **是** |
| `F1-010-m1` | 168 | [116, 128] | 122 | left | left | **是** |

**6 格里有 2 格（恰好是 A 臂本来就做对的那两格）标签与所需运动相反。** 这是任务书对标签的定义
（"安全缺口在屏幕左还是右"，只来自 `s.gap`/`s.mirror`）的直接后果，本轮不修改它、也不拿它当借口：
报告里每一条"辅助头读对"都同时给出该格的所需运动，读者可以自己判断。

### 4) 初始等价（单测硬约束）

- `test_step_zero_is_bitwise_the_same_policy_in_both_arms`：三个 seed 下，两臂的 `heads` SHA **相同**且等于冻结表
  （`66e5f85f…`/`f7d03e20…`/`276573d1…`），辅助头 SHA 也**相同**（`d99d2104…`/`b89fe88d…`/`a4cca3a6…`），
  `policy_logits` 逐位相等、masked 动作相同。
- `test_perturbing_the_auxiliary_head_changes_no_policy_logit`：把辅助头权重与偏置换成随机大值（×10），
  **策略前向逐位不变**（`policy_logits`/`residual_logits`/`hidden` 全部 `torch.equal`）。这是"只提供梯度"的最强形式。
- `test_noise_in_the_auxiliary_state_changes_no_closed_loop_decision`：把 checkpoint 里的辅助状态换成常数 7，
  真实一帧像素过 `PrivNetwork` 得到的 18 维 logits **逐位相同**。
- `test_zero_weight_leaves_the_auxiliary_head_bitwise_untouched`：`w=0` 走两步 Adam 后辅助头 SHA 不变。

## 推理路径不读标签（三条独立测量，不是声明）

1. `test_the_label_function_is_never_called_on_the_inference_path`：把 `aux_target`/`aux_mask`/`aux_terms`/`aux_batch`/`supervision_table`
   **全部换成抛异常的桩**，然后用真实 checkpoint + 真实像素跑一次闭环调用，**正常返回 18 维 logits**。
   也就是说：推理路径若读过标签，这个测试必然炸。
2. `test_the_policy_input_surface_is_unchanged`：GRU 的 `input_size == 285 == 256 + 19 + 4 + 1 + 1 + 2 + 1 + 1`，
   hook 实测每次喂进去的是 `[1,1,285]`、共 80 次；像素区域集合仍是 `{playfield, hud_score, hud_status}`；
   `features` 仍是 `[80,256]`。**没有任何通道被拼进 features/history/pixels。**
3. `test_the_inference_network_is_the_parent_class_and_has_no_aux`：`PrivNetwork` 的 payload 键集合是**精确的 13 个**
   （多一个 `label_side` 就 `ValueError`），`heads` 的键首段恰好是 9 个策略头模块，模型 `type(...) is TacticalPolicy`、
   `hasattr(model,'aux')` 为假。辅助**状态**只以 SHA 形式被登记为溯源地标（不是张量、不参与任何计算）。

### 6) X 改了方向，但改的方向不对；"学会但不用"的逐格证据

逐格把"辅助头读了什么"与"策略做了什么"并排放（`probes.usage`，18 格/臂，`*` = 墙落下时不在缺口内）：

- 反过来，X 的 base 组 **9/9 走对**（A 是 6/9）：辅助任务确实被**用上了**——用在 base 组，那里"缺口在屏幕右半边"与"向右走"恰好同向。
  所以本轮不能简单说"任务学会了但完全没用"；准确的说法是**"任务被用来加强一个本来就存在、且在镜像组是错的屏幕向右先验"**。

## 与 R22 的对比（判据的结论）

| 臂 | seed | R22 F1 留出 | R23 F1 留出 | Δ | R22 合计 | R23 合计 | Δ | 14 事件 first hit 相同数 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| A（= R22 A，逐位复现） | 7 / 17 / 27 | 2 / 2 / 2 | 2 / 2 / 2 | 0 / 0 / 0 | 3 / 3 / 3 | 3 / 3 / 3 | 0 / 0 / 0 | **14 / 14 / 14** |
| X（特权辅助任务） | 7 / 17 / 27 | — | **1 / 3 / 2** | **−1 / +1 / 0** | — | **1 / 3 / 2** | — | **11 / 8 / 9**（对 A） |

按预注册判定：**X 对 A = `improved`**（顺序读规则：任一 seed 严格更大 → improved；s17 是 +1）。
但本轮必须把同一批数据里的另外三件事一起写在判定旁边：

1. **一个 seed 掉了 1 格**（s7：`007-m1` 从"停进缺口、不碰撞"变成"屏幕向右、60 帧撞死"）；
   s27 同一格也掉了，但同 seed 的 `010-m0` 补回一格，所以 s27 的 Δ = 0；
2. **三 seed 合计 3/3/3 → 1/3/2**，而且 **F2 留出的唯一可行事件在三个 seed 上全部丢失**（`F2-399-m1`）；
3. 判据里的"任一更大 = improved"是 R22 判据结构的直接继承，它**不编码**"一升一降"与"不变"之间的偏好。
   本轮不改判据（预注册就是预注册），但因此**只报告规则的输出与全部计数，不声称任何更广义的"变好了"**。

机制上与 R22 的关系：

| | R22（空间融合） | R23（特权辅助任务） |
|---|---|---|
| F1 留出合计 | 3/3/3 → 3/3/3（`unchanged`） | 3/3/3 → 1/3/2（规则判 improved，合计更低） |
| 镜像走对率 | 3/9 → 3/9（**一格没变**） | 3/9 → **1/9**（变了，但更差） |
| base 走对率 | 6/9 → 6/9 | 6/9 → **9/9** |
| 停进缺口（base / 镜像） | 3/3 → 3/3 | 3/3 → **5/1** |
| 屏幕方向（右/左/hold） | 12/3/3 → 12/3/3（A 臂两轮都是同 18 格） | **17/1/0** |
| 行为形态 | 最大切换 2→3 | 最大切换 **2 不变** |
| first hit 被改动的格数 | 0 / 14 ×3 | **3 / 6 / 5** |
| "学习"证据 | 融合层 94.4% 学成常数 | 辅助头 0.94 seen / 0.61 holdout，2/3 seed 高于机会 |

**R22 的结论是"信息在、行为没动"；本轮的结论是"行为动了、但动的是先验那一侧"。** 两者合起来把问题推到更具体的位置：
**这不是"梯度不够"的问题，而是"梯度指向的目标本身与任务方向不一致"**——辅助标签是位置事实，而策略需要的是位移。
两者在 **2/6 个留出事件（6/18 格）上相反**；在一致的 **4 个事件（12 格）**里，X 也只在 **2 个事件（6 格）**上用对了方向，
另外 **2 个事件（6 格）**（`005-m1`、`010-m1`）用反了（§6）。

## 判定（有界，不做显著性声明）

1. **控制成立到逐位**：A 的三个 checkpoint SHA 与 R22 相同，6 个 (arm,split) 的闭环**每一步**与 R22 相同
   （`equivalence.all_equal = true`），F1 留出与合计与 R22 相同，6 个 F1 留出格的停车位置逐 px 相同。
   两臂初始 head SHA 与初始辅助头 SHA 都逐位相同，step 0 的动作分布相同（单测断言 logits 逐位相等、masked 动作相同）。
   因此本轮的两臂比较是干净的单因子比较，差异只有一个数：辅助损失权重 0.0 vs 0.5。
2. **主指标（预注册规则）**：**`improved`**（F1 留出逐 seed Δ = −1/+1/0，s17 +1）。**但合计更低、且 F2 丢了一格**，
   两条必须并列读；本轮不把它当作"变好了"。
3. **唯一干预确实改变了方向结构**（这是相对 R22 的实质进展，虽然结果是负面的）：
   base 走对 6/9→9/9、停进缺口 3→5、误差 13.33→8.00 px；镜像走对 3/9→1/9、停进缺口 3→1、误差 45.33→60.44 px；
   屏幕方向 12 右/3 左/3 hold → **17 右/1 左/0 hold**；X 的镜像组在 s7 与 s27 上（0/0/3）与冻结 B0 逐计数相同。
   **结论：辅助任务加强的是"屏幕向右"这个先验，不是"缺口在哪"这个信息。**
   同时必须说明：**已见（train）侧 X 的 base 组从 9/0/0 变成 6/0/3**，所以"base 变好"只在留出侧成立。
4. **辅助任务"在训练行上学会、在留出上只部分泛化且退化"**：seen 0.943 池化（在线末段 0.81–0.87、首段 0.45–0.50），
   holdout 0.606 池化（0.636 / 0.682 / **0.500**），且 18 个留出格中 16 格读 "left"。
   按冻结的 `aux_learned` 规则，**不能宣称留出上学会**。
5. **"学会但不用"有逐格证据，而且比"不用"更强——是"用反了"**：X 的辅助头在镜像组 8/9 格读对该侧缺口，
   策略 8/9 格背离缺口；其中 6 格是"辅助头读 left（正确）、所需运动也是 left、策略向右并撞死"。
   反过来 base 组 9/9 走对，说明辅助任务**被用上了**，只是用在"标签与所需运动同向"的那一半世界。
6. **状态可解码性反向变化**：同一标签从 GRU 状态的线性可解码性 A 0.826 → X 0.619（扫描均值，22/24 对严格更高），
   而辅助头自己的留出读数 0.467 → 0.606。信息没有被加进去，被转了编码。这是"表征学会了、线性子空间没学会"的测量。
7. **行为形态不变**：最大切换仍为 2、恒定 0/84、两段式 **X 38/42 对 A 39/42**、中位切换 1。
   所以本轮改变的是**一次移动的方向与幅度**，不是输出形态。
8. **不宣称战术理解**，也不声称"特权辅助任务无用"：只说"**这个标签（缺口屏幕侧别）+ 这个头（GRU 状态上的 514 参数线性分类器）+ 固定权重 0.5 + 200 updates**"这一个组合，
   在 3 个 seed 上把 base 组推到 9/9、把镜像组推到 1/9，并把 F2 的可行事件丢掉。

## 为什么（机制，逐条）

1. **标签与运动不是同一个量。** "缺口在屏幕左半边"与"往左走"只在玩家位于中心另一侧时等价；6 个 F1 留出格里 2 格相反，
   而且恰好是 A 臂唯一做对的两格（`007-m0`、`007-m1`）。所以这个辅助任务在结构上**不能**等价于"学会朝缺口走"。
2. **它等价于什么，本轮测出来了：等价于"屏幕右侧有东西"。** X 的屏幕方向分布 17 右 / 1 左 / 0 hold，
   镜像组在 s7 与 s27 上与 B0 逐计数相同。也就是说：辅助梯度把 GRU 状态推向"与右侧内容/右侧先验对齐"的方向，
   再经 `base_logits + residual`（`base_logits` 本身带"屏幕向右"）放大。
3. **它确实产生了新的运动**：`005-m0` 从"三个 seed 全 hold"变成"三个 seed 都向右走"，`010-m0` 从"−8 px"变成两个 seed"停进缺口"。
   这两格都在 base 组，方向与先验同向；代价落在镜像组的 `007-m1`（s7/s27 各丢一格）。**所以方向上的收益没有转成计数上的净收益**
   （合计 3/3/3 → 1/3/2，F2 还丢了一格）。
4. **"没有把信息加进状态"有直接测量**：状态对侧别的线性可解码性 **下降**（0.826 → 0.619），而辅助头自己的读数 **上升**。
   所以辅助任务不是"给状态补上了缺口位置"，而是"把状态按这个头的读法重新组织"。
5. **输出形态没被推动**：95% 以上仍是 hold，最大切换 2，两段式 X 38/42、A 39/42。要在 45 帧里"早动、动对方向、到点停"，
   需要三段以上；辅助任务只调了那一次移动的**方向**，没有调**次数**。
6. **裁剪范围的选择（必须在报告里写明）**：冻结协议裁 `model.parameters()`；在本轮，那个集合会多出 514 个辅助参数
   （A 臂梯度恒 0、X 臂非 0）。本轮把裁剪定义成**429 200 个策略头参数、两臂同一个张量集合**，理由是
   (a) 让裁剪规则在两臂覆盖**同一个**参数集合（否则两臂的裁剪规则在效果上不同），
   (b) 让控制臂的浮点路径与 R22 **完全相同**。其后果被记录并可检验：A 三个 checkpoint 与 R22 逐位相同
   （`clip_scope.includes_auxiliary = false`、`matches_round22_control = true`）。辅助头自身的 514 个参数不在裁剪内，
   它自己的梯度范数（最大 7.2–7.7）单独记录。
7. **为什么 A 臂能逐位复现**：`0.0 · L` 的梯度恰好是 0，所以辅助项对 GRU/策略头的更新逐位无影响；
   辅助头在 A 臂上因此**从未**移动（末 SHA = 初 SHA），它的留出读数（0.467）就是"随机初始化 + 无语义"的负对照。

## 限制（必须与结论一起读）

1. **n = 3 个 seed、7 个留出组**，F1 留出只有 3 组 / 6 个事件；镜像不是独立样本。`9/9`、`1/9`、`11/18` 这些数字是**计数**，不是速率，
   本轮不做任何显著性声明。
2. **标签是位置事实，不是运动指令**（§干预-3）。6 个 F1 留出**事件**里 2 个（对应 6/18 格）两者相反。这是任务书的定义，本轮不改，但它限制了
   这个干预能声称的上限：**它最多能把"缺口在哪一侧"接进去，不能直接教"往哪走"**。
3. **标签在事件内恒定、且完全镜像配对（每侧 3 左 3 右）**，所以一个头可以靠"这是哪个世界"而不是"缺口在哪"拿分。
   逐格表、`distance_from_centre` 列与混淆矩阵都列出来了，这一点无法被隐藏：X 的留出读数有 16/18 格是 "left"，
   说明它确实**没有**在做一个真正的位置读取器。
4. **辅助监督只覆盖 6/14 个训练事件、只在预告窗口内**，所以 200 步里只有 **88 步**有辅助梯度，另外 112 步辅助项恰好为 0。
   这是"F1 才有缺口"的直接后果，不是选择。
5. **只测了一个权重（0.5）**，运行前固定，未调。没有扫 0.1 / 1.0 / 2.0，也没有测"只监督 base 组"或"用位移标签而不是侧别标签"。
6. **状态可解码性探针 p ≫ n**（132 行 vs 256 维，标签在事件内恒定），结论只以整条 λ 扫描与两臂对比的形式给出，
   不依赖单个 λ；`λ=1` 那一列在 A-s7 上恰好是扫描的最小值，所以报告以**扫描均值**为主要读数。
7. **辅助头读数是在每个 checkpoint 自己的闭环轨迹上测的**，不是在一个中立的探索分布上；重放保真度 1.0（每格 80/80）保证
   它看到的是 runner 的输入，但轨迹本身由策略决定，所以不同网络的读数不在同一个输入分布上。
8. **教师不是学习到的策略**：`TacticalTeacherV2` 被直接告知世界几何，是 12 帧 beam 规划器；14/14 只说明"这些世界对
   知道参数、能前瞻 6 步的规划器可玩"。
9. **F1 的胜利条件是 12–20 px 的精确停车**，是几何构造，不是"会玩"；F3 是卡时机的越线。
10. **数据是合成固定 y 世界**：两帧动作、无射击、无炸弹、无真实 TH08 像素与判定；horizon 固定 160。
11. **只有一种超参配置**（200 updates / lr 1e-3 / clip 1 / batch 1 / 单路线 one-hot）；没有扫"更多 update 是否就学会"。
12. **有一次预先披露的冒烟运行**：预注册之前在 `.tmp/privaux-smoke/` 用同一份冻结代码跑过一次完整流水线（4 次尝试，
    前 3 次被真实缺陷挡住，见 `command-results.md`），其数值未用于任何结论；它与正式 run 的 **6 个 `research-heads.pt`、14 个闭环文件、
    `f1-gap.json`、`probes.json`、`records.json`、`baselines.json`、28 个事件文件全部逐字节相同**，
    70 个文件里 59 个逐字节相同、其余 11 个只差墙钟字段（去掉 `timings`/`optimization_seconds` 后 `checkpoints.json` 与
    `summary.json` 完全相等），因此本轮可以声明"两次独立进程逐位相同"。
13. **不产生任何可部署产物**：六个 `research-heads.pt` 是研究用 head，`deployable = false`、`formal_gate = false`、`game = false`。
14. **特权标签是训练期的，不是部署方案**：本轮证明的不是"可以用特权信息做出好策略"，而是"给一个什么样的特权任务会/不会改变行为"。
    任何把训练期标签当部署捷径的读法都超出本轮范围。

## 对既有结论的处置

| 既有结论 | 处置 |
|---|---|
| R22："冻结 256 维 features 线性可解码缺口侧别 98.5%，但策略在预告窗口 95–97% hold，方向由底座先验决定" | **前置承认，并再被本轮独立测量一次**：A 臂 GRU 状态对同一标签的线性可解码性扫描均值 **0.826**（未训练的辅助头也在上面），说明信息确实在表征里 |
| R22："加一个池化空间特征完全无效（镜像 3/9 → 3/9，94.4% 学成常数）" | **本轮把它推进一步**：不是"必须改结构才行"，而是**改变目标函数就能改变方向**——只是这次改变的方向是先验那一侧 |
| R22 的隐含推论"行为目标没有逼它用这个信息" | **部分确认、部分修正**：确认的是"梯度指向的目标不对齐时，行为可以完全不动"；修正的是"目标一旦对齐到某个可学的东西，行为**会**动"（base 6/9→9/9、屏幕方向 12/3/3→17/1/0）。所以问题不是"没有梯度"，而是"梯度的目标函数选错了量" |
| "给一个合适的辅助任务就能让镜像方向翻转" | **必须撤回**：镜像走对率 3/9 → **1/9**，屏幕方向反而更"向右"；X 的镜像组在 s7 与 s27 上与冻结 B0 逐计数相同 |
| R20/R17："KL 锚改变分布但不改形态" | 本轮两臂都**没有**锚，形态仍是两段式（A 39/42、X 38/42）、hold 0.93–0.94、中位切换 1、**最大切换 2**——再次说明"两段式"不是锚造成的，而且**可以在不改形态的前提下改变方向** |
| R22："约束在输出形态与这个向量的分辨率上" | **形态这一半本轮被部分松动了**：方向确实能在形态不变的情况下被改（最大切换仍是 2）。**分辨率那一半本轮没有触碰**（没有换空间源） |
| R22 的架构观察"`forward_features` 会 detach，上游可训练模块拿不到梯度" | **本轮的补充**：**下游**模块不需要绕这个 detach，父类可以逐字使用；而且"上游/下游"这个区分本身就决定了要不要改父类。以后接模块先问"它在 GRU 上游还是下游" |
| 后续该怎么做 | 不要在"缺口侧别"这类**位置事实**标签上继续。下一步应当把标签换成**位移指令**（`sign(gap_centre − player_x)`，需要把玩家位置一起给出）或**逐帧 stop 信号**，并且分别作为预注册的单因子；同时保留本轮的三个读数（逐格 usage 表、状态可解码性 A 对 X、行为形态）作为验收口径，因为它们能区分"没学会"、"学会了没用"与"用了但用反了" |

本轮不修改 `ledger-round17.md`（属上一轮台账）。建议父级在 round23 台账登记：
**训练期特权侧别辅助任务 = F1 留出 2/2/2 → 1/3/2（规则判 improved，合计 3/3/3 → 1/3/2，F2 唯一可行事件三 seed 全丢）**、
**镜像走对率 3/9 → 1/9（更差）、base 6/9 → 9/9（更好）、停进缺口 3/3 → 5/1**、
**屏幕方向 12 右/3 左/3 hold → 17 右/1 左/0 hold（s7/s27 的镜像组计数与 B0 相同）**、
**辅助头 seen 0.943 / holdout 0.606（0.636/0.682/0.500，18 格中 16 格读 left）→ 按冻结规则不算"留出上学会"**、
**"学会但不用"的逐格证据：镜像组辅助头 8/9 读对、策略 8/9 走反，其中 6 格"读 left + 需 left + 走 right"**、
**GRU 状态线性可解码性 A 0.826 → X 0.619（辅助头自身 0.467 → 0.606）**、
**行为形态不变（最大切换 2、恒定 0/84）**、
