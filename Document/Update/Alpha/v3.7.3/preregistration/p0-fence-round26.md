- 写入时间：2026-11-02，**在本次真机执行之前**。本文件不含任何本轮实测数字。
- 触发原因：[P0 出口判定](<../reports/P0-exit-round15.md>)第 34–36 行写明冻结的解除条件是"需要能给出呈现栅栏的独立证据……届时 P0 需重跑，不能沿用本轮结论"。v3.7.4 已交付该证据（[帧栅栏 round1](<../../v3.7.4/reports/P0-frame-fence-round1.md>)），但那一轮只验证了机制（attract demo、无按键、无边界、无动力学），**没有重跑 P0 的任何门**。本轮就是这次重跑。
- 镜像前提：`third_party/th08/build_fence/th08.exe`（研究变体，**非 canonical**）。所有结论只对该变体 + 其地址表成立；不得用于 exact-match / 版本一致性声明。

## 1. 问题

冻结表里有三条与"能否用像素做精确标签"直接相关的欠账，本轮只回答这三条，不扩题：

| 台账行 | 现状态 | 本轮要测什么 |
|---|---|---|
| 截图与状态精确同帧 | unknown（已冻结） | 在**实战（非 demo）**会话里，每张样张能否用 `ticket + holdPhase + 摘要 + 后台缓冲`证明归属同一帧 |
| 每类 20 次独立动力学重复 | failed | 普通/聚焦/纵向/斜向四类各 20 次独立转移的逐帧位移 |
| 四边界 | partial（每边界 1 次） | 四个方向的饱和值 + 反向"旧方向多走一帧"的精确帧数与像素数 |

附加一条本轮才有意义的问题：**"发送→生效滞后 1 帧"能否从区间变成整数**。旧读法（不 hold）只能给区间，因为发送时刻落在两次 present 之间；栅栏把发送锚定在"第 T 帧已 present 且游戏停住"这一确定的帧边界上。

### 2.1 打断处理（执行前修订，理由见下）

修订时间：本次正式执行之前（此前只跑过不落盘的探索性小样）。修订原因：探索性小样在边界推进段（第 651 逻辑帧）被击中一次，`player_state=2`。若沿用"一次死亡即整场中止"，会用一个与度量无关的打断丢掉已经完成的试验。

修订后的规则（只改打断处理，**不改任何判据 G1–G11、样本量、类定义**）：

1. 一次打断只作废**当前这一次**试验/推边/反向试验，不进入统计。
2. 打断后等待 `player_state` 回到 0（复活有一小段无敌期），再重做该次试验；重做不计入 20 次之内。
3. 所有打断逐条记录（相位、逻辑帧、ticket、player_state）并计数上报；重做次数单独报告。
4. 若打断次数超过 12 次、或生命耗尽、或离开 playing，则**停止该相位**并如实报告 partial，不改判据。
5. 已被打断的试验不得补成"通过"；只有完整走完的试验才进入统计。

补充测量（不进门）：会话 B 里同样记录 `ticket`/`logicFrame` 增量，作为 G1/G2 的第二次独立观测；若与 A 不一致，以失败记录，不得只报 A。

## 3. 试验定义与判据（先写死，不看结果）

### 记号

- `F`：读取方观察到 `ticket == T && holdPhase == 1`、并在该 hold 内写入新按键的那一帧（锚帧）。
- `F+1, F+2, …`：之后连续被 hold 的帧。
- `C`：`F` 之后第一个 `(engine input mask & 方向位) == 期望值` 的帧。
- `P`：`F` 之后第一个该轴坐标与锚帧不同的帧。
- `lag_in = logicFrame(C) − logicFrame(F)`，`lag_mv = logicFrame(P) − logicFrame(F)`。

### 四类（每类 20 次独立试验）

| 类 | 按键 | 期望方向位 | 稳态位移 |
|---|---|---|---|
| C1 横向普通 | `right` 或 `left`（按当前 x 取远离墙的一侧，逐次交替记录） | `BTN_RIGHT` / `BTN_LEFT` | 4.000 px/帧 |
| C2 纵向普通 | `up` 或 `down`（按当前 y 取远离边界的一侧） | `BTN_UP` / `BTN_DOWN` | 4.000 px/帧 |
| C3 横向聚焦 | `shift`+`right`/`left` | `BTN_FOCUS`+方向 | 2.000 px/帧 |
| C4 斜向普通 | `right`+`up` / `left`+`down` | 两位同时 | 每轴 2.828427 px/帧（4/√2） |

"独立"定义：每次试验开始前必须有 **≥2 个静止帧**（该帧与前一帧坐标完全相同），且上一试验已经松开方向键 ≥2 帧。位移测量取 `P` 帧相对锚帧的坐标差（= 该帧的单帧位移）。

### 判据（全部为布尔，逐条落盘）

| 编号 | 判据 | 通过条件 |
|---|---|---|
| G1 | ticket 增量 | 被 hold 的连续帧之间 `ticket` 增量恒为 1 |
| G2 | 逻辑帧与 ticket 同速 | 同批帧之间 `logicFrame` 增量恒为 1，且等于 ticket 增量 |
| G3 | 呈现速率 | 由游戏侧 QPC 计算，M1 期间 ≥ 55 Hz |
| G4 | 输入生效为整数帧 | C1/C2 各 20/20 满足 `lag_in == 1` |
| G5 | 聚焦/斜向同样为整数帧 | C3/C4 各 ≥18/20 满足 `lag_in == 1` |
| G6 | 位移响应不晚于输入 | 全部 80 次试验满足 `lag_mv >= lag_in` 且 `lag_mv <= lag_in + 1` |
| G7 | 动力学数值 | C1/C2 每次试验 `|Δ| = 4.0`（浮点精确相等）、C3 `|Δ| = 2.0`、C4 每轴 `|Δ| = 4/√2`（容差 1e-4 相对）；每类 20/20 |

> G7 的说明（执行前写死）：源码 [Player.cpp L762–L794](<../../../../../third_party/th08/src/Player.cpp#L762-L794>) 显示速度取自 shot 文件的 `normalAxisSpeed / normalDiagonalSpeed / focusedAxisSpeed`，再乘 `framerateMultiplier`；因此判据同时记录 (a) 绝对值和 (b) 关系式 `C3/C1 = 0.5` 与 `C4/C1 = 1/√2`（容差 1e-6）。若绝对值落在 4.0/2.0 之外，**判 G7 失败并如实写出实际值**，不把关系式成立当替代。
| G8 | 四边界 | 右 376、左 8、上 16、下 432（浮点精确相等）；每个方向至少出现 2 个连续静止帧才记为饱和 |
| G9 | 反向旧方向 | 反向后的第 1 帧记录"旧方向是否仍走 1 帧、是否恰好 4 px"；四个方向全部出现"恰好 1 帧且 4 px" |
| G10 | 像素—状态同帧 | 60 张样张全部通过 13 项检查，其中 `pixels_match_backbuffer` 100%；丢弃样张数单独报告 |
| G11 | 旧读法仍不可用 | 60 次旧读法中至少出现 1 次 ticket 变化或摘要不一致（**这是测量，不是通过门**；若为 0 也必须如实报告，且不得因此宣布旧读法可用） |

### 汇总与判定规则

- **P0 解冻成立** 需要 G1–G10 全部通过。任一条不通过：对应冻结规则保持原样，**不得**在看结果后放宽阈值、剔除试验或补跑到通过。
- 若中止发生在某类试验中途导致样本数 < 20：按实际数量报告，判该条 `partial`，不追认为通过。
- 允许且只允许**一次**重启：仅在会话因启动/菜单/`player_state != 0` 在**任一判定阶段完成之前**中止时使用；重启与原因必须写入 summary，且第一次的原始记录不得删除。
- 判据、样本量、类定义在本轮执行后不得修改；后续若要改，另开预注册。
