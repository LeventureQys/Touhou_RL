## 3. 采样（本轮唯一的因子）

- 行为策略：v4.5.0 `S`（`round2.pt`，stochastic，`generator_seed=seed*1000+7`） + **R5**（`staged`：3 雷 80 px / 2 雷 60 px / 1 雷 40 px，`nearest_all_px < threshold` 且 `bombs_remaining > 0`）；复用 `tools/rl/v860_bombdag.py::behaviour_decision`，未重写。
- **live `nearest_all_px`**：对 live `HAZARDS` 的**全部** `bullet_count` 颗求最小，不是存储的 12 颗。
- 采样规则：规则触发的决策 **±10** 个决策（`trigger` + `window`），其余决策按 **1/10** 概率抽样（`sampled`）。
- 每状态记录：`nearest_all_px`、最近 12 颗（按距离升序，含 `vx`/`vy`）、`bullet_count`、`bombs_remaining`、`rule_bomb`，外加 36 路标签（H=120）。

### 3.1 两遍回放（实现方式，不是采样规则的改动）

「触发点 ±10」要求在被标注之前就知道触发点，所以每局走两遍：

1. **pass 1**：完整 300 决策行为轨迹（`HAZARDS` + `PARK` + 2 帧/决策），不打标签，记录每个决策的 live `nearest_all_px` / 阈值 / 是否触发 / 采到的候选；
2. **采样**：套用上面的冻结规则；
3. **pass 2**：warm RESET，重放**记录下来的**动作，只在被抽中的决策上 `PARK` + 36 路标签。行为策略**不重采样**，所以两遍共享同一条动作序列。

回放是**被验证**的，不是被假设的：pass 2 在**每个**决策上比较 live `frame` 与 live `nearest_all_px` 是否等于 pass 1，本轮 **46,088 次校验 / 0 个 mismatch**。

### 5.2 为什么到不了 25%（机制，不是借口）

触发的决策数量是硬上限：正例只可能出现在「规则会触发」的决策上，而 ±10 窗把每个触发点周围再拉进 ~20 个**非触发**决策。以本轮实测：

- 每局（300 决策）触发 **7.71** 个决策，抽中 **64.9** 个决策（触发 + 窗 + 1/10）；
- 段 1（1 雷，40 px）最稀：**187/2724 = 6.86%**，因为 40 px 的距离本身很少出现，且它只在「雷已剩 1 颗」之后才生效；
- 由此，25% 这个门槛在「触发 ±10 + 1/10 抽样」这条规则下**结构上不可达**：窗宽与抽样率都是冻结的，正例率就锁在 ~12–16%。

### 7.1 标签矩阵本身是退化的（本轮最重要的发现）

| 指标 | 值 |
| --- | ---: |
| 36 路全 safe 的状态 | **6,572 / 10,008 = 65.67%** |
| 36 个动作的平均 alive_frames | 118.5613 / 120 |
| 平均 safe 动作数 | 34.3571 / 36 |
| best bomb=1 **严格更好** 的状态 | **0** |
| best bomb=1 **严格更差** 的状态 | 0 |
| best bomb=1 **相等** 的状态 | 10,008 |

**这意味着什么**：在每个采样状态上，都存在某个 bomb=0 的候选能活满整个 H=120 帧窗口（`max(alive_frames) == 120` 在全部 10,008 个状态成立），因此**放雷在反事实标签里从不换取帧数**。于是：

- 臂 B（只 `BCE(36)`）的雷位**没有任何监督信号**——不是「学得不够」，而是标签里没有可学的差异；预注册 §1 对臂 B 的假设（「触发点附近的反事实标签可能终于出现『放雷更差』的例子」）被数据**否定**：不是「更差」，而是**完全相等**；
- 臂 A 的 0.5×`BCE_bomb(规则)` 会是**唯一**的雷位监督；
- 这解释了 v8.3–v8.11 这条线的停滞：瓶颈不在采样分布（本轮的单因子），也不在规则蒸馏权重（v8.5），而在**标签无法表达一颗雷的价值**。要让标签有雷位信号，必须先有「18 个候选**全部**在 H 内死亡」的状态（放雷才可能救），本轮 65.67% 的状态连一个动作都不死。

## 12. 命令与偏差

`commands.tsv` 共 30 条命令（label / exit / wall_s / started / finished / argv）。

1. **每格 quota 834 = 10,000/12**：预注册 §1 同时写了「600 局」与「≈10,000 状态」，但在冻结规则下每局约 63–68 个抽样决策，600 局会是 ≈40,000 状态（≈2.4 h 采集），与 §3 的 45–60 min 成本表矛盾。本轮以**状态预算**（§3 的成本锚）为准，每格 quota 834，实际每格 12–13 局、共 160 局，`--max-episodes 50` 未触发。
2. **两遍回放**是「先跑完整轨迹再在触发点附近采状态」这句话的实现方式，不改变被采样的决策集合；回放保真由 46,088 次逐决策校验保证。
3. **行为策略的随机数消耗**：本实现每局固定消耗 300 次策略抽样（pass 1 走满 300 决策），v8.6 则在 quota 到达处截断。两者共用同一 `torch.Generator` 播种规则，但同一 (seed, window) 下的具体轨迹因此与 v8.6 不同。
4. **采集与 v8.6 评测并发**：开工时 WSL 里有 v8.6 的 eval grid 在跑（`th08-modern` 计数 47–60），按工单等了 10 min 后开跑，采集期间仍与其共用 CPU，单状态标签成本 2.9–3.0 s 属受影响的观测值。
5. **未训练、未评测**：P0 不成立（§2.1 `S-data`），不是漏做。
