## 1 为什么需要新版本

v3.6.0 §6.2 把进入 T2 的条件写成 G-1…G-4 全过，其中 **G-3 是生存门**：`ALL` 相对 `BASE` 的 `death_60` 必须提升 +0.05。

T1b 诊断证明这条路走不通，而且原因与策略无关：连"只留两条 T1 通过的块"也只有 **+0.0038**。因为 `ENEMY` 的门禁标签是**归属发弹量**、`POWER` 的是 **power 变化**——两者都不是生存量。**用生存门去挡一个发弹量战术，判据本身就是错配的。**

本版本的修正（**范围修正，不是降阈值**）：

```text
一条策略可以进入 T2，当且仅当它在定义该门禁的语料上通过了自己的 T1 门
（绝对门 + 增量门 + 置换 p<0.05）。
```

明确边界：

1. **G-3 依然有效**，只是它约束的是"七条战术整体能改善生存"这一主张，不再被当作逐策略 T2 的入口；
2. **没有任何逐策略阈值被改动**（绝对门、增量门、p 门逐字沿用 v3.6.0 D3 的 `gate-set d3`）；
3. 已通过的 T1 数字与判定**一字不改**，本版本只新增 T2 证据。

## 3 设计（预注册）

### 3.1 固定协议

| 项 | 值 |
|---|---|
| 游戏 | TH08 1.00d 重建版 |
| 难度 / 机体 | Lunatic / team 0（Border Team） |
| 起点 | practice stage 1，同一菜单宏 |
| frameskip | 2 |
| `max_steps` | 3000（每局 100 秒游戏时间） |
| 每臂局数 | **20**（共 40 局） |
| 采集 | `probe35 collect`，记录全 trace（含 `slots` 与相位字段） |

**为什么固定 team 0**：只有 Border Team 的移动常量被验证过（4.0 / 2.0 px/帧，D2 实测 4.0 / 2.0）。换机体就给某一条臂一个错误的 20 帧前瞻模型，那不是"只改一个因素"。

### 3.2 交错（interleaved）而不是分块

臂按局轮换：`baseline, tactic, baseline, tactic, …`。机器/游戏漂移因此等比例落在两臂上，配对按"局内顺序对"进行。

### 3.3 确定性：必须加种子热身

**实测**：不加随机化时，同一臂的两局**逐字节相同**（动作序列与自机坐标全同）。原因是 TH08 在 run 开始时定种子、practice stage 1 的敌机生成固定。若照原计划跑 20 对，实际样本量是 **1**。

先试过"策略权重抖动"（`horizon_steps ∈ 8..12`、`bottom_bias`、`switch_penalty`），**无效**：开局阶段所有动作的 clearance 都顶到 60 px 上限，排名只由"偏好更大的 y"决定，改变偏好的**幅度**不改变顺序。

改用**种子热身**：

```text
pair k 的前 N 个决策使用伪随机动作序列，N ~ U{20..60}，由 seed+k 唯一确定
    shoot = 1（保持射击）
    bomb  = 0（不得随机化资源使用，否则污染 bomb 指标）
    move  ∈ [0,8], focus ∈ {0,1} 随机
同一对的两条臂使用**完全相同**的热身序列
```

这样配对仍然成立（同一初始条件分布），而各对之间不再重复。种子 `arm_seed = 20261025` 预先写定。

### 3.4 两条臂的定义

| 臂 | 定义 | 代码 |
|---|---|---|
| baseline | `AvoidPilot(PilotConfig(frameskip=2))`，即 D1/D2/D3 用的同一个教师 | `tactics.pilot_config_kwargs("none") == {}` |
| ENEMY | 同上 **+** `aim_weight=3.0`、`aim_safe_margin=10.0` **+** 把目标敌人的坐标当作 `bosses` 传给 pilot 的既有点瞄项 | `tactics.pilot_config_kwargs("clear_enemy")`、`choose_target` |

**单因素**：束搜索宽度、时间视界、bomb 逻辑、安全下限、所有特征块**全部不动**；只把"点瞄谁"从 Boss 换成"价值最高的敌人"，并只在 clearance ≥10 px 的路径上生效（这是 `aim_safe_margin` 的既有语义）。

目标价值函数（固定，不得事后调整）：

```text
value(e) = boss_weight(e) × above_weight(e) / (1 + dist(e)/100)
boss_weight  = 1.0（boss）/ 0.4（普通敌人）
above_weight = 1.5（在自机上方）/ 0.7
```

## 4 指标与判定（ENEMY）

### 4.1 主指标

**每决策归属发弹数**（`attributed_spawns`：槽位法判定新弹、32 px 就近归属），以**相对变化率**比较：

```text
reduction = 1 − mean(tactic) / mean(baseline)
```

配对单位是"对"：每对给出一个 reduction，再做配对 bootstrap（5000 次，`seed=3611`）求 95% 区间与 p。

### 4.2 次指标（必须同时报）

- 目标敌人 life 下降速率、击杀数；
- 60/240 帧后的弹数（`n_bullets`）；
- 生存帧数、死亡次数、bomb 使用数；
- 意图切换率、贴墙率、动作熵、override/中止次数（来自逐决策 `controller`）。

### 4.3 通过条件（全部满足）

| 编号 | 判据 | 阈值 |
|---|---|---:|
| T2-E1 | 归属发弹数下降（配对均值） | **≥15%** 且 bootstrap p<0.05 |
| T2-E2 | 生存帧数 | ≥ baseline 的 **90%** |
| T2-E3 | 死亡率增幅 | ≤ **+10 个百分点** |

**安全优先**：若 T2-E2 或 T2-E3 不满足，无论 T2-E1 多好，一律记 `fail_safety`。

### 4.4 POWER（后续，同一协议）

主指标：**clearance ≥6 px 时的 power 增速**；次指标：P 收集数、Boss 出现时 power、高风险猛冲率（10 帧内把 clearance 压到 3 px 以下）。通过条件：power 增速 ≥15% 且同样满足 T2-E2/T2-E3。

`collect_power` 臂的定义：baseline pilot 不动，仅在 `power<128`、有屏内 P、且 pilot 所选动作 clearance ≥6 px 时，强制"上移+射击+聚焦"（在 y≤110 时改为"停留+聚焦"）。所有中止原因逐决策记录。

## 5 停止线

1. 可用对 < 16 / 20 → `underpowered`，不作任何结论。
2. 任一臂 complete 率 < 95% → 先查记录器，不分析。
3. baseline 臂的归属发弹率与 D3 语料均值相差 >30% → 环境变了，先对比环境再谈差值。
4. 看到结果后**不得**调整 `aim_weight`、`aim_safe_margin`、目标价值函数、32 px 归属半径或热身参数。
5. 不得用同一批对同时调参与判定。

## 6 伪通过清单

- 用 `frames_mean` 提升代替发弹量下降；
- 目标敌人 life 下降但总发弹量没降（说明打错了目标）；
- 生存帧数下降却只报 T2-E1；
- 把 fallback/热身阶段的收益算进战术；
- 用 bomb 的使用换取"活得更久"再宣称清怪有效；
- 只看配对均值不看区间；
- 用 D1/D2/D3 的离线 ρ 代替 T2 的真机证据。
