# v3.6.1 T2-ENEMY 报告：ClearEnemy 对准约束有方向正确的效果，但幅度不到门槛的 1/4

- 日期：2026-10-25
- 依据：[v3.6.1 执行计划-T2](<../执行计划-T2.md>)（预注册）、[v3.6.0 T1-D3 报告](../../v3.6.0/reports/T1-D3报告.md)（准入依据）
- 性质：**T2 真机 paired comparison**。首个按"策略自己的指标"判定的 T2。
- 机器可读：[paired.json](<../experiments/t2-enemy/paired.json>)；人读：[paired.md](<../experiments/t2-enemy/paired.md>)

## 0 一句话结论

20 对同初始条件、同热身、只差"点瞄谁"的真机对比：

| 判据 | 阈值 | 实测 | 判定 |
|---|---:|---:|---|
| T2-E1 归属发弹数下降 | **≥15%** | **+3.63%**（95% CI −0.53% … +7.72%，p=0.047） | ❌ |
| T2-E2 生存帧数比 | ≥90% | 100.0%（两臂都截断在 max_steps） | ✅（退化） |
| T2-E3 死亡次数增量 | ≤+0.10 | **−0.60**（CI −1.20 … +0.05） | ✅ |

**总判定：`fail`。** 方向正确、统计上刚从 0 分离，但幅度只有门槛的 **1/4**，而且 20 对里只有 3 对达到 15%。

这**不是**"清怪无效"的证据，而是"在预注册的对准权重（`aim_weight=3.0`、安全裕度 10 px）下，效果太小"。按预注册，不得在看到结果后调这两个常数。

## 1 设计与执行

| 项 | 值 |
|---|---|
| 游戏 / 难度 / 机体 | TH08 1.00d / Lunatic / team 0（唯一验证过移动常量的机体） |
| 起点 | practice stage 1，同一菜单宏 |
| 每局 | 3,000 决策 / 6,000 帧 / 106.2 s 墙钟 |
| 对局数 | **20 对（40 局）**，交错排布：baseline, tactic, baseline, tactic, … |
| 热身 | 每对 20–60 个伪随机决策，**两臂共享**（种子 `20261025`） |
| complete 率 | 99.96–100%（`frame_mismatch` 0.0–0.04%） |
| 总耗时 | 4,251 s ≈ 71 分钟 |

**两条臂只差一件事**：`aim_weight=3.0` + `aim_safe_margin=10.0`，并把"价值最高的敌人"的坐标当作 `bosses` 传给 pilot 的既有点瞄项。束搜索宽度、时间视界、bomb 逻辑、安全下限、所有特征块全部不动。

### 1.1 一个必须先解决的前置问题：游戏是确定性的

第一次试跑（不加随机化）发现：**同一臂的两局逐字节相同**——动作序列与自机坐标全同。TH08 在 run 开始时定种子，practice stage 1 的敌机生成固定。照原计划跑 20 对，实际样本量是 **1**。

先试"策略权重抖动"（`horizon_steps ∈ 8..12`、`bottom_bias`、`switch_penalty`）——**无效**：开局阶段所有动作的 clearance 都顶到 60 px 上限，排名只由"偏好更大的 y"决定，改变偏好的**幅度**不改变顺序。

最终用**种子热身**：每对的前 20–60 个决策走伪随机动作（射击保持、bomb 强制关闭），两臂共享同一序列。实测两对热身长度 51 / 58 时轨迹确实不同（见 v3.6.0 的 T2 前置记录），而同一对的两臂仍共享初始条件。

## 2 主指标

| 量 | baseline | tactic | 变化 |
|---|---:|---:|---:|
| 归属发弹数 / 决策 | 2.0194 | 1.9357 | **−3.63%** |
| 配对下降均值 | — | — | **+0.0363**，95% CI [−0.0053, +0.0772] |
| bootstrap p（≤0） | — | — | 0.0472 |
| 符号检验（13 正 / 7 负） | — | — | p ≈ 0.263 |
| 达到 15% 的对数 | — | — | **3 / 20** |

逐对下降率：`+16.9, +2.4, +14.1, −3.2, −7.3, +9.2, +19.5, +14.1, −0.8, −6.9, +15.6, −11.4, −9.7, +1.0, +6.6, +6.1, −12.6, +2.9, +7.9, +8.1`（%）

**怎么读这组数**：

- bootstrap p=0.047 略低于 0.05，但 **95% CI 跨 0**（下界 −0.53%），符号检验 p=0.263。三个检验中只有 bootstrap 的边缘显著，所以"下降 3.6%"这个点估计**处在可探测边缘**，不是稳健效应。
- 结论按预注册走：**幅度未达 15% → fail**，且即使把门槛降到 0，这个效应也只能称"弱"。

## 3 次指标（决定"这个 fail 该怎么理解"）

| 指标 | baseline | tactic | 变化 |
|---|---:|---:|---:|
| 屏上平均弹数 | 145.90 | 136.74 | **−6.3%** |
| 平均 clearance | 40.31 | 40.98 | +1.7% |
| 平均 power | 5.38 | 7.70 | **+43.2%** |
| 峰值 power | 12.40 | 14.40 | +16.1% |
| 贴墙帧占比 | 0.3721 | 0.2386 | **−35.9%** |
| 动作熵 | 1.988 | 2.269 | +14.1% |
| 死亡次数 / 局 | 2.25 | 1.65 | **−0.60** |
| bomb 使用 / 局 | 1.6 | 1.3 | −0.3 |
| 瞄准窗口占比（clearance ≥10 px） | 0.8711 | 0.8853 | +1.6% |

三个必须一起读的观察：

1. **瞄准窗口不稀缺**（87% → 89%），所以 3.6% 不是被安全裕度门控住的结果，而是这个权重下的真实上限。
2. **屏上弹数降了 6.3%，比归属发弹数（−3.6%）还多。** 归属指标只算"32 px 内有敌人"的新弹，而瞄准敌人会连带打到**正在发射的敌人本体**（省掉后续整轮弹幕），这部分收益落在 `mean_bullets` 而不完全落在 `attributed_spawns` 上。换句话说：主指标可能**低估**了清怪的效果。
3. **贴墙率降了 36%、死亡少了 0.6 次/局、power 多 43%。** 这三个是同一个机制的三面：为了对准敌人，策略更多地待在场地中上部而不是贴边——而这恰好是"减少贴墙伪通过"想要的，也是 v3.6.0 §2.2 里"保留出口"的间接体现。

**但按预注册，次指标不能救主指标。** 主指标 fail 就是 fail；上面三条写下来是为了让下一版知道往哪走，不是为了翻案。

## 4 判定的严格性检查

| 检查项 | 结果 |
|---|---|
| 可用对 ≥16/20 | ✅ 20/20 |
| 任一臂 complete 率 ≥95% | ✅ 99.96% |
| baseline 归属发弹率与 D3 语料均值差 >30% | 否（2.02 vs D3 的 2.10/决策，差 3.8%） |
| T2-E2 是否有信息 | **无**——两臂都在 max_steps 截断，生存帧恒等 → 该门在本轮**退化**，真正的安全信号是 T2-E3（死亡数） |
| 是否事后调过任何常数 | 否（`aim_weight=3.0`、`aim_safe_margin=10.0`、32 px 半径、热身范围全部按预注册） |

T2-E2 的退化是本轮暴露的一个协议缺陷： practice stage 1 全长约 16,000 帧，而 `max_steps=3000`（6,000 帧）只覆盖前 37%，所有局都截断，生存帧无法区分两臂。**下一轮的 POWER 臂必须提高 `max_steps` 或改用整面**，否则同样退化。

## 5 结论与下一步

### 5.1 本轮结论

- **ClearEnemy 的 T2 判定 = `fail`**：幅度 3.6% / 门槛 15%；
- 但它是第一个**方向与多项次指标同时改善**的战术（发弹 −3.6/−6.3%、死亡 −0.6、贴墙 −36%）；
- **不得**因为方向对就把 fail 改成 pass，也**不得**在本轮调权重重跑。

### 5.2 下一版该做什么（写进提案，不在本轮执行）

预注册一个**更强意图**的实验，而不是调旧权重：

| 候选 | 单因素改动 | 需要的门 |
|---|---|---|
| `clear_enemy_commit` | 把"对准"从软偏好改成"连续 N 帧保持目标 x±8 px 内"的硬约束，安全裕度不变 | 同一 T2-E1/E2/E3，`max_steps` 提到 9000（整面） |
| `clear_enemy_weight` | 只把 `aim_weight` 从 3.0 提到 6.0，其余全同 | 同上；这属于**新实验**，不能用来重判本轮 |

两者都必须在 v3.6.2 里先写后跑。本轮不选。

### 5.3 POWER 臂

同一份预注册已经定义了 POWER 的臂与指标（安全窗口 power 增速），尚未执行。执行前必须先修 T2-E2 的退化（提高 `max_steps`），否则安全门形同虚设。
