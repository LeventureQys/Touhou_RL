## 0. 一句话结论

**单因子 = 放雷规则。** 在冻结的 600 决策（20 s）预算、同样的 4 窗口 × 300 条 × 3 种子 = 3,600 条/臂下，**R5（分段：3 颗 80 px → 2 颗 60 px → 1 颗 40 px）活满 2,776/3,600 = 77.11 %（+6.00 pp，单侧 Fisher p = 3.53e−09，Holm 1.77e−08）**，**R3（双弹：≥2 颗子弹在 60 px 内）2,726/3,600 = 75.72 %（+4.61 pp，p = 5.32e−06，Holm 2.13e−05）**，两者都**显著优于** R0 的 **2,560/3,600 = 71.11 %**（R0 逐条复现 v8.1.0 的 A3 评估：3,600/3,600 条在 11 个行为字段上完全相同）。反方向也清楚：**R1 67.44 %、R4 25.81 %、R2 17.22 % 显著更差**（R1 双侧 Holm 8.17e−04，R2/R4 小到 1e−489 / 1e−334）。两条赢家的性格不同：**R5 冲上限**（seed0/1 = 99.17 % / 98.17 %，但 seed2 只有 **34.0 %**），**R3 压方差**（82.08 / 76.67 / **68.42 %**，最差种子仍近七成）。**R5 的 900 决策档已完整**：**634/3,600 = 17.61 %**（逐种子 18.75 / 34.08 / **0.00 %**），高于 R0 记录的 13.33 %，但 **seed2 归零** —— R5 买的是均值，不是尾部。**334,517 次按雷全部按各自规则逐条复核，0 违例。**

**必须同时读的八件事**：

1. **这是「规则」的胜利，不是「学习」的胜利**：六臂全是脚本规则，**零训练**；本轮不训练、不蒸馏、不改策略。
2. **赢家的机制是「同样的雷，更晚的第二、三颗」**：R0/R1/R5 都在**决策 0** 就放第一颗（停车状态最近子弹只有 18.29–36.38 px，见 §3），而 R5 把第 2、3 颗的触发收紧到 60 / 40 px、R3 收紧到 60 px 且要求 ≥2 颗，末次放雷中位数从 433 推到 **458**，用雷数几乎不变（2.94 vs 2.98）。
3. **「省雷」是错方向**：R2 前 200 决策不放，2,891/3,600 局**三颗雷一颗没花**就死了（活满 17.22 %）；R4 只在贴墙时放，2,300 局一颗没花（25.81 %）。20 s 内一颗雷就是一条命。
4. **R1 提供了反向证据**：把最后一颗放宽到 120 px（更早放）用雷更多（2.9917/局、99.17 % 耗尽）而**更差**（−3.67 pp）。所以不是「放得越多越好」，而是**第一颗早、后面晚**。
5. **均值与方差的取舍必须一起读**：R5 的净增益 +216 条 = **+33（seed0）+54（seed1）+129（seed2）**——前两个种子 R0 已经 96.42 / 93.67 %，能抬的空间只剩 43 + 76 条，所以**增益的大头来自最难种子**（23.25 % → 34.00 %），但 34.00 % 仍是赢家里最差的一格；R3 的 +166 条几乎全部来自 seed2（+542），并在前两个种子各让出 172 / 204 条。**按池化均值 R5 更好（77.11 vs 75.72），按最差种子 R3 更好（68.42 vs 34.00）**；预注册没有为这个分支登记判据（§6.3）。
6. **R0 是精确对照，不是同名不同跑**：1,200×3 条 episode 与 v8.1.0 的 `eval_A3_d600_seed{k}.jsonl` 在 11 个行为字段上**逐条相同**（0 差异），所以 ±pp 列可比。
7. **900 决策档的快照史必须一起读**：任务签发时它是 **1,001 / 971 / 1,200** 行的不完整快照（据此的池化值 **504/3,172 = 15.889 %**，逐种子 **17.982 / 33.3677 / 0.00 %**；任务书写作「15.01 %」，与 504/3,172 不符）；**发布时点三个种子都已跑满 1,200 行**，发布值 **634/3,600 = 17.6111 %**。中间过程的 1,078/1,044 快照已被覆盖、不再存在（§6.2）。
8. **本轮的全部数字都是自算的**：诊断由 `scripts/publish_v840.py` 从**已发布副本**重算，并用执行器自己的 `summary.json`（`out_sha256` / `out_bytes` / `status` / 计数）与日志末行做三源交叉校验（21/21 全过）；本摘要不引用任何执行代理的口头数。

## 2. 判据表

> 口径：P1 用**预注册指定的单侧 Fisher（对 R0）+ Holm 校正 5 个比较**，p 值用**精确有理数**（`math.comb` + `Fraction`）计算，`scipy.stats.fisher_exact` 做交叉校验（相对差 ≤ 1.7e−15，R2/R4 在双精度下下溢，精确值分别为 3.23e−490 / 1.41e−335）。**「显著更差」用的是同一批表的双侧族**——预注册的单侧（greater）族在构造上无法证明「更差」，这一层如实标注（`diagnostics.json → p1_fisher_holm.secondary_family`）。
