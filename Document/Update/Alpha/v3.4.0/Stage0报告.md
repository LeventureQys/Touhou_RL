## 3 逐项证据

### 3.1 S0-1 V 排序：通过，但含金量有限

| 指标 | 数值 |
|---|---:|
| 逐局 Spearman 均值 / 中位 / 最小 | 0.749 / 0.789 / 0.348 |
| 全池 Spearman | 0.665 |
| 剩余帧 MAE | 329 帧 |
| `survive_60` AUC / `survive_240` AUC | 0.925 / 0.934 |
| 剩余帧回归 R² | 0.377 |

**必须一起读的基线**（同样的切分、同样的“逐局 Spearman 均值”）：

| 只用这一个信号排序 | Spearman |
|---|---:|
| 学到的 V | **0.749** |
| 屏幕上活跃弹数量 | **0.681** |
| φ（20 帧可选路线比例） | 0.448 |

结论：V 的排序确实高于随机，但其中大部分可由“屏幕上有多少弹”这一单调时间代理解释；相对该基线的增量只有 +0.07。**V 不能当作“剩余生存帧数预测器”使用**，它目前更像一个“局面推进度”读出。

### 3.2 S0-2 Q 安全判别：通过，且不是“状态级”通过

| H | 安全 AUC（全池） | 同状态内 AUC | top-1 安全率 | oracle 安全率 | R² |
|---|---:|---:|---:|---:|---:|
| 10 | 0.9838 | 0.852 | 98.4% | 99.5% | 0.915 |
| 20 | 0.9768 | 0.858 | 96.8% | 99.3% | 0.900 |
| 40 | 0.9648 | 0.866 | 93.3% | 98.1% | 0.875 |

全池 AUC 可能被“这个状态整体安不安全”抬高，所以另外算了**同状态内**（只在同时含有安全/不安全候选的 3,292 / 5,699 / 8,958 个状态上）的排序 AUC：0.85–0.87。这说明模型确实在使用候选相关的几何信息，而不只是判断局面松紧。

### 3.3 S0-3 教师一致率：未过，原因可分解

实测 35.13%（教师局 3,533 状态，其中 1,523 个“教师在移动”）。诊断（事后，不改判据）：

| 量 | H=10 | H=20 | H=40 |
|---|---:|---:|---:|
| 模型 argmax == 教师动作 | 38.6% | **35.1%** | 13.5% |
| **标签 argmax == 教师动作**（标签族自身的上限） | 52.1% | **48.3%** | 43.3% |
| 模型 argmax == 标签 argmax（复现自己的标签） | 52.9% | 46.9% | **22.9%** |
| 教师动作在标签下的安全率 | 93.7% | 86.6% | 77.9% |
| 教师动作的标签排名（0=最优，均值） | 2.97 | 3.38 | 3.64 |
| 教师动作恰为标签最优 | 52.1% | 48.3% | 43.3% |
| 教师动作在标签 top-3 | 60.0% | 56.6% | 54.4% |

两条独立的原因：

1. **标签族不是教师的决策规则。** 教师是“按 1/3/5 决策的 chunk 做 beam + 每次重规划”的规划器；本阶段标签是“把一个方向按住 H 帧”。教师动作的平均标签排名是 3.4，只有 48.3%（H=20）恰为标签最优。也就是说：**即使模型 100% 复现标签，也过不了 50% 这条门**（H=20 的上限是 48.3%，H=10 是 52.1%）。
2. **模型的 argmax 精度不够。** 回归用的是 `log1p(clearance)` 的 MSE，遇到大量候选同时顶到 60 px 的平台区时，损失不区分“谁第一”；H=40 时模型只复现了 22.9% 的标签 argmax。AUC 高（0.965）与 argmax 差可以同时成立。

### 3.4 S0-4 死亡前风险：通过

| 量 | 数值 |
|---|---:|
| AUC（`remaining < 60` 正类 336，`> 300` 负类抽样 336） | 0.938 |
| 置换检验 p（200 次） | 0.005（可达到的最小值 1/201） |
| 风险均值：正类 / 负类 | 0.2457 / 0.0088 |

注意：`survive_60` 头的**准确率 98.31% 对基率 98.29%**——正类只占 1.7%，准确率没有信息量，排序 AUC 才是判据。

### 3.5 标签口径：0.9005

用执行动作的 H=20 几何 clearance 去预测“60 帧内死亡”，AUC = 0.9005。几何标签与真实危险同向，这一条支持继续用该标签族做 Stage 1 的价值目标（但见 §3.3：不要再用“教师动作”做监督目标）。

## 4 结论

1. **Stage 0 未通过**：S0-0（77.93% < 90%）与 S0-3（35.13% < 50%）未过。按执行计划 §6/§9，Stage 1 不启动，也不做任何“调门禁重跑”。
2. **失败不是“状态不够”**：S0-1/S0-2/S0-4 通过，且 Q 的同状态内排序 AUC 0.85–0.87、R² 0.88–0.92；几何标签对真实死亡 AUC 0.90。信息在状态里。
3. **失败是两件具体的事**：
   - 数据可用率被**采集缺陷**（教师演示 23% 抓帧不一致）与**旧版 trace**（8,326 行无快照）拉低，这是可修的工程问题；
   - 预注册的 S0-3 把“学到标签”与“与教师动作相同”混为一谈，而后者在本标签族下**上限只有约 48%**。
4. **V 的读数需要打折**：0.749 的排序里有 0.681 可由“弹幕数量”解释。

## 5 对 v3.4.1 的建议（不在本版执行）

1. **修采集**：教师演示的 `complete=false` 达 23%，而 Stage 1 需要的正是这些密集状态。先在采集侧把三次抓帧的时间戳对齐（或至少记录可复现的丢弃口径），再谈 90% 的数据门。
2. **重写数据门的分母**：把“旧版 trace（无快照）”“抓帧竞争”“无敌帧”三类分开报，而不是合成一个 77.93%；对 schema 内行单独给阈值。
3. **替换 S0-3**：改为三条与 Stage 1 真正相关的判据——
   - 标签保真：模型 argmax == 标签 argmax ≥ 80%（H=10/20）；
   - 排序包容：教师动作落在模型 top-3 ≥ 70%；
   - 教师安全：教师动作在模型下的安全率 ≥ 95%（当前 H=20 为 86.6%，对应的是标签口径差异，不是模型错误）。
4. **Q 的目标函数**：MSE 回归在平台区不区分 top-1（H=40 复现率 22.9%）。若要 Stage 1 用 argmax 选动作，至少要加 pairwise/listwise 排序项，并把训练轮数加到验证损失不再下降（本版 12 轮末仍在下降）。
5. **V 的目标**：`remaining frames` 与“局面推进度”高度共线（弹幕数量基线 0.681）。改为预测固定视界的生存概率，或对弹幕密度做条件化，并在报告里固定给出密度基线。
