## 1. 本轮改了什么（代码/合同）

1. **`f2_labels.validate_event_annotation`（F-1）**
   - 新增必填容差 `aim_miss_px`（命中半径漏距）、`aim_lookback_frames`（瞄准帧回看上限）、`emission_recency_frames`（发射距当前行上限）。
   - 瞄准证明改为：以**特权 teacher 位置**算弹速，取"标注自机点 → 弹道直线"的垂直距离 `|cross|/|v|`；要求 ≤ `aim_miss_px`、自机在发射前方、瞄准帧在回看窗口内、发射在流内时间窗内。
   - 每发必须申报 `miss_px`，合同**重算并比对**（阈值 0.01 px），申报值造假即失败。
   - 删除原"速度空间角度"判据——它允许几十度的角度误差，留着只会假装检查过。
   - "发射帧"与"首个可测像素帧"分离：teacher 轨迹必须起于发射帧，像素轨迹只需覆盖观测帧且不得早于发射帧。
2. **`f2_dataset._verify_teacher`（F-1 第二道）**：直接从**原始弹池**（位置+速度）重算漏距，不信任标注里的 teacher 副本。
3. **新工具 `tools/rl/v376_wpc_review.py`**：冻结窗口选择 + 逐行穷举标注；结构性规则（历史帧缺失即不可用）与测量分离；申报容差由实测反推。
4. **新工具 `tools/rl/v376_wpe_plan.py`**：把预注册 + 九份复核 + 三份采集冻结成 `v376-f2-bc-plan-20261105-r4.json`，逐项校验 review↔capture↔replay↔collect 的 SHA 绑定。
5. **新工具 `tools/rl/v376_wpd_audit.py`（F-6）**：独立实现，不 import `f2_labels`/`f2_dataset`/复核工具；自带 18 路映射、自带漏距算术、另一套像素估计器。
6. **新工具 `tools/rl/v376_eval.py`（G-1）**：只读冻结协议，禁止改容差；基线必须与模型并列；test 只读一次且拒绝覆盖。

## 4. 训练：执行了什么

- 一次更新集成测（[report](../../../../../third_party/th08/build/rl/f2/v376-f2-bc-train-20261105-r4-oneupdate/report.json)）：`updates=1`、`validation_loss=2.7696`、骨干不变、`test_used=false`、checkpoint 可读回 → 链路成立。
- 冻结预算正式训练（[report](../../../../../third_party/th08/build/rl/f2/v376-f2-bc-train-20261105-r4/report.json)）：arm N1、seed 7、lr 1e-3、burnin16/seq32、**epochs 30 / max_updates 1000**、GPU FP32。实际 **120 次更新**（每 epoch 4 次；6 个 train 窗口里有 2 个不含任何监督行，被跳过并计数 `skipped_unknown=2`）。
- 验证损失轨迹：epoch 0 **2.7601** → epoch 2 **2.7589（最优，被选中）** → epoch 4 3.03 → epoch 10 3.67 → epoch 29 **5.4640**。**单调恶化**：54 行有效训练行、12 次更新后就开始过拟合，之后越训越差。
- 被选中的 checkpoint（epoch 2）在**训练集**上只有 16.7% 准确率——即选模规则把一个"几乎还没学会"的模型选成了最终模型。这是数据量不足 + 选模规则（最低验证损失）共同造成的，两条都在预注册里写明，不是事后调参。

## 5. 评估：冻结指标（先验证，后封存测试）

| 指标 | 验证集（121 行） | 封存测试（68 行） |
|---|---:|---:|
| **模型总体准确率** | **4.96%** | **1.47%** |
| 类别平衡准确率 | 4.19% | 1.14% |
| 逐事件宏平均 | 4.22% | 1.28% |
| 动作变化行准确率 | 33.3%（3 行） | 0.0%（9 行） |
| **保持上一动作基线** | **97.52%** | **86.76%** |
| 多数类基线（train 的 8） | 12.40% | 0.00% |
| 均匀随机 | 5.56% | 5.56% |
| 训练集监督行数 | 54 | 54 |

逐事件：验证 0.0% / 9.4% / 3.2%；测试 0.0% / 3.8% / 0.0%。

**像素消融**（把 playfield 置零后重测）：验证准确率 **5.79%**，比不置零的 4.96% **更高**。也就是说模型完全没有在利用弹幕画面——不是"学会了错误特征"，而是"没学到东西"；同时也没有 HUD 捷径可归因。

**为什么说这是可信的否定结果**：
1. 两个 split 独立给出同一方向的结论；test 在一次封存读里复现了验证结论。
2. 基线是照协议事先写死的，不是事后补的；模型低于**任一条**平凡基线（连"随机"都不如）。
3. 交叉检查显示链路本身是活的：loss 从 2.76 降到 0.02（后期），梯度范数有限，骨干 SHA 前后一致，checkpoint 可读回——**优化器在工作，是数据量和"保持动作"主导的标签分布让泛化不可能**。

**必须写清的解释边界**：
- 任务本身对"策略"极不友好：验证集 97.5% 的行都是"保持上一动作"，任何模型必须先打败这个常数预测器才有意义。
- 训练窗口按"存在瞄准弹流"选，这些窗口恰好也是人类频繁变向的时刻（train 104 行里 20 处变化），而验证/测试事件以长按为主（12/17 处变化分布在更多行上），存在**由选窗规则带来的分布位移**。这不是 bug，但它说明"用瞄准弹流窗口训练、在整段验证"这种协议本身需要重新设计。
- 因此本轮结论只能写：**该数据规模与选窗规则下，冻结预算训练没有产生任何技能证据**；不能写"F2 弹流无法学习"，也不能写"方法无效"。

## 6. 本轮自己发现并修掉的错误（自我证伪记录）

1. **第一次写评估工具时把"保持上一动作"基线算成 4.13%**：代码拿它跟**模型预测**比，而不是跟真值比。修正后同一份数据的该基线是 97.5%。原始错误读数的报告已删除重生成；这段保留，因为"基线的定义错误"正是最容易把否定结果说成肯定的地方。
2. **第一次构建失败**：`missing complete current/past exact PNG`。原因不是数据错，是采集在个别帧跳过了 `-4/-2`，而冻结配置要求精确历史帧。处置：把"历史帧缺失即不可用"写成**结构性规则**（先于任何像素/动作判断），重新生成 r6 复核、重新冻结 plan r4；失败目录未落盘、未覆盖任何旧证据。r5/r3 作为失败尝试保留在库里。
3. **第一版瞄准探针把瞄准帧取在当前行而不是发射帧**，得出"只有 83/3000 行合格"的错误结论。改成发射帧后是 293–500/3000 行。这段说明：合同里"瞄准帧必须绑定发射帧"不是形式要求，它决定了整个数据的量级。

- **F-6 独立性**：本轮的"独立复核"是另一份实现、同一个 AI 开发者写的，**不是**未参与实现的人类复核。要满足计划 §7 的原文要求，仍需真人或另一组织的执行者只读复核。

- **技能**：无。任何"模型学到了 F2 应对"的表述都不成立。
- **数据量**：340 行有效监督、单关卡、三份回放。要在统计上谈泛化，事件数至少要再上一个量级，而且选窗规则必须重新预注册（本轮已暴露"瞄准弹流窗口 ↔ 动作频繁变化"的分布位移）。
- **长训练**：本轮 120 次更新就在验证集上单调恶化；在一个先打败"保持上一动作"的表述框架建立之前，加预算没有意义。
