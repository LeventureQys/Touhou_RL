## 2. 接口契约（输入 / 输出 / shape / 退出码）

### 2.1 `touhou_rl/vmodels.py`

```python
VISION_ARCH_V1 = "v1"; VISION_ARCH_V2 = "v2"; VISION_ARCH_V3 = "v3-st"
KNOWN_VISION_ARCHES = ("v1", "v2", "v3-st")
V3_CHECKPOINT_SCHEMA = "vision-checkpoint/3"
V3_REQUIRED_EXTRA = ("source_state_sha","teacher_fingerprint","manifest_sha","val_index_sha256","loss_config")

vision_arch(model) -> str
    # v1 -> "v1"; v2 -> "v2"; v3 -> "v3-st"; 其它 -> ValueError("v104:CHECKPOINT: unknown vision model type ...")
```

- `save_vision_checkpoint(path, model, extra=None)`：arch 由模型类型决定。v1/v2 **保持 v1.0.3 payload 形状**（`kind/arch/state_dict/config/frame/extra`，无 `schema`）；v3 写 `schema=vision-checkpoint/3` + 同上键，并在**落盘前**调用 `validate_v3_payload()`，缺身份/契约不符直接失败，写不出伪 checkpoint。
- `validate_v3_payload(payload) -> dict`：校验 schema/kind/arch、`extra` 五键（`source_state_sha` 允许空串=无初始化来源，但 `stage` 含 "policy" 时空串即 `v104:CHECKPOINT`；`manifest_sha`/`val_index_sha256` 必须 64 位小写 hex；`teacher_fingerprint` 非空；`loss_config` 非空）、depth=3、`channels`/`normalization`/`state_head` **有则校验、无则按 C1/C5 默认**（S3-5 的真实 config 不暴露 `state_head`）、`candidate_order_version=="focus9-move-v1"`、`score_semantics=="preference_logits"`、`history_contract ∈ {legacy, causal-segment-v1}`、`roi_native_hw==(128,128)`、`local_grid_hw==(16,16)`、`align_corners is False`、三 ROI 尺寸 `224x192/34x216/126x216`、`frame.C==3`；返回 contract 记录（含 `legacy_frame` 与 `identity`）。
- `load_vision_checkpoint(path, map_location="cpu") -> (model, extra)`：
  - 无 `arch` → v1（pre-v1.0.3 兼容不变）；未知 arch → `v104:CHECKPOINT: unknown vision arch ...`（消息仍含 `unknown vision arch`，旧断言兼容）；
  - v1/v2 继续校验 `frame.H/W == 128/112`（历史构建约束），`state_dict` 严格加载；
  - **v3**：先 `validate_v3_payload`，再按 `config` 构造 `VisionSpatialTemporalConfig` 并 `load_state_dict(strict=True)`；Q6 前 `vmodels3.py` 缺失时曾报 `v104:CHECKPOINT: ... v3 branch blocked ...`，该防御分支保留（缺模块仍不伪造成功、不落到 v1），Q6 后真实模型存在即正常加载（见 §11）。
- `frame` 语义：v1/v2 是历史构建字段；v3 仅是 H128/W112 兼容标记，真实输入以 `config.region_sizes` 为准（单测 `test_checkpoint_frame_is_a_legacy_marker_not_the_model_input` 固定）。

```python
resolve_vision_depth(model, requested: int) -> int
    # 0 或缺省 = model.config.depth；requested<0 -> v104:CHECKPOINT；requested not in (0, depth) -> v104:CHECKPOINT
    # 消息：v104:CHECKPOINT: --vision-depth <requested> != checkpoint depth <actual>
```

- 解析在建 env **之前**（`load_vision_checkpoint` → `resolve_vision_depth` → 才构造 `Th08Env`/stub）；v3 协议校验同样在加载阶段。
- `main()`：捕获 `v104:<CODE>:` 前缀的 `ValueError` → `print(str(exc), file=sys.stderr)` + `return 2`；未知异常保留 traceback 与非零退出。
- `vision_report_node(checkpoint, model, depth, max_steps=None, extra=None)`：保留原键 `checkpoint/arch/depth/region_sizes/frame_shape/isolation`，**增量键** `max_steps`（A-04 需要，report 其它处无法表达）；仅 v3 追加 `contract`（`validate_v3_payload` 的 contract 记录）。非 vision 报告的键集合不变（单测 `test_no_vision_node_without_vision_checkpoint` 仍锁定原 13 个顶层键与 15 个逐局键）。
- 逐局 **增量键**（仅 vision 分支）：

```json
"vision_diagnostics": {
  "bomb_actions_requested": 0,
  "screenshot_to_action_ms": {"count": 4, "mean": 4.585, "p50": 4.641, "p95": 4.867, "max": 4.901},
  "observed_frame_delta": {"count": 3, "min": 2, "p50": 2.0, "p95": 2.0, "max": 2, "nonpositive": 0}
}
```

  - 时延：`perf_counter` 从本决策 `env.render()` 开始到动作交给 `env.step` 之前，毫秒；`count==0` 时其余统计为 `null`（不写 0.0）。
  - 帧差：取自 harness 既有的 `info["frame"]/["stage"]`；只统计**同 stage 且 delta>0** 的相邻决策，`<=0` 另计 `nonpositive`，缺字段则断开区间；不同 stage 不计数。
  - `bomb_actions_requested` 按真正发给 `env.step` 的 `action[3]` 逐次求和（当前必为 0），不当资源净消耗。
  - 原始采样写入 `<out>/vision-diagnostics-raw.json`（`schema=v104-vision-diagnostics-raw/1`，含每局 `timing_ms[]`/`frame_delta[]`/`nonpositive`），p50/p95 可复算。
  - 诊断只在该决策动作**已算出并送出后**记录，绝不参与策略输入、历史重置或任何动作选择。

### 2.3 `tools/rl/compare_state_models.py`

```
--dataset PATH            必填
--manifest PATH           可选；缺省 = <dataset>/manifest.json；B 必须显式给 S3-1 评估清单
--mode full-val|stage-sample  默认 stage-sample（向后兼容）
--per-stage N             默认 128
--checkpoint LABEL=PATH  可重复
--batch N                 默认 64
--out PATH                可选，JSON 数组（每 checkpoint 一行）
--baseline PATH           可选，A 侧此前的输出，用于 A-03 比例
```

- **校验**：`DatasetManifest.load` → `verify(deep=True)`（分片存在/字节/总数/多余文件/`split_indices` 重推导与 `val_index_sha256` 比对）→ 再显式 `verify_split()` 复核；manifest 缺失或任一不符 → `v104:DATA`（**不**回退重推 split）。
- **采样**：`full-val` = 验证索引全集（升序）；`stage-sample` = 每 stage 验证索引**升序前 N**（不足则全取并报 `available/selected`）。选择结果与调用方传入顺序无关（内部排序），`selected_index_sha256 = sha256(",".join(str(i)))`（与 `val_index_sha256` 同算法）。
- **depth/历史**：`depth = model.config.depth`；`history_contract` 取 checkpoint `extra["history_contract"]`，缺失 → `legacy` 且 `legacy_history=true`；`dataset.stack_indices(chunk, depth)` 得 oldest→newest 的 `[N,depth]`，逐 ROI reshape 成 `[N,depth,H,W,3]` → `regions_to_batch`。**不复制第二份历史算法、不 reshape 成 depth 1**。
- **输出字段（每行）**：`label / checkpoint / checkpoint_sha256 / arch / depth / history_contract / legacy_history / playfield_hw / parameters / dataset / manifest / manifest_sha256 / val_index_sha256 / val_frames / sampling_mode / per_stage_limit / per_stage{stage:{frames,available,selected,mae,mae_raw,p90}} / selection{stage:{available,selected}} / frames / selected_index_sha256 / selected_indices / mae_raw / mae / median / p90 / under_10px_share / tail_gt30_share`。`mae_raw` **不舍入**；展示值 `mae=round(mae_raw,2)`。
- **误差口径未改**：`(|Δx|·384 + |Δy|·448)/2`；预测/标签非有限 → `v104:DATA`。
- **A-03**：`--baseline` 读入 A 侧输出，要求同 `checkpoint_sha256`、同 `sampling_mode=stage-sample`、不同 `dataset`；输出 `ratio=B_mae_raw/A_mae_raw`、`threshold=1.25`、`pass`；`full-val` 侧会被 blocked（禁止 full-val 与 B 分层比）。
- **错误/退出**：已知 `v104:<CODE>`（CONFIG/DATA/CHECKPOINT）→ stderr 同前缀 + exit 2；未知异常保留 traceback 非零。`evaluate(checkpoint, dataset_dir, per_stage, stride)` 旧签名保留（stride 仅为兼容而忽略，默认 stage-sample）。

### 2.4 `tools/rl/check_v104.py`

```
--artifacts PATH   冻结清单（schema=v104-final/1）
--out PATH         逐项判定 JSON
--root PATH        冻结相对路径的解析根（默认仓库根）
--quiet            只写 JSON
```

- **冻结清单**：强制 20 个平铺键（state_checkpoint/state_checkpoint_sha256/state_summary/policy_checkpoint/policy_checkpoint_sha256/policy_summary/teacher_cache/teacher_fingerprint/manifest_a/manifest_a_sha256/manifest_b/manifest_b_sha256/val_index_sha256/arch/depth/seed/experiment_table/selection_reason/frozen_at/external_guard_uses）+ `evidence`；`state_run`/`policy_run` 可选仅交叉核验；`architecture` **不是** `arch` 别名（显式 `KeyError` → CLI `v104:EVIDENCE` exit 2）；所有路径必须工作区相对、`*_sha256` 64 位小写 hex、`frozen_at` 带时区、`arch ∈ {"v1","v2","v3-st"}`。
- **身份核验**：`state_checkpoint/policy_checkpoint/manifest_a/manifest_b` 重新 hash 与声明比对；`state_summary`/`policy_summary` 必须 `schema=vision-summary/2`、`contract_version=v104-A/1`、且 `stages.<stage>.best.checkpoint_sha256` == 冻结 sha（"summary 必须与重评对象一致"）；`manifest_a` 的 split 重算必须等于冻结 `val_index_sha256` 且 `val_frames==7241`；`manifest_b` split 可复现。教师/实验表仅存在性（`teacher_fingerprint` 非空，接受 str 或 mapping）。
- **证据 9 键**：`state_recheck / policy_full_val / cross_replay / eval_report / pytest / d9 / d10 / d11 / startup`，每项 `{path, sha256}` 指 `schema=v104-evidence/1` 索引，索引必需 `kind/status/created_at/producer/command/cwd/exit_code/artifacts/observations/reason`；索引文件 sha 与每个 artifact 的 sha 都重算；索引 `observations` 与 artifact 内 `observations`（或平铺同名字段）逐键比对；证据映射多出键 → `v104:EVIDENCE` exit 2。
- **复算（不只信 status）**：
  - A-01（`state_recheck`）：`checkpoint_sha256==frozen state_checkpoint_sha256`、`frames==7241`、`coverage_sha256==frozen val_index_sha256`、`player_pos_px<10.0`、`danger_corr_perframe_median>0.8`、`danger_corr_perframe_valid>0`；身份/覆盖不符 blocked，阈值不达 fail。
  - A-02（`policy_full_val`）：`checkpoint_sha256==frozen policy_checkpoint_sha256`、`0-15` 桶 `frames>0`、未 clip 教师 px `regret<1.5`、`top3` 必须存在；空桶 fail（零值不得当测量）。
  - A-03（`cross_replay`）：同 policy、`sampling_mode=stage-sample`、`per_stage==128`，`a/b_indices_sha256` 与 `a/b_frames` 由两份 manifest **重新推导**比对，`ratio=B/A<=1.25`。
  - A-04（`eval_report` + `startup`）：从 eval-report 原始 JSON 复算 `episodes`、`frames_mean`、`hit_step_cap`（`termination_reason=="max_steps"` 计数）、逐局字段完整性、`difficulty==3(Lunatic)/team==0/frameskip==2/practice_stage∈{None,-1}/max_steps==12000`；report 的 `vision.checkpoint` 必须解析到冻结 policy.pt 字节；**startup 必须存在且 pass/真实开局**（`real_game_started/pixels_only/no_crash/no_exception_log/ui_checked==true` 且 screenshots 非空）——stub 报告无法通过。
  - A-05（`pytest`）：`failed==0`、`passed>=178`、`command_exit==0`，并从原始日志解析 `N passed/failed/error` 与索引计数比对。
  - A-06（`d9`+`d10`+`d11`）：三者齐全且 `status` 非 blocked；D9 `expected==actual==7241` 且 `visited_index_sha256==frozen`；D10 `budget_bytes==536870912`、`max_resident_bytes<=budget`、`lru_verified/value_equal==true`；D11 `validated_files==expected_files>0`、`bytes_total>0`、`value_equal==true`、`manifest_sha` 为 64 hex。
- **退出码**：exit 0 = 六项全 pass；exit 1 = 有 fail 且无 blocked；exit 2 = 有 blocked（可与 fail 并存，JSON 每项独立状态）或冻结清单本身不可用。
- **输出 JSON**（`schema=v104-check/1`）：`artifacts{path,sha256,root}`、`frozen{arch,depth,seed,val_index_sha256,frozen_at,external_guard_uses,identity_ok,identity_errors,files,manifests,summaries}`、`evidence{key:{ok,status,path,hash,errors}}`、`items{A-01..A-06:{status,source,path,hash,artifacts,values,thresholds,reason}}`、`counts`、`exit_code`。
