派生属性（与 v2 同名同语义）：`region_names == ('playfield','hud_score','hud_status')`、`region_sizes -> {name: (H,W)}`、`heatmap_hw == (56,48)`（= playfield/4）、`native_playfield_hw == (448,384)`。

**未暴露 `state_head`**：C5 允许「若不支持就别暴露该配置」，本实现不提供该开关，`decode_state` 因此永远不会抛 `state_head=False` 的 RuntimeError。S3-6 的 `validate_v3_payload` 对该键**缺省即通过**（已由单测锁定）。

### 3.2 层结构（与 C5 文字逐条对应）

1. 场地：`Conv5 s2 p2 9→32` → `Conv3 s2 p1 32→64` → **F4** → 两个 `ResidualBlock(64)`（Conv3-ReLU-Conv3 + skip + ReLU，无 BN）→ `Conv3 s2 p1 64→96` → 两个 `ResidualBlock(96)` → **F8**。
2. 定位：F8 `F.interpolate(..., mode='bilinear', align_corners=False)` 到 F4 尺寸 → concat F4 = **160** → `Conv3 p1 160→64` + ReLU → `Conv1 64→1` → `heatmap_logits[B,56,48]`；`decode_position`（复用 v2 唯一实现）给出 `position=(rx,ry)`；`location_stats = [entropy/log(HW), max_prob]`；4 维 `[rx, ry, entropy_n, max_prob]` → `Linear(4,16)+ReLU`。
3. 局部：`local_grid(position.detach())`；`grid_x = 2rx-1+2dx/384`、`grid_y = 2ry-1+2dy/448`（dx/dy 为原生像素 bin 中心 −60…+60，步长 8）；`grid_sample(mode='bilinear', padding_mode='zeros', align_corners=False)`；同一 grid 采样全 1 `[B,1,56,48]` 得 `[B,1,16,16]` 有效性 mask；concat 65 通道 → `Conv3 s2 p1 65→64` → `Conv3 s2 p1 64→96` → flatten `96×4×4=1536` → `Linear 1536→128`。
4. 全局：F8 `Conv1 96→32` → `AdaptiveAvgPool2d(7,6)` → 追加 2 个 cell-center 归一化坐标通道（`(row+0.5)/7`、`(col+0.5)/6`）→ flatten `34×7×6=1428` → `Linear 1428→128` + ReLU。
5. HUD：两个独立小 CNN，**结构与 v2 相同**（Conv5 s2 → Conv3 s2 → Conv3 s2 → AdaptiveAvgPool(pool) → Flatten → Linear → ReLU，pool 分别 `(2,8)`/`(8,4)`），但输入通道是 **3**（只取最新帧），各 64 维。
6. 融合：`[local128, global128, hud_score64, hud_status64, location16]` = **400** → `Linear400→256`+ReLU → `Linear256→256`+ReLU → `features[B,256]`。
7. 头：`policy_head=Linear(256,18)`；`self_head=Linear(256,22)`，`self_pred = cat([position(2), self_head(22)]) = [B,24]`（列 0/1 仍是位置，保持 C3「self 辅助只训 4..12,14..23」的列语义）；danger：F8 `Conv1 96→32` → bilinear 到 `32×16` → `Conv3 p1 32→32`+ReLU → `AvgPool2d(2)` → `16×8` → `Conv1 32→1` → 行优先 flatten `[B,128]`（末端无 ReLU）。

### 10.3 两处 C5 文字的解释选择（请 S3-4/S3-7 复核，不是遗漏）

1. **`location_stats` 的熵是归一化熵**：C5 写「归一化 entropy/log(HW) … 与 rx/ry 合计 4 维 … `location_stats[B,2]` 为 [entropy, max_probability]」。本实现取 `location_stats[:,0] = entropy / log(56*48)`（∈[0,1]，均匀分布=1、单格≈0），与进 MLP 的 4 维完全同源（不做第二份统计）。若评审要求给原始熵，改一处即可，但训练/诊断口径需同步。
2. **`center_detach` 只切「采样坐标」**：按 C5「仅阻断策略梯度经采样坐标」的字面，`location_mlp` 的输入 `(rx, ry, entropy_n, max_prob)` **未** detach，因此策略损失会经该 MLP 给 heatmap 头一点梯度。实测（`evidence/11-shape-grad-probe.log` §D）：heatmap 单独反传时 heat_conv/heatmap_head 的 `sum|grad|` = 422024.3/5852.6，策略单独反传时仅 0.0231/0.000128（低 7 个量级），采样坐标路径的 `position.grad` 严格为 `None`。若评审要「heatmap 只由辅助损失训练」，只需在 `location_mlp` 输入处再 detach 一次，属一行改动 + 改本报告口径，请勿默认已如此。
