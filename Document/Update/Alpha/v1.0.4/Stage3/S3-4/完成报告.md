### 2.4 matrix 编排（两段式，同 depth 同字节）

1. 先跑所需 depth 的感知 run（`--stage state --epochs-state 72`）。
2. 读 `stages.state.best`：有 `state-pass.pt` 用它，否则 `state.pt`；把该文件路径绑进六个策略 run 的 `--init-from` 并记 sha256。**本次两个 depth 都没有 state-pass.pt（A-01 未达标），所以六个策略 run 都从 `state.pt` 起跑**（policy 传播，`source_state.selection_rule` 记录在 summary 里）。
3. 策略 run 跑完强制核 `source_state.sha256 == 该 depth state 检查点 sha256`，不等即 `v104:CHECKPOINT` 停止。
4. 每个 run 后硬核 `coverage.val.actual_frames==7241 && complete==true`，否则 `v104:COVERAGE` 停止。
5. 每个策略 run 后用该 `policy.pt` 在 7241 上重评感知（`final_policy_perception`），供 gate 的"policy 全量感知"条件。
6. 已存在 run 目录：recipe 逐项一致 → `reused=true` 跳过；不一致 → `v104:EVIDENCE` 拒绝。

### 2.5 60 s/epoch 口径（用户裁决 Q5）

- `BUDGET_SECONDS=60.0`；`epoch_seconds_summary()` 把前 2 个 epoch 记为冷启动（一次性 cache/labels 填充），**稳态**用于比较；`budget_exceeded()`/`budget_overrun()` 只标记不停止、不重测、不改轮数/batch/depth。
- 每行实验表带 `cold_start_seconds`、`steady_mean_seconds`、`steady_max_seconds`、`exceeded`、`overrun_fraction`。
- 单测 `test_budget_uses_the_steady_state_not_the_cold_start_epoch` 锁定"冷启动不得触发超限标记"。
