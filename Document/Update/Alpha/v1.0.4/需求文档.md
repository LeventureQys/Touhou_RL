## 0. 三十秒版本

项目要让 AI 只看游戏画面就会玩东方 Project（当前 TH08）。读内存只允许出现在训练期，作为特权教师。

v1.0.3 的结论是「架构没改错，但数据集里 73% 的帧画面冻结」。该问题已修复：采集器加了三重护栏，
重新采的 `pilot-ud0059-v2` 与补充采的 `pilot-ud0063` 都是 0 冻结帧。视觉学生随之从 68 px 改善到 12.81 px。

**现在卡在两处，且都不是数据量问题：**

1. **策略（A-02）几乎没工作**：0–15 px 桶后悔值 3.97 px，只比「18 个候选里瞎猜」的 4.90 px 好 19%。
   根因已定位：教师价值近乎并列（24.9% 的帧最優与次优完全相等），用回归逼它，输出会塌成常数，argmax 等于随机。
2. **位置（A-01）只剩一个关卡没过**：stage 0/1/4/5/7 已到 4.7–10.6 px，**stage 2 停在 15.2 px**；
   全验证集均值 12.81 px，但 70.3% 的帧已经 ≤10 px，均值是被 12.6% 的长尾拉的。

**已被实验排除的方向（不要再花时间）**：继续采数据（跨回放只差 17%）、提高场地输入分辨率（更差）、
自机被弹幕遮挡（与误差无关）。

## 4. 瓶颈诊断（三条，含证据）

### 4.1 P1 · 策略目标与标签不匹配（**最高优先级**）

教师对 18 个候选给出的价值近乎并列：

| 指标 | 值 |
| --- | ---: |
| 最优 − 次优 差值 p50 | **0.609 px** |
| 完全并列（≤0.01 px）的帧 | **24.9%** |
| 差值 ≤1.0 px 的帧 | **61.6%** |
| 帧内 18 候选极差 p50 | 12.56 px（**有信号**） |

后悔值基准：

| 策略 | 平均后悔 |
| --- | ---: |
| 只在 teacher top-3 里随机挑 | **0.892 px** |
| 只在 top-6 里随机挑 | 1.841 px |
| 18 个候选完全随机 | 4.895 px |
| **当前视觉学生** | **3.744–3.968 px** |

机制：`smooth_l1` 要求逐候选回归到几乎相等的目标，最优解就是把 18 个输出压成近似常数；
argmax 于是在并列里随机取一个，后悔值退化到随机水平附近。**这不是数据量或表征能力问题**
（表征把位置误差从 68 px 降到 12.8 px，策略却纹丝不动）。

### 4.2 P2 · 位置误差的残差集中在 stage 2 与长尾

- 12.6% 的帧误差 >30 px，贡献 **41.7%** 的总误差；其余帧中位数 5.18 px。
- 与弹幕密度 corr=−0.12、与自机处亮度 corr=+0.09、与 15 px 内子弹数 corr=−0.05 → **遮挡/拥挤被排除**。
- 场地输入 224×192 → 336×288（24 轮对照）：**21.95 px，比 224×192 的 15.59 px 更差**，且收敛更慢 → **分辨率被排除**。
- 过拟合 100 帧可到 **8.06 px** → 容量不是硬上限。
- 结论：残余误差是**复杂关卡上的精度问题**，需要更强的手段（多尺度 heatmap、容量、难帧加权），不是更多同质数据。

### 4.3 P3 · danger 分支落后于位置分支

per-frame corr 0.638（目标 0.8），全局 0.728。位置已 9–13 px，danger 却仍是「能看出大概密度」的水平。
可能是 danger 头（1×1 conv on pooled 16×8）容量不足，或 per-frame 相关对宽分布天然敏感。

## 5. 已被实验排除的方向

### 5.1 提高场地输入分辨率 —— 更差

| 配置（24 轮） | 位置误差 | 说明 |
| --- | ---: | --- |

### 5.2 增加回放数量 —— 跨回放只差 17%

| 指标 | 同回放 | 跨回放（未见过） | 变化 |
| --- | ---: | ---: | ---: |

| 中位数 | 5.18 px | 5.46 px | +5% |
| ≤10 px 占比 | 70.3% | 69.5% | −0.8 点 |

**模型换一份全新回放几乎不掉点** → 数据多样性不是瓶颈，全量采集（21 小时 / 730 GB）在当前瓶颈上无效。

## 6. 本版需求

### R1 · 修策略目标（对应 P1，最高优先级）

把 18 候选的**排序**学对，而不是把值回归对。硬要求：

1. 实现至少一种**成对或列表排序损失**（如 RankNet / listwise softmax），并**显式处理并列**：
   差值小于阈值（建议 0.5 px）的候选对不计损失或计零梯度；
2. 与原回归损失做**同预算对照**（同数据、同 epoch、同 seed），至少三组配置，记录成表；
3. 报告里必须并列 `top3` 命中率与 `0–15 px` 桶后悔值——因为「进前三」只要 0.892 px，是真正有用的判据；
4. 禁止改动作空间、候选顺序（`focus*9 + move`）、教师定义。

### R2 · 把 stage 2 与长尾拉进线内（对应 P2）

1. 全验证集位置误差要从 **12.81 px 降到 < 10 px**，且**不允许靠改口径**（口径见 §7）；
2. 允许的手段：多尺度 heatmap 头、heatmap 头容量、难帧加权（按当前误差分层）、对 location 目标的温度/σ 调参、
   深度通道（`--depth 3`）——**不允许**提高场地输入分辨率（已被证伪）、**不允许**新增数据；
3. 每次尝试仍按 `runs/v104-<描述>/` 独立落盘，不得覆盖 `v104-a01-72ep`（本版基线）。

### R3 · danger 分支（对应 P3）

把 per-frame corr 从 0.638 提到 **> 0.8**。允许改 danger 头结构（例如在 28×24 特征图上做 16×8 的可学习池化、
或加一层反卷积），不允许改 danger 的标签定义（16×8 计数、`log1p(x/8)`）。

### R4 · 真机复核（必须做，不许省）

用最终策略在 Lunatic 真机跑 **≥3 局**，报告 `frames_mean` 与 `hit_step_cap`。判据见 §7 A-04。
注意：v1.0.3 的 1,352 帧是**在 73% 坏数据上训练的模型**跑出来的，不能作为当前水平。

### R5 · 工程缺陷（顺手修掉，别扩大）

| 编号 | 缺陷 | 修法 |
| --- | --- | --- |
| D9 | 验证循环按整批迭代，7,241 帧只用 7,200 帧（丢尾部 41 帧） | `batches()` 增加 `drop_last`；验证路径取全量 |
| D10 | `VisionDataset` 的 npz 缓存预算用 `per_frame=1200` 估算，实际 253 KB/帧，导致把 20 GB 全塞进内存 | 按真实分片大小计算，或改成 LRU + 上限参数 |
| D11 | `pilot-ud0063` 没有解码缓存，跨回放评估每次现解码 | 建缓存（约 16 GB） |

### R6 · 文档

设计 / 开发文档 / 验收文档 / 验收报告 / 总结报告 齐备；过程日志增量写入 `Document/Dialogs/`。

## 7. 验收判据（v1.0.4）

| 编号 | 判据 | 取数位置 |
| --- | --- | --- |
| A-01 | 全验证集 `val_player_pos_px < 10.0` 且 `val_danger_corr_perframe_median > 0.8` | `stages.state.best`（**不读 final**） |
| A-02 | 0–15 px 桶后悔值 `< 1.5 px`，并并列报告 top3 命中率 | `stages.policy.best.by_danger` |
| A-03 | 跨回放不退化：ud0063 均值 `≤ 1.25 ×` 同回放均值 | `tools/rl/compare_state_models.py` |
| A-04 | 真机 ≥3 局，**`frames_mean > 4000`** 且 `hit_step_cap == 0` | `eval-report.json` + `compare_evals.py` |
| A-05 | `pytest touhou_rl/tests -q` 0 failed 且 ≥ 178 条 | 命令输出 |
| A-06 | R5 三个缺陷各有单测或证据 | 代码 + 报告 |

**A-04 的口径（用户 2026-10-19 裁决，比初稿更严）**：

- 通过线是 **4,000 帧**，不是随机基线 2,419.7。随机基线只作为「不能比瞎按差」的下限参照写进报告；
- 参照系：特权教师同难度 6,502 帧；v1.0.3 的 1,352 帧来自坏数据模型，仅作历史对照；
- **风险（已被用户接受）**：本版重心在 R1（策略排序）能否把 0–15 桶后悔值拉进 1.5 px。
  即便 A-02 达标，真机也未必立刻跑到 4,000 帧——后悔值达标与真机存活之间不是线性关系。
  若出现「A-02 pass 但 A-04 fail」，验收报告必须给出逐局数字与 `hit_step_cap`，
  并明确说明这是策略强度不足还是评估口径问题，不得用训练指标替代；
- 3 局均值的统计噪声约 ±7%（随机基线单局 2,118–2,695），4,000 显著高于噪声带，具备判别力。

**口径不可改**（改动需用户裁决）：
- 位置误差 = `(|Δx|·384 + |Δy|·448)/2` 的均值，全验证集（7,241 帧，且必须真正跑满，见 D9）；
- danger per-frame corr = 逐帧 128 格 Pearson 的中位数；
- 后悔值用教师 px 单位，桶边界 `(0,15)(15,30)(30,60)(60,120)(120,∞)`；
- 训练集 = `pilot-ud0059-v2` 的 manifest 训练划分（65,172 帧），验证集 = 其 7,241 帧固定划分
  （`val_index_sha256 = e5d4ebbe…`）。**`pilot-ud0063` 只作跨回放检验，不参与训练**（否则 A-03 失效）。
