## 0. 五分钟读法

1. 终极目标是**纯视觉**：框选一块游戏画面，模型只看这块像素就会玩东方，最好能迁移到其它东方作品。
   读内存只允许出现在**训练期**当特权教师，部署端一行内存都不许读。
2. 已经做到：能自动启动游戏、走菜单、放回放、采数据、读状态、注入按键、训练、评估、自主开打、截图取证。
3. 已经有：2 份干净回放数据（141,749 帧）、一个 55 万参数的视觉学生、178 条单测、完整的四阶段文档体系。
4. 真机最好成绩仍是**特权教师**（不读像素，用内存里的弹幕坐标）：6,502 帧；随机策略 2,419.7 帧。
   所有**纯视觉**模型都还没超过随机——最新一次是 1,352 帧（且那还是在一个 73% 数据损坏的旧数据集上训的）。
5. v1.0.3 查清了「为什么视觉模型那么差」：数据集里 73% 的帧画面冻结、标签照走。修好后位置误差从
   **68.07 px 降到 12.81 px**（70.3% 的帧已经 ≤10 px）。
6. 现在唯一没被改善的是**策略**：0–15 px 桶后悔值 3.97 px，只比「18 个动作里瞎猜」的 4.90 px 好 19%。
   根因是**标签近乎并列**（24.9% 的帧最优与次优完全相等），用回归去拟合它会让输出塌成常数、argmax 等于随机。
   v1.0.4 就是来修这个的。

## 2. 系统全貌

### 2.1 三条与游戏交互的通道（全部只在 Windows 本机、TH08 1.00d 日文版上验证过）

```
                    ┌──────────────────── 游戏：TH08（窗口 640×480；场地 32,16,384,448）
                    │
   ① 只读内存 ──────┤ touhou_rl/memory.py + state.py（ReadProcessMemory）
      → 特权观测    │   self_feat[24] / bullets[64,6] / danger[16,8]
                    │
   ② 键注入 ────────┤ touhou_rl/winapi.py（SendInput 扫描码）
      ← 动作        │   9 方向 × 2 射击 × 2 低速 × 2 放雷 = 18 个候选
                    │
   ③ 截屏 ──────────┤ touhou_rl/winapi.py GdiCapture（GetDC + BitBlt）
      → 视觉张量    │   三块分区：playfield 448×384 / hud_score 34×216 / hud_status 126×216
                    └────────────────────
```

### 2.2 两条学习路径

**训练期（用特权教师）**

```
内存真值 → AvoidPilot（脚本教师，beam search 规划 18 个候选的价值，单位 px 净空）
                ↓ 给每一帧打 18 个价值标签
视觉学生 VisionScorerV2 → 两阶段训练
   stage=state：像素 → 特权观测（自机位置 heatmap、danger 16×8、其余资源）
   stage=policy：像素 → 18 个候选的价值 → argmax 作为动作
```

**部署期（只看像素）**

```
env.render() → 按三分区裁剪 + resize → FrameStack → regions_to_batch → 模型 → argmax → 键注入
```

关键约束：`vision.regions_to_batch` 是**唯一**的预处理函数，训练与推理必须共用（v1.0.2 曾因两份实现漂移踩坑）。

### 3.1 为什么会有 v1.0.3 这一版（关键转折）

v1.0.2 结束时有一条被当成前提的结论：**「数据从 4,524 帧扩到 72,472 帧（16 倍），位置误差反而 48 → 71 px，
所以瓶颈是架构不是数据量」**。v1.0.3 因此把全部精力放在改架构上。

v1.0.3 验收时发现这条前提是**假的**：72k 数据集里有 **73.0% 的帧画面是同一张冻结图**（52,888 帧），
而标签仍在前进。根因是采集时系统锁屏（显示器 5 分钟关闭、15 分钟睡眠），`GetDC + BitBlt` 在窗口不刷新时
**仍返回成功**，于是 28 分钟内反复采到同一帧。

- 冻结的分片：从 `ud0059-00153` 到 `00565`；冻结图与最后一帧干净帧 SHA-256 **完全相同**；
- 后果：模型在 stage 4/5/7 上对上千个不同输入输出**逐位相同**的坐标（`corr = nan`）；
- 因此「16 倍数据反而更差」不是架构问题，而是**干净数据 vs 损坏数据**的对比。

修复动作：电源计划（关屏/睡眠全部设为「永不」）+ 采集器三重护栏（`SetThreadExecutionState`、
连续 5 帧同图即中止、窗口可见性检查）+ 采集报告新增 `frozen_frames` 等字段。重采后 `frozen_frames = 0`
（最长连续相同 2 帧，重复率 0.32%，全是孤立的一对）。

## 6. 六条关键教训（每条都有实测支撑）

1. **「数据变多反而变差」几乎总是数据有问题，不是模型有问题。**
   v1.0.2 的 16 倍扩容结论是假象：新数据集 73% 的帧画面冻结。同一架构只换回干净数据，误差就从 68 掉到 20 px。
   → 教训：任何「加数据带来负收益」的结论，先验证数据完整性。

2. **采集必须自检「画面在动」。**
   `GetDC + BitBlt` 在窗口不刷新时仍返回成功，静默地采 28 分钟同一帧。
   → 现在的护栏：连续 5 帧同图即中止、报告 `frozen_frames`、窗口最小化/被遮挡即中止、采集期禁止熄屏。

3. **末端池化会直接抹平空间精度。**
   v1 把场地特征池化到 2×2，等于只保留「自机在哪个象限」，位置误差必然停在 50–70 px。
   v2 改成 stride 8 特征图上出 28×24 heatmap + 加权期望，同数据下误差减半。

4. **用交叉熵训分布、用均值读指标，会系统性地把坐标往先验中心拉。**
   在干净数据上实测：同模型 argmax 解码 29.8 px，加权期望 38.8 px。加显式坐标损失后 8 轮从 42.35 → 37.89 px。

5. **策略标签的并列会毁掉 argmax 监督。**
   教师对 18 个候选的价值 24.9% 完全并列、61.6% 在 1 px 内。用回归拟合这种标签，最优解就是把输出压成常数，
   argmax 于是在并列里随机取——这就是「模型只比瞎猜好 19%」的机制。

6. **静态指标不等于能玩。**
   位置误差 12.81 px 的模型，真机表现仍是未知数；而 v1.0.3 那个 68 px 的模型只跑 1,352 帧。
   → 教训：每版必须做真机复核，且必须用「比随机强」作为最低门槛。

## 7. 当前卡点与 v1.0.4 要做什么

### 7.1 三条瓶颈（按优先级）

| 编号 | 瓶颈 | 证据 | v1.0.4 对策 |
| --- | --- | --- | --- |
| **P1** | 策略目标与标签不匹配 | 后悔值 3.97 vs 随机 4.90；进 top-3 只要 0.89 | R1：成对/列表排序损失，显式忽略并列（阈值 0.5 px） |
| **P2** | 位置残差集中在 stage 2 与长尾 | 五关已 4.7–10.6 px，stage 2 停在 15.2；12.6% 的帧贡献 41.7% 的误差 | R2：多尺度 heatmap、难帧加权、head 容量 |
| **P3** | danger 分支落后 | per-frame corr 0.638（目标 0.8） | R3：danger 头改「可学习池化」 |

### 7.2 已被实验否掉的方向（不要再走）

| 方向 | 实验 | 结果 |
| --- | --- | --- |
| 继续采数据 | 采第 2 份回放，用 ud0059 模型评估它 | 均值 9.43 → 11.02 px（+17%），中位数只差 5%，≤10 px 占比不变 → **数据多样性不是瓶颈** |
| 提高场地分辨率 | 224×192 → 336×288，24 轮对照 | 21.95 px（更差），收敛更慢 |
| 自机被弹幕遮挡 | 误差与弹幕密度/近处弹数/最近弹距离/亮度求相关 | 全部无关（−0.12 ~ +0.06） |
| 模型容量不够 | 100 帧过拟合测试 | **8.06 px** —— 容量足够 |

### 7.3 v1.0.4 的验收判据

| 编号 | 判据 |
| --- | --- |
| A-01 | 全验证集位置误差 < 10 px **且** danger per-frame corr 中位数 > 0.8 |
| A-02 | 0–15 px 桶后悔值 < 1.5 px（并列报告 top3 命中率） |
| A-03 | 跨回放不退化：ud0063 均值 ≤ 1.25 × 同回放均值 |
| A-04 | 真机 ≥3 局，`frames_mean > 4000` 且 `hit_step_cap = 0` |
| A-05 | 单测 0 failed 且 ≥178 条 |
| A-06 | 三个工程缺陷（D9/D10/D11）各有证据 |

## 9. 运行手册（复制即可用）

```powershell
$py = "C:\Users\a5935\AppData\Local\Programs\Python\Python312\python.exe"
cd D:\WorkShop\Touhou_RL
$env:PYTHONPATH = "D:\WorkShop\Touhou_RL"

# 单测（178 条）
& $py -m pytest touhou_rl/tests -q

# 采集一份回放（39 分钟；必须保证不锁屏，采集器会自检冻结并在报告里写 frozen_frames）
& $py -m touhou_rl.pipeline collect --modality vision --replay th08_replay/Th8_ud0059.rpy `
    --out third_party/th08/build/rl/datasets/<新目录> --every 2 --max-seconds 3000 --difficulty lunatic

# 处理（校验 + 教师标签 + manifest）
& $py -m touhou_rl.pipeline process --raw third_party/th08/build/rl/datasets/<目录>

# 建解码缓存（训练提速 2.4 倍；模型分辨率变了要重跑）
& $py -c "from pathlib import Path; from touhou_rl.vision_data import build_decode_cache; print(build_decode_cache(Path(r'third_party/th08/build/rl/datasets/pilot-ud0059-v2'), {'playfield': (224,192), 'hud_score': (34,216), 'hud_status': (126,216)}))"

# 训练视觉学生（state 72 轮 + policy 12 轮，约 40 s/epoch）
& $py -m touhou_rl.vision_train --dataset third_party/th08/build/rl/datasets/pilot-ud0059-v2 `
    --out third_party/th08/build/rl/runs/<新目录> --arch v2 --stage both `
    --epochs-state 72 --epochs-policy 12 --batch-size 96 --depth 1 --device cuda `
    --heatmap-sigma 1.0 --w-coord 1.0

# 分关卡 / 跨回放对照
& $py tools/rl/compare_state_models.py --dataset third_party/th08/build/rl/datasets/pilot-ud0059-v2 `
    --checkpoint "base=third_party/th08/build/rl/runs/v104-a01-72ep/state.pt" --per-stage 128

# 真机评估（3 局；不传 --vision-depth，默认跟随 checkpoint）
# 产物 eval-report.json 里只有逐局 frames_reported；frames_mean / hit_step_cap 由下面的汇总脚本算
& $py -m touhou_rl.evaluate --vision-checkpoint <policy.pt> --out third_party/th08/build/rl/eval/<目录> `
    --episodes 3 --max-steps 4000 --frameskip 2 --difficulty lunatic --device cuda
& $py tools/rl/compare_evals.py --run new=third_party/th08/build/rl/eval/<目录>/eval-report.json `
    --run random=third_party/th08/build/rl/eval/random/eval-report.json
```

**注意**：真机评估与采集都要求游戏窗口独占前台（失焦会掉到 14 fps），且同一时刻只能有一个游戏实例。

## 10. 术语表

| 术语 | 含义 |
| --- | --- |
| **特权观测 / privileged** | 从内存读出来的结构化游戏状态（自机坐标、弹幕、资源），部署端不可用 |
| **教师 / teacher** | `AvoidPilot`，用特权观测做 beam search 规划，输出 18 个候选动作的价值（px 净空） |
| **视觉学生** | `VisionScorerV2`，吃三块分区的像素，学教师的输出 |
| **S1 / state 阶段** | 像素 → 特权观测（自机位置、danger 图、资源）的训练阶段 |
| **S2 / policy 阶段** | 像素 → 18 候选价值的训练阶段 |
| **位置误差 px** | `(|Δx|·384 + |Δy|·448)/2` 的均值，全验证集；与 v1 历史数字严格可比 |
| **后悔值 regret** | 教师认为最好的候选价值 − 学生实际选的候选价值，单位 px 净空 |
| **danger 图** | 场地 16×8 粗格子里每格的弹数，训练目标是 `log1p(count/8)` |
| **帧堆叠 depth** | 把最近 N 帧作为额外通道输入，用于提供运动信息（当前 depth=1） |
| **冻结帧 frozen** | 采集时画面停止更新但仍被记录；v1.0.3 因此损失 73% 数据 |

## 11. 如果我是新接手的人，第一小时该做什么

1. 读本文件 §0、§3、§7（15 分钟）；
2. 跑 `pytest touhou_rl/tests -q`，确认 178 条绿（1 分钟）；
3. 用 §9 的命令把 `v104-a01-72ep` 的指标打印一遍，确认 12.81 px（1 分钟）；
4. 跑一次 `compare_state_models.py` 看分关卡数字，理解「只剩 stage 2 没过线」（3 分钟）；
5. 读 `v1.0.3/根因分析-数据冻结与解码错配.md` §8.2，理解策略为什么卡住（15 分钟）；
6. 然后按 `v1.0.4/需求文档.md` 的 R1 开始动手——**不要先加数据、不要先调分辨率**，两者都已被实验否掉。
