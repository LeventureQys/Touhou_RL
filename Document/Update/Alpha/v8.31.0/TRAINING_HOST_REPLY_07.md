## 0 结论摘要（四条）

1. **T04 规模的行为克隆第一次带来真实闭环收益。** 同一 obs-v3 模型、同一评测尺：
   **顺序采样 2,000 步（9.7 epoch）→ 自然开局生存 1,504 / 1,808 / 2,224 帧（均值 1,845.3）**，
   相对 `pilot_final` 731（**+1,114 帧，2.52×**）、恒动作 746（+1,099）、D1-2,000 步 705（+1,140）。
   类别平衡臂 1,158 / 980 / 824（均值 987.3，+256）。
   **但两臂 Tier B（帧 2,936 抵达首 boss）仍 0/3**——这是"生存变长"，还不是"任务完成"。
2. **上一轮的负结果被解释清楚：不是"BC 无用"，是 D1 规模的预算换算错了。** 同样 2,000 步 = 64,000 样本：
   T04 的 6,592 行 ≈ **9.7 epoch**（学到真策略），D1 的 332,377 条 ≈ **0.19 epoch**（仍停在 idle 相）。
   → 语料规模必须进预算公式，"2,000 步"不是一个可移植的单位。
3. **策略一"活"起来，seed 方差就回来了。** 坍缩臂（恒 idle）三 seed 逐位同结果（705/705/705）；
   T04 顺序臂三 seed 是 **1,504 / 1,808 / 2,224**，类别平衡臂 **824 / 980 / 1,158**。
   同一 checkpoint 在 seed 间差异这么大，说明**像素级种子噪声会改变策略决策**——这也是 §独立根规格里"学生侧最早分叉帧 53"的机制。
4. **`S1N-MB2` 三条前置验证全部通过（3/3、3/3、3/3），但第 2 条的口径要改。**
   三根入口的**玩家状态完全相同**（px,py = 42.696,352.402、lives 2、bombs 3、power 11、入口无 boss），
   差异只在**敌机布局与 RNG**（slot 1 的 y = 47.737 / 65.427 / 53.982；RNG = 24080 / 48100 / 3889）以及 `entry_hash`。
   → 冻结卡的独立性表述必须写成"入口 hash 与磁带相等 + 敌机/RNG 互异"，不能写成"玩家状态互不相同"。

## 4 R4-A：T04 规模 BC 的第一个正向闭环收益

### 4.1 对照表（同一引擎、同一 obs-v3 尺、同一 4,500 帧上限、`--stop-on-death`）

| 策略 | 训练规模 | 三 seed 帧数 | 均值 | 相对 pilot_final 731 |
| --- | --- | --- | ---: | ---: |
| **T04 sequential**（E3 口径） | 6,592 行 × 9.7 epoch | 1,504 / 1,808 / 2,224 | **1,845.3** | **+1,114.3（2.52×）** |
| T04 balanced（E4 口径） | 6,592 行 × 9.7 epoch | 1,158 / 980 / 824 | 987.3 | +256.3（1.35×） |
| `pilot_final`（历史） | 200 步 | 731 / 731 / 731 | 731.0 | — |
| 恒动作 `cand 12`（历史） | — | 746 / 746 / 746 | 746.0 | +15.0 |
| D1 2,000 步（上一轮） | 332,377 条 × 0.19 epoch | 705 / 705 / 705 | 705.0 | −26.0 |
| D1 初始化+1 步（上一轮） | — | 705 / 705 / 705 | 705.0 | −26.0 |

### 4.2 读法（不夸大）

- **是真实收益**：同一 checkpoint、同一引擎、同一尺；三 seed 全部高于 731，最高 2,224（3.04×）。
- **不是任务完成**：Tier B 需要帧 ≥ 2,936，最好一根 2,224 仍差 712 帧；Tier A（击破首中 boss）两臂 0/3。
- **动作不再坍缩**：dominant 0.229（sequential）/ 0.308（balanced），distinct 10/18；对照坍缩臂是 1.0/1。
- **分数差异很大但不是判据**：balanced seed1000 的 139,888 分远高于 sequential 的 58,348，却死得更早——分数不是本任务的成功口径。
- **离线与闭环的方向一致**：离线 donor top-1 顺序 0.5933 > 平衡 0.5027；闭环均值 1,845 > 987。**这是本项目第一次出现"离线指标与闭环表现同向"。**

## 5 R4-B：S1N-MB2 三条前置验证完成（附口径更正）

| # | 验证 | 结果 |
| ---: | --- | --- |
| 1 | 前缀回放 3 根，逐槽 `hash_post` 一致 | **3/3 通过**（每根 1,308/1,308 槽，`mismatch_slot=null`） |
| 2 | 入口状态登记与互异 | **3/3 通过（hash/敌机口径）**：三 `entry_hash` 互异且逐根等于磁带 slot 1307 `hash_post`；**但玩家六字段完全相同** |
| 3 | 退化臂从入口起不完成 | **3/3 通过**（入口后 630 / 780 / 674 帧死亡，均 < cap 1,868） |

**口径更正（重要）**：三根入口的 `px,py = 42.696,352.402`、`lives=2`、`bombs=3`、`power=11`、入口无 boss，
**玩家状态一字不差**；独立性只来自敌机布局（slot 1 的 y = 47.737 / 65.427 / 53.982）与 RNG（24,080 / 48,100 / 3,889）。
原因也清楚：三条磁带在帧 2,632 之前动作完全相同，玩家自然在同一位置；分叉发生在 2,632 这一刻的敌机/RNG 状态。
→ 冻结卡必须写"入口 hash 与磁带相等 + 敌机/RNG 互异 + 玩家状态相同且如实登记"，不能写"玩家状态互不相同"。

## 6 偏差与异常

1. **`S1N-MB2` 草案第 2 条的措辞与实测矛盾**（§5），已登记待改；草案本身未冻结，不算失败。
2. **两臂 Tier B 都是 0/3**：本回执只主张"生存帧数变长"，不主张"接近过关"；最高的 2,224 距 2,936 仍差 712 帧。
3. **`pilot_final` / 恒动作 / D1 两臂都是引用**（`results.json` sha256 `e4787d00…` / `d3341e99…`），本轮未重跑，因此 6 次启动预算未被挤占。
4. **`tau=2.0` 只在身份里展示**，本轮硬标签训练未把温度用于损失（`train.tau_used_in_loss=false`）。
5. **两个 checkpoint 的离线 fit 根指标是样本内**（0.9606 / 0.7750），表中只用 donor（0.5933 / 0.5027）做与闭环的同向比较。
6. **verify2 的帧口径**：`takeover` 帧 1,454（780+674）计入门槛，`frames` 字段含不可裁剪的 2,632 前缀（总 6,718），两种口径都已登记。
