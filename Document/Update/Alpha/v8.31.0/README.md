## 首个短任务怎样成立

优先选自然开局可达的最早攻击阶段。任务卡以真实阶段完成、可核转场或明确的击破事件结算，并区分合法失败、超时和技术无效。现有数据若只能支持按时间结束的窗，先说明动作是否会改变完成类别或资源结果。任务卡需要同约束成功见证、至少一条可判别的合法失败或不同任务后果，以及一条独立可核验的入场路径。阶段与开发起点在观察候选新成绩前确定。

中局入口只使用已登记且满足帧和掩码契约的前缀。恢复时核对状态哈希、资源与实际执行历史，保留接管前真实帧。若必须重录前缀，先提出独立资产工单，写明来源、首个冲突、最少采集量和登记方式。整面教师重放只作为整面判分校准。 [v8.30 像素切片和边界](../v8.30.0/PIXEL_SLICE_PLAN.md)

## 学习试点的冻结草案

使用一个学习配方和一个训练 seed，首选可复用的 `obs-v3` 像素模型。优先用已登记、同节拍、合法且覆盖目标事件的训练轨迹做局部 BC。资料不足时回报缺少的事件、动作或来源，由下一单确定最小补采或受限在线学习方式。在线探索需要事先给出实际交互帧上限。像素 actor 只接收画面和自身动作历史。教师真值、审计事件或真值回报若参与训练，按训练期特权诊断记录。

首批设计目标为最多 2 个训练根、4 个未参与拟合或选参的开发根，每根至多 2 次配对重复。实际分配、每局受控帧上限、总交互帧、更新数、墙钟和磁盘在首单实测后冻结。每臂共用根、合法动作、资源、事件判分、射击节拍和评测预算。训练根及其派生窗按同一谱系计数。开发根缺少时，以实际分母回报并保留结论边界。

| 臂 | 冻结方式 | 研究问题 |
| --- | --- | --- |
| 学习前像素 | 冻结初始化权重和 actor 身份 | 训练前水平 |
| 学习后像素 | 使用事前指定的最终更新点和相同读出 | 同等评测条件下，学习是否改善任务结果 |
| 强开环 | 首选用训练后策略在独立训练供体上生成动作表，匹配节拍、持续长度和资源规则。用训练材料验证强度，在开发起点评测前冻结。已验证的强固定策略可另作参照 | 在有竞争力的参照下，闭环能否体现实时反馈的价值 |

以短阶段完成与资源后果为主，逐根报有效尝试、成功、合法失败、技术无效、实际受控帧、真实库存消耗和墙钟。早死导致的帧数差单独显示。若两个对照的逐根等权完成差均为正，且各有至少两个开发根出现正差，可提名扩大试点。开环质量未达到预先冻结的要求时，反馈价值保持待判。稳定性仍需多训练种子和新根复验。 [反馈对照设计](../v8.30.0/ROUTE_DECISION.md)

| 观察 | 下一项开发 |
| --- | --- |
| 同契约正对照失败或短阶段终态不可辨 | 优先核查驱动、入口和任务事件，保留已取得的像素接线证据 |
| 学习后优于学习前，开环仍持平 | 核查开环供体质量与真实任务的反馈区分力，再冻结对照或任务 |
| 接线正确且像素训练停滞 | 在同任务、同目标上用小型状态输入臂定位。若状态臂也失败，先查共有的目标、采样和更新。若状态臂有效，先用同批数据检查可见先兆，再单独改变视觉或历史表示 |
| 两个对照均有逐根信号 | 冻结候选，复训并扩大到新根。随后提前接管、保持连续资源和记忆，再测自然开局 |
