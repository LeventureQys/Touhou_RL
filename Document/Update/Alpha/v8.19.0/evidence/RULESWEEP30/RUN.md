### 6.4 机制：阈值动的是「第三颗雷的时机」

同一候选头内的对照（`within_sweep_contrasts.json`，离线复算已落盘的 960 行）：

| 对比 | 率 A | 率 B | Δ | 单侧 Fisher p（A>B） |
| --- | ---: | ---: | ---: | ---: |
| S1 vs S2 | 24.17 % | 18.33 % | +5.83 pp | 0.0733 |
| S3 vs S4 | 24.58 % | 19.17 % | +5.42 pp | 0.0925 |
| S1 vs S4 | 24.17 % | 19.17 % | +5.00 pp | 0.1114 |
| S1 vs S3 | 24.17 % | 24.58 % | −0.42 pp | 0.5842 |
| S2 vs S4 | 18.33 % | 19.17 % | −0.83 pp | 0.6371 |
| **晚臂组 S1+S3 vs 早臂组 S2+S4** | **117/480 = 24.38 %** | **90/480 = 18.75 %** | **+5.62 pp** | **0.0206** |

单对比较（240 vs 240）都在 p ≈ 0.07–0.11，把两个晚臂/两个早臂合并后才过 0.05
——这是 n = 240/臂 的检验力上限，不是方向不定。

也是正的 +5.62 pp（p = 0.0206）。**

## 8. 偏差、失败与保留意见

1. **对照 R0 的候选头与 S1–S4 不同（预注册设计自带，但必须写明）**：
   发布的 R5 `d900` 格用 `ckpt_sha256 = 4abee069…`，即 **v4.5.0 `S` 学生**；
   本轮 S1–S4 用 `bombdag.pt`（`9c6d5d4a/36a51090/885dde70`）。所以
   「臂 vs R5」的 Fisher 同时混了**候选头**与**阈值**两个因子，不是纯阈值因果。
   预注册 §1 明确要求「R0 不重跑」，因此照做；纯阈值的效应只能用 §6.4 的
   **同头对照**（+5.62 pp，p = 0.0206）来支持，而两者方向一致。
2. **S4 / seed0 第一次失败并整格重跑**：原进程在 w17 起父进程时报
   `HarnessError: harness closed the control pipe`（引擎启动即关闭控制管道，
   当时机器上有 168 个引擎进程、loadavg ≈ 50），跑到 40/80 条后 exit 4。
   处置：把该格已完成的 w11/w12 原始文件留档到
   `.tmp_v8k0_rulesweep30/attempt1/`，然后用新 tag `v8k0-eval-S4-d900-s0-r2`
   **整格重跑 4 个窗口**（不是从 w17 续跑：协议是「每进程一个
   `torch.Generator(seed*1000+7)`、按 11→12→17→18 顺序每决策消费一次」，
   从 w17 续跑会重置抽样流）。最终 `eval_S4_d900_w*_seed0.jsonl` 全部来自
   重跑（exit 0），`attempt1/` 只作审计。
3. **预检引擎数远超 6**：开工时机器上已有 **105 个**他轮引擎进程
   （`v8i0_nobomb` 的 18 路 d300/600/900 eval，属 v8.17/v8.18 轮次）。
   这些不是本轮的进程，**未做任何终止**（硬约束禁止 `pkill -f`），
   按「> 6 先等 5 分钟」等待后仍 > 6，故在保留它们的前提下以 **12 路**开工
   （预注册 §3 的并行度），loadavg 峰值 ≈ 55/20 核。这解释了每条约 4–6 s
