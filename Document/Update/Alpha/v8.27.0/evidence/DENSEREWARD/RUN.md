# v8.27.0 DENSEREWARD（缩减版）— 密集奖励能否救活 30 s 放雷学习

**结论：`S-not-reward`。** 把奖励从稀疏改成密集 **没有** 救活 900 决策（30 s）的放雷学习，
反而把活满率从 v8.24 的 **4.08%** 进一步压到 **D1 0.61%（11/1,800）/ D2 0.78%（14/1,800）**
（单侧 Fisher，H1 = 密集臂 < D0：D1 p = **1.11e-15**、D2 p = **8.62e-14**）。
P1（>24.17%）不成立，P2（>60.83%）不成立，P3 本轮**未测**（ERRATA 删掉 20 s 档）。
按 `ERRATA_SCOPE_REDUCTION.md` 的判定表 ⇒ **`S-not-reward`**：30 s 崩溃**不是奖励形状问题**。

### 2.1 两臂的奖励（唯一变量）

| 臂 | `R` | 与 D0 的关系 |
| --- | --- | --- |
| **D0**（v8.24，只引用不重跑） | `survived(900) + 0.5 × alive/1800` | 4.08% @30 s（147/3,600） |
| **D1** | `alive_frames / 1800` | 去掉终局项、存活项权重 ×2 |
| **D2** | `alive_frames / 1800 + 0.5 × survived(900)` | 存活项 1.0→0.5，存活项 0.5→0.0 |

> **关键事实（写进结论）**：`survived(900) ⇔ alive_frames == 1800`，所以
> **对任何未活满的回合，D1 与 D2 的 `R` 完全相同**（只差一个常数 0）。
> 两臂只在约 1–2% 的"活满"回合上有区别。这是本轮设计无法回避的性质。

## 8. 判定

| 条件 | 判定 |
| --- | --- |
| P1 成立（D1 或 D2 > 24.17% 且 p<0.05） | ⇒ `S-dense-works-partial` |
| **P1 不成立** | ⇒ **`S-not-reward`** ← **本轮** |

**`S-not-reward`。** 按 `ERRATA_SCOPE_REDUCTION.md`：**问题不在奖励形状**。
v8.24 的机制解释（§33.3：「稀疏奖励 ⇒ advantage ≈ 0 ⇒ 梯度变噪声」）**被否证**：
把奖励改成每一步都给信号（D1，梯度密度最高）后，30 s 不但没回到 10% 以上，
反而从 4.08% 掉到 **0.61%**（p = 1.11e-15），20 s 档本轮未测。
两臂一致表现为「第 0 决策放雷 + 三颗放完 + 熵单调上升 + alive 单调下降」，
即 **REINFORCE 在这个 2 动作头上学到的稳态就是"能放就放"**，与奖励是否密集无关。

### 8.1 不能声称什么

- **不能**声称「密集奖励优于稀疏」或「稀疏优于密集」的完整结论：只测 900 档、2 臂、n=150/格；
- **不能**推断 20 s 或 40 s（本轮**无** 20 s 档，**无** 1,200 档）；
- **不能**把 D1/D2 的 0.17 pp 差异归因于「终局项是否有/权重多少」（两臂 CP95 重叠，D3 未跑）；
- **不能**声称「学会了资源分配」——候选头冻结，只学放雷时机；
- 训练/评测同批 4 个 dev 窗，没有任何跨窗泛化结论。
