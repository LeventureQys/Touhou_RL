本地 89 份 evidence JSON 均可解析；这不等于 89 份实验全部有效。当前 v420 代码/配置/测试缺失，故历史 469 passed/2 skipped、资产 46/46 等数字仅为历史记录，本次不认领为重新通过。可复算检查与源文件 SHA 见 [检查记录](evidence/review_checks.json)，复核入口见 [执行计划](EXECUTION_PLAN.md)。

## 3 影响路线的主要问题

### P1-01 没有完成最关键的学习定位，却宣布探索穷尽

[G420_2.md](../v4.2.0/evidence/T04/G420_2.md) 明确列出 A2 未建、10 个真实可解微段未做、三训练 seed 未做。后续 A1 已补做，不能再引用旧文档说 A1 完全未做；但当前证据中没有 A2/微段/三 seed 完成记录。[ROUTE_CONCLUSION §10](../v4.2.0/ROUTE_CONCLUSION.md) 却用了“能力探索已穷尽”。

影响：不知道系统是看不清、记不住、学错目标，还是根本到不了产生成功奖励的状态，就进入成本较高的扩标。v4.3.0 将真实微段、状态诊断和记忆消融放在大采集前。

### P1-02 短程安全集合不能承担战术与长期价值

A1 标签施加候选动作两帧，此后由冻结 A0 续行至 120 帧或终止。它估计的是**指定续行下的两秒结果**。优化 `-log Σπ(S)` 或集合内均匀 CE，只约束短程集合质量；不会自动产生“提前清怪避免发弹”“先引弹再横移”“绕过整个扇形覆盖区”“牺牲一点眼前余量换持续输出”的目标。

反过来，弱学生续行全部失败也不能证明状态无解。标签应有不同续行、实际资源和较长战术结果；成功条件从“末端不死”扩到波次/阶段真正完成。详见 [战术规格](TACTICAL_LEARNING.md)。

这里不是说仓库从未研究战术：旧 `escape`、ENEMY/POWER 工作存在，且有真机负结果。[旧策略总索引](../v3.6.0/总索引.md) 说明没有策略接入控制环。复用它们的表示/检查经验合理，复用合成 PASS 充当当前学生战术能力不合理。

### P1-03 用结果分支表代替因果识别

[SETLOSS_FORM.md](../v4.2.0/evidence/T08/SETLOSS_FORM.md) 的单因素变化确实使崩塌指纹改变：首死均值 669→1139.9，留出 set-hit 却 0.55→0.45，标准 S1N 仍 0/20。这支持该损失形式在此配方上影响行为，不足以认定“泛化就是数据问题”。

[扩容规格](../v4.2.0/experiments/T08-corpus-expansion-spec.md) 写“命中不上升→扩多少都没用”“两点斜率外推所需规模”。小规模、单训练 seed、固定更新数且样本组成会变化，不能排除优化程度、分布、表示、标签与规模的交互。换大数据而固定 5000 更新，也改变每样本曝光量。

新做法：固定留出祖先与任务，构造嵌套训练子集；同更新预算作为主比较，等样本曝光作为诊断；至少三训练 seed。只否定测试过的配方和预算，不宣称唯一原因。禁止两点直线外推作为下一轮必然成功规模。

### P1-04 对“看不见威力”的结论过强，R1 定义漂移

[旧观测源码](../../../../touhou_rl/v400/student/obs_spec.py) 的确没有裁进报告指出的威力 HUD 条，短探针的高 R² 也有时间混淆。但是 [观测修正规格](../v4.2.0/experiments/T08-power-observation-spec.md) 从此推出“威力奖励原理上不可学”，不成立：POMDP 可以通过动作后果、射击形态、道具与历史估计隐藏量；缺失直接 HUD 会增加困难，却不是不可能性证明。

同一规格将 R1 说成“从零只用像素”，而原计划允许同一预训练初始化后的严格像素适应；又将特权标量诊断称为不可逆路线收缩。正确边界是逐臂区分：特权输入臂不算部署，仍可作诊断；纯像素后续训练可以从特权训练得到的像素 checkpoint 开始。

修 HUD 值得做，但要同时补全威胁源、输出机会、宏观区域与历史。只新增威力条不能解决全部战术缺口。

### P1-05 RL 的负结果范围小于总结里的否定范围

证据存在单 seed 50k、200k 等短跑以及 PPO 起点/奖励/KL 的诊断。原计划要求的三 seed×1M 正式诊断没有完成证据；1M 派发被停止。[进展记录](../v4.2.0/PROGRESS.md)、[200k 撤回与追加](../v4.2.0/evidence/T06/BUDGET_200K_RETRACTION.md)

“50k→200k 没提升”可以停止当时的配方，不能证明训练量对新课程、新观测、有效成功奖励均无用。更不能把全是早死的轨迹上的回报相关性当成长程通关目标已经正确。

新路线先让真实片段学习成立、产生足量成功/恢复经验，再对预注册预算做三 seed 比较。不会在旧失败配方上无界加步数，也不把“预算变量永远关闭”当科学结论。

### P1-06 控制通路和目标没有完整表达标准任务

旧评测的 SHOOT 问题说明仅测试策略 logits/数据 HASH 不足以覆盖完整交互通路。A1 学生的 bomb 固定为零，动作目标没有直接覆盖预防性清场；最终任务却允许标准资源、需要菜单切换与死亡恢复。局部不死不能代替游戏完整流程。

v4.3.0 统一训练与部署按键状态机，优先补成功回放正对照、像素转场和自然恢复；不能在评测器里额外引入特权救援。

### P1-07 实现和审计脚本未进入当前代码交付

当前路径检查：`touhou_rl/v420`、`configs/v420`、`tools/rl/v420.py`、`tools/rl/v420_eval_shoot.py` 均不存在，`tests/test_v420*.py` 数量为零。报告还依赖 `.tmp_v420_*` 的聚合和裁决脚本。Git 资产保护不应把必要源码、配置、评测器和裁判规则一并留在临时目录。

W00 将代码/配置/测试恢复到可同步范围，数据和二进制仍不上传。当前检出缺资产是预期限制，源码缺失则是独立的交付问题。没有访问原执行端前不声称文件丢失或报告造假。

### P2-08 版本状态漂移会驱动错误的下一步

README 仍写“尚未执行”；state 的 `in_flight` 保存 68/750；最后 journal 记录 394/750；ROUTE_CONCLUSION 某交接段写 307/750。它们是不同历史快照，不是当前活进程状态。日志还出现“六个门”却列出七个门的计数。

旧 G420-4 的 `failed_valid` 与“正式 100 局尚未开展”也需分开读：开发失败足以拒绝提名候选，不等于正式确认已经执行失败。新账本分 `implementation_status / protocol_validity / research_result / capability_gate`，由不可变证据生成当前视图；本次不修改旧账本。

## 4 需要收窄而非删除的结论

| 旧表述 | 本次可支持的表述 |
| --- | --- |
| 当前观测下能力探索已穷尽 | 已测若干指定配方未达能力；关键诊断仍未完成 |
| 集合损失奖励被动，因此必然失败 | set-mass 不区分集合内动作；本次模型出现坏行为，唯一机制未被隔离 |
| 泛化是数据问题，扩不动说明表征有问题 | 两种配方留出较差，数据/表示/目标/优化的贡献仍需区分 |
| 不含威力 HUD，所以威力奖励原理上不可学 | 缺少直接读数；历史估计可行性、行为价值和信用分配未解决 |
| 13,195 帧是通关所需长度 | 一条已验证成功参照的长度 |
| 单 seed/n=20 不能有区间 | 可以对该模型评测的不确定性给区间；不能据此估计跨训练 seed 稳定性 |
| 3 轮 DAgger 失败说明 DAgger 路线关闭 | 当前输入/教师/课程/预算的 3 轮配方未达目标 |
| A1 有 178 proper 状态 | 原 JSON 按 `0<|S|<18` 有 184；后续训练取 178、排除了 6 个 singleton，应写明过滤口径 |

预注册能限制事后挑指标，不能把无效的因果推断变正确。发现基线错误或协议错误时应保留原记录、明确 invalid/superseded，并重新冻结开发协议，不以“阈值已冻结”为由继续使用错误数字作新的科学依据。

## 5 是否符合最终目标路线要求

| 维度 | 判断 |
| --- | --- |
| 最终目标与特权边界 | 原计划符合；个别后续规格定义漂移需纠正 |
| 数据/时序/分支真实性 | 有实质进展，范围有限，仍需原环境复现 |
| 会玩所需的战术与长程学习 | 不足，尚无通过真实微段到整面连接的证据 |
| 因果归因与停止规则 | 部分结论过度，不能据此宣布方法穷尽 |
| 真实部署、像素反馈、完整一周目 | 没有完成证据，不能长期仅列为远期事项 |
| 可复现交付 | 当前检出缺必要实现和运行资产，需分别恢复/核验 |

因此 v4.3.0 保留 v4.2.0 的有效工程成果，重排主线为“可信通路 → 威胁预防与真实片段学习 → 自然课程连接 → 第一面/全流程 → 严格像素改进与迁移”。它是一条待实施和检验的工程路线，不是把版本号或门名改掉后追认成功。
