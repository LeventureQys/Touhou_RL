## 3 与 `contracts.o2_parameters()` 的一致性：**复用，不是复制**

1. `O2_SHAPES` 由 `contracts.o2_parameters()` 的 `*_chw` / `*_shape` / `memory_shape` 现场构造
   （`_plan_shapes()`），并在 **import 时**双向断言：
   `tuple(O2_SHAPES) == contracts.ACTOR_OBSERVATION_KEYS` 且
   `O2_SHAPES == {name: spec.shape for name, spec in contracts.FIELD_SPECS.items()}`，不一致直接 `RuntimeError`。
2. 裁剪矩形、灰度权重/移位、降采样因子与累加器、存储 dtype、归一化点、`KEY_ORDER`、
   通道顺序、`O2_IMAGE_BYTES_PER_DECISION` 全部以模块级别名指向 `contracts.*`（如
   `PLAY_CROP_XYWH = contracts.O2_PLAY_CROP_XYWH`），本模块**没有**第二套数字。
3. `encoder_parameters()` 以 `contracts.o2_parameters()` 为基底 `update`，只**追加**编码步骤与策略键；
   `test_encoder_parameters_reuse_the_contract_block` 逐键断言契约块的值未被改写、且新块是严格超集。
4. `o2_digest()` 是 `contracts.o2_digest` 的**透传**；`encoder_digest()` 也走同一条哈希路径
   （`o2_digest(encoder_parameters(...))`），因此只有一套 sha256 口径。
5. 隐私判据同样复用：`assert_actor_inputs_clean` 先调 `contracts.assert_not_privileged`
   （即 `FORBIDDEN_ACTOR_FIELDS`），再用本模块**追加**的 27 个名字（`stage_id`、`player_center`、
   `lives`、`power`、`boss_hp`、`frame_index`、`true_state` …）扫描；import 时断言
   “追加集合与契约集合无交集、且契约集合是并集子集”，所以是**扩展**不是替换。
   合计拒绝 43 个名字（16 契约 + 27 追加）。

## 4 必须进入 digest 的“顺序”

`ENCODER_STEPS`（9 条）以符号名描述顺序（`crop(play_crop_xywh)` → `gray_bt601_int(gray_rule)` →
`downsample_2x2_int(downsample_rule)` …），数字仍只存在于契约块，`encoder_digest` 覆盖二者；
`test_digest_is_stable_and_sensitive_to_one_changed_parameter` 直接断言**把 steps 逆序后 digest 必变**，
证明顺序是身份的一部分，不只是参数值。

## 5 身份口径（`SHA_LINE_ENDING_FINDING.md` §6）

* 文本产物：`text/lf-normalized`。`o2_identity()` 带 `o2_digest_scope` / `encoder_digest_scope` /
  `pixel_digest_scope`，`sha256_text()` 带 `digest_scope`。
* 像素/二进制：`binary/raw`。`sha256_pixels()` 对 C-order 原始字节哈希，绝不做换行规范化；
  测试用一个含 `\r\n` 字节的数组证明 raw 摘要 ≠ LF 规范化摘要。
* `check_identity_record()` 拒绝“只有 sha256 没有口径”的记录（`X_digest` 必须配
  `X_digest_scope`，裸 `sha256` 必须配 `digest_scope`，且 scope 必须在白名单内）。
* 当前身份值：`o2_digest = cb1616e4cbfa928e691c2fb8497a84c813bded528064cf2b0aa1e30fa86b85b5`
  （与 `contracts.o2_digest()` 相同）、
  `encoder_digest = 4cc3c6cd24a15221eebc5f70df766d822f05d1e8c181a64bf90d05d94a767139`
  （= `sha256_text(encoder_parameters())`，两条路径一致）。

## 8 已知边界与限制（不掩盖）

1. **`sha256_text` 的窄边界**（复核方独立发现，已登记，不在本片修复范围）：
   `sha256_text` 对**序列化后的 JSON 字节**做 `CRLF→LF`。JSON 会把字符串里的换行转义成
   反斜杠序列（`\r`/`\n` 两个字符），字节级替换匹配不到；因此“dict 内嵌多行字符串、只有换行不同”时
   摘要会不同。当前 `o2_parameters()` / `encoder_parameters()` 全为数字/形状/短标识串，不受影响；
   不得声称 `sha256_text` 对任意载荷换行无关。文件级身份应使用 `binary/raw`（原始字节），
   或先做 `CRLF→LF` 再哈希（本仓 W00 规则）。
2. **重复帧严格拒绝**：四帧栈中出现任意两帧字节相同即拒绝。静态画面（暂停/菜单）因此无法编码——
   这是按 §4.2“不得用重复一帧伪造四帧栈”的**故意选择**，代价留给会话层（W02 后续切片）处理，
   不是本片的静默行为。
3. **alpha 策略**：只接受常量 0（未使用的 DIB alpha）、常量 255（不透明）、以及 0/255 二值；
   中间值 alpha 一律拒绝（缓冲被混合/预乘时丢 alpha 不是无损）。若真实 Windows 采集给出中间值 alpha，
   W06 必须先修正采集，而不是放宽此规则。
4. **`elapsed_capture_s` 拒绝整数**：整数在这个位置只能是帧/步计数，明确按“引擎帧号不是 actor 输入”拒绝。
   若上层只有整数计时，必须自行换算成秒（float）。
5. **只覆盖 O2**：O0/O1/O-G 未实现；O-G 需要独立 digest/模型身份（§9 末段）。
6. **合成测试不等于能力**：本文件的 47 个断言全部基于构造的 numpy 数组，证明的是编码算术与拒绝路径，
   不证明真实采集、真实帧连续性、游戏反应或任何 G410/G430 门。
7. **未实测性能**：单次 `encode_o2` 的成本只做了量级观察（测试内约 ms 级），未做正式吞吐测量；
   `474112` B/决策的存储估算仍以 `contracts.O2_IMAGE_BYTES_PER_DECISION` 为准（本片未落盘任何样本）。
