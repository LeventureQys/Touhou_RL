## 2. Instrument changes (all inside git-ignored `.tmp_v430_o2/`, each minimal)

### 2.1 `capture_o2.py` — new optional `--tape-sha256` (default = old behaviour)

Why: the instrument pinned the tape to the ruler's single seed-12 constant
(`_V420.CLEAR_SHARD_SHA256`), so the seed10/seed11 tapes were refused **before
any engine start** (exit 1 after 13 s). The refusal is correct — replaying an
unaudited shard must never silently happen — but it had no way to name another
audited shard.

Line-by-line (function `load_tape_schedule`, new keyword-only argument):

```python
def load_tape_schedule(tape, *, tail_decisions, expected_sha256=None):
    ...
    if expected_sha256 is None:
        pinned = getattr(_V420, "CLEAR_SHARD_SHA256", None)   # unchanged default
    else:
        pinned = str(expected_sha256)                          # explicit re-pin
    if pinned is not None and str(info["shard_sha256"]) != str(pinned):
        raise CaptureError(...)                                # same refusal
```

* the comparison, the error message and the recorded
  `meta.tape.frozen_sha256` / `sha256_matches_frozen` fields are unchanged —
  an explicit `--tape-sha256` is a **re-pin**, not a bypass: if the bytes on disk
  differ from the supplied digest the run still fails;
* `capture()` passes `expected_sha256=args.tape_sha256`;
* `main()` adds `--tape-sha256 HEX64` (default `None`) and **refuses with exit 2**
  anything that is not 64 hex characters, so a typo cannot weaken the check;
* with the flag omitted, behaviour is bit-for-bit the historical seed-12-only
  behaviour (verified offline: seed12 default still loads 6,588 slots / 6,596
  decisions; seed10 default is still refused).

### 2.2 `verify_manifest_bc.py` — `dataset_id`/ancestor seed from the tape

Why: the document builder hard-coded the literal `seed12` in two functional
places, so the seed10 corpus would have been named
`w03h-o2-capture-seed12-strided-1099` — exactly the identity defect the parent
forbids (`-64` in `o2-1k`, seed12 on a seed10 corpus).

```python
# was: dataset_id = f"w03h-o2-capture-seed12-{tag}{n}"
dataset_id = f"w03h-o2-capture-seed{seed}-{tag}{n}"
# was: lineage.ancestor_id("engine", "d1-s0d1-n3300-seed12", seed, ...)
ancestor = lineage.ancestor_id("engine", f"d1-s0d1-n3300-seed{seed}", seed, ...)
```

`seed` was already read from `meta["tape"]["seed"]`; for `seed = 12` both strings
are byte-identical to before, so the accepted seed12 manifest is unaffected.

### 2.3 `verify_labels_provenance.py` — tape/out-dir as optional arguments

Why: the audit hard-coded the seed12 tape and took the out dir as a positional
argument only, so it could not audit the two new corpora (and the suggested

Changes: `TAPE` → `DEFAULT_TAPE` (same seed12 path), and `main()` now accepts
`--out-dir`, `--tape`, `--tape-sha256` **in addition to** the historical

`recorded_slot_cross_check`, report schema `w03h-label-provenance/1`) is
untouched; the report records `tape.path`/`tape.sha256` of the tape actually
audited.

### 4.1 Why `6,646 decisions / 13,291 frames` and not seed12's `6,598 / 13,195`

This is tape length plus the post-tape clear tail, **not** stride drift:

1. **Tape length**: seed10/11 `slots.jsonl` have **6,592** rows vs seed12's
   **6,588** → schedule 6,600 vs 6,596 → +4 replayed decisions = +8 frames.
2. **After the tape ends** the loop keeps executing the last recorded candidate
   until the engine reports `stage_clear` (bounded by `--max-frames 14000`).
   seed10/11 need 46 such beyond-schedule decisions (6,600–6,645); seed12 needed
   2. That is +44 decisions = +88 frames. 8 + 88 = 96 = 13,291 − 13,195.

The saved window is **entirely inside the recorded schedule**: samples run
`6, 12, …, 6,594` (`step 6`), the last sample is still a `recorded_slot`
(slot row 6,586 < 6,592), and every beyond-schedule decision is refused as
`label_without_tape_row`. Independent confirmation that the stride semantics
still hold on these tapes: `cand_mismatches = 0` against the tape at the same
positions, `expected_stride_positions = true`, and both frame deltas are exactly
`[12]` (§7).

## 11. What this evidence does and does not claim

* **Does**: two more real O2 corpora exist, were produced by replaying the real
  engine on the real T04 clear tapes under the W03L stride-6 protocol, have the
  same 1-shard manifest shape and the same 1,099-sample / 9-`move` coverage, and
  every label is cross-checked against its own tape with zero mismatches.
* **Does not**: make any learning, capability or gate claim. The parent's
  cross-tape experiment (train seed12, validate seed10/11) is already reporting a
  negative result; these corpora are the audit material for that conclusion,
  not a positive result.
* The 46 beyond-schedule decisions per seed10/11 replay exist only because the
  capture replays until the engine reports `stage_clear`; they are refused
  labels and are not part of the corpus.
* `shoot`/`bomb` remain unsupervised-by-construction, and candidate 9 is absent
  from all three tapes' stride-6 positions.
