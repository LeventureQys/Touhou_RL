## 2. 公式与常量

```text
gamma_t        = exp(-effective_frames_t / (hz * tau_s))
lambda_t       = lambda_base ** (effective_frames_t / 2)
delta_t        = r_t + gamma_t * bootstrap_mask_t * V_next_t - V(obs_t)
A_t            = delta_t + gamma_t * lambda_t * continuation_mask_t * A_{t+1}
value_target_t = stop_gradient(A_t + V_old(obs_t))
```

默认值与 `PLAN_SPEC.json` 的 `ppo` 块逐键相等，并由
`tests/test_v430_sequence.py::test_constants_match_plan_spec` 直接读 JSON 断言：

| 常量 | 值 | PLAN_SPEC 键 |
| --- | --- | --- |
| `TAU_S` | `200.0` | `gamma_time_constant_seconds` |
| `REFERENCE_HZ` | `60`（从 `contracts.REFERENCE_HZ` 复用） | `reference_hz` |
| `LAMBDA_BASE` | `0.97` | `lambda_at_two_frames` |
| `ROLLOUT_DECISIONS_PER_ENV` | `512`（仅记录） | `rollout_decisions_per_env` |
| `BURN_IN_DECISIONS` | `64`（未使用） | `burn_in_decisions` |
| `LOSS_UNROLL_DECISIONS` | `64`（未使用） | `loss_unroll_decisions` |

### 数值（与手算对照，机器精度完全相等）

| 情形 | 实际值（20 位小数） | 手算 | 差 |
| --- | --- | --- | --- |
| 2 帧 `gamma` | `0.99983334722145067452` | `exp(-2/12000)` = `0.99983334722145067452` | `0.0` |
| 2 帧 `lambda` | `0.96999999999999997335` | `0.97` = `0.96999999999999997335` | `0.0` |
| 4 帧 `gamma` | `0.99966672221604990778` | `exp(-4/12000)` = `0.99966672221604990778` | `0.0` |
| 4 帧 `lambda` | `0.94089999999999995861` | `0.97**2` = `0.94089999999999995861` | `0.0` |

`discounts_and_lambdas` 的返回形状跟随输入：标量入 → `(float, float)`；
序列入 → `(list[float], list[float])`，与 transition 索引逐位对齐。

## 3. Mask 规则（§7.2）

| 情形 | `bootstrap_mask` | `V_next` | `continuation_mask` |
| --- | --- | --- | --- |
| `terminated=True` | 0 | —（`A_t = delta_t`） | 0 |
| `truncated=True` | 1 | `terminal_value`（缺则 `SequenceError`） | 0 |
| 普通步（同 episode 有后继） | 1 | `values[t+1]` | 1 |
| `episode_id` 变化处 | 按上一格规则，但见下 | — | 0 |
| 序列末尾（非 terminated / truncated） | 0（除非显式给 `terminal_value`） | — | 0 |

`terminated and truncated` 同时为真 → `SequenceError`（与
`contracts.check_bootstrap` 同口径）。

## 5. 测试覆盖（45 项）

`tests/test_v430_sequence.py` 要求 9 条全部落地，另加 fail-closed 边界：

1. `discounts_and_lambdas(2)`：`gamma` 与 `math.exp(-2/12000)` 差 `< 1e-15`，`lambda` 与 `0.97` 差 `< 1e-15`。
2. `discounts_and_lambdas(4)`：`lambda` 与 `0.97**2` 差 `< 1e-15`。
3. `effective_frames` = `0` / `-1` / `2.5` / `2.0` / `True` / `"2"` / `None` → `SequenceError`；序列内单个非法元素同样抛。
4. 单 episode、无终止、3 步、2 帧：`r=[1.0, 0.5, -0.25]`、`V=[0.3, 0.4, 0.2]`，
   在测试注释里写出 `d0/d1/d2`、`A2=d2`、`A1=d1+G*L*A2`、`A0=d0+G*L*A1` 与
   `value_target_t = A_t + V_t`，对 `deltas`/`advantages`/`value_targets` 做
   **精确浮点相等**断言（不是 approx）。
5. terminated 末步：断言 `advantages[1] == 2.0 - 0.9`，并断言它**不等于**带
   `gamma * V_next` 的版本；同时首步仍按 `d0 + G*L*A1` 递推。
6. truncated：末步 `advantages[1] == 1.0 + GAMMA_2*2.0 - 0.4`，且与
   `1.0 - 0.4` 的差**恰为** `GAMMA_2 * terminal_value`；缺 `terminal_value` → 抛错。
7. 跨集切断：见 §6。
8. 常量：直接读 `PLAN_SPEC.json` 断言 `tau_s`/`hz`/`lambda_base` 与签名默认值。
9. 文件头注明"合成测试，不是游戏能力证据"。

## 6. 「跨集切断」的具体断言方式

`test_cross_episode_cut_matches_second_episode_alone`：

1. episode 1 两步，末步 `terminated=True`；episode 2 三步，帧数混用 `2 / 4 / 2`。
2. **拼接跑**：`joined = gae(ep1 + ep2, ep1_V + ep2_V)`；
   **单独跑**：`alone = gae(ep2, ep2_V)`。
3. 对 `advantages` / `value_targets` / `deltas` / `valid` 四个键逐个断言
   `joined[key][2:] == alone[key]` —— **精确相等（`==`），不用容差**：
   只要 episode 1 的 `A`、`gamma`、`lambda` 或 `V` 有一丝漏过边界，至少有一个
   float 会变。这是本测试最强的部分。
4. 再对拼接结果整体做 longhand 复核：ep1 两步按 `A1 = 2.0 - V1`（terminated 不
   bootstrap）、`A0 = d0 + G*L*A1`；ep2 三步按各自的 `gamma_t`（4 帧步用
   `exp(-4/12000)`、`lambda = 0.97**2`）、末步为数据末尾（`A = r - V`）分别断言。
5. 反向证据：`test_mid_sample_episode_boundary_requires_an_end_flag` 断言
   "中途换 `episode_id` 但既非 terminated 也非 truncated" → `SequenceError`，
   保证那个边界不可能被悄悄当成普通步。

## 7. TODO / 未定项

1. **中段 episode 边界被拒**（`TODO(W03B)`）：样本中间出现 `episode_id` 变化、
   且上一步两个 end flag 都为 `False` 时，本切片抛 `SequenceError` 而不是
   静默 `bootstrap_mask=0`。理由：end flag 缺失属于记录错误，猜一个值会污染
   value target。是否改由 rollout 写入端自动合成一个 truncation，属于分段切片
   的决定。
2. **`segment_end` 的语义**：`contracts.TRANSITION_END_FLAGS` 有三个标志，本切片
   把 `segment_end=True` 当 `truncated` 处理（`continuation_mask=0`，且要求
   `terminal_value`）。若后续判定 segment_end 表示"跨段连接、需要继续递推"，
   这里要改。
3. **序列末尾的 bootstrap**：末尾元素既非 terminated 也非 truncated 时取
   `bootstrap_mask=0`（无后继 `V` 可 bootstrap）。若给了 `terminal_value`
   则用它 bootstrap。何时应给，属于调用端契约，本切片不推断。
4. **`stop_gradient`**：本模块无张量库，`value_targets` 返回的就是
   `A_t + V_t`，梯度截断是调用端的义务，已在 docstring 写明。
5. **`valid` 恒为 `True`**：本切片不 padding，mask 只是给未来分段调用端留的位置。
6. **优势标准化 / `gamma` 的 reward 聚合口径**：§7.2 提到按帧产生的 reward 聚合
   到 decision 时必须与 gamma 单位一致；本切片只接收已聚合好的 `reward`，不校验
   它来自几帧。
