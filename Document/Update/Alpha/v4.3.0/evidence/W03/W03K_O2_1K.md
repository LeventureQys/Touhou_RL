### `frames_rgba.npy` is deliberately bounded

The raw `(480,640,4)` readback is **evidence for a future premultiplied-alpha
ruling, never a training input**, and costs 1.2 MB per decision (1.2 GB at 1000).
It is therefore kept for the **first 64 decisions only** (`--raw-frames-limit 64`,
new optional flag, §10): `(64,480,640,4)` = 78,643,328 B instead of ~1.23 GB.
This is recorded in machine-readable form in `meta.json`:

```json
"raw_frames": {"limit": 64, "retained": 64, "collected": 1000, "covers": "decisions [0,64)", …}
```

The alpha statistics that used to be derived from `frames_rgba.npy` are now
measured **per collected decision during the replay**, so `blank_audit.alpha`
covers **all 1000** decisions instead of only the retained 64 (§7).

This slice is a **sequential prefix**, not a representative sample: decisions
**1…1000** of the replay, in order. Measured on the produced labels and
independently on the tape (`labels_vs_tape_cand_mismatches: 0`):

```

coverage_whole_tape: move 9/9, focus 2/2, cand 17/18          # what 9/9 actually costs
```

`move` histogram of the 1000 collected labels:
`{0: 339, 2: 110, 3: 205, 4: 3, 6: 145, 7: 198}` — `move = 1`, `5`, `8` **never
occur**, and `move = 4` occurs **exactly 3 times**.
`focus` histogram: `{0: 739, 1: 261}`. `cand` is 10 of 18 possible values.

| window (tape order) | n | `move` | `focus` | `cand` | missing `move` |
| --- | ---: | --- | --- | --- | --- |
| first 64 (W03H) | 63 | 5/9 | 2/2 | 9/18 | 1, 4, 5, 8 |
| first 200 | 199 | 5/9 | 2/2 | 9/18 | 1, 4, 5, 8 |
| **first 1000 (this slice)** | **999** | **6/9** | **2/2** | **10/18** | **1, 5, 8** |
| whole tape | 6,596 | 9/9 | 2/2 | 17/18 | — |

> *One-decision offset*: the table windows start at decision 0 for the tape
> columns, while the capture starts at decision 1 (decision 0 is `short_stack`).
> That is why the independent count over the *tape* gives `{0: 338, …, 7: 199}`
> and this corpus gives `{0: 339, …, 7: 198}` for the same 1000 samples.
>
> **Consequence, stated plainly:** growing 64 → 1000 decisions moved `move`
> coverage only from **5/9 to 6/9**. The tape's behaviour is highly concentrated
> in its first thousand decisions and only diversifies later; **reaching 9/9
> requires strided (cross-tape) sampling, not a longer prefix.** This corpus is
> therefore valuable as the **ordered-prefix control point**, and must not be
> described as covering the 9 `move` values.
>
> `bomb = 0` is a **whole-tape property**, not an accident of the first 64
> samples: all **6,588** recorded `slots.jsonl` rows have the BOMB bit clear, and
> all 6,588 have the SHOOT bit set (measured). "Never bombs" is an instrument
> property of this tape, not a sampling artifact.

## 9. Two evidence-integrity defects, and what was actually fixed

The W03H builder (`.tmp_v430_o2/verify_manifest_bc.py`) hardcodes identity and
registers **one shard per artefact** (8 channel files × n decisions).

| # | field | before | after | fixable here? |
| --- | --- | --- | --- | --- |
| 1 | `dataset_id` | `w03h-o2-capture-seed12-64` (**same name as the 64-sample corpus**) | `w03h-o2-capture-seed12-1000`, derived as `f"…-seed12-{sample_count}"` | **yes** — derived in `recompute_manifest_stats.py` |
| 2 | `bc_smoke.bc_smoke.disclaimer` | "…**64 real decisions**, 2 epoch(s)…" (hardcoded) | "…**1000 real decisions**, 2 epoch(s), 8 optimizer step(s)…" | **yes** — derived from `n_samples`/`epochs`/`n_steps` |
| 3 | `assert_o2_compatible.returned_dataset` | `…-seed12-64` | `…-seed12-1000` (re-asked of `assert_o2_compatible`) | **yes** |
| 4 | `bc_smoke.manifest.manifest_sha256` | stale digest of the pre-rewrite manifest | refreshed to the manifest actually on disk | **yes** |
| 5 | **`counts.decisions`** | `8000` with no unit stated | `8000` **+ `counts.sample_count: 1000` + `counts.observation_channels: 8` + `counts.files: 8` + `counts_note` + `counts_rule` + `sample_count_check`** | **the number cannot change** — see below |
| 6 | `counts.episodes` | `8` | `8` + `counts_note` explaining it is 8 listings of the one seed-12 episode | **the number cannot change** |

### Why `counts.decisions` cannot be set to 1000 here (measured, not assumed)

`touhou_rl/v430/data/manifest.py::_check_counts` (lines 1531–1573) requires
`counts.X == sum over the listed shards`. With one shard per channel file, the
only self-consistent value is `8 × n`. Measured on this exact manifest:

```text
as_is                valid= True  problems= []
decisions=1000       valid= False P_COUNTS_MISMATCH: counts.decisions is 1000 but the shards sum to 8000
episodes=1           valid= False P_COUNTS_MISMATCH: counts.episodes is 1 but the shards sum to 8
additive_fields_only valid= True  problems= []
```

So the 8× is the **library's shard model**, not a transcription error, and
`touhou_rl/**` is out of scope for this work package. The defect is therefore
fixed *where it can be*: the corpus' own size is now stated in derived fields
that cannot drift, and `sample_count_check` makes a wrong number **fatal**:

```json
"sample_count": 1000,
"counts": {"decisions": 8000, "labels_valid": 8000, "episodes": 8, "shards": 8,
           "files": 8, "observation_channels": 8, "sample_count": 1000},
"counts_note": "counts.decisions=8000 is 8 channel-shards x 1000 decisions (the library's
                sum-over-shards rule), NOT 8000 training samples. …"
```

**Open decision for the W03 owner** (not taken here): either teach
`_check_counts` that a channel shard is not a decision shard, or register **one
shard per corpus** instead of per channel. Either change moves byte-identical data
and would need its own evidence slice.

The self-check is enforced in **two** places: `capture_o2.py::assert_written_shapes`
(generation time, exit **3**, §10) and `recompute_manifest_stats.py::check_sample_count`
(post-hoc, exit **2**), both comparing *labels lines == every per-decision
`shape[0]` == `meta.counts.collected`*. For this corpus all three are **1000**.

### `o2-64` was **not** rewritten

The user's W03K brief freezes `.tmp_v430_o2/o2-64/`, so it was recomputed
**read-only** (`--dry-run`, nothing written; all 12 files still carry their W03H
mtimes, `o2-64/manifest.json` sha256 unchanged = `338d83d0…`). Its recomputed

`recompute_manifest_stats.py --out-dir .tmp_v430_o2/o2-64` (without `--dry-run`)
adds only derived fields; it was not done here because it would overwrite accepted

## 15. Limitations, stated up front

1. **Coverage, not size, is the binding constraint**: `move` 6/9 (missing 1, 5, 8;
   `move=4` ×3). 9/9 needs a strided cross-tape slice, which this slice does not
   attempt.
2. **One episode, one tape**: no train/dev separation exists inside this corpus;
   it is a prefix of a single clear (seed 12).
3. **`shoot`/`bomb` are constant** (`1`/`0`) across the whole tape — only
   `move`/`focus` are supervised.
4. **`counts.decisions` still reads 8000** for a 1000-decision corpus (§9); the
   corrected number is `sample_count: 1000`, and changing the library's rule is an
   open decision for the W03 owner.
5. **Raw frames only for the first 64 decisions** (§3): a premultiplication ruling
   can be re-derived for those 64, not for all 1000.
6. **The BC numbers are a smoke test**, not a capability result.
