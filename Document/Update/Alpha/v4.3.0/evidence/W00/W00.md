## 2 资产登记的设计

- `schema = v430-assets/1`，`experiment_id = v430-w00-assets-r2`，`spec_revision = v430-plan-r2`
  （从 [PLAN_SPEC.json](../../PLAN_SPEC.json) 读，`revision` 字段），`frozen_at` 带 `+08:00` 时区。
- **路径口径**：仓库侧一律用 Windows 原生**相对**路径（`path_base: "repo"`，如 `.tmp_v420_data/T04/…`），
  解释器用绝对路径；**Linux 侧路径只出现在 `wsl: {distro, path}` 独立字段里**，Windows 路径字段不写任何 WSL 根，
  换执行机只需改 `wsl.distro`/`wsl.path`，不会把某台机器的 `/root/...` 写死进 Windows 路径。
- **50 条** = `python` + `torch` + `engine:rl_v3` + `engine:rl_laser` + `game_data` + `wsl-python` + 44 条
  `ASSET_SYNC.sha256` 相对路径条目。`ASSET_SYNC.sha256` 里的另 2 条是 WSL 绝对路径，映射到
  `engine:*` 两行（`sync_manifest.external_entries`），因此**46 条清单全部有对应检查**：
  audit 的 `sync_manifest:coverage` 行实测 `manifest_entries=46`、`manifest_entries_covered=46`。
- **只登记与校验，不复制**：44 条全部就**原地**算 sha256（合计 43,051,781 B / 44 个文件），没有任何文件被复制或移动。
- 每条资产声明 `require`：`hash` 必须内容哈希对上；`presence` 只要求存在（如目录）。
  另有 `live_mutated` 标记 6 条**活执行文件**（`v4.1.0`/`v4.2.0` 的 `state.json`/`journal.jsonl`/`budget.jsonl`）：
  这类文件会被运行过程追加，漂移时 audit 仍判 `present_mismatch` 并 gate 失败，但会说明「这是活文件漂移，
  不要盲目重钉（[DEVELOPMENT_GUIDE](../../DEVELOPMENT_GUIDE.md) §12）」。
- `ASSET_SYNC.sha256` 本体被 pin（`sync_manifest.sha256_expected = 0d08ae4e…`）：清单变了 audit 立即发现，
  且不需要修改清单文件本身。

## 3 `audit` 的判定与退出码（实现即契约）

逐项状态（`checks[].status`）：`present_verified`（存在且请求的校验全部通过）、`present_unhashed`
（存在但未做内容哈希：目录、活文件、或 >2 GiB 的对象；**不计入 verified**，且一定出现在 `remaining_gaps`）、
`present_mismatch`、`missing`、`unreachable`。WSL 不可用/命令失败/超时一律记 `unreachable`，**不会**降级成
`missing` 或 pass。

退出码（实测见 [EXIT_CODES.txt](EXIT_CODES.txt)）：`0` 请求的检查全部真实满足；`2` 输入/配置/环境无效
（含**已存在 `--out` 默认拒绝覆盖**）；`3` 有效测量但未达门（任何 missing/mismatch/unreachable，或该哈希却被跳过的
超限对象）；`4` 保留给资源不完整（audit 不产生）；其他 = 程序错误。

结果 JSON 含 `schema`、`experiment_id`、`identities`（源码/引擎/数据/协议 digest）、`started_at`/`finished_at`
（带时区）、`argv`（逐字）、`exit_code`、`protocol_validity`、`research_result`、`capability_gate`
（恒为 `not_run`）、`checks`、`statistics`、`remaining_gaps`。

一个实现层面的坑（已处理，值得后背包注意）：`wsl.exe -- <cmd>` 会先把命令交给发行版默认 shell，`$变量` 在到达
目标 shell 前就被展开成空串，导致「路径存在却判 missing」的假阴性。`audit` 改用 `wsl.exe -e bash -lc <script>`
（不经 shell），失败时回退到 `-e bash -s` + stdin；实际用到哪种传输记录在 `identities.wsl.transport`
（本次 `exec`，`wsl.commands=3`）。

### 4.3 唯一未满足项：`v4.2.0/journal.jsonl` 在清单生成之后又被写入

```
sync:Document/Update/Alpha/v4.2.0/journal.jsonl  [present_mismatch]
  sha256_expected = 5ed3693f38e4ac4a7f823d6ddd50c7eabbffa15c20acd13566798b3bafaf64e9
  sha256_actual   = 835b9e18d22095a78761dd0773245b39d355cb1c61cdadc33bf6202002fdae38
```

证据链（全部只读，命令与退出码见 [EXIT_CODES.txt](EXIT_CODES.txt) §1）：

1. **不是换行符假象**：当前文件 190,979 B 且含 CRLF（混合换行，10 行是 LF-only）。三种口径与 pinned 值比对，
   raw / LF / 全 CRLF **三者全不匹配**（`matches_under: none`），换行符三口径判别命令 exit 0。
   对比：同批并行的另一半发现的是另一处问题——`review_checks.json` 的 101 条源码 SHA 有 96 条属于
   「基线按 CRLF 记录、工作区是 LF」，那一处**可以**被归一化解释；本条**不能**。
2. **是活文件在 pin 之后被追加**：`ASSET_SYNC.sha256` 的 mtime 是 `2026-11-15 08:24:47`，
   `v4.2.0/journal.jsonl` 的 mtime 是 `2026-11-15 08:26:39`（晚 1 分 52 秒）；同目录的 `state.json`
   （08:24:39）与 `budget.jsonl`（11-14 15:52）在 pin 之前且哈希仍然命中。
3. **因此不能在本包修**：按 [AGENTS.md](../../../../../../AGENTS.md) §8.2 与
   [DEVELOPMENT_GUIDE](../../DEVELOPMENT_GUIDE.md) §12，「不把 state/journal 的活文件漂移当静态资产损坏，
   也不任意重钉真正不匹配的静态文件」。重钉 `ASSET_SYNC.sha256` 需要专门的清单任务授权，**不在 W00 白名单内**，
   本包也没有改它（其 sha256 仍是 `0d08ae4e…`）。

所以 `audit` 的 exit 3 是**正确的测量结果**，不是实现 bug：换成「活文件只查存在性」就会把这条真实漂移藏起来，
那才是伪造通过。

## 7 剩余阻塞与下一步

1. **`v4.2.0/journal.jsonl` 漂移（本包无法解除）**：需要授权的清单任务重新生成 `ASSET_SYNC.sha256`
   （或由主代理判定该行的处理口径）。在那之前 `audit` 会稳定返回 3；处理后再跑一次到**新路径**
   （例如 `audit-002.json`，本工具默认拒绝覆盖）即可得到 0。
2. **工作树是脏的**：`identities.source_repository.git.tracked_changes = {D: 3493, M: 21}`
   （合计 3,514 条 tracked 变更，`clean=false`）。`git HEAD` 不能复现当前工作树，所以「源码身份」不能只用 HEAD；
   这一块属于并行的另一半（[source_identity.json](source_identity.json)）。
3. **协议 digest 未定义**：本 audit 的 `protocol_digest` 只覆盖审计身份（schemas/config/plan spec/manifest/tool），
   不覆盖 obs/action 协议；W01 落地 `contracts.py` 后应把协议 digest 接进来。
4. **引擎/数据「可查不可用」**：现已证明两个引擎与数据目录在 WSL 内存在且哈希正确，但「能启动、能跑一局、
   能发键、帧/时序如何」完全未验证（W01/W06 的活）。
5. **G430-E0 not_run**：本包只完成身份/资产半边，[执行计划](../../EXECUTION_PLAN.md) §7 的 G430-E0 需要 W01 一起判定。
