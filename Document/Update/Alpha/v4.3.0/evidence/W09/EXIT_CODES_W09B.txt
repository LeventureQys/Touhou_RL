## 2 退出码语义（本子命令，严格按 EXECUTION_PLAN §4）

| 情形 | 退出码 | 实测 |
| --- | --- | --- |
| `validate_splits` 返回 `passed=True` 且 `problems == []` | **0** | 命令 1：**0** |
| 调用成功但 `passed=False`（有效测量未达请求门） | **3** | 见 §2.1：**3** |
| 输入/配置无法解析、schema 不符、`--out` 已存在、内部无法构造合法结果 | **2** | 见 §2.2 / §2.3：**2** |
| 其它程序错误 | 非 0 且非上述 | `main()` 的兜底分支返回 **1**（未触发） |

### 2.1 `passed=False` → 3（有效测量未达门）

构造：复制真实配置 `configs/v430/splits.json`，把 `splits.dev.ancestor_ids[0]`
（`model_selection|v420-dev-panel|dev-seed-1000|th08-stage1-normal-team0`）追加进
`splits.train.ancestor_ids`。注册表仍然全部可解析且 sha256 仍然匹配，所以这是一次**有效测量**，
只是被谱系规则拒绝：

```text
validate-splits: mode strict | problems 2 | splits 5 | sha 151cae489939 | gate NOT met | exit 3
problem A_MULTI_SPLIT: ancestor …dev-seed-1000… is assigned to several splits ['train', 'dev']
problem X_TRAIN_OVERLAP: ancestor group th08-stage1-normal-team0|dev-seed-1000 appears in both 'dev' and 'train'
真实退出码 = 3
```

同一份配置用纯函数自己的口径仍是 2：`lineage.exit_code_for(validate_splits(bad_config)) == 2`
（断言写在 `test_cli_validate_splits_exit_3_when_registry_is_rejected` 里）。
CLI 把纯函数的判定保留在 `research_result.status="fail"` + `research_result.lineage_exit_code=2`，
而进程退出码按计划表取 **3**；这不是放宽规则，只是把"有效测量未达门"与"输入无效"分开。
