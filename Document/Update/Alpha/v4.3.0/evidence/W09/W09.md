## 2 CLI 调用方式（接线留给整合任务）

`validate-splits` 子命令**尚未接线**（`tools/rl/v430.py` 不在本包白名单）。本包只提供纯函数：

```python
from touhou_rl.v430.data.lineage import validate_splits, exit_code_for

report = validate_splits("configs/v430/splits.json")   # 路径或 dict；strict= 可关闭
json.dump(report, fh, ensure_ascii=False, indent=1)     # --out 的内容
raise SystemExit(exit_code_for(report))                 # 0 = 通过；2 = 输入/协议无效
```

- 默认 `strict=True`：任何 finding 都是 fatal。
- `strict=False`：只把 `ADVISORY_CODES`（当前仅 `P_SOURCE_ENUMERATION_LIMIT`，即"该来源只到 family 级"
  这一粒度说明）降级到 `report["degradations"]`，**其余 finding 仍然 fatal**（有测试覆盖，见
  `test_degraded_mode_never_hides_a_lineage_violation`）。降级模式不会把违规变成通过。

  （它不测量任何能力）。
- `report` 必含 `passed / problems / statistics / split_registry_sha / split_registry_sha_scope /
  checks_performed / not_checked / mode / exit_code`；每个 problem 带 `code` 与人类可读 `message`，
  冲突类还带 `ancestor_id` / `group` / `conflicting_ancestors` / `seeds`，可直接写进 `--out` 证据。

## 3 谱系模型（`lineage.py`）

### 3.1 三层结构

| 概念 | 定义 | 实现 |
| --- | --- | --- |
| **任务祖先** ancestor | 由 `(source_kind, source_id, episode, task_family)` 唯一确定；`seed` 是**属性不是身份** | `ancestor_id()` → `kind\|source\|episode\|family` |
| **独立组** group | `(task_family, episode)`；另用 `trajectory_sha256` 合并"换名字的同一条轨迹" | `group_key()` + union-find |
| **预训练来源** source | `(kind, source_id)` 记录它接触过哪些 ancestor（`ancestor_ids`）或只到 family 级（`touched_families`） | `pretraining_sources.json` |

`seed` 不进入身份是刻意的：把同一 episode 换个 seed 再登记，会得到**同组**而不是新任务。
同一 split 内出现两个同组祖先 → `A_DUPLICATE_GROUP`（`independent_ancestors` 只算 1）；
跨 split 出现 → `X_TRAIN_OVERLAP` / `X_SPLIT_OVERLAP`。这直接实现
`TRAINING_PLAN.md` §4 "不可由换 seed 伪造未见任务"。

### 3.2 校验规则（fail-closed，全部有测试）

| 代码 | 拒绝条件 |
| --- | --- |
| `X_TRAIN_OVERLAP` / `X_SPLIT_OVERLAP` | train 与 dev/confirm/adapt/quarantine 的祖先组交叉（并给出冲突祖先） |
| `H_TOUCHED_BY_SOURCE` | 冻结/备选留出家族出现在**任一**预训练来源的谱系里（9 类来源各一条测试） |
| `H_HOLDOUT_IN_SPLIT` | 留出家族出现在 train/dev/confirm/quarantine |
| `H_INSTRUMENT_FIXTURE_LEAK` | 有来源声明 `uses_retail_replay_fixtures=true`，而留出家族在零售回放语料里有 fixture（语料覆盖全部 33 个 (difficulty,stage) 组合） |
| `H_DIRTY_FAMILY` / `H_NO_EVIDENCE` / `H_TOO_FEW` / `H_UNKNOWN_FAMILY` / `H_NOT_TARGETED` | 留出家族"脏"、无 `clean_evidence`、少于 2 个、改名冒充、adapt 未指向 |

| `P_BINDING_SHA_MISMATCH` / `P_BINDING_MISSING` / `P_REGISTRY_SCHEMA` | 冻结注册表内容漂移 |

### 3.3 `split_registry_sha` 与换行口径

- `stable_registry_digest()`：对整份配置做**排序键 + 紧凑 JSON**（`json/sorted-keys-compact-utf8-lf`），
  再按 `text/lf-normalized` 取 sha256；`split_registry_sha` 永远与 `split_registry_sha_scope`
  成对出现，报告里再记 `split_registry_sha_canonicalization`。
- 文本产物：`text_lf_digest()` = 先把 `CRLF` 与孤立 `CR` 折成 `LF` 再 sha256，口径标注
  `text/lf-normalized`（`file_identity()` 强制要求显式 scope）。
- 二进制：`binary_raw_digest()` = 原字节 sha256，口径 `binary/raw`。
- 测试断言：同一文本 CRLF 与 LF 两份文件的 `text/lf-normalized` 摘要**相同**、`binary/raw` 摘要**不同**、
  孤立 `CR` 也折成 `LF`；未知 scope 抛 `LineageError`。
- 摘要敏感：同输入两次相同；把 `roots.repo` 从 `.` 改成 `./` 摘要即变（`EXIT_CODES_W09.txt` §2）。

### 3.4 诚实边界（`report["not_checked"]`，随每次输出返回）

1. 只校验**记录**，不能证明证据文件内容如其声明（不读资产/像素载荷）；
2. 本机不存在 sealed 资产，sealed 保护是**引用型**（配置里出现 sealed 路径即拒），不是内容型；
3. 只有提供 `trajectory_sha256` 才能识别"同轨迹换 seed"；否则按 `(task_family, episode)` 折叠；
4. "未接触"不是从像素反推的，而是依据已登记来源的训练集成员关系。

- `train_seed_count=146`、`train_seed_min=1`、`train_seed_max=3091`：**没有一个落在

## 8 与前序说法不一致之处（复核发现）

1. **任务书引用 `touhou_rl/v420/preregistered_split.py` 不存在**。实际实现在
   `touhou_rl/preregistered_split.py`（schema `v200-preregistered-rollout/1`，只支持
   `train/dev/test`、无 `confirm/adapt`、无祖先/来源概念）。本包只读它作为"现有 split 实现"参考，
   没有复用其 schema——G410-6 需要的东西它不表达。
2. **`ASSET_SYNC.md` §3 的 s1c 描述与磁盘不符**：写 "20 个 train seeds（1–20）/ 66,143 decisions"，
   而 `.tmp_v410_s1c/d1/manifest.json` 只有 **12 分片 / seed 9–20 / 39,518 decisions**。
   差额是 WP03.1a 的 8 个分片（seed 1–8），它们不在 `.tmp_v410_s1c/d1/shards` 下。
   "20 个 train seeds"实际是"20 个分片"。本包按 manifest 登记（seed 9–20），并在来源 note 里写明。
3. **`.tmp_v410_s1b` 完全没有入 `ASSET_SYNC`**：39,011 decisions / 约 2.03 GB / stage 1 Normal /
   dev seed 1000–1011 / 已被判 rejected，`grep -c s1b ASSET_SYNC.md` = **0**，
   `ASSET_SYNC.sha256` 也没有条目。这违反 AGENTS.md §8.2，且它恰好是谱系关键证据。
   本包只登记进谱系（quarantine），**没有改资产清单**（不在白名单）。
4. **`exposure.json` 过期**：2026-11-13 版写 "1020–1099 unused"，而 v4.2.0 README §6（11-15）
   已把 **1020–1039** 划给候选选择。本包把 1020–1039 记为 `dev.reserved_seeds`（**不**假装已曝光，
   因为没有运行证据），并把它写进 `contamination_if_used`。
5. **保护范围实际消耗情况比 `ASSET_SYNC` §6 更严重**：§6 只说 61000–61099、61400–61499 未使用；
   实际 **61300–61399 已被 v4.1.0 G410-1 用掉**（100 个种子，100/100 过面）。本包把该范围标
   `usage=spent`，并在 `_check_confirm_batches` 里禁止"spent 范围再声明 unused"或反向。
6. **v4.2.0 2 帧语料的来源命名有误导**：`.tmp_v420_data/T04/dataset/index.json` 的分片名是

   的错误谱系结论。
7. **任务书说 dev 面板是 "1000–1039"**：v4.2.0 T02/T08 的**实际**评估配置只写 1000–1019
