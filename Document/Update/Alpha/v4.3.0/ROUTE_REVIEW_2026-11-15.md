## 2 纠正 BC 基线

### 2.1 原计算的含义

[数据腿报告](evidence/W03_DATA_LEG.md) 第 156 行写明：`move=0` 占 `468/1099`，因此“基线 CE ≈ 0.85”。

恒猜最多类可以给出一个**准确率基线**：在该完整语料上为 `468/1099≈42.58%`。它不能直接给出 `−log(42.58%)` 作为全体样本的交叉熵。

对于固定预测分布 `q`，无类别权重、无标签平滑时，留出集 CE 为：

```text
CE = −(1/N) × Σ_i log(q[y_i])
```

必须计算每个真实类别对应的损失。如果把恒猜最多类表示成 one-hot 概率，其他真实类别的预测概率为零，其损失发散；若做截断或平滑，结果取决于事先定义的概率，仍不会自然等于 `−log(p_max)`。[PyTorch 交叉熵定义](https://docs.pytorch.org/docs/2.15/generated/torch.nn.CrossEntropyLoss.html)

### 2.2 按报告直方图复算

[W03M 语料统计](evidence/W03/W03M_SEED10_11.md) 第 240、251 行给出以下完整语料计数。以 seed12 的完整频率作为固定预测分布，可得到：

| 量 | 复算值 |
| --- | ---: |
| seed12 完整语料样本数 | 1099 |
| seed10 完整语料样本数 | 1099 |
| seed12 多数类准确率 | 0.425842 |
| 旧算法 `−log(p_max)` | 0.853688 |
| seed12 完整频率分布在 seed12 上的 CE | 1.685989 |
| seed12 完整频率分布在 seed10 上的 CE | 1.707497 |
| 9 类均匀概率分布 CE | 2.197225 |

**这只是对报告数字的确定性复算，不能作为新的正式模型评测。** 原模型训练划分为 880 条训练样本、219 条验证样本；上述完整 1099 条的频率混入了验证标签。正式基线必须仅由真实训练划分拟合，冻结后在与模型完全相同的留出集上计算。当前编辑端没有该实验的原始数组、划分与 checkpoint，不能据此替代精确比较。

可复算的 Python 代码如下，不需要引擎、数据资产或第三方库：

```python
import math

seed12 = [468, 28, 203, 172, 32, 21, 78, 76, 21]
seed10 = [467, 28, 153, 197, 20, 21, 92, 97, 24]
p = [n / sum(seed12) for n in seed12]
r = [n / sum(seed10) for n in seed10]

print("majority_accuracy", max(p))
print("old_formula", -math.log(max(p)))
print("full_seed12_prior_on_seed12", -sum(x * math.log(x) for x in p))
print("full_seed12_prior_on_seed10", -sum(x * math.log(y) for x, y in zip(r, p)))
print("uniform_9_class_ce", math.log(9))
```

正式重评应同时保留：训练集频率概率基线的 CE、恒猜训练集多数类的准确率、模型逐头 CE 与准确率、逐类表现，以及真实闭环成功率。缺失类别的平滑方案须预先固定。不要把逐头 CE、四头求和 loss 和准确率混用。

旧报告中的小模型 seed10 CE 为 1.6020，已经说明将所有结果统一与错误的 0.8537 比较会影响判断；是否优于合法基线仍须按原划分重算。高训练拟合与较差验证之间的差距仍值得诊断，但“BC 零迁移”没有获得原基线比较的有效支持。

## 3 实际推进偏离了原设计

### 3.1 学习能力门应直接检验任务成功

[原训练计划](TRAINING_PLAN.md) §6.2 要求按独立开发片段的实际操作结果挑选 checkpoint，CE/top1 仅作诊断；同时安排 D-state、D-pixel、D-pixel-memory 对照。

后来的[状态报告](evidence/FINAL_STATUS.md) 第 88 行以及[交接说明](W12_HANDOFF.md) §4，却把 BC 失败解释为“真实微段 ≥9/10 不可能达成”。这个必要条件没有被证明。

BC 优化的是对教师具体动作的预测；游戏目标允许多种有效动作序列。教师的选择还可能受未提供给学生的信息、历史或 tie-break 规则影响，这些都是待验证的标签可模仿性假设。在线学习应有机会直接优化任务结果。

因此，保留“微段学会后再扩大课程”的要求，同时允许从零在线学习、BC 初始化后在线学习等分支接受同一真实成功标准。某个 BC 配方失败，只约束该配方。

### 3.2 数据覆盖要对应能力问题

三批 stride 语料各 1099 个采样点，但每批来自一条轨迹；`move` 覆盖 9/9 只说明动作类别出现过。[W03M](evidence/W03/W03M_SEED10_11.md) 同时记录：shoot 全为 1，bomb 全为 0，二者由旧仪器规则固定。

这批数据可用于移动与 focus 的有限模仿诊断。仅凭这些常量标签无法学出释放射击或使用 bomb 的情境选择，也不能以其离线成绩判定完整资源管理路线。

后续采集应针对独立事件、不同合法可达起点、资源条件以及学生实际失败状态组织。增加同一轨迹的相邻帧，不能等价替代增加独立情境。循环策略训练还需要符合部署时间尺度的连续窗口与历史；stride 覆盖统计本身没有证明记忆能力。

### 3.3 离线动作指标与真实控制结果分别验收

闭环执行会改变学生随后看到的状态。只在教师回放上预测动作，无法覆盖所有由学生偏差导致的新局面；这也是 [DAgger 原论文](https://proceedings.mlr.press/v15/ross11a.html)讨论的核心问题。采集学生访问状态并提供可靠纠正是一种可比较分支，前提是教师对这些状态仍有有效指导。

相同 `cand` 前缀也不能单独证明像素训练样本完全重复。旧报告关于前缀污染的强结论，后续应按原始帧、动作历史、时间对齐和轨迹祖先复核。去掉共有动作前缀可以作为保守诊断，但不能把剩余后缀自动认定为干净泛化集。

### 3.4 架构修改应由受控实验支持

现有 [ActorPolicy](../../../../touhou_rl/v430/models/actor.py) 已是三路空间 CNN 加 GRU，不能将“换成 CNN”当作尚未尝试的统一解法。缩小网络同时大幅降低输入分辨率，会同时改变容量和可见信息；这类比较不能单独证明容量是否为主因。

首先固定输入、数据划分和预算，分别检验容量或记忆等因素。只有真实错误分析支持时，再增加战术头、图注意力或其他复杂结构。

## 4 下一轮真实实验

### 4.1 从一个可判别的战斗片段开始

先选一个 3–10 秒、已有真实成功见证、仍需要学生作出有效动作的片段，例如扇形形成前撤离，或 Boss 尚需战斗的短后缀。冻结成功事件、失败事件、控制协议和时间上限。只等过场确认、恒定按键也可轻松完成的片段不适合作为战术学习证据。

训练起点必须由合法真实轨迹恢复；恢复可见历史，并保留教师前缀与学生新决策的边界。训练与开发按独立轨迹祖先或事件划分，避免把同一片段相邻帧当作独立泛化样本。

### 4.2 先比较能回答问题的分支

| 分支 | 主要用途 | 比较条件 |
| --- | --- | --- |
| D-state 在线学习 | 检查任务、信号、探索与优化是否支持局部学习 | 与像素臂使用相同任务、动作和起点范围；状态输入与历史明确登记 |
| D-pixel-memory 从零在线学习 | 检验像素与记忆组合是否能直接改善操作结果 | 固定输入、目标和新交互预算 |
| 同像素模型 BC 初始化后在线学习 | 检验 BC 是否实际帮助学习 | 与从零臂比较同在线预算，同时披露额外演示、预训练更新和计算成本 |

若像素与状态分支出现稳定差异，再加入同输入、容量尽量匹配的无记忆像素臂，区分表示与记忆因素。不同编码器使状态与像素比较无法严格归因于单一因素，结果只用于缩小排查范围。

固定开发评测时点，报告更新前后任务成功率、成功次数/总次数、资源使用和独立事件数。CE、熵、value 误差等用于诊断。先用一个训练种子确认最小学习信号，再按原计划扩到多个种子；前期结果不能提前称为稳健提升。

预先给每个分支设定有效游戏帧、更新次数和墙钟上限，成本中单列前缀重放、评测、教师查询与预训练。比较 BC 的收益时，同时报告“相同在线预算”和完整成本，不能把额外数据与算力隐藏起来。执行额度以现有用户授权为准，本文件不新增训练授权。

### 4.3 按结果决定下一步

| 观察结果 | 优先排查或推进方向 |
| --- | --- |
| D-state 也学不会 | 可解性、奖励事件、探索、优化与预算；暂不增加视觉复杂度 |
| D-state 能学，像素分支不能 | 可见信息是否充分、视觉表示、时间对齐和记忆 |
| BC 初始化无益，从零在线学习有效 | 降低该 BC 配方优先级，继续有效在线分支 |
| 训练起点能过，独立开发起点失败 | 数据情境覆盖、学生访问分布与泛化 |
| 留出片段能过，连续运行失败 | 课程连接、资源与记忆继承、长程决策 |

这些是诊断优先级，不能由单次比较推出唯一因果解释。

### 4.4 有学习信号后再扩展

由一个片段扩到原计划的 10 个训练片段和至少 30 个独立留出片段，比较至少 3 个训练种子。训练片段达到 ≥9/10 仅证明局部可学；留出结果及不确定性单独报告。

随后由包含真实战斗的成功后缀逐步向前扩展，验证“上一段学生实际结束状态 → 下一段”的连续运行，继承位置、资源、弹幕、rank 与记忆。逐步提高自然开局比例；多个教师起点上的成功不能拼接成自然整面成绩。

这种推进保留了[反向课程学习](https://arxiv.org/abs/1707.05300)的思路，但论文结果不保证本项目成功。推进依据应是新起点上的实际任务改善，而不是采集量、manifest 合法性或离线 loss 单独变好。

## 5 仍需训练机核验的内容

1. 找到原 880/219 划分、三个模型与逐样本预测，按训练集频率重新评估所有旧基线比较。若原记录缺失，建立新实验身份，不能把新划分的结果当作复现。
2. 核验原始画面、历史与轨迹谱系，确认共同前缀的实际重叠范围，并构建独立开发事件。
3. 检查教师选择是否可由学生可见历史预测，以及偏离演示轨迹后教师能否给出有效纠正。
4. 完成真实状态与像素策略的有界微段对照，再决定采集扩容、架构调整或课程扩展。

本次没有取得上述新的训练机证据。确定性数值复算不计入任何 G410/G430 游戏能力门；各门状态以实际验收为准。
