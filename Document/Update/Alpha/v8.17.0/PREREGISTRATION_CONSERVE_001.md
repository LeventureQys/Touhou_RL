# 预注册 v8170-CONSERVE-001：用**保守放雷**的行为策略采集，让「带着雷去死」的状态进入标签

冻结时刻：2026-11-22（Asia/Shanghai），**在任何 v8.17.0 采集之前**。
状态：**FROZEN**。

---

## 0. v8.16 的冒烟给出了最终机制

真冒烟（1 条死亡 episode，死亡决策 828）：

| 视界 | critical | diff |
| ---: | ---: | ---: |
| 120 | 0/3 | 0/3 |
| 240 | 0/3 | 0/3 |
| **600** | **3/3** | **0/3** |

**原因**：`bombs_at_death = {0: 1}`，三个状态的 `bombs_remaining` **全部为 0** ⇒ `bomb=1` 是 no-op ⇒ 不可能有 diff。

把这与 v8.15 合起来，整条线的机制就闭合了：

| 区域 | 雷的状态 | 标签能否表达雷的价值 |
| --- | --- | --- |
| 策略还活着（v8.15 的 10,008 状态） | 有雷 | ❌ `bomb=0` 已经够好（critical = 0） |
| 策略要死了（v8.16 的死亡邻域） | **雷已用光** | ❌ `bomb=1` 是 no-op（diff = 0） |

⇒ **在 R5 的轨迹上，雷从来不是「边际资源」**——它总是在「不需要」的时候被花掉，在「需要」的时候已经没了。

## 1. 设计（单因子：行为策略的放雷阈值）

| 项 | v8.16（R5 行为策略） | **v8.17.0** |
| --- | --- | --- |
| 行为策略的放雷规则 | R5 分阶段 80/60/40 px | **保守：只在 `nearest_all_px < 25 px` 时放**（≈贴脸才放） |
| 其余 | `S` + 规则、900 决策、死亡即停 | **不变** |
| 采样 | 死亡前最后 20 决策 | **不变** |
| 标签 | 36 路 × H=120/240/600 | **不变** |
| 目标 | 600 状态/视界 | **不变** |

> **预期**：保守规则下玩家会**带着 2–3 颗雷死**（因为它不在 80/60/40 px 就放），于是死亡邻域的状态里 `bombs_remaining > 0`，`bomb=1` 才可能把濒死拉回存活。

**若「带雷死亡」仍然稀少**（例如保守规则下 20 s 活满率仍很高），则退一步用 **`--bomb-rule none`**（完全不放雷）采集：那样玩家**带着全部 3 颗雷死**，死亡邻域必然 `bombs_remaining = 3`。这正是最纯粹的「雷能否救命」实验。

## 2. 判据

| # | 终点 | 判据 |
| --- | --- | --- |
| **P0a（前置）** | 死亡邻域是否带雷 | 采到的状态里 `bombs_remaining > 0` 的占比 **≥50%** |
| **P0b（前置）** | 标签是否出现差异 | 其中 `best bomb=1 > best bomb=0` 的占比 **≥20%** |
| **P1（主）** | 臂 B（纯标签）的 600 决策活满率 | **> 19.44%**（v8.3.0） |
| **P2** | 臂 A（+规则监督） | 与 B 并排 |
| **P3** | 用雷分布 | **出现「只用 1–2 颗」的 episode** |
| **P4** | 900 决策 | 与 v8.3（0.61%）、v8.6（2.94%）、R5（17.61%）并排 |

### 2.1 停止条件

| # | 条件 | 动作 |
| --- | --- | --- |
| **S-nobomb** | P0a 不成立（死亡邻域仍几乎无雷） | 判「保守规则不够保守」；改用 `--bomb-rule none` 采一轮（**这是最纯的实验**） |
| **S-nodiff** | P0a 成立但 P0b <20% | 判「即使带雷，放雷也救不回来」；**这是「雷的价值有限」的硬证据**，转在线 RL 或接受 20 s 上限 |
| **S-ok** | P1 与 P3 都成立 | 判「带雷死亡邻域采样可行」；下一轮扩到 5,000 状态并做阈值扫描（25/40/60 px） |
| **S-partial** | P1 成立但 P3 不成立 | 判「学得更久但不省」；转在线 RL |
| **S-fork** | 保真门失败 | 整轮作废 |
