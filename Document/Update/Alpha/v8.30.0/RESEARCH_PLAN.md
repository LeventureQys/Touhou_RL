# 下一阶段研究计划

2026-11-24，v8.30.0 第二稿。本稿按用户要求先决定研究路线，再安排核验与实施，取代上一稿以 BC 修正、G1/T2 复验为首批主工作的顺序。方向决策见 [路线复核](ROUTE_DECISION.md)。目前完成的是设计取舍，路线可行性尚待小规模实测。

## 主研究问题

在真实 TH08 第一面任务中，像素策略能否通过学习，利用当前画面与执行历史，提高任务完成表现，并把能力带到新起点和连续对局？这个问题先于放雷阈值排名、克隆损失下降和大规模独立确认。

主路线选为：**真实任务结果驱动的像素闭环学习，配合同任务特权诊断，逐步验证未见起点、连续资源和自然第一面。** 现有引擎、恢复、教师、数据和训练器按需复用。教师动作、短视反事实标签、BC/DAgger、特权 critic 均为可检验的辅助选择；不把其中任何一项自动设为主线必经门。

actor 尽早使用部署允许的像素及真实执行历史。训练可以使用登记清楚的特权回报、价值估计和辅助标签；这种设置验证像素执行能力，不等于严格像素自我改进。WP06 的像素奖励、终止与重开继续独立推进，后续按原门切换训练反馈来源。

| v8 的指标是恢复起点后活满 N 决策，未测 Boss 击杀 | 主任务应连接真实阶段完成与资源后果；无死亡存活保留诊断用途 |
| 目前 BC 预训练目标与双类决策错配 | 相关分支需要修正，但修好它仍不证明整个 BC→RL 或特权→像素路线成立 |

这些约束来自历史证据，详见 [路线依据与原文链接](ROUTE_DECISION.md)。旧仪器缺陷限制部分负结果的能力解释；历史失败只约束对应的任务、输入、实现与预算。

## R1 先定义一个路线判别任务族

从已有训练来源选择一个真实短攻击阶段，以实际完成事件或合法阶段转场为终点。允许用审计真值定义训练期任务结果，但 actor 不能读取真值。冻结机体、动作库、射击、focus/bomb、决策节拍、初始资源、技术终止和最大预算；自然第一面仍按正常残机规则定义。

该任务应有同约束真实可解见证，能解释一次成功和一次失败；缺见证时先补任务可解性，不把教师完整动作成绩套到缩减任务。固定动作通过某窗不构成排除条件。任务族和开发起点按来源与阶段预先抽样，不能看新策略输赢后筛选。训练起点可以用于设计，未见开发与正式确认各自保留用途。

只读补充范围缩到这个切片：任务与恢复、现有真实轨迹、像素/动作历史、可用控制器、开发祖先供给和端到端成本。暂不要求追溯四轮所有头或复核 G1/T2 的 24 文件；这些不能优先决定主路线。

## R2 同任务下区分可控性、反馈和学习

先把同一个任务上的像素观测、动作执行和裁判接通；同约束控制器作为单列正对照。像素接线与特权可解性检查可并行，不要求先训练出能通关的状态学生。

随后给一个小规模像素学习候选保留学习前参照，并在相同任务目标、资源、动作和评测安排下比较学习前后。必要时加入状态输入的同任务学习诊断臂，帮助区分任务/优化问题与像素表示问题。它不是强制先完成的大规模特权项目。

| 比较 | 解释范围 |
| --- | --- |
| 同约束已知控制器与简单固定动作 | 可解性与参照强度；不证明像素可学 |
| 像素候选学习前后 | 在该输入和预算下学习是否带来任务改善；loss 下降不作为替代 |
| 同任务状态臂与像素臂 | 帮助定位任务、表示、历史与优化；不能把差值全部归为像素信息缺失 |
| 冻结闭环与预生成开环 | 在线反馈在该任务和对照构造下是否有价值；另核对动作频率、持续时长与供体质量 |

开环只从独立训练供体预生成，不重放同一目标局已经成功的闭环动作表。特权 bomb 规则只能作为特权/混合参照；若两臂共用它，结果只涉及该规则条件下的移动反馈，不能宣称端到端像素控制。

学习与反馈判别是相互联系的开发步骤，不能要求一个尚未训练的弱像素 actor 先证明反馈收益才允许学习。小规模学习后冻结候选再检查反馈；单片段能拟合但不胜冻结动作，仍不足以说明看懂弹幕。

## R3 从局部可行性推进到未见起点

在看新成绩前分配训练和开发祖先；同根的分支、相邻片段和近重复前缀归一簇。首批为路线探索，不以固定 8 祖先或池化 p 值结算泛化。先由来源供给与一个端到端回合的真实算时确定可负担的规模，完整记录每根、每阶段和每种子的结果。

一个训练 seed 的成功仅作为可行性观察。若有局部改善，再做多个训练 seed 与未见开发起点，确认效果不只来自一次初始化或一个固定剧本。训练动作频率先验、固定动作和开环参照只从训练来源确定。不能根据开发最佳结果反过来调整参照。

若局部可拟合而跨起点失败，优先研究阶段覆盖、学生来访状态与历史/记忆；若连局部都学不会，先区分任务/奖励、可见性、接线和优化。不要一次更换网络、奖励、动作与教师后失去归因。

## R4 早做连续执行与自然开局诊断

一旦有可运行像素候选，就在开发用途内检查更早接管和自然开局的最早失效位置，同时记录入口抵达率、入口位置/资源及抵达后的完成率。局部课程可以继续，但不能无限等微段指标更高才看自然分布。

连续执行不补雷、不恢复残机、不在段间清空本应继承的记忆；允许正常游戏中的掉命、重生与补给，并按预注册规则记录。恢复段成功而连续失败时，针对接缝和来访状态训练；不把恢复后的三颗雷当作自然资源。

HUD、自机和死亡/终局检测根据当前切片的实际需要推进；像素执行研究与严格像素反馈能力分别记录。使用引擎终止或训练回报时不能报告 G410-3/G410-4 已成立。

## R5 何时才做确认

主路线先需要局部学习、反馈价值、未见起点和连续执行的开发证据；确认工作用于检验已经有可行性证据的冻结候选。G1/T2 的历史排名不是进入第一面确认的条件。

自然第一面达到原开发提名条件后，再冻结纯像素候选按 G410-2 实施 S1N 100 局与至少 20 个 Windows 会话；能力判据和封存样本用途沿用 [v4.1 规格](../v4.1.0/README.md)。微段确认、复训稳定性、第一面能力和严格像素自我改进分别报告，不能相互替代。

## 预算与分叉

撤销上一稿把 96 个 G1/T2 回合、两档 403,200 帧及两初始化三种子 60 回合列为近期排程。它们保留在条件协议中，只有路线诊断证明相关问题值得投入时再重新冻结。

下一笔实施预算用于一个能区分路线解释的小任务切片，首先量真实恢复、渲染、控制与记录成本。正式派单时必须填写任务来源、运行上限、受控帧、含前缀和重试的墙钟、磁盘限额，以及工程失败和合法负结果的处理。这里不以尚未取得的算时编造规模或日期。

| 结果 | 研究行动 |
| --- | --- |
| 任务或同约束控制不可解 | 修任务与动作契约；不扩大任何学习配方 |
| 接线完成但没有学习收益 | 保留负结果，区分信号、可见历史和优化；不把接线当路线验证 |
| 学习有收益但开环足以解释 | 检查任务族与对照质量；不作避弹/反馈能力声明 |
| 局部成功但未见/连续失败 | 聚焦分布覆盖、资源继承与记忆，推迟能力确认 |
| 多种子、未见、连续和自然开发均改善 | 冻结候选，计算确认规模与功效，再安排相应确认 |

原 WP05 保持暂停。本次完成路线设计修订，下一步的具体确认与实施以路线判别所需的最少材料为依据，不直接沿用上一稿的技术盘点和批量实验顺序。
