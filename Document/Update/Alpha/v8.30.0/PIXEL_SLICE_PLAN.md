# v8.30｜像素最小闭环与连续事件切片

**第二稿定位：** 本文保留为 [路线决策](ROUTE_DECISION.md) 中的接线与事件接口子计划。接线后应紧接同任务的小学习及反馈判别，不再把接口冒烟作为下一阶段的主要研究终点。下述数量是候选切片上限，须按新路线重新冻结，不自动进入当前排程。

**2026-11-24 · GPT 研究端规划 · 待训练端核实和另单实施。** 本文规定一个可与 BC 复核、G1/T2 配对试点并行的最小切片。本次交付是计划，不包含新引擎结果、像素能力或训练完成声明；WP05 保持暂停。训练端先按本版只读工单回报可用入口、前缀与历史证据，收到实施工单后才运行或开发。

## 1. 本切片回答什么

先回答“同一条真实轨迹中，框内像素能否经过 actor 生成动作，动作能否按约定生效，帧序与终态能否独立核对”。本版不要求像素先通关。固定策略能发键只证明接线；一条像素轨迹跑满短窗也不能证明利用视觉、学会避弹或达到 G410-2。

后续另拨预算，才回答“一个像素学习候选能否拟合同一个真实片段”。该实验与接线冒烟分号、分预算、分结论。跨祖先泛化、连续运行和第一面能力继续按原路线逐项验证，不由本切片替代。

| 顺序 | 最小交付 | 可以作出的结论 |
| --- | --- | --- |
| P0，只读核实 | 一个已分配开发窗的来源、合法前缀、像素与动作入口及缺口 | 具备或不具备实施条件 |
| P1，实际接线 | 一条真实像素 → actor → 动作 → 实际帧 → 独立终态的完整轨迹 | 此身份与入口的数据流可运行；分别报告正常满窗或合法死亡 |
| P1，校准与边界 | 同约束教师的真实成功正对照；实际成功、实际死亡及终态边界证据 | 此窗口在相同动作约束下可解，驱动和裁判的覆盖范围可核 |
| P2，另单学习 | 单片段、固定输入与预算的像素学习候选，保留学习前参照 | 仅对该片段的拟合结果；不作泛化或第一面声明 |
| P3，另单扩展 | 新开发祖先、相邻连续片段和自然抵达率 | 按实际完成的范围评估课程与分布差异 |

## 2. 开发窗和恢复入口

1. 数据管理员先分配本切片专用开发祖先，登记来源清单 SHA、独立对局根、曝光用途、阶段和接管帧。本切片不得使用 BC 的 heldout 祖先，也不得使用 PAIR 已分配的 8 个新开发祖先及其派生根。正式确认、适应保留家族继续原用途。一个根的分叉、切片和近重复前缀仍归同簇。
2. 优先使用现存干净、符合当前恢复契约的合法前缀。登记最后一个已执行的前缀帧、第一受控帧、最后历史哈希锚点、接管哈希、资源与阶段；用独立恢复核对。窗口资格按来源和脚本边界确定，不看候选成败后再挑容易窗。
3. 冒烟每条轨迹至多执行 **600 个受控游戏帧**。前缀重放、记忆预热和恢复核验另计成本，不能藏进“只跑 600 帧”。先以可机械核对的短片段查接线，再在冻结清单内扩至上限。段长、动作节拍和射击/bomb 约定随实施单冻结。
4. 若没有合法前缀，只回报首个冲突的决策号/实际帧、该处原始 mask 与契约、已有恢复路径和退出码。不得覆盖旧录像、强行忽略哈希不符或悄悄改恢复契约。重采或重录须另立工单；BC 离线复核和 PAIR 盘点继续推进，不等待本窗解阻。
5. 不预设需要新平台或 GL/PARK 改造。已有慢速逐帧路径如能保真恢复和读出像素，先用它量一个端到端真实切片的成本。吞吐经实测确为关键成本后，再独立评估加速。

## 3. actor、驱动和审计的输入边界

| 组件 | 允许读取 | 禁止作为策略反馈的内容 |
| --- | --- | --- |
| 像素 actor | 框内实际像素、由这些像素构造的帧栈/记忆、自己实际执行的动作历史 | 引擎玩家坐标、弹幕、资源、阶段、命中/死亡、真实 done、未来信息、教师动作和裁判结果 |
| 固定策略冒烟 | 同一输入接口；输出事前冻结的合法动作或动作表 | 根据审计真值、候选成败或 heldout 反馈改动作 |
| 独立审计/裁判 | 允许读取引擎真值、动作与帧日志，核对恢复、资源、终态和控制生效 | 回写 actor 观测、记忆、动作选择或学习 batch |
| 同约束教师正对照 | 明确登记的真实状态、相同动作库与动作节拍 | 将其轨迹或成绩并入像素轨迹，或据此宣称像素能力 |

真实资源只进入隔离审计；HUD 中可见的资源像素可以由 actor 或像素检测器读取。若需要驱动在引擎退出后停止，该信号单列为运行管理事件；不能因此声称整个训练/终止/重开流程满足严格像素要求。

第一批先冻结受控帧上限和合法环境停止条件，不学习、不选模。后续 P2 若使用真值回报或真值 done，必须标为特权训练诊断；只有奖励、终止、重开、样本选择和选模均满足原边界时，才允许提出严格像素学习声明。

输入依赖检查覆盖两层：静态列清 actor 实际调用与张量来源；离线保持像素和实际动作历史不变、扰动裁判资源/死亡/阶段等字段，核对 actor 输入摘要、记忆和输出不变。该检查验证隔离约束，不替代真实引擎轨迹。

## 4. 最小实施顺序与验收

### P0：把一窗的身份和动作约束钉住

实施单绑定主机、时间与时区、实际检出 HEAD/差异摘要、引擎和数据 SHA、前缀/恢复器/裁判/像素转换器身份、来源祖先、框选范围、像素尺寸与通道次序。动作库沿用当前已登记入口；先冻结每决策保持长度、focus、射击及 bomb 位约定，不同时改变动作空间和像素管线。

帧栈和记忆必须有明确起点：记录前缀末尾可用帧、burn-in 长度、填充方式、记忆重置条件和实际执行的前缀动作。不得把教师计划动作写成像素 actor 的实际历史；未生效或失败的输入也不能假记为已执行。每次独立恢复都重建同样的历史，不跨回合残留隐藏状态。

### P1：先走通一条真实像素轨迹

从一个已分配合法窗开始，用事前冻结策略生成动作。逐步保存逻辑帧/像素帧/决策号、像素摘要、actor 版本与读出方式、请求动作、实际执行 mask/保持帧数和独立终态。固定策略和学习权重候选分别编号；前者完成时报告“接线冒烟”，不报告“视觉策略有效”。

验收真实像素从正确帧进入 actor，动作作用于预定的后续帧，日志实际执行动作与历史一致；请求后合法死亡也保留为有效轨迹，不能仅为拿到满窗再重试。帧丢失、错位、恢复哈希不符、终态不明等记技术失败，报告首个差异位置。

独立恢复核对、真成功和真死亡均要各自登记实际尝试和帧预算。不能把同一成功录像多次解码算成多个真实引擎验收。现存真实记录可以补充边界解释，但标为历史来源；新进程复跑才标为本次实测。

### P1：同约束正对照与边界核对

在同一合法窗上至少取得一条**同动作库、同射击/bomb 约定、同保持长度**的教师真实成功轨迹。教师可用真值，报告独立 run ID 和输入范围。历史完整动作教师 100/100 不能直接充当本切片正对照。教师不能成功时先检查约束、恢复和任务可解性；保留像素接线已核实部分，不把缺正对照写成视觉模型失败。

边界证据覆盖正常运行/完整满窗、临界死亡/末帧死亡、合法转场以及 unknown/技术故障。每项标注为本次真实轨迹、历史真实记录或离线边界用例。末帧死亡记失败；提前合法转场单列，不填作完整无死亡满窗；终态未知保留未知。离线边界测试可验证计分实现，不能填补缺失的真实成功或真实死亡。

### P2：再申请单片段可拟合学习实验

仅在 P1 的输入、执行、恢复与计分可核后，为一个像素学习候选另开实施单，冻结训练祖先、初始化、像素栈/记忆、动作空间、奖励与终止来源、交互帧/更新上限和选模规则。先问同一个真实片段能否学会，再考虑多窗、BC 初始化和三训练种子。完整保留固定策略或学习前权重参照及全部失败尝试。

单片段可拟合只支持局部可行性。单片段学不会时先按像素时序、可见性、动作接线、目标和优化依次诊断；已能拟合而新祖先失败时，才优先研究泛化、记忆或课程。P2 的预算和结果不得倒填成 P1 的接线验收。

## 5. WP06 的并行最小切片

原规格明确 WP06 在 WP01 条件满足后独立推进，不等待 G410-2：见 [v4.1.0 依赖与 WP06](../v4.1.0/README.md)。本版按此安排；完整像素 RL 仍需对应依赖门。

从已登记开发材料切一个保留 HUD 的真实连续流，先让 HUD 资源读数、像素玩家定位、死亡/终局状态机各自给出可检查输出。数据管理员同样先排除 BC heldout、PAIR 新开发祖先与确认家族。先用已有材料，新增采集或标注另单登记。

| 子切片 | 最小记录 | 当前验收边界 |
| --- | --- | --- |
| HUD/资源 | 正常读数、真实资源变化、遮挡、unknown；像素预测与隔离真值对照 | 原始分母、误读与未知可定位；真值不得纠正在线像素读数 |
| 玩家定位 | 正常、自机消失/临界死亡、重生/转场，定位或 unknown 及像素叠图 | 误差与未知逐状态报告；若用于局部裁剪，裁剪中心只能来自像素定位 |
| 死亡/终局 | 连续状态序列，首次可见证据、引擎边沿、预测边沿及 unknown | 区分 alive、hit_pending、respawn、stage_transition、game_over、menu、unknown 或等价语义；不把 unknown 当零资源/死亡 |

这些输出先用于开发与审计。少量片段不能改写 G410-3：完整连续流、事件精确/召回与延迟、资源准确性、长流误报、像素终止重开仍需原门单独验收。HUD/定位/事件切片也不以 P2 学会或 G1/T2 分胜负为前提。

## 6. 成本登记与收束路由

每条轨迹的受控上限为 600 游戏帧；所有独立恢复、额外真成功/真死亡、教师尝试、输入边界重放和技术重试单列。先量一条慢路真实轨迹，再根据实测决定后续批次，不在本计划内默许无限重试、重采或训练。

回执至少给出：计划/实际/有效轨迹数、恢复次数、技术失败与合法失败数；前缀/预热/受控游戏帧；启动、恢复、渲染与读回、actor、发键/步进、审计、I/O 的墙钟；端到端总耗时及每小时有效轨迹。多于一条时报告可支持的分位数和样本数；只有一条不估 P90/P95。学习预算、状态读取的额外成本和 Windows 零售验证另列。

| 状态 | 判据 | 后续路由 |
| --- | --- | --- |
| 接线通过 | 有完整真实像素轨迹，恢复/帧序/实际动作可核，终态明确，输入隔离检查通过 | 单独报告教师正对照与真实死亡覆盖；齐备后可提名 P2 的小学习实施单 |
| 接线失败 | 首个恢复、像素时序、动作生效或历史冲突可复现 | 在新版本实现范围内定位修复，保留原记录；BC/PAIR 独立推进 |
| 正对照失败 | 同约束教师没有真实成功，或仅有不同动作约束的历史成功 | 先查可解性/动作契约，不归咎像素学习；报告接线已取得部分 |
| 待证 | 无合法前缀、缺真实成功/死亡、身份或终态不明 | 回报具体文件/帧/错误、可独立推进项和最小补证；重采/更改契约另工单 |
| 单片段拟合通过/失败 | P2 另单按固定预算取得实际学习结果 | 只记录该片段及其训练身份；另定多祖先与连续课程实验 |
