# V830-PAIR-01｜G1 与 T2 的新起点配对试点协议

**第二稿状态：条件备选，不在当前排程。** 按 [路线方向决策](ROUTE_DECISION.md)，G1/T2 先作为冻结参照；仅当同任务路线判别定位到资源调度确为相关限制，并另发受限实施单后，才启用本比较。下文保留科学协议，上一稿的 8 祖先、96 回合及 30/40 秒预算不自动继承为当前任务；启用时须重新核定独立用途、成本与规模。当前先完成路线设计，不以规则排名替代反馈价值和像素学习的验证。

**2026-11-24，研究端预注册设计，待训练端回执与最终冻结。** 问题是在 TH08 第一面 Normal 的新开发微段上，同一冻结移动头配 G1 或 T2，哪种放雷规则更常无死亡活满 900 决策（30 秒）？本协议继承 [v8.29 配对设计](../v8.29.0/PREREGISTRATION_PAIR_001.md)，将 30 秒主批与 40 秒可选扩展分别排期。路线设计完成后的信息模板见 [V830-ROUTE-INFO-01](TRAINING_HOST_REQUEST.md)，当前尚未转交执行；本文件不自动授权开发、启动引擎或评测。WP05 继续暂停。

## 1. 单一主比较与冻结行为

| 项 | 约定 |
| --- | --- |
| 主比较 | 同起点、同 checkpoint、同配对策略 RNG、同 900 决策预算，G1 与 T2 无死亡满段差 Δ30 |
| G1 | B 为当前库存，R 为本档预算减已执行决策数。B=3/2/1 时 base=35/15/3 px，`thr = clip(base * sqrt(R/(max(B,1)*200)), 5, 120)`。从接管首步就用本档预算 |
| T2 | B=3/2/1 时固定 40/20/5 px，两时长用同一常数 |
| 触发 | 同一 `nearest_all_px` 度量，存在距离且严格小于本臂阈值才请求；两份旧实现 B=0 或 B>3 时均不请求。保留这一语义，不把 >3 偷换成 3 |
| 移动头 | 原 `bombdag.pt` 的 seed0/1/2 三个冻结 checkpoint，分别完整 SHA 绑定；18 个候选各取两 bomb logits 的最大值，温度 1.0 softmax，`torch.multinomial` 每决策抽一次。两臂都采用该读出，不混用学习轮的 argmax |
| 动作与输入 | 相同引擎/游戏数据/特征/候选映射，射击常开、focus 和两帧保持相同；只在决策首帧带 bomb 位，第二帧保持移动且清 bomb 位。两臂唯一变量为外置放雷规则 |
| 随机流 | 每个（祖先、预算、checkpoint、重复号）预分配唯一策略 RNG 种子；每臂重置同状态生成器，不跨回合消费。候选策略 RNG 与清单抽样、臂顺序、程序初始化流分离；记录 PyTorch/设备、初始状态摘要和抽样次数 |

同流只保证两臂在相同分布输入下共用随机数；状态分叉后可抽到不同动作，不强制把另一臂动作回放过来。旧历史按进程跨窗跨局消费一个流，故本版 RNG 协议单独编号。30/40 秒从同一接管状态**各自恢复并独立开跑**；G1 的阈值从首步已随预算改变，40 秒不能由 30 秒幸存轨迹续跑或只挑幸存局。

G1 使用预先知道的微段剩余预算；本试点比较的是有这项输入的特权微段控制器，不等于自然整面部署。整面预算来源、像素观测边界和 G410 正式验收另立协议。[历史 G1](../../../../tools/rl/v8r0_urgency.py) · [历史 T2](../../../../tools/rl/v8o0_ruletight.py)

## 2. 祖先供给、切分和盲于成败的抽样

1. 目标 **8 个未曝光开发祖先，道中4、Boss4，每个独立对局根仅选一个起点**。同根的相邻切片、不同分支和派生录像归一簇。`game_seed`、`training_seed`、`policy_rng`、录像名不能替代祖先身份。用来源、实际消费的有序前缀和接管锚点核对谱系；引擎 SHA 或整录像 SHA 不足以单独证明独立。
2. 先通过 INFO 的全部来源清单登记供给，再按祖先预留互斥用途：本配对开发、BC 修正学习开发、像素训练/开发、后续独立确认。**本配对所选祖先不能先被 BC/像素实验曝光，也不能在结果出现后改充确认根。** 离线 BC 探针只用旧的已曝光材料。排除历史训练窗13–16、开发窗11/12/17/18及其派生根，并核对其他教师/训练/选参曝光。未知谱系先隔离。
3. 沿 [splits.json](../../../../configs/v430/splits.json) 与登记谱系检查用途。保留60000–60199、61000–61499及已登记适应/确认家族原用途；不读取封存策略结果，不擅自把确认集划作本次开发。阶段、祖先与帧边界沿 [v4.4 实验协议](../v4.4.0/EXPERIMENT_PROTOCOL.md)。
4. 在看任何新策略结果前冻结阶段判据、全部来源及 SHA、入选资格和排除原因。只按既有前缀/脚本阶段元数据判断可校验接管、初始库存3颗、预计可容纳主档1800帧；40秒扩展另检查2400帧资格。资格判断不得依赖 G1/T2、教师或其他控制器在该新起点的成败。已知接管后很快合法转场的段不事后换窗。
5. 抽样算法先从仅具单一阶段资格的祖先中按预公布随机种子排序，各阶段最多4根；再按同一原则从兼具两阶段资格者补道中、Boss缺额，每选一根即从两表移除。每根有多个合格窗时，同样固定种子均匀选一窗。登记算法、种子、每层供给数、排序和选中前缀摘要、与自然阶段频率的差别。不足4+4时在看新结果前明确缩减探索范围或补来源，不能跑后替换失败阶段。

30秒主批不以40秒资格为必要条件。若未来选中的8根中有人没有2400帧资格，40秒须在**任何新策略结果可见前**冻结其可支持的范围；不足8祖先只报探索数据，不能套用完整8祖先的提名门，也不能看完30秒后另挑“适合40秒”的幸存祖先。

## 3. 分阶段工作量与最终清单

| 批次 | 计划配对 | 单臂回合 | 每回合受控帧 | 全满段时计划受控帧 |
| --- | ---: | ---: | ---: | ---: |
| **先执行：30秒主批** | 8祖先 × 3 checkpoint × 2 RNG = **48对** | **96** | 900决策×2=1800 | **172,800** |
| **单独决定：40秒扩展** | 同样最多48对 | 最多96 | 1200决策×2=2400 | **230,400** |

早死时实际帧少于上表；前缀恢复、旧窗冒烟和保留记录的技术重试另计。游戏帧预算不是墙钟。根据 INFO 的真实资源、逐局中位/P90、恢复开销和剩余可用时段先保证8祖先主批；不强制两档都跑。40秒是否执行及规模须在该批任何策略结果可见前单独冻结，不根据其部分胜率停止或补窗。若两批均完整，合计96对、192单臂回合、403,200计划受控帧，不能把这个可选总数写成首轮硬门。

每祖先的3 checkpoint×2 RNG是嵌套重复，独立单位始终是祖先。两臂先后次序用单独随机流平衡交错，运行清单预先固定。冻结表须包含 run ID、主机/时区、实际代码HEAD与脏文件摘要、引擎/数据/三权重/适配器/计分器SHA、祖先用途与来源表、最后已执行前缀帧/第一受控帧、最后历史锚点/接管哈希、每pair策略RNG、两臂顺序、预算、资源限额、协议摘要。

研究端收到 INFO 后先冻结抽样和预算设计，经用户转交**单独实施工单**。训练端完成获准适配与旧窗冒烟后、在任何新开发窗产生策略结果前，冻结最终实际清单。身份、源数据、计分或抽样规则变更须换清单版本，保留变更前材料并登记已看过哪些结果。

## 4. 后续实施与门禁（当前均未执行）

未来入口拟为 `tools/rl/v8_30.py paired-eval`，**尚未实现**。它不是当前可运行命令；本只读工单既不创建该入口，也不授权调用历史 runner 开新实验。实施工单下达后才按白名单新增适配器、配置与测试。已有 runner 的四旧窗/PARK限制、恢复/split guard与计分语义保留，不绕过旧限制强塞新窗。

实施切片按顺序验收：

1. 核对恢复入口和 split guard 支持新开发用途；先在已曝光旧窗完成历史D3五项门。每新起点按自己的参考前缀恢复，登记最后已执行帧与第一受控帧；两次独立恢复核对接管哈希、资源和阶段。旧8663帧只作历史桥接，不硬编码成新起点。
2. 先一个旧窗、一个checkpoint、一条配对流冒烟；比对同输入下的阈值、随机抽样和送出mask，检查每决策一次采样、两帧动作、无bomb续帧、音频、库存及故障回收。记录首个差异帧，无论胜负均保留。
3. 用已有真实边界记录加离线边界测试核对正常满段、末帧死亡、提前转场、技术中断计分，明确两类证据各自来源。测试通过只证明软件边界，不构成新起点能力。
4. 用实际启动/恢复/旧窗逐局时间更新墙钟预算，在任何新窗结果前冻结运行表。各工作进程独有tag、新输出目录，拒绝覆盖旧运行和暂停快照。新资产及SHA按资产册登记；仅回传小表、身份和命令，资产留训练端。

## 5. 计分、库存与故障

满段须完整执行本档1800/2400帧、帧序正确且截至最后一帧无死亡；最后一帧死亡记0。预算前可核实的合法转场/过面单列事件，本微段满段指标记0，两臂均报告次数。合法输赢占原位置，不重跑挑结果。

无法恢复、帧丢失、引擎报错或终态不明记技术无效。每个pair技术故障**至多按同起点、同随机流、同配置重跑双方一次**；原两臂和重试记录都保留，不覆盖。仍未判定的pair留在清单分母，报告计划/有效/重试/待判数及待判全部偏向G1/T2时Δ上下界；不能临时换根。未收齐主批时仅报阶段性结果，不触发完整提名门。

逐实际帧记录库存前后值、决策号和游戏事件；分开发出请求、引擎忽略、实际扣库存、补给与掉命重置。段内合法补给使B>3时沿原实现不请求并继续计分、单列事件，不能偷偷裁库存或剔除此局。无法区分异常和补给而影响有效性时保留pair进入待判界限。

对每颗雷报真正扣库存决策/帧；耗尽后存活帧在幸存局段尾截断，死亡局与幸存局分别列。历史仅有请求步和相邻请求前库存时，只报可推断区间；除非能唯一归属并排除补给/重置，不把“末次请求”改名“末次扣雷”。另报带雷死亡、B>3补给、候选动作种类数和抽样次数。

## 6. 祖先等权分析与研发取舍

每个祖先分别列：同满、仅G1满、仅T2满、同未满四格。完整时每祖先6对，差值 `d_i=(仅G1满−仅T2满)/6`；Δ30为8个祖先差值的等权平均。报告两臂绝对满段率、Δ30、正/平/负祖先数、按阶段和三checkpoint的结果，以及删去任一祖先的Δ范围。不能把48对或96个回合说成48/96个独立祖先。待判界按原计划每祖先6对计算，不丢失整根或用有效回合数任意重权。

| 完整30秒主批结果 | 研发决策 |
| --- | --- |
| Δ30≥+5个百分点，且至少5/8祖先为正 | **仅提名G1**进入另一批全新祖先的独立复验；不据此宣称泛化、显著优越或整面可用 |
| Δ30≤−5个百分点，且至少5/8祖先为负 | 保留T2作默认参照，按阶段/真实扣雷/耗尽后失守定位G1弱点 |
| 其余完整结果 | 差异未定，保留T2这一简单参照；看祖先集中度与不一致胜负，再决定补新根或另立机制假设 |
| 祖先不足、身份/计分缺证、主批不完整 | 报实际范围、待判界及缺口；不触发上面8祖先门，不事后缩分母造成通过 |

40秒另报Δ40及绝对满段率；只有其完整8祖先批满足Δ40≥+5个百分点且5/8为正时，才同时提名40秒复验，始终列为次要终点。30秒提名不自动成立于40秒。5pp和5/8是预算取舍门槛，不是统计确认或非劣性门。

研究端不从跨版本池化Fisher或本批回合池化p值宣称新祖先泛化、等效或“资源分配学会了”。独立确认另编号，事先冻结一个主比较、新祖先清单、配对/簇级检验和区间；用试点不一致率与祖先变异估算功效和所需根数。供给或预算不足时报告可支持范围。G1/T2始终是外置手写规则，本试点也不替代像素B/C和G410正式门。
