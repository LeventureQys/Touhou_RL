# 路线先行的下一步工作计划

2026-11-24，v8.30.0 第二稿。工作顺序以 [路线决策](ROUTE_DECISION.md) 为准：先完成研究端方向取舍，再为一个真实任务族核实最少输入，随后用小规模实验区分可解性、反馈、像素观测和学习问题。上一稿 W00–W05 的排程已撤出近期计划；本次不派发训练或批量确认，WP05 保持暂停。

GPT 研究端负责路线、协议与离线复核，DeepSeek 训练端负责实际主机上的执行，用户转交工单与回执。训练端主代理监督范围和验收，实际执行交给 Provider=DeepSeek、模型=DeepSeek v4.1 flash 的子代理。

## R0 路线设计与当前结论

本次已完成 R0 的研究端设计审查：将真实任务中的像素闭环学习选为主线；将 BC 损失修正、反事实标签和 G1/T2 排名降为辅助或条件性分支。依据与竞争解释见 [路线决策](ROUTE_DECISION.md)。这项完成只表示研究问题和投入顺序已经调整，不表示新方法已被实验验证。

后续首个问题是：在同一真实短攻击任务族中，合法控制能否完成任务，现场反馈是否具有控制价值，像素学习候选能否获得相对学习前与强参照的实际改善。R0 不指定某个优化器必胜，也不要求先训练出能通关的特权学生。

## R1 冻结真实任务与最少输入

R0 设计复核后，首张可供用户转交的工单为 [V830-ROUTE-INFO-01](TRAINING_HOST_REQUEST.md)。本次尚未转发，也未取得该路线定向工单的回执。已同步的 [v8.29 评审包及历史回执](../v8.29.0/RESEARCH_REVIEW_PACKET.md) 优先复用，只补首个路线判别任务所缺的材料，不做全面旧资产盘点，不运行引擎或训练。

| 所需信息 | 研究端据此作出的决定 |
| --- | --- |
| 一个真实短攻击任务族的来源、阶段起止事件、接管与资源语义 | 主目标是否对应实际阶段完成，能否以已有入口恢复和计分 |
| 同动作库、保持长度、射击与 bomb 约定下的真实成功/失败见证 | 任务可解性是否有依据；缺失动作会不会把任务人为变成无解 |
| 对齐像素、实际执行动作历史、关键事件可见性与恢复能力 | 像素 actor 输入能否重建，是否存在时序、历史或特权泄漏问题 |
| 可用教师/状态控制器、可部署固定/开环参照、像素候选的现况 | 首批能比较哪些臂，哪些旧模型无需追索或重建 |
| 少量训练与开发祖先的来源、曝光和用途 | 能否先做开发探索，如何避免把同根切片冒充独立样本 |
| 一个端到端切片的恢复、渲染、控制成本与可用时段 | 首个实验的受控帧、含恢复墙钟与磁盘上限怎样冻结 |

研究端收到最少回执后，把任务目标、动作/观测契约、实际源码和数据身份、训练/开发用途、对照构造及资源上限写入一份具体实施单。任务选择先使用训练材料和脚本元数据，不看新开发候选成绩筛容易窗。优先复用既有可信入口，只补本任务所需薄适配。

主指标应对应真实阶段完成、合法任务事件及资源后果。首死与固定时域存活另报诊断；正常第一面允许使用残机和资源，不能把一次死亡直接等同整面失败。任务资格和截断上限须提前定义，不能看结果后修改成功含义。

先用训练侧已有成功/失败记录检查完成事件是否只是自动转场、动作能否改变后果，以及小预算内能否出现有效区分信号。任务回报过稀疏时先查起点、可解范围与探索支持；阶段转场本身不证明反馈价值，也不默认密集奖励能解决问题。

## R2 同任务上的路线判别

R2 可以把可解性、像素接线和小规模学习放进同一个开发切片并行实施；相同任务、动作节拍、资源和计分必须一致。小学习后冻结候选，再检验反馈价值，不以旧 A 或特权臂先证明反馈收益作为像素学习前提。先测一个端到端回合的真实成本，再冻结学习与评测规模，撤销上一稿预排的固定 96 局或 60 回合额度。

| 子问题 | 必须交付的证据 | 未成立时的处理 |
| --- | --- | --- |
| 同约束任务可解 | 一个可核验的成功见证及动作、帧序、阶段/资源事件；正对照与像素臂分开编号 | 先查动作约束、任务和驱动。禁 bomb 的缩减任务失败不能否定允许 bomb 的完整任务 |
| 像素控制链可运行 | 真实像素进入 actor、实际动作生效、历史/记忆正确、终态可独立重算 | 定位首个恢复、旧画面、帧栈、动作历史或终态冲突；固定策略发键只结算接线 |
| 学习带来任务改善 | 同评测安排下的学习前后像素候选、训练选定强参照、实际任务结果与全部分母 | loss 下降或单片段拟合不足以证明控制收益；先区分目标、观测、覆盖和优化问题 |
| 现场反馈具有控制价值 | 闭环与合法冻结固定/开环参照的同任务对照，记录动作表来源、质量和差异 | 参照已解释全部成绩时，检查任务族和对照质量，不扩确认弱假设 |

开环表只能从独立训练供体生成并在目标局前冻结，不回放目标闭环成功局来制造对照。应核对动作频率、持续时长和采样安排，避免把劣质拼接序列的失败当成反馈价值。固定动作通过个别窗不使任务无效；比较对象是整个任务族，不要求每个评估窗全部固定动作死亡。

像素 actor 只读取框内画面和自身实际执行历史。特权教师、状态控制器、训练期回报/价值估计或辅助标签均单列用途。使用特权距离/库存放雷的 live/open 对照，只能解释该规则条件下的移动反馈，不能标为像素端到端控制。允许特权训练的像素执行研究可以先推进；严格像素回报、终局和重开另按 WP06/G410-3 验收。

首个单 seed 是接线、优化与可行性观察。若要报告复训稳定性，再安排多个训练 seed；若要报告新祖先的确认性收益，再使用另一批全新祖先。状态臂成功而像素臂失败时，观测、历史/记忆、表示和优化仍是竞争解释，不能直接判定像素不可观察。

## R3 未见祖先与阶段

局部任务出现可复现学习信号后，冻结候选与训练程序，在未参与拟合和选参的开发祖先上检验。逐祖先、逐阶段报告学习前后和强参照结果，不以增加同窗 RNG 代替新增独立对局根。

训练窗有效、未见起点失败时，先研究任务覆盖、学生来访状态和记忆需求，不立即投入整面长训。若独立供给不足，报告条件性开发观察和实际分母；不挪用封存或保留家族补数。正式确认另编号，不把本阶段开发集事后改称确认集。

## R4 连续资源与自然来访状态

在相邻真实阶段连续执行，资源与记忆自然继承；逐步提前接管，记录到达入口的比例、到达后完成率、资源消耗和最早失效位置。恢复短段有效而串联失败时，针对接缝和学生来访状态训练，不在每段补足资源来掩盖问题。

一旦有可运行像素候选，就可提前做少量自然开局开发诊断，定位第一处失效；这项诊断不等待所有短窗优化完成，也不消耗正式确认集。已知剩余微段预算、固定三颗雷和库存超过三颗的旧规则语义，不能直接移植为自然第一面的默认假设。

HUD、自机定位、死亡/终局按任务所需最小范围推进。其开发输出可帮助定位问题，完整严格像素回报与重开能力仍按原门独立证明。

## R5 原正式能力确认

自然第一面开发候选达到原提名条件后，冻结模型、观测、动作、计分、数据和运行身份，再进入 [G410 原验收](../v4.1.0/README.md)：S1N 新确认 100 局，过关点估计至少 50%、Wilson 95% 下界至少 35%；另有至少 20 局 Windows 零售复验，点估计保留不低于 harness 的 70%，并报告区间。

第一面、严格像素自我改进、完整作品和跨作品适应分别结算。R0 设计复核、R2 接线或小任务学习成功均不把能力门改为通过。

## 后续实施单必须写明的内容

研究端为已选定的最小任务编写具体工单，经用户转交后由训练端执行。每单必须给出：唯一研究问题和目标；实际输入及身份；精确文件修改白名单与新输出路径；可复制的实现/验收命令；受控游戏帧、更新机会、含前缀恢复的墙钟和磁盘上限；真实正负结果、技术无效与未判定的处理；每种结果对应的下一项路线决策。

依赖实际成本和材料的数值在派工前冻结，不在观察结果后调整。验证预算时区分相同回合/更新机会与相同实际交互帧；早死导致的帧差应如实报告。软件回归、真实引擎测量和能力结论分别列证据，退出码不能单独代替验收。

训练端按项目协作规则保护旧数据、引擎、checkpoint、既有证据和暂停快照；新资产在本机新路径创建并登记 `ASSET_SYNC.md` 与 `ASSET_SYNC.sha256`，只回传小表、摘要和必要边界样例。禁止越包改协议/ABI、依赖或第三方，不删除、覆盖、提交或上传资产。任务完成或遇阻立即返回命令、退出码、计划/有效/合法失败/技术无效/缺失分母、产物身份及下一步。
