# v4.2.0 第一面像素控制与学习闭环计划

日期：2026-11-13，Asia/Shanghai。对象：项目负责人、主代理与远端执行代理。

**状态：计划已制定，尚未执行。远端 v4.1.0 训练保持 paused。** 本次仅新增版本计划和首轮任务单，不恢复采集，不运行训练，不改变旧状态、资产或验收结论。以后明确派发“执行 v4.2.0”时，才在本版本新目录启动工作。

v4.2.0 的重点是把已有引擎、数据和 checkpoint 接成可解释的学习闭环：先核对时间与动作，再检验教师目标是否有用，区分视觉、监督与状态覆盖的问题，同时提前开展引擎回报 RL 诊断。近期能力目标是 TH08 Normal 第一面像素部署；完整一周目、严格像素自我改进和跨作品迁移继续作为后续目标。

## 3 对 v4.1.0 的执行顺序调整

1. 把 2 帧部署与 4 帧采集、真实执行历史的一致性列为首要技术门。既有 S1 的 passed 不替代该核查。

3. 在少量真实失败状态上验证多个首动作及其后续控制，先建立有分辨力的监督，再扩大标注。
4. 从记录“完成多少版本、重复多少 epoch”改为记录“新增多少自主状态、纠正了什么失败、独立闭环是否改善”。

## 5 工作包规格

### WP420-00 远端接管与固定参照

目标：恢复一个可重复运行的已知学生，以及它实际使用的数据、源码和控制路径。

在资产主机按明确路径读取清单，核验两个引擎、B0、5k/20k、classweight/tiebreak 的身份，恢复原 argv、split、配置和逐局记录。大数据只核验 manifest 与本轮实际读取的 shard，不全盘扫描或重复复制 30 GB。

用原 evaluator、原设备设置和原观测窗口，对 B0 与 20k 各跑 3 个已使用开发 seed，重复一次。核对原有帧数和已保存的动作信息；为新运行记录完整观测与动作 trace。tiebreak 若有已完成报告，直接重新汇总，不盲目重训。

验收：6 组重复对照可解释、无未知源码依赖；一次真实结论能从逐局记录复算。旧快照与实际暂停状态不一致时，在 v4.2.0 新记录中说明，不修改 v4.1.0 state、journal、budget。

### WP420-01 时间与动作契约

目标：让一条训练样本与一次部署决策具有相同的时刻、历史和作用时长。

新契约命名为 obs-v420-2f 与 action-v420-2f。默认每 2 个逻辑帧决策，18 个移动/聚焦候选，bomb 独立，保留开火与释放规则。旧 B0 没有可用 bomb 策略时明确固定为 0，不能用隐藏事件替它按 bomb。

逐项记录与核对：

- 绝对逻辑帧、最后实际可见画面帧、决策点、按键发送与生效帧、实际持续长度。
- 四个连续画面帧的真实时间戳；不以跨决策帧伪装连续帧。
- 过去 8 个已实际执行的 2 帧动作，不使用教师“建议动作”替代学生实际动作，不混入当前或未来动作。
- 同一 4 帧教师块中两个子动作分别是什么；原始标签是否只覆盖第一个槽。
- 冷启动、接管、死亡、换面、截断与重开时的历史和记忆边界。

新 S1 数据每个 2 帧决策槽都要有对应标签。可用原掩码重放并在缺失槽重新查询教师；仅复制上一条标签、插值 logits、把一条计成两条均不成立。原 4 帧数据保留，只作为明确标注的历史样本或经核验的子集。

先做 3 个训练 seed、每个 2 次重放、每次至少 2,000 帧的切片。主进程、分支和像素重建必须对应同一状态；动作历史逐槽与实际掩码一致。再通过同一冻结模型比较离线与在线前向：相同设备、相同输入的动作必须可复现；跨设备数值差异单列处理。

G420-0 要求所有已消费样本的时间/动作索引一致，HASH 重建零未解释差异，部署输入边界测试通过。8 px 的几何模型容差不能替代精确的时间和输入一致性。

### WP420-02 候选动作与后续控制验证

目标：把“教师选了什么”转成“在什么后续控制下，该动作产生什么结果”。

从至少 10 条训练祖先轨迹选 1,000 个分层状态，覆盖普通状态、旧模型首次死亡前 0.5–5 秒、低余量、贴边、并列动作、资源操作和面过渡。相邻帧先聚类，不能用同一死亡前的一串近重复帧充满集合。split 按祖先冻结。

先用 20 个状态测成本，再对预注册的 200 个状态验证全部 18 个首动作：

1. 用原始前缀掩码重放至同一状态，核验 HASH，park 后分别 fork。
2. 仅先执行候选动作 2 帧；此后使用同一固定版本的教师规则续行。
3. 默认总验证长度 H=120 游戏帧，记录逐帧死亡、资源、进度和终止。先测 H=32 作为既有短视界参照，不把短视界存活直接当长期 Q 值。
4. 分别记“查询过”“执行完整”“引擎死亡”“引擎存活”“未知”，保存完整后续动作。真实分支的结果不依赖几何分数是否打平。
5. 在其中 50 个失败相关状态上，额外比较候选首动作之后由冻结学生续行的结果，至少覆盖教师动作、学生动作和一个已验证替代动作。

分支运行到 H，或事前定义的首次死亡、局部过面终止；达到这些终止条件是有效完成，死亡分支记已验证死亡。超时、缺帧或进程故障造成的提前停止记 unknown。这里的短分支终止不改变标准 S1N 允许正常残机继续的规则。

这里得到的是“固定教师续行下的有限视界代价”，不是最优 Q，也不是该首动作无条件安全。若教师续行安全、学生续行失败，优先查后续控制和状态覆盖。若教师也不能恢复，先修恢复策略或提前介入，不能继续用无解状态强迫模仿。

教师不得依赖学生不可见的 PLAYER_HIT 反射来制造“视觉可学”结论。预防式 bomb 与隐藏 death-bomb 分开诊断。原 8 px 阈值只描述几何预测误差；精确引擎分支、像素与动作时间分别核对。

并列处理规则：

- 几何打平不能自动组成安全集合；只有真实验证结果可以进入集合。
- 全部动作都存活的状态可用于普通 BC，但不给“区分危险”的任务虚构信息量。
- 安全集合为空、不完整或后续执行失败的状态不补造正例，明确记录对应原因。
- 对目标诊断至少保留 100 个“安全集合非空且不是全部 18 动作”的有效状态；数量不足先补有信息的状态，不能改变分母让门通过。

G420-1 是标签有效性门：200 个全候选状态有完整来源和验证结果，含至少 100 个上述有效状态，重复分支一致。它不要求 idle 比例下降，也不要求教师分数必须唯一。

### WP420-03 受控学习与视觉输入诊断

目标：在少量可判别实验中找到可继续的学习配方。

先复用现有约 73 万参数的空间模型。固定正确的 2 帧数据、split、batch、更新数、教师和部署节拍，做以下对照：

| 臂 | 输入 | 学习目标 | 要检验的内容 |
| --- | --- | --- | --- |
| A0 | 像素与实际动作历史 | chosen 动作 CE | 正确时间契约下的 BC 参照 |
| A1 | 与 A0 相同 | 普通 BC 加真实分支的安全集合/代价监督 | 有信息的目标是否改善闭环 |
| A2 | 当前特权状态与历史 | 与 A1 相同 | 目标与优化链能否在较易的表示上工作；仅作诊断 |

A2 复用已有实体表征可覆盖的当前自机、致死物位置/速度/判定、敌人与资源。不得偷用未来 tape、未来动作或 episode 结果作为输入。必须记录特征是否完整；A2 与像素模型的编码器不同，因此它是定位工具，不是“仅输入变量改变”的严格因果结论。A2 失败也不能单凭一次试验否定视觉。

A1 的集合损失仅在完整候选验证且安全集合非空的状态上使用。例如 L_set = -log Σ[a∈S]π(a|history)。全部 18 动作都安全时该项为零；未知不能被补成死亡。若试用代价回归，只监督实际验证动作，代价与续行版本显式入模。首轮固定一个集合配方，至多一个替代配方，不同时扫描大量温度、权重和模型。

学习检查分三层：

1. 在 256 个训练状态上故意过拟合。报告 proper safe-set 内的动作率、代价误差和训练/留出指标；不能只报多数类 top-1。
2. 在 10 个教师可解、旧学生会失败的固定训练微段上检查闭环。片段长 3–10 秒，目标至少 9/10 完成。该结果只证明能学会小片段，不计为泛化。
3. 使用整段 S1N 和 DIAG-FIRST-DEATH 两种开发套件检查泛化、恢复与失败形态。

A0/A1 先以 seed 0、5,000 步筛查，曲线健康时按相同规则扩到 20,000 步；有闭环信号的配方再用训练 seeds 0/1/2 复验。累计训练 top-1、末窗口拟合和留出指标分开。

如果 A2 能学、像素臂不能学，再单独测试一项输入变化：全局 192×224（宽×高）、RGB、或像素定位的局部高分辨率窗。确有历史别名时再测 GRU，按真实序列、burn-in 与截断反传训练。每次只加一个因素，最多两个表示替代分支。像素定位器失败不能用真值中心替代部署输入。

G420-2 记录微段学习与受控开发结果。正向继续条件是至少 2/3 训练运行改善游戏指标，并且安全相关错误没有被多数类指标掩盖。只有离线改善时，优先回 WP420-02 查首次错误，不继续无界加步数。

### WP420-04 学生自主访问与恢复课程

目标：验证纠正监督能否改善新学生实际访问的状态。

保留旧 round1/2/3，只把时间与目标已校正的部分接入新训练。后续采集进入全新的 v420 run，不直接续写暂停的 round3。

首轮最多三轮，每轮先采 5,000 个决策检查分布，再扩到 25,000：

| 轮次 | 教师执行概率 β | 主要作用 |
| --- | --- | --- |
| D1 | 0.25 | 从当前候选的错误区域过渡，保留干预记录 |
| D2 | 0 | 教师只标注，不替学生执行 |
| D3 | 0 | 用更新后的学生再验证一次分布改善 |

D2/D3 的 β=0 自主决策累计目标至少 50,000。无法达到独立状态覆盖时如实报告，不通过重复相同轨迹凑数。每轮冻结并登记实际 rollout checkpoint，采集学生与训练后学生分别记录。

起点按决策量目标分为自然开局 50%、真实教师中后段 30%、上一轮失败前状态 20%。后两类属于训练课程；β=0 从课程起点运行不等于自然开局过关。标准能力评测始终自然开局。

聚合采样固定为当前轮 50%、最近历史轮 30%、固定 BC 20%，不能只用最新轮覆盖全部历史。危险状态依据真实死亡距离或分支结果加权，最高 5 倍；不把“非 idle”当作危险定义。比例不同时记实际值，缺少某一来源时先声明 bootstrap 配方。

按祖先和失败类型报告新覆盖、标签纠正率、真实干预、最早失败帧、动作与位置轨迹、资源、恢复成功率和整面结果。强制换向可作单独的探索实验，不能混入 β=0 后仍称自主策略。

G420-3 要求上述自主访问、谱系、标签和每轮评测完整。三轮之后若仍无整面过关、开发首死相对 A0 改善不足 30%，结束当前配方，转已登记的标签/输入或 RL 分支；这不是项目停止条件。

### WP420-05 提前开展引擎回报 RL 诊断

目标：在可靠反馈下检验像素策略能否通过 RL 改善，而不把事件识别误差与控制学习混在一起。

本工作包只依赖 G420-0 和与新时间契约一致的可加载像素初始化，不等待正式 BC 过关或 G410-3。优先复用 PPO 和现有环境，替换必要的时间/终止连接层，不先迁移算法库。旧模型的输入适配属于显式新实验，不能绕过冻结 digest 后直接称原模型初始化。

| 臂 | 观测 | 反馈与重开 | 声明范围 |
| --- | --- | --- | --- |
| R0 | 像素与自身历史 | 冻结策略，仅评测 | 初始参照 |
| R2 | 与 R0 相同 | 引擎真值奖励、终止与重开 | 训练期特权诊断 |
| R1 后续 | 像素与自身历史 | 经对应范围验证的像素事件、终止与重开 | 严格像素自我改进 |

先检查零次更新的 argmax 与随机采样行为、初始 logits、联合 log_prob、PPO ratio、GAE、reward 单位和 truncation bootstrap。实际 death 与 game_over 分开，正常第一面训练不把首死当作整局终止。初始策略采样已经退化时先处理分布与 KL 锚，不靠加长训练掩盖起点差异。

critic 先预热，冻结 actor 及其共享特征；记录预热后 logits 是否仍一致。actor 初始学习率建议 3e-5、critic 3e-4、clip 0.2、梯度裁剪 0.5，熵系数从 0 或 0.001 中按训练切片事前冻结一个，记录对 BC 的 KL 和实际梯度量级。只允许一次有具体诊断依据的学习率/KL 修订。

折扣按物理时间确定：Δt=2/60 秒，首轮 τ=30 秒，γ=exp(-Δt/τ)≈0.99889，GAE λ=0.95；这是初始配置而非最优参数断言。旧 γ=0.99 的几何尺度约 3.3 秒，不代表模型只能记住 3.3 秒。更新 rollout 先用每环境 512 决策，按实测显存和稳定性调整 batch，并冻结变更。

奖励以完成第一面为主要正事件，死亡与资源作辅助，进度信号有界。正式训练前，用真实轨迹比较过关、早死、拖延和滥用 bomb 的折扣总回报，冻结每项系数与单位。裸生存常数不能压过任务目标；除以常数不修复错误的相对奖励。势函数 shaping 若使用，必须核对真实终止和时间截断处理。

首档为 3 个独立训练 seed，各 1M 有效游戏帧；每个 run 与 R0 在相同开发任务上评测。每 run 5M 是后续档，三 run 合计 15M，未纳入本首轮 12M 主环境帧上限。进入后续档前要求数值检查通过、至少 2/3 run 的配对游戏指标为正，并在剩余授权范围内另编该档预算。只有首死改善而无过关时可以记诊断收益，不能记能力门通过；不自动追加训练。

特权 critic 仅在确有价值估计问题时另开诊断，记录历史与状态的共同条件，不能默认状态 critic 自动解决部分可观察性；它不进入严格 R1。

R2 若成功，可产出 G420-4 候选。R2 失败则检查首次更新、回报、恢复课程和探索；一次短跑或单训练 seed 的失败不作为“RL 不可行”的结论。

### WP420-06 第一面正式确认与 Windows 部署

目标：使用同一冻结 checkpoint 在标准第一面和真实 60 Hz 游戏中验证像素控制。

S1N 固定 stage_index=0、Normal、team=0，标准资源、自然开局，不续关；记录实际资源字段及屏幕含义。保持 19,887 游戏帧 cap，不在观察确认结果后扩大。运行至过面、game_over 或 cap，死亡后允许使用正常残机继续。

DIAG-FIRST-DEATH 单列，用于首个错误与零死亡能力诊断。旧“首死即停的 0/20”不转写成新的标准 S1N 成绩。

候选通过开发筛选后冻结权重、加载器、输入、动作、开火、记忆处理和设备。确认阶段不按中途结果换模型、改奖励或继续训练。使用新确认批次；建议 62000–62099，先只检查历史曝光登记，无冲突才冻结。不得读取或运行旧保留的 61000–61099、61400–61499，60000–60199 继续禁止训练。

G420-4：100 个确认 episode，成功至少 50/100，Wilson 95% 下界至少 35%，部署输入只有像素与自身历史。所有失败、超时和崩溃保留分母；技术无效时先修协议，再用新的完整批次确认。

G420-5：同一 checkpoint、至少 20 个 Windows 零售会话、真实 60 Hz，点估计至少保留 harness 过关率的 70%，并报告区间、延迟、抓帧陈旧与动作生效情况。不能可靠控制 RNG 时按独立真实会话记录，不伪称同 seed 配对；点估计保留率不等于总体非劣效证明。

首面过关还不等于任意游戏画框可迁移。Windows 失败时检查输入延迟、陈旧截图、缩放、颜色、归一化和帧历史，不替换默认模型或零售件来隐藏差异。

### WP420-07 后续完整能力扩展

本工作包在首轮资源评估后按条件解锁，沿用最终目标，不挤占第一面诊断预算。

| 阶段 | 前置与工作 | 对应验收 |
| --- | --- | --- |
| 连续像素反馈 | 复用 WP06 契约，补逐帧全分辨率 HUD、死亡/重生/终局数据与冻结可见锚点 | 对应 scope 的 G410-3；单帧读数准确不能代替连续事件门 |

第一面预训练已接触多个 TH08 关卡的历史 checkpoint，只可按其真实谱系用于能力开发；干净适应实验需要另建合格谱系，不能通过改 seed 名称消除污染。

## 6 开发评测与统计

开发诊断先用已有 1000–1019，候选选择使用 1020–1039；这些属于开发曝光，不能称独立确认。新训练 seed 与所有开发/确认注册表取差集；旧被拒绝的 train/dev 混合数据不进入新训练。

方法复验使用训练 seeds 0/1/2，每个至少 20 个相同开发 episode。报告逐训练 seed 和配对差，跨训练运行的区间按层级计算；3 个训练 seed 仍然有限，不能把 60 个 episode 当作 60 次独立训练。

重复运行同一完整轨迹不增加样本量。派生起点和裁剪按共同祖先分组，另报跨 seed 的像素、动作及实体轨迹重复。不能只凭相同首死帧或 25 个导出字段相同，就断言完整游戏状态相同；也不能只凭 seed 不同就假定覆盖不同。确认集的抽样与相关性处理在运行前冻结，不按成功/失败结果事后去重。

开发选模按标准 S1N 过关率、冻结 cap 下的进度、死亡与资源作字典序比较；DIAG 首死只作补充。每个候选给出有效决策数、独立祖先数、真实采样帧、优化步数和墙钟；离线 loss、idle、熵和动作一致率均为诊断。

如果只是从多个训练 seed 中选择一个部署 checkpoint，明确报告选择规则和全部训练结果。部署能力确认与“某方法稳定优于另一方法”是两种不同结论。

## 7 验收门与失败后动作

| 门 | 所需证据 | 不满足后的下一步 |
| --- | --- | --- |
| G420-0 时间与运行有效 | 远端原模型复现；2 帧样本/历史/输入/像素一致；零未解释 HASH 差异 | 修对应连接层，停止使用无效数据的训练 |
| G420-1 标签有效 | 200 状态全候选验证，至少 100 个有区分度的有效状态；续行可追溯 | 补分支或修教师；未知不改为负例 |
| G420-2 学习诊断 | 固定状态拟合、10 个训练微段、A0/A1/A2 与整面开发结果 | 区分目标与输入，限定两个替代分支 |
| G420-3 自主覆盖 | 两轮 β=0 累计至少 50k 决策、聚合来源与自然/课程起点分表 | 改恢复课程或停止当前 DAgger 配方 |
| G420-R RL 诊断 | 三个训练 seed 的零更新与 1M 帧结果、反馈与数值审计 | 一次有依据的修订，再定位；不强求正结果 |

版本第一面能力必须有 G420-0/4/5 的真实通过。G420-1/2/3/R 是研究路径的结果记录；若某条路径有效失败，另一条有效路径仍可产出候选。完整项目完成仍受原最终能力门约束。

## 8 首轮资源与时间安排

首轮建议窗口为 4 个工作周，目标是前 2 周得到能决定分支的结果，后 2 周争取第一面候选和部署。工期是排程目标，不是成功保证；资产主机争用、吞吐和旧消耗在接管时实测。

| 阶段 | 建议工作日 | GPU 小时上限 | 资产主机活动墙钟上限 | 交付 |
| --- | --- | ---: | ---: | --- |
| A | 第 1–5 天 | 8 | 24 小时 | 复现、时间契约、分支成本与标签 |
| B | 第 6–10 天 | 12 | 24 小时 | 受控学习、首个真实错误归因、RL 初始化诊断 |
| C | 第 11–20 天 | 28 | 48 小时 | 有条件的 DAgger/RL、正式候选与真实部署 |
| 合计 | 20 个工作日 | 48 | 96 小时 | 按实际资源决定达到的阶段 |

另设首轮共同上限：12M 主环境有效游戏帧、1.5M 外层反事实续行帧、64M 教师内部及影子推进帧、650k 教师查询、40 GB 新增磁盘、8 小时真实 Windows 会话。外层续行与查询内的 tape/verify 推进分开计数，不能漏记内层 fork 成本。GPU 活动与占用时间、CPU 核时、主机活动墙钟分别记账；同时运行任务的墙钟不重复相加，CPU 核时累加。

这些是计划额度，执行时取各项历史已授权剩余额度与本表的较小值，旧未知消耗不记为零。本轮制定计划不启用任何运行预算。后续 5M/run、多面与严格像素训练未纳入首轮，扩大前必须重新核算。

以端到端实测速率预测成本，不能拿无策略引擎 FPS 当教师吞吐。200×18×120=432,000 外层分支帧，动态教师续行最多约 216,000 次 2 帧查询；每次查询的内部记录与验证又会推进引擎，不能只报前一个数字。内层帧数无法直接取得时，按实际 horizon、验证候选数与调用数给出上界，估算与实测分列。重放前缀和开发评测另计；先用 20 个状态验证成本。高危状态少不靠复制填数量。

默认一个重 GPU 任务、一个 CPU 标注批次，先 2–4 个引擎实例。共享总核数、软件渲染与 fork 都计资源，避免多个代理各自占满机器。采样、标注或数据加载确实限制当前实验时再优化，不把追逐固定 FPS 门槛作为所有学习的前置。

达到任一资源上限 80% 时停止新增长实验并完成可安全收尾的切片。第 10 个工作日还没有可重复的微段学习或任何开发收益时，提交剩余假设、已排除项与替代分支，重排后半程，不能照原计划继续大采集。阶段结束有关键缺口时写明未达能力，不用“预算跑完”宣布成功。

## 9 执行与证据管理

实际实现、测试、采集与训练遵守根 [AGENTS.md](../../../../AGENTS.md) 的 Provider=DeepSeek、模型=DeepSeek Flash 分工；每次只派目标、白名单、禁止事项、完整验收命令和立即返回要求。指定入口不可用时不静默换模型。本次纯规划由主代理按约定例外完成。

明确执行授权后，在 v4.2.0 新建状态、journal、budget 和实验目录，引用 v4.1.0 的暂停快照，不改旧记录。状态未知使用 unknown，未运行使用 not_run；不从旧 state 的 running 字段推断真实进程仍在跑。

每个 run 保存完整 argv、cwd、进程身份、开始/结束时间、真实退出码、stdout/stderr、配置、源码与资产身份、逐局结果、训练曲线、失败 trace 和产物索引。小证据可同步，像素/权重/游戏文件留在资产主机。checkpoint 保存 optimizer、RNG、采样游标与版本；只加载权重重新训练属于新 run。

采用短切片与可恢复进程，工具等待单次不超过 60 秒；长任务在后台记录进度与心跳。只管理自己拥有的进程，不根据旧 PID 杀其他任务。单个配方失败时继续依赖满足的其他分支，技术失败、有效负结果与有效正结果分开。

本版本的具体首轮派发与验收见 [首轮执行任务单](首轮执行任务单.md)。其中新 CLI 是待实现契约，只有对应任务完成后才可调用；不能把本计划中的示例命令当作已存在功能或已通过证据。

## 10 方法依据

- [DAgger](https://proceedings.mlr.press/v15/ross11a.html)：支持在策略实际访问的分布上迭代补充专家监督；不保证信息不足或错误目标也能学成。
- [Implementation Matters](https://arxiv.org/abs/2005.12729)：支持在归因算法失败前检查实际实现、初始化与更新细节。
- [Unbiased Asymmetric RL](https://arxiv.org/abs/2105.11674)：部分可观察条件下，特权 critic 的条件与偏差需要审查；特权不自动等于更正确。
- [Statistical Precipice](https://arxiv.org/abs/2108.13264)：有限训练运行需要区间与分层统计，不能只比较最好 checkpoint。

这些研究为实验设计提供依据，不保证 TH08 像素通关或跨作品适应。路线是否有效，由本计划中的真实控制与独立确认决定。
