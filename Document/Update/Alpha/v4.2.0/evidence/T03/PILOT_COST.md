## 0 结论摘要

1. **shadow ≡ env 在 HASH 层成立（在本试点覆盖的前缀上）**：seed 10、记录掩码前缀
   2,000 帧，shadow 与 env 逐帧 HASH **2,000/2,000 相等**，两次独立重复都是 2,000/2,000，
   第一处不一致帧 `None`；两个角色各自对语料 `hash_post` 的 500 个决策边界也 500/500 相等。
2. **env 角色贵 38 倍**：shadow 2,879–2,925 fps（341.9–347.3 µs/帧），env(xvfb) 73.2–77.6 fps
   （12.9–13.7 ms/帧），比值 **39.3× / 37.7×**。
3. **批量推进只把 shadow 提到 4,297–4,620 fps**：`advance(mask,4)` 仅 +3.2%/+27.7%（500 个决策里
   只有 263 个的 4 个掩码相同），按相同掩码分段批量（`runs_full`）+47%/+60%。
   反解出单帧引擎成本约 175–189 µs、单次调用开销约 150–172 µs，所以批量的天花板不高。
4. **fork 真实可用且可复算**：`PARK` 在 7/7 次成功；18 个首动作 × H=120：
   `BRANCH` 一条命令 18 条分支共 **405–626 ms**；`SPAWN`+`CHILD STEP 120` 共 442–673 ms；
   每 2 帧一次 `CHILD STEP`（真实教师续行节拍，60 次/分支）共 **797–1,136 ms**，
   即 **2,015–2,709 有效帧/s**，每分支中位数 **43.7–61.4 ms**。
   引擎自报 `child_us` 折算 **139–229 µs/帧**，fork 固定开销（`fork_us−child_us`）中位数 **2.02–2.61 ms**。
5. **fork ≡ 直放**：cand 0 的 `BRANCH` HASH == `CHILD STEP` HASH == 父进程重放同掩码 HASH，
   6/6 次运行成立；`BRANCH` 前后父 `FRAME` 不变 6/6；三次深度重放的停放点 HASH 在两次重复间
   逐比特相同（`22ec1c2e…`/`46c1288b…`/`897c5286…`）。
6. **200×18×120 = 432,000 外层分支帧**：分支引擎侧 **185.2 s**（3,600 分支 × 51.46 ms 中位）。
   策略 (a)「每个状态重新开+重放前缀」**340–656 s**；策略 (b)「一次开局连续评估多个状态」
   **208–240 s**。**推荐 (b)**，(a) 也跑得动但纯属浪费（重置占 140.7 s）。
   这是**争用条件下**的上界；空载主机的历史同口径实测（EXP-P0-050，41.42 µs/帧）暗示可低到 ~20–40 s。
7. **50 个状态的学生续行对照**：引擎侧 7.72 s + 学生前向 16.55 s = **24.3 s** 增量（shadow 特权输入）。
8. **不可行/受限项**（详见 §9）：env 角色不能 fork、不能做分支验证；fork 出的子进程**不能出像素**；
   因此“像素学生续行”只能走 env 重放，50 状态按本机 env 速率是 **35 min–3.8 h**，不是 24 s。

## 4 测量 3：fork 成本（停放点 = 第 200 个决策 / 第 800 帧）

命令（同一条驱动跑 3 个深度）：

```bash
wsl -e bash /mnt/d/WorkShop/Touhou_RL/.tmp_v420_t03p/run02_fork.sh fa
wsl -e bash /mnt/d/WorkShop/Touhou_RL/.tmp_v420_t03p/run02_fork.sh fb
```

两次都是 `FAILURES=0 / EXIT_CODE=0`。流程（全部在一个 shadow 进程内）：
快速重放前缀 → 校验停放点 HASH → `PARK` → 对 18 个候选首动作分别走三条 fork 路径：

* **A `BRANCH <mask> 120`**：一次真实 `fork()`，子进程用**同一个掩码**推进 120 帧，
  逐帧 HASH 全部回传，父进程不动（引擎上限 300 帧）。
* **B `SPAWN` + `CHILD <h> STEP <mask> 120` + `CHILD <h> QUIT`**：fork 出一个可对话子实例，
  一次命令推进 120 帧。
* **C `SPAWN` + 60 × `CHILD <h> STEP <mask2> 2` + `QUIT`**：**真实教师续行节拍**
  （每 2 帧一个决策、掩码可逐次改变）。本试点对 18 个分支用“首 2 帧 = 候选掩码，
  其余 118 帧 = 固定掩码 1（cand 0）”。

停放点深度 200（帧 800，`hash_post` = `46c1288b474a1d73`），18 分支 × 120 帧 = 2,160 帧：

| 路径 | 18 次合计 ms（fa / fb） | 单次中位 ms（fa / fb） | 引擎自报（fa / fb） |
| --- | ---: | ---: | --- |
| A `BRANCH` | **524.8 / 570.3** | 27.17 / 27.42 | `child_us` 23.51 / 25.22 ms、`fork_us` 27.04 / 27.27 ms、固定开销 2.61 / 2.02 ms、195.95 / 210.18 µs/帧 |
| B `SPAWN`+1 次 `CHILD STEP 120` | 456.9 / 489.9 | 24.45 / 27.43 | spawn 1.63 ms、step 22.0 ms、quit 0.58 ms（fa） |
| C 每 2 帧一次 `CHILD STEP` | **797.3 / 977.8** | 43.70 / 55.84 | 2,709 / 2,209 有效帧/s；单次调用 p50 0.516 / 0.501 ms，p95 1.63 / 3.54 ms |

18 次 fork 合计 **2,160 帧**的折算（fa / fb）：
A 524.8 / 570.3 ms → **242.9 / 264.0 µs/帧**；
B 456.9 / 489.9 ms → 211.5 / 226.8 µs/帧；
C **797.3 / 977.8 ms → 369.1 / 452.7 µs/帧**（T03 的真实节拍）。

六次运行的引擎侧汇总（每行 18 个分支取中位）：

| run | `fork_us` ms | `child_us` ms | `fork_us−child_us` ms | `child_us`/帧 | C 路径单分支 ms | C 路径 µs/帧 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| fa d100 | 22.43 | 18.83 | 2.34 | 156.93 | 47.24 | 393.6 |
| fa d200 | 27.04 | 23.51 | 2.61 | 195.95 | 43.70 | 364.2 |
| fa d400 | 29.47 | 27.43 | 2.10 | 228.62 | 55.19 | 459.9 |
| fb d100 | 20.06 | 16.71 | 2.20 | 139.28 | 47.72 | 397.7 |
| fb d200 | 27.27 | 25.22 | 2.02 | 210.18 | 55.84 | 465.4 |
| fb d400 | 29.00 | 25.97 | 2.21 | 216.45 | 61.45 | 512.1 |

`PARK` 接受率 **7/7**（含 1 次冒烟），墙钟 1.086–6.408 ms（median 3.27 ms），
回复形如 `OK park=1 template=<id> pid=<pid> frame=800`。

### HASH 一致性（fork 侧）

| 检查 | 结果 |
| --- | --- |
| A 的 `hash` 等于其 `trace` 最后一帧 | 18/18 × 6 次运行 |
| B 的末帧 HASH == A 的末帧 HASH（同掩码流） | **108/108**（18×6） |
| C 的 cand 0（掩码流与 A 相同）== A | **6/6** |
| `BRANCH` 前后父进程 `FRAME` 不变 | **6/6** |
| 额外重放：`RESET`+重放到停放点+父进程直推 120 帧 == A 的 HASH | **6/6** |
| 停放点 HASH == 语料 `hash_post`（帧 400/800/1600） | 6/6，且两次重复逐比特相同（`22ec1c2e…`/`46c1288b…`/`897c5286…`） |

**结论**：`BRANCH`、`SPAWN+CHILD` 与“不 fork、直接在父进程重放同一掩码流”三者
在 HASH 上等价；fork 不改父进程状态；停放点可跨进程逐比特复现。

## 5 测量 4：前缀重放 + fork 的深度曲线

命令同上（`fa` / `fb`，深度 100 / 200 / 400）。表内 “fork 18” = 18 分支 × 120 帧的

| 深度 | 前缀帧 | 重放 s（fa / fb） | 重放 fps（fa / fb） | fork 18 s（fa / fb） | 前缀+fork s（fa / fb） | +`RESET`（median 0.704 s） |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |

## 6 测量 5：200 状态 × 18 候选 × H=120 的容量外推

目标量：200×18×120 = **432,000 外层分支帧**；3,600 条分支。

实测单价（6 次运行取中位）：

| 单价 | 值 |
| --- | ---: |
| shadow 前缀重放 | **5,860.96 fps** / 170.6 µs/帧（观测区间 3,994.77–6,703.45 fps） |
| shadow 单帧 `advance` | 2,879–2,925 fps（341.9–347.3 µs/帧） |
| 一条 120 帧分支（C 路径，含 spawn+60 次 `CHILD STEP`+quit） | **51.457 ms** |
| 同上折算 | 2,332 有效帧/s；428.8 µs/帧 |
| `RESET` | 0.704 s |
| 引擎启动 | 1.381 s |
| `PARK` | 3.27 ms |
| 学生一次决策（§8） | 1.839 ms（mean，CPU+CUDA 四次运行中位） |

策略定义：

* **(a) 每个状态都重新重放前缀**：每个状态 `RESET` 一次 + 从第 0 帧重放到该状态 + 18 个 fork。
* **(b) 一次开局连续评估多个状态**：每条祖先轨迹只启动/`RESET`/重放到最深状态一次，
  沿途每个状态 `PARK` + 18 个 fork，父进程继续沿记录前缀走到下一个状态。
  （200 个状态来自 ≥10 条祖先轨迹，所以按 10 条轨迹各开一次。）

| 平均前缀深度 | 前缀帧 | (a) 中位 s | (a) 慢 s | (b) 中位 s | (b) 慢 s |
| --- | ---: | ---: | ---: | ---: | ---: |
| 100 决策 | 400 | 339.6 s | 346.0 s | **208.1 s** | 208.8 s |
| 200 决策 | 800 | 353.2 s | 366.0 s | **209.5 s** | 210.8 s |
| 400 决策 | 1,600 | 380.5 s | 406.0 s | **212.2 s** | 214.8 s |
| 1,000 决策 | 4,000 | 462.4 s | 526.2 s | **220.4 s** | 226.8 s |
| 1,650 决策（3,300 决策 shard 的中点） | 6,600 | 551.2 s | 656.4 s | **229.3 s** | 239.8 s |

慢 fps = 用观测到的**最慢**前缀重放（3,995 fps）重算，作为保守上界。

分解（1,650 决策档，中位 fps）：

| 策略 | 开启/重置 | 前缀重放 | fork | park | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| (a) 200 状态各自重放 | 140.7 s | 225.2 s | **185.2 s** | — | 551.2 s |
| (b) 10 条轨迹连续评估 | 20.9 s | 22.5 s | **185.2 s** | 0.7 s | 229.3 s |

**判定**：
* 两种策略都**可行**（都远小于 §8 的 96 小时资产主机活动墙钟，也都远小于 10 分钟单命令上限的
  组合），**推荐 (b)**：同样 200 个状态，比 (a) 便宜 **1.6 倍（前缀 100 决策）到 2.7 倍
  （前缀 1,650 决策，慢 fps 端）**，且 (a) 的差额几乎全是 200 次 `RESET`（140.7 s）
  加 200 次前缀重放，(a) 没有任何正确性收益。
* **真正的成本主项是 3,600 次 fork（185.2 s）**，两种策略相同；
  想再省只能减少分支数、缩短 H，或把 H=120 用一次 `CHILD STEP 120` 批量推进
  （那样 18×120 帧只要 0.44–0.67 s/状态，即 3,600 分支 ≈ 88–134 s，但**牺牲逐决策改掩码**，
  只适用于“固定续行”而不是“教师续行”）。
* 预算占比：432,000 / 1,500,000（§8 外层反事实续行帧上限）= **28.8%**，未触 80% 停训线。
* 20 个状态的 pilot 阶段（WP420-02 要求“先用 20 个状态测成本”）：fork 侧 18.5 s；
  (a) ≈ **35.3 s**，(b) ≈ **20.9 s**（平均前缀深度 200 决策、10 条轨迹口径按 (a)/(b) 同式）。

## 9 不可行项、受限项与原因

1. **env 角色不能做分支验证（能力 + 成本双重否决）。**
   `PARK`/`BRANCH` 的引擎前置条件是 `IsShadowRole()`（`fork.cpp` 的 `Ready()`），
   env 角色会被拒（`ERR fork-unsafe role=shadow-required`）；
   即使能 fork，env 只有 73.2–77.6 fps，432,000 帧要 **1.55–1.64 小时**，
   是 shadow 的 38 倍。**结论**：分支/续行一律走 shadow，env 只用于真的需要像素的场合。
2. **`BRANCH` 不能做“逐决策改掩码”的续行。** 它一条命令只能用**一个**掩码推进
   （且 ≤300 帧）。真实教师续行必须用 `SPAWN`+`CHILD STEP`，成本从 22–30 ms/分支
   涨到 **43.7–61.4 ms/分支**（60 次协议往返，每次 p50 0.43–0.57 ms）。
   这一点直接影响 432k 帧的估算：按 `BRANCH` 会低估约 2 倍。
3. **fork 出来的子进程不能出像素。** 子进程继承的是 shadow 的 null device，
   且 `CHILD` 只转发只读命令 `HELLO/HASH/QUIT/DEBUG/FRAME/PING/STATE/PLAYER/EVENTS/
   HAZARDS/BULLETS/LASERS/ENEMIES`（`fork.cpp` 的 `ChildReadOnlyCommand`），
   **没有 `PIXELS`/`READBACK`/`SHM`**。所以“像素学生续行”不能 fork，
   只能在 env 角色里重放：
   * 50 状态 × 3 臂 × (前缀 + 120 帧)，env 无 fork 必须每臂 `RESET`+重放，
     按本机 env 单价（`RESET` 1.65 s + 13.28 ms/帧，往返 150 臂）：
     前缀深度 200 决策 → **≈ 35 min**；前缀深度 1,650 决策 → **≈ 3.8 h**。
   * 因此 §7 的 24.3 s 只在“学生用 obs-v3 特权/记录平面”时成立；
     要像素就必须另编预算，且很可能不在 20 状态 pilot 的预算内。
   **这是 T03 排程必须提前决定的唯一结构性岔路。**
4. **并发 fork 未测。** 引擎允许一个 template 最多 32 个 spawn，
   但本试点全部是**串行**执行（18 分支一条一条跑）。并行能省多少没测，
   且在 PID 1884178 占约 10.6 核的情况下并行会加剧争用；不作为本文结论。
5. **纯 `fork()` syscall 时间不可得。** `fork_us` 是父侧跨度（含子推进 + 管道 + `waitpid`），
   与 EXP-P0-050 同一口径。本文只报 `fork_us−child_us` 作为“子循环之外”的混合固定开销，
   **不称其为 syscall 时间**。
6. **`BRANCH` 上限 300 帧**：H=120 在界内；H>300 必须分段，成本未测。
7. **本试点没有语义结论。** 续行掩码是固定的，18 个分支的存活/死亡不计入任何安全集合，
   也不构成 G420-1 的有效状态。

## 10 稳定性（两次重复的差异）

| 测量 | 第一次 | 第二次 | 差异 |
| --- | ---: | ---: | ---: |
| shadow f1 fps | 2,879.33 | 2,924.68 | +1.6% |
| env f1 fps | 73.18 | 77.55 | +6.0% |
| shadow `advance(mask,4)` fps | 2,971.92 | 3,733.62 | +25.6% |
| shadow 分段 fps | 3,456.35 | 3,901.06 | +12.9% |
| shadow 分段（不切边界）fps | 4,620.23 | 4,297.35 | −7.0% |
| 前缀重放 fps（深度 100 / 200 / 400） | 6,703 / 6,091 / 5,665 | 3,995 / 6,057 / 4,703 | −40% / −0.6% / −17% |
| fork 18 条 C 路径合计（深度 100 / 200 / 400） | 823 / 797 / 1,072 ms | 897 / 978 / 1,136 ms | +9.0% / +22.6% / +6.0% |
| 学生 mean（cpu） | 1.933 ms | 2.794 ms | +44.5% |
| 学生 mean（cuda） | 1.717 ms | 1.745 ms | +1.6% |

判读：**结论层面的量（shadow/env 比值 ≈38×、fork 43.7–61.4 ms/分支、fork≡重放）
在两次重复间稳定**；抖动集中在“短计时窗口 + 重尾”的量（前缀重放 0.06 vs 0.10 s、
CPU 学生 mean 被 72–125 ms 的单次停顿拉高）。所以：
排程用**区间**而不是单点，且所有区间都按争用条件下的慢端写。
