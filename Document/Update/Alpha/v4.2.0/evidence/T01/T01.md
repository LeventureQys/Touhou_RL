### 6.2 与侦察备忘录期望值的一处差异（如实登记，未改数）

备忘录 §9.3.4 期望 `slots_play_reconstructible=3300`，本实现实测 **3299**。原因：`play[i]` 存的是帧 `4i-4..4i-1`，槽 1 需要帧 `4i-2..4i+1`，即 `concat(play[i][2:4], play[i+1][0:2])`；**最后一块没有后继块**（该 shard 的 `play96x112.npy` 只有 3300 行，末块槽 1 所需的帧 `4i+1` 从未落盘），所以只剩 3299 块可在**本 shard 内**拼出。
本实现同时报两个字段，避免任一读法被隐去：

- `slots_play_reconstructible = 3299`（本 shard 内可拼）
- `slots_play_reconstructible_including_boundary = 3300`（按块/帧规则可拼，含需要后继块的那一块）
- `slots_play_boundary_missing_successor = 1`

这不影响任何判定：`slot_registry` 的结论是「槽 1 有动作、无标签、HUD 缺」，play 侧可拼与否都不使其成为训练样本。

## 8 剩余阻塞（交给 T02 / 主代理）

1. **在线腿缺失**：`audit_live_episode` 与 `audit-time --execute` 未实现（T02）。G420-0 因此**只完成离线腿**，不能报通过。
2. **槽 1 不可训练**：`slots_action_only=3300`、`slots_hud_missing=3300`。要给槽 1 独立标签与 HUD，只能按 2 帧节拍**重采**（不得复制/插值/平移槽 0 标签）。
3. **旧 shard 无逐帧 HASH / 无时间戳**：`labels.jsonl` 无 `timing_ms`，`shm.py` 头部只有 `frame`；旧数据能给的最强对齐证据是 3300×2 个边界 HASH（6600/6600 相等）。T02 的「像素时间」只能在新在线审计里落地。
4. **该 shard 无死亡/换面样本**（`stop_reason=max_frames`、`deaths_observed=0`、`stage_clear=false`），`first_death`/`game_over`/`stage_clear` 目前只有代码级单测证据。
5. **WP00 注册表跨主机路径**：`windows_checkout` 与 `python_env` 记的是 Windows 绝对路径，在 WSL 上被 v4.1.0 `check_wp00` 判为 invalid。`audit-assets` 将其归类为 `host_mismatch`（`wp00.status = pass_with_host_mismatch`），不作为 v4.2.0 缺资产；此项需 T00/主代理决定是否在 v4.1.0 之外另立登记，**本任务不改旧证据**。
6. **`local.json` 的 seed 分配**：T00 登记 `dev_used=1000-1019`、`confirm_teacher_exposed=61300-61399`。T01 的 `legacy-reproduce.json` 用 1000/1001/1002（在 `dev_used` 内），确认批次另留 61000–61499；若 T07 要避开 61300–61399，需在 `exposure_registry` 里显式登记。
