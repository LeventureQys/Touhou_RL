# verified 集合的 idle 统计（T04，纯离线，不启引擎、不训练）

- 作者：T04 执行子代理（DeepSeek Flash），按主代理的离线核查任务执行
- 数据源（**只读**）：`.tmp_v420_data/T04/dataset/<shard>/{slots.jsonl,targets.jsonl,meta.json}`，
  3 个 shard、**19,772 槽**（6,592 + 6,592 + 6,588）
- 脚本：`.tmp_v420_idle/analyze_verified_idle.py`（统计，写
  `.tmp_v420_idle/verified_set_idle_raw.json`）、`.tmp_v420_idle/assemble_evidence.py`
  （把 raw 组装成机器可读镜像 [`verified_set_idle.json`](verified_set_idle.json)，本文件
  每张表都由它打印的同一批数字粘贴而成，不手抄）
- 全程**没有**启动引擎、**没有**训练、**没有**写 `.tmp_v420_data/**`；
  `touhou_rl/**`、`tools/**`、`configs/**`、`tests/**`、`evidence/{T02,T03}/**`、
  `evidence/T04/` 既有文件**一个字节未改**
- 被回答的问题：**为什么用 `chosen_verified_cand`（verified 集合的 argmax）训练会得到比
  `executed_cand` 更高的 idle 占比、更差的闭环**

> **一句话**：`chosen_verified_cand` 确实比 `executed_cand` 更 idle（44.38% vs 36.54%），
> 但这不是 argmax 或并列问题——`|verified_mask| = 1` 在 **19,772/19,772** 个槽上成立，
> 集合里只有 1 个候选，argmax 无比较对象，**全语料 0 个槽在最大分处并列**。这份 idle 差额
> **全部**来自 legacy 块的第 2 帧（决策帧 `4i+2`）：那里 `executed_cand` 是 2 帧前那份计划的
> 第二个元素（idle 29.25%），而 `chosen_verified_cand` 是该帧的**新查询**（idle 44.85%）。
> 在第 1 帧（`4i`）两列几乎是同一个标签（idle 43.90% vs 43.83%，动作相同 9,825/9,886）。
> 这个 8.06 pp 的标签差额只够解释 A0v 实测回升的 **39%–49%**，因此
> 「A0v 只是忠实拟合了 target 分布」**不成立**；A0v 高于自己的 prior 5.2–6.3 pp，A0 低于自己的
> prior 3.2–6.3 pp，残差本统计**无法归因**。

## 1 定义与分母口径

| 项 | 定义 |
|---|---|
| idle | 候选 0（冻结的 18 路表 `focus*9 + move`，`touhou_rl/v420/contracts.py` `N_MOVE_FOCUS = 18`） |
| verified 集合 S | `S = {i : verified_mask[i] == 1}`，来自 `slots.jsonl` |
| `chosen_verified_cand` | S 上 `scores` 的 argmax（并列取最小下标，`dataset_2f.choose_verified`）；本脚本在 19,772 槽上**逐个重算并与 `slots.chosen`、`targets.chosen_verified_cand` 相等断言** |
| `executed_cand` | 语料 `step_frames` 实际执行的动作（行为克隆目标） |
| 并列判定 | 两分数之差 `< 1e-9` 视为并列；分数在数据集里已按 6 位小数落盘，所以与逐值相等等价 |
| train / holdout | `row_index % 5 == 4` → holdout，其余 train（T04 训练用的同一规则；本脚本数出 **15,819 / 3,953**，与 `TRAIN_CONTROLLED.md` §3 的 5,274+5,274+5,271 / 1,318+1,318+1,317 一致） |
| 每张表的分母 | 写在表里（`占比 (分子/分母)`），或在表题显式写出「denominator = …」 |

**一处必须点明的口径**：`A0`/`A0v` 的**实测** idle 占比（0.2989 / 0.3303 / 0.5055 / 0.4952）
**不是**本文件算出来的，是从 [`ACTION_MIX.md`](ACTION_MIX.md) §1 照抄的对照值；本文件只做
「label prior vs 实测」的比较，不重算 dev-eval。

**这不是「idle 总是最大分」，而是「S 里根本没有第二个元素可供比较」**：|S|=1 时 S 的唯一成员
天然是 S 的 argmax，`unique_max / tied_max / below_max` 三个类别在结构上是空的（0/8,774）。
所以任务里这一项在**本语料上不可做**（`not_available`，原因 = |S|≡1，不是字段缺失，也不是

max = 6.67 / 8.18 / 6.70——即 `unverified_discount` 把 verified 候选抬到所有 unverified 之上，
间隔至少 5.0。因此任何「idle 在全部 18 个分数里的排名」统计都只是在测量这个折扣。

条件化的两问（分母 = 0 个并列槽）：

| 问题 | 分母 | 结果 |
|---|---:|---|
| 这些槽里 verified 是否包含全部并列最大项 | 0 | `not_available`（无并列槽，0 不能写成 1.0000） |

所以「argmax 因并列而系统性选 idle」这条机制在本语料上**被数据排除**。

| A0v（`chosen_verified_cand`） | 首死即停 | 0.5055 | 0.4429 | **+0.0626** | [0.4978, 0.5132] | [0.4352, 0.4506] | 否 |
| A0v（`chosen_verified_cand`） | 标准 S1N | 0.4952 | 0.4429 | **+0.0523** | [0.4893, 0.5010] | [0.4352, 0.4506] | 否 |

| 对比量 | 数值 |
|---|---:|
| 目标 prior 的臂间差（chosen − executed） | **+0.0806** |
| 实测臂间差（首死即停） | **+0.2066** |
| 实测臂间差（标准 S1N） | **+0.1649** |
| prior 差额能解释的实测差额比例 | **39%（首死）/ 49%（S1N）** |

**任务给的判据**：若 `target idle ≈ argmax(idle) ≈ 0.50`，则 A0v 是拟合了 target 分布、问题在
target 而非优化。**数据说前提不成立**：target 的 idle 是 **0.4429（train）/ 0.4473（holdout）**，
不是 0.50；A0v 的 0.4952–0.5055 比它高 5.2–6.3 pp（区间不重叠）。同时 A0 比自己的 prior
**低** 3.2–6.3 pp（区间也不重叠）。两个臂朝**相反方向**偏离各自的 prior，所以「两臂都在照抄
自己的 target 边缘分布」这一说法被自身的对照否掉。

对「A0v 的 target 更好/更易拟合」这一可能的反驳，用 `TRAIN_CONTROLLED.md` §5.1 的公开数字
和本文件的边缘熵交叉核对（**不是**泛化差距，只是把熵底算清）：

| arm | holdout CE | 训练边际熵 H(Y)（本文件算） | CE − H(Y)（下界口径） |
|---|---:|---:|---:|
| A0（`executed`） | 2.802158 | 2.191999 | 0.610159 |
| A0v（`chosen_verified`） | 2.642093 | 1.967563 | 0.674530 |

A0v 的 holdout CE 比 A0 低 0.160 nats，但它的**目标边际熵底**本来低 0.224 nats
（18 路均匀是 `ln18 = 2.890372`），按「CE − H(Y)」这个下界口径 A0v 反而高 0.064 nats。
所以「A0v 的 holdout 数字更好 ⇒ 目标更干净 ⇒ 闭环变差来自别处」**不成立**；
反过来用它证明「目标更难」也**不成立**（这是下界口径，不是 `H(Y|X)`）。

两个目标列的边缘分布本身（train 行，18 路按候选 0..17）：

```text
executed        : 0.3623, 0.0190, 0.0644, 0.0859, 0.0223, 0.0157, 0.0757, 0.0850,
                  0.0140, 0.0000, 0.0023, 0.0410, 0.0738, 0.0068, 0.0012, 0.0566, 0.0711, 0.0029
chosen_verified : 0.4429, 0.0209, 0.0871, 0.1056, 0.0221, 0.0125, 0.0671, 0.0728,
                  0.0137, 0.0000, 0.0029, 0.0562, 0.0665, 0.0058, 0.0013, 0.0116, 0.0075, 0.0037
H(nats)         : executed 2.191999 | chosen_verified 1.967563 | 均匀 ln18 2.890372
TV 距离 0.140603，KL(chosen‖executed) 0.089885 nats（同一批 19,772 槽，差异纯来自标签列）
```

差异最大的不只是 idle：候选 15（0.0566 → 0.0116）、16（0.0711 → 0.0075）在 `chosen_verified`
里几乎消失，而 2/3/11 变多。**这条额外的分布差异本文件不作解释**——两列的边缘分布确实不同

## 4 归因判定

**判定：`target 本身偏向 idle`（偏差全部集中在 legacy 块第 2 帧）——已证实、必要、
但只占实测差距的 39%–49%；「A0v 只是忠实拟合 target 分布」——不成立；
「argmax 并列处理」——被排除；剩余 5–6 pp——其他 / 本统计无法归因。**

逐假设：

| 假设 | 状态 | 数据依据 |
|---|---|---|
| **H1「verified argmax 因并列而系统性选 idle」** | **被排除** | `\|S\|=1` 在 19,772/19,772 槽成立 → argmax 无比较对象；最大分并列 0/19,772；S 内部并列 0/19,772；`chosen_verified_cand` = 唯一全局 argmax 19,772/19,772；最小下标规则从未触发 |
| **H2「chosen_verified 列本身更 idle」** | **成立** | train 44.29% vs 36.23%（+8.06 pp / 1,275 槽净额）；holdout 44.73% vs 37.79%；全槽净 idle 注入 2,362 − 813 = 1,549 槽 = 7.83 pp |
| **H3「A0v 的高 idle = 忠实拟合 target」** | **不成立** | A0v +5.2…+6.3 pp 高于自己的 prior，A0 −3.2…−6.3 pp 低于自己的 prior，四条 95% 区间全部不重叠；实测臂间差 0.1649–0.2066 是 prior 差 0.0806 的 2.0–2.6 倍；A0v 的 CE 优势 0.160 nats < 熵底优势 0.224 nats |
| **H4「差额来自 teacher 的 verify 阶段偏爱 idle」** | **被排除，换成更锐的机制** | chosen 列 idle 率帧平稳（43.90% / 44.85%），executed 列不平稳（43.83% / 29.25%）；99.03% 的不一致（6,227/6,288）在第 2 帧；第 1 帧两列一致 9,825/9,886。**差额产生在 executed 一侧**：第 2 帧的 executed 是 2 帧前计划的第二个元素 |
| **H5「剩余 5–6 pp 是优化/行为效应」** | **`not_available`** | 数据里没有训练轨迹、没有 rollout 状态、没有 dev 观测分布；且 dev 协议本身的 idle 底噪就比任何训练 prior 高（冻结基线 B0 在 dev 上 idle 0.4581/0.4610，而 executed 训练 prior 只有 0.3623），所以 label prior 不能当闭环速率的点预测 |

**闭环（更差）这一半**：本文件**不**给因果结论。数据只能给出一条「一致的隐患」：
`chosen_verified` 列在 6,288/19,772 槽（31.80%）上教一个**不等于当时实际执行**的动作，其中
3,113 槽（15.74% of all）是两个不同的非 idle 动作；而观测平面是由**实际执行过的**动作序列生成
的（`RESLOT_2F.md` §3 的 hash/帧一致性）。「从由 A 生成的观测去拟合非 A 的动作」是一种分布
一致性隐患，量级可测、因果**未证**（要分离它需要 §6 的实验）。

## 5 不能主张什么

1. 不能主张「A0v 的 idle 回升完全由 target 分布解释」——它只解释 39%–49%，剩余 5–6 pp 未归因。
2. 不能主张「verified-argmax 目标一般有害」——单 seed、5,000 步、单配方；残差机制未定。
3. 不能主张「并列 / tie-break 在这里有影响」——最大分并列 0/19,772，|S|≡1，最小下标规则从未触发。
4. 不能主张「idle 占比是能力指标」——[`ACTION_MIX.md`](ACTION_MIX.md) §3 引计划 §6：idle、熵、
   动作一致率都只是诊断；A0/A0v 都是 0/20。
5. 不能主张「`executed_cand` 是干净的 BC 目标」——在 9,886/19,772 槽（第 2 帧）上它是 2 帧前
   计划的第二个元素，idle 率只有 29.25%，与新查询的 44.85% 差 15.6 pp。这条对 **A0 也成立**。
6. 不能主张「A0 的低 idle 是更好的打法」——两者都是 0/20，`+4.5%` 存活是 20 个 dev episode、
   单训练 seed、无区间比较。
7. 不能主张「第 2 帧的分歧是教师不确定性」——两列在第 2 帧被查询的**决策时刻不同**
   （executed 来自 `4i` 的计划，chosen 来自 `4i+2` 的新查询），本数据集里没有「同一状态重复查询」
   的对照，无法把分歧拆成「状态变化」与「教师不稳定」。
8. 不能主张「dev 评测分布 = 训练分布」——冻结基线 B0 在 dev 上 idle 45.81%/46.10%，而 executed
   训练 prior 是 36.23%；把 label prior 当闭环速率的点预测会系统性偏低。
9. 不能把本文件的 `A0`/`A0v` 实测 idle 当作我算的数——它们照抄 `ACTION_MIX.md`，本文件只做比较。

## 6 下一步的可判定实验（无需引擎、无需新数据）

本统计顺带给出一个**匹配对照**，能把「标签分布」与「其余一切」分开：

- 在第 1 帧（`4i`，9,886 行）两列**统计上就是同一个标签**：idle 43.90% vs 43.83%，
  动作相同 9,825/9,886 = 99.38%；
- 在第 2 帧（`4i+2`，9,886 行）两列**差得极远**：idle 44.85% vs 29.25%，不一致 62.99%。

因此：`A0-slot0`（executed CE，仅第 1 帧行）vs `A0v-slot0`（chosen_verified CE，同一批行）
**必须落在一起**；若臂间差距在第 1 帧上仍然出现，则原因**不在标签分布**。对称地，
`A0-slot1` / `A0v-slot1` 应当复现全部差距。

| 行集（按 `decision_frame % 4` + train/holdout 规则） | slots | train 行 | holdout 行 |
|---|---:|---:|---:|
| 偏移 0（帧 `4i`） | 9,886 | **7,909** | 1,977 |
| 偏移 2（帧 `4i+2`） | 9,886 | **7,910** | 1,976 |
| 合计 | 19,772 | **15,819** | **3,953** |

两个子臂各约 7,910 个 train 行（净额），是 T04 现有 15,819 行的一半——不需要重采、
不需要引擎，只需在现有 `slots.jsonl` 上加一个行过滤。
