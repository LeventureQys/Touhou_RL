## 0 两个口径必须分开：标准 S1N ≠ 首死即停

| 口径 | argv | 语义 | 历史 |
|---|---|---|---|
| **标准 S1N** | **不带** `--stop-on-death` | 死亡是可承受事件：残机用完才 `game_over`，否则继续到 `stage_clear` 或 `--max-frames 19887` | **本项目首次测量**。历史**没有**任何标准 S1N 数字 |
| **DIAG-FIRST-DEATH** | 带 `--stop-on-death` | 首次死亡即结束该局 | 历史上的全部 20-dev 数字（B0 1453.25 / 20k 1714.65 等）都是这个口径 |

所以：

- 不能把历史上的 1453.25 当标准 S1N 基线；
- 不能把本文件的标准 S1N 均值（2880.95 等）与历史首死均值直接比较；
- 两种口径的「过关」定义相同（`stage_clear`），但有机会过面的前提完全不同：首死即停口径下
  只要死一次就再也没机会，标准 S1N 允许用残机继续。

两种口径都用**同一个冻结 evaluator**（`tools/rl/v410_student_eval.py`，sha256
`2db2caaf…`）、同一引擎（`rl_v3`，sha256 `691bfd77…`）、`--stage 0 --difficulty normal
--max-frames 19887 --obs-window consecutive --device cpu`、dev seeds **1000–1019**、
`xvfb-run` 下真实的 `rl_v3/th08-modern`。
argv 全部由 `touhou_rl.v420.eval.build_legacy_eval_argv(config)` 构造（**不手拼 shell 字符串**），
运行脚本 `.tmp_v420_t04/eval_dev.py`；每个 batch 的完整 argv、退出码、墙钟与逐局字段都在
`dev_eval.json#evaluation.<suite>.arms.<tag>.commands`。

**数据目录是副本**：`$V420_DATA/T04/evaldata/`（`th08.dat`/`thbgm.dat` 为指向只读
`/root/v400-data/game/` 的符号链接）。`/root/v400-data/**` 全程未写。

### 3.5 一个必须记录的操作事实：两个引擎实例不能并发

首次尝试并行跑两个 checkpoint 时，后启动的那个在第 6–7 秒 `RESET` 失败
（`HarnessError: harness closed the control pipe`，`stop_reason=reset_failed`，0 帧）。
两者共用同一个 `--data-dir`。改成**严格串行**后，同一 checkpoint 单独重跑立即成功
（A0v seed 1000：3,363 帧、`game_over`、退出码 0）。因此本轮**全部 160 局都是串行的**，
并发数为 1；那条失败记录留在 `.tmp_v420_data/T04/eval/pilot/`（`exit_code=1`），
没有计入任何分母。

## 4 这些数字不能说明什么

1. **没有一个 checkpoint 过关**（两种口径都是 0/20）。frames 均值是「冻结 cap 下能撑多久」，
   不是过关率，也不能外推成过关率（Wilson 上界在 0/20 时是 0.1611）。
2. **不能与历史首死数字混比**。历史全部 20-dev 数字都是首死即停口径（§0）。
3. **不能当 G420-4**：分母 20 ≠ 100，过关 0 < 50；四个 checkpoint 全部 `not_met`。
4. **不能当确认集**：dev 1000–1019 早已暴露，历史上也被反复使用；确认需要新批次。
5. **单训练 seed**：A0/A0v 只有 seed 0。「2/3 训练运行改善」需要 seeds 0/1/2，本轮没做。
6. **A0 > B0 不等于方法更好**：只有 20 局、单 seed、且 0 过关；这属于「开发集补充观测」，
   计划里开发选模按标准 S1N 过关率优先，而四者都是 0。
