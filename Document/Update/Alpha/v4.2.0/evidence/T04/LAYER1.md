## 2 proper safe-set 的定义与分母

- `safe_set(slot) = {cand : verified_mask[cand] == 1}`，取自 T02d 的逐槽引擎判定。
- **proper** = 非空且不是全部 18 个候选。
- 本语料每槽恰好 1 个 verified 候选（`verified_count` 直方图 `{"1": 256}`），因此：

| 项 | 256 训练槽 | 3,953 留出槽 |
|---|---:|---:|
| 槽数 | 256 | 3,953 |
| 安全集合为空 | **0** | **0** |
| 安全集合 = 全部 18 个 | **0** | **0** |
| proper（可用分母） | **256**（`proper_rate = 1.0`） | **3,953** |

- **proper safe-set 内动作率** = argmax 落在该槽 own verified 集合里的比例。分母 = 256。
- **cost 误差 = `n/a`**：本语料**没有代价标签**。有限视界代价由 T03/WP420-02 的分支验证产生，
  本轮不存在；写任何数字都是编造标签。

### 3.1 三条必须一起读的读数

1. **A0 的 safe-set 率上限就是 0.6820**：把 `executed` 学到 top1 = 1.0 的模型，只有在
   `executed == chosen_verified` 的槽上才自动落在安全集合里，而这个比例是 13,484/19,772 = 0.6820。
   实测 0.6875（= 176/256）与之吻合。**这不是缺陷，是两列标签本身不同。**
2. **A0v 的 safe-set 率 = 1.0 是构造性的**：它的目标就是这个 1-of-18 的 verified 候选，
   top1 = 1.0 必然意味着 safe-set 率 = 1.0。它不说明「更安全」，只说明「目标一致」。
3. **留出 CE 12.46 / 12.88 远高于均匀基线 2.89**：过拟合后的模型在没见过的槽上**高置信地答错**。
   这是记忆的教科书特征，也是「训练池 top1 好看」绝不能当选模依据的直接证据。
