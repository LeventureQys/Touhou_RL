## 2 A1 的前置缺口（这是「未做」的实质原因，不是排期问题）

A1 的集合损失 `L_set = -log Σ[a∈S] π(a|history)` 只有在「**完整候选验证**且**安全集合非空且
不是全 18**」（proper）的状态上才有定义。这样的状态必须来自 T03/WP420-02 的真实分支验证。

**最新实测（T03 试点，[`../T03/COUNTERFACTUAL_PILOT.md`](../T03/COUNTERFACTUAL_PILOT.md)）**：

| 指标 | 实测 |
|---|---|
| 分支总数（2 档 × 20 状态 × 18 候选） | **720**，全部有裁决（`unknown = 0`） |
| 其中**引擎死亡** | **0** |
| `engine_alive` | 360 / 360（每档） |
| 安全集合大小 | 20 个状态**全部 `|S| = 18`**（`empty = 0`、`all_safe = 20`） |
| **proper 状态数**（`0 < |S| < 18`） | **0** |
| G420-1 的 proper 要求 | ≥100 → 现状 0，且「按同样方式扩到 200 状态 still 0」 |

也就是说：**在固定教师续行、H ≤ 120 的设置下，A1 现在没有任何可用训练信号**——
全安全状态按计划「可作普通 BC 数据，但不给『区分危险』的任务虚构信息量」，
空集合/不完整/续行失败的状态**不允许补造正例**。所以 A1 不能做，不是没时间做。

要解除该前置，需要先做一件**性质上不同**的事（T03 文档已列）：
学生续行对照（50 状态 × ≥3 首动作）、真正危险的状态（不是「首死前 0.5 s」而是已进入
不可恢复区域）、或更长的 H（H=600 约 22 h，需重排预算）。这些都在 T04 范围之外。

### 2.1 严禁的替代做法（本轮明确没有做）

- 不得把「几何打平」（同分平台）当安全集合；
- 不得把未验证动作补成正例；
- 不得用空集合/不完整状态凑分母；
- 不得把 `verified_mask` 之外的 17 个候选当作「不安全」的证据（本语料 `verify_k=1`，
  另外 17 个只有未验证折扣）。

## 3 正向继续条件：**未满足**

计划原文（README §5 WP420-03）：*「正向继续条件是至少 2/3 训练运行改善游戏指标，并且安全
相关错误没有被多数类指标掩盖。只有离线改善时，优先回 WP420-02 查首次错误，不继续无界加步数。」*

逐条对照本轮：

| 条件 | 本轮 | 判定 |
|---|---|---|
| 至少 2/3 **训练运行**改善游戏指标 | 只跑了 2 个臂 × **1 个训练 seed**（seed 0），没有 3 个训练运行的矩阵；且两种口径都是 **0/20 过关** | **未满足**（结构上也不适用：2/3 需要 seeds 0/1/2） |
| 安全相关错误没有被多数类指标掩盖 | A1 未做 ⇒ 没有「安全相关错误」这个量；而多数类指标的掩盖效应本身已被量化：训练池 top1 0.996、留出 top1 0.538、留出 CE 2.80（A0v 2.64） | **无法判定为满足**；且已有反例迹象（见 §4） |
| 只有离线改善时回 WP420-02 查首次错误，不无限加步数 | 离线确实改善了（训练池 CE：A0 2.269 → 0.051、A0v 2.077 → 0.093，曲线单调），游戏指标没有过关（两种口径 0/20） | **应回 WP420-02**：本轮没有加步数、没有扩到 20k |

**结论：正向继续条件未满足。** 按计划，下一步不是把 5k 加到 20k，而是回到 WP420-02
（首次错误与真正危险状态），先让安全集合有区分度。

## 4 本轮给出的、与「多数类指标掩盖」直接相关的两个量化证据

1. **256 槽过拟合（层 1）**：训练 256 槽 top1 → 1.0、CE → 1.6e-05，同一模型在 3,953 个留出槽上
   CE **12.455**（A0）/ **12.882**（A0v），远高于均匀基线 2.890 —— **高置信地答错**。
   这就是「训练池 top1 好看」与「实际能力」之间的差距，不能用累计 top-1 当选模依据。
2. **交叉目标**：A0 的模型在留出上对 `chosen_verified` 的 CE 是 **4.361 > ln18**；
   A0v 的模型对 `executed` 是 **4.310 > ln18**。两个标签不可互相替代，
   行为拟合不会自动带来「落到安全动作上」的能力。

同时，层 1 的 proper safe-set 率给了另一个方向的事实：A0 的 0.6875 与
`executed == chosen` 的比例 0.6820 吻合 —— 在**当前标签**下，A0 的安全集合命中率上限就是
标签一致率，**不是模型不够大**。这条正是「改目标（A1）而不是加容量/加步数」的依据。

## 6 若要推进 G420-2，缺的三件事（按依赖排序）

1. **T03 的区分度**：让分支验证产生 proper 状态（学生续行对照 / 真正危险状态 / 更长 H），
   达到 G420-1 的「≥100 proper 状态」。没有这一步，A1 不存在。
2. **A1 训练**：在同一个 2 帧语料 + 同一 B0 模型 + 同一协议上，只把目标换成
   「普通 CE + 集合损失」，作为 A0 的唯一变量对照。
3. **seeds 0/1/2 的等预算矩阵**：才有可能谈「2/3 训练运行改善游戏指标」。

这三件都不属于本轮，且第 1 件不在 T04 的白名单内。
