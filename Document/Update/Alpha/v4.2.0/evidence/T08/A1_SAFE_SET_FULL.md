### 2.3 显示模式：先量，再决定（不照抄“影子模式”）

派发给本轮的运行方式写的是“学生续行不需要像素 ⇒ 用 `env -u DISPLAY` 影子模式”。这两条**都被实测否掉了**，依据如下，两次测量跑的是同一个状态（seed 3042 帧 1920，`first_death = 2041`）和同一条臂：

| 模式 | 一条臂墙钟 | 前缀重放 | `trace_sha256` | 可用性 |
| --- | ---: | ---: | --- | --- |
| `env -u DISPLAY`（无 X） | **31.71 s** | 1,920 帧 @ 65.8 fps | `49767895…c5032f` | **能跑**，但慢 2.14× |
| `xvfb-run -a`（DISPLAY=:145） | **14.81 s** | 同一条 | `49767895…c5032f` | 采用 |

两条结论：

1. **“不需要像素”是错的**：`_StudentSession._require_pixels` 与 `obs_spec.encode_planes_v3(self.shm.pixels())` 就是从渲染帧建 obs-v3；`role=shadow` 是引擎的 null-device 模式（`HarnessClient` 自己的注释："no SDL window and no GL"），**根本不产生像素**，也就无法构造这条臂的观测。所以「影子模式」不是更省的做法，而是**跑不出这条臂**的做法。
2. **headless 的 env 角色能跑，但代价翻倍**：两种模式给出**逐比特相同**的 `trace_sha256`，所以显示模式不影响裁决，只影响速度。一条臂 31.71 s ⇒ 一个状态 18 条臂 ≈ 570 s，正好压在 600 s 命令上限上；因此本轮**每条命令自带 `xvfb-run -a`**。

**清理纪律（按属主 pid，不按模式匹配）**：每条状态命令用 `setsid` 开自己的会话，pid/pgid 写进 `logs/pids.tsv`，`timeout 580` 兜底；唯一允许被杀的进程是**这个会话组**（它只含本命令自己的 `xvfb-run`、`Xvfb`、python 与引擎）。本轮**没有执行过任何一次 kill**（0 条命令超时、0 个残留需要清理），也**没有**碰同主机上别的代理的 Xvfb。

## 3 一条臂的语义（全部来自既有实现，本轮没有新写臂逻辑）

```text
RESET(seed, stage=0, difficulty=1, team=0)            # 私有 cp -a 数据目录，env 角色
  -> 校验 RESET HASH == 记录 trace 的 frame 0 HASH（不等则重启进程重试一次）
  -> 按记录 trace 的逐帧掩码重放 1..state.decision_frame，逐帧比对 HASH
  -> 校验停放点 HASH == 该状态冻结的 expected_hash（不等即 fail-closed）
  -> 在停放点做一次学生前向（同时给出"学生自己的 argmax"，并与录制动作比对）
  -> 施加候选首动作 恰好 2 帧
  -> 循环 { 学生前向 -> 提交 2 帧 } × 59
  -> 到达 H=120 / 首次死亡 / 游戏结束 / 本地过面 = 有效完成；超时/缺帧/进程故障 = unknown
```

复用的既有函数（`touhou_rl/v420/counterfactual.py`，**一行未改**）：`_run_student_episode`（探测）、`trace_prefix` / `Prefix`、`_StudentSession`、`_run_student_arm`、`contracts.classify_branch_outcome`（唯一分类器）、`contracts.safe_action_set`（唯一安全集合函数）、`summarise_contrast`（交叉核对）、`rl.check_data_dir`（数据目录 fail-closed 门）。

**唯一没有复用的是 `_run_contrast_state`**：它按设计把每状态限制在 2–4 条臂（`contrast_arms_max`）。本轮需要“同一状态跑 18 次、每次换首动作”，所以驱动脚本 `.tmp_v420_a1full/a1_full.py` 直接对 18 个候选各调一次 `_run_student_arm`。这是**复用既有能力**，不是重写。

## 8 边界与不能主张什么

1. 这是**标签生成**，不是能力证据：它不产生任何分数、过面率、dev/confirm 评测或泛化测量。
2. **G420-1 没有过关**：它的 `passed` 标志一个字节都没动，而且本轮没有做门里同样点名的“冻结学生续行对照”。
3. `|S| = 18` 不等于“18 个首动作都安全”：H=120 是截断视界，而状态就取在首死前 30–120 帧，死亡完全可能落在窗口之外。
4. `|S| = 0` 不等于“这个状态必死”：它等于“在这 18 个首动作 × 这 120 帧里，没有一条活到 H”。
5. 状态挂在 A0 自己录制的 **TRAIN** 轨迹上：它们对种子 61000–61499（从未读取）什么也没说，对另一个 checkpoint（D2/B0）也需要各自重跑。
6. 墙钟是**共享主机上的争用观测值**，不是性能基准。
7. proper 超过 100 只说明**标签表足够大、可以拿去训练**，不说明训练后学生会变好。
8. **两轮的 |S| 不可比**：臂集（40 状态 vs 200 状态）、状态来源（dev+train+固定帧 vs 纯 train 近死帧）、offset 网格都变了；本文件不把与试点的差当作任何效应的度量，只把试点当成本外推的参照。
9. **状态是诊断定位，不是评测**：它们挂在 A0 自己的 TRAIN 轨迹上，其中 seed 3042–3091 是 D3 用过的训练 seed；本轮不产生任何过关率/分数结论。
10. **A0 是单 checkpoint、单训练 seed（0）**：本轮所有结论只在 A0 上成立，换成 D2 或 B0 需要重跑。
