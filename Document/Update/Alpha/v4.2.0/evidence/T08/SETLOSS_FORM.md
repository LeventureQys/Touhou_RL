## 3 三种损失形式

```text
set_mass        L = -log sum_{a in S} pi(a|s)                         （上一轮；默认；逐位不变）
                dL/dz_a = p_a - p_a/P * 1[a in S]，P = sum_{a in S} p_a
uniform_in_set  L = -sum_{a in S} (1/|S|) * log pi(a|s)               （本轮跑的）
                dL/dz_a = p_a - 1[a in S]/|S|：集合内目标分布是均匀的
hinge           L = max(0, m - log sum_{a in S} pi(a) + log sum_{a not in S} pi(a))
                dL/dz_a = 0（当 log(P/(1-P)) >= m），否则 -1[a in S]*p_a/P + 1[a not in S]*p_a/(1-P)
                m = ln 2 = 0.6931471805599453，跑前冻结，写进 config
```

**为什么只跑 `uniform_in_set` 一条**：上一轮把失败机制**命名**了——20 个 DIAG 局全部恰好 669 帧、`NE` 占 0.587，即策略把"集合内的质量"塌缩到单一动作；`set_mass` 在集合内是**无所谓**的（π 全压在一个成员上时 `L_set` 仍是 0，梯度也趋近 0，见 `test_uniform_in_set_punishes_the_collapse_that_set_mass_ignores`）。`uniform_in_set` 直接针对这个已命名机制：它把集合内目标改成 `1/|S|`，塌缩会让损失留下 `(1/|S|)·Σ_{a∈S,a≠a*} -log π(a)` 的残差，因而**不能**靠塌缩把损失压到 0。这是最强的单因素检验，所以只跑它；`hinge` 只定义、不跑（跑第二条会是第二次运行，不是第二个因素）。

**默认形式逐位不变的证据**（`test_the_default_form_is_byte_identical_to_round_1` + `.tmp_v420_setloss/round1_reference_check.json`）：把上一轮的实现逐字复制成参考函数，在 float32/float64 × batch ∈ {1,2,7,32,128} × logit scale ∈ {0,1,5,12} 共 **40** 组随机张量上比较，默认调用的损失与其 **float64 位模式完全相同**（`max abs diff = 0.0`，诊断字典逐键相等）；对同一张量显式传 `mode="set_mass"` 也给出同一结果。

| 项 | 值 |

**塌缩消失了，而且是彻底消失**：上一轮 20 个 DIAG 局是**同一条** 669 帧的短轨迹（`NE` 0.587、10.5 个不同动作）；本轮 20 个 DIAG 局有 **19 种长度**，`NE` 降到 **0.132562**（低于 0.5 的门槛很多），每局平均用到 **17.3/18** 个动作（R0 只有 9.9），主导动作不再集中（`S` 8 局、`NE` 7 局、`NW` 3 局、`W` 2 局），主导动作占比均值只有 0.167755。S1N 口径同样（20 种长度、`NE` 0.122442、18.0 个不同动作）。

但是（§5）它没有换来泛化，也没有换来更长的生存：见 §7。

## 8 五条分支判定

| 分支 | 条件 | 本次 |
| ---: | ---: | ---: |
| ① | 机制 且 不塌缩 | ✗（机制 fail） |
| ② | **只不塌缩** | **← 成立** |
| ③ | 只机制 | ✗ |
| ④ | 都 fail | ✗（不塌缩成立） |
| ⑤ | 出现过关 | ✗（0/40） |

**成立的分支：② —— 塌缩是损失形式问题，泛化是数据问题（两个独立缺陷）。** 证据 JSON 里 `decision.branch_text` 的逐字机器串是：`no-collapse only: the collapse is a form problem and generalisation is a data problem (two independent defects)`。

逐条读数：

1. **损失形式确实是上一轮塌缩的原因之一**：同一 138 状态、同一超参、同一仪器，只把集合内目标从"无所谓"改成"均匀"，20 个 DIAG 局就从 **1 种长度 / NE 0.587 / 669 帧** 变成 **19 种长度 / NE 0.133 / 1139.9 帧**。这是单因素对照能给出的最强因果读数（形式变了、别的没变）。
2. **但泛化完全没有改善**：留出 set-hit 0.550000 → 0.450000，低于均匀随机参考 0.538889，离门槛 0.6389 更远。训练集仍是 1.000000（条件：`L_set` 2.036393 ≈ 形式下限 2.031161）。**换形式不可能解决"40 个留出状态没被学到"这件事**——那是数据规模/覆盖问题。
3. **能力仍为零**：40 局 0 过关，两个口径的均值都低于 R0（−510.5 / −713.4 帧），也远低于关口（13195 帧）。
4. **所以这两个缺陷是独立的**：形式缺陷（集合内无所谓 → 单动作塌缩）已被本轮修掉；数据缺陷（138 个训练状态、40 个祖先不交叉留出状态）没有被触到，而且看起来是当前的主要约束。

## 9 为什么"塌缩消失"却"帧数仍低于 R0"

* **R0 的行为是 `idle` 为主（diag 29.3%、s1n 33.5%）、9.9–12.2 个不同动作**；本轮策略是**几乎均匀地在 17.3–18 个动作上**（`idle` 只占 5.1%、`NE` 13.3%），主导动作占比只有 0.168。也就是说，它从"一个固定方向"变成了"近似随机方向"。
* 在一个需要**特定闪避方向**才能活过 669 帧之后那些弹幕的游戏里，近似随机方向并不比"一直在原地"更好：R0 的 `idle` 至少保持在原地不乱撞，本轮策略则到处移动。1139.9 帧 > 669 帧说明它比"常数 `NE`"好，但 1139.9 < 1650.4 说明"均匀乱动"并不比 A0 的保守行为好。
* 这与 §5 的留出测量一致：模型在 40 个留出状态上没有学到"哪些方向安全"，只学到了"在训练集的 138 个状态上把质量均匀铺在安全集合里"。**形式修正改变了塌缩方式，没有改变"没学到"这件事。**
* 一个可检验的推论（**本轮未做，属于第二因素/下一轮**）：如果缺陷主要是数据规模，那么扩大语料（更多 TRAIN 祖先上的安全集合）应当主要抬升留出 set-hit 与帧数；如果主要仍是形式，则 `hinge`（只要求 margin、满足即停）可能表现不同。本轮不允许加第二个因素，所以只把推论写在这里。

## 11 不能主张什么

* **这不是 R1**，也不是超出这 40 局的能力主张；R1 是本项目从未运行的 v4.1.0 WP02 曲线。
* 单训练 seed（0）、每口径 n = 20 dev 局、**无区间、无过关率**：40 局里 0 次过关是一个计数，不是"过关率上界"。
* 留出集是同一批 178 个 A1 状态的划分，不是 dev / confirm 划分，且与训练分享 H=120；它衡量的是"这 40 个状态是否被学到"，不是泛化到新轨迹。
* A1 状态落在 A0 自己的 TRAIN 轨迹（seed 3042–3091）上，是**诊断定位**，不是通用语料。
* 本轮只改损失形式：语料规模、奖励、预算、PPO 全部与上一轮相同（`one_factor` 逐项核对）。
* 未读 confirm 61000–61499、未碰 60000–60199、未改 `tools/**`、未改其它 configs/tests/证据文件。
* 帧数是描述性的：sd 327.8 / 355.3 帧，比与 R0 的配对差（−510.5 / −713.4）小不了多少；这里没有区间，也没有"已证明更差"的统计结论——只有 40 局的计数与均值。

## 12 剩余阻塞

* **分支 ② 的两个缺陷现在分开命名了，但只有一个被修掉**：形式缺陷（集合内无所谓 → 单动作塌缩）已由 `uniform_in_set` 消除；数据缺陷（138 状态 / 40 留出状态）仍在，且与"留出 set-hit 0.45 < 随机 0.5389"一致。
* **要判定数据规模是不是唯一约束，下一轮必须改语料（第二个因素）**，本轮明确不允许；在此之前不能声称"扩大语料就能解决"。
* **`hinge` 只定义、未运行**：它的 margin（ln 2）已冻结、测试已覆盖，但没有 40 局测量，不能与本次结果比较。
* 单 seed、n=20、无区间：任何"更好/更差"的排序都只是这 40 局的描述。
