## 0 结论摘要

1. **区分度是存在的，而且不小**：40 个状态 × 18 候选 = **720 条臂**，
   裁决 **`engine_alive = 476` / `engine_death = 244` / `unknown = 0`**，退出码全 0，
   fail-closed 零触发（`reset_retries = 0`、`prefix_retries = 0`、`arm_error = 0`）。
2. **|S| 直方图（0..18）**：`{0:1, 1:0, 2:3, 3:2, 4:0, 5:2, 6:0, 7:3, 8:2, 9:3,
   10:0, 11:2, 12:2, 13:2, 14:1, 15:0, 16:0, 17:2, 18:15}`，
   出现过的 |S| 有 **13 个不同值**（0/2/3/5/7/8/9/11/12/13/14/17/18）。
3. **四个互斥比例（分母 = 40 个状态）**：
   **|S|=18 占 37.5%（15/40）**、**1<|S|<18 占 60.0%（24/40）**、
   **|S|=1 占 0.0%（0/40）**、**|S|=0 占 2.5%（1/40）**。
   四档之和 40/40，且 40 个状态**全部**有完整裁决（无 unknown 污染）。
4. **判别状态率 = 24/40 = 60.0%**（fail-closed 口径：0<|S|<18 且 18 条臂全部有有效裁决）。
   远高于预注册的 5% 门槛，且**不是**靠单一桶撑起来的：|S|=18、2..17、0 三个桶都非空。
5. **分层看，规则比机器更能决定判别力**：
   T03 结转 6/6（100%）、dev 近死层 13/20（65%）、train 近死层 4/5（80%）、
   **固定帧控制层 1/9（11.1%）**。按距首死帧的 offset 分组：
   **offset ≤ 121 帧的 20 个状态里 18 个判别（90.0%）**；
   offset 165–301 帧的 13 个**非固定帧**状态里只有 6 个（46.2%）。
6. **成本**：720 条臂 **9,068.959 s（2.5192 h）**进程内墙钟、40 条命令合计 **9,895.863 s（2.7489 h）**；
   每臂 **min 4.309 / p50 12.4147 / mean 12.2215 / max 19.1312 s**；
   单条命令最长 **361.18 s**（state 20），全部 < 10 分钟上限。
   3 个分片进程并行，整段实际耗时 **≈ 60.5 min**（05:35:50 → 06:36:22）。
   **所有墙钟都是争用条件下的观测值**（同主机期间有别的代理在跑 T06 的 dev 评测，
   `loadavg` 峰值 38.5；线程固定为 1 后降到 ~2–3）。
7. **200 状态 × 18 候选的算术外推**：3,600 臂 × 实测每臂墙钟 ⇒
   **最好 4.309 h / 中位 12.415 h / 最差 19.131 h**。这是**算术外推，不是排期承诺**，
   且不含每条命令的解释器/引擎启动与任何排队。
8. **A1 目标可行，但要改抽样规则**：按本轮最有效的规则（首死前 30/60/90/120 帧）
   实测量级约 90% 判别率，200 状态 → 约 180 个 proper ≥ 门的 100；
   照抄"固定帧网格"则只有 11%，需要 ~909 状态才够 100，成本约 55 h，**不可行**。
9. **与 T03s 的对照**：T03s 用 3 条臂认定有区分度的 6 个状态，在本轮 A0 续行 + 18 候选下
   **6/6 仍然有区分度**（|S| = 12/7/2/2/11/13）；但两轮的 |S| **不可比**
   （臂集不同、续行 checkpoint 不同），只能读作"这 6 个位置在两种口径下都不是全存活"。
10. **本轮最容易被误读的一点**：|S|=18 的 15 个状态**不是**"18 个动作都同样好"，
    只是"在这 120 帧里都没死"；其中 8 个是固定帧控制层（离首死 **209–1328 帧**），
    属于**截断效应**而不是安全。

## 2 预注册：40 个状态怎么来的（跑前写死）

配置：[`configs/v420/a1-safe-set-pilot.json`](../../../../../configs/v420/a1-safe-set-pilot.json)
（sha256 `1a428dec0e6afe5ac8102d13c3086b0efa851a97fd280a5712e90a999232648e`）。
冻结清单：`.tmp_v420_data/T08/states_frozen.json`
（sha256 `f838980c7f9703a22051902f3b4e662e8e544dea676582cd840fdc5175036c90`），
在**任何一条臂开跑之前**由 `plan` 阶段写出，之后 40 条命令都读它。

**抽样规则（原文写在 config 的 `sampling_rule` 与 `strata` 里）**：

| 层 | 条数 | 规则 |
| --- | ---: | --- |
| `t03_carry_over` | 6 | T03s 报告"既有死亡又有存活"的 6 个状态，原样结转：(10,1448)(11,1716)(11,1760)(11,1896)(12,1704)(12,1736) |
| `dev_proximate` | 20 | dev seed `1000+i` 各 1 个，offset = 网格 `[30,60,90,120,165,210,255,300][i % 8]`，帧 = `floor_to_2(首死帧 − offset)` |
| `train_proximate` | 5 | train seed `3000+j` 各 1 个，offset = 网格第 `j` 项（30/60/90/120/165），同式取帧 |
| `fixed_grid` | 9 | dev seed 1000/1001/1002 × 帧 400/800/1200（控制层：远离死亡的普通状态） |

* **floor**：所有状态帧都向下取到 2 帧决策网格；**去重**：不同状态不得共享 (seed, frame)，
  `plan` 遇到重复直接拒绝而不是静默丢掉。
* **fallback（唯一的条件分支，形式也是跑前写死的）**：若某 seed 在 `probe.max_frames = 6000`
  帧内没有首死，或近死帧 < 40，则该 seed 的近死状态替换为固定帧 1200（并 clamp 到最后一个决策），
  逐状态记 `fallback_used = true` 与原因。**本轮 40 个状态全部命中主规则，fallback 用了 0 次**。
* **不使用**：`max_frames` 之外的状态、跨 seed 的重采样、事后挑选。**本轮没有改过一次冻结清单**。

## 3 一条臂的语义（全部来自既有实现，本试点没有新写臂逻辑）

```text
RESET(seed, stage=0, difficulty=1, team=0)            # 私有 cp -a 数据目录，env 角色
  -> 校验 RESET HASH == 记录 trace 的 frame 0 HASH（不等则重启进程重试一次）
  -> 按记录 trace 的逐帧掩码重放 1..state.decision_frame，逐帧比对 HASH
  -> 校验停放点 HASH == 该状态冻结的 expected_hash（不等即 fail-closed）
  -> 在停放点做一次学生前向（同时给出"学生自己的 argmax"，并与录制动作比对）
  -> 施加候选首动作 恰好 2 帧
  -> 循环 { 学生前向 -> 提交 2 帧 } × 59
  -> 到达 H=120 / 首次死亡 / 游戏结束 / 本地过面 = 有效完成；超时/缺帧/进程故障 = unknown
```

复用的既有函数（`touhou_rl/v420/counterfactual.py`，**一行未改**）：
`_run_student_episode`（探测）、`trace_prefix` / `Prefix`（前缀与 HASH 链）、
`_StudentSession`（env 进程、私有数据副本、逐帧 HASH 校验的重放、obs-v3 栈与动作历史）、
`_run_student_arm`（一条臂的全部语义）、`contracts.classify_branch_outcome`（唯一分类器）、
`contracts.safe_action_set`（唯一安全集合函数）、`summarise_contrast`（交叉核对）、
`rl.check_data_dir`（数据目录 fail-closed 门）。

**唯一没有复用的是 `_run_contrast_state`**：它按设计把每状态限制在 2–4 条臂
（`contrast_arms_max`）。本轮需要"同一状态跑 18 次、每次换首动作"，
所以驱动脚本 `.tmp_v420_a1/a1_pilot.py` 直接对 18 个候选各调一次 `_run_student_arm`。
这是**复用既有能力**，不是重写：臂语义、分类、安全集合、数据目录门都在原模块里。

**学生身份**：A0 = `.tmp_v420_data/T04/checkpoints/a0_seed0_step5000.pt`，
sha256 `96cb219eac83391f42b18ea656b5a6c5ac81e97cd1fd8c1e2c0d404aee6b89ad`，
arm `B0`、`ProbeNet`、731,802 参数，经冻结 v4.1.0 loader 加载（`load_v410_checkpoint`），
argmax over 18 路 move logits、bomb 恒 0。每条臂/每条 shard 都重算了一次 sha256 并与配置比对。

**端到端自检**：34 个挂在 A0 自己轨迹上的状态，**34/34** 的学生前向 argmax 复现了录制动作；
另 6 个 T03 结转状态重放的是 B0 的 trace，其中 3 个（state 2/3/5）与录制动作不同——
这是**预期**的，不是故障（不同 checkpoint 在同一状态上有不同 argmax）。

**逐帧 HASH 校验**：**976,140 次 / 0 处不一致**（720 条臂各自的 RESET + 前缀重放）。

## 5 unknown 与 fail-closed

| 项 | 值 |
| --- | ---: |
| `unknown` 臂 | **0** |
| 触发 fail-closed 的臂（`error` 非空） | **0** |

**口径（写进 config 的 `unknown_policy`）**：`unknown` 永不变成 `engine_alive`、永不变成

两种数都写进了证据 JSON（`discriminating.rate_over_all_states` 与

`reference_proper_18 = 24`。也就是说 |S| 与直方图**不是本试点自己算的一套数**，

> 一处必须点明的方法差异：`summarise_contrast` 的 `proper_18` 只检查
> `0 < |S| < 18` 与臂数，它会把"17 活 + 1 unknown"也记成 proper。本轮 unknown = 0，

## 9 边界与不能主张什么

1. **不是 G420-1**：40/200 状态、24 个判别状态、28 条 seed 祖先（门要 200 / 100 / ≥10）、
   没有做 200 状态全量重复。门的通过状态**未变**：`passed = false`。
2. **`|S|=18` 不等于"18 个动作都安全"**：H=120 是截断视界；15 个全活状态里 8 个是固定帧控制层
   （离首死 209–1328 帧），它们只是"这 120 帧里没死"。
3. **`|S|=0` 不等于"这个状态必死"**：它等于"在这 18 个首动作 × 这段 H 里没有一条活到 H"。
   状态 22 的 18 条臂死亡帧相差 89 帧，说明首动作确实改变了轨迹，只是没改变结局。
4. **状态是诊断定位，不是评测**：34 个新状态挂在 A0 自己的 dev/train 轨迹上，
   其中 dev 1000–1019 是 development 曝光；本轮不产生任何过关率/分数结论。
5. **两轮的 |S| 不可比**（§7）：臂集与续行 checkpoint 都变了。
6. **墙钟不是性能基准**：全部是争用条件下的观测值，同一台机器空载时会更快（state 31 4.35 s/臂）。
7. **A0 是单 checkpoint、单训练 seed（0）**：本轮所有结论只在 A0 上成立，
   换成 D2（`9f284e48…3751b6`）或 B0 需要重跑，不能外推。
8. **dev 与 train 混在 40 个状态里**：本轮是标签可行性试点，不是泛化测量；
   若 A1 正式跑，状态的 seed 层必须按 gate 口径重排（≥10 条互不相同的**训练**祖先）。
9. **教师查询 = 0**：本轮没有测"教师在该状态的动作"，也没有把教师动作当臂；
   18 个候选全部是"首动作 × 冻结学生续行"。
10. **没有训练**：本轮不产生任何 checkpoint，也不改变任何既有 arm 的任何数字。
