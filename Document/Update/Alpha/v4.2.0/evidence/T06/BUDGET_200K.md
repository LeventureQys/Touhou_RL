## 0 一句话结论

**唯一的变量是预算，跑完了：200,000 帧 / 100,018 决策 / 90 局 / 196 次更新 / 3,735.5 s
（53.54 fps），90 次终局奖励全部进入 PPO，checkpoint 被冻结 evaluator 逐位读回（logits 差 0）。**
两口径各 20 dev 的结果是 **diag 1,575.2 帧**、**s1n 2,808.6 帧**（§6），
跑前写死的两条腿（`diag ≥ 1636.8` 且 `s1n ≥ 3011.5`）**都没到**，
偏离 **−61.6 帧（−3.76%）** 与 **−202.9 帧（−6.74%）** ⇒ **预测 fail**（§7）。

**这否掉的是"49 次更新不够"这个假设，而不是"预算没用"这么简单**：
相对 50k 的同 seed 配对差是 **−14.0（diag）/ −83.0（s1n）**，
其 95% 区间 **[−237.5, +209.5] / [−476.9, +310.9]** 都包含 0 ——
**把预算 ×4（49 → 196 次更新）在这个仪器上测不出任何变化**，
`R2→R0` 的缺口闭合率甚至从 **93.63% / 89.15%** 变成 **91.76% / 81.64%**，
每 +1 万帧的边际收益是 **−0.93 / −5.53 帧**（50k 时是 +140.0 / +197.0）。
按 §2 预注册的判定规则，结论是：**奖励可见性不是这条差距的主因**，
"再攒预算"也解释不了它（§8 据此给出 200k→1M 的判断）。

同时有两个**没有被削弱**的正结果：r3@200k 对 R2 无锚仍然是 **20/20 逐 seed 全胜**
（+685.85 / +902.2 帧，t = 9.85 / 8.22），说明"奖励可见性 + KL 锚"的增益在另一个预算点上**可复现**；
两臂都是 **0/20 过关**，所以本档**没有任何能力结论**。

## 2 跑前写死的预测与判定规则

写在配置的 `budget_only` 块里（`frozen_before_run: true`），跑完之后才填数字：

| 腿 | 门槛（R0 的 20 dev 均值） | 判定 |
|---|---:|---|
| `diag_first_death` 均值 | **≥ 1636.8 帧** | 与另一腿同时成立才 hold |
| `s1n` 均值 | **≥ 3011.5 帧** | 同上 |
| n | 20 | dev seeds 1000–1019，两口径各 20 |

判定规则（原文，跑前冻结）：

- 两腿都 hold ⇒ **49 次更新的预算才是绑定约束**：r3 的排序信号在预算 ×4 之后换成了帧数。
- 任一腿 fail ⇒ **奖励可见性不是这条差距的主因**（200k 仍到不了未训练但带锚的 R0），
  下一个问题在策略侧（优势归一化、rollout 长度）或奖励表，各自都必须先另立预注册。
- 无论判定如何，**不调** ε/δ/β/lr/温度/γ/奖励表/rollout 长度。

5. 两臂都是 **0/20 过关**：没有任何能力结论。

**据实判定**：这是一次**可证伪预测的失败**，而且失败方向和 50k **不同**——
50k 是"差 2.91% / 3.98%"，200k 是"差 3.76% / 6.74%"：diag 的缺口略宽，
**s1n 的缺口从 −119.9 帧扩到 −202.9 帧（1.69 倍）**。
按 §2 跑前冻结的规则，`if_either_leg_fails` 分支成立，原文照录：

> **reward visibility is NOT the main cause of the remaining gap to R0**: the 200k
> checkpoint still does not reach the untrained-but-anchored reference, so the next
> question is the policy side (advantage normalisation, rollout length) or the reward
> table, each needing its own pre-registration before its own run.

**但要同时说清楚两件事**，否则这条判定会被读成比证据更强：

1. 200k 相对 50k 的下降**不可分辨**（§6.4：t = −0.13 / −0.44，区间含 0），
   所以"预算越多越差"**不成立**；正确说法是**预算这个变量在本档的测量精度内是平的**。
2. 200k 相对 R0 的下降同样**不可分辨**，所以"r3 到不了 R0"在本档只能说成
   "点估计仍低于 R0，且本档没有把它拉上去"，不能说成"确认存在 3–7% 的真实差距"。

**结论仍然成立且不依赖上面两点**：把更新次数从 49 提到 196，**没有**把点估计推到 R0 线上，
也没有把 r3 相对 R2 无锚的增益再放大。

## 8 预算曲线：50k → 200k

| 量 | diag | s1n |
|---|---:|---:|
| R0（20 dev 均值） | 1,636.800 | 3,011.500 |
| R2 无锚（20 dev 均值） | 889.350 | 1,906.400 |
| R3 @50k（20 dev 均值） | 1,589.200 | 2,891.600 |
| **R3 @200k（20 dev 均值）** | **1,575.200** | **2,808.600** |
| 50k → 200k 变化 | −14.000 帧 | −83.000 帧 |
| 50k → 200k 变化率 | −0.881% | −2.870% |
| R2→R0 缺口 | 747.450 帧 | 1,105.100 帧 |
| 缺口闭合率 @50k | 93.630% | 89.150% |
| **缺口闭合率 @200k** | **91.760%** | **81.640%** |
| 闭合率变化 | −1.870 个百分点 | −7.510 个百分点 |
| 200k − R0 | −61.600 帧 | −202.900 帧 |
| **每 +1 万帧的边际收益（50k→200k）** | **−0.933 帧** | **−5.533 帧** |
| （参照）50k 从 R2 起步每 +1 万帧 | +139.970 帧 | +197.040 帧 |

边际收益的算法：`(x_200k − x_50k) / (150000 / 10000)`，即把 15 万帧的增量摊到每 1 万帧；
括号里的参照行用 `(x_50k − x_R2) / (50000 / 10000)`，同一个口径。

**曲线形状**：预算从 0（R2 无锚 889.4 / 1906.4）到 50k（1589.2 / 2891.6）是**陡的**
（每 1 万帧 +140 / +197 帧），从 50k 到 200k 是**平的且略负**（−0.93 / −5.53 帧）。
两者合起来是本档唯一的"曲线"信息：**有效区间在 0→50k，50k 之后这条维度就饱和了**。

**200k→1M 是否值得（一句话）**：**按本档证据不值得** —— 从 50k 到 200k 的边际已经是
−0.93 / −5.53 帧每万帧，再花 5 倍帧数（3 seed × 1M 的实测成本 14.0 h 空载 / 31.6 h 争用，
需另编预算）只会把同一个已饱和的方向放大 5 倍，除非**先**给出"存在某个 >200k 的阈值"的
独立假设（本档没有任何阈值证据），否则那笔钱应该花在策略侧那个第二因素上，而不是预算上。

## 9 并发与墙钟口径（哪些数字不能用）

本档在同一台 20 vCPU 主机上运行，**没有杀任何进程**，也没有与被禁的 `/root/v400-data`
或任何 `.tmp_v410_*` 目录发生读写。运行期间同机有**别的任务的引擎进程**在飞

| 时间点 | loadavg (1 min) | 本档进程 |
|---|---:|---|
| 200k 起跑 | 3.17 | 训练（单实例） |
| 训练第 1 次更新前后 | 6.32 | 训练 |
| 训练中段 | 4.78 / 4.64 / 4.01 / 3.37 | 训练 |
| 训练后段 | 1.98 / 1.56 / 1.47 | 训练 |
| 训练结束（`load_after`） | 1.66 | — |
| diag 4 批之前 | 3.41 / 4.08 / 3.06 / 1.65 | 评测（单实例） |
| s1n 4 批之前 | 2.06 / 2.92 / 6.57 / 6.88 | 评测（单实例） |

**所以 53.54 fps / 3,735.5 s 不是"独占主机"的基准**，它是"load 0.5–6.3、期间有别的任务"
条件下的观测值。可以用的比较只有两类：

- **同一档内部的相对量**（每 rollout 分片 4.7–25.8 s、单片全部 < 10 min、总墙钟 3,740 s）；
- **算术换算**（200,000 / 53.54 = 3,735 s，与实测一致；200,000 / 49.39 = 4,049 s 是把
  r3 50k 的速率套到 200k 上的预估值，实测比它快 7.7%，因为后段 load 降了）。

**不能用的**：把 53.54 fps 和 r3 50k 的 49.39 fps（load 4.4–7.1）直接比成"200k 更快"，
也不能把它外推成 1M 的排期承诺。本档只报观测值。

**单条命令的 10 分钟上限**：训练用 `timeout 7200` 兜底、实测 3,740 s（一条命令跑完，
**没有分段重启** —— 引擎的活 episode 由训练器的 `collect_rollout(resume=carry)` 跨 rollout
携带，重启会丢掉这个状态，所以本档刻意不分段）；8 条 dev 各 137–258 s，全部在 10 分钟内。

**一个必须披露的写点**：`rl.run_pilot()` 内部固定调用
`private_data_dir(config, "pilot")` → `$V420_DATA/T06/data/pilot`（`rl.py` 的硬编码，本档**不能改**），
所以 200k 训练期间引擎写的是那个目录里的 `score.dat`/`th08.cfg`（内容是从本档私有的
`engine-data-r3b200` copy2 过来的一份副本，两个大 blob 是符号链接）。这不是本档新增的实验目录，
而是"跑一次训练必然要刷新的运行时私有目录"；r3 50k 那次也刷过同一个目录。**除此之外本档只写**
`.tmp_v420_data/T06/{b200,dev-r3b200,checkpoints/r3b200_*,engine-data-r3b200*}` 与 `.tmp_v420_b200/`。

**还有一个并行的 1M 档**：本档结束前后，`.tmp_v420_data/T06/` 下出现了另一个任务的
`b1m/`、`engine-data-r3b1m*`（07:11）。§8 关于 200k→1M 的判断**只根据本档的 50k / 200k 两个点**；
如果那个并行 1M 档产出实测，它应当覆盖 §8 的方向性判断，本档不为它背书、也没有读它的数字。

## 10 边界与据实的下一步

### 10.1 不能主张什么

1. **不能说"200k 更好"或"200k 更差"**：200k − 50k 的两腿区间都含 0（t = −0.13 / −0.44）。
2. **不能说"确认 r3 比 R0 差 3.8% / 6.7%"**：点估计低于 R0，但区间含 0；
   预注册规则是点比较，所以判 fail —— 这是**规则判定**，不是效应量确认。
3. **不能说任何能力结论**：两臂两口径都是 0/20。
4. **不能说 1M / 3 seed 的行为**：本档仍是 **1 个训练 seed**、200k。
5. **不能把 r3 说成 R1**：奖励用引擎真值，是训练期特权诊断。
6. **不能说"奖励可见性无效"**：它相对 R2 无锚是 20/20 逐 seed 全胜、t = 9.85 / 8.22。
7. **不能说"预算无用"**：只能说"在本档的测量精度内，50k→200k 的预算增量没有可测出的收益"。
8. **不能把 §6.4 的 t 区间当成"本档选的样本量"**：20 个 dev seed 是冻结的分配，
   区间只用于区分"没变化"和"变化小于仪器分辨率"。
9. **不能引用 P4 的授权**：P4 仍是 `not_authorized_premise_false`。

### 10.2 据实的下一步（按本档证据强度排序）

1. **先关掉预算这条轴**：不要再为"攒更多帧"编预算。200k→1M 的边际是 −0.93 / −5.53 帧每万帧，
   而 1M × 3 seed 的实测成本是 14.0 h（空载）/ 31.6 h（争用），**需要另编预算**；
   在没有"阈值假设"之前，这笔钱买不到本档能测出的东西。
2. **把第二因素放到策略侧**：`advantage_normalisation = true` 会把优势幅度抹平，
   这是 [`R2_COLLAPSE_DIAGNOSIS.md`](R2_COLLAPSE_DIAGNOSIS.md) H3 点名的第二个机制，
   也是本档 §10.1 第 6 条之后唯一还站得住的候选。它是 **PPO 改动**，必须单独预注册；
   成本低（同 50k 预算 ≈ 17 min 训练 + 8 批 dev ≈ 26 min）。
3. **补同轮"r3 但 ε=δ=0"的消融**（[`REWARD_R3.md`](REWARD_R3.md) §10.2 第 3 条）：
   本档已经证明"奖励 + 锚"相对 R2 无锚的增益在 200k 上复现（20/20），
   但仍不能把 +685.85 / +902.2 严格归因到奖励而不是轮次差异；这一条成本最低、信息量最大。
4. **先解决 dev 分辨率，再谈 3–4% 的差距**：n=20 的配对区间宽 ±220 / ±400 帧，
   任何小于 ~5% 的效应在这台仪器上都测不出；要么换更大的 dev 分配（需要协议/预算决策），
   要么把判据从"点比较"改成"区间比较"（那是判据修订，必须先声明再跑）。
