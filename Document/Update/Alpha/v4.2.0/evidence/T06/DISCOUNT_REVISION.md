# T06 / WP420-05：唯一一次折扣修订（τ = 30 s → 200 s）

对象：v4.2.0 `T06`（WP420-05）审计项 `reward_discount_horizon` 的修复。
运行产物：[`discount_revision.json`](discount_revision.json)（本文件全部数字由它生成）。
原始运行：`.tmp_v420_data/T06/audit2.json`
（`tools/rl/v420.py rl --config configs/v420/rl-engine-audit.json --out ... --execute`，退出码 **0**）。

**结论：修订成立，`reward_discount_horizon` 由 fail 转 pass，审计 17/17 全 pass。**
修订只改了 τ（以及由它复算的 γ）——奖励表所有系数逐字节未动。

> R2 uses engine-truth reward and termination, so it is a training-time privileged
> diagnostic: it is NOT strict pixel self-improvement (R1) and no result here may be
> reported as R1.

## 1 诊断：为什么允许改、为什么必须改

WP420-05 §5 的原文把 `Δt = 2/60 s、τ = 30 s、γ = exp(-Δt/τ) ≈ 0.99889、GAE λ = 0.95`
定义为**初始配置，而不是最优参数断言**，并允许在**有具体诊断依据**时做**一次**
学习率/KL 类修订（不得连续试错）。本项就是那一次修订，诊断依据是上一档审计里
唯一失败项的实测值：

| 量 | τ = 30 s 时的实测 |
|---|---|
| 真实过关轨迹长度 | T = **6,598 决策**（13,195 帧，≈ 219.9 s） |
| 有效视界 `1/(1-γ)` | **900.5 决策**（30.0 s） |
| 终局权重 `γ^T` | **6.548455766e-04** |
| 1.0 过关奖金到终点的价值 | **0.000654846** |
| 一次死亡罚分 | 0.25 |
| 倍数关系 | 过关奖金比一次死亡罚分**小 382 倍** |

即：冻结的 τ 让“过面”这件事在 220 秒的任务长度上几乎不可见，
`1/(1-γ)` 的 900 决策视界与 6,598 决策的任务长度直接冲突。这不是奖励表排错
（`reward_ordering` 一直 pass），而是 γ 与任务长度不匹配。

## 2 事前规则（先写进 config，再跑）

规则写在 `configs/v420/rl-engine-audit.json` 的 `discount_floor` 与
`discount.revision` 两个块里，在修订**应用之前**就存在，跑完不改：

> 在候选 `[200, 300, 400, 600]` 秒中，选**使 `γ^T_clear ≥ 0.30` 的最小 τ**
> （`γ^T` 与有效视界都随 τ 单调递增，所以“最小合格 τ”等价于“最小化视界延长”）。

规则只依赖 `Δt`、候选 τ 和**已经测得的**过关长度 T = 6,598，
不依赖任何审计或训练结果，所以这张候选表在任何运行之前就能算完
（`rl.discount_candidate_table()`，纯算术）。

## 5 为什么这不是"为了让门通过而放宽容忍度"

四条可以逐条核对的理由：

1. **新下限比旧判据更严。** 旧判据是隐式的
   `stage_clear_bonus·γ^T > death_penalty`，在冻结的奖励表上等价于 `γ^T > 0.25`。
   显式下限取 **0.30 > 0.25**，是把门抬高，不是降低。
2. **它必须能否决 τ = 30 s，而它确实否决。** `6.548e-04 < 0.30`（差 458 倍），
   `|clear|/|early| = 0.052 < 1.5`（差 28 倍）。一个能被被否决的配置满足的阈值
   不可能"为了通过而放松"。
3. **第二条阈值是旧判据里根本没有的新条件。** 旧判据只谈终局权重，不谈类别边际；
   `|clear|/|early_death| ≥ 1.5` 是新增的信息量要求。
   它必须写成**量级**形式：早死的折扣回报是负数，字面形式
   `clear ≥ 1.5·early_death` 对任何正的 clear 都成立，
   **反而无法否决 τ = 30 s**（τ=30 时 clear = 0.006047 ≥ -0.174366），
   所以字面形式是空条件，不能作为判据。
4. **config 只能抬高、不能降低。** `rl.resolve_discount_floor` 拒绝任何低于
   冻结下限的配置值（有单测覆盖），所以后来的运行无法靠改 config 放水。

## 6 只改了什么

| 项 | 状态 |
|---|---|
| `tau_seconds` | 30.0 → **200.0** |
| `gamma` | 复算 `exp(-Δt/τ)` → **0.9998333472214507**（不手写，config 与模块互相校验） |
| `delta_t_seconds` | 0.0333333（= 2/60）不变，仍是契约常量，不是自由参数 |
| `gae_lambda` | 0.95 不变 |
| `stage_clear_bonus / death_penalty / bomb_penalty / progress_total / survive_per_decision` | **1.0 / 0.25 / 0.1 / 0.5 / 0.0，逐字节未动** |
| `clip / actor_lr / critic_lr / entropy_coef / epochs / minibatch` | 未动 |
| 折扣版本号 | `v420-discount/1` → **`v420-discount/2`**（唯一一次修订的可追溯标记；旧号记在 `version_legacy`） |

未做的事，也写清楚：**没有**因为本次修订更换任何奖励系数，**没有**在
`reward_discount_horizon` 仍失败时连续换 τ 试错——如果修订后仍不过，本档会如实写
fail 并停下。事实上修订后一次通过（见 §7）。

## 8 边界

- 修订解决的是**可见性**：终局过关奖励在 220 s 的任务长度上不再是噪声，
  它**不**证明 1M 档能训练出过面策略。
- 一次修订 + 一次 17/17 审计通过，不等于 3 seed × 1M 的结论。
- `G420-R` 仍是 **not_passed**（缺口见 [`RL_PILOT2.md`](RL_PILOT2.md) §6）。
