## 1 实现：唯一改动

### 1.1 损失项

```
loss = policy_loss + value_coef · value_loss − entropy_coef · entropy
       + beta · mean_t KL( softmax(z_A0) ‖ softmax(z) )
```

- `z` 是策略的**原始 logits**（`move_head` 输出，**不除温度**）；`z_A0` 是同一批观测上
  参考模型前向得到的原始 logits。
- 方向是 `A0 ‖ π`：`KL(p_A0‖p_π) = Σ p_A0·(log p_A0 − log p_π)`；它对 `z` 的解析梯度是
  `softmax(z) − softmax(z_A0)`，单测用这个闭式对照 autograd，不靠约定。
- 空间钉死 **T=1**：配置里 `space` 只能是 `"T1"`，否则 `load_rl_config` 直接拒绝
  —— 塌陷发生在部署空间（3.276 nat 对 T=8 的 0.281 nat，低估 11.6×），锚必须量在同一个空间。

### 1.2 参考模型：只读、冻结、不进图

`FrozenReference`（`touhou_rl/v420/rl.py`）从同一 checkpoint **再 load 一次**：

| 性质 | 实现 | 运行期实测 |
|---|---|---|
| 与 actor 是**不同对象** | `assert_disjoint()` 按参数 `id()` 比对，共享即 `RlError` | `shared_parameters = 0` |
| 不参与梯度 | 全部 `requires_grad_(False)`；前向在 `no_grad` 下；进 loss 的是 **detach 后的数组** | `requires_grad_true = 0`、每个参数 `grad is None` |
| 全程不动 | 前后各算一次全部权重的 sha256 | `fingerprint_before == fingerprint_after == 97497ab10a27…0e89` |
| 前向次数 | 每次 rollout 一次（49 次） | `forward_calls = 49` |

### 1.4 逐 rollout 的 `max_t` 与门

每次 rollout（512 决策）在**更新前**与**更新后**各量一次
`max_t KL_T1(A0‖π_t)`（512 个 transition 的逐行 KL 取最大），记 `before`/`after`/`max_t`；
全程的界 = 所有 rollout、所有时刻的最大值。`kl_anchor_gate()` 判 `passed`（有限且 ≤ 阈值），
`apply_kl_anchor_gate()` 在失败时写 `status = "failed"` + `failure` 说明并返回**退出码 3**，
**保留 checkpoint**（失败必须可诊断，不能连产物一起毁掉）。`nan`/`inf` 一律算失败。
本轮运行**确实**被门判失败：`PILOT_KL_EXIT=3`、载荷 `status = "failed"`。

### P1 机制 —— **fail**（并说明这是判据不可达）

- 逐 rollout 的 `max_t`：均值 **0.40175**、sd 0.13378、min 0.19938、**max 0.87934**（第 6 次更新）、
  首 0.35492、末 0.36494。**49/49 个 rollout 全部超 0.05。**
- 同一时刻的 `mean_t` 只有 0.007027–0.023092 nat（末值 0.016757）——**最大与平均差约 24 倍。**
- **同一策略在 P2 那批 2×256 冻结槽上，同一定义（`KL_T1(A0‖p)`）的对比集统计量**：
  均值 **0.005817 nat**、中位数 0.000363、p99 0.058404、**max 0.085348**、
  只有 **6/256** 行超过 0.05、**0 行**超过 0.10（R2：均值 3.275952、max 13.172151、
  **214/256** 行超 0.05）。
- 也就是说：0.05 nat 这个界，量在**对比集**上只差 1.7 倍（0.0853）；量在**单轨迹约 5 万个时刻取最大**上
  差 17.6 倍（0.8793）。A0 在部署温度下行熵只有 0.2396 nat，少数"无差别"状态的 logit 微动
  就能把单点 KL 顶到 0.2–0.9，而**这些行几乎不翻转 argmax**（R2-kl 的 top-KL 行全部
  `argmax_flipped = false`、A0 `top1−top2` 只有 0.35–2.80；R2 的 top-KL 行 13.17 全部翻转）。
  所以这条预测按字面 fail，**它失败在统计量的尾部，不是漂移复发**：`mean_t` 曲线全程平、
  不增长，末值 ≈ 起点。
- **代码里的 fail-closed 门完全没动**：阈值仍是 0.05，运行被判 `status = "failed"` + 退出码 **3**，
  checkpoint 保留。判据修订只发生在**判定文字与后续预注册**里（§8），不是改代码放行。

### P4 判别 —— **未触发**

P4 的前提是「P1 成立 ∧ P2 成立 ∧ diag < 1473」。本轮 **P1 fail、P2 fail、diag = 1512.1 ≥ 1473**，
三段前提**三段全不成立**，所以：

- **不能**说"漂移被洗清、下一个目标是奖励与尺子错位"——那需要 diag 掉到 1473 以下；
  本轮 diag 反而回到了带内。
- **也不能**断言相反的结论（"奖励完全无罪"）：奖励对度量的盲区仍然是被测过的
  （R2 档：24/24 `game_over` ⇒ 死亡项恒为常数、回报方差的 100% 来自 progress、
  `corr(return, 首死帧) = 0.354` 对 `corr(return, 总帧) = 0.705`）。本轮只是**没有授权**
  把它当成下一步的唯一目标。
- 一句话：**本轮把"漂移"这一侧的量测做实了，但没有走到能把"奖励"那一侧定罪的判别点。**

## 5 这次修订证明了什么

1. **锚在部署空间确实生效，量级可测**：同一批冻结槽上 `KL_T1` 均值 3.276 → **0.0058 nat**（÷563）、
   argmax 翻转 61.7% → **1.17%**、部署熵 0.411 → **0.245**、前三动作从 `focus-E/idle/E`
   回到 **`idle/E/W`（与 A0 相同）**。
2. **权重漂移幅度没变，函数漂移被改了方向**：`max|ΔW|` 2.68e-3 对 3.37e-3，但函数差 563 倍。
   这直接反驳了"只要限制参数位移就能防塌陷"的做法。
3. **行为侧同向**：20 dev diag **+622.75 帧（20/20 全正）**、s1n **+719.60（20/20 全正）**；
   训练内部首死从 R2 的 −29.3% 变成 **+15.5%**。
4. **失败的是判据，不是机制**：P1 的 0.05 nat 单轨迹最坏值在 β=1.0、A0 行熵 0.24 nat 的条件下
   不可达（对比集上只差 1.7 倍）；P2 的两半测的是两件事；P3 只差 s1n 84 帧。
5. **门是活的**：运行被自己的 fail-closed 门判 `failed` 并退出 **3**，没有静默通过。

## 6 不能主张什么

1. 不能把任何数字写成 R1 或能力结论；R2 是训练期特权诊断，两臂 **0/20** 过关。
2. 不能说 KL 锚提升能力：50k 档它最多只能**阻止**漂移，本轮 `stage_clear = 0`（21 局全 `game_over`）。
3. 不能说"漂移是唯一原因"：P1/P2/P3 按字面都没 hold，**P4 不被授权**，奖励/尺子错位这条替代解释
   既没被证实也没被排除。
4. 不能说 1M / 5M / 3 seed 的任何结果；本轮只有 seed 0 的一个 50k 档。
5. 不能说 `0.05 nat` 这个界已经被满足；它被违反了 **17.6 倍**（单轨迹）或 **1.7 倍**（对比集）。
6. 不能说评测条件与 R2 完全相同：数据目录是两条流各自的私有副本（`T06/data/kl-eval-{diag,s1n}`），
   不是 R2 用的 `T06/engine-data-gamesrc`。同一 checkpoint 的两次 20 局 diag 测量逐帧相同，
   说明这把尺子在**同条件**下确定；跨目录的可比性仍只有"经验上惰性"（H5：gameplay 三个 blob 逐字节相同，
   只有被引擎重写的 `score.dat` / `modern-files.txt` 不同），不是"证明惰性"。
7. 不能说 P4 的 `reward_ruler_mismatch` 分支已被授权（见 §4）。
8. 不能说这台机器上的墙钟是可比的性能数字（见 §7）。

## 8 据实的下一步

按规格的两条分支都不成立（P3 不是 hold，所以**不能谈 1M**；P3 fail 但 **P1/P2 也不是 hold**，
所以**不能按 P4 转向奖励错位**）。据实的下一步是**三次预注册层面的事，不是第三次跑**：

1. **判据修订（先做，且必须下一次跑前写死）**：把 KL 界从"单轨迹 `max_t`"改成
   **对比集策略 KL**（2×256 冻结槽的均值与 p99，本轮实测 0.005817 / 0.058404），
   `max_t` 降级为**报告项**。理由是可测的：同一个 β=1.0，对比集上 0.0853（距 0.05 差 1.7×），
   单轨迹上 0.8793（差 17.6×），而 A0 行熵只有 0.24 nat。
   **这不是放松**：代码里的门不动（仍 0.05、仍 fail-closed、本轮仍记 `failed`/退出 3），
   原始 P1/P2 数字全部保留在 `rl_kl_anchor.json` 里供人复核。
2. **P2 拆成两条独立预测**：翻转率（本轮 0.0117，hold）与逐动作均值位移（本轮 1.5156，fail）
   约束的是两件不同的事，合取会掩盖"到底哪一半没达标"。若保留后者，β 只能**调大**（唯一合法方向）。
3. **P3 若还要用 ±10% 带，就把两口径分开判**：diag 本轮已经进带（1512.1），s1n 只差 84 帧（3.1%）；
   合取会把"diag 进带"这个真实结论埋掉。
4. **1M 的门**：本轮不足以为 1M 提供依据（P1/P2/P3 未全 hold）。若要做 1M，
   必须先有按上面 1–3 改写的预注册，并在 50k 上按新判据复现一次（**不加第二个因素**）。
5. **r3（生存奖励项）是另一个实验**，不是本轮的替代路径：本轮没有跑它，也没有测它与锚的交互；
   它的 50k 结果出来之前，不能用"奖励错位"解释本轮的 s1n 差 84 帧。
