| 口径 | band（预注册） | 锚 | 实测 mean | n | 判定 | 偏离量 | 占锚 % | 距带中 |

**判定**：

1. **diag 腿 = hold**：1512.1 在 1473–1800 内，偏离 0 帧；比带中心低 124.4 帧（−7.6%），
   仍在 R0 的 ±10% 内。
2. **s1n 腿 = incomplete**：本档 10/20，观测均值 2499.8，比带下界低 210.2 帧（−6.98%）。
   完整 20 局样本只存在于独立复现（**2626.0**，比带下界低 84.0 帧），**本档不据此判定该腿**。
3. **P3 整条 = `incomplete`**（diag hold / s1n incomplete），**不写成 fail**。

**一个必须写下来的观察**：本档自有的 10 个 seed（1000–1004、1010–1014）均值是 **1446.9**，
比带下界还低 26.1 帧；而 20 局里另外 10 个 seed（1005–1009、1015–1019）均值是 **1577.3**。
也就是说，**如果拿 10 局子样本去套 20 局判据，会得出相反结论**。判据要求 20 局不是形式主义：
单局 sd 160.65 帧 ≈ 均值的 10.6%，20 局均值的标准误约 35.9 帧（≈2.4%），而带半宽只有 10%
——**"在带内"只是一个 2 倍噪声量级的相容性判断，不是与 R0 的精确相等**。

### 5.1 与同 checkpoint 的 KL-锚证据文档的关系（必须写清）

同一个 checkpoint 的 [`RL_KL_ANCHOR.md`](RL_KL_ANCHOR.md)（**另一位代理**拥有它自己的 20/20
s1n 样本）把 **P3 判为 fail（合取）**，因为它的 s1n 20 局均值 2626.0 比带下界低 84 帧。

两份文档在**所有数字上逐值一致**（diag 1512.1、s1n 2626.0、diag 配对 +622.75 / 20 全正、
冻结槽翻转 0.0117 vs 0.617、`max_a|mean_s Δlogit| 1.5156`、P1 0.8793 vs 0.05）。差别只在
**谁拥有该腿的完整样本**：

- **本档**：自有 s1n 10/20 ⇒ 不替该腿下判定，P3 写 `diag hold / s1n incomplete`；
- **KL-锚档**：自有 s1n 20/20 ⇒ P3 写 fail（合取）。

**合并读法**：diag 腿 hold；s1n 腿在**取到的两个样本里都在带下**（自有 10 局 2499.8、独立跑 20 局
2626.0），所以 P3 的合取结论落在 s1n 腿上 = **fail**。这个判定属于
[`RL_KL_ANCHOR.md`](RL_KL_ANCHOR.md)（它拥有完整样本），本档只提供 10 局独立复核与逐值一致性。
本档的 [`r2_kl_p3.json`](r2_kl_p3.json) 里 `p3.verdict` 仍写 `incomplete`，这是**覆盖口径**的
表述，不是对该腿数字的否认。

## 7 P1 / P2 / P4

### 7.1 P1 = **fail**（判据不可达，不是实现错误）

| 量 | 值 |
|---|---|
| 声明阈值 `max_t KL_T1(A0‖π_t)` | **0.05 nat** |
| 实测最大 | **0.8793413160101484**（update 6） |
| 裕度 | **−0.8293 nat**（超阈 **17.6 倍**） |
| 超阈 rollout | **49/49**（整个 50k 没有一次通过） |
| 全网最小 `max_t` | **0.19937977870743498** = 阈值的 **3.99 倍** |
| 每个 rollout 的 mean KL 范围 | 0.0070 – 0.0231（均值从未超阈，但最大行从未低于阈值的 4 倍） |
| 运行状态 | `status: "failed"`（fail-closed），checkpoint 仅作诊断保留 |

**结论**：这是**判据不可达**——把"整个 50k 帧（**25,008 个决策位置**）逐点取最大"限制在
0.05 nat，与任何仍然在学的策略都不相容（连最好的一次都是阈值的 4 倍）。代码里的 fail-closed 门
**不得降级**：本次运行就该是 failed。要动的是判据（换成对比集策略 KL），并**明确声明这是判据
修订，不是放宽**。

### 7.2 P2 = **fail by conjunction**（一条腿 hold、一条腿 fail）

| 腿 | 口径 | 阈值 | 实测 | 判定 |
|---|---|---|---|---|
| argmax 翻转率 | 冻结 2×256 槽，A0 vs R2+KL，T=1 | ≤ 0.10 | **0.011719 = 3/256** | **hold** |
| `max_a \|mean_s Δlogit\|` | 同上 | ≤ 0.5 | **1.5156** | **fail** |

- **同空间对照**：冻结槽翻转 **0.0117 vs R2 的 0.617 = −98%**。这是"锚把漂移按住了"的
  同口径证据。
- **不可跨空间比较**：`pilot_kl.json` 里的 **0.0509** 是**最后一轮 on-policy rollout（432 个
  transition）**的翻转率，**不是**冻结槽口径。两者状态分布不同，不能相互换算；本档把它们分开写。
- 因此 **P2 整体 fail**（合取），但**分歧点只在 Δlogit 幅度腿**，翻转腿是 hold。

### 7.3 P4 = **不授权**（前提逐条不成立）

P4 有两个版本的措辞：原档 §4 是「若 P1、P2 成立**但 diag < 1473**」，本档任务书是「若 P1 fail
**但 P2 hold 且 P3 hold**」。逐条核对：

| 前提 | 实测 | 成立？ |
|---|---|---|
| P1 成立 | P1 = **fail**（49/49 超阈） | ✗ |
| P2 成立（合取） | P2 = **fail**（Δlogit 腿 1.5156 > 0.5） | ✗ |
| P1 fail 且 P2 hold 且 P3 hold（任务书口径） | P2 不 hold；P3 = `incomplete` | ✗ |
| `diag < 1473`（原档口径） | **1512.1**，在带内 | ✗ |

**因此本轮不落任何一条 P4 分支**：既**不**写"漂移被洗清 → 奖励与尺子错位"（它的前提
`diag < 1473` 不成立），也**不**宣称 P3 整条成立（s1n 腿 10/20）。

**本轮支持的读法（是推断，不是预注册分支的判定）**：**漂移是元凶，且 KL 锚在部署空间有效**——
同空间 argmax 翻转 −98%（0.0117 vs 0.617）、diag 配对 **+622.75 帧 / 20 全正**、diag 均值落在
R0 的 ±10% 内且只比 R0 低 124.7 帧（R2 低 747.45 帧）。**其中"锚有效"只被 diag 腿与同空间翻转
支持，不被 s1n 腿支持（未完成），也不被 Δlogit 幅度腿支持（1.5156 > 0.5）。**

## 9 并发与墙钟口径

本档在**已经饱和**的主机上跑，所有墙钟都是**争用下界（吞吐上界）**，不是安静主机上的成本：

| 量 | 实测 |
|---|---|
| 采样 | 25 次，窗口 `2026-11-13T20:10:20Z` → `20:35:59Z`（`uptime` 每 60 s，`.tmp_v420_p3/load_samples.log`） |
| 1 分钟 load（采样窗口内） | min **15.20**、mean **45.43**、max **67.35** |
| 1 分钟 load（本轮其它时点的点测） | 03:08 **31.0** → 03:15 **44.2** → 03:30 峰值 **79.9** → 03:48 **73.1** → 04:09 **64.4** → 04:26 **47.4** |
| 同机 `rl-role env` 引擎会话 | 采样 2–8 个；04:10 点测 **11 个**（T05 D3 采集 + 另一路评测 + 本档 4 路） |
| 本档并发路数 | 4（diag×2、s1n×2，各自独立 data 目录） |
| 单局墙钟（自有 diag） | **347.0 – 997.5 s**（1117–1655 帧） |
| 单局墙钟（自有 s1n） | **83.6 – 1967.8 s**（2070–3479 帧） |
| 单批墙钟（5 seed） | diag **3866.6** / **3364.1** s；s1n **4570.7** / **3666.3** s |

**必须如实登记的偏差**：任务要求的"单条命令 ≤10 分钟"在本轮**没有达成**——5 seed 一批在
load 60–80 下需要 56–76 分钟。分批粒度本身是裁决要求（5 seed / 批），我没有把批次拆得更细，也
没有让任何命令挂死：每批都有 `timeout` 兜底、逐次尝试日志与退出码。**同一把尺子的单局墙钟随
负载波动一个数量级以上**（s1n：2407 帧用 **83.6 s**，3479 帧用 **1967.8 s**；diag：1425 帧
用 529.8 s，1655 帧用 996.2 s），而帧数只差 1.16–1.45 倍——这是争用而非测量变化的直接证据。

**争用没有改变测量本身**：evaluator 是确定性 argmax，同一 seed 在三条独立引擎启动（单局冒烟、
本档批内、并发独立跑）上给出**同一帧数**，10/10 diag 与 10/10 s1n 逐值一致。

## 10 这次测量不能主张什么

1. **不能**说 P3 整条成立：s1n 腿本档只有 10/20（完整的 20/20 属于
   [`RL_KL_ANCHOR.md`](RL_KL_ANCHOR.md)，且判 fail）。
2. **不能**把"本档不判 s1n 腿"读成"该腿没问题"：自有 10 局（2499.8）与完整 20 局（2626.0）
   **都**在带下；「incomplete」是覆盖口径，不是对 84 帧差值的否认。
3. **不能**把"在带内"当成"与 R0 相等"：单局 sd 160.65 帧（≈10.6%），20 局均值标准误 ≈35.9 帧
   （≈2.4%），而带半宽 = 10%；band 只有噪声的约 2 倍宽。**本档没有做任何区间比较**。
4. **不能**给 −124.70 / +622.75 帧做因子分解：这是均值与配对差，不是机制份额。
5. **不能**说 KL 锚提升能力：四臂两口径**全 0/20 过关**，R2+KL 与 R2 在能力上没有区别。
6. **不能**把 P2 的 0.0117 与 payload 里的 0.0509 相比：一个是冻结 2×256 槽、一个是最后一轮
   432 个 on-policy transition，**空间不同**。
7. **不能**说 P1 的实现错了：P1 失败是**判据不可达**（49/49 超阈、最小 3.99 倍），fail-closed
   门保持失败是正确行为。
8. **不能**外推到 1M 档或 3 seed；本档 1 个训练 seed、1 个 checkpoint、diag 20 局 / s1n 10 局。
9. **不能**说 `score.dat` 的差异已被证明无关：引擎是闭源二进制，只能说经验上无关（T04 跨
   campaign delta 0.0、本档 gameplay 相关文件哈希与源逐一致）。
10. **不能**说 20 局 diag 是本档单路跑出来的：其中 10 局来自并发独立跑（逐值一致，但不是本档
    的执行）。
