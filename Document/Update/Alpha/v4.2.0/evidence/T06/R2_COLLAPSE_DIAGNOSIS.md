## 0 一句话结论

**复合原因。** 真正改变策略的是一次**没有锚、也几乎没有奖励去抵抗的系统性函数漂移**：
A0→R2 在同一批像素上的 **argmax 翻转率 61.7%**，其中 **58.2% 的 logit 变化方差是一个与状态
无关的"全局动作偏好"**（focus-E +8.33、W −6.09、idle −3.32，两个独立数据切片相关 0.9992）。
让它一路走通的三个条件分别是：**(a)** 奖励看不见评测度量（24/24 都是 `game_over` ⇒ 死亡项是
常数 −0.75，回报方差 100% 来自 progress；训练中首死从 1207.8 掉到 854.0，即 −29.3%，而回报只
动了 0.24%）；**(b)** 优势被白化成单位方差、Adam 每步位移≈lr，所以幅度信息被丢掉、"小信号"
照样走满 392 步；**(c)** KL / 熵 / clip **全部在 T=8 温度空间量测**，而部署是 T=1 的 argmax，
同一处策略变化在部署空间的 KL 被低估 **11.6 倍**，且**计划要求的"对 BC 的 KL"一次都没记**
（payload 里只有 `approx_kl`）。

**不是**温度错配（rollout 与 `log_prob` 同温，排除）、**不是**评测条件变化（排除）、
**不是** `resume=` 的状态泄漏或 TD 错位（排除）。

### H1 采样温度 vs 训练温度错配 —— **排除**

但这条假设被排除之后，留下一个**真的问题**：rollout 在第 8 温度空间里走，指标也在第 8 温度

见 H4。

### H2 初始策略退化 + 49 次更新的破坏量 —— **支持**

离线算完，结论是：**"actor 参数最大变化 2.40e-04" 不是"更新很小"的证据**。

1. **Adam 每步都走满 lr。** 每次更新 `epochs 2 × ceil(512/128)=4 = 8` 个 minibatch 步，
   全程 `49 × 8 = 392` 步。实测每更新 `max|ΔW| = 2.4031e-04 ± 7.24e-07`
   （`pilot_stats.json update_arithmetic`），除以 8 得 **3.004e-05 = 1.0013 × lr(3e-05)**。
   也就是说：最差的那个坐标，在每个 minibatch 上都被推动了一个**完整的 Adam 步长**。
2. **累计漂移是实测的，不是估的。** A0→R2 实测 `max|ΔW| = 3.372e-03`
   （`play_readout.3.weight`，形状 `(128, 2688)`），是"49×2.4031e-04 = 1.1775e-02"这个
   **不反向**上界的 28.7%。移动最大的 5 个参数**全部在共享特征侧**，没有一个在 `move_head`：
   `play_readout.3.weight (128,2688) 3.372e-03`、`hist.1.weight (64,144) 3.104e-03`、
   `hud.10.weight (64,4480) 3.066e-03`、`play.6.weight (64,48,3,3) 3.030e-03`、
   `play.3.weight (48,24,3,3) 2.825e-03`。
   线性头自己也动了（`move_head.weight (18,128)` 最大 2.400e-03、`bias` 1.311e-03），
   但**只解释观测到的 `Δlogit` 的 5.7%**——漂移主要是**主干/特征**改的，不是最后一层改的。
   > **需要更正 [`RL_PILOT2.md`](RL_PILOT2.md) §3.3 第 2 条（本档写作时位于 :243）**：那里写的
   > "权重离 A0 的最大偏移约 1.2e-2"其实是上面那个不反向上界；实测是 **3.37e-03**，
   > 文档把权重漂移高估了 3.5 倍。这个更正**不削弱**诊断，因为函数层面的漂移是直接量出来的
   > （见第 3 点）。同一段里"argmax 在大量状态上会翻转"这一句，本档给出了实测值：**61.7%**。
3. **函数层面一点都不小。** 2×256 个冻结槽（纯前向）：

| 量 | 值 |
|---|---:|
| `Δlogit` 平均绝对值 | **3.858** |
| `Δlogit` RMS | 5.095 |
| `Δlogit` 最大绝对值 | 33.94 |
| A0 每行 logit range / 全局 sd | 32.83 / 7.15 |
| **argmax 翻转率**（同一批像素） | **61.7%**（seed10 复现 64.8%） |
| 折算每次更新 | ≈ **1.26%** 的状态翻转 |

4. **一次更新内部就已经把策略推离开自己的 rollout 数据。** `ratio_max_abs_deviation`
   均值 0.256（首次 0.284、最大 0.479，`pilot_series.json within_update`）——这是在**同一次
   更新的 8 步之内**、同一批 rollout 数据上测到的。换成对数比：`log(1+0.479)=0.391 nat`
   （T=8），在部署空间等价于 **3.13 nat**。
5. **actor 的梯度有三条通道，只有一条跟任务有关。** `rl.py:1270-1271` 同一个 trunk 同时喂
   `move_head` 与 `critic`；`rl.py:1597-1600` 两组参数（trunk 走 actor lr 3e-05，critic 头走
   3e-04）；`rl.py:1640-1643` 把 `policy_loss + 0.5·value_loss − 0.001·entropy` 一起 backward。
   于是：(i) **value loss 会经共享 trunk 反传进 actor**，而它的目标 99.8% 是个常数，带不来任务
   信号；(ii) **熵项符号恒定**，在 Adam 下（每坐标按自身 RMS 归一）它拿到的是**满步长**，
   与它 0.001 的系数大小无关——这与观测到的"logit 变得更平"一致（每行 logit range
   32.83 → 26.77，全局 range 79.56 → 46.75，全局 sd 7.15 → 6.43；T=8 熵 2.3317 → 2.5574）。
   这三条通道在本轮**没有做分离实验**，所以只作为机制登记，不作为份额。

所以：A0 在 T=1 下熵只有 0.4126 nat / 有效动作 1.51（`RL_AUDIT.md:174`；我在教师槽上量到
0.2396 / 1.394），这种策略上一个 Adam 步就能把少数被采样的动作顶起来；49 次更新不是"轻微
扰动"，是 **392 个满步**。

### H3 奖励尺度与优势尺度 —— **支持（最可疑的一条，确实成立）**

| 量 | 值 | 含义 |
|---|---:|---|
| episode return 均值 / sd / 极差 | −0.747441 / **0.001404** / **0.004909** | 24 局几乎是同一个数 |
| 结束原因 | `{"game_over": 24}` | 死亡项在所有局里都恰好是 **−0.75** |
| `var(death)` | **0.0** | 死亡项对回报方差贡献为零 |
| `var(progress)/var(return)` | **1.0000** | 回报方差 100% 来自 progress |
| progress 均值 / sd / 上限 | 0.002559 / 0.001404 / 0.5 | 占回报的 **0.34%** |
| `corr(return, 总帧数)` | 0.7049 | 回报能排"总共活了多久" |
| `corr(return, 首死帧)` | **0.3545** | 回报**排不动**评测度量 |
| value loss 均值 → RMSE | 0.0078 → **0.08832** | = **62.9×** 回报 sd、**18.0×** 回报极差 |
| `advantage_normalisation` | **true**（`rl.py:1593-1596`） | 幅度信息被丢掉，只剩方向 |

**最狠的一处证据在训练自己的记录里**（`pilot_series.json`，24 局按时间四等分）：

| 区间 | 帧数 | **首死帧** | 回报 | progress |
|---|---:|---:|---:|---:|
| Q1 | 2291.7 | **1207.8** | −0.74650 | 0.003500 |
| Q2 | 1949.5 | 996.8 | −0.74720 | 0.002800 |
| Q3 | 1954.3 | 950.5 | −0.74770 | 0.002300 |
| Q4 | 1993.2 | **854.0** | −0.74830 | 0.001700 |
| 变化 | −13.03% | **−29.29%** | **+0.241%** | — |

即：**训练过程中首死存活掉了 29.3%，回报只动了 0.24%**。折算下来，"1% 的首死存活"在奖励里
大约值"0.008% 的回报"。**优化器没有理由去保住评测度量**——这就是"回报几乎没有方差"的真实
后果，而且它不是统计噪声，是奖励表本身的结构（`survive_per_decision = 0.0`、progress 有界
0.5、死亡项与死亡**时刻**无关）。

### H4 clip fraction 与 KL 是否被误读 —— **支持**

1. **三个"健康"指标都在 T=8 空间量测。** `rl.py:1631-1634` 的 `probs`/`entropy` 与
   `1650-1651` 的 `approx_kl`/`clip_fraction` 全部来自 `log_softmax(logits/8)`。所以
   `KL 4.46e-03`、`熵 2.5111`、`clip 0.0537` 描述的**不是**部署分布。
2. **低估倍数实测出来了**（同一处 A0→R2 变化，两个空间各量一次）：

| 空间 | 对称 KL | TV |
|---|---:|---:|
| T=1（部署） | **3.276 nat** | 0.605 |
| T=8（训练） | 0.281 nat | 0.282 |
| 比值 | **11.64×**（seed10 复现 **12.59×**） | 2.14× |

   二阶小量极限是 T²=64×；实测 11.6× 是**保守下界**。也就是说每更新那条
   `approx_kl 4.46e-03` 对应的部署空间变化是 **5e-02 量级**，不是 4e-03。
3. **动作分布确实被推歪了，不是评测漂移。** 冻结 evaluator 是确定性的、seed 固定，所以
   `TV > 0` 只能是策略变化：

| 口径 | idle 占比 R0→R2 | 有效动作 R0→R2 | 行熵(nat) R0→R2 | TV(聚合) | 逐 seed TV |
|---|---|---:|---:|---:|---:|
| `diag_first_death` | 0.2989 → **0.5112**（20/20 seed 都为正，+0.2123） | 6.873 → 3.738 | 1.9276 → 1.3186 | **0.4207** | 0.4336（0.368–0.487） |
| `s1n` | 0.3303 → 0.4828（+0.1525，20/20） | 6.891 → 4.039 | 1.9302 → 1.3959 | 0.3913 | 0.3988 |

   前三动作：R0 = `idle / W / SW`，R2 = `idle / focus-E / E`。`focus-E` 从 0.0541 涨到
   0.2589，`W` 从 0.1711 掉到 0.0451，`SW` 从 0.1592 掉到 0.0102。
4. **计划要求的那条 KL 从来没记过。** `README.md:237` 明确要求"记录对 BC 的 KL 和实际梯度
   量级"。`pilot2.json` 与 `rl_pilot2.json` 里 **`kl` 字段只有 `approx_kl` 一个**
   （`check_kl_to_bc.py` 的实测输出），`touhou_rl/v420/rl.py` 里也**没有**任何 anchor /
   参考策略项（唯一的 `reference` 是 GAE 对照与 forward-equivalence 校验）。
   这正是唯一能提前看见 3.28 nat 漂移的那个量，而它缺了。

## 3 主因判定：复合原因

**代理（真正改变策略的东西）**：一次**系统性**漂移，不是随机游走。

| 证据 | 值 |
|---|---|
| argmax 翻转率（2×256 同像素） | **61.7%**（复现 64.8%） |
| **与状态无关的"全局动作偏好"占 Δlogit 方差** | **58.2%**（复现 59.6%） |
| 只用这个常数偏移能得到的翻转率 | **50.4%** |
| 只用状态相关残差能得到的翻转率 | 30.1% |
| 两者合起来（完整 R2） | **61.7%** |
| 同幅度**无方向**高斯扰动的翻转率（对照） | 38.4% / 40.9% |
| 两个独立数据切片的 per-action 均值相关 | **0.9992** |

per-action 平均 Δlogit：`focus-E +8.33`、`SE +5.90`、`focus-SE +5.49`、`E +4.48`、
`focus-idle +3.38` ／ `W −6.09`、`focus-SW −5.00`、`idle −3.32`、`SW −2.42`。
方向与 dev 动作占比变化部分吻合（`focus-E`/`W`/`SW`/`focus-SW` 全对；`s1n` 口径 13/18 同向），
但 `idle` 与 `E` 两个符号不一致——说明 dev 层面的占比变化**不能**只用这个常数解释（还有 42%
的状态相关残差，且 dev 是另一条状态分布）。这一点在 §5 明确列为不能主张。

**为什么没人拦住它**：

1. **奖励看不见度量**（H3）：24/24 `game_over` ⇒ 死亡项恒定 −0.75；训练中首死 −29.3% 只
   换了 −0.24% 的回报；`corr(return, 首死帧) = 0.354` 对 `corr(return, 总帧) = 0.705`。
2. **幅度信息被删掉**（H3+H2）：`advantage_normalisation` 白化 + Adam 的每步位移≈lr，
   于是"信号只有 0.3%"这件事在梯度里根本不存在；实测每步正好 1.0013 lr。
3. **观测空间错位**（H1+H4）：指标全在 T=8，部署在 T=1，低估 11.6×；而计划要求的
   KL-to-BC 一次都没记，所以连"漂了多远"都没有曲线。
4. **actor 的三条梯度通道只有一条跟任务有关**（H2 第 5 点）：value loss 经共享 trunk 反传、
   熵项在 Adam 下拿满步长。这与"漂移集中在特征层、线性头只解释 5.7%"的实测一致，
   但**本轮没有分离**，因此不作为份额计入。

**各因子的相对贡献估计（只给可测的部分，不给编的数）**：

| 层面 | 可测份额 |
|---|---|
| 已发生的函数变化 | 58.2% 全局动作偏好 + 41.8% 状态相关残差 |
| R0/R2 的 dev 差异 | 100% 策略、0% 评测方差（确定性 + 配对） |
| 奖励对度量的激励强度 | 1% 首死存活 ≈ 0.008% 回报（约差 100 倍量级） |
| KL 的量测低估 | ×11.6（保守；二阶极限 ×64） |

**−747.45 帧的可加分解这一轮拿不出来**，任何百分比都会是编的。证据支持的是一个**次序**：
奖励的盲区决定了"没有人抵抗"，白化+Adam 决定了"漂得多大"，T=8 的量测决定了"没人看见"。
三者在 §4 的改动里被有意分开检验。

## 4 下一步唯一改动（计划允许的那一次 KL 修订）

> **加一个对 A0 的 KL 锚，量在"未加温度"的 T=1 logits 上。**
> `loss += beta · mean_t KL( softmax(z_A0) ‖ softmax(z) )`，**β 在跑之前冻结为 1.0**，
> 并加一条 fail-closed 检查：**50,000 帧内每次更新都必须满足 `max_t KL_T1(A0‖π_t) ≤ 0.05 nat`**。
> 检查不过时，β **只允许上调、不允许下调**，且只有在检查失败后才允许。

**明确不动**：rollout 温度仍 8.0、`actor_lr` 仍 3e-05、奖励表逐字节不动、帧预算仍 50,000、
更新数仍 49。**不加长训练、不加 step。**

**为什么是这一个**：

1. 它把 `README.md:237` **已经要求、这次运行却没记**的"对 BC 的 KL"补回来——这不是新超参搜索，
   是补一个缺失的必要观测量；
2. 它作用在**部署空间**（T=1），而塌陷正是发生在部署空间（3.276 nat 对 0.281 nat）；
3. 它**不动奖励、不动学习率**，所以它是唯一能把"漂移是元凶"与"奖励是元凶"分开的那一次改动；
4. 它**与尺度无关**：单纯砍 lr 会连真信号一起砍，而且在 Adam 下 lr 是步长不是幅度旋钮。

**可证伪预测**：

| 编号 | 预测 | 现状 |
|---|---|---|
| **P1 机制** | `max_t KL_T1(A0‖π_t) ≤ 0.05 nat`（50k 全程） | 累计 **3.276 nat** |
| **P2 函数** | 同一批 2×256 槽：argmax 翻转率 ≤ **0.10**；各动作平均 Δlogit 的最大绝对值 ≤ **0.5** | 0.617；8.33 |
| **P3 行为** | 20 dev `diag_first_death` 均值落在 **1473–1800 帧**（1636.8 ±10%）；`s1n` 落在 **2710–3313**（3011.5 ±10%） | 889.35；1906.4 |
| **P4 判别** | 若 P1、P2 成立但 diag < 1473，则**漂移被洗清**，下一个目标就是本档已量化的奖励/度量错配（29.3% 首死换 0.24% 回报） | — |

P3 的区间之所以能取得这么紧：dev 尺子是**确定性 + 同 seed 配对**的，所以偏离 R0 只可能是策略
差异，不是测量噪声。
另：这次改动**不可能**带来过关，两臂在 50k 都应是 0/20。

## 5 本轮不能主张什么

1. **不能**把"2×256 教师槽上 61.7% 的翻转率"当成 dev 层面的翻转率——前者是在 D410-S1
   seed-10/12 的教师状态分布上量的，dev 的动作占比是在另一条 on-policy 状态分布上量的。
2. **不能**给出 −747.45 帧的因子分解；§3 给的是"logit 方差份额"和"dev 差异份额"，不是帧数份额。
   也**不能**区分 policy / value / entropy 三条梯度通道各自的贡献——本轮没有分离实验。
3. **不能**说 KL 锚会提升能力；50k 档它最多只能**阻止**漂移。
4. **不能**说 `score.dat` 的差异已被证明无关——引擎是闭源二进制，只能说它**经验上**无关
   （T04 跨 campaign delta 0.0、两个目录在本轮前都已脏）。
5. **不能**说训练/评测的射击脉冲差异已被量化：训练环境每 48 决策松一帧 SHOOT
   （`rl.py:760-774`），而冻结 evaluator 从不松（`v410_student_eval.py:967`）。这是**两臂共享**的
   train/deploy 错配，也是"永远不可能过关"的必要条件（`RL_AUDIT.md:272-277`），但只凭代码
   识别，没有测量它的帧级影响。
6. **不能**说 R0 是本轮重测的：R0 是 T04 冻结记录，靠"三个文件逐值一致 + checkpoint sha 一致"
   建立同一性，没有做同轮 A0 对照重跑。
7. **不能**把任何结论外推到 1M / 3 seed / R1。
8. **不能**说这次 PPO"发散了"：KL、clip 从未爆掉，这是**静默漂移**，不是发散。
9. **不能**说温度是 ratio bug：H1 已排除，问题是**量测空间**，不是采样与重算的不一致。
