## 1 机制与证据

### 1.1 白化在哪一行、当前是什么（逐行）

| 位置（`rl.py`，sha `8b201a35…`） | 代码 / 值 | 含义 |
|---|---|---|
| `:198` | `ADVANTAGE_NORMALISATION = True` | 模块默认值 |
| `:2167-2170` | `adv_t = torch.tensor(np.asarray(advantages, …))`；`ret_t = torch.tensor(np.asarray(returns, …))` | 优势与回报**各自**装成张量 |
| `:2171-2174` | `if normalise_advantages and count > 1:`<br>`    std = float(adv_t.std(unbiased=False).item())`<br>`    if std > 1e-8:`<br>`        adv_t = (adv_t - adv_t.mean()) / (std + 1e-8)` | **唯一的白化点**：减均值 + 除标准差 |
| `:2215-2220` | `for _epoch in range(int(epochs)):` … `for start in range(0, count, int(minibatch)):` | epoch / minibatch 循环在**白化之后** |
| `:2233-2234` | `unclipped = ratio * adv_t[index]`；`clipped = torch.clamp(…) * adv_t[index]` | minibatch 只是**索引**已白化的张量 |
| `:2236` | `value_loss = mse_loss(values, ret_t[index])` | critic 目标 = **原始**回报 |
| `:2193-2196` | 两组 `Adam`：actor `lr=3e-05`、critic `lr=3e-04` | 第二步尺度归一 |
| `:2250-2252` | `clip_grad_norm_(…, grad_clip)` | 第三步尺度归一 |
| `:3065-3066` | `"advantage_normalisation": bool(ppo.get(…, ADVANTAGE_NORMALISATION))` | 配置解析 |
| `:3588-3589` | 审计路径 `normalise_advantages=bool(config["ppo"]["advantage_normalisation"])` | 审计**也**读这个键 |
| `:4376` | 训练路径 `normalise_advantages=bool(config["ppo"]["advantage_normalisation"])` | 训练读同一个键 |
| `:1371` | `returns[index] = gae + float(values[index])` | 回报在 GAE 里生成，**从不白化** |
| `:4399-4415` | 每更新的 `record`（policy_loss / value_loss / entropy / approx_kl / clip_fraction / grad_norm / ratio_max_abs_deviation / minibatch / samples） | **payload 里没有任何 advantage 统计** |

**现状的四条结论（这就是"当前是什么"）：**

1. **按 batch（一次 rollout = 512 决策）白化一次，不是按 minibatch。** 白化在 `:2171-2174`，
   在 epoch/minibatch 循环（`:2215`）**之前**，且用的是整个 rollout 的 `adv_t`（`:2167`）；
   minibatch 在 `:2233-2234` 只是取下标。⇒ 同一个 scale 被 8 个 minibatch 共享。
2. **减均值 + 除标准差，两者都做。** 标准差用总体口径 `unbiased=False`（ddof=0）。
3. **`epsilon = 1e-8` 出现两次**：`:2173` 的门槛 `std > 1e-8`，`:2174` 的分母 `std + 1e-8`。
   以 r3 审计槽实测 `sd = 1.73392948666343836e-04` 计，分母被 `1e-8` 抬高
   `1e-8 / 1.73392948666343836e-04 = 5.7672e-05`（即 **5.8e-05 相对量**，可忽略）；
   以 r2 审计槽 `sd = 6.50673926760994e-06` 计是 `1.5369e-03`。两处都远小于其它不确定性。
4. **白化在优势上，不在回报上。** `adv_t` 被改（`:2174`），`ret_t` 未被改（`:2169-2170`、
   `:2236`），GAE 的 `rewards`/`returns` 一字未动（`:1325-1373`）。
   ⇒ critic 永远在**原始回报单位**里拟合；白化只是 actor 的**梯度权重**。

### 1.2 为什么"幅度信息消失"——把它写成可测的版本：**三层嵌套的尺度移除**

诊断的原话是"优势被白化成单位方差、Adam 每步位移≈lr，所以幅度信息被丢掉、'小信号'照样走满 392 步"
（`R2_COLLAPSE_DIAGNOSIS.md` §2 H3 / §3）。这句话**成立**，但它比实测能支持的少说了两层：
在这条更新链上，尺度被移除**三次**，白化只是第一层。

| # | 阶段 | 代码 | 做了什么 | 实测（本档复算） |
|---:|---|---|---|---|
| 1 | **白化** | `:2171-2174` | 优势幅度 → 单位方差 | `1/sd = 5767.247`（r3 审计槽 `sd = 1.73392948666343836e-04`）；均值被平移 `5.3303 sd` |
| 2 | **Adam** | `:2193-2196` | 每坐标步长 → lr | 每 minibatch 的 `max\|ΔW\| / lr ∈ [0.9916, 1.0013]`（四个臂：r2 1.0013、r2+KL 0.9920、r3@50k 0.9929、r3@200k 0.9916）；r2 那个 `1.0013` 就是诊断的 `1.0013 × lr` |
| 3 | **全局裁剪** | `:2250-2252` | 总梯度 → 范数 `0.5` | 裁剪前范数 `4.902`（r2）/ `9.273`（r2+KL）/ `9.046`（r3@50k）/ `8.50464`（r3@200k）⇒ 每次都裁掉 **9.80–18.55 倍** |

**推论（本规格最重要的一句）：** 一次 PPO 更新在这里是
`ΔW = Adam(0.5 · g/‖g‖, lr)`——**方向**由三项损失的梯度混合比决定，**步幅**由 `lr` 决定。
奖励的绝对大小（"这一局比那一局好多少"）在这三层里**各被移除一次**，
因此**任何**对优势的常数缩放（乘 `sd`、除 `sd`、乘 `10`）都不改变更新；
能改变的只有两件事：**(a) 优势向量的偏移（均值）**、**(b) 策略项与 value/entropy 项的混合比**。
(b) 正是诊断 §2 H2 第 5 点登记但"本轮没有做分离实验"的那三条通道（同一个 trunk 同时出 logits 与
value：本版 `rl.py:1557` 的 `logits_and_values`；两组 lr：`:1636` 与 `:1639` 的
`actor_parameters` / `critic_parameters` 分别进 `:2193-2194` 的两个 param group；
三项损失一起 backward：`:2237` 拼 `loss`、`:2249` 调 `backward`）。

这条推论同时决定了三个候选的**可证伪性上限**：它们都**不能**"恢复幅度→步幅"这条通道
（那条通道只能靠改 `lr` 恢复，而 `lr` 属 §7.1 的受限类别且配额已用尽）。
它们能检验的只有：**白化这一行（偏移 + 混合比）到底承不承重。**

### 1.3 r3 奖励下 advantage 的真实结构（本档新读数，来自既有 payload）

r3 审计的 `gae` 项（`.tmp_v420_data/T06/r3/audit-r3-c.json`，真实引擎 256 transition / 1 段）：

| 量 | 值 |
|---|---:|
| `advantage_min` | **4.9890269778720825e-05** |
| `advantage_max` | 0.0009946544139796197 |
| `advantage_mean` | 0.0009242311007047813 |
| `advantage_sd` | 0.00017339294866343836 |

三处复算（`.tmp_v420_advnorm/arith.py`，38/38 通过）：

| 检查 | 复算 | 结论 |
|---|---|---|
| `ε + δ` vs `advantage_min` | `1.2e-05 + 3.7890269778720825e-05 = 4.9890269778720825e-05` | **差 0.0，逐比特相同** |
| `advantage_max / advantage_min` | `19.936842` | = GAE 几何视界 `1/(1−γλ) = 19.936872`（相对差 1.5e-6） |
| `advantage_mean / min`、`sd / min` | `18.5253`、`3.4755` | 均值与离散度都以"每决策常数"为单位 |

**读法**：在这条真实 rollout 上，r3 的 advantage 向量几乎就是
`(ε+δ) × k_t`，`k_t ∈ [1, 19.936842]` 只取决于"离段末还有多少决策"（一个纯时间的几何权重），
**任务微分量是叠在上面的小残差**。

由此得到白化两个半边的**相对量级**（这是本档必须写清、既有诊断没有分开的一点）：

| 半边 | r3 奖励表下 | r2 奖励表下 | 含义 |
|---|---:|---:|---|
| **除标准差**：`1/sd` | `5767.247` | `153686.8` | 一个**正**常数，**Adam 下近似无效**（只改混合比） |
| **减均值**：`mean/sd` | **`5.3303`** | `0.4844` | r3 下均值是 **5.33 倍 sd**，是一条共模斜坡 |

⇒ **同一个开关在 r2 与 r3 上的含义不同**：r2 的 advantage（只有 progress + 常数死亡项）
均值只有 0.48 sd，白化的两半量级相当；r3 加了 `survive` 与 `first_life` 两个**每决策常数项**之后，
均值变成 5.33 sd，**减均值成了主导动作**（把那条共模斜坡整条去掉）。
这不是"白化更强了"，是"白化现在在做一件不同的事"。

> **口径限制**：这个结构是从**审计槽**（256 transition、1 段、无 episode 终止）上量的，
> 不是从训练 rollout（512 决策、含 `death −0.25` 与终止）上量的。训练 rollout 的同一量
> **从未被记录**（`:4399-4415` 无 advantage 统计）——见 §1.5。

### 1.4 必须区分的六件事（逐条给依据）

| 说法 | 对/错 | 依据 |
|---|---|---|
| 白化作用在**优势**上 | **对** | 只有 `adv_t` 被改（`:2171-2174`） |
| 白化作用在**回报**上 | **错** | `ret_t`（`:2169`）直接来自 `gae_returns`（`:1371`），critic 目标用的是它（`:2236`） |
| 白化改变**奖励排序** | **错** | 奖励表逐字节未动；GAE 逐行未动；白化是对 `A_t` 的**正比例 + 常数平移**，保序 |
| 白化改变**梯度尺度** | **对，但只在"混合比"通道上生效** | §1.2 的三层归一里尺度被移除三次 |
| 白化直接改变 **argmax / 部署** | **不直接** | 它只经梯度影响参数；部署是 T=1 argmax，由 `v410_student_eval.py` 决定 |
| 白化的**实际除数**被记录 | **错（从不记录）** | pilot payload 无 advantage 统计（`:4399-4415`）；只有审计的 `gae` 项记（`:3628-3629`） |

### 1.5 证据缺口（执行档必须先知道）

1. **训练期的白化分母从未落盘。** 五个臂的 payload 里都没有 `advantage_mean/sd`，所以
   "在 r3 的训练 rollout 上 `1/sd` 到底是 5.8e+03 还是 1.5e+05"**不可知**——
   唯一可得的同配方读数是审计槽（`5767.247`）。这不影响候选选择（三个候选都不依赖该数值），
   但影响**事后归因**的精度。
2. 补这个缺口**不需要改代码**：审计的 `gae` 项（`:3628-3629`）就是同配方的真实 rollout 统计；
   执行档重跑 18 项审计即可拿到（`REWARD_R3.md` §6 实测 555.7 s）。
3. 诊断 §2 H3 的 `corr(return, 首死帧) = 0.3545`、`corr(return, 总帧) = 0.7049`、
   `value RMSE = 0.08832 = 62.9× 回报 sd` 三条**与白化无关**（它们量的是奖励表与 critic），
   引用时不得与白化的机制混在一句话里。

## 2 三条候选改动（各自单因素、互斥）

**先给一张映射表，因为三条候选只产生两个不同的映射**（这是本档的第二个结构性发现）：

| 候选 | 等价映射 | 需要什么改动 | 单因素？ |
|---|---|---|---|
| 现状 | `(A − mean) / (sd + 1e-8)` | — | — |
| **N-a①**（keep mean, drop `/sd`） | **`A − mean`** | 改 `rl.py`（把 `:2171` 的一个布尔拆成两半） | 是，但要改代码 |
| **N-a②**（完全不除 std、也不减均值） | **`A`** | **一个配置键**（`:3065-3066` 已有通路） | 是（协议自己的原子单位） |
| **N-b**（分项保留 `first_life`） | 混合：`first_life` 用原幅，其余白化 | 改 `rl.py`（分项 GAE + 选择性白化） | **不是** |
| **N-c**（白化后按 `reward_scale` 乘回） | `(A−mean)/(sd+ε) × sd` = **`A − mean`** ≡ **N-a①** | 改 `rl.py`（在 `:2174` 后乘回） | 是，但要改代码 |

⇒ **N-c 与 N-a① 是同一个映射**，三条候选实际只测两件事：`A`（N-a②）与 `A − mean`（N-a①=N-c）。

### 2.1 **N-a 去掉白化**

**(a) N-a②（推荐形态）——精确到字段**

- 改什么：新配置 `configs/v420/rl-engine-r3-advnorm.json` 的
  `ppo.advantage_normalisation` 由 `true` 改为 **`false`**（现值见 `rl-engine-r3-pilot.json:96`）。
  `rl.py:3065-3066` 解析、`:3588-3589`（审计）/`:4376`（训练）送入、`:2171` 短路掉整个 `:2172-2174`。
  **`rl.py` 零改动。**
- 为什么可能有用：它把"白化这一行是否承重"变成一次可判定实验。按 §1.2，
  它不改变步幅（Adam+裁剪已经固定），改变的是**方向**：去掉 `5.3303 sd` 的共模斜坡
  （r3 下最大的一块）与 `5767.247` 的常数缩放（只影响混合比）。
  在三个候选里，它是**唯一作用在有量级通道上的那个**。
- 副作用风险（三条，逐条可测）：
  1. **方向被 value/entropy 通道接管**（诊断 H2 第 5 点）。策略项相对量级掉到
     `6.5e-06 … 1.7e-04`，而总梯度仍被裁到 `0.5`；若策略项原本主导 `‖g‖`，
     更新就变成"拟合 critic + 抬高熵"。**可测**：熵曲线、`clip_fraction`、`value_loss`。
  2. **共模斜坡回注**：`mean = +9.24e-04`、`sd = 1.73e-04`、`min = +4.99e-05`（§1.3）——
     关掉减均值等于把所有被采样动作同向强化（越靠近段首越强），理论上抬方差、降熵。
     **可测**：T=8 熵、dev 动作直方图的 idle 占比。
  3. **两半不可分离**：协议只有一个布尔（`:2171`），单次运行无法区分是偏移还是缩放起作用。
     **声明为已知限制**（见 §3 末段），不掩盖。
- 如何证伪：§4.5 的 P-N1/P-N2/P-N3 三条方向性预测。特别是 P-N2：
  若每更新 `actor_max_abs_parameter_change` 偏离 `2.38e-4 ± 5%`，则"Adam 已把步幅与优势尺度解耦"
  这个前提被证伪，§1.2 的整条推理作废（并且按 §7.1 触发配额追溯）。

**(b) N-a①（keep mean, drop `/sd`）**

- 改什么：把 `:2171-2174` 拆成两个布尔（或加一个 `advantage_centre_only` 键），只保留 `− mean`。
- 为什么可能有用：理论上更干净——它**只**动尺度、不动偏移，因此只测混合比通道。
- 副作用风险：预测 **null**（§1.2：常数缩放被 Adam 抵消），且要改 `rl.py` + 测试。
- 如何证伪：同 §4，但 null 结果只能给 1 bit，且这 1 bit 已由 §1.2 的算术给出。
- **本档不选它作为本轮，理由见 §3。**

### 2.2 **N-b 分项保留 `first_life` 的 advantage —— 不可行**

**结论：不可行。** 不是工程量问题，是**定义不唯一** + 幅度不可控 + 非单因素，三重否决。

1. **定义不唯一。** critic 的 baseline `V(s)` 是**共享**的（一个头、一个 trunk：本版 `:1557` 的
   `logits_and_values` 同时出 logits 与 value），GAE 的 `δ_t = r_t + γV(s_{t+1}) − V(s_t)` 里那个
   `V` **无法按奖励分量分摊**。两种自然分摊给出**不同**答案：
   - (i) 全部 baseline 记在总和上 ⇒ `first_life` 的"分项 advantage"等于
     `Σ_k (γλ)^k r^{fl}_{t+k}`，即一条**无 baseline 的正斜坡**（不是 advantage，是未折扣的未来和）；
   - (ii) 按比例分摊 ⇒ 需要 6 个 critic（或一个分项头），那是新算法、不是单因素。
   规格里"对 `first_life` 分量的 advantage 做分项保留"在数学上不是良定义；
   任一实现都是**选择了其中一种分摊**，因此结论无法与"白化"这个变量绑定。
2. **幅度不可控。** `δ × GAE 视界 = 3.7890269778720825e-05 × 19.936872 = 7.554135e-04`，
   是当前整个 advantage `sd`（`1.73392948666343836e-04`）的 **4.3567 倍**。
   把 `first_life` 按原幅回注，就是让一个 r3 已经用 `first_life_cap = 0.25`、
   断言 ②（`0.119322 + 0.25 = 0.369322 ≤ 0.5`，`REWARD_R3.md` §1.3）明确限界的奖励项
   **主导**策略梯度（放大 4.36 倍）。
3. **不是单因素。** 它同时改（a）advantage 的分项计算，（b）白化策略；两项都在同一个臂里，
   违反"一次只改一个"。

**数据侧可行性（记录在案，供将来）：** `Transition.reward_terms` 已在 `rl.py:1981` 定义、
`:2050` 逐决策写入、`:1104-1106` 由 accountant 生成，六项键齐备（`:728-748`：
`survive` / `progress` / `death` / `bomb` / `stage_clear`，r3 再加 `first_life`）。
⇒ **数据拿得到**；缺的是**良定义**与**改 `rl.py` 的授权**，不是数据。
本档白名单也不允许改 `rl.py`（只允许本文件与 `.tmp_v420_advnorm/`）。

### 2.3 **N-c 白化后按 `reward_scale` 复原幅度**

**结论：字段不存在 ⇒ 按原文字面不可执行；且数学上等于 N-a①。**

1. **`reward_scale` 在 v4.2.0 协议里不存在。** 全仓只有 v4.0 的
   `tools/rl/v400_rl_train.py --reward-scale`（`:472`、`:546`）与
   `touhou_rl/v400/rl/env.py:885-910`（`reward_scale_table` / `reward_scale_report`）用过这个名字。
   `touhou_rl/v420/**` 与 `configs/v420/**` 里**没有**这个键。所以 N-c 不能"改一个字段"，
   必须新造一个（例如把 rollout 的 `sd` 记进日志再乘回）。
2. **数学上它就是 N-a①**：`(A − mean)/(sd + ε) × sd = A − mean`（`ε` 的相对量 `5.8e-05`，忽略）。
   ⇒ 它不是第三个候选；它与 N-a 的"只保留减均值"是**逐元素相同**的映射。
3. **"乘回一个正常数"在 Adam + 全局裁剪下不是幅度旋钮**（§1.2 三层）：它只能改混合比，
   因此预测 null。要真正让幅度影响步幅，只能改 `lr`（受限类别、配额已用尽，见 §7.1）
   或去掉第三节的裁剪——两者都不在本档三个候选之内。
4. **唯一有价值的一半：把 `sd` 记进日志。** 这一半**免费且应当无条件采纳**：
   既有审计的 `gae` 项已经给出该数（`1.73392948666343836e-04`，§1.3），
   执行档重跑审计即可拿到同配方下的同一量，**零代码**。
5. 若坚持"乘回"的实现，需要改 `rl.py`（在 `:2174` 后乘回）并加一个键 ⇒
   成本高于 N-a②、预测 null、且与 N-a① 重复。

### 2.4 互斥性

- N-a② 与 N-a①（=N-c）是**同一开关的两半**，不能在同一个臂里跑，也不能同轮跑
  （会互相污染解释：一个是偏移+尺度，一个是尺度）。
- N-b 与其余二者不互斥，但被 §2.2 的三条否决。
- ⇒ **一轮一个候选。** 本档推荐 N-a②（§3）；若其结果需要拆解，N-a① 是**下一轮**，不是同一轮。

## 5 预算与排程

### 5.1 帧预算：**50,000**

**理由（复算，不是估计）**：预算这一维在 50k 之后**已经饱和**——
`BUDGET_200K.md` §8 的边际收益是 **−0.933 帧（diag）/ −5.533 帧（s1n）每 +1 万帧**
（复算：`(1575.2 − 1589.2)/15 = −0.933`、`(2808.6 − 2891.6)/15 = −5.533`），
而 200k − 50k 的配对差 `−14.0 / −83.0` 帧的 95% 区间 `[−237.5, +209.5] / [−476.9, +310.9]` **含 0**
（t = −0.13 / −0.44）。⇒ "再多攒帧"买不到本仪器能测出的东西；而本改动是策略侧的**方向**改动
（§1.2），与预算正交互补，所以**必须**把预算钉回 50k 才是单因素。

**反过来的硬约束**：若本臂在 50k 上不改善，**不得**用"再加预算"补救——
那正是 `BUDGET_200K.md` §8 关掉的轴（200k→1M 的边际已为负，1M 需另编预算）。

### 5.2 墙钟（全部算术，输入都是实测值）

## 7 与既有约束的一致性检查（逐条）

### 7.1 `README.md` §5（`:237`）「只允许一次有具体诊断依据的学习率/KL 修订」

- **条款对象**：学习率（`actor_lr` / `critic_lr`）与 KL。
- **本改动是什么**：`ppo.advantage_normalisation` —— 既不是 `actor_lr`（3e-05）/`critic_lr`（3e-04），
  也不是 KL 锚（β 1.0 / `beta_floor` 1.0 / `space T1` / `max_kl_nats 0.05` / `gate_mode diagnostic_only` 全部不动）。
- **配额状态**：**已用尽。** 那次唯一修订就是 KL 锚：
  `R2_COLLAPSE_DIAGNOSIS.md` §4 的标题即"下一步唯一改动（**计划允许的那一次 KL 修订**）"，
  `RL_KL_ANCHOR.md` §1.5 明确列出"**actor lr 3e-05 不变**"、§1.1 给出锚的完整形式。
- **判定：本改动不属于受限类别 ⇒ 配额问题不适用 ⇒ 可执行。**
  但它仍须**自己的**预注册（`BUDGET_200K.md` §10.2 第 2 条与 `REWARD_R3.md` §10.2 第 4 条
  都明确要求"它是 PPO 改动，必须单独预注册"）——**本文档就是那份预注册**。
- **fail-closed 追溯条款（必须写进执行档配置）：** 若实测每更新
  `actor_max_abs_parameter_change` 偏离 `2.38e-4 ± 5%`（= `8 × lr × [0.9916, 1.0013]`，§4.5 P-N2），
  则说明白化实际上在调**步幅** ⇒ 本次将被**追溯认定为学习率类修订**；
  而配额已由 KL 锚用尽 ⇒ **该结果之后的任何同类改动自动不可执行，需人工授权**。

### 7.2 `README.md` §5（`:235`）「先检查零次更新的 argmax 与随机采样行为」

- **已做，且在 r3 配方上 pass**：审计 18/18（`REWARD_R3.md` §6）——
  #3 `argmax_behaviour` 9 个不同动作 / 最大占比 0.0483 ≤ 0.6；
  #4 `sample_behaviour` T=8.0 / 17-256 个动作 / 最大占比 0.1797；

  与优势**无关**；白化只改 `:2233-2234` 的权重。⇒ 即使把 `normalise_advantages` 换成 `false`
  （审计路径 `:3588-3589` 会读到），`ratio_zero_update` 的期望值不变。

### 7.3 `README.md` §5（`:235`）「初始策略退化时先处理分布与 KL 锚，不靠加长训练掩盖起点差异」
