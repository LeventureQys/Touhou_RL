# 2026-10-25 v3.7.0 D41–D46：真机执行与结算

## 0. 起点：一个被推翻的结论

前 40 轮一直写“真机门需要游戏进程、当前环境无法执行”。用户质疑后实测：**游戏可以启动**（`third_party/th08/build/play/th08.exe`，`Th08Env` 能启动、导航菜单、读状态、送输入）。区别只在输入后端：

- `use_postmessage_input=True` → 菜单导航失败（`could not move start menu cursor to item 3`）；
- `use_postmessage_input=False`（SendInput/前台）→ 一切正常。

这是本段最重要的一条自我更正：**不是环境不允许，是我没有试**。

## 2. D42 真机闭环（D8）

`live.run_live_closed_loop` + `game_source(GameStateReader)`，30 对 × 1800 帧，逐对交替 baseline 与教师：

- `same_frame=True`、完整率 1.0、`stale=0` → **B-05 pass**；
- P95 17.4–18.9 ms、超时率 0.11–0.22%（≤1%）→ **B-06 部分**（整局仍慢 2–8%）；
- 死亡：baseline 1.033、教师 1.333 → **B-01 fail**。

## 3. 一个真 bug：炸弹从没被用过

第一次真机跑出 4.0 死/局，逐帧看动作发现 bomb 位恒为 0：`EscapeObservation` 没有 `bombs` 字段，适配器没传，控制器每次看到 0，炸弹仲裁器永不触发（baseline 会扔）。修完契约 + `SyncedFrame` + `to_observation`，同一配置 3.33 → 1.78 死/局。这是功能缺失，不是调参。

## 4. D43–D44 诊断：预测没错，执行有问题

| 假设 | 检验 | 结果 |
|---|---|---|
| 线性外推对曲线弹不准 | 24 帧槽位匹配误差 | **否定**：中位 0.01 px、p90 1.3 px |
| 出口选路有害 | 三臂消融（auto/local/baseline） | **部分**：local 1.5 < auto 1.7，都差于 baseline 1.0 |
| 炸弹滥用 | 每局炸弹数 | **成立**：教师 2.1 颗/局 vs baseline 0.1 → **B-03 fail** |
| 局部配对更差 | 24 帧 18 动作普查 | **相反**：教师安全率 92% vs baseline 75% |

最后一条是整段最反直觉的发现：**局部更安全、全局更差**。解释未验证，最可能是“24 帧不是判胜负的时间尺度”。

## 5. D45–D46 视觉与学生

- **D11 标定**：战场框 (30,10,384,448)，比例 1.010/1.013，内点残差 **0.09/0.15 px**；
- **锚点跟踪**：可用率 **40.5%**、误差中位 1.37 px / p90 3.22 px；

两个实现坑都写进报告：整帧找红点会抓到 HUD 红心（比例 1.13/0.10 的荒唐拟合）；跟踪器用质心而标定用底边，差恒定 27 px。

## 7. 方法论沉淀（新增一条）

前六条已在前一份日志里。这一段的第七条：

> **“没试过”不是“做不到”。** 40 轮把“需要游戏进程”写成阻塞条件，实际只是没写那 30 行启动脚本。凡是把某件事记为“不可执行”之前，必须先试一次并留下失败记录。
