# 2026-10-25 v3.6.0 T0–T1 执行日志（增量）

用户要求：读 v3.6.0，然后「一步步开始对所有策略做消融实验，持续的工作，不需要我的请示」。

v3.6.0 目录下只有一份 `需求文档.md`——**没有执行计划、没有契约、没有 data/experiments/evidence/reports**。而需求文档 §7 明确要求"训练前必须建立这些目录"，§4 明确 T0→T1→T2 门禁、§6 明确停止线。所以这一轮的第一件事不是跑实验，而是**先把预注册写出来**：没有预注册的消融，事后一定会变成"挑一个好看的视界/阈值"。

## 1 先决定"消融什么"

需求文档 §2 定义了六条战术（诱导换边、出口保留、主动清怪、输出窗口、条件收 P、bomb），§3 给了七种意图（含 LocalDodge）。问题是：这些是**策略**，不是**可消融的量**。直接把七条策略各训一个网络再比通关率，需要 7×20 局真机时间，而且任何一条的收益都会被其他条的噪声吞掉。

所以把"策略"拆成最小可证伪单位：

```
一条策略 = 一个特征块（只有它能看见的观测）
          + 一个未来标签（它声称能改善的量）
          + 一个基线（不含该块时能拿到的信息）
```

消融 = 同标签、同模型、同交叉验证下「加块前 / 加块后」的差。这样七条策略变成 8 个特征块（多一个 HISTORY 对应 §3.1 的 temporal encoder），一轮离线就能全测，且每条都独立判定、互不掩盖。

这个拆法写进了 `执行计划.md` §2。**阈值、视界、特征块、交叉验证协议、置换次数全部在跑任何实验之前写死**，包括"任一策略都不许用其他策略的收益掩盖"。

## 3 引擎：`touhou_rl/ablate36.py`

设计上的三个硬约束：

1. **标签只来自真实未来**。`death_60` 是"未来 30 个决策里出现 death 事件"，`min_clearance_60` 用**未来快照里的真实弹位与真实自机位**重算，`in_region_60` 是"i+30 决策时的玩家连通分量"。不用外推——否则特征会跟自己的正向模型互相印证，得到假增量。
2. **不用神经网络**。21k 样本 / 123 维、且只有 462 个死亡阳性，非线性只会把噪声拟合得更像信号。用岭回归 + 留一局交叉验证（LOEO，9 折），每决策恰好被预测一次，同局绝不同时进训练和预测。
3. **显著性用局内列置换**。把被消融块的各列在局内独立打乱（保留边缘分布、局归属、其他块），重跑同一流程 200 次。

几何部分是 v3.5.0 S1 的教训直接产物。S1 只取"玩家所在的单一连通分量"，报告自己指出这是失败原因之一。所以 REGION 块这次做满：两尺度（8/16 px）× 五时间片（0/10/20/40/60 帧）、占据与密度分开、**并集/密度区域**单列、质心扩张方向、到最近可用出口的 Chebyshev 环距、出口分量面积与方向、路径密度积分、三边贴墙距离——40 维，比 S1 的 2 个二值变量多两个数量级。

## 4 写引擎时踩的三个坑（都发生在看结果之前）

1. **`exit_info` 每个候选格做一次 BFS** → 实测 8 ms/决策，21k 决策要 3 分钟。改成每个环只查第一个空格、总 BFS 上限 6 次；并且"只有一个格的小口袋"不算出口（`SAFE_MIN_CELLS=8`），返回 area 0 但保留环距，让"远"和"被封死"可区分。
2. **LOEO 里的中位数填补**：`np.nanmedian` 在 (19k, 90) 上约 50 ms/折，200 次置换会被它主导。特征块按构造无 NaN，于是把 `isfinite(X).all()` 提到 `loeo_predict` 里做一次、传下去——**没有按 `id(X)` 缓存**（对象 id 会复用，那是个会静默出错的优化）。
3. **"空特征"的 pooled AUC 不是 0.5**。这是本轮最有价值的方法学发现，见第 6 节。

单测 26 项，其中两项是泄漏守卫：

- `test_loeo_does_not_see_test_fold_labels`：把一个局的标签全改掉，该局的 out-of-fold 预测必须**一点不变**。会变就说明答案键漏进训练了，后面所有增量都是假的。
- `test_loeo_rank_correlates_with_real_signal` / `test_loeo_ignores_pure_noise`：真信号必须 ρ>0.9，纯噪声必须 |ρ|<0.15。防止"静默坏掉"被当成"没有信号"。

## 5 结果（第一次跑完，先看数再下结论）

第一次跑完是 3 条 pass：LocalDodge、REGION、POWER。**没有直接写报告**，而是回头核对每个 pass 数到底进了哪个门。查出两个问题：

**问题一：门禁映射错了。** `CELLS` 表把每条的增量门挂在它自己的**主标签**上，于是 REGION 用 `in_region_60`（"我能不能预测我会不会待在大区域里"——自我循环）给自己判了 pass。而 `执行计划.md` §6.1 写的 REGION 增量门在 **`death_60`** 上，实测是 **−0.0148**。

这个 bug 如果流进报告，结论会从"2 pass / 不进入 T2"变成"3 pass / 进入 T2"，而依据是一条自评指标。修法是让 `CELLS` 显式写清"每个门评在哪个标签上"，`judge()` 只从 `CELLS` 读标签、绝不从结果读。**阈值一个没改，改的是"哪个数进哪个门"。**

**问题二：pooled 与局均符号相反。** BOSS 的 pooled Δρ = −0.0108，局均 Δρ = **+0.0914**。查下来是 pooled LOEO AUC 混进了折间基准率：有 Boss 的局和没 Boss 的局基准差极大。按 `执行计划.md` §9"符号矛盾记 unstable，不进 T2"处理——**两个数都留在表里，不挑一个报**。

顺带确认了这条偏差的量级：同一个协议下，**空特征常数预测器在 `death_60` 上 pooled AUC = 0.3170，局均 = 0.5000**。所以 pooled 的**方向**可信（两侧同受影响），但**绝对 AUC 不能读成"泛化到新局的 AUC"**。每个单元格因此并列局均 Δ 作敏感性对照，12 个里 10 个符号一致。

最终：**pass = LocalDodge、POWER（2 条，G-1 要 3 条）；G-3 也失败——八块全上比只用 BASE 差 0.021 AUC。不进入 T2。**

## 6 最值得记的三条结论

1. **REGION 第二次 fail，而且这次把 S1 建议的修法全做满了。** v3.5.0 S1 说失败原因是"只取单一连通分量、没做并集/密度区域"。本轮改成两尺度 + 密度并集 + 扩张方向 + 出口环距，40 维，增量**仍然**是负的（−0.0148，p=1.000，200 次置换全部比它好）。所以 S1 的失败不是实现太粗，而是：**"玩家处于一个大范围危险区域"这个描述，在给定局部 clearance 之后没有额外信息**。LeaveRegion 真机控制继续不启动。

2. **`ALL` 比 `BASE` 差 0.021 AUC。** 七条策略全加进去，对 60 帧死亡的预测反而变差。原因：123 维里大量列与 BASE 强共线（`POWER_power` 与 `BASE_power` 同值；EMERGENCY 三列是 clearance 的单调变换），而死亡阳性只有 462 个。这是需求文档 §6"不在同一实验中同时修改多个因素"的**精度**证据，不只是纪律。

3. **LURE 的 fail 是口径不匹配，不是策略无用。** 自机狙几何量把 `min_clearance_60` 的 ρ 从 0.8808 抬到 0.9011（+0.0203，p=0.005），方向对、幅度不到 +0.05。但 LURE 真正要证明的是"诱导→换边→更宽出口"的**多步**收益，单决策回归表达不出来。所以它该在 T2 用 paired comparison 判，而不是在这里判死刑——报告里明确这么写，不等结果翻案。
