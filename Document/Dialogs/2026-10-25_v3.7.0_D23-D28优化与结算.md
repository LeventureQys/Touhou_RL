## 2. 时延：从 79 ms 到 27 ms

Profile 显示 `_search_first_action` 占 86%，其中 85k 次 `cell_of` 调用是主要开销。五项改动：

1. beam 打分改为每次展开一次 numpy gather；
2. 自由区分量按时间节点缓存；
3. 一帧动作位移预计算；
4. `clearance_many` 改逐轴形式（最大单项收益）；
5. `future_freedom` 改反向 DP。

| 场景 | 前 | 后 |
|---|---:|---:|
| SC-15 | 79.4 ms | **27.1 ms** |
| SC-16 | 95.8 ms | **30.6 ms** |
| E-05 | 70.1 ms | **25.2 ms** |
| 真实 trace | 64.7 ms | **25.9 ms** |

优化后重跑 dev 12 种子，八门结果与优化前**完全一致**，证明是行为保持的优化。

治理：formal v2 在优化前跑，仍记为唯一 formal；重跑需升 formal-v3 并声明 v2 作废。

## 3. 真实回放：预算耗尽与弹数无关

四条真实采集 trace、399 决策：feasible 376 / budget 23（5.8%）/ no_solution 1。

budget 决策平均 74.1 弹、feasible 78.1 弹——**没有密度相关性**。逐决策看，7 次预算耗尽集中在两个簇且全为瞬态（下一两决策恢复）。结论：控制器在真实弹幕上的失败语义工作正常。

## 4. A-05：负例从 2 例扩到 4 例

新增 E-21（第二波，帧 40 起全覆盖）与 E-22（远处封路，帧 120 起全覆盖），两者的“不可解”由参考的 `area_covered` 覆盖证明给出。

过程中发现一个语义问题：两例的覆盖在 **24 帧计划视界之外**，规划器返回 `model_unknown` 是**正确**的。于是新增标签 `blocked_late` 与 A-06 检查：“视界外的覆盖必须报未知/预算耗尽，不能伪装安全，也不能伪装已证明”。

## 5. 结算：从文档到机器可读

`evaluate.settle()` 从评估数据生成门禁表 + 逐族分母 + 参考标签，写 `settlement-{dev,formal}.json`；`test_escape_settlement.py` 校验生成逻辑与 `gates()` 一致。

顺带得到一条结论：**SC-16 是两臂差距最大的一族**——新方案 18/18，旧 pilot 3/18。原因清楚：pilot 20 帧局部视界看不到 90–180 帧后关闭的出口。

同一命令连跑两次 dev 12 种子评估，逐行/逐门比较：门禁一致、97 行一致、真实 trace 回放逐决策一致；单次耗时 45.6 s（优化前 96 s）。
